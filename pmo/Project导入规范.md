# Project 导入规范 V1

> 适用范围：信息化项目数字化底座计划管控
> 版本：V1 | 编写日期：YYYY-MM-DD | 编写人：xxx

## 一、CSV 准备规范

1. 编码：UTF-8 with BOM
2. 日期格式：YYYY-MM-DD
3. 工期单位：统一使用"工作日"
4. 前置任务格式：用逗号分隔多个前置 ID（如 "11,12"）
5. 资源池列只用 `主责资源`，不用原 `资源名称`（含组合资源）
6. 供应商、协作资源、审核人/审批组均独立成列，不进资源池

## 二、字段映射规范

导入时按以下映射关系配置。以下列导入：

| CSV 列名 | Project 字段 | 备注 |
|---|---|---|
| 任务名称 | 名称 | 导入向导中设为合并键 |
| 任务类型 | Text1 | 自定义字段，值域见附录 |
| 工期 | 工期 | 单位统一为工作日 |
| 开始时间 | 开始时间 | YYYY-MM-DD 格式 |
| 完成时间 | 完成时间 | YYYY-MM-DD 格式 |
| 前置任务 | 前置任务 | CSV 行号，导入后需手动重新关联 |
| 主责资源 | 资源名称 | **只导入此列** |
| 责任部门 | Text2 | — |
| 供应商 | Text3 | 独立字段，关键：不进资源池 |
| 审核人/审批组 | Text4 | — |
| 风险等级 | Text5 | 高 / 中 / 低 |
| 里程碑 | Text6 | 是 / 否 |
| 交付物 | Text7 | — |
| 备注 | 备注 | — |

以下列**不导入**：

| CSV 列名 | 不导入原因 |
|---|---|
| ID | Project 自动生成行 ID |
| WBS | 导入后 Project 自动生成 |
| 资源名称（原列） | 含组合资源，改用主责资源 |
| 协作资源 | 已独立为字段，不进资源池 |
| 供应商资源 | 已并入供应商列 |
| 原资源名称 | 仅作参考 |
| 资源池导入建议 | 仅作参考 |
| 评审意见 | Phase 1 评审用，不入 Project |

（本节在 Phase 2 实操后补充实际执行流程和偏差说明）

1. 打开 Office Project，新建空白项目
2. 设置项目信息：开始日期 → 2026-06-01
3. 文件 → 打开 → CSV 文件 → 导入向导
4. 选择"新建映射"，按第二节字段映射表配置
5. 导入完成后立即检查：
   - 层级是否正确缩进
   - 前置任务是否断链
   - 甘特图是否能正确渲染

## 五、基线设置步骤

1. 基线前最终复核：日期、里程碑、前置依赖、资源分配
2. `项目 → 设置基线 → 设置基线 → 整个项目`
3. 验证基线列有值：插入"基线开始时间""基线完成时间""基线工期"列
4. 配置 4 个视图：
   - PMO 管理视图：全量，按 WBS 一级分组，月/周时间刻度
   - 里程碑视图：筛选 Text6=是，按风险等级分组
   - 高风险视图：筛选 Text5=高，按资源分组
   - 供应商进度视图：筛选 Text3 不为空，按供应商分组
5. `文件 → 信息 → 高级属性` 中录入版本信息
6. 导出基线版 CSV（含基线时间和自定义字段）

## 六、维护规则

1. **每周只更新重点任务进度**（不维护全部任务）
2. **每次重大调整后保存新版 .mpp**，版本号和变更原因记录在文件属性中
3. **风险/问题/变更不进 Project**，走独立台账
4. **H5 看板以基线版 CSV 为数据源**
5. **管理版和执行版 CSV 同步更新**：修改先改执行版，再筛选同步到管理版

## 附录：风险等级判定标准

| 等级 | 判定标准 |
|------|---------|
| 高 | 核心路径、资源紧张（如单核心开发人）、供应商未定、跨系统依赖多 |
| 中 | 有缓冲但存在不确定性、评审依赖多、多人协作但可控 |
| 低 | 常规任务、有成熟方案、独立执行不影响关键路径 |
