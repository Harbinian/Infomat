# pmo/weekly-issues — PMO 周会事项台账正本

> 状态：正式跟踪台账
> 范围：周会行动项、风险事项、问题事项、变更事项、责任池事项

`ledger.json` 是 PMO 行动台账的唯一正本，记录周会登记的事项、责任方、截止时间和当前状态。

《信息化项目协同工作规则》6.1 规定「PMO 行动台账是正式跟踪记录」。本目录取代了此前的浏览器 `localStorage` 存储 —— 后者按浏览器及访问来源隔离（5173与5174是不同origin），不会自动共享，清除该浏览器数据才会丢失；它不能替代服务端文件正本或备份。

## 数据边界

- 只记录四要素（规则 6.3）：**事项、责任方、截止时间、当前状态**。实际执行人由部门内部安排、日常不报 PMO，因此刻意不设执行人字段，也不要求部门重复填报。
- 关闭需具备结果、材料位置、记录或明确结论（规则 6.4），由 `resultNote` 或 `closureNote` 承载；两者皆空时服务端拒绝关闭。
- 期限调整必须记录同意人（规则 8.1）；原截止时间保留在 `history` 中，**不追溯消除已经发生的逾期事实**（规则 8.2）。
- 逾期不是状态而是派生：`dueDate < 今天 && status !== 'closed'`。

## 与交付物行动项的关系

两者是同一套规则的两种载体，都发到信息化工作群、都用同一份发布文本模板：

| | 本目录（周会事项） | `pmo/deliverables/`（交付物行动项） |
|---|---|---|
| 对象 | 周会现场的任何事项 | 受控交付物 |
| 正本形态 | 单个 `ledger.json` | 一事一文件，状态在 frontmatter 的 `action` 块 |
| 适用 | 非交付物类行动项 | 交付物类的编制、提交与整改 |

## 维护

- 本文件由 `pmo/gantt-react` 的 dev 插件读写（`plugins/pmoWeeklyIssuesPlugin.js`），**不要手工编辑结构**；误录事项请通过界面修正。
- 规则校验实现在 `src/utils/weeklyIssueUtils.js` 的 `applyWeeklyIssuePatch`，浏览器与服务端共用同一实现。
- 容器部署时本目录以**可写**方式挂载；不挂载则登记会失败（根文件系统只读）。
