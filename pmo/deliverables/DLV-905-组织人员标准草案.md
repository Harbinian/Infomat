# 组织人员标准草案

| 项目 | 内容 |
| ---- | ---- |
| 交付物编号 | DLV-905 |
| 关联 WBS | 3.1.2 组织/部门/岗位/人员标准-标准草案编制 |
| 计划完成时间 | 2026-07-07 |
| 主责 | MDM 工作组 |
| 协作 | 数据质量工作组、各业务工作组 |
| 审核 | 各部门授权审核员；数据质量工作组 |
| 执行标准 | STD-GEN-001 |
| 完成判定 | 草案包含编码、属性、状态、维护责任、适用系统 |
| 当前状态 | 已提交可执行评审版，待业务评审 |

本草案承接 DLV-138 的花名册输入，并以组织真源、花名册和信息化项目人员角色映射为依据。它不直接修改 `docs/organization/` 真源，也不替代各部门对组织、岗位和人员事实的确认。

## 一、对象范围

| 对象 | 标准目标 | 当前来源 |
| ---- | -------- | -------- |
| 公司 | 定义公司级组织根节点 | `组织架构和部门职责.md` |
| 部门 | 定义真实组织单元、简称、上级关系和职责边界 | `组织架构和部门职责.md` |
| 办公室 | 承载领导岗位及配套人员，不替代部门层级 | `组织架构和部门职责.md` |
| 岗位 | 定义岗位编码、岗位名称、所属组织和任职状态 | `组织架构和部门职责.md`、`花名册.md` |
| 人员 | 定义人员唯一标识、姓名、部门、职务、状态和来源 | `花名册.md` |
| 项目角色 | 定义信息化项目中的临时运行角色和任命状态 | `信息化项目人员角色映射.md` |

## 二、编码草案

| 编码对象 | 编码格式 | 示例 | 维护责任 |
| -------- | -------- | ---- | -------- |
| 公司 | `OU-COM-{公司简称}` | `OU-COM-CXF` | 行政人事部牵头，MDM 工作组建模 |
| 部门 | `OU-DEP-{部门简称}` | `OU-DEP-ENG` | 行政人事部牵头，各部门确认 |
| 办公室 | `OU-OFC-{父级简称}-{办公室简称}` | `OU-OFC-CXF-CEO` | 行政人事部牵头，相关办公室确认 |
| 岗位 | `POS-{组织简称}-{岗位简称}` | `POS-CXF-CEO` | 行政人事部牵头，各部门确认 |
| 人员 | 优先使用工号或胸卡号 | `100000` | 行政人事部维护，数据质量工作组校验 |
| 项目角色 | `PROJ-{项目}-{角色简称}` | `PROJ-INFOMAT-MDM-LEAD` | PMO 和项目管理工作室维护 |

## 三、属性草案

| 对象 | 必填属性 | 说明 |
| ---- | -------- | ---- |
| 组织单元 | 组织编码、组织名称、组织类型、简称、上级组织编码、状态、来源 | 只登记真实组织单元；领导岗位不作为独立组织 |
| 岗位 | 岗位编码、岗位名称、所属组织、岗位类型、状态、来源 | 岗位与人员分离，人员变动不删除岗位 |
| 人员 | 工号、姓名、部门、职务、人员类别、合同类别、核查状态、来源 | 工号/胸卡号作为去重主键 |
| 项目角色 | 工号、姓名、项目组织、项目角色、任命状态、来源材料、是否待确认 | 项目角色不替代常设部门职责 |

## 四、状态草案

| 状态 | 适用对象 | 含义 | 处理规则 |
| ---- | -------- | ---- | -------- |
| 在用 | 组织、岗位、人员、项目角色 | 当前有效 | 可用于项目选择和数据建模 |
| 待确认 | 人员、岗位、项目角色 | 来源存在冲突或缺正式确认 | 不作为最终权威口径，需进入待治理事项 |
| 暂定 | 项目角色 | 项目运行需要先用，但正式任命未完成 | 可用于 PMO 跟踪，不写成红头任命 |
| 已撤销 | 项目角色 | 项目分工已取消 | 保留历史，不再进入新增事项 |
| 停用 | 组织、岗位、人员 | 当前不再使用 | 保留历史引用，不物理删除 |

## 五、适用系统和边界

| 适用位置 | 用途 | 边界 |
| -------- | ---- | ---- |
| MDM 平台 | 后续组织、岗位、人员、角色模型输入 | 以评审通过后的标准为准 |
| PMO 看板和周会行动项 | 只读选择项目人员和角色快照 | 不反向修改花名册或组织真源 |
| 文档结构化输出服务 | 辅助识别执行部门和角色 | 不写回组织真源 |
| 业务系统集成 | 后续统一身份、权限和组织同步依据 | 需另行形成集成规范 |

## 六、待评审问题

| 编号 | 问题 | 责任方 | 处理建议 |
| ---- | ---- | ------ | -------- |
| ORG-STD-001 | 项目角色是否需要独立于 RBAC 权限角色维护 | MDM 工作组、PMO | 先作为项目运行角色，不混入权限定义 |
| ORG-STD-002 | 来源冲突人员如何进入正式治理流程 | 行政人事部、数据质量工作组 | 以 `花名册事实核查问题清单.md` 和部门确认结果为准 |
| ORG-STD-003 | 暂定任命是否可用于周会行动项 | PMO、项目管理工作室 | 可用于跟踪，但页面应显示暂定状态 |

## 七、来源优先级

| 优先级 | 来源 | 使用规则 |
| ------ | ---- | -------- |
| P1 | 正式组织职责文件和部门确认记录 | 用于确认组织单元、职责边界和上级关系 |
| P2 | DLV-138、花名册和行政人事部确认资料 | 用于确认人员、部门、职务和任职状态 |
| P3 | 信息化项目人员角色映射和 PMO 任命记录 | 用于确认项目运行角色，不替代常设岗位 |
| P4 | 访谈记录、会议纪要和临时说明 | 只作为待确认线索，不能直接写成权威标准 |
| P5 | 系统导出、Excel 台账或截图 | 用于辅助核对，需标明导出时间和来源系统 |

## 八、评审矩阵

| 对象 | 主责确认 | 协同审核 | 必查内容 |
| ---- | -------- | -------- | -------- |
| 公司和部门 | 行政人事部 | 各部门授权审核员、MDM 工作组 | 名称、简称、上级关系、职责边界、状态 |
| 办公室 | 行政人事部、相关办公室 | MDM 工作组 | 是否为组织单元、是否只承载岗位和人员 |
| 岗位 | 行政人事部、所属部门 | 数据质量工作组 | 岗位名称、所属组织、状态、是否与人员混淆 |
| 人员 | 行政人事部、所属部门 | 数据质量工作组 | 工号、姓名、部门、职务、状态、来源 |
| 项目角色 | PMO、项目管理工作室 | MDM 工作组、数据质量工作组 | 任命来源、有效期、是否暂定、是否混入权限角色 |

## 九、数据质量检查

| 检查项 | 规则 | 异常处理 |
| ------ | ---- | -------- |
| 唯一性 | 公司、部门、岗位、人员、项目角色编码不得重复 | 进入待治理事项，不导入正式口径 |
| 上级关系 | 部门和办公室必须能追溯到公司或上级组织 | 缺失时退回行政人事部确认 |
| 人岗分离 | 岗位不因人员离职而删除，人员变动不直接改岗位编码 | 拆分为岗位问题和人员问题 |
| 状态一致 | 在用、待确认、暂定、已撤销、停用必须按适用对象使用 | 状态冲突时保留待确认 |
| 来源可追溯 | 每条标准数据至少有来源材料或确认记录 | 无来源时不得写入权威标准 |
| 敏感信息控制 | 公开交付物不写电话、身份证、私人联系方式等信息 | 必要明细留在受控数据源 |

## 十、导入准备和例外处理

| 场景 | 可执行动作 | 不允许动作 |
| ---- | ---------- | ---------- |
| 评审通过 | 形成 MDM 导入字段映射和样例数据 | 直接覆盖组织真源 |
| 有条件通过 | 标记可先用字段和待补字段，进入整改清单 | 将待确认项写成正式事实 |
| 来源冲突 | 按来源优先级保留主口径，冲突项进入待治理事项 | 由系统或项目组自行裁定组织事实 |
| 临时项目角色 | 可用于 PMO 看板和周会行动项，并显示暂定状态 | 作为 RBAC 权限或正式任命依据 |
| 人员隐私字段 | 在标准中说明字段存在和维护责任 | 在公开交付物中列出敏感明细 |

## 十一、评审通过条件

| 条件 | 判定口径 |
| ---- | -------- |
| 对象完整 | 组织、部门、办公室、岗位、人员、项目角色均有范围和边界 |
| 编码可执行 | 每类对象都有编码规则、维护责任和冲突处理 |
| 属性可落库 | 必填属性、状态和来源字段能支撑后续 MDM 建模 |
| 责任清楚 | 行政人事部、各部门、PMO、MDM 工作组、数据质量工作组职责不混淆 |
| 风险保留 | 未确认和冲突事实继续保留待治理状态，不写成最终事实 |
