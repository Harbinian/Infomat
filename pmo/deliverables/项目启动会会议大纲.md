# 昌兴复材数字化底座项目启动会会议大纲

用途：启动会会议材料底稿  
范围：会议主线、讲解章节和讨论事项  
说明：本稿只写会上要讲什么，不写人员名单、现场执行表和预设表决结果。

## 一、会议定位

本次会议定位为数字化底座项目启动会，重点不是做项目宣传，而是让项目进入可执行、可治理、可追踪的状态。

会议需要围绕三条主线展开：

1. 项目为什么启动，以及当前阶段要解决什么问题。
2. 启动后项目如何治理、如何调研、如何记录和升级问题。
3. 数字化底座已有工具如何支撑计划管控、交付物闭环和治理结果承接。

当前阶段的分析对象是流程、数据、证据和责任边界，不以具体应用系统作为评价对象。

## 二、会议目标

本次会议希望形成以下工作口径：

| 目标 | 说明 |
| ---- | ---- |
| 项目启动口径 | 明确数字化底座项目进入启动执行状态后的工作方式 |
| PMO 治理口径 | 明确 PMO 对计划、交付物、阶段门、风险、问题、变更和责任池的治理边界 |
| 调研授权口径 | 明确 PMO 开展流程治理、证据留存、现场观察、业务行为模拟和历史问题推演的边界 |
| 责任池口径 | 明确启动期历史问题、边界问题和资料不一致问题如何先纳入治理 |
| 工具承接口径 | 明确甘特图、PMO 看板和 MDM 平台在启动后的试运行用途 |
| DLV-003 处理口径 | 明确《项目治理与调研机制管理办法》如何纳入会议讨论和会后修订 |

## 三、会议主线

### 1. 项目背景与启动必要性

讲清项目启动的业务背景：

- 当前信息化工作需要从零散事项推进，转向按流程、数据、证据和责任边界推进。
- 项目管理需要形成计划真源、交付物台账、阶段门和问题升级机制。
- 流程地图、数据地图和主数据治理准备工作需要统一入口、统一口径和统一追踪方式。

本部分不展开具体系统选型，不对具体应用系统做评价性排序。

### 2. 当前阶段工作范围

讲清当前阶段重点工作：

- 梳理流程地图。
- 梳理数据地图。
- 建立字段台账和待确认主数据对象。
- 明确跨部门输入输出和责任边界。
- 建立 PMO 项目治理、调研、证据和责任池机制。

需要特别说明：MDM 平台开发不是当前会议的唯一目标，当前更重要的是把流程和数据治理链路跑通。

### 3. 启动后的治理方式

讲清 PMO 启动后如何治理项目：

- 用 WBS 和甘特图管理项目计划。
- 用交付物台账管理每项任务的输出。
- 用阶段门管理关键节点是否具备进入下一阶段的条件。
- 用风险、问题、变更和责任池台账分流不同类型事项。
- 用周会和专项会公开阻塞事实、影响和下一步动作。

本部分只讲治理方式，不把会议讨论写成已经完成的最终制度。

### 4. PMO 调研与证据规则

讲清 PMO 调研不是检查式追责，而是为了还原真实流程和数据链路。

可讨论的调研方式包括：

- 现行流程治理。
- 关键访谈和会议纪要校核。
- 现场观察、跟产或参会。
- 业务行为模拟。
- 历史不符合项推演。
- 表单、台账、会议记录和系统痕迹比对。

这些记录进入项目治理台账，用来支撑流程地图、数据地图、风险处理、问题处理、变更处理、责任池和阶段门判断。

### 5. 责任池机制

讲清责任池解决什么问题：

- 鼓励各部门暴露历史流程问题、历史数据问题和跨部门边界问题。
- 避免项目在虚假一致的材料上继续推进。
- 将历史问题先作为治理对象记录、分级、确认责任边界和制定治理动作。

需要讲清责任池不是免做池。进入责任池的事项仍要记录、跟踪、整改和关闭。

### 6. 数字化底座工具展示

本部分介绍三个工具在启动后的用途，而不是做正式验收。

| 工具 | 会议中需要讲清的重点 |
| ---- | -------------------- |
| 数字化底座甘特图 | 项目计划真源、WBS 主线、任务层级、里程碑、阶段门、关键路径和风险任务 |
| PMO 看板 | PMO 周会视图、交付物台账、本周交付物、延期交付物、阶段门缺失和高风险任务 |
| MDM 平台 | 角色工作台、流程治理、字段台账、冲突管理、基础主数据和治理结果承接 |

MDM 平台承接结构化查看、状态记录、角色工作台和后续治理验证，不直接改原始流程资料。

### 7. DLV-003 专题讨论

DLV-003《项目治理与调研机制管理办法》应作为会议专题讨论内容。

讨论重点包括：

- 治理原则是否覆盖当前阶段需要。
- 责任池机制是否能支撑启动期历史问题治理。
- PMO 调研机制是否覆盖流程治理、证据留存和现场观察。
- 周会、月报、阶段门和专项会如何分工。
- 交付物治理、退回重提和归档口径是否清晰。
- 风险、问题、变更和责任池台账是否需要分开管理。
- 默认处理和升级机制如何避免项目长期等待。

会议不需要逐字审定 DLV-003 全文，但需要形成会后修订和发布的处理口径。

## 四、会议材料章节

### 1. 封面：数字化底座项目启动会

封面只说三件事：这是数字化底座项目启动会；会议要把项目从准备状态推到执行状态；今天要把启动、治理、调研、责任池和工具试运行讲清楚。

封面不需要堆很多信息。标题下方可以放一句话：从今天开始，项目按计划、交付物、阶段门和治理台账往前走。

这句话够直白，也能把会议的味道定下来。

### 2. 会议定位：为什么这次会议是启动会

这一章要先把会的性质说清楚。

这不是一次普通说明会。普通说明会讲的是“大家了解一下”；启动会讲的是“后面就照这个机制往前推进”。所以这一章要把边界说透：

- 项目启动后，任务不再只靠口头催办。
- 部门反馈不再只停留在聊天记录里。
- 流程、数据、责任边界和证据都要进入可追踪的台账。
- 遇到迟迟不反馈、跨部门边界不清、资料不一致的问题，PMO 要能记录事实、说明影响，并把事项推到下一轮处理。

这里要提醒大家：当前阶段先把流程和数据摸清楚，不急着把所有事情都写成系统功能。流程没讲清，系统页面做得再漂亮也会返工。

### 3. 项目背景：为什么现在要启动数字化底座项目

这一章说人话，不要把背景写成口号。

可以这么讲：

公司现在的信息化工作已经不是买一个系统、上一批功能那么简单。真正麻烦的地方在流程和数据。比如一张表从哪个部门来，谁确认，谁接收，后面哪个岗位继续用，出了问题谁来判断，这些事情如果不说清楚，系统上线以后还是会回到手工解释、临时补表、反复对账。

数字化底座项目要先解决底层问题：

- 流程怎么走。
- 数据从哪里来。
- 字段谁维护。
- 部门之间怎么交接。
- 证据怎么留。
- 有争议时怎么升级。

这一章可以点到项目规模：当前项目计划已经拆到 434 项任务，里程碑 46 个，关键路径控制任务 75 项。这个量级说明项目不能靠临时协调推进，必须有管控节奏。

### 4. 当前阶段：流程地图、数据地图和主数据治理准备

这一章要把“当前阶段干什么”讲清楚。

当前不是一上来就讨论每个系统怎么改，也不是直接进入开发。现在要做的是把流程地图和数据地图沉下来。

会议材料可以按这几句话展开：

- 先看流程。一个业务动作从哪里开始，经过哪些岗位和部门，最后形成什么结果。
- 再看数据。流程里产生了哪些字段、表单、台账和系统痕迹，哪些数据以后可能成为主数据。
- 然后看责任。谁维护，谁确认，谁消费，跨部门交接有没有明确输入和输出。
- 最后看治理。发现历史问题、字段缺口、边界不清，不是马上找人背锅，而是先进责任池，先把事实说清。

这里要把 MDM 平台的位置说准：它是后续承接治理结果的地方，不是替大家编流程的地方。流程和数据要先被业务讲清楚，平台才有东西可承接。

### 5. 治理方式：PMO 如何管计划、交付物、阶段门和阻塞事项

这一章讲 PMO 怎么管项目。

项目计划不是一张排期表。现在计划里有任务、里程碑、关键路径、阶段门、H5 重点展示任务和执行管控字段。会议上要让大家知道，启动后 PMO 会围绕这些对象推进：

- 任务：看每件事有没有责任部门、计划节点和交付物。
- 里程碑：看关键节点是否按节奏推进。
- 阶段门：看进入下一阶段前该有的材料是否齐。
- 关键路径：看哪些任务一拖就会影响后续安排。
- 风险任务：看哪些事项需要提前暴露、提前协调。
- 交付物：看每件事最后有没有可归档、可复核的结果。

PMO 看板不是为了多做一个页面，而是为了周会能少讲空话。周会要看本周要完成的 A/B 类交付物、已经延期的交付物、阶段门缺口和高风险任务。讲这些，会议才不会变成泛泛汇报。

### 6. 调研方式：PMO 如何还原真实流程、数据和证据链

这一章要把“调研”讲得不吓人。

PMO 调研不是为了挑毛病，而是为了把真实做法还原出来。制度怎么写、现场怎么做、表单怎么走、台账怎么记、系统里留下什么痕迹，这几件事经常不完全一致。调研就是把这些差异摆出来，看看哪些需要保留，哪些要修，哪些先进入责任池。

可以按五类方式讲：

- 访谈和会议：把业务口径说清楚。
- 现场观察：看真实节奏，不看表演出来的流程。
- 表单台账比对：看字段、版本、审批痕迹是否一致。
- 业务行为模拟：拿一个样例从申请、审批、变更、异常一直推到关闭。
- 历史问题推演：从已经发生过的问题倒推流程断点和数据断点。

这一章要强调一句：录音、记录、截图、台账不是为了情绪化追责，是为了让会议纪要、流程图、数据图和问题处理有依据。

### 7. 责任池：历史问题如何先治理、再整改、再关闭

责任池这一章要讲得很直。

如果大家一暴露历史问题就担心被追责，那会议上听到的就只会是“没问题”“一直这么做”“后面再说”。这样项目一定会在假平稳里往前走，后面再集中返工。

责任池要解决这个问题。启动期暴露出来的历史流程问题、历史数据问题、跨部门边界问题、表单台账不一致问题，先进入责任池。进入责任池不等于没事了，也不是免做。它的意思是：先把事实记下来，先判断影响，再定治理动作。

需要讲清两条线：

- 历史问题先治理。重点是还原事实、补齐证据、明确边界。
- 新的执行问题要处理。比如拖期、材料不交、材料质量无法支撑下一步评审，这类事情不能用责任池挡掉。

这样说，大家会更容易理解：责任池不是保护拖延，而是保护真实暴露问题。

### 8. 工具展示：甘特图、PMO 看板、MDM 平台

这一章是现场展示的重点，但不要讲成产品发布会。

先讲甘特图。它解决的是“项目怎么排、怎么追、哪里卡住”。目前计划已经拆成 434 项任务，46 个里程碑，214 项适合重点展示，75 项需要作为关键路径控制。甘特图要让大家看到项目不是一堆散点任务，而是一条有层级、有前后关系、有阶段门的执行链。

再讲 PMO 看板。它解决的是“周会看什么、交付物怎么盯”。看板里要关注本周交付物、延期交付物、阶段门缺失、高风险任务和交付物台账。后续 PMO 周会可以直接围绕这些内容开，不用每次从头问进度。

最后讲 MDM 平台。它解决的是“治理结果放哪里、谁来处理下一步”。平台里要重点展示角色工作台、流程治理、字段台账、冲突管理和基础主数据。角色工作台让每个人先看到自己该干什么；流程治理承接 L3 流程、A1 行为和跨部门风险；字段台账承接数据对象、字段、消费系统和同步方式；冲突管理记录字段和术语分歧；基础主数据为后续建模做准备。

讲到这里要收住，不宣布验收，不承诺所有功能已经完整。今天只是确认这些工具作为启动后的试运行管控入口。

### 9. DLV-003 专题：治理与调研机制如何落地

这一章要把 DLV-003 从“文件”讲成“以后怎么干活”。

DLV-003 需要回答几个现实问题：

- PMO 管哪些事，不管哪些事。
- 调研可以怎么做，证据怎么留。
- 历史问题进责任池后怎么跟踪。
- 周会和专项会分别处理什么。
- 风险、问题、变更、责任池要不要分开记。
- 部门确认是阶段性确认，还是永久背书。
- 遇到长期不反馈，项目怎么继续往前走。

会议上不需要逐字审全文。更合适的方式是把这些问题拿出来谈，确认方向后，会后再把文字修顺、补完整、发出来执行。
