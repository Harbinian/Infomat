## 一、目的

为落实启动会对 PMO 治理与调研授权的会议事项表决结果，建立项目计划、交付物、阶段门、风险、问题、变更、调研和责任池的统一管理规则，制定本办法。

本办法服务于当前阶段的流程地图与数据地图梳理沉淀。PMO 的治理对象为流程、数据、证据、责任边界和项目履约状态，不以具体应用系统作为评价对象。

## 四、治理原则

| 原则 | 管控口径 |
| ---- | -------- |
| 流程优先 | 当前阶段以流程和数据为分析对象，不以应用系统作为评价对象 |
| 证据闭环 | 会议、访谈、现场观察、表单台账、系统痕迹和历史问题均需形成可追溯记录 |
| 责任池保护 | 启动期暴露历史问题先纳入责任池治理，除本办法列明三类例外外，一律不追责 |
| 阻塞公开 | PMO 周会公开阻塞事实、影响和下一步动作，不公开羞辱，不做情绪化归责 |
| 默认推进 | 逾期未反馈事项可采用 PMO 默认版本进入下一轮评审，避免项目无限等待 |
| 阶段确认 | 部门签字为阶段性确认，不代表无限责任；后续变化按变更流程处理 |
| 台账分流 | 风险、问题、变更、责任池事项分别入账，不把所有事项混入 Project 进度表 |

## 六、责任池机制

### 6.1 责任池定义

责任池是启动期和调研期的历史问题保护机制。凡在项目推进中主动暴露、被 PMO 发现或由部门说明的历史流程问题、历史数据问题、跨部门边界问题、表单台账不一致问题和历史不符合项，原则上先进入责任池，作为治理对象处理。

责任池的目的不是免做、免改或免确认，而是降低各部门暴露真实问题的顾虑，避免项目在虚假一致的材料上继续推进。

### 6.2 进入责任池的事项

| 类型 | 常见表现 | 治理动作 |
| ---- | -------- | -------- |
| 历史流程问题 | 制度写法、现场做法、会议决策、表单流转不一致 | 记录差异，形成流程断点，提出流程修订或控制点建议 |
| 历史数据问题 | 编码重复、字段缺失、责任主体不清、历史台账不完整 | 分级入账，明确修复优先级、数据责任和修复方式 |
| 跨部门边界问题 | 一个流程多个部门参与但无明确输入输出、交接时点和确认责任 | 建立 RACI，必要时提交项目决策层 |
| 表单台账不一致 | 表单版本、台账字段、审批痕迹、现场记录不一致 | 做证据比对，保留差异并组织确认 |
| 历史不符合项 | 既往质量、安全、生产、财务、审计等不符合事项 | 做历史不符合项推演，倒推流程和数据断点 |
| 历史例外处理 | 长期依靠口头、邮件、临时表格、手工补录解决业务问题 | 判断是否需要制度化、数据化或阶段性旁路 |

### 6.3 不追责口径

除以下三类执行问题外，责任池内事项一律不追责：

| 例外类型 | 判定口径 | 处理方式 |
| -------- | -------- | -------- |
| 拖期 | 逾期未提交、逾期未反馈、逾期未确认，且未提前说明原因或申请协调 | 纳入 PMO 周会阻塞项；影响阶段门时提交项目决策层 |
| 交付物未交 | 应提交的清单、记录、模板、确认单、台账、材料未提交 | 纳入交付物台账；不得用口头说明替代交付物 |
| 提交材料质量过于低劣 | 空白、明显与任务无关、关键字段大量缺失、无法追溯来源、经一次退回后仍不能支撑下一步评审 | 退回重提；仍未改善的列为执行质量问题 |

材料质量不以文字是否漂亮为标准，而以是否能支撑下一步流程梳理、数据地图、方案设计、阶段门评审为标准。

### 6.4 责任池处理流程

| 步骤 | 动作 | 责任方 | 输出 |
| ---- | ---- | ------ | ---- |
| 1 | 发现事项 | PMO / 部门 / 工作组 / 供应商 | 责任池事项登记 |
| 2 | 判断类型 | PMO | 历史问题、边界问题、数据问题、执行问题分类 |
| 3 | 纳入责任池或转执行问题 | PMO | 责任池台账或问题台账 |
| 4 | 组织核实 | PMO / 相关部门 | 事实说明、证据材料、影响范围 |
| 5 | 制定治理动作 | PMO / 责任部门 / 工作组 | 整改、补录、确认、变更、阶段性旁路 |
| 6 | 周会跟踪 | PMO | 状态、阻塞、升级条件 |
| 7 | 关闭确认 | PMO / 责任部门 | 关闭依据和确认记录 |

### 6.5 责任池登记表模板

| 编号 | 发现日期 | 事项名称 | 类型 | 涉及部门 | 事实描述 | 证据来源 | 是否追责例外 | 治理动作 | 状态 |

## 七、PMO 调研机制

### 7.1 调研总流程

| 步骤 | 动作 | 输出 |
| ---- | ---- | ---- |
| 1 | 编制调研计划 | 调研对象、时间、方式、资料清单、参加人员 |
| 2 | 发出调研通知 | 目的、范围、方式、证据规则、责任池口径 |
| 3 | 开展调研 | 访谈、会议、现场观察、流程治理、模拟推演 |
| 4 | 整理记录 | 会议纪要、观察记录、流程断点、数据对象、责任边界 |
| 5 | 部门确认 | 阶段性确认或差异说明 |
| 6 | 纳入台账 | 流程地图、数据地图、风险、问题、变更、责任池 |
| 7 | 复盘升级 | 对阻塞、争议和重大风险进行周会或决策层升级 |

### 7.2 现行流程治理

现行流程治理用于还原制度流程、实际做法、表单台账、系统痕迹和例外处理之间的关系。

| 记录项 | 内容 |
| ------ | ---- |
| 流程名称 | 业务流程或待确认流程名称 |
| 制度依据 | 文件号、版次、文件名、条款 |
| 实际做法 | 部门实际执行步骤 |
| 表单台账 | 使用的表单、台账、会议记录 |
| 系统痕迹 | 已有系统、表格、邮件或纸质记录中的证据 |
| 例外处理 | 口头、临时表、手工补录、线下审批等情况 |
| 流程断点 | 等待、返工、重复录入、责任不清、数据不一致 |
| 治理建议 | 保持、修订、补充控制点、进入责任池、提交变更 |

### 7.3 录音录像

录音录像用于事实还原、纪要校核和争议事项复核，不作为个人绩效或情绪化追责材料。

| 管控项 | 要求 |
| ------ | ---- |
| 使用场景 | 关键访谈、业务演示、流程说明、争议复核、历史问题推演 |
| 告知要求 | 调研开始前说明录音录像目的、使用范围和保存方式 |
| 保存要求 | 统一归档到 PMO 指定位置，登记编号、时间、对象和访问范围 |
| 使用边界 | 用于项目治理、流程地图、数据地图、纪要校核和阶段门评审 |
| 禁止事项 | 禁止剪辑后用于个人评价，禁止脱离项目目的传播 |

### 7.4 全日跟产或参会

全日跟产或参会用于观察真实业务节奏，不要求部门为了调研额外表演流程。

| 观察项 | 内容 |
| ------ | ---- |
| 触发 | 业务如何开始，谁提出，依据是什么 |
| 流转 | 经过哪些岗位、部门、会议或表单 |
| 等待 | 等谁、等什么资料、等哪个判断 |
| 返工 | 因何原因退回、修改、补充、重做 |
| 交接 | 输入、输出、责任人、确认方式 |
| 例外 | 临时处理、口头沟通、线下绕行 |
| 证据 | 表单、台账、截图、会议记录、现场说明 |

### 7.5 业务行为模拟

业务行为模拟以样例单据或典型场景为输入，推演申请、审批、变更、异常、关闭全过程。

| 记录项 | 内容 |
| ------ | ---- |
| 模拟场景 | 如申请、审批、采购、入库、领用、返工、报废、异常处理 |
| 样例输入 | 表单、台账、图纸、合同、物料、项目、人员或设备样例 |
| 角色动作 | 各岗位或部门的动作 |
| 判断规则 | 审批条件、校验规则、例外规则 |
| 数据对象 | 过程中产生或引用的数据对象 |
| 断点问题 | 缺字段、缺权限、缺规则、缺责任、缺证据 |
| 输出结论 | 流程地图、数据地图、问题台账、变更建议 |

### 7.6 历史不符合项推演

历史不符合项推演用于从典型历史问题倒推流程断点、数据断点和责任边界。上线前暴露的历史不符合项原则上进入责任池治理，不直接追责。

| 记录项 | 内容 |
| ------ | ---- |
| 历史事项 | 不符合项名称、时间、来源 |
| 事实摘要 | 已知事实和证据 |
| 当时流程 | 当时应执行的制度、流程、表单 |
| 实际路径 | 实际发生的处理路径 |
| 断点分析 | 流程断点、数据断点、权限断点、责任边界断点 |
| 当前影响 | 对流程地图、数据地图、系统设计或阶段门的影响 |
| 治理动作 | 修订流程、补数据、补规则、补权限、补台账、纳入变更 |

## 八、PMO 会议机制

### 8.1 周会机制

PMO 周会不逐条追全部任务，重点处理阶段门、重点任务、交付物、阻塞、风险、问题、变更和责任池事项。

| 项目 | 口径 |
| ---- | ---- |
| 频率 | 每周一次，必要时增加专项会 |
| 主持 | PMO |
| 输入 | 任务进展、交付物状态、风险问题、变更申请、责任池事项 |
| 输出 | 周会纪要、行动项、升级事项、默认处理事项 |
| 公开范围 | 公开事实、影响、责任边界、下一步动作和升级条件 |

### 8.2 周会纪要模板

| 栏目 | 内容 |
| ---- | ---- |
| 本周完成 | 里程碑、交付物、阶段门、关键调研完成情况 |
| 下周计划 | 计划开展的评审、调研、会签、交付物提交 |
| 阻塞事项 | 事实、影响、责任边界、下一步动作 |
| 风险事项 | 风险描述、影响、等级、应对措施 |
| 问题事项 | 问题描述、责任方、解决时限 |
| 变更事项 | 变更内容、原因、影响、审批状态 |
| 责任池事项 | 新增、治理中、已关闭事项 |
| 默认处理事项 | 逾期未反馈事项及 PMO 默认版本 |

### 8.3 月报机制

月报只汇报管理层需要判断的事项。

| 栏目 | 内容 |
| ---- | ---- |
| 本月完成 | 已完成里程碑、已关闭交付物、已通过阶段门 |
| 下月关键节点 | 需要管理层关注的计划节点 |
| 延期事项 | 拖期原因、影响、恢复计划 |
| 重大风险 | 需要协调或决策的风险 |
| 重大问题 | 影响阶段门、上线、合同或部门配合的问题 |
| 重大变更 | 范围、时间、资源、技术路线、依赖变化 |
| 责任池概览 | 新增、关闭、持续治理事项数量和典型影响 |

### 9.1 交付物分类

| 等级 | 说明 | 管控要求 |
| ---- | ---- | -------- |
| A 类 | 阶段门、验收、合同付款、重大决策相关交付物 | 必须评审、必须有结论、必须留证 |
| B 类 | 方案、台账、计划、机制、模板类交付物 | PMO 评审后纳入执行基线 |
| C 类 | 会议、清单、过程记录类交付物 | 完整、可追溯、可支撑后续工作 |

### 9.2 交付物评审口径

| 维度 | 要求 |
| ---- | ---- |
| 完整性 | 是否覆盖任务要求、会议事项表决结果和阶段门要求 |
| 可执行性 | 是否能直接指导下一步调研、设计、评审或整改 |
| 可追溯性 | 是否能追溯到会议、制度、表单、台账、系统痕迹或确认记录 |
| 边界清晰 | 是否明确责任部门、配合部门、默认处理和升级路径 |
| 口径一致 | 是否与 WBS、任务真源、PMO 工作原则和项目命名约定一致 |

### 9.3 退回重提规则

交付物存在以下情况时退回重提：

1. 关键章节缺失，无法支撑下一步评审。
2. 大量内容与任务无关。
3. 关键数据、责任方、时间、结论为空。
4. 与已通过会议事项或项目真源冲突。
5. 经 PMO 一次反馈后仍无法支撑下一阶段工作。

## 十一、默认处理和升级机制

### 11.1 默认处理

对逾期未反馈事项，PMO 可采取默认处理：

1. 以已收集证据形成默认版本。
2. 在默认版本中标注未反馈部门、未反馈事项和风险影响。
3. 默认版本进入下一轮评审或调研。
4. 后续部门补充反馈时，按变更或补充确认处理。

默认处理不是替部门决策，而是防止项目因无反馈长期停滞。

### 11.2 升级机制

| 升级条件 | 升级路径 |
| -------- | -------- |
| 跨部门责任边界无法确认 | PMO 周会 -> 项目决策层 |
| 阶段门放行存在争议 | PMO 专题会 -> 项目决策层 |
| 关键交付物拖期影响后续任务 | PMO 周会 -> 项目决策层 |
| 供应商责任边界争议 | PMO / 采购 / 合同责任方 -> 项目决策层 |
| 重大范围、时间、资源、技术路线变化 | 变更台账 -> 项目决策层 |

## 十二、阶段性确认口径

部门签字建议使用以下口径：

> 本部门确认该版本内容可作为下一阶段调研、设计、开发、测试或联调依据。后续如因业务变化、政策变化、跨部门约束调整或项目基线变更导致调整，按项目变更流程处理。

该签字不代表部门或个人对历史问题承担无限责任。历史问题按责任池机制治理；上线后新增且未按流程处理的问题，按问题台账和责任闭环处理。
