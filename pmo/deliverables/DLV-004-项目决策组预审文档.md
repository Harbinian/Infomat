## 五、宏观事务——治理范围与定位边界

### 5.1 项目当前阶段的真实定位

当前阶段是流程地图与数据地图的梳理沉淀，不是应用系统建设。分析对象是流程、数据、证据和责任边界，不以具体应用系统作为评价对象。后续涉及应用落位时，以业务流程、数据对象、角色责任、系统边界和实施条件为依据。

### 5.2 PMO 治理对象

PMO 治理对象 = 流程 + 数据 + 证据 + 责任边界 + 项目履约状态

不适用：个人绩效评价、部门绩效评价、与项目无关的内部管理追责。

### 5.3 PMO 调研的 5 种授权方式

| 方式 | 适用场景 | 输出 |
| ---- | -------- | ---- |
| 现行流程治理 | 制度、实际做法、表单台账、会议记录不一致 | 流程断点清单 |
| 录音录像 | 关键访谈、业务演示、争议复核 | 录音录像登记表 |
| 全日跟产或参会 | 观察真实业务节奏、交接、返工 | 现场观察记录 |
| 业务行为模拟 | 用样例单据推演申请、审批、变更、异常全过程 | 模拟记录 |
| 历史不符合项推演 | 从典型历史问题倒推流程断点 | 推演记录 |

上述记录用于流程地图、数据地图、风险台账、问题台账、变更台账、责任池台账、阶段门评审，不作为个人绩效或情绪化追责材料。录音录像使用边界已写入 DLV-003：禁止剪辑后用于个人评价，禁止脱离项目目的传播。

### 5.4 治理原则 7 条

| # | 原则 | 口径 |
| - | ---- | ---- |
| 1 | 流程优先 | 当前阶段以流程和数据为分析对象，不以应用系统作为评价对象 |
| 2 | 证据闭环 | 所有事项形成可追溯记录 |
| 3 | 责任池保护 | 历史问题先入池，除三类例外外不追责 |
| 4 | 阻塞公开 | 周会公开阻塞事实、影响和下一步动作，不公开羞辱 |
| 5 | 默认推进 | 逾期未反馈事项可用 PMO 默认版本进入下一轮评审 |
| 6 | 阶段确认 | 部门签字=阶段性确认，不代表无限责任 |
| 7 | 台账分流 | 风险/问题/变更/责任池分别入账，不混入 Project 进度表 |

## 六、宏观风险——责任池与升级机制

### 6.1 责任池的本质

责任池是启动期和调研期的历史问题保护机制，**不是免做池**。进入责任池的事项仍需记录、分级、确认责任边界、制定治理动作。目的是降低各部门暴露真实问题的顾虑，避免项目在虚假一致的材料上继续推进。

### 6.2 不追责边界——仅三类例外

| 例外 | 判定口径 | 处理方式 |
| ---- | -------- | -------- |
| 拖期 | 逾期未提交/反馈/确认，且未提前说明 | 纳入周会阻塞项，影响阶段门时上报决策组 |
| 交付物未交 | 应提交的清单、记录、台账未交 | 纳入交付物台账，不允许口头替代 |
| 材料质量过于低劣 | 空白、与任务无关、关键字段大量缺失、经一次退回仍不达标 | 退回重提，未改善列为执行质量问题 |

材料质量以能否支撑下一步评审为标准，不以文字是否漂亮为标准。

### 6.3 6 类进入责任池的事项

| 类型 | 治理动作 |
| ---- | -------- |
| 历史流程问题 | 流程修订或控制点建议 |
| 历史数据问题 | 分级入账 + 修复优先级 + 数据责任 + 修复方式 |
| 跨部门边界问题 | 建立 RACI，必要时提交决策组 |
| 表单台账不一致 | 证据比对 + 保留差异 + 组织确认 |
| 历史不符合项 | 倒推流程和数据断点 |
| 历史例外处理 | 判断是否需要制度化、数据化或阶段性旁路 |

### 6.4 升级到决策层的 5 类情形

| 升级条件 | 触发后果 |
| -------- | -------- |
| 跨部门责任边界无法确认 | PMO 周会 → 决策组裁决 |
| 阶段门放行存在争议 | PMO 专题会 → 决策组裁决 |
| 关键交付物拖期影响后续任务 | PMO 周会 → 决策组协调 |
| 供应商责任边界争议 | PMO / 采购 / 合同责任方 → 决策组裁决 |
| 重大范围/时间/资源/技术路线变化 | 变更台账 → 决策组审批 |
