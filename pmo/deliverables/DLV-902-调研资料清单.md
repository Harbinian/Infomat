## 五、下发与回执流程

| 步骤 | 执行动作 | 责任方 | 输出证据 |
| ---- | -------- | ------ | -------- |
| 1. 固定清单版本 | 确认本文件版本、下发对象和回执截止时间 | 信息化项目组、PMO | 下发版文件或会议确认 |
| 2. 统一下发 | 将 DLV-901、DLV-902 和回执表一起发给责任对象 | PMO | 邮件、IM 截图或会议纪要 |
| 3. 部门回执 | 填写资料是否存在、位置、版本、责任人和提供限制 | 各部门、各专项工作组 | 回执表、文件清单或说明 |
| 4. 缺口核对 | 对“没有、部分有、待确认、需审批”逐项登记 | 信息化项目组 | 缺口台账和责任人 |
| 5. 关闭确认 | 对已提供、已说明、已升级的资料项标记处理结果 | PMO | 回执汇总、整改项或周会行动项 |

## 六、回执跟踪台账字段

| 字段 | 填写口径 | 关闭标准 |
| ---- | -------- | -------- |
| 资料编号 | 对应 MAT-001 至 MAT-013，新增项另行编号 | 编号唯一且能追溯到专项 |
| 下发对象 | 写部门、工作组或供应商接口，不写私人联系方式 | 与 DLV-004 对象清单一致 |
| 责任角色 | 写资料保管角色或业务确认角色 | 能找到回执责任方 |
| 回执状态 | 未下发、已下发、已回执、部分回执、需审批、已升级 | 状态有证据支撑 |
| 资料版本 | 写日期、版本号、系统导出时间或“当前使用版” | 能判断是否为最新可用资料 |
| 使用限制 | 可直接使用、需脱敏、需审批、只能现场查看、不可提供 | 限制已被项目组知悉 |
| 缺口说明 | 写缺什么、影响什么、谁处理、何时回看 | 可进入整改或周会行动项 |

## 七、异常处理规则

| 场景 | 处理方式 | 升级条件 |
| ---- | -------- | -------- |
| 资料不存在 | 记录“没有资料”和实际业务处理方式 | 影响流程或数据确认时进入问题台账 |
| 资料只有纸质或线下版本 | 记录保管位置和可查看方式 | 无法验证关键事实时升级 PMO |
| 资料需脱敏或审批 | 先收集字段清单和脱敏样例 | 超过回执截止时间仍不能提供时升级 |
| 责任人不清 | 按部门或工作组登记待指定 | 连续两次会议仍未明确时进入周会行动项 |
| 供应商输入缺失 | 单独登记供应商资料项和响应状态 | 影响基础设施判断时提交项目决策组 |
