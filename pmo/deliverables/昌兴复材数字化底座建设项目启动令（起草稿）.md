# 昌兴复材数字化底座建设项目启动令（起草稿）

各部门、各项目工作组：

根据公司数字化底座建设工作安排及项目启动会决议，经项目决策组研究，决定正式启动昌兴复材数字化底座建设项目第一阶段工作，并授权PMO牵头组织项目计划、流程治理、数据治理、阶段门控制和跨部门协同推进。

本启动令为项目决策组正式签发的项目启动授权文件。PMO负责编制、发布、解释、组织实施和归档管理；各部门、各项目工作组应按本启动令要求开展工作。本启动令自签发之日起生效。

## 一、启动范围与总体原则

第一阶段采用“一令三启动”口径：启动项目执行管控，启动流程地图与流程治理，启动数据地图、主数据待确认项治理与MDM承接。

本项目第一阶段坚持“流程先行、数据先行、映射先行”。各部门和工作组应先完成部门职责、L1/L2/L3/A1、字段台账、数据对象、维护责任、待确认黄金源、待确认主数据对象和S1承接关系的梳理，再进入具体系统方案深化。

本启动令不以具体系统模块、供应商方案或历史使用习惯作为第一阶段工作起点。第一阶段重点是形成流程地图、数据地图、字段台账、待确认主数据对象、待确认黄金源和映射关系确认结果，为后续系统方案深化、接口设计、权限矩阵、联调安排和验收提供依据。

本项目第一阶段并非直接确定系统模块、开发范围或供应商实施方案，而是先对公司现行业务运行方式进行系统梳理。各部门应说明相关流程的发起、审核、执行和数据维护责任，明确现行制度、表单、台账、流程图、会议确认等材料如何支撑业务运行，哪些字段需要被其他部门、业务场景或系统继续使用。上述关系明确后，后续系统建设、接口设计、权限配置、主数据管理和验收工作才能形成统一依据，避免因流程边界不清、数据责任不明或历史问题未暴露而影响项目实施。

## 二、术语与工作口径

| 术语 | 工作口径 |
| --- | --- |
| L1 能力域 | 按业务领域归集的高阶能力分类，用于说明某项工作属于哪个能力范围。 |
| L2 业务能力 | 能力域下相对稳定的业务能力，用于承接部门职责和管理要求。 |
| L3 业务流程 | 可被执行、确认和管理的具体流程，是本阶段流程治理的核心对象。 |
| A1 业务行为 | 从L3流程进一步拆出的具体业务动作，是确认角色、输入、输出、字段、证据和责任边界的基础单元。 |
| S1 应用系统 | 承接或支撑业务流程的信息系统层级，用于记录流程与系统之间的关系；S1不是本阶段的分析起点，也不等同于系统选型结论。 |
| 流程责任链 | 指流程发起、审核、执行、结果确认等责任关系。 |
| 数据责任链 | 指数据产生、维护、审核、使用、变更和确认等责任关系。 |
| 现行依据 | 指支撑现行业务运行的制度、表单、台账、流程图、会议确认等材料。 |
| 证据材料 | 指用于证明流程、字段、责任边界和处理结果的可追溯材料。 |
| 映射关系 | 指部门职责、L1/L2/L3/A1、数据字段、待确认主数据对象、待确认黄金源和S1承接之间的关联关系。 |
| 治理成果 | 指流程地图、数据地图、字段台账、责任边界、问题闭环、评审结论等阶段性成果。 |
| 阶段性确认材料 | 指用于阶段门放行、评审和归档的确认记录、交付物、会议纪要和整改闭环材料。 |
| 责任池 | 指暂不能立即判定责任归属、需要跨部门澄清的问题集合。 |
| 问题清单 | 指PMO持续跟踪的风险、阻塞、缺证、逾期、争议和待闭环事项。 |

## 三、第一阶段交付成果

第一阶段应形成以下成果：项目总体计划、WBS执行基线与PMO管控台账；流程地图与部门流程清单；L3流程与A1业务行为梳理结果；数据地图与字段台账；待确认主数据对象清单；待确认黄金源与维护责任确认表；治理问题清单与责任池台账；阶段门评审材料与会议纪要。

## 四、PMO WBS执行基线与项目管控

以PMO发布的项目总体计划和WBS为执行基线，围绕467个WBS节点、10条一级工作主线建立项目管控台账。第一阶段重点纳入WBS 1“项目启动与总体蓝图”、WBS 3“数据标准与主数据治理”、WBS 4“MDM建设准备与数据治理沉淀”的执行跟踪，并将WBS 1.1“项目启动与治理机制”、WBS 1.2“现状调研”、WBS 1.3“总体蓝图与实施计划评审”作为近期PMO周例会重点管控对象。

PMO周例会重点跟踪阶段门未通过事项、关键路径控制任务、高风险任务、交付物未完成事项、主数据与流程治理阻塞项、跨部门责任不清事项。对逾期、无人确认、材料缺失、责任边界不清的任务，纳入问题清单和责任池；影响阶段门、蓝图评审或后续联调条件的事项，提交项目决策组协调。

## 五、流程治理、数据治理与MDM承接

各部门应围绕现行依据开展流程治理，确认L3流程、A1业务行为、流程责任链、跨部门输入输出和待补证据。对证据不足、责任边界不清或跨部门存在争议的事项，应进入问题清单或责任池。

各部门应围绕数据责任链开展数据治理，梳理字段台账、数据对象、维护责任、消费场景、待确认黄金源和待确认主数据对象。黄金源确认应按字段和证据材料逐项确认，不因流程建议落位或历史使用习惯自动认定。

MDM工作组从治理承接开始工作，承接流程治理和数据治理成果，组织字段台账、待确认主数据对象、待确认黄金源、映射关系和治理闭环的复核。MDM当前作为治理成果承接和验证能力，不替代正式流程资料，不以具体平台功能作为唯一执行依据，也不在第一阶段直接冻结最终主数据模型。

## 六、交付物台账与阶段门管理

PMO建立交付物台账管理机制，对项目计划内成果进行登记、责任确认、版本留痕、评审状态跟踪、阶段门关联、归档位置记录和问题闭环管理。台账的具体承载方式、工具形态和操作流程，由PMO根据项目推进阶段和管理工具建设情况动态优化。

项目按阶段门进行过程控制。阶段门放行应以计划任务完成情况、交付物完整性、责任确认、评审结论、风险问题闭环情况为依据。阶段门验收以交付物内容、责任确认、评审结论和归档记录为依据，不以某一固定系统操作作为唯一依据。

## 七、部门配合、问题清单与历史问题边界

各部门应指定项目接口人，负责日常资料收集、问题反馈、会议联络和整改跟踪；涉及流程口径、数据来源、维护责任、审批责任、跨部门边界和阶段性成果确认的事项，应由部门负责人或经授权的业务负责人确认。

本项目启动后，流程梳理、数据治理、主数据盘点、系统调研过程中发现的历史遗留问题，原则上进入治理问题清单和责任池，重点用于澄清事实、明确责任边界、制定整改措施和形成闭环记录，不直接作为部门或个人追责依据。

## 八、组织分工

PMO负责项目计划、WBS执行基线、周例会、阶段门、交付物台账、问题清单、责任池、会议纪要和归档管理。MDM工作组负责承接流程治理和数据治理成果。各部门负责提供现行依据，确认本部门流程责任链和数据责任链，配合跨部门映射澄清。项目决策组负责重大争议、重大变更、阶段门阻断、资源协调和关键成果确认。

## 九、近期重点工作安排

启动后近期重点工作包括：建立PMO周例会、问题清单、责任池和阶段门跟踪机制；完成各部门接口人确认；启动现状调研计划；围绕流程地图开展L3流程、A1业务行为、责任边界、跨部门断点梳理；围绕数据地图开展字段台账、数据对象、维护部门、消费场景、待确认黄金源和待确认主数据对象梳理；由MDM工作组承接治理成果，形成后续评审准备材料。

## 十、生效、解释与归档

本启动令自签发之日起生效。PMO负责解释、组织实施和归档管理。涉及项目范围、阶段门阻断、重大资源协调、跨部门重大争议和关键成果确认的，提交项目决策组研究决定。
