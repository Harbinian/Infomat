## 一、第一阶段试运行考核方案

### 1.1 试运行目的

本方案先服务第一阶段流程治理和数据治理工作，不直接全项目铺开。试运行的目的不是把所有事项一次性奖惩到底，而是先验证三件事：

1. 任务权重是否能反映真实工作负荷。
2. 有效工作评价是否能区分“做了很多”和“做成、做准、一次过”。
3. 高风险任务、里程碑任务、阶段门任务是否能成为可复盘、可兑现、可考核的重点标的。

试运行结果用于校准权重、评价阈值和后续全项目推广规则。试运行期间发现任务边界、主责部门、证据标准不清的，先进入 PMO 待确认清单，不倒推修改 PMO 任务基线。

### 1.2 试运行范围

首轮试运行范围按 PMO 任务基线和 WBS 结构基线识别，不另造任务口径。

| 范围 | 管控对象 | 试运行重点 | 首轮测算任务 | 首轮测算总负荷 |
| ---- | -------- | ---------- | ------------ | -------------- |
| WBS 1.2 现状调研 | 部门调研、流程与数据现状、问题清单、调研小结 | 高风险调研任务、关键路径控制任务、GATE-1.2 准入确认 | 40 项可计负荷任务，1 项节点兑现项 | 225 分 |
| WBS 3.1-3.4 数据标准与主数据治理前段 | 组织/人员、物料编码、BOM 口径、工艺资源标准 | 数据标准草案、业务评审、修订确认 | 16 项可计负荷任务 | 58 分 |
| WBS 4.1-4.7 MDM 建设准备与数据治理沉淀 | 流程地图、数据地图、主数据边界、模型与样例沉淀 | 数据治理沉淀、规则样例、跨系统口径准备 | 20 项可计负荷任务 | 108.5 分 |
| 合计 | 第一阶段流程治理与数据治理试运行 | 按总负荷评价有效工作 | 76 项可计负荷任务，1 项节点兑现项 | 391.5 分 |

> 说明：以上为基于当前 PMO 任务基线数据形成的首轮测算值，只用于本方案试运行口径说明。正式执行仍以经批准的 PMO 任务基线为准；任务增删、日期变化或 WBS 调整时，应重新测算。

### 1.3 试运行考核对象

试运行按工作组为主评价，跨部门工作组主要考核主责部门。第一阶段先按以下承接口径记录：

| 工作组 / 承接对象 | 对应范围 | 首轮测算任务 | 首轮测算总负荷 | 评价方式 |
| ----------------- | -------- | ------------ | -------------- | -------- |
| 信息化项目组 | WBS 1.2 现状调研 | 40 项 | 225 分 | 按调研、流程治理、数据治理前置任务整体评价 |
| MDM 工作组 | WBS 3.1-3.4、WBS 4.1-4.7 | 36 项 | 166.5 分 | 按数据标准、数据地图、主数据边界与治理沉淀整体评价 |

若具体任务涉及多个部门配合，PMO 只记录主责工作组、主责部门、协作部门和阻塞原因，不按人员姓名直接拆分得分。主责部门尚未由组织架构文件或任命文件明确的，先列为“待主责确认”，不得凭职务或口头印象推断。

### 1.4 重点激励和重点考核标的

以下任务不按普通事项处理，应进入 PMO 周会、月度复盘和阶段评审重点清单：

| 标的 | 识别规则 | 正向应用 | 负向应用 |
| ---- | -------- | -------- | -------- |
| 高风险任务 | 风险等级为高 | 同等完成质量下优先纳入正向激励资格 | 未获批逾期、证据不足或反复返工时优先进入整改清单 |
| 关键路径控制任务 | 标记为关键路径控制任务 | 按期通过后优先支撑阶段兑现 | 影响后续任务启动时，纳入 PMO 阻塞升级 |
| 里程碑任务 | 任务类型为里程碑，或任务基线中标注为里程碑 | 不按普通工作量堆积分，作为节点兑现项 | 节点未达成时暂缓相关阶段正向激励资格 |
| 阶段门任务 | 阶段门编号、阶段门名称、放行/阻断规则或合同/付款控制口径不为空 | 前置交付物齐套、评审结论明确后进入专项激励资格确认 | 前置交付物缺失、阻塞项未闭环时不得进入节点兑现 |

首轮试运行已识别的节点兑现项为 WBS 1.2.7.6“进入总体蓝图编制条件确认”，对应 GATE-1.2 和交付物“蓝图编制准入确认单”。

## 二、任务权重与总负荷计算

### 2.1 计入范围

1. 计入总负荷：非摘要、非 0 工作日、可执行且有明确交付要求的任务。
2. 不计普通工作量：摘要任务、虚拟父节点、仅用于分组展示的任务。
3. 里程碑和阶段门：不按普通工时堆积分，单独作为节点兑现和节点考核标的。
4. 经执行副组长审批同意调整的客观原因任务：按调整后周期计入，不作为未完成处理。

### 2.2 单任务权重分

普通可执行任务基础分为 1 分，在此基础上按影响、风险和控制要求加权：

| 加权项 | 加分 | 说明 |
| ------ | ---: | ---- |
| 高风险任务 | +2 | 风险等级为高 |
| 关键路径控制 | +2 | 影响后续关键任务、阶段门或整体节奏 |
| H5 重点展示 | +1 | 已纳入 PMO 重点展示或管理层关注清单 |
| 阶段门/放行阻断/合同付款控制 | +2 | 与节点放行、阻断、合同或付款控制直接相关 |
| 有明确交付物或审核人 | +1 | 任务基线存在交付物、审核人或审批组 |
| 工期 6-10 工作日 | +0.5 | 适度补偿持续工作负荷 |
| 工期超过 10 工作日 | +1 | 适度补偿长周期协调和材料闭环负荷 |

单任务权重分封顶 8 分。权重只用于评价任务负荷和有效工作，不代表资金金额。

### 2.3 总负荷

试运行期应完成总负荷 = 试运行周期内应完成任务的权重积分合计。

PMO 不按任务条数简单平均，也不按参与人数平均。一个工作组做了少量高风险、关键路径、阶段门任务，其总负荷可能高于做了多项普通整理任务的工作组。

### 2.4 任务级有效积分

任务级有效积分用于月度复盘和阶段汇总，计算公式为：任务有效积分 = 任务权重分 × 完成系数 × 质量系数 × 证据系数。

| 系数 | 取值口径 |
| ---- | -------- |
| 完成系数 | 按期完成或经执行副组长审批调整后完成为 1.0；未获批逾期但已完成为 0.6；未完成为 0 |
| 质量系数 | 一次通过为 1.0；退回一次后闭环为 0.8；退回两次后闭环为 0.5；最终未通过为 0 |
| 证据系数 | 证据齐套为 1.0；补齐后可追溯为 0.8；无有效证据为 0 |

## 三、按总负荷计算的有效工作评价

有效工作评价按权重积分计算，不按任务数量粗算。

### 3.1 核心指标

| 指标 | 计算公式 | 用途 |
| ---- | -------- | ---- |
| 按期完成率 | 按期或经执行副组长审批调整后完成的权重积分 / 应完成总负荷 | 判断节奏是否受控 |
| 一次通过率 | 一次评审通过的权重积分 / 已提交评审的权重积分 | 判断提交质量和前置准备质量 |
| 证据齐套率 | 证据齐套任务的权重积分 / 已完成任务权重积分 | 判断交付是否可追溯 |
| 返工扣减率 | 返工任务扣减积分 / 已提交评审权重积分 | 判断返工对有效产出的消耗 |
| 有效工作得分 | 按期完成率 × 40% + 一次通过率 × 30% + 证据齐套率 × 20% - 返工扣减率 × 10% | 月度和阶段试运行综合评价 |

若分母为 0，该指标不参与当期计算，并在复盘表中说明原因。

### 3.2 一次通过口径

一次通过必须同时满足以下条件：

1. 按任务要求提交交付物、清单、纪要、评审材料或确认单。
2. 首次正式评审结论为通过，或仅需文字性修订且不影响结论。
3. 证据能回到任务、责任部门、审核人、日期和版本。
4. 未出现“提交内容无法判断”“证据链缺失”“关键字段为空”“部门未确认”等实质性退回原因。

### 3.3 返工扣减口径

返工扣减只用于评价有效工作，不直接转化为个人金额处理。

| 情形 | 返工扣减积分 |
| ---- | ------------ |
| 首次退回，按要求补正后通过 | 任务权重分 × 20% |
| 第二次退回，按要求补正后通过 | 任务权重分 × 50% |
| 仍未通过、证据不成立或无法支撑下一步工作 | 任务权重分 × 100% |

因 PMO 模板、审核口径或上游任务变化导致的返工，经 PMO 确认为客观原因后，不计入返工扣减。

### 3.4 试运行评价分档

| 分档 | 条件 | 应用 |
| ---- | ---- | ---- |
| A 档 | 有效工作得分不低于 90%，且关键节点无未闭环阻塞 | 优先确认正向激励资格，作为月度重点任务完成的支撑材料 |
| B 档 | 有效工作得分不低于 75%，且阶段门未被阻断 | 视为试运行达标，进入常规复盘 |
| C 档 | 有效工作得分低于 75%，或高风险/阶段门任务存在未闭环阻塞 | 暂缓相关专项激励资格，形成整改清单 |
| D 档 | 关键节点未达成，且无执行副组长审批调整或有效证据 | 取消当期相关任务正向激励资格，并纳入月度绩效扣分依据 |

### 3.5 典型情形与处理结果

以下示例用于统一试运行期间的判断口径。实际执行时仍以任务基线、评审结论、证据记录和审批记录为准。

| 情形 | 示例表现 | 评价结果 | 激励或考核结果 |
| ---- | -------- | -------- | -------------- |
| 完美交付 | 高风险任务按期提交，首次评审通过，证据齐套，未产生返工 | 完成系数 1.0，质量系数 1.0，证据系数 1.0，任务有效积分等于任务权重分 | 计入按期完成率、一次通过率和证据齐套率；优先纳入正向激励资格 |
| 按期交付但小幅补正 | 任务按期提交，首次评审发现格式、文字或附件命名问题，补正后不影响结论 | 完成系数 1.0；如不影响评审结论，可按一次通过处理；如形成正式退回，质量系数按 0.8 | 可计入当期完成；若仅为轻微补正，不影响专项激励资格 |
| 经审批调整后完成 | 因上游材料或跨部门确认延迟，主责工作组提前提交调整说明，经执行副组长审批后按新节点完成 | 按调整后节点评价，完成系数 1.0；不计未获批逾期 | 不作为负向激励事项；仍需按新节点验证一次通过和证据齐套情况 |
| 未获批拖期但未阻塞节点 | 任务超过计划日期提交，未提前取得执行副组长审批，但未影响阶段门或后续关键任务 | 未获批逾期，完成系数最高按 0.6；按实际评审质量和证据情况继续折算 | 不进入该任务正向激励优先项；纳入月度复盘说明，可作为绩效扣分事实依据 |
| 高风险任务返工 | 高风险任务按期提交，但首次评审发现关键字段缺失、证据不足或结论不能支撑下一步工作 | 按返工次数扣减有效积分；一次退回后闭环按 20% 扣减，两次退回后闭环按 50% 扣减 | 暂缓该任务正向激励资格；进入整改清单，闭环后再评价工作组分档 |
| 证据缺失 | 声称任务完成，但没有评审记录、确认人、版本文件、纪要或其他可追溯证据 | 证据系数为 0；任务有效积分为 0 | 不计入有效完成；补证后可重新评价，但不作为一次通过 |
| 里程碑未达成 | 里程碑节点到期，前置交付物未齐套或评审结论未形成 | 不按普通任务补积分；节点兑现不成立 | 暂缓相关阶段正向激励资格；PMO 形成节点偏差说明 |
| 拖期并阻塞阶段门 | 关键路径或阶段门前置任务未获批拖期，导致 GATE-1.2 等阶段门无法放行 | 相关任务有效积分为 0；阶段门判定为阻塞；工作组当期分档原则上不高于 C 档，严重时按 D 档处理 | 暂缓相关工作组阶段专项激励资格；提交 PMO 周会和项目决策层复核，作为月度绩效扣分和整改挂牌依据 |
| 虚假完成或隐瞒阻塞 | 提交材料与实际进展不一致，或明知关键阻塞存在但未在周会和调整申请中说明 | 任务有效积分为 0；不接受事后按客观原因追认 | 取消该任务当期正向激励资格；提交 PMO 周会和项目决策层复核，并纳入负向激励记录 |

## 四、正向激励应用

### 4.1 月度绩效挂钩

试运行期每月由 PMO 汇总工作组有效工作得分，作为公司月度绩效中重点任务和行动项完成情况的支撑材料。

月度应用只提供事实和建议，不替代现行月度绩效审批流程。经营发展部、项目管理部或相关审核部门仍按现行制度确认最终应用结果。

### 4.2 项目专项激励资格

项目专项激励先确认资格，不直接计算金额。满足以下条件的工作组或主责部门，可进入专项激励资格确认：

1. 当期应完成总负荷已完成，或未完成部分已有执行副组长审批调整。
2. 高风险任务按期闭环，未形成未闭环重大阻塞。
3. 里程碑或阶段门前置交付物齐套。
4. 一次通过率、证据齐套率达到试运行分档要求。
5. 无重大质量、进度、客户抱怨或合规问题。

专项激励金额、分配方式和审批仍按公司项目激励管理流程执行。

### 4.3 年度部门绩效挂钩

试运行期的月度汇总表、阶段门兑现确认表和整改闭环记录，可作为年度部门绩效中重点任务及行动项考核的事实依据。

年度应用坚持三项原则：

1. 看总负荷完成质量，不只看任务数量。
2. 看一次通过和证据闭环，不只看是否提交。
3. 看高风险和阶段门结果，不只看普通事项完成率。

## 五、负向激励与资格暂缓

负向激励限定在项目积分、专项激励资格和既有绩效流程内应用，不新增独立个人经济处理条款。

### 5.1 触发情形

| 情形 | 处理口径 |
| ---- | -------- |
| 未获批逾期 | 对应任务完成系数按 0.6 或 0 计算，纳入按期完成率 |
| 无交付物或交付物无法支撑下一步工作 | 对应任务质量系数按 0 计算 |
| 无有效证据 | 对应任务证据系数按 0 计算 |
| 高风险任务未闭环 | 暂缓相关工作组当期专项激励资格 |
| 里程碑或阶段门未达成 | 暂缓节点兑现和后续阶段正向激励资格 |
| 虚假提交、重复提交无效材料或隐瞒阻塞事实 | 取消该任务当期正向激励资格，提交 PMO 周会和项目决策层复核 |

### 5.2 客观原因调整

任务确需调整时，主责工作组应在任务节点前 3 个工作日提交调整说明，说明调整原因、影响范围、需协调事项和新的完成时间。

客观原因调整必须经执行副组长审批确认；未经执行副组长审批的调整，不作为获批调整处理。客观因素消除后仍未完成的，按调整后的节点重新评价。

### 5.3 责任池边界

第一阶段流程治理和数据治理会暴露历史流程、历史数据、跨部门边界、表单台账和历史不符合项。对责任池内历史问题，本方案只评价当前项目任务的承接质量、证据闭环和整改推进，不对历史遗留问题本身做追溯处理。

## 六、执行流程

| 步骤 | 动作 | 输出 |
| ---- | ---- | ---- |
| 1 | PMO 按试运行范围抽取当期应完成任务 | 第一阶段试运行任务清单 |
| 2 | 按权重规则计算任务权重分和工作组总负荷 | 总负荷与有效工作评价表 |
| 3 | 主责工作组提交交付物、证据和调整申请 | 交付物、证据包、调整申请 |
| 4 | 涉及任务调整的，由执行副组长审批确认 | 客观原因调整审批记录表 |
| 5 | 审核人或审批组给出首次评审结论 | 一次通过率记录表 |

PMO 每月只做事实记录、权重测算和建议输出。最终绩效应用、专项激励申请和审批仍按公司制度执行。
