## 四、会议确认事项

会议确认，昌兴复材数字化底座项目进入启动执行状态。项目当前阶段以流程地图与数据地图梳理沉淀为主，PMO 以项目计划、阶段门、交付物、风险问题、变更闭环和责任池治理为抓手组织推进。

### 会议事项讨论框架

本次会议事项采用 A/B 两档严格等级讨论。A 档为柔性推进口径，适合启动期先建立机制、允许会后补齐细节；B 档为强管控口径，适合把反馈时限、阶段门、证据闭环、默认推进和升级机制写成硬约束。

| 编号 | 表决事项 | 讨论目的 | 建议讨论问题 | A 档建议 | B 档建议 | 建议形成结论 |
| ---- | -------- | -------- | ------------ | -------- | -------- | ------------ |
| V-01 | 项目启动 | 确认项目从准备状态进入启动执行状态 | 启动后由谁统筹、按什么计划和例会机制推进 | 同意启动，允许 PMO 会后完善计划基线、交付物清单和例会安排 | 同意启动，同时要求责任人、计划基线、交付物基线和周例会机制同步生效 | 确认项目启动状态，并明确第一轮计划基线发布时间 |

| V-09 | 阶段门与交付物验收控制 | 确认关键阶段必须有交付物、证据和评审结论 | 哪些节点设置阶段门，缺少交付物或证据时是否允许进入下一阶段 | 关键阶段设置阶段门，PMO 汇总交付物、问题清单和评审意见后组织通过 | 未通过阶段门、缺少关键交付物或证据不足时，不进入下一阶段或触发关键节点 | 确认阶段门、交付物和证据闭环是推进前提 |
| V-10 | 联调启动与总体验收控制 | 确认联调和总体验收以准备度为依据 | 联调启动前主数据版本、接口清单、测试环境、权限、备份和阻塞问题如何检查 | 联调启动前由 PMO 组织准备度检查，未关闭事项形成条件清单 | 主数据版本、接口清单、测试环境、权限、备份和阻塞问题未满足前，不启动联调或总体验收 | 确认联调和验收以准备度检查为依据，不只按日期推进 |

## 六、责任池会议口径

责任池是启动期和调研期的历史问题保护机制。凡在项目推进中主动暴露、被 PMO 发现或由部门说明的历史流程问题、历史数据问题、跨部门边界问题、表单台账不一致问题和历史不符合项，原则上先进入责任池，作为治理对象处理。

除以下三类执行问题外，责任池内事项一律不追责：

| 例外类型 | 判定口径 | 处理方式 |
| -------- | -------- | -------- |
| 拖期 | 逾期未提交、逾期未反馈、逾期未确认，且未提前说明原因或申请协调 | 纳入 PMO 周会阻塞项；影响阶段门时提交项目决策层 |
| 交付物未交 | 应提交的清单、记录、模板、确认单、台账、材料未提交 | 纳入交付物台账；不得以口头说明替代交付物 |
| 提交材料质量过于低劣 | 空白、明显与任务无关、关键字段大量缺失、无法追溯来源、经一次退回后仍不能支撑下一步评审 | 退回重提；仍未改善的列为执行质量问题 |

责任池不是免做池。进入责任池的事项仍需记录、分级、确认责任边界并制定治理动作。
