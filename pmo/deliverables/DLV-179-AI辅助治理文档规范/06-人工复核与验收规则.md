# 人工复核与验收规则

## 一、验收对象

人工复核分别检查四类输出，不能互相替代：

1. 候选JSON：流程、行为、数据、表单、证据和待确认问题的机器结构；
2. 独立问题处理记录：每个结构问题的处理结论和理由；
3. 部门业务核对记录：部门对本部门事实的确认、修正或待定说明；
4. PMO行动项：责任人、期限、阻塞、证据和关闭条件。

## 二、复核顺序

| 顺序 | 复核主体 | 复核重点 | 输出 |
| --- | --- | --- | --- |
| 1 | 部门编制人 | 范围、来源、AI遗漏和明显误解 | 修订候选 |
| 2 | 独立复核AI或结构复核人 | Schema、技术标识、引用、字段归位和对象拆分 | 结构问题清单 |
| 3 | 部门业务核对人 | 本部门流程事实、岗位、表单、字段、异常和依据 | 部门复核记录 |
| 4 | 接收部门核对人 | 跨部门交付物、接收动作、承接标准和返回关系 | 跨部门确认记录 |
| 5 | MDM工作组 | 结构门槛、待治理对象、待定关系和后续承接 | MDM结构核验结果 |
| 6 | PMO | 行动项责任、期限、证据和关闭条件 | PMO跟踪记录 |

## 三、交付阻断项

出现以下任一情况，不得交接为“部门未审核候选完成”：

1. 使用了未授权、未脱敏或禁止输入的材料；
2. 存在`failed`或`blocked_unreadable`来源，却没有停止候选编译；
3. AI根据文件名、截图、扫描画面、常识或相似名称补造事实；
4. 候选JSON不符合附带结构规则；
5. 技术标识重复、引用断裂、枚举非法或往返丢失；
6. 多个L3流程被强行合并为一个3001候选；
7. 没有明确流程归口部门、编制人或业务核对人；
8. AI把自动抽取证据标为`verified`；
9. AI自动合并数据对象、认定主数据、确认权威来源或确定责任部门；
10. 当前事实、治理结论和改进建议无法区分；
11. 输出包含审核通过、批准、发布、生效或已导入3000等虚假状态；
12. 问题处理记录或部门复核意见被写入业务JSON；
13. 交接文件没有版本、生成时间或SHA-256，无法确认双方使用同一文件；
14. 把v6文件描述为可直接导入当前3000。

## 四、允许保留的待确认项

以下业务缺口可以保留为待确认，但必须写明确认主体和关闭条件：

- 流程名称、L1/L2映射或边界仍需部门确认；
- A1执行岗位、时限、完成标准或异常规则原文未说明；
- 条件分支、回路或并行路线缺少明确流向；
- 数据对象创建行为、字段取值来源或跨部门接收方未知；
- 是否属于主数据、唯一标识、责任部门、权威来源、质量规则或生命周期待治理；
- 跨部门双方尚未形成一致意见；
- 当前系统名称或现状数据位置需进一步核对。

待确认不代表错误，也不自动升级。PMO只有在事项影响部门责任边界、已发布版本、批准期限或跨部门在规定范围内无法一致时，才按规则组织升级。

## 五、部门业务复核清单

部门业务核对人逐项回答：

- [ ] 流程目的、开始和结束边界与实际一致。
- [ ] 每个A1的执行部门和岗位与实际一致。
- [ ] 每个A1写明实际动作、对象和结果，没有空泛口号。
- [ ] 条件、退回、并行、异常和下一步流向与实际一致。
- [ ] 输入、输出、表单、台账和字段与当前使用情况一致。
- [ ] 数据对象的创建、更新、使用和来源关系与实际一致。
- [ ] 跨部门位置已经列出，未把“未识别”写成“不涉及”。
- [ ] 当前系统只作为现状记录，没有形成系统评价或选型结论。
- [ ] 证据可以回到源文件位置或具名业务确认记录。
- [ ] 未知内容保留待定，没有为了完整度猜测。
- [ ] 建议与现状分开，没有把未来设想写成当前事实。

## 六、MDM结构复核清单

MDM工作组逐项回答：

- [ ] JSON结构版本正确，结构规则快照与交接摘要一致。
- [ ] 技术标识唯一，所有引用完整。
- [ ] L3、A1、关系、数据对象、表单、字段和证据之间可以追溯。
- [ ] 每个A1的执行主体、触发、前提、输入、动作、输出、完成标准和证据已经检查。
- [ ] 跨部门候选没有被自动确认。
- [ ] 工作角色只保留原文或候选，没有编造`WR-*`编码。
- [ ] 同名数据对象没有自动合并。
- [ ] 主数据、责任、权威来源、质量和生命周期只作为待治理内容。
- [ ] `pending_issues[]`可以定位到对象、字段和来源。
- [ ] 未生成正式`structure_block_projection`。
- [ ] 问题处理记录、业务核对记录和PMO行动项与JSON分开保存。

## 七、3001交接清单

- [ ] 使用当前3001导入候选，未修改源文件。
- [ ] 3001技术错误为零。
- [ ] 四轮阶段下载和最终待核对下载按实际需要留存。
- [ ] 最终v6文件已经重新导入核对业务内容和稳定引用。
- [ ] 文件名包含“未审核”、部门、流程、阶段和时间。
- [ ] SHA-256按最终文件实际字节计算并登记。
- [ ] 已明确v6不能直接导入当前3000。

## 八、验收结论

复核结论只允许以下四种：

| 结论 | 含义 | 后续动作 |
| --- | --- | --- |
| 通过本阶段 | 结构阻断为零，本部门事实核对完成，待定项可按计划继续处理 | 进入下一阶段交接 |
| 有条件通过 | 结构阻断为零，但存在不影响当前交接的明确待定项 | 登记责任、期限和关闭条件 |
| 退回修订 | 存在结构错误、事实混写、证据不足或边界不清 | 修订后重新复核 |
| 阻断 | 存在安全、授权、不可读来源、数据泄露或版本边界问题 | 停止处理，解除阻断后重新开始 |

AI不得填写或决定验收结论。结论必须由对应人工责任主体记录。

## 九、关闭证据

每个关闭项至少保留：

- 问题编号；
- 原问题和影响；
- 处理动作；
- 修改后的对象和字段；
- 依据或确认记录；
- 处理人和时间；
- 复核人和时间；
- 关闭条件检查结果；
- 关联文件名、版本和SHA-256。

模型评分、结构自检通过或语言表达改善不能单独作为业务问题关闭证据。
