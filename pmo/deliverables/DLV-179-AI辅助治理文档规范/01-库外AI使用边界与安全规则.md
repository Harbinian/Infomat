# 库外AI使用边界与安全规则

## 一、适用对象

本规则适用于各业务部门、MDM工作组、数据质量工作组和PMO在公司代码仓库之外使用第三方或公共AI服务辅助流程和数据治理的场景。

“库外AI”是指不能直接读取Infomat仓库真源、运行规则和受控状态的AI服务。该AI只能依据本规格包和用户本次提供的材料工作。

## 二、开始前的四个检查

部门编制人在上传任何材料前，必须完成以下检查：

| 检查项 | 必须回答的问题 | 不满足时的处理 |
| --- | --- | --- |
| 授权 | 本人是否有权把材料用于本次AI辅助工作？ | 不上传，先取得材料责任人或管理要求规定的授权 |
| 敏感性 | 材料是否包含禁止外传或未经批准处理的内容？ | 不上传；改用经批准的摘录、脱敏样例或人工说明 |
| 最小化 | AI完成本次任务是否真的需要整份材料和全部数据？ | 只提供完成任务所需的最小范围 |
| 可读性 | 材料是否可以直接读取文字、表格或流程节点文本？ | 登记为`blocked_unreadable`，由资料责任人提供可读原件或人工确认文字版 |

## 三、禁止输入

未经公司有权主体明确批准，不得向库外AI输入：

- 国家秘密、涉密工作信息或密级不明的材料；
- 商业秘密、未公开经营信息、价格策略、投标底价、未公开技术方案；
- 客户、供应商或合作方要求保密的材料；
- 个人敏感信息、完整花名册、身份证件、联系方式、薪酬、健康、银行账户等信息；
- 生产账号、密码、API Key、令牌、Cookie、私钥、连接串或其他凭据；
- 未经批准的完整生产数据库导出、运行日志、附件目录或源代码包；
- 无法确认所有权、授权范围或使用目的的第三方材料。

材料是否可以使用存在疑问时，部门编制人不得自行判断为“可以”。应先停止上传，并向材料责任人、保密管理、安全管理或项目管理责任主体确认。

## 四、允许输入的处理方式

在材料已经授权的前提下，部门编制人仍应执行最小化和脱敏：

1. 删除与本次流程无关的章节、附件和历史版本。
2. 用稳定占位符替换姓名、工号、电话、账号、客户名称、供应商名称和具体金额，例如“人员A”“供应商A”“金额区间A”。
3. 保留流程理解必需的角色、部门、条件、字段含义和先后关系，不得因脱敏删除业务逻辑。
4. 只提供能证明当前问题的样例行，不上传整库或全量台账。
5. 在任务单中记录删减和替换内容，使业务核对人知道AI看到的材料与原件存在什么差异。

占位符不得伪装成真实业务事实。AI输出引用占位符时，部门复核记录应说明该内容只用于结构核对，正式事实仍回到受控原件确认。

## 五、不可读来源

图片、扫描件、无文本PDF、损坏文件和无法直接提取文字的流程图不得用于自动形成正式候选。处理规则如下：

1. AI或编制人将来源状态登记为`blocked_unreadable`。
2. 不从文件名、目录名、缩略图或模糊画面推断流程事实。
3. 不把图像转文字或自动识别结果直接当作已核验证据。
4. 资料责任人提供可直接读取的原件，或提供经过人工逐项核对的文字版后，重新开始材料整理。

## 六、库外AI的权限边界

库外AI可以：

- 追问流程边界、业务行为、责任岗位、表单、字段、数据来源、异常和完成标准；
- 从可直接读取的材料中摘录候选事实并保留来源位置；
- 生成待确认问题、结构缺口和可能的对象拆分建议；
- 按附带结构规则生成未审核候选JSON。

库外AI不可以：

- 确认业务事实、部门职责或跨部门责任；
- 认定主数据、权威来源、唯一标识、责任部门或质量规则；
- 根据名称或相似度合并数据对象；
- 根据岗位名称生成正式工作角色编码；
- 选择OA、MES、PLM、ERP或其他系统作为未来承载系统；
- 生成审核通过、批准、发布、生效或已导入3000等状态；
- 写回仓库、数据库、PMO台账或业务系统。

## 七、服务和会话记录

部门编制人应记录AI服务名称、模型名称或版本、使用日期、提示词版本、输入材料清单和输出文件。不得在记录中保存API Key、密码或其他凭据。

部门编制人还应核对所用AI服务的数据使用、留存、训练、访问和删除说明。服务规则不清或不符合公司要求时，不得输入业务内容。

AI聊天页面、服务端历史和浏览器历史不是治理证据。需要交接时，部门编制人应主动下载或整理本次输出，并计算文件SHA-256。未主动保存的内容不得假定可以恢复。

## 八、发生异常时

| 异常 | 立即动作 | 后续动作 |
| --- | --- | --- |
| 误上传禁止内容 | 停止会话和继续传播；按公司安全或保密要求报告 | 依据服务能力申请删除，保留事件处置记录，不在普通问题台账复制敏感正文 |
| AI补造事实 | 标记相关输出无效 | 回到原材料和业务人员重新核对，重新生成候选 |
| AI把建议写成现状 | 撤销该状态表述 | 分别写入“当前事实”和“改进建议” |
| AI自动合并同名对象 | 保留原对象，撤销合并 | 依据业务含义、生命周期、唯一标识、责任边界和使用场景形成待定匹配问题 |
| 输出无法通过结构规则 | 不进入后续交接 | 修正技术标识、枚举和引用；业务未知值继续保持待确认 |
| AI服务版本发生变化 | 停止沿用旧会话结论 | 记录新版本，使用同一输入做最小回归核对后再继续 |
