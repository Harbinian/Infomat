## 六、PMO 治理与调研授权口径

PMO 的治理对象为流程、数据、证据、责任边界和项目履约状态。PMO 可基于项目需要，对项目及各部门开展以下治理和调研活动：

| 方式 | 适用场景 | 输出记录 |
| ---- | -------- | -------- |
| 现行流程治理 | 制度、实际做法、表单台账、会议记录和现场执行不一致 | 现行流程治理记录、流程断点清单 |
| 录音录像 | 关键访谈、业务演示、争议事项复核和纪要校核 | 录音录像登记表、纪要校核记录 |
| 全日跟产或参会 | 观察真实业务节奏、等待、返工、交接和会议决策链 | 现场观察记录、会议观察记录 |
| 业务行为模拟 | 用样例单据推演申请、审批、变更、异常、关闭全过程 | 业务行为模拟记录 |
| 历史不符合项推演 | 从典型历史问题倒推流程断点、数据断点和责任边界 | 历史不符合项推演记录 |

上述记录用于流程地图、数据地图、风险台账、问题台账、变更台账、责任池台账和阶段门评审，不作为个人绩效或情绪化追责材料。

---

## 七、责任池口径

启动期建立项目责任池。凡在启动、调研、流程地图、数据地图和现状盘点阶段暴露的历史流程问题、历史数据问题、跨部门边界问题、表单台账不一致问题和历史不符合项，原则上先进入责任池治理。

除以下三类执行问题外，责任池内事项一律不追责：

1. 拖期：逾期未提交、逾期未反馈、逾期未确认，且未提前说明原因或申请协调。
2. 交付物未交：应提交的清单、记录、模板、确认单、台账、材料未提交。
3. 提交材料质量过于低劣：空白、明显与任务无关、关键字段大量缺失、无法追溯来源、经一次退回后仍不能支撑下一步评审。

责任池不是免做池。进入责任池的事项仍需记录、分级、确认责任边界并制定治理动作。
