# 调研模板与访谈提纲

| 项目 | 内容 |
| ---- | ---- |
| 交付物编号 | DLV-901 |
| 关联 WBS | 1.2.1.2 调研模板与访谈提纲编制 |
| 计划完成时间 | 2026-07-06 |
| 主责 | 信息化项目组 |
| 协作 | 信息化项目管理工作室 |
| 审核 | 信息化项目管理工作室 |
| 执行标准 | STD-PLAN-001；STD-INTV-001 |
| 完成判定 | 模板覆盖流程、系统、数据、接口、问题 |
| 当前状态 | 已提交可执行评审版，待 PMO 评审后定版 |

本文件承接 DLV-004 的五类专项范围，先把调研时必须收集的信息固定下来。它不是访谈结论，也不替代后续会议纪要、资料回执和正式评审结论。

## 一、使用边界

| 可以用于 | 不用于 |
| -------- | ------ |
| 统一各专项调研提问和记录格式 | 直接形成系统选型结论 |
| 提醒部门准备流程、数据、表单和系统证据 | 替部门确认最终责任人 |
| 让访谈结果能沉淀为标准信息 | 替代访谈纪要和评审纪要 |

## 二、通用调研模板

| 字段 | 填写要求 | 输出去向 |
| ---- | -------- | -------- |
| 调研专项 | 数据与主数据、PLM、MES/低代码、ERP/OA、基础设施与 IT 资源之一 | 调研总表 |
| 被调研部门或工作组 | 写部门或工作组名称；联系人未确认时写待指定 | 资料清单和日程表 |
| 业务场景 | 写实际工作场景，不写抽象模块名 | 流程地图 |
| 现行流程 | 谁发起、谁处理、谁审核、谁接收结果 | 流程责任矩阵 |
| 数据对象 | 组织、人员、物料、项目、工装、设备、供应商、客户等 | 数据地图 |
| 关键字段 | 字段名称、业务含义、维护人、使用系统、是否必填 | 字段台账 |
| 表单或台账 | 源文件名称、编号、版本、页码或表格位置 | 证据链 |
| 系统现状 | 当前使用系统、Excel、纸质单据或线下沟通方式 | 系统现状清单 |
| 接口和重复录入 | 哪些地方重复录入、手工搬运或需要接口 | 接口差距清单 |
| 问题和风险 | 返工、等待、绕行、口径冲突、无证据场景 | 问题台账 |
| 权限和确认 | 谁能看、谁能改、谁最终确认 | 权限和责任边界 |

## 三、访谈提纲

| 主题 | 必问问题 | 证据要求 |
| ---- | -------- | -------- |
| 流程责任 | 这件事谁发起、谁审核、谁执行、谁接收结果 | 制度条款、表单签批、系统截图或会议确认 |
| 数据来源 | 这个对象或字段从哪里来，谁维护，多久更新 | 台账、系统导出、表单样例 |
| 表单和台账 | 当前使用哪些制度、表单、Excel 或手工记录 | 源文件名称、编号、版本、存放位置 |
| 系统使用 | 当前在哪个系统处理，哪些环节仍在线下 | 系统截图、操作记录或业务说明 |
| 接口和协同 | 是否跨部门、跨系统、跨供应商传递数据 | 上下游交接记录或接口说明 |
| 异常处理 | 出错、缺资料、责任不清时怎么处理 | 问题单、补充说明或责任池记录 |
| 审核确认 | 访谈结论谁确认，哪些问题需要升级 | 确认记录、评审意见或待办项 |

## 四、五类专项提示

| 专项 | 重点追问 |
| ---- | -------- |
| 数据与主数据 | 组织、部门、岗位、人员、物料、供应商、客户、项目等对象是否有统一编码、状态和维护责任 |
| PLM | 图文档、EBOM、设计变更、适航追溯和采购衔接是否能追到源文件 |
| MES/低代码 | 生产计划、派工、报工、质量闭环、仓储和工装现场记录是否能在线留痕 |
| ERP/OA | ERP U8 模块、OA 流程、计划采购库存和财务口径之间是否重复录入或口径不一致 |
| 基础设施与 IT 资源 | 服务器、虚拟化、网络、安全域、机房条件、备份容灾和供应商输入是否有书面证据 |

## 五、待确认事项

| 事项 | 当前口径 | 处理方式 |
| ---- | -------- | -------- |
| 各部门联系人 | 仍以 DLV-004 的待指定项为输入 | 进入资料清单和日程表继续跟踪 |
| 资料存放位置 | 部分材料位置未确认 | 在 DLV-902 中列为待回执 |
| 访谈日程 | 需由 PMO 统一发出会议安排 | 在 DLV-903 中形成拟排期 |
| 评审结论 | 尚未形成正式评审纪要 | 在 DLV-904 中作为待评审内容 |

## 六、评审检查清单

| 检查项 | 通过标准 | 不通过处理 |
| ------ | -------- | ---------- |
| 调研范围 | 五类专项均有对应问题、对象和证据要求 | 退回补充缺失专项，不进入访谈执行 |
| 业务对象 | 部门、工作组、供应商接口和待指定联系人均有跟踪位置 | 将缺失对象登记到 DLV-903 或整改清单 |
| 问题可回答 | 每个主题都能用业务人员可理解的句子提问 | 改写为具体场景，不使用系统模块口号替代 |
| 证据可取得 | 每个问题至少对应制度、表单、台账、截图、导出记录或会议确认之一 | 在 DLV-902 增补资料项或标记为会中确认 |
| 输出可沉淀 | 访谈结果能进入流程地图、数据地图、字段台账或问题台账 | 明确输出去向后再执行访谈 |
| 边界清楚 | 文件不写成访谈已完成、结论已确认或评审已通过 | 保留待确认状态，待实际证据补齐后更新 |

## 七、访谈记录表

| 记录字段 | 现场填写要求 | PMO 核验要求 |
| -------- | ------------ | ------------ |
| 访谈场次 | 写专项、时间、会议方式和参会部门 | 与 DLV-903 日程或会议邀请一致 |
| 受访对象 | 写部门、角色或工作组；未到具体人员时写待补实名 | 后续补会议签到或确认记录 |
| 业务行为 | 写“谁在什么场景下做什么”，不写空泛模块名 | 能映射到流程地图或待建流程 |
| 数据对象和字段 | 写对象、字段、来源、维护人和使用去向 | 能进入数据地图或字段台账 |
| 证据材料 | 写源文件名称、编号、版本、页码、表格位置或系统截图说明 | 与 DLV-902 回执或现场材料一致 |
| 问题描述 | 写影响业务执行的具体问题和发生环节 | 可登记到问题台账，能指定责任跟踪 |
| 待确认项 | 写待补资料、待确认责任人、待升级事项 | 必须有责任方和下一步时间 |

## 八、执行闭环规则

| 输出 | 责任方 | 关闭证据 |
| ---- | ------ | -------- |
| 访谈纪要 | 信息化项目组 | 纪要文件、参会确认或会议记录 |
| 资料缺口 | 信息化项目组、资料责任部门 | DLV-902 回执、补充资料或缺口说明 |
| 待办和风险 | PMO、相关专项工作组 | 周会行动项、整改清单或责任池记录 |
| 流程和数据沉淀 | 信息化项目组、MDM 工作组 | 流程地图、数据地图、字段台账或问题台账更新记录 |
| 评审结论 | 信息化项目管理工作室 | DLV-904 评审纪要、整改项和关闭状态 |
