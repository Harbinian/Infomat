# AI辅助治理文档规范

| 项目 | 内容 |
| --- | --- |
| 交付物编号 | DLV-179 |
| 关联任务 | WBS 4.7.1 AI辅助治理文档整理规范制定 |
| 责任部门 | MDM工作组 |
| 协作范围 | 技术架构组、数据质量工作组、各业务工作组、各业务部门 |

| 当前版本 | V0.1 编制中 |
| 使用场景 | 各部门在仓库外使用AI辅助梳理一个真实业务流程及其数据、表单、证据和待确认事项 |

## 一、交付结论

本交付物把仓库中的流程治理、数据治理、证据、组织、版本和安全边界整理为一套可带出仓库使用的规格包。各部门可以把规格包与经授权、已脱敏、可直接读取的业务材料一并交给库外AI，由AI追问和整理候选内容。

库外AI只负责发现信息缺口、整理候选结构和生成待确认问题。业务部门确认本部门事实，MDM工作组检查结构并组织治理，PMO跟踪责任人、期限、证据和关闭条件，有权主体作出治理决定。AI输出不是正式流程、正式数据地图、主数据认定、系统选型结论或批准记录。

本稿为编制中版本。部门试用时应保留“未审核”标识；信息化项目管理工作室和数据质量工作组评审通过前，不得把本规格包描述为公司正式发布的AI治理制度。

## 二、文档包组成

文档包入口位于 [DLV-179-AI辅助治理文档规范/README.md](DLV-179-AI辅助治理文档规范/README.md)。包内文件分为四组：

1. 使用规则：安全边界、统一治理口径、组织和版本基线。
2. AI规格：可复制核心提示词、单流程工作SOP、输出字段和结构要求。
3. 人工控制：复核、验收、待确认、异常和升级规则。
4. 配套文件：任务单、事实采集表、待确认事项台账、会话交接记录和结构规则快照。

## 三、适用范围

本规格包适用于：

- 依据制度、规程、表单、台账、流程图节点文字、文本型PDF和人工业务说明，整理L3业务流程及A1业务行为候选；
- 记录流程中的业务对象、数据输入输出、表单主表和明细表、字段取值来源、创建更新使用关系；
- 发现跨部门位置、流程条件、退回、异常、待补证据和待确认事项；
- 为后续3001单流程编制、部门业务核对、MDM结构核验和PMO行动项提供未审核输入。

本规格包不适用于：

- 向外部AI提交国家秘密、商业秘密、个人敏感信息、客户或供应商敏感信息、凭据或未经授权材料；
- 让AI确认部门职责、业务事实、主数据分类、唯一标识、权威来源、责任部门或未来系统归属；
- 让AI直接修改仓库流程输入基线、3000数据库、PMO台账或任何正式发布记录；
- 把图片、扫描件或无文本PDF交给AI自动识别后直接作为正式证据；
- 把AI生成的JSON直接描述为已通过3001技术校验、部门审核或3000受控导入。

## 四、统一工作链路

| 阶段 | 责任主体 | 主要动作 | 输出 | 完成条件 |
| --- | --- | --- | --- | --- |
| 1. 建立任务 | 部门编制人 | 选择一个真实L3流程，填写任务单，确认材料授权和脱敏状态 | AI任务单、材料清单 | 范围、编制人、业务核对人和禁止输入已经写明 |
| 2. AI追问与整理 | 库外AI、部门编制人 | AI按规格逐项追问；编制人只提供已知事实或明确写“待确认” | 对话记录、候选结构、待确认问题 | AI未补造事实，所有候选能追溯到材料或具名业务说明 |
| 3. 部门事实核对 | 部门业务核对人 | 回到源文件或实际做法核对流程、岗位、表单、字段、异常和跨部门位置 | 部门复核记录 | 已确认项写明确认主体和依据；未知项仍保持待定 |
| 4. 结构核验 | MDM工作组 | 检查引用、对象拆分、字段归位、证据状态和待确认问题 | 结构问题清单 | 硬性结构错误为零；业务提示未被误写成结论 |
| 5. 3001编制 | 部门编制人 | 将候选导入或录入3001，在当前页面内存中修改并下载未审核v6 JSON | 未审核v6 JSON、SHA-256交接信息 | 3001技术校验通过，下载后重新导入核对内容和引用 |
| 6. 交接与跟踪 | 部门、MDM工作组、PMO | 分别交接JSON、问题记录、部门复核记录；PMO登记需跟踪事项 | 交接记录、行动项 | 文件、版本、摘要、责任人、期限和关闭条件一致 |

## 五、关键边界

1. 当前分析对象是流程和数据，不是应用系统。系统名称只记录数据当前在哪里产生、保存、使用或传递。
2. 一次只处理一个真实流程。制度跨多个L3流程时，AI可以先形成多个候选，但进入3001前必须拆成一份文件一个流程。
3. 自动抽取只能形成待复核候选。只有人工回到可直接读取的原文位置确认后，证据才可以标为`verified`。
4. 名称相同不能证明两个数据对象相同。AI不得自动合并对象、认定主数据、确认权威来源或确定责任部门。
5. 当前事实、治理结论和改进建议分别保存。建议未经批准不得写成现状或已安排动作。
6. 3001当前输出`process-governance-v6`，下载JSON是唯一保存方式；v6不能直接导入当前3000。3000当前只承接v1至v3并统一保存v3。
7. 3001 v7生命周期设计尚未实现。AI可以把生命周期线索列为待治理问题，但不得向v6 JSON添加不存在的v7字段。

## 六、评审与生效

本稿当前状态为“编制中”。正式使用前应完成以下评审：

1. 信息化项目管理工作室核对责任、推进和交付边界。
2. 数据质量工作组核对数据对象、字段、证据、待定状态和验收规则。
3. MDM工作组使用至少一个跨部门真实流程试跑完整链路。
4. 试跑人员核对库外AI是否遵守安全、证据和人工确认边界。
5. 评审意见关闭后，按PMO交付物流程提交、评审和批准。
