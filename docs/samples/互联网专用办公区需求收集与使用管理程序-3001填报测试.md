# 互联网专用办公区需求收集与使用管理程序

> 测试用途：本文件用于 3001 文档结构化输出辅助服务的填写测试，不是公司已发布制度，也不是流程输入基线。
>
> 使用方法：在 3001 页面选择“导入制度文件”，导入本文件。导入后应看到 3 条业务流程。将流程三中的“确认本次使用是否具有业务必要性”“核对所选业务流程是否需要重新评审”和“评审业务流程变更内容”设置为判断节点，检查判断分支是否在当前步骤下方自动出现，再检查表单和字段，最后导出结构化文件。

制度编号：CX-BDV-INET-001

制度名称：互联网专用办公区需求收集与使用管理程序

版次：A

归口部门：经营发展部

相关部门：行政人事部、工程技术部、质量管理部、财务部、物资保障部、项目管理部、复材车间、运维安环部

目的

收集公司各部门使用公共互联网的业务需求，形成建设容量、使用范围和管理要求。互联网专用办公区内的办公电脑只连接互联网，不连接公司内网、生产网、涉密网及其他受控网络。

适用范围

适用于各部门提出互联网访问需求，以及互联网专用办公区的建设、启用、预约、使用和记录管理。涉及国家秘密、未经批准的内部资料上传、双网连接、个人热点或者绕过安全控制的需求不适用本程序。

术语和定义

互联网专用办公区：公司设置的受控办公场所，场所内的办公电脑只连接互联网。

互联网办理流程清单：经过业务必要性、保密要求和信息安全要求审核后，列明可以在互联网专用办公区办理的业务流程及其现行使用要求的清单。

流程变更记录：记录业务流程的网站、软件、数据类型、上传下载方式或者其他控制要求发生变化的受控记录。

职责

经营发展部负责发布调查、检查填报完整性、汇总公司需求、组织联合评审、维护互联网办理流程清单和流程变更记录，并安排日常使用时段。

各部门需求联络人负责汇总本部门需要使用互联网办理的业务流程，经部门负责人确认后统一提交。

行政人事部保密管理人员负责核对保密要求，信息化工作组信息安全责任人负责核对网络、终端、账号、日志和数据传输要求。

基础设施工作组负责场地勘察、建设方案、设备配置、实施协调和技术验收。

互联网终端管理员负责人员核验、终端登记、现场检查、故障处理和使用记录维护。

工作流程

阶段一：公司级需求收集与联合评审

行为1：发布互联网使用需求调查

执行角色：经营发展部需求管理员

触发场景：公司决定启动互联网专用办公区首次建设。

前置条件：调查范围、提交期限和部门需求联络人要求已经确定。

输入材料：《互联网业务流程需求调查表》

输出结果：需求调查通知、部门需求联络人清单

执行标准：通知应写明纳入范围、禁止事项、填报字段和提交期限，各部门在5个工作日内提交。

行为2：汇总并确认部门业务流程需求

执行角色：各部门需求联络人 / 各部门负责人

触发场景：收到经营发展部发布的互联网使用需求调查通知。

前置条件：本部门申请人已经说明业务目的、目标网站、人员范围和数据类型。

输入材料：《互联网业务流程需求调查表》、业务办理说明

输出结果：经部门负责人确认的部门互联网使用需求清单

执行标准：每个部门只提交一份汇总清单，每一行对应一个具体业务流程；只写“需要上网”的需求不得提交。

行为3：检查需求完整性

执行角色：经营发展部需求管理员

触发场景：收到部门负责人确认的部门互联网使用需求清单。

前置条件：部门名称、需求联络人和部门负责人确认信息齐全。

输入材料：部门互联网使用需求清单

输出结果：完整性检查结果、退回补充事项

执行标准：按照表单填写要求检查内容；退回时说明具体不符合内容。

行为4：组织保密与信息安全联合评审

执行角色：经营发展部需求管理员 / 行政人事部保密管理人员 / 信息化工作组信息安全责任人

触发场景：部门需求通过完整性检查。

前置条件：目标网站、使用频次、上传下载、软件外设和数据类型已经填写。

输入材料：公司互联网使用需求汇总表、完整性检查结果

输出结果：互联网办理流程清单、流程使用要求、退回意见、专项评审清单

执行标准：联合评审应逐项说明业务流程是否允许办理、需要采取的控制措施和责任人；涉及涉密信息、双网连接或绕过安全控制的需求不得纳入互联网办理流程清单。

阶段二：办公区建设与启用

行为5：编制建设方案和容量建议

执行角色：基础设施工作组

触发场景：联合评审形成互联网办理流程清单和峰值并发需求。

前置条件：经营发展部已经合并重复业务流程需求，并确认预计使用人数、频次和业务截止时间。

输入材料：互联网办理流程清单、公司互联网使用需求汇总表、容量测算表

输出结果：互联网专用办公区建设方案、设备清单、预算建议

执行标准：终端数量按峰值并发测算；建设方案应写明场地、网络隔离、账号、终端配置、日志、数据传输和异常处置要求。

行为6：审批建设方案

执行角色：公司授权审批人

触发场景：基础设施工作组提交建设方案、设备清单和预算建议。

前置条件：保密要求、信息安全要求和现场条件已经形成书面意见。

输入材料：互联网专用办公区建设方案、设备清单、预算建议

输出结果：批准意见、退回意见或者暂缓意见

执行标准：按照公司现行预算和授权规则办理；未批准的方案不得采购设备或者实施建设。

行为7：实施建设并完成联合验收

执行角色：基础设施工作组 / 行政人事部保密管理人员 / 信息化工作组信息安全责任人

触发场景：建设方案获得批准。

前置条件：场地、预算、设备和实施计划已经落实。

输入材料：经批准的建设方案、设备清单、验收检查表

输出结果：验收记录、终端台账、首批开放安排

执行标准：验收应确认办公电脑无法访问公司内网、生产网、涉密网及其他受控网络；人员、终端、时间和业务流程能够对应；阻断项未关闭前不得开放使用。

阶段三：日常预约、使用与关闭

行为8：提交互联网专用办公区使用预约

执行角色：使用人

触发场景：使用人需要通过互联网专用办公区执行一项已纳入互联网办理流程清单的业务流程。

前置条件：使用人能够在互联网办理流程清单中选择本次实际执行的业务流程。

输入材料：《互联网专用办公区使用预约单》

输出结果：待部门负责人确认的使用预约

执行标准：常规预约至少提前1个工作日提交；申请人只选择业务流程，不填写内部流程编码、流程版本或者额外的办理目标。

行为9：确认本次使用是否具有业务必要性

执行角色：使用人所在部门负责人

触发场景：收到本部门使用人提交的使用预约。

前置条件：预约单中的申请人、申请部门、业务流程、使用日期和预计时长已经填写。

输入材料：待部门负责人确认的使用预约

输出结果：同意意见、退回补充意见或者不同意意见

执行标准：部门负责人确认本次使用是否具有实际业务需要；同意后进入业务流程变更判断，退回时说明需要补充的内容，不同意时结束本次申请。

行为10：核对所选业务流程是否需要重新评审

执行角色：经营发展部需求管理员

触发场景：部门负责人同意本次使用预约。

前置条件：互联网办理流程清单和流程变更记录可以查询。

输入材料：经部门负责人同意的使用预约、互联网办理流程清单、流程变更记录

输出结果：无需重新评审意见或者需要重新评审意见

执行标准：所选业务流程的网站、软件、数据类型、上传下载方式和其他控制要求均未发生需要重新评审的变化时，进入使用排期；存在需要重新评审的变化时，只对变化内容进行联合评审。

行为11：评审业务流程变更内容

执行角色：行政人事部保密管理人员 / 信息化工作组信息安全责任人

触发场景：经营发展部需求管理员确认所选业务流程存在需要重新评审的变化。

前置条件：流程变更记录已经说明变化内容、变化原因和影响范围。

输入材料：经部门负责人同意的使用预约、流程变更记录、现行流程使用要求

输出结果：允许使用意见、退回补充意见、不允许使用意见或者转专项处理意见

执行标准：联合评审只审查本次变化内容；允许后进入使用排期，退回时说明补充要求，不允许时结束本次申请，需要独立方案时转专项处理。不得回跳并重新启动阶段一或阶段二。

行为12：安排使用时段

执行角色：经营发展部需求管理员

触发场景：所选业务流程无需重新评审，或者变化内容已经通过联合评审。

前置条件：使用预约已经取得部门负责人同意，且不存在待处理的联合评审事项。

输入材料：经确认的使用预约、终端可用情况

输出结果：使用时段、终端安排

执行标准：按照业务截止时间、终端可用情况和提交顺序安排；无法按申请时段安排时，应与申请人确认替代时段。

行为13：办理到场核验和终端交接

执行角色：互联网终端管理员

触发场景：到达已安排的使用时段。

前置条件：预约状态为已排期，指定终端处于可用状态。

输入材料：已排期的使用预约、终端台账

输出结果：到场核验结果、指定终端

执行标准：核对使用人、预约单号、业务流程、终端编号和计划时段；不得借用他人账号，不得把终端交给未登记人员使用。

行为14：受控使用互联网终端

执行角色：使用人

触发场景：使用人通过到场核验并取得指定终端。

前置条件：使用人已经了解禁止事项，需要的外部业务账号已经准备完毕。

输入材料：已排期的使用预约、指定终端、必要的外部业务账号

输出结果：业务办理结果或者异常报告

执行标准：使用人只执行预约单绑定的业务流程并遵守现行使用要求。发现异常弹窗、误传、疑似泄密、违规外联或设备故障时，应立即停止操作并报告。

行为15：检查终端并关闭使用记录

执行角色：互联网终端管理员

触发场景：使用人完成本次操作或者报告异常。

前置条件：使用人已经退出外部业务账号并交还指定终端。

输入材料：预约单号、终端编号、业务办理结果或者异常报告

输出结果：《互联网专用办公区使用记录》、异常处置记录

执行标准：登记实际开始时间、实际结束时间、完成情况和异常情况，检查终端状态并关闭使用记录；存在异常时按异常处置要求移交，不得直接标记为正常完成。
