## 3. 页面和定位测试数据

每条 `prompt` 必须提供唯一问题事实和至少一条建议。测试程序至少验证：

- 基础字段定位到`input`、`select`或`textarea`；
- 行为、关系、数据、承接和表单问题先选中稳定引用对应对象，再定位实际控件；
- 多字段问题分别提供`focusPaths`，不得只高亮整个分区；
- 没有具体控件的结构性问题才退回对象卡片或分区；
- 定位后设置键盘焦点和`aria-invalid="true"`；
- 用户启用减少动画时保留静态红色外框，不播放呼吸动画；
- 定位和高亮不调用内容修改函数。

## 4. 旧文件兼容测试

实现评审准备功能后，测试人员继续验证：

1. 上一受支持v1文件导入后在当前页面内存中升级，导出当前v4；
2. v2多流程文件拆分为单流程候选，逐个导出v4；
3. v3和旧v4文件导入当前版本后，除合法导出时间外内容和稳定引用一致；
4. 未收录岗位、填写项类型、历史工作角色、参考材料和内部流程调用原样保留；
5. 迁移或检查失败时源文件不变，当前页面内容可以继续处理；
6. 重复执行检查和兼容转换不产生重复对象。
7. 业务行为逐动作可执行性、评审图例、循环退出和并行中止检查只读取既有字段、节点与关系；v1、v2、v3和旧v4不增加迁移字段，普通导出确认框保持既有提示范围。

## 5. 试点测试与技术测试分离

上述测试数据只能证明规则实现和无损兼容。三条真实流程试点还必须分别形成部门业务核对、3000预览、审核导入、发布前评价、部门确认、跨部门双方确认和发布记录。自动化结果不得替代这些记录。
