# 2026-06-17 文档过时风险审查提炼

> 范围：根目录入口文档、`docs/**/*.md`、`pmo/**/*.{md,html}`、`apps/**/README*.md`
> 目标：提炼“跨库通用的过时/误导风险模式”，并落档本次审查结论摘录。
> 备注：本报告不联网校验外部 URL 可用性；仅基于仓库当前文件与配置一致性审查。

## 1. 一般性问题提炼

### 1.1 高优先（会直接误导使用或造成跨环境失效）

- **文档使用本机绝对路径（`file:///...` / 盘符绝对路径）作为跨人协作入口**
  典型风险：链接在他人机器、CI、GitHub/Code Viewer 中必然失效；读者会误判“仓库缺文件/路径”。
  建议口径：仓库内导航一律使用相对路径；仅在“本机脚本/调试说明”中允许出现绝对路径，且需明确为示例。
- **运行口径（端口/启动方式/访问地址）与实际配置不一致**
  典型风险：读者按文档操作无法启动或访问，排障成本高；多个 README/CLAUDE 互相打架时会放大误导。
  建议口径：以实际配置（如 Vite `vite.config.js`、`package.json` scripts）为准，文档只保留一个“默认访问地址”，其余作为“可能变化”说明。
- **“规则文档”与“真实实现/资产位置”冲突**
  典型风险：规则被当作唯一真源后，会指导出错误的相对路径、错误的目录归属或错误的修改点。
  建议口径：规则文档中所有路径示例需可在仓库中被证实（存在且与实现一致）；对关键静态资产引用规则（如 `echarts.min.js` 相对路径）应以实际页面为准抽样回归。
- **文档引用不存在的文件/目录（断链），且上下文未标注“历史/待补”**
  典型风险：读者把缺失文件当成当前必备规范，导致错误追溯或重复造文档。
  建议口径：引用前先确认文件存在；若为“规划中的文件名”，必须在同段落显式标注“当前不存在/待补齐”。

### 1.2 中优先（易造成“把历史当现行”的误读）

- **计划/草稿文档缺少醒目的状态标识与适用范围**
  典型风险：读者只打开单文件就把阶段计划当成当前承诺或执行口径。
  建议口径：所有计划类文件开头固定包含“状态（草稿/暂停/已废止/仍执行）+ 最后确认日期 + 适用范围”。
- **待办池/候选池未被明确定位为 backlog**
  典型风险：候选映射、待处理清单被误读为“已确认规则/已完成成果”。
  建议口径：待办池文件在标题或首段明确“这是 backlog，不是已确认映射”；并给出维护节奏或迁移入口。
- **目录命名口径并存（同义目录同时出现）**
  典型风险：检索与归档口径漂移，后续迁移/脚本引用时产生“看起来像重复但其实是不同阶段”的噪音。
  建议口径：对“预留/未来目录”统一写法；如目录当前不存在，应明确“尚未创建”并避免与现有目录并列呈现为同等真源。

### 1.3 低优先（对新读者有干扰，但不致命）

- **历史记录/阶段产物里保留过多本机路径、一次性命令、临时目录名**
  典型风险：全文检索命中噪音高，后续审计会被大量“非现行口径”淹没。
  建议口径：历史文件允许保留原样，但应在目录级 README 明确其为历史，并建议读者以边界文件为准。
