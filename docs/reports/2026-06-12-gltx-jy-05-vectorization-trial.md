## 5. 试验判断

本次单文档向量化是有效的，尤其适合：

1. 从抽象词反查具体对象，例如 `绩效结果` 召回 `公司月度综合打分表`。
2. 从审批词反查同一对象的控制链，例如 `财务核对 / 分管领导审核 / 总经理批准`。
3. 从表单名称反查正文条款、表格和归档描述。
4. 查找“可能不存在”的证据，例如 `通报 / 发布 / 签收` 未命中，可提示继续人工核验或标记待补。

但它也暴露了边界：

1. 向量分数不能证明对象同一性。
2. 相近文本不能证明输入来源部门或输出目标部门。
3. `下发` 命中不等于“绩效结果下发”，必须看对象。
4. 归档、审批、保存、适用范围都不能自动变成受控传递关系。
5. Word 表格抽取存在少量缺字，例如 `公司 月综合打分表`，正式引用前必须回看原文版面。

## 6. 后续建议

1. 将 `.docx` 抽取能力纳入正式向量预处理脚本，而不是只靠临时抽取。
2. 对每个待确认召回结果增加 `verification_status` 字段：`unverified` / `source_checked` / `rejected`。
3. 在桑基图 H5 中只显示已回看原文的待确认；未核验待确认放在“待确认证据/待核验”面板，不进入正式链路。
4. 全量处理 norms 前，先用 3 类样本文档回归：正文型、表格/表单密集型、流程图/附件型。
