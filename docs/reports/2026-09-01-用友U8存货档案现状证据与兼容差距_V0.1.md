# 用友 U8 存货档案现状证据与兼容差距

> 文档状态：V0.1 审核稿；只读证据报告，不是整改结果或业务验收  
> 审核日期：2026-09-01  
> 目标：判断 U8 现状能否支持航空存货主数据源头编码设计，并列出正式启用前必须补齐的兼容证据  
> 建议方案：[航空存货主数据分类与编码规则——源头设计 V0.1](../integration/航空存货主数据分类与编码规则_源头设计_V0.1.md)  
> 本次操作：未写数据库，未修改 U8 配置，未改 Excel，未改历史报告

## 1. 审核结论

当前 U8 `Inventory.cInvCode` 能唯一识别当前存货档案行，字段长度也能容纳建议的新码 `MAT-0000000001`。但 U8 当前存货分类、名称、规格、自定义项和能力开关不能直接成为新的企业物料身份规则。

主要依据如下：

- 2026-09-01 较晚只读快照中，`Inventory`、`Inventory_Sub` 各有 6,565 条，`InventoryClass` 有 146 条；
- `cInvCode` 为 `nvarchar(60)`，当前 6,565 个编码无空值、无重复；
- 现码长度为 2 至 39，包含 33 条小写编码、689 条不符合“大写字母/数字/连字符”候选字符集的编码及 1 条双连字符编码；
- 名称重复 726 组、涉及 3,598 条；名称加规格重复 464 组、涉及 2,563 条，只能形成查重候选；
- `cInvStd` 缺少有效值 4,356 条，说明规格字段当前不足以独立支撑身份判定；
- 146 个分类节点混入物料形态、项目、研发阶段、用途、来源和资产属性，不能直接编码为永久身份；
- `cInvDefine9` 含“客供”的 865 条记录只是自由文本线索；其中 62 条当前未启用批次，不能据此直接判断来源、所有权或追溯要求；
- `bSerial=1` 为 0 条，`bInvKeyPart=1` 为全部 6,565 条且默认值为 1，两者都不能替代工程和质量确认。

因此，U8 适合作为历史编码和存货运行事实的一个来源，不适合作为新编码语义的唯一来源。建议采用无分类语义的新码、保留旧码别名，并把分类、用途、供给、所有权、批次、序列和 BOM 关系分别治理。

## 4. 表和字段关系

### 4.1 物理对象

| 对象 | 当前证据 | 结论 |
|---|---|---|
| `dbo.Inventory` | 主键 `cInvCode`；257 字段 | 当前 U8 存货主档物理表 |
| `dbo.Inventory_Sub` | 与 `Inventory` 当前 6,565 个键一一对齐；114 字段 | 扩展表；当前未发现数据库外键，不能只依赖应用约定 |
| `dbo.InventoryClass` | 146 条分类记录 | 当前 U8 分类真源，不是企业技术分类真源 |
| `dbo.Ca_Inventory` | 38 字段视图 | 查询投影；视图字段不能代替物理字段和来源关系 |
| `dbo.BufferInventory` | 早期快照 6,140 条，与主表不完全一致 | 历史/缓存候选；不得当主档镜像直接覆盖 |

`Inventory.cInvCCode` 到 `InventoryClass.cInvCCode` 存在外键，但该外键当前 `is_not_trusted=1`，且主表列允许空。较晚快照未发现空分类或孤儿分类，只能说明当前样本对齐，不能证明约束可信或未来写入安全。

### 4.2 与新码直接相关的字段

| 字段 | 当前情况 | 对新方案的含义 |
|---|---|---|
| `Inventory.cInvCode` | `nvarchar(60)`，当前唯一 | 14 字符 `MAT` 新码可放入；历史码不改写 |
| `Inventory.cInvName` | 大量重复 | 名称不是唯一身份键 |
| `Inventory.cInvStd` | 大量空白 | 规格字段需要分对象必填规则和数据补证 |
| `Inventory.cInvCCode` | 当前无空、无孤儿 | 保留历史兼容；不写入新码 |
| `Inventory.cInvAddCode` | 空白多，且有重复 | 可作为别名线索，不能直接升格为企业编码 |
| `Inventory.cInvDefine9` | 自由文本含“客供”等 | 只用于人工复核，不自动推断来源或所有权 |
| `Inventory.bInvBatch` | 需结合对象和质量要求判断 | 主档开关不是批次事实本身 |
| `Inventory.bSerial` | 当前全部未启用 | 不等于业务没有单件追溯要求 |
| `Inventory.bInvKeyPart` | 当前全部为 1 | 默认值无区分度，不能作为关键件证据 |

## 6. 数据质量判断

### 6.1 可以安全使用的事实

- 当前 `cInvCode` 在所审计时点唯一；
- 当前字段类型和长度能够容纳 14 字符建议新码；
- 当前分类、名称、规格、自定义文本和能力开关的分布可以用于识别治理风险；
- 当前 `Inventory` 与 `Inventory_Sub` 键集合对齐；
- 当前 146 个分类节点没有孤儿引用。

### 6.2 只能作为候选或线索的内容

- 同名、同规格、同辅助代码记录；
- 分类名称中的项目、阶段、客供、自制、设备或工装信息；
- `cInvDefine9` 中的来源说明；
- `bPurchase`、`bSelf`、`bInvBatch`、`bSerial`、`bInvKeyPart` 等开关；
- U8 帮助资料中描述但尚未证明公司启用的 BOM、版本、工程变更和供应类型能力。

### 6.3 当前不能得出的结论

- 6,565 行等于 6,565 个不同企业物料身份；
- 2,563 条名称加规格重复记录可以直接合并；
- “客供”文本等于客户所有权或真实收货来源；
- 全部记录都是关键件；
- 当前没有单件序列追溯需求；
- U8 当前已经承载 EBOM、PBOM、MBOM 的正式闭环；
- 当前分类可作为企业永久技术分类；
- 新码已获得下游系统或业务验收。

## 7. 新编码兼容性

建议格式：

```text
MAT-0000000001
```

### 7.1 已证实

| 检查 | 结果 |
|---|---|
| U8 字段长度 | `nvarchar(60)` 可容纳 14 字符 |
| 字符类型 | `M`、`A`、`T`、数字和半角连字符可由 Unicode 文本字段保存 |
| 当前唯一性 | `cInvCode` 当前唯一；新码必须继续执行唯一约束 |
| 历史字符兼容 | 旧码字符多样，不应因新规则批量清洗 |

### 7.2 尚未证实

| 检查对象 | 必须取得的证据 | 未完成影响 |
|---|---|---|
| PLM/PDM/CPM | 字段长度、字符集、大小写、主键和接口约束 | 不能宣布设计源头贯通 |
| MES/工艺系统 | 物料字段、BOM 引用、标签和扫码 | 不能宣布制造侧兼容 |
| U8 接口和二次开发 | API、导入模板、报表、单据、SQL 类型和长度 | 不能仅凭主表字段上线 |
| 打印与条码 | 标签宽度、字体、Code 128/二维码和扫描精度 | 不能确认现场可用性 |
| 外部客户/供应商交换 | 件号和企业码的字段区分、最大长度 | 不能把企业码冒充客户件号 |
| 历史 BOM 和单据 | 引用量、活动状态、冻结期和回退 | 不能批量改码或合并 |

## 8. 历史过渡差距

| 差距 | 风险 | 控制措施 |
|---|---|---|
| 企业物料身份尚未建立 | U8 行被误当成物料身份 | 先做对象判断和身份核验 |
| 旧码别名关系未建立 | 新旧系统无法稳定对照 | 建立带证据和状态的别名关系 |
| 分类维度混杂 | 分类变化诱发改码 | 新码不含分类；建立分类映射 |
| 规格大量空白 | 判重和采购错误 | 按对象类型制定条件必填规则 |
| 重复候选量大 | 自动合并破坏历史引用 | 人工核验并保留合并/拆分审计链 |
| 客供文本与批次不一致 | 来源和所有权混淆 | 核对订单、收货、库存和客户资料 |
| 序列/关键件开关缺乏区分 | 追溯不足或过度控制 | 工程和质量按对象重新确认 |
| BOM 真实对象未探查 | 物料变更影响不明 | 在实施前盘点 BOM 表、版本、引用和生产订单 |

## 9. 实施前必须完成的只读盘点

1. 采购订单、到货、检验、入库、库存、批次、序列号和所有权相关表族；
2. 生产订单、领料、退料、实耗、实装、代料和偏离表族；
3. U8 BOM、BOM 版本、工程变更、替代和供应类型的真实使用情况；
4. PLM/PDM/CPM、工艺、MES、标签和接口字段；
5. 活动项目、未结单据、当前库存和历史归档的引用量；
6. 代表性原材料、标准件、设计件、外购件、组件、消耗品、工装和服务样例；
7. 所有一对多、多对一和证据不足的旧码候选。

每项盘点必须记录物理表/字段、业务含义、数据量、主外键、空值、重复、引用关系、责任人、证据时间和限制。没有恢复方案和 dry-run，不得进入批量迁移。
