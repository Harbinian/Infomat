# 工程技术部候选源归属确认检查表

> 日期：2026-06-11  
> 范围：只为工程技术部候选源归属确认提供检查表。  
> 边界：本表不补写工程技术部 DCM/BBM，不把外部参考材料直接纳入 `docs/norms/工程技术部业务资料/`，不修改 PMO 或 MDM 快照。

## 1. 确认原则

候选材料只有同时满足以下条件，才可从“参考线索”升级为工程技术部流程证据：

| 条件 | 判定问题 | 不满足时处理 |
|---|---|---|
| 所有者明确 | 文件是否由工程技术部或其职责承接组织维护？ | 保持待业务确认 |
| 适用范围明确 | 文件是否适用于昌兴当前工程技术部，而不是客户方、外部单位或历史部门？ | 作为外部参考，不进入工程技术部 DCM/BBM |
| 版本明确 | 文件是否有版本、日期、清单或确认记录？ | 标为待复核，不作为正式依据 |
| 流程证据充分 | 文件是否包含角色、输入输出、表单、审批、移交或记录载体？ | 只作背景材料，不拆 A1 |
| 可追溯 | 后续映射能否回指到文件路径、标题、页签、节点或条款？ | 先补提取记录，再建映射 |

## 2. 候选组确认表

| 候选组 | 当前状态 | 需确认对象 | 确认可接受证据 | 确认后处理 |
|---|---|---|---|---|
| 科技创新部一图三表与信息流图 | 待业务确认 | 是否与昌兴工程技术部职责等同、部分重叠或仅为外部参考 | 部门负责人确认、项目组织说明、制度目录、流程清单或来源交接说明 | 若确认纳入，逐文件登记到工程技术部 source manifest；若部分纳入，列出纳入/排除文件 |
| 数字工程部一图三表与信息流图 | 待业务确认 | MBOM、ERP 物料主数据、工时定额、代用管理是否归工程技术部或其他数据治理角色 | 部门职责说明、主数据职责矩阵、系统维护职责、流程页签说明 | 若确认纳入，优先提取字段和主数据对象；不直接生成 L3/A1 |
| 集成研发工艺性审查候选 | 待业务确认 | 工艺性审查是否属于工程技术部职责，或属于研发外部参考 | 研发/工程接口说明、审查流程责任人、审批或交付记录 | 若确认纳入，先建立单流程提取记录，再进入 DCM/BBM |
| 工艺/主数据编码类根目录文档 | 待业务确认 | 是否为工程技术部正式制度、数据规范背景，还是跨部门通用参考 | 文件所有者、适用范围、制度编号或发布记录 | 多数情况下只进入 MDM 要求或术语背景，不单独支撑流程 |
| 供应链协同平台管理制度 | 待业务确认 | 其中工艺、生产异常、协同场景是否有工程技术部受控动作 | 制度条款、责任部门、表单或系统记录 | 只抽取有明确责任和交付物的片段 |

## 3. 文件级确认要求

对每个拟纳入文件，至少补齐以下字段后再进入工程技术部映射：

| 字段 | 填写要求 |
|---|---|
| 文件路径 | 仓库相对路径 |
| 文件名称 | 完整文件名 |
| 候选组 | 科技创新部 / 数字工程部 / 集成研发 / 编码规范 / 其他 |
| 归属结论 | 纳入 / 部分纳入 / 排除 / 待业务确认 |
| 归属依据 | 业务确认记录、制度条款、职责说明或来源说明 |
| 可用证据 | 流程图节点、页签、表头、角色、表单、输入输出、审批或移交 |
| 后续动作 | 提取流程图 / 提取表格 / 建 DCM / 建 MDM 要求 / 排除 |

## 4. 当前禁止动作

- 不从其他部门跨部门引用反推工程技术部流程。
- 不把科技创新部、数字工程部或集成研发名称自动改写为工程技术部。
- 不直接在 `docs/norms/` 新增工程技术部 canonical 三件套。
- 不为消除 PMO 高风险项而手工补 dashboard 或 JSON。

## 5. 下一步

1. 先按候选组取得业务归属确认。
2. 对确认纳入或部分纳入的文件建立文件级确认表。
3. 对 `.xlsx` 汇总清单读取页签、表头和流程编号，作为 `.vsd` 信息流图的配套索引。
4. 完成文件级确认后，再创建工程技术部 DCM/BBM 草稿。
