# docs/reports 说明

> 状态：审计与整改记录目录  
> 生效日期：2026-06-10  
> 范围：仓库边界、流程输入基线缺口、质量审计、安全整改和迁移提案。

本目录用于保存阶段性审计结论、整改分流和迁移提案。这里的文件可以引用真源、解释风险和记录处理状态，但不替代任何真源文件。

## 1. 口径边界

| 报告类型 | 作用 | 不承担 |
|---|---|---|
| 仓库边界审计 | 记录目录、运行产物、重复资产和文档漂移问题 | 不直接移动资产 |
| 流程输入基线缺口审计 | 记录缺失部门、历史别名和跨部门风险来源 | 不补写部门映射 |
| 质量或证据审计 | 汇总 DCM/BBM、A1 或跨部门证据问题 | 不替代标准映射 Markdown |
| 整改分流报告 | 跟踪问题层级、状态和已完成小片 | 不作为产品需求或流程输入基线 |
| 迁移提案 | 说明后续迁移待确认和风险 | 不等同于已执行迁移 |

## 2. 真源仍在原目录

- 组织真源：`docs/organization/组织架构和部门职责.md`
- 流程输入基线：`docs/norms/{部门}部门-能力-流程-系统映射关系.md`
- PMO 驾驶舱：`pmo/procedure-management/dashboard.html`
- MDM 平台：`apps/mdm-platform/`

修改上述真源时，应按对应目录的 README 或 AGENTS.md 执行验证。

## 3. 命名规则

新增报告优先使用：

```text
YYYY-MM-DD-topic.md
```

报告标题和正文应写清：

1. 审计范围。
2. 数据来源。
3. 已确认、待复核、过时或延后的结论。
4. 是否改动了真源或只做只读分析。

大体量报告可以保留在本目录，但需要在正文说明生成方式和复现命令。
