# 3000 后端鲁棒性与流程、数据治理功能评估

评估日期：2026-10-10  
主责资产：`apps/mdm-platform`；运行目标：`http://127.0.0.1:3000`  
报告性质：技术评估与整改建议，不是业务事实、治理决定、正式发布或业务验收依据。

## 1. 结论

**当前服务能够响应基础健康与就绪请求，但不宜据此认定全部治理功能已开启、权限边界完整或已具备生产容量。** 本轮列出 13 项问题及风险：高 5 项、中 7 项、低 1 项。其中高风险包括 3 项隔离复现的缺陷，以及 2 项尚未开展破坏性验证的可用性风险。

最应优先处理的是：

1. **版本历史读取缺少与正文一致的对象、部门授权**。部署源码在合成会话下返回了异部门历史值。
2. **部署版工作包写入存在撤权竞争窗口**。真实隔离 MySQL 中，请求等待业务锁期间撤销角色、改变 `authVersion`，释放锁后仍创建了任务。工作树已有事务内授权复核并通过相关测试，但未部署。
3. **登录限流可由账号空白变体绕过，且没有并发准入限制**。顺序同键第 9 次请求被限流，但 10 个空白变体及同键 16 个并发失败请求均进入验证并返回 401。
4. 业务数据库访问和旧 Excel 导入尚未形成统一的资源上限。会话、就绪和现代证据解析已有较好的隔离机制，不能将这些局部保障推广到全部接口。

功能上，3000 已实现较丰富的**流程编制成果接收、修订核对、审核发布、固定版本溯源、数据定义、映射、定向事实核对、问题处置和分析任务管理**。未找到将业务流程图直接执行为生产办理实例的通用工作流引擎，也未找到跨 PLM、MES、ERP 自动采集运行时数据血缘、实时数据质量监控和完整外部告警闭环的实现。

本轮只新增本报告和隔离评估证据，没有修复服务代码、修改正式业务记录、重启或替换 3000，也没有暂存、提交或推送。

### 3.2 已有防护

- 会话采用 MySQL 持久化、SID 哈希和最小字段存储；登录重新生成会话，失效授权与禁用账号可使会话失效。HTTPS 模式具备受控代理、Secure/HttpOnly/SameSite Cookie；本机 HTTP 是受限运行模式。
- 已有 CSRF 校验、固定权限模型、管理员治理只读、部门范围和部分事务内身份复核，不能概括为“没有认证授权”。
- 大量 SQL 使用参数绑定；部分动态表名来自白名单。数据库结构校验为只读，运行启动不自动迁移。
- 正式版本绑定修订号、内容摘要及核对记录；新增模块使用请求标识、幂等回执、乐观并发、事务及事件。
- 旧字段批量导入仓储使用内容/上下文摘要、命名锁和原子写入；已分类死锁、锁等待及提交结果不明，不能概括为“旧模块没有事务保障”。
- Excel/DOCX/PDF 证据解析采用工作线程或子进程、文件和展开限额、并发门禁、超时与输出限制。PDF 不执行脚本、XFA 等，Word 拒绝外部实体声明；这些措施不等于旧台账导入也已采用相同保护。
- 分析任务具有租约、令牌隔离、心跳、有限重试、取消、部分覆盖和成功证据保留，不以失败或缺覆盖推断问题已经解决。

## 4. 问题与风险清单

评级为本次技术优先级：高表示可能跨越授权边界或显著影响服务可用性；中表示异常处理、兼容、恢复或验证保障不足；低表示纵深防护可改进。不是 CVSS 评分，也不是法规合规评级。

下文 `D/` 指本轮容器源码快照 `artifacts/mdm-3000-assessment-20261010/runtime-server/`；`W/` 指当前 `apps/mdm-platform/server/`。部署快照行号用于固定证据，工作树行号可能随既有修改变化。

### R01 高：历史接口缺少对象范围授权

**证据：部署源码隔离 HTTP 已复现，工作树仍有同类逻辑。**

位置：`D/routes/versions.js:26-65`、`D/auditMysqlRepository.js:101-117,176-181`；工作树对应 [versions.js](../../apps/mdm-platform/server/routes/versions.js) 和 [auditMysqlRepository.js](../../apps/mdm-platform/server/auditMysqlRepository.js)。

`/api/versions/mapping/:id`、`/field/:id` 仅验证登录；通用 `/entity/:type/:id` 只对少数类型另作过滤。仓储按类型、ID 查询，没有传入对象或部门范围。知道或猜中 ID 的登录用户可能绕过正文读取限制，访问历史旧值、新值或操作信息。

修复建议：以实体类型白名单分派授权策略；先核对对应正文或合法历史归属，再查询历史。已删除对象必须有可验证的保留归属，不能默认开放。三个入口统一策略，避免修复一个仍可从通用入口绕过。

关闭条件：全局、同部门、异部门、无读取权、管理员、删除对象六类身份/对象组合测试；不允许的访问不返回任何历史值，且无存在性差异泄漏。不得删除旧历史来消除漏洞。

### R02 高：部署版工作包写入在锁等待后未复核授权

**证据：部署仓储配合真实隔离 MySQL 已复现；工作树有修复并通过 30 项相关检查，未部署。**

位置：`D/processDataGovernanceRepository.js:59-65,231` 起；工作树 [currentWriteActor](../../apps/mdm-platform/server/processDataGovernanceRepository.js#L71) 及 queue、materialize、候选、事实答复、完成入口。

部署版保留调用时的 person/department/role，路由授权之后等待业务锁，事务内不重读账号授权。测试确实观察到锁等待，随后撤销角色并将 `authVersion` 从 1 改为 2，释放锁后仍产生 1 条任务。

修复建议：在事务内按统一锁顺序核对当前主体、账号、部门、角色、强制改密和授权版本，并拒绝管理员治理写入。沿用工作树已实现机制，但发布前对部署候选全链复验，不能仅复制一个函数。开关未开启时属于潜在暴露，不应误报已发生正式越权。

关闭条件：撤权、调部门、禁用、改授权版本与各写动作的真实锁竞争均拒绝；业务、审计、任务无部分写入；精确操作者可追溯；核对目标镜像摘要确认修复实际部署。

### R03 高：登录限流标准化不一致，缺少并发准入及存储上限

**证据：部署源码隔离 HTTP 已复现绕过；存储增长为源码风险。**

位置：`D/security.js:5-7,43-81`，`D/routes/org.js` 的 `loginWithMysqlIdentity`。

查询账号使用 `trim()`，限流 key 保留原始空白。同一账号可被计入多个窗口。失败计数在异步校验完成后增加，因此并发请求在计数更新前均被放行。Map 没有全局容量和周期过期清理，随机账号还可持续增加条目。

修复建议：登录校验和限流共用账号规范化规则；按 IP 和规范化账号设置独立有界窗口及同时校验数；准入先计数，完成后按策略更新；设置过期回收、最大容量和 429 的重试提示。是否采用集中存储取决于部署形态，不在本报告直接决定系统选型。

关闭条件：10 个空白变体、16 个并发错误密码和大量随机账号均受控；并发密码计算数和限流存储量有明确上限；合法用户解锁和共享出口误封场景可解释。

### R04 高：业务数据库访问缺少统一等待上限和连接预算

**证据：部署源码确认；250 ms 悬挂分支观察；未做全业务池耗尽压力测试。**

位置：`D/mysqlConfig.js:1-14`、`D/auth.js:186` 及各领域 `createPool`。对照已有 `D/boundedMysql.js`、`D/mysqlSessionStore.js`。

通用业务配置启用 `waitForConnections`，未显式限制排队长度和查询总时限；多个领域分别创建池。驱动连接超时不能替代池等待、锁等待和查询时限。数据库故障时可能累积排队、请求和连接，同时 health 继续成功。

修复建议：按领域设置连接预算、最大队列和总操作 deadline，统计全进程池总量；超时后终止相应连接或操作，不能只对 Promise 返回失败而让后台写继续。写事务必须区分未提交、已提交和提交结果不明；后者通过请求标识查回执，禁止盲目重试。

关闭条件：池耗尽、锁等待、连接黑洞、恢复和提交回执丢失场景中响应有界、队列有界、无迟到非预期写入；读写失败码及重试规则一致。会话、就绪已通过的保护应保留。

### R05 高：旧字段台账导入仍在 HTTP 主线程执行无展开预算的解析

**证据：部署源码确认；未执行压缩炸弹或耗尽内存测试。**

位置：[旧导入路由](../../apps/mdm-platform/server/routes/import.js)，部署 `D/routes/import.js:10-13,70-111`。

上传限制为 5 MB 文件大小，内存接收后在主线程执行 `workbook.xlsx.load`、遍历所有行，没有与现代证据解析相同的 ZIP 展开、单元格总量、线程超时和并发限制。压缩后小文件仍可产生较大解析成本。写入权限在解析前核对，但文件接收发生在该领域权限核对之前。

修复建议：复用有界 Excel 解析基础设施，补齐 files/fields/parts、展开大小、工作表、行列、文本和解析输出限制；设置全局解析并发门禁。保留旧模板、UUID 幂等、上下文哈希和原子导入语义。发布目录解析已有 ZIP 中央目录及行列限制，不应误判为完全无保护，但也可统一隔离执行。

关闭条件：截断 ZIP、超大展开比、超量工作表/单元格、并发上传及取消均有界失败，不阻塞普通业务；解析失败时不产生字段、对象或导入批次的部分写入。

### R06 中：异常日志既有漏记，也有原始驱动对象输出

**证据：部署源码隔离 HTTP 已复现。**

位置：`D/index.js:121` 起全局异常处理、`D/routes/org.js:30,56`；多个路由的 `console.error(error)`。

两次普通 JSON 解析异常进入全局处理却没有日志；另一方面未分类合成驱动异常的 SQL 属性原样进入 console。响应正文没有泄露诊断文本，但日志若采集原始 SQL，可能包含业务值或数据库内部信息。现有业务事件不替代请求级诊断，worker 的安全事件模式也未统一到各路由。

修复建议：增加请求关联号、路由模板、耗时、状态、分类错误码和最小操作者标识；通过允许字段列表输出诊断，不记录密码、Cookie、CSRF、正文、原始 SQL 参数或 claim token。记录拒绝访问、限流、解析失败、提交不明和 worker 恢复，并明确保留期与读取权限。

关闭条件：异常请求可由响应关联号追到安全日志；敏感标记扫描为零；数据库故障时日志失败不能掩盖原始业务结果。日志轮转及集中存储须另核部署配置。

### R07 中：普通解析错误与登录类型错误分类不准确

**证据：部署源码隔离 HTTP 已复现。**

位置：`D/index.js:48-55,121` 起；`D/routes/org.js` 登录路径及 `D/auth.js` 密码验证。

普通畸形 JSON、大于 2 MB 请求分别应是客户端格式或容量问题，现返回 500；对象密码返回 503。错误分类会误导客户端重试与可用性监控。

修复建议：全 API 统一处理 body-parser 的语法、容量及不支持编码错误；在访问仓储和密码计算前校验凭据类型与长度；维持账号存在与否一致的失败外观。保留 analysis 的现有错误码兼容，必要时增加通用码而非静默替换。

关闭条件：畸形 JSON 400、过大请求 413、非法凭据类型 400；不访问数据库或执行 bcrypt；普通登录失败维持既定认证契约，客户端能正确区分重试与修正输入。

### R08 中：部署版身份 BIGINT 边界未与候选统一

**证据：源码确认边界拒绝或转换；未在正式数据上发现超界身份。**

位置：`D/auth.js:54-55`、`D/processDataGovernanceRepository.js:59-65`；对照工作树 `sessionSubject.js`、`identityMysqlRepository.js` 及 `currentWriteActor`。

部署版将账号及授权版本转换为 Number 后检查安全整数，超过 JavaScript 安全整数的合法数据库标识会被拒绝；部分主体归一化直接 Number 转换也存在精度丢失风险。工作树已有精确标识处理，相关事务测试覆盖 BIGINT，但不能外推部署版已支持。

修复建议：统一主体边界与 SQL 绑定的精确标识表示；迁移会话、审计引用和前端协议时保留旧值。不能通过截断、取默认值或创建新身份来掩盖不能转换的数据。

关闭条件：安全整数边界内外、相邻 BIGINT、人员账号及独立管理员分别验证，无身份合并、错误授权或审计错绑；旧会话按明确契约保留或显式失效。

### R09 中：全量导出缺少资源预算与断连处理

**证据：源码确认；未实测大数据集、客户端断连。**

位置：`D/routes/export.js:34-116`。

路由获取全部可见数据、内存构建完整工作簿并写入响应，没有明确行数、输出字节和并发预算；catch 未判断 `headersSent` 就发送 JSON。流已开始后失败不能再可靠改成 JSON 错误。

修复建议：先核验导出规模与范围，再采用分块或异步导出；设置资源配额和取消信号，客户端关闭后停止取数/生成。按响应是否已开始分别处理错误，避免二次发送。导出仍须遵守与在线数据相同的范围授权。

关闭条件：最大允许规模、超限、生成失败、半途断连及并发导出均可控；无未处理异常和持续后台耗用；下载状态能明确区分完成与中断。

### R10 中：分析列表可见性分页存在放大扫描成本

**证据：源码确认；未进行大规模数据基准测试。**

位置：`D/analysisApi.js:43-58` 的 `visiblePage`。

为避免隐藏记录泄露，代码逐批扫描并逐项解析权限，直到累计足够可见记录。大量不可见数据或较深 offset 可能触发许多查询和解析；页面条数上限不能约束内部扫描量。

修复建议：保持不泄露隐藏计数的原则，将可表达的授权范围下推查询；使用可见集合的稳定游标，并设置扫描及时间预算。不要以返回隐藏总数换取性能。

关闭条件：高比例不可见记录、深分页、并发查询时 SQL 次数、耗时和内存可预测，游标不跨越授权范围，不丢失合法可见记录。

### R11 中：关闭流程与 worker 数据库黑洞场景保障不完整

**证据：源码风险；正常 worker 停止和崩溃恢复已通过，数据库黑洞下全链退出未验证。**

位置：`D/index.js:24-27,131-151`，`D/analysisWorker.js:33-63`。

HTTP 关闭统一登记仅包括 readiness 和 session store，其他领域池未统一纳入；15 秒硬退出能限制进程退出等待，但不等于资源已按顺序排空。worker 在 `stop()`、心跳或等待 `busy` 完成期间仍依赖数据库调用返回，适配器可取消不代表数据库调用也可取消。

修复建议：集中登记各领域池和 worker 资源；停止准入、限定在途任务排空时间、保存可恢复状态、终止连接，再退出。数据库维护与心跳调用也应有 deadline。

关闭条件：正常停止、正在写入、正在解析、数据库暂停和恢复分别验证；重启后无重复完成、丢失成功证据或不明提交被自动重试。本轮没有据此声称已经发生连接泄漏。

### R12 中：就绪集成测试前置迁移漂移，发布证据链不完整

**证据：原测试失败，隔离诊断已确认原因。**

位置：[test-stage03-mysql-isolated.js:98-141](../../apps/mdm-platform/scripts/test-stage03-mysql-isolated.js#L98-L141)、[readiness.js](../../apps/mdm-platform/server/readiness.js)、[todoTermSourceMigration.js](../../apps/mdm-platform/server/todoTermSourceMigration.js)。

测试创建基础表和会话迁移，未应用 `2026-09-28-todo-term-source-v1`；基础表已有该列但缺迁移标记，当前 readiness 正确拒绝。专项脚本补齐该标记后 ready 通过。原测试在首个 ready 断言即退出，后续 TLS/重启/故障用例没有本轮证据。

修复建议：将测试前置迁移与显式维护入口共用、版本化；保留缺迁移时必须拒绝的负例，不放宽 ready 断言。整改后从头运行该套测试。发布证据同时绑定代码摘要、结构标记和启用能力，不能只引用旧测试名称。

关闭条件：新空库、已迁移库、缺标记、结构漂移分别得出预期结果；全套 Stage03 实际通过；目标 3000 的只读就绪复核与候选证据相匹配。

### R13 低：CSP 允许内联脚本，削弱纵深防护

**证据：源码确认策略；未发现或复现 XSS 注入点。**

位置：`D/security.js:9-17`。

`script-src 'self' 'unsafe-inline'` 不能阻止被注入的内联脚本。此项不等于已经存在 XSS。

修复建议：先盘点旧页面和新前端的内联依赖，迁移为静态脚本或 nonce/hash，再逐步收紧策略；避免直接收紧导致旧页面失效。

关闭条件：指定桌面 Edge 环境下全部保留页面可用，预期脚本被允许、非授权内联脚本被阻断，控制台无新增策略阻断错误。

## 6. 用户要求的核心能力覆盖

不计算单一“覆盖率百分比”：业务运行引擎与治理状态机、运行时血缘与材料溯源不是同一个分母，混算会误导范围判断。

| 核心能力 | 现有覆盖 | 缺口或边界 | 后续建议 |
|---|---|---|---|
| 流程编排 | 案例、修订、核对、正式提交/审核/发布及工作包状态流转 | 未找到通用 BPMN 执行、业务实例调度、补偿、生产任务执行器 | 先确认是否需要管理“流程定义”以外的实际业务实例，再决定是否另建或集成执行平台 |
| 流程状态监控 | 案例、核对任务、问题、工作包、分析 run、待办和角色工作台 | 不提供生产办理实例级追踪和统一 SLA 看板；health 不代表业务成功 | 先统一治理状态、失败原因、任务积压和依赖健康指标 |
| 数据全链路溯源 | 固定原文/来源、摘要、修订、审核、定义版本、映射、设计交接、分析证据和事件链 | 无自动采集跨系统表/字段变换及实际数据传输的端到端血缘 | 明确材料溯源、定义血缘和运行血缘的分别验收范围；逐个经授权连接器扩展 |
| 数据质量校验 | 结构、引用、摘要、操作约束、字段身份进度、规则发现、问题核对及处置 | 不覆盖所有业务语义、运行数据全量质量和实时异常；不可达规则未开启 | 由业务确认规则与例外，MDM 组织核验，再确定采样、阈值和整改闭环 |
| 数据权限管控 | 固定 RBAC/RACI、部门/对象范围、账号授权版本、部分事务内复核、管理员治理只读 | R01/R02 等边界缺陷；不等于数据库行级策略和动态敏感字段脱敏全覆盖 | 优先统一所有读取/写入/历史/导出授权及字段约束，随后按实际敏感性增加控制 |
| 数据合规审计 | 账号事件、业务版本和变更、核对及发布记录 | 不具备已验证的外部不可篡改存储、完整读取审计、保留销毁及法规映射 | 由有权主体确认合规范围与期限；技术侧补关联、脱敏、受控导出和防篡改保存 |

## 7. 优化实施方案

以下均为建议，不是已排期、已授权的生产操作。具体负责人、投入和日期待项目负责人确认；不能由本报告代替业务主体分配职责或决定系统选型。

| 阶段 | 建议实施范围 | 交付物与验收门槛 |
|---|---|---|
| P0：扩大使用前 | R01 历史授权、R02 事务内当前授权、R03 登录限流；审查尚未部署的身份修复 | 路由+仓储负例、真实锁竞争、限流并发与容量测试；候选镜像绑定摘要；未关闭高风险前不扩大相应功能暴露 |
| P1：可靠性基础 | R04 数据库预算、R05 导入隔离、R06 日志、R07 错误契约、R11 关闭恢复、R12 测试迁移 | 超时/断连/提交不明矩阵、解析限额、安全日志规范、全套 Stage03 通过；明确读写重试规则 |
| P2：兼容与规模 | R08 BIGINT、R09 导出、R10 可见性分页、R13 CSP | 受支持 V7/V8 与历史身份回归；接近约定最大数据量的持续压测；指定桌面 Edge 验证 |
| P3：业务能力增量 | 治理任务监控、告警、审计保留、可见能力状态；按确认需求扩展运行血缘或业务实例管理 | 每项先明确业务主体、触发条件、输入输出、异常和验收；不把建议能力伪装成现有功能 |

### 7.1 技术实施约束

1. 建立统一的请求主体、授权、事务和资源生命周期边界，逐领域迁移，不同时重写所有路由。
2. 读取、历史、导出、来源材料和任务详情使用同一范围判断；写动作仍在取得关键锁后核对当前权限与状态。
3. 数据库 deadline 必须覆盖获取、执行和收尾；查询可重试与非幂等写入分开。提交结果不明保留请求标识和可核查回执。
4. 兼容 V7 原文、摘要、审核历史、旧台账请求与固定版本引用。迁移不能静默清空或靠默认值掩盖未知内容。
5. 接口错误码、参数、状态、权限或数据结构改变时，同步 API 契约、迁移说明和测试。单纯内部实现调整不要求重写仍准确的说明。
6. 真实第三方服务接入前另做授权、数据最小化、超时、熔断、限流、重试幂等、失败回退及供应商不可用验证。不能为了满足清单自行开启外部调用。

### 7.2 候选发布与回退建议

1. 在不覆盖当前既有改动的前提下明确候选变更清单、依赖锁文件和源码摘要。工作树测试结果不能直接贴到旧容器名下。
2. 使用新建临时库验证从受支持旧结构到候选结构的迁移；对原文、摘要、版本链、身份、审计及任务计数作前后比对。
3. 在候选实例执行权限负例、并发竞争、故障注入、资源配额与恢复测试。仅在指定桌面规格进行界面回归。
4. 正式备份、维护窗口、迁移、开启功能、通知及发布须重新核对用户授权；由有权主体确认业务试用范围及验收。
5. 发布后核对目标 3000 的镜像/源码摘要、health、ready、功能状态及经授权的业务抽样；分别记录“已实现、已准备、已开启、已验收”。
6. 预先确定停止准入和回退条件：新增越权、摘要错绑、不可解释的数据差异、无法恢复任务或异常率超出确认阈值即停止扩大。已有新数据时不能直接回滚不兼容 DDL；优先保留数据、停止写入并采用经验证的前向修复或备份恢复方案。

### 7.3 需要业务或运维确认的事项

- 近期目标是完善治理办理，还是同时承担生产业务实例运行。后者会显著扩大流程、权限、补偿和运维责任。
- 哪些历史数据、字段和导出属于敏感范围；保留期限、审计读取权及外部保存要求是什么。
- 告警针对哪些事件、由谁接收和处理、何时升级；是否授权接入真实通知渠道。
- 支持的数据规模、并发用户、最大导入/导出、响应目标、恢复时间和可接受数据损失目标。
- 下一次发布采用哪些已完成的工作树加固，以及何时核验当前功能开关。未确认前不能把部署说明记录作为实时开启结论。
