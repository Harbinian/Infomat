## 1. 规范结论

企业物料编码只负责稳定识别技术对象，不负责解释项目、用途、来源、所有权、供应商、仓库、BOM层级或生命周期状态。新物料编码固定采用：

```text
<域>-<对象>-<8位流水>
```

例如，具有独立设计定义的试验件可以使用已确认的形式：

```text
PM-PRT-00001234
```

同一技术物料在试验和批产、公司自采和客户供应、公司所有和客户所有之间切换时，不改物料编码。用途通过多值适用关系管理；计划供给责任通过带场景和生效期的策略关系管理；实际来源和所有权通过收货行、批次、序列号或库存身份管理。

EBOM、PBOM、MBOM是三个独立、受控、可修订的BOM对象。EBOM回答“设计上由什么组成”，PBOM回答“如何制造、装配和检验”，MBOM回答“生产准备和制造执行使用哪套结构”。三者通过明确的来源版本和行级映射衔接，不得复制后失去来源，也不得由上游变化静默覆盖已发布或已投产的下游版本。

## 2. 依据及其使用边界

### 2.1 内部证据

- 当前U8存货档案、扩展表和分类表的DDL与最新只读统计；
- 2026-08-31 `Ca_Inventory` Excel冻结快照；
- [用友 U8 存货档案数据库表关系与字段关系探查报告](./2026-09-01-u8-inventory-archive-table-and-field-relationships.md)；
- [U8 本地帮助资料](../U8SoftHelp/md/BO_zh-CN.md)中关于BOM版本、状态、生效、替代、工程变更和供应类型的产品能力说明；
- 当前仓库的数据治理规则。业务事实、治理结论和改进建议必须分层，数据库实现不能单独证明业务权威性。

### 2.2 Boeing文件的正确用法

`D6-51991_Rev_P.pdf`可支持以下原则：

- 权威工程定义及派生数据在接收、转换、制造、检验和产品生命周期中保持完整；
- 制造工程、计划和检验派生数据能够追溯到明确的权威数据及修订；
- 权威数据和派生数据分别受控修订，BOM本身属于变更控制范围；
- 只有当前且已授权的数据可以用于生产和检验；预发布或仅供参考的数据不能作为验收依据；
- 非当前和过期数据应隔离、保留并可检索；
- 数据保存应具备访问控制、未授权修改防护、备份和恢复。

该文件没有直接定义 `EBOM`、`PBOM`、`MBOM`，没有规定我方编码格式，也没有规定三类BOM的具体转换或表结构。本规范的三层设计是我方依据上述控制原则形成的治理方案，不能写成Boeing原文规定。

### 2.3 Airbus文件的正确用法

Airbus采购条款PDF可支持以下原则：

- 产品应能追溯到所用原材料和适用文件；
- 合格证应按适用要求包含订单、零件号、数量和单位、制造日期、失效日期、批号、序列化标识或其他批次标识，以及批准人员信息；
- 质量和交付记录应保持可识别、清晰、可复制，并防止丢失、毁损、伪造、未授权修改和未授权访问；
- 批次、序列号、合格证和原材料文件应与实际交付或制造对象建立关系。

该文件没有定义BOM分层或工程BOM变更流程。条款中的五年期限用于保密义务，不能作为BOM、质量或追溯记录的保存期限。

## 3. 术语和对象边界

| 术语 | 本规范定义 | 不得混同 |
|---|---|---|
| 物料身份 | 由技术定义和互换性边界决定的稳定对象 | 项目、用途、供应商、仓库、批次或所有权 |
| 物料编码 | 企业对物料身份分配的不可复用标识 | 名称、分类、修订、图号或条码 |
| 物料修订 | 同一物料身份下受控变化的设计版本 | 新物料身份或物料编码 |
| 企业技术分类 | 只表达材料、零件、组件、产品、工装、服务等内在技术类别 | 试验/批产、自采/客供、项目或仓库 |
| 用途适用性 | 某物料在项目、产品或构型基线下允许用于研发、试验、试制、小批验证或正式批产的关系 | 物料身份和生命周期状态 |
| 供给责任 | 在指定组织、项目、订单或场景下由谁负责提供物料的计划策略 | 实际收货来源和库存所有权 |
| 实际来源 | 某次收货、制造或调入事实来自哪个主体和单据 | 主档的外购或自制能力 |
| 库存所有权 | 某批或某件实物归哪个主体所有 | 来源、供应商、仓库或库位 |
| EBOM | 已批准工程定义的产品结构 | U8“允许BOM母件”开关 |
| PBOM | 从指定EBOM发布版受控派生的工艺转化结构 | 一次性工单、实耗或实装记录 |
| MBOM | 从指定PBOM发布版受控派生并供生产准备和制造执行使用的结构 | 生产批次或As-built BOM本身 |
| 发布基线 | 某一BOM或物料修订在批准时冻结的不可变内容、状态和有效性 | 最后保存的工作稿 |
| As-built BOM | 某一批或某一序列化产品实际装入的物料、修订、批次、序列号、代料和返修事实 | 标准MBOM |

## 4. 物料身份和编码规则

### 4.1 身份判定

物料身份采用“形状、配合、功能和互换性”判定：

1. 变化影响形状、配合、功能或互换性时，新建物料编码，并建立替代、承接或不兼容关系。
2. 变化不影响物料身份时，沿用原编码并形成新的受控修订。
3. 名称、说明、录入错误等纠正事项如果不改变物料身份，只能通过受控更正处理，不得新建编码规避审批。
4. 名称、规格或图号相同不能自动合并物料；名称不同也不能自动认定为不同物料。
5. 普通材料仅因被试验任务使用，不产生新物料身份。具有独立设计定义、验收要求和互换性边界的试验件，按独立零部件对象编码。

### 4.2 编码格式

```text
<域>-<对象>-<8位流水>
```

| 组成 | 规则 |
|---|---|
| `<域>` | 来自MDM批准的域代码字典；只使用大写英文字母和数字 |
| `<对象>` | 来自MDM批准的对象代码字典；只使用大写英文字母和数字 |
| 分隔符 | 只能使用半角连字符 `-` |
| 流水 | 在“域＋对象”范围内顺序分配，固定8位，不足补0 |
| 总体字符 | 只能使用大写英文字母、数字和半角连字符 |
| 校验规则 | 使用格式校验、唯一性检查和条码/二维码，不增加校验位 |

格式校验表达式为：

```regex
^[A-Z0-9]+-[A-Z0-9]+-[0-9]{8}$
```

V0.1只冻结结构，不自行扩充域和对象代码。示例中的 `PM`、`PRT` 作为已确认形式保留；其正式中文全称、对象边界及其他代码值需要MDM工作组评审。字典未批准前，不得仅凭英文字面批量分配新码。

### 4.3 禁止进入编码的语义

以下内容不得作为编码数位：

- `RND`、`TEST`、`TRIAL`、`PILOT`、`SERIES`用途；
- 公司自采、客户供应、内部制造、委外等供给责任；
- 实际供应商、客户或制造组织；
- 库存所有权；
- 项目、产品构型、订单、合同、仓库或库位；
- EBOM、PBOM、MBOM层级；
- 草稿、发布、停用、替代、作废等生命周期状态；
- 物料修订、BOM修订或生效日期。

这些属性具有多值、上下文、时间或生命周期特征，写入编码会导致业务场景变化时改码、重复建码和历史引用断裂。

### 4.4 分配、冻结和作废

1. 编码由MDM统一分配，不允许个人、部门或用友管理员离线拼码。
2. 流水号只保证唯一，不表达数量、先后重要性或业务等级。出现间断属于正常现象。
3. 编码发布后保持不变。名称、规格、分类、用途、来源、仓库或状态变化不得改码。
4. 已发布、停用、作废或被替代的编码不得重新分配。
5. 申请被撤回但编码已经正式发出时，该编码继续保留为未使用或撤回状态，不回收给其他物料。编码预留超时规则属于系统设计事项，V0.1保持待确认。
6. 任何人工录入、导入和接口调用均应执行字符、段数、8位流水和全局唯一性检查。

### 4.5 历史编码过渡

现有U8编码采用“冻结并映射”方式：

- 不批量改写现有 `Inventory.cInvCode`；
- 建立 `MaterialCodeAlias`，保存企业物料身份、现用U8编码、其他历史编码、来源系统、状态、有效期和变更依据；
- 新增物料在域和对象字典批准后按新规则分配；
- 只有重复建码、身份边界错误或业务明确要求转换的记录，才通过受控变更单逐项处理；
- 历史单据和BOM继续使用原U8编码，通过别名映射识别同一企业物料；
- 现有 `cInvDefine9` 原值保留为历史证据，不自动生成用途、来源或所有权关系。

## 5. 分类、名称、规格和修订

### 5.1 双层分类

1. U8现有 `InventoryClass` 暂时保留，维持历史单据和现有业务兼容。
2. 企业技术分类只表达内在技术类别，不写项目、阶段、用途、来源、所有权、供应商或仓库。
3. 建立“现有U8分类—企业技术分类”映射，保留来源分类、目标分类、适用范围、确认人、批准人和有效期。
4. 立即停止新增“批产任务”“研制任务”“试验件项目”“客供半成品”等混合节点。
5. 不直接删除、改名或批量迁移现有分类。实施前必须形成引用影响、映射、例外和回退清单。

### 5.2 名称和规格

- 名称使用目标用户能够识别的标准名称，不把用途、项目、来源或仓库作为名称前后缀；
- 规格型号按材料、零件、组件和产品的识别要求条件必填；服务类等不适用对象说明不适用原因；
- 图号、标准号、材料牌号、尺寸和状态分别落字段或关系，不用一个长名称拼接所有属性；
- 名称或规格更正不自动触发新物料编码；是否新码仍由身份判定决定。

### 5.3 物料修订

物料身份和物料修订必须分开。每个修订至少保存：

- `material_revision_id`和所属`material_id`；
- 修订标识；
- 设计依据及其修订；
- 生命周期状态；
- 生效条件和失效条件；
- 变更原因、影响分析和变更授权；
- 编制、复核、批准和发布时间；
- 被替代修订及回退关系。

已发布修订不得原地修改。更正或变化从已发布修订创建新的工作修订，经过复核和批准后形成新发布版。

## 6. 用途、供给责任、来源和所有权

### 6.1 用途适用性

用途字典固定为：

| 代码 | 含义 |
|---|---|
| `RND` | 研发 |
| `TEST` | 试验 |
| `TRIAL` | 试制 |
| `PILOT` | 小批或批产验证 |
| `SERIES` | 正式批产 |

用途是多值关系。同一物料可以同时具有 `TEST` 和 `SERIES` 适用性，不因此拆码。每条用途关系必须包含物料、用途代码、项目或产品/构型基线、状态、生效期和批准记录。

系统实施阶段只有存在有效 `SERIES` 批准记录时，才允许该物料投向正式批产。物料具备生产订单资格或曾经被批产工单使用，不能替代该批准记录。

### 6.2 计划供给责任

计划供给责任至少区分：

- 公司自采；
- 客户供应；
- 内部制造；
- 委外；
- 其他经批准的供给方式。

供给责任按物料、项目/订单/组织场景和有效期管理。同一物料在A项目可以公司自采，在B项目可以客户供应，仍使用同一物料编码。`bPurchase`和`bSelf`最多作为U8能力开关或发布镜像，不能代替场景化策略。

`iSupplyType`不承担公司自采或客户供应语义。U8帮助将其用于BOM子件的入库倒冲、工序倒冲、领用、虚拟件或直接供应方式。

### 6.3 实际来源和库存所有权

实际来源和库存所有权必须分开保存：

- 实际来源说明这批或这件实物由哪个主体、哪张订单或哪次内部制造产生；
- `owner_party_id`说明该批或该件实物归谁所有；
- 仓库、库位和“客供库”只用于物理或账务隔离，不能替代所有权；
- 同一物料编码可以同时存在公司所有和客户所有库存，库存可用量必须按所有权、来源、项目和质量状态分开计算；
- 发料时，来源、所有权或用途与工单要求不一致，系统实施阶段必须阻断。只有取得受控替代或偏离批准后才能继续。

### 6.4 历史事实重建

- 新业务在实施阶段必须从首次收货或制造入库开始维护实际来源和所有权；
- 当前库存、在制品和活动项目需要依据订单、收货、批次、盘点和客户资料重建；
- 历史已关闭业务不从 `cInvDefine9`、分类名称或仓库名称自动推断；
- 证据不足时保留“待确认”，不得为了提高完整率填入默认主体。

## 7. 风险分级追溯

### 7.1 追溯级别

| 对象或条件 | 最低要求 | 说明 |
|---|---|---|
| 客供实物 | 批次 | 需要区分客户资产、来源、收货和领用去向 |
| 原材料 | 批次 | 按材料、炉批、批号和合格资料追溯 |
| 关键件 | 批次；需要单件履历时升为序列号 | `bInvKeyPart`默认值不能替代工程和质量确认 |
| 有保质期、材料声明、合格证或炉批要求 | 批次 | 记录制造日期、失效日期和关联文件 |
| 需要单件构型、单件质量或单件交付证明的产品和零部件 | 序列号 | 形成单件As-built BOM和质量履历 |
| 服务类和不形成库存实物的对象 | 不机械启用批次 | 必须说明不适用依据 |

追溯级别由工程、质量和物资责任人员依据物料类别、设计要求、合同和适用法律共同确认。系统默认值只用于提醒或候选，不代表审批结论。

### 7.2 最小追溯链

批次或序列号追溯至少应支持：

```text
物料及修订
  ↔ 订单/收货行或内部制造来源
  ↔ 实际来源主体与库存所有权
  ↔ 批次/炉批/序列号
  ↔ 合格证、材料声明、检验和质量记录
  ↔ 生产订单与实际采用的MBOM发布基线
  ↔ 实耗、实装、代料、偏离和返修
  ↔ 交付对象或上层序列号
```

### 7.3 例外与阻断

以下情况必须在系统实施阶段阻断：

- 没有有效 `SERIES` 用途记录却投向正式批产；
- 客户所有库存发给公司自有工单，或公司所有库存发给客户资产工单；
- 实际来源不满足工单或合同规定；
- 要求批次或序列追溯但未提供有效身份；
- 使用未发布、已替代、已作废或不在有效范围内的BOM版本；
- 临时代料或偏离没有批准记录。

阻断只能由具名、受控的替代、偏离或紧急授权解除。解除记录应保存原因、批准人、适用数量、批次或序列号、有效期和后续补救要求。

## 8. 逻辑数据对象

下列对象是业务和数据设计要求，不代表本次在U8数据库中建表。

| 逻辑对象 | 稳定身份和最小内容 | 来源与维护候选 | 状态、生效、变更和追溯 |
|---|---|---|---|
| `Material` | `material_id`、不可变物料编码、名称、规格、企业技术分类、状态 | 工程确认技术身份；MDM审核并发布 | 发布后编码不变；通过修订和变更单演进；关联历史别名 |
| `MaterialRevision` | `material_revision_id`、`material_id`、修订、设计依据 | 工程编制和确认；MDM校验身份关系 | 独立状态和生效条件；已发布不可原地修改；可反查BOM和变更 |
| `MaterialCodeAlias` | `alias_id`、`material_id`、旧码、来源系统、状态、有效期、变更依据 | MDM维护；源系统提供历史事实 | 不覆盖旧码；保存停用、替代和历史引用 |
| `MaterialUsageApplicability` | 物料、用途代码、项目/产品/构型基线、生效期、状态、批准记录 | 项目管理部确认场景；工程确认技术适用；MDM发布 | 多值；保留前后版本；`SERIES`是正式批产门槛 |
| `MaterialSourcingPolicy` | 物料、项目/订单/组织场景、计划供给责任、生效期、批准记录 | 经营发展部确认采购策略；内部制造范围由相关责任部门确认 | 策略变化不改码；保留有效期和历史批准 |
| `InventoryTraceIdentity` | 物料、收货行、批次/序列号、实际来源、`owner_party_id`、项目/订单、质量文件 | 物资保障部记录实物事实；质量管理部复核追溯证据 | 每批或每件独立；状态变化、调拨、领退和隔离均留痕 |
| `ControlledSubstitution` | 原物料、替代物料、适用项目/BOM、生效期、数量范围、原因、批准记录 | 工程和质量确认技术与质量影响；项目/物资按场景参与 | 临时和永久替代分开；到期自动失效；关联实装事实 |
| `ChangeAuthorization` | 申请、原因、影响对象、旧值、新值、影响分析、复核、批准、生效和回退 | 业务责任部门提出；MDM审查跨对象一致性 | 不可删除的变更链；关联物料、BOM、关系和执行结果 |

每个逻辑对象都必须明确：稳定身份、事实来源、维护责任、状态、生效条件、变更授权、历史保留和上下游引用。任何接口镜像字段不得在没有来源对象和版本的情况下升格为权威数据。

## 9. EBOM、PBOM和MBOM设计

### 9.1 共同规则

三类BOM分别拥有：

- 稳定 `bom_id`；
- 明确 `bom_type`；
- 独立 `bom_revision_id`和修订标识；
- 生命周期状态；
- 生效条件；
- 不可变发布基线；
- 来源BOM版本；
- 变更授权和被替代版本；
- 编制、复核、批准和发布时间；
- 内容摘要及附件清单。

BOM修订不得写入物料编码。BOM头、BOM行、物料修订、有效性和变更记录是不同对象，不能用一张无版本明细表替代。

### 9.2 EBOM

EBOM回答“设计上由什么组成”。已发布EBOM至少包含：

- 产品或装配对象及其修订；
- 父子结构、零部件及明确修订；
- 数量、单位、装配位置和设计适用范围；
- 图纸、模型、标准和规范等设计依据；
- 结构修订、状态、有效性和变更授权。

只有已审核批准并发布的EBOM基线可以派生PBOM。草稿、预发布或仅供参考的数据不得作为生产、检验或验收依据。

### 9.3 PBOM

PBOM回答“已批准设计结构如何制造、装配和检验”。PBOM从一个明确的EBOM发布版受控派生，可以：

- 重组装配层级；
- 拆分或合并工艺装配单元；
- 增加工艺件、过程件、辅料和中间交付物；
- 关联工艺路线、工序、工位、工装、设备和检验点；
- 设置制造用量、损耗和投料位置。

PBOM每个节点和结构关系必须保留到EBOM节点或结构行的映射。一对一、一对多和多对一均可，但必须可解释。PBOM新增而EBOM不存在的对象标记为“工艺新增”，保存新增原因和批准记录，不得伪造EBOM来源。

### 9.4 MBOM

MBOM回答“生产准备和制造执行使用哪套结构”。MBOM从指定PBOM发布版受控派生，至少表达：

- 制造场所或生产组织适用范围；
- 工序投料关系；
- 标准用量、基础数量和损耗；
- U8供应类型、倒冲或领用方式及替代规则；
- 制造版本、有效性和发布状态；
- 供ERP、MES、计划、采购和库存消费的发布数据。

只有当前有效且已批准的MBOM发布基线可以用于新下达生产。生产订单、工单、批次、序列号、实耗、实装、代料和返修是执行事实，不是MBOM主版本的组成部分；这些事实应关联实际使用的MBOM发布基线，并形成As-built BOM或实物履历。

### 9.5 BOM逻辑对象

| 对象 | 最小内容 | 控制要求 |
|---|---|---|
| `BOMDefinition` | `bom_id`、`bom_type`、产品/装配身份、业务范围 | 稳定身份；BOM类型发布后不得随意改变 |
| `BOMRevision` | `bom_revision_id`、修订、状态、有效性、来源修订、变更授权 | EBOM/PBOM/MBOM各自独立修订；已发布不可覆盖 |
| `BOMLine` | `bom_line_id`、父行/子物料及修订、数量、单位、位置、有效性 | 行身份稳定；结构变化保留前后版本 |
| `BOMDerivationMap` | 来源BOM行、目标BOM行、映射类型、原因、批准 | 支持一对一、一对多、多对一和工艺新增；可双向追溯 |
| `BOMBaseline` | `baseline_id`、冻结内容摘要、附件清单、发布人、批准人、发布时间 | 不可变；下游只消费明确基线，不自动取“最后修改版” |
| `ExecutionConfiguration` | 订单、批次或序列号、实际MBOM基线、实耗、实装、代料、偏离、返修 | 记录执行事实；支持As-built和质量反查 |

这些逻辑对象不代表本次要在U8中创建同名表。后续系统设计应先核对PLM、工艺系统、U8和MES现有能力，再决定权威源、发布接口和镜像位置。

## 10. BOM状态、派生和变更

### 10.1 生命周期状态

| 状态 | 是否可编辑 | 是否可用于下游 | 处理规则 |
|---|---:|---:|---|
| 草稿 | 是 | 否 | 仅编制人和授权协作者可编辑 |
| 评审中 | 受限 | 否 | 修改后重新提交评审；保留评审意见 |
| 已发布 | 否 | 是，受有效性限制 | 生成不可变基线和内容摘要 |
| 已替代 | 否 | 不用于新业务 | 历史订单继续引用；保留查询 |
| 已作废 | 否 | 否 | 记录作废原因；隔离但不删除 |

状态名称可在系统设计阶段与现有平台对齐，但语义不得合并。特别是“已保存”不等于“已发布”，“停用”不等于“删除”。

### 10.2 派生规则

```text
已发布EBOM基线
  → 创建PBOM工作修订并建立行级映射
  → PBOM评审与发布
  → 创建MBOM工作修订并建立行级映射
  → MBOM评审与发布
  → 生产订单绑定明确MBOM基线
  → 批次/序列形成As-built与质量履历
```

上游BOM变化只生成下游影响项：

- EBOM变化不得自动覆盖PBOM；
- PBOM变化不得自动覆盖MBOM；
- 下游责任人员对影响项作出采纳、延期、不适用或需要补充资料的决定；
- 已下达生产、已有采购、库存、在制品或已交付产品时，影响分析必须分别说明处理方式；
- 任何自动派生结果在批准发布前只能是工作修订。

### 10.3 变更链

```text
变更申请或问题提出
  → 身份及影响分析
  → 变更授权
  → 新物料修订或新BOM工作修订
  → 下游影响确认
  → 评审与批准
  → 按有效性发布
  → 实施、核对和关闭
```

每次变更至少保存：申请人、原因、影响对象、旧值、新值、库存/采购/在制/交付影响、复核人、批准人、有效范围、实施人、实施时间、完成证据和回退关系。

设计变更、工艺更改、制造偏离、临时代料、永久替代和录入更正必须分别分类，不能全部写成“BOM修改”。

## 11. 保存、归档和受控追溯

### 11.1 保存原则

1. 已发布物料修订、BOM基线、派生映射、变更授权、As-built、批次/序列号、合格证和质量记录应安全保存并可检索。
2. 当前版本、工作版本和过期版本分区管理。过期或作废版本停止投用，但不物理删除。
3. 已发布记录应只读，防止未授权修改；访问和关键操作应具名记录。
4. 归档包应保存来源系统、原始标识、修订、文件清单、内容摘要、批准和发布时间。
5. 应具备备份、恢复和定期恢复验证。备份存在不等于恢复已经验收。
6. 发现数据异常或来源不明时，暂停该版本继续投用，保留原始内容并启动复核；不得先覆盖后调查。

### 11.2 保存期限

保存期限按以下优先顺序确定：

1. 合同或客户要求；
2. 项目要求；
3. 适用法律法规和监管要求；
4. 公司档案制度；
5. 经过批准的业务保留策略。

V0.1不写死年限。每类记录的期限、起算点、暂停删除条件和删除批准尚未确认时，标记“待确认”，系统不得据此启用自动删除。Airbus条款中的五年保密期不得替代BOM或质量记录期限。

### 11.3 最小保存清单

| 记录 | 保存内容 | 起算点和期限 |
|---|---|---|
| 物料及修订 | 身份、编码、设计依据、状态、批准和替代链 | 待合同、项目和档案制度确认 |
| EBOM/PBOM/MBOM发布基线 | 头、行、修订、有效性、内容摘要和附件 | 待确认；旧版不得覆盖 |
| 派生映射 | EBOM↔PBOM↔MBOM行级关系、工艺新增原因 | 待确认；随相关基线共同保留 |
| 变更授权 | 原因、影响、前后值、批准、实施和回退 | 待确认；不得只留最新状态 |
| 批次/序列和As-built | 来源、所有权、实耗、实装、代料、偏离和返修 | 待合同、交付和质量要求确认 |
| 合格证和质量记录 | 原材料、批次、序列、检验、签署和日期 | 待适用合同和质量制度确认 |
| 访问与发布审计 | 用户、时间、操作、对象和结果 | 待信息安全和档案制度确认 |

## 12. 候选责任分工

V0.1采用“职能分治＋MDM发布”。下表是候选责任分工，正式发布前必须由各部门依据现行制度、表单和真实案例确认。

| 事项 | 内容确认候选 | 治理审核和发布 | 系统执行 |
|---|---|---|---|
| 技术物料身份、规格、互换性和修订 | 工程技术部 | MDM工作组审核身份、编码和关系后发布 | 用友管理员配置已批准结果 |
| 企业技术分类 | 工程技术部提出技术类别 | MDM工作组维护字典和映射 | 用友管理员只配置映射或镜像 |
| 项目、研发、试验、试制、小批和批产适用性 | 项目管理部确认场景；工程确认技术适用 | MDM工作组审核有效期和跨项目一致性 | 用友管理员配置已批准结果 |
| 公司自采、客户供应等计划供给责任 | 经营发展部确认采购策略；相关部门确认内部制造或委外边界 | MDM工作组审核关系和字典 | 用友管理员配置已批准结果 |
| 实际收货来源、库存所有权、批次、库位和领退料 | 物资保障部记录和确认实物事实 | MDM工作组校验物料身份和引用 | 业务系统按批准规则记录；管理员不判断所有权 |
| 批次/序列、检验、合格证和质量追溯要求 | 质量管理部；涉及技术判定时工程技术部共同确认 | MDM工作组审核规则完整性 | 用友管理员配置已批准开关和字典 |
| EBOM技术内容 | 工程技术部 | MDM工作组校验物料身份；正式批准链待部门确认 | 权威工程系统发布，具体系统待确认 |
| PBOM/MBOM技术和工艺内容 | 工程技术部；具体工艺岗位待确认 | MDM工作组校验跨层映射和发布完整性 | 目标系统和管理员只承接批准版本 |
| 编码分配、别名和跨系统一致性 | 业务部门提供申请事实 | MDM工作组审核并发布 | 分配器和接口执行；管理员处理技术故障 |
| 变更、替代和偏离 | 相应业务责任部门提出并确认影响 | MDM工作组审核跨对象一致性和留痕 | 系统按批准结果生效 |

用友管理员只负责把已批准结果配置或发布到系统，不替工程、项目、经营、物资或质量部门判断物料身份、用途、来源、所有权、追溯级别或BOM内容。

## 13. 申请、审核和发布流程

### 13.1 新物料

1. 申请部门提交技术定义、用途、初始供给场景和必要质量要求。
2. 工程技术部判断是否为新物料身份，检查形状、配合、功能和互换性。
3. MDM工作组检索现有物料和历史别名，排除重复建码。
4. 工程确认名称、规格、技术分类和修订；项目、经营、物资和质量按各自事实补充关系。
5. MDM工作组完成字段、字典、关系、证据和责任检查。
6. 统一分配编码并发布主数据；用友管理员只承接已批准结果。
7. 发布后任何更正或变化进入受控变更，不直接编辑已发布记录。

### 13.2 变更

1. 提出变更并说明原因、对象和期望生效范围。
2. 判断是否改变物料身份；改变身份则新建编码，不改变则升修订或更正。
3. 分析对用途、供给、库存、采购、BOM、生产、质量和交付的影响。
4. 相应部门复核并批准；MDM检查跨对象一致性。
5. 按有效性发布新版本，旧版本转为已替代或已作废，继续保留。
6. 核对接口、镜像、活动订单、库存、在制品和追溯链，保存实施证据。

### 13.3 紧急情况

紧急止损可以采用范围明确、可撤销的临时偏离或替代，但必须记录：受影响的订单、数量、批次或序列号，技术和质量风险，批准人，有效期，补救措施和关闭条件。紧急处理不得覆盖原发布基线，也不得长期替代正式变更。

## 14. 必测场景和验收口径

| 场景 | 规范预期 | V0.1当前状态 |
|---|---|---|
| 同一材料同时用于试验和批产 | 一个物料码，两条用途关系；无有效`SERIES`时阻断正式批产 | 规则已定义；系统验证待实施 |
| 同一物料在不同项目分别自采和客供 | 一个物料码，两条场景化供给策略；收货批次分别记录来源和所有权 | 规则已定义；系统验证待实施 |
| 同一码同时有公司所有和客户所有库存 | 库存身份分开；可用量和发料按所有权判断 | 规则已定义；交易表族未审核 |
| 独立设计定义的试验件 | 建立独立`PM-PRT`对象，不把“试验”写入普通材料编码位 | 规则已定义；域/对象字典待批准 |
| 设计变化影响互换性 | 新物料编码并保存替代关系 | 规则已定义；真实案例待评审 |
| 设计变化不影响互换性 | 原编码升受控修订 | 规则已定义；真实案例待评审 |
| 历史U8码仍被单据和BOM引用 | 通过别名映射识别，不批量改历史码 | 规则已定义；影响清单待编制 |
| EBOM发布后派生PBOM和MBOM | 三层独立升版，可反查来源修订和行级映射 | 规则已定义；当前系统对象待探查 |
| EBOM变化 | 只生成下游影响项，不覆盖已发布PBOM、MBOM或生产订单 | 规则已定义；系统验证待实施 |
| BOM版本失效 | 停止新业务投用，历史订单、批次、序列和质量文件仍可查询 | 规则已定义；保存期限待确认 |
| 客供批次错发到公司自采工单 | 系统阻断；仅受控替代或偏离可放行 | 规则已定义；交易表族未审核 |
| 62条客供文本但未批次 | 进入人工复核，不自动修改 | 最新只读清单已形成；业务复核未完成 |
| Excel与当前库对账 | 分别保留6,532、6,533、6,565时点，不直接判断异常 | 数据时点已分开；业务原因未确认 |
| 自由文本、分类和实物事实冲突 | 保留原值并待核，不自动生成来源或所有权 | 规则已定义；事实重建未开始 |

自动化检查、数据库只读查询和文档审核只能证明规则或数据条件，不能代替部门业务验收。每个场景正式验收时应保存输入、使用版本、预期结果、实际结果、证据、复核人和日期。

## 15. 实施门槛和阶段

### 15.1 本阶段停止点

本阶段只形成V0.1方案和评审材料。禁止：

- 修改数据库结构、数据、约束、索引、视图或权限；
- 修改用友配置和功能开关；
- 批量改写历史编码或分类；
- 从 `cInvDefine9` 或分类名自动生成权威关系；
- 启动正式迁移、接口切换或历史数据回填；
- 发布可直接在生产数据库执行的变更脚本。

### 15.2 后续阶段门槛

数据库实施属于后续独立项目。必须先确认目标环境、权限、备份、恢复、演练、回滚和业务验收，不得因为本规范已经完成就视为获得数据库写入授权。

## 16. 正式发布前待确认事项

1. `PM`、`PRT`及其他域/对象代码的正式中文定义和边界；
2. 当前PLM、工艺系统、U8和MES中BOM的真实名称、对象、字段、版本和状态；
3. 企业是否实际维护PBOM，还是存在EBOM直接转制造BOM的现状；
4. EBOM、PBOM、MBOM分别由谁编制、复核、批准、发布、替代和作废；
5. 物料修订变化与BOM结构升版的具体判定；
6. 支持哪些有效性维度：日期、批次、架次、序列号、订单、项目或制造场所；
7. 当前设计变更、工艺更改、临时代料和制造偏离的制度与表单；
8. U8 BOM变更历史参数、定时任务和历史完整起点；
9. 采购、收货、库存、批次、序列号、生产订单、实耗、实装和质量记录的物理表及权威边界；
10. 每类记录的保存期限、起算点、暂停删除条件和删除批准；
11. 当前库存、在制品和活动项目重建来源及所有权的证据和工作量；
12. 价格、成本、税率、药品、零售和其他行业扩展字段的适用性及责任部门。

在以上事项确认前，相应内容保持“待确认”。任何候选职责、枚举映射、保存期限和系统落位都不得写成现行事实。
