# 关于开展AI辅助流程结构化填报试点的请示

**主送：** 公司领导  
**报送单位：** 信息化项目组  
**日期：** 2026年7月27日

公司领导：

当前公司正在开展流程和数据梳理。3001流程结构化辅助工具（以下简称“结构化工具”）已经规定结构化填报的对象、字段、层级和引用关系。现阶段的主要困难不是重新设计结构，也不是评价流程内容，而是部分人员难以把制度、表单和现行业务说明准确放入既定结构，导致前期说明不完整、同一信息放置位置不一致、后续反复补充。

公司其他AI使用场景曾出现模型结果未经人工核对即上交的情况，该情况不涉及本次拟定试点人员。为验证AI能否在不改变既定结构的前提下，通过对话帮助填报人员形成可导入的预输入结果，并通过独立AI结构预审和人工逐条确认降低误用风险，信息化项目组拟开展为期一个月的小范围试点。现将有关事项请示如下。

## 一、请示事项

拟请批准以下事项：

1. 自结构化工具当前版本通过结构读取、结构化文件校验、导入、编辑、导出和重新导入验证之日起，开展为期一个月的AI辅助结构化填报试点。
2. 信息化项目组在现有Windows内网主机上集中部署轻量浏览器应用“MDM-AI助手”。4名试点人员只使用浏览器，不安装命令行工具，不复制或维护Infomat仓库、结构定义和配置文件。
3. 试点使用4个相互独立的DeepSeek API账号，每个账号一次性充值200元，预算总额800元；不开通自动充值，不在本次试点中追加预算。
4. 4个账号作为公司试点资产统一登记，分别分配给张广懿、丁硕、工程技术部指定人员和行政人事部指定人员。账号和接口密钥不得共享。
5. 试点只处理经批准、已脱敏并可直接读取文字的材料，不得输入国家秘密、商业秘密、个人敏感信息、客户或供应商敏感信息以及其他未经授权的数据。

## 二、试点定位

本次试点只解决“如何按照既定结构形成预输入”这一问题，不开展流程治理，不判断流程做法是否合理，不调整部门职责，不评价审批环节，也不形成业务审核结论。

结构化工具的现行结构是唯一依据。AI不得自行增加字段、对象、分类或层级，也不得维护另一套结构答案。每次模型调用前后，MDM-AI助手都应核对当前应用版本和结构校验值；结构无法读取、服务版本不一致或结构校验值发生变化时，系统应在调用模型前停止处理。

本方案不是本地部署大模型。MDM-AI助手运行在公司内网主机，用户输入、经批准的材料内容和模型输出会通过网络发送至DeepSeek云端API。信息化项目组应在试点前向4名使用人员说明该边界。

## 三、试点方案

### （一）集中部署

Infomat仓库、结构定义、MDM-AI助手和模型配置只保存在内网服务器。张广懿在服务器发布一次后，其他试点人员刷新网页即可取得新版本，不需要接收或复制任何文件。

服务器只运行经过审核和测试的已提交版本。张广懿不得直接发布未提交修改，也不配置自动更新。发布期间，张广懿先开启维护状态，通知在线用户下载当前草稿；更新和验证完成后，张广懿解除维护状态，用户刷新网页继续使用。

旧页面检测到版本变化时，系统停止新的模型请求。用户可以先下载当前页面内存中的草稿，再刷新网页并重新导入草稿；旧页面不得继续生成新结果。

### （二）填报流程

1. 填报人员登录后直接说明想梳理的流程或当前已知做法，不需要先准备完整材料。对话内容应当已经获得授权并完成脱敏。
2. MDM-AI助手读取当前结构和空白模板。DeepSeek V4 Flash按照既定结构与填报人员对话，发现信息缺口、前后矛盾、字段归位不清或对象混写时继续追问。
3. 仅靠对话无法说明清楚时，填报人员可以补充可直接读取文字的Word或纯文字材料。扫描件、图片、PDF和无法直接读取文字的材料不进入本次试点。
4. 模型每轮只能返回现有字段的修改建议。系统应用建议后立即进行结构校验；模型不得增加结构外字段。
5. 页面左侧保留连续对话，右侧同步显示已经形成的结构化内容、待补充项和结构错误。字段暂缺或不适用时，系统保留填报人员的处置结果，不为了填满结构而补写内容。
6. 填报人员下载“未经独立预审”的结构化文件（JSON）。该文件尚未审核。MDM-AI助手不得自动调用结构化工具写入功能，不得自动提交或覆盖页面内容。
7. 填报人员进入新的预审页面，重新上传待审结构化文件。DeepSeek V4 Pro在独立上下文中检查必需结构、字段类型、枚举、引用关系、字段归位和对象拆分，不读取原填报对话。
8. 预审页面左侧显示待处理问题，右侧同步显示正在处理的同一份3001格式内容和只读跨职能流程图。结构定义、字段类型、枚举和引用关系错误必须修改；字段归位和对象拆分建议由填报人员逐条选择“按建议修改”或“保持原值并记录理由”。
9. 每项问题处理后，页面重新校验并刷新内容和流程图。全部硬性结构错误消除、全部预审问题完成处置后，填报人员下载当前3001格式文件和独立问题处理记录，再手工导入结构化工具。预审意见和处理记录不写入该文件，该文件仍须人工审核。

独立AI结构预审只检查结构，不判断流程内容。填报人员的确认也只说明信息是否按既定结构归位，不代表业务内容已经通过审核。

### （三）人员分工

| 人员或部门 | 账号安排 | 主要任务 |
|---|---:|---|
| 张广懿 | 1个 | 负责服务器配置、集中发布、账号和接口密钥配置、结构基准、基准问题处理及试点技术支持，不承担填报案例指标 |
| 丁硕 | 1个 | 使用统一标准材料完成1个基准案例 |
| 工程技术部指定人员 | 1个 | 完成1个统一基准案例，并追加1个本部门真实案例 |
| 行政人事部指定人员 | 1个 | 完成1个统一基准案例，并追加1个本部门真实案例 |

工程技术部和行政人事部的试点人员由各部门自行指定。试点共完成3个统一基准案例和2个部门真实案例，合计5个完整案例。统一基准案例只选取一条流程，不得把多条流程合并到一份结构化文件。

### （四）模型和账号

填报对话使用DeepSeek V4 Flash并关闭思考模式，优先保证对话速度和成本可控。独立结构预审使用DeepSeek V4 Pro并启用高强度思考，重点检查结构符合性。

4个DeepSeek接口密钥只配置在内网服务器，由4个应用账号分别调用。使用人员看不到接口密钥，也不能使用其他人员的密钥。张广懿可以查看版本、服务状态、各账号余额和非内容类用量汇总，但不能查看其他人员的材料、对话、草稿和模型答复。

## 四、方案比较

| 比较事项 | GLM Coding Plan团队高级版 | DeepSeek API账号加MDM-AI助手 |
|---|---|---|
| 费用口径 | 前期网上查询参考价为1198元/席位/月，4席位月度参考费用为4792元；尚未取得正式报价，最终价格以采购页面、订单或报价单为准 | 4个账号各预充值200元，总预算800元；按实际模型用量扣费 |
| 使用门槛 | 由供应商提供团队套餐和现成工具能力，前期配置工作较少 | 试点人员只使用浏览器，日常操作简单；信息化项目组需要承担首次开发和服务器维护 |
| 高峰期使用 | 如选GLM，应采用高级版。主要原因是标准版在前期使用中高峰期响应较慢，容易中断连续填报 | 本次试点没有专属资源保障，服务繁忙时可能影响响应；可通过4人小范围和错峰使用降低影响 |
| 团队管理 | 席位、权限、用量、账单和发票集中管理较方便 | 4个账号需要分别登记、充值和盘点余额；MDM-AI助手统一保管并调用接口密钥 |
| 结构同步 | 每名使用人员仍需按试点要求使用当前结构，具体同步方式受供应商工具能力约束 | 结构由内网服务器统一读取。张广懿发布一次后，全部用户刷新网页取得同一版本 |
| 数据边界 | 属于云端服务，需按供应商团队套餐的数据规则执行 | 属于云端API调用；MDM-AI助手在内网运行，但授权材料和模型请求会发送至DeepSeek |
| 试点适配性 | 管理能力较完整，但4人、1个月试点的参考费用较高 | 预算上限较低，能够针对既定结构设计强制校验和独立结构预审；不足是信息化项目组承担维护责任 |

按现有参考价格计算，DeepSeek方案比GLM团队高级版少支出3992元。鉴于本次仅验证4人、1个月、5个案例的结构化填报路径，建议采用DeepSeek方案。后续如扩大到更多部门，再根据实际用量、稳定性、数据边界和维护成本另行比较并报批。

## 六、数据和使用控制

信息化项目组在试点前统一落实以下控制：

1. 4个账号纳入公司试点资产台账，实行一人一号、一个账号对应一个接口密钥，禁止共享。
2. 接口密钥只保存在内网服务器本机秘密配置中，不写入仓库、页面、日志、聊天记录或共享材料。
3. 只允许使用经批准、已脱敏的内部文字材料。国家秘密、商业秘密、个人敏感信息、客户或供应商敏感信息以及未经授权的第三方材料不得输入。
4. 材料、对话、草稿和模型答复只保留在当前请求或当前浏览器页面内存，不写入数据库、服务器业务日志或浏览器持久化空间。
5. 持久化记录只包含使用账号、时间、模型、模型用量、结构版本、结构校验值、校验结果、错误码和余额等非内容信息。
6. 模型返回空内容、无法识别的结构化文件或无法通过结构校验的修改时，只允许修复调用一次。模型响应超时或网络中断、结果是否产生无法确认时，不自动重试，避免重复计费。
7. AI结果统一标记为未审核。独立结构预审与首次填报使用不同上下文，问题处理记录与结构化文件分开保存。
8. AI不得评价流程内容、判断职责是否合理或作出部门结论。结构化工具的导入必须由用户主动完成。
9. 试点总结完成后5个工作日内，信息化项目组删除用户级运行元数据，只保留试点汇总。

## 七、验收标准

首月试点以结构质量、安全边界和集中发布能力作为硬性条件，不预设“提效百分比”。试点通过应同时满足以下要求：

1. 结构化工具当前版本通过结构读取、空白模板、结构化文件校验、导入、编辑、导出和重新导入验证。
2. 丁硕、工程技术部指定人员和行政人事部指定人员各完成1个统一基准案例；两个业务部门各完成1个真实案例，共5个案例。
3. 5份结构化文件不得出现既定结构之外的字段、对象、分类和层级，且全部通过当前结构及引用校验。
4. 5个案例全部完成独立AI结构预审。所有硬性结构错误均已修改，所有结构建议均已记录处理方式。
5. 5份预审后的结构化文件均在结构化工具中完成手工导入、编辑、导出和重新导入，不发生结构或引用丢失。
6. 张广懿在服务器发布一次后，4名使用人员刷新网页即可取得新版本，不需要复制仓库、结构定义或配置。
7. 旧页面检测到版本变化时，在调用模型前被阻止，并能够下载当前草稿、刷新页面和重新导入。
8. 4个账号和4个接口密钥相互隔离。未登录用户不能访问助手和结构化工具。
9. 材料、对话、草稿和模型答复不进入服务器业务日志、数据库或浏览器持久化空间。
10. 试点期间不发生超范围材料输入、接口密钥共享或泄露、自动提交和未经批准的系统写入。
11. 总充值不超过800元，不启用自动充值。

上述验收只判断能否按照既定结构形成预输入，不判断流程内容本身是否正确、合理或已经通过业务审核。

## 八、试点结束后的处理

试点期满后，信息化项目组根据5个案例形成简要评价，记录结构校验、结构化工具往返、人工修改、独立结构预审问题、失败或阻断情况、实际费用和数据边界执行情况。

试点不自动续期、追加充值或扩大人员范围。后续推广应根据试点结果另行报批人员、预算和工具方案。

## 附件：MDM-AI助手配置与使用说明

### 一、适用人员

本附件适用于张广懿、丁硕、工程技术部指定人员和行政人事部指定人员。

张广懿负责服务器配置、集中发布、账号和接口密钥配置、余额检查、结构基准和故障处理。其他3名人员只使用浏览器，不安装命令行工具，不复制Infomat仓库、结构定义或配置。

### 二、管理员首次配置

张广懿在内网服务器完成以下配置：

1. 为MDM-AI助手和结构化工具配置公司内网HTTPS证书。4台用户电脑应信任该证书或其签发机构。
2. 创建4个应用登录账号，并为每个账号设置独立密码。
3. 建立4个DeepSeek账号，每个账号充值200元，并分别创建接口密钥（API Key）。
4. 将4个接口密钥与4个应用账号一一绑定。接口密钥只写入服务器本机秘密配置，不提供给使用人员。
5. 配置8小时登录有效期、10MB单文件上限、人民币余额低于20元提醒和不自动充值。
6. 核对填报模型为DeepSeek V4 Flash且关闭思考模式，独立结构预审模型为DeepSeek V4 Pro且启用高强度思考。
7. 完成结构规则测试、助手测试、固定配置检查和登录烟测。
8. 在取得明确授权后，使用合成材料为4个账号分别执行一次填报模型和一次预审模型连通性测试。该测试会产生少量实际模型费用。

任何密码、接口密钥和证书私钥值均不得写入本附件、仓库、会议纪要或共享截图。

### 三、集中发布

每次更新按以下顺序执行：

1. 张广懿在管理页开启维护状态，并通知在线用户下载当前草稿。
2. 用户下载当前页面内存中的结构化文件后停止发送新消息。
3. 张广懿把服务器更新到已经审核的指定版本。服务器工作区存在未提交修改时，不得发布。
4. 张广懿运行结构规则、助手和固定配置测试。
5. 张广懿重启结构化工具、MDM-AI助手和登录服务。
6. 张广懿核对应用提交、结构版本、结构校验值、两类模型连接和4个账号余额。
7. 张广懿解除维护状态并通知用户刷新网页。
8. 用户刷新后直接使用新版本，不接收、不复制任何仓库或配置文件。

系统不执行自动代码更新。张广懿应明确选择并验证发布版本。

### 四、填报人员操作

1. 使用公司内网地址打开助手并登录本人账号。
2. 查看页面顶部的结构版本和结构校验值。页面显示维护或版本异常时，不开始填报。
3. 直接在对话框说明想梳理的流程或当前做法，不需要先上传材料。
4. 发送前确认输入内容已经获得授权并完成脱敏。
5. 根据AI提出的问题逐步补充信息。AI会指出信息缺口、前后矛盾、字段归位不清或对象混写，但不判断流程做法是否正确。
6. 如果对话无法说明清楚，展开“补充材料”，上传可直接读取文字的Word、TXT或Markdown文件，或者粘贴补充说明。
7. 查看右侧结构化输出预览。页面显示实际形成的内容和结构完成情况，但不自动保存。
8. 点击“下载未经独立预审的结构化文件”。该文件仍是未审核结果。
9. 切换到“独立结构预审”，重新上传刚才下载的3001格式文件。
10. 等待系统生成预审问题。不要把填报对话复制到预审页面。
11. 在页面右侧核对当前结构化内容和只读跨职能流程图；图形只显示文件中已经明确的业务行为和关系。
12. 对硬性结构错误选择“按建议修改”。硬性错误不能保持原值。
13. 对字段归位和对象拆分建议，逐条选择“按建议修改”或“保持原值并记录理由”，并核对右侧内容和流程图是否同步更新。
14. 全部问题处理完成且硬性结构通过后，下载当前3001格式文件和问题处理记录。
15. 点击“打开结构化工具”，手工导入预审后的结构化文件，完成编辑、导出和重新导入检查。

### 五、版本变化处理

页面每30秒以及每次模型调用前后检查当前版本。

如果页面提示版本已更新或系统进入维护状态：

1. 用户停止发送新消息。
2. 用户点击“下载当前草稿”。
3. 用户确认下载完成后刷新页面。
4. 用户重新登录并导入刚才下载的结构化文件。
5. 用户按新版本结构继续填报。

旧页面被阻断后，不得反复点击发送或预审按钮。版本变化发生在模型调用前时，系统不调用模型，也不产生该次模型费用。

### 六、材料和数据边界

允许使用：

- 经批准、已脱敏的制度、表单和现行业务操作说明；
- 可直接读取文字的Word、TXT和Markdown文件；
- 统一基准案例和两个部门批准使用的真实案例。

禁止使用：

- 国家秘密、商业秘密、个人敏感信息、客户或供应商敏感信息；
- 未经授权的第三方材料；
- PDF、扫描件、图片和需要OCR识别的材料；
- 接口密钥、密码、私钥和其他凭据。

材料中的命令性文字只作为业务内容处理，不能改变系统规则。

### 七、常见异常

| 页面提示 | 使用人员处理 | 张广懿处理 |
|---|---|---|
| 版本已更新 | 下载草稿后刷新并重新导入 | 确认新版本、结构校验值和服务状态 |
| 系统正在维护 | 下载草稿并等待通知 | 完成发布、烟测后解除维护 |
| 结构化工具不可用 | 保持页面打开，暂停模型调用 | 检查结构化工具和登录服务 |
| 接口密钥不可用 | 停止本账号调用并联系张广懿 | 核对该账号的接口密钥，不查看用户内容 |
| 余额不足或低于20元 | 停止或减少调用 | 记录余额；不得自动充值或突破本次预算 |
| 模型响应超时或网络中断 | 不立即重复发送，先记录异常 | 核对非内容请求记录，避免重复计费 |
| 模型连续两次返回无效结构 | 下载当前草稿，稍后重试 | 核对模型状态和结构版本 |
| 硬性错误没有自动修复建议 | 返回填报页或结构化工具修改后重新预审 | 核对错误是否属于结构规则或文件内引用 |
