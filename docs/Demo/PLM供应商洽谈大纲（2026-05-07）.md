# PLM供应商洽谈大纲

> 时间：2026-05-07  
> 背景：PLM 是研发域数据源头，直接影响 EBOM、MBD、ECO、物料主数据、构型管理和后续接口设计。此次洽谈是 2026-05-09 专题会前的关键预沟通动作，目标不是泛泛了解产品，而是确认其是否能支撑昌兴复材航空复材制造场景下的集成方案，并与公司现有组织分工相匹配。

---

## 一、洽谈目标

本次洽谈建议聚焦五个目标：

1. 确认 PLM 是否能支撑航空复材场景下的 EBOM、MBD、ECO、构型与版本管理。
2. 确认 PLM 与 PDM、CAPP、ERP、MES、OA、数据中台之间的接口能力和责任边界。
3. 确认 PLM 方案与公司各部门职责边界是否匹配，避免后续出现“谁主导、谁维护、谁审批、谁验收”不清的问题。
4. 获取供应商可提供的数据模型、字段清单、接口方式、实施交付物和典型案例资料。
5. 形成对 5月9日专题会 Q5、Q7 及接口设计的输入，避免后续接口设计返工。

---

## 二、建议参会人员

先明确本次会议定位：这是 **PLM 供应商选型介绍会**，主要形式是供应商介绍产品能力，昌兴复材现场提问题。它不是集成评审会，也不是跨部门方案冻结会。因此内部参会范围应保持精简，以 **工程技术部、质量管理部** 为主。

| 角色 | 参会级别 | 建议参会原因 |
|---|---|---|
| 工程技术部 | 必须全程参加 | 按部门职责负责项目研发、技术文件制定和下发、研发项目立项管理、技术管理，是 PLM 选型的第一业务主责部门；重点确认 EBOM、ECO、MBD、物料版本、工程发布要求 |
| 质量管理部 | 必须全程参加 | 按部门职责负责质量技术策划、质量体系、实物质量控制及外协供应商质量管理；重点确认质量文件受控、NDT规范、适航追溯、构型与偏离记录 |
| PLM候选供应商 | 必须全程参加 | 负责完整介绍产品能力、实施边界、接口方式和案例，并现场回答问题 |

> 本场会议原则上不要求项目管理部、经营发展部、复材车间、物资保障部、财务部、ERP/MES接口方到场。若会后进入 shortlist 比较、集成边界确认或立项评审，再按主题扩展参会范围。

---

## 三、提问分工原则

本场不做跨部门职责划分，只围绕 **工程技术** 和 **质量受控** 两条主线提问：

| 部门 | 洽谈中的主关注点 |
|---|---|
| 工程技术部 | 设计主数据、EBOM、MBD、ECO、技术文件、版本与发布机制 |
| 质量管理部 | 质量文件受控、检验规范、构型记录、适航追溯、供应商质量要求 |

> 采购、合同、外协、库房、车间执行、成本预算等议题不作为 5 月 7 日本场重点，不建议在本次会议中展开。

---

## 四、建议议程（120分钟）

| 时间 | 议题 | 目标 |
|---|---|---|
| 0-10min | 项目背景说明 | 说明昌兴复材业务场景、PLM选型目的和本次会议边界 |
| 10-25min | 供应商方案总览 | 供应商介绍 PLM 产品定位、模块范围、航空/复材相关能力 |
| 25-45min | EBOM / MBD / 工程发布能力 | 确认 EBOM结构、铺层顺序、材料规范、固化规范、NDT规范、MBD模型和虚拟件标记如何管理 |
| 45-60min | ECO / 版本 / 构型管理 | 确认 ECO流程、版本生效、旧版本保留、构型状态、偏离/超差记录如何实现 |
| 60-80min | 质量受控与适航追溯 | 确认 PLM/PDM中哪些数据可用于适航追溯、质量文件受控和长期归档 |
| 80-100min | 数据开放与下游接口能力 | 了解 PLM→PDM/CAPP/ERP/MES/OA 的接口能力，但不在本场做集成方案定稿 |
| 100-115min | 实施交付与边界 | 确认实施周期、需客户准备的数据、标准功能与二开边界、交付物 |
| 115-120min | 资料清单与会后动作 | 明确供应商需在会后提交的材料、样例、报价或二次演示安排 |

## 五、必须问清楚的问题

### 1. EBOM 与复材工程数据

| 问题 | 需要供应商回答 |
|---|---|
| EBOM 能否管理铺层顺序（Ply Stack-up）？ | 字段方式、结构方式、样例截图或数据样例 |
| 材料规范号、固化工艺规范、NDT检测规范如何挂接？ | 是物料属性、文档对象，还是工艺对象 |
| 虚拟件如何标记？ | 能否在发布到下游时过滤虚拟件 |
| 版次 REV 是否可作为独立字段管理？ | 是否支持旧版本保留和版本追溯 |
| 对外交付件号和内部物料编码能否分离？ | 是否支持映射表和多编码体系 |

### 2. MBD 能力

| 问题 | 需要供应商回答 |
|---|---|
| 是否支持 MBD 模型管理？ | 支持哪些格式、是否可管理 PMI 标注 |
| MBD 如何与 EBOM 关联？ | 模型、零件、BOM、版本之间的关系 |
| MBD 如何传给 CAPP 或三维工艺？ | 接口方式、格式、触发方式 |
| MBD 变更后如何触发 BOM 或工艺更新？ | 与 ECO 流程的关系 |

### 3. ECO 变更闭环

| 问题 | 需要供应商回答 |
|---|---|
| ECO 在 PLM 中如何发起、审批、发布？ | 是否可对接 OA 审批 |
| ECO 生效范围如何定义？ | 按日期、批次、订单、序列号或构型状态 |
| ECO 发布后如何通知 PDM、CAPP、ERP、MES？ | 消息、接口、人工任务或中台同步 |
| 已下发生产订单和 MES 工单如何处理？ | PLM 是否只通知，还是能参与闭环控制 |
| 旧版本 EBOM 和旧工艺文件如何保留？ | 是否支持审计追溯 |

### 4. 接口与数据开放能力

| 问题 | 需要供应商回答 |
|---|---|
| 是否提供标准 API？ | REST、SOAP、WebService、数据库视图、文件交换等 |
| 是否支持 JSON / XML 数据交换？ | 字段清单和样例 |
| 是否支持事件触发？ | 工程发布、ECO发布、物料变更、版本生效 |
| 接口失败如何处理？ | 重试、告警、日志、人工补偿 |
| 是否支持接入数据中台或 ESB？ | 供应商已有案例和技术边界 |
| 接口开发通常由谁负责？ | PLM方、客户方还是第三方实施商，供后续集成阶段参考 |

### 5. 主数据与黄金源

| 问题 | 需要供应商回答 |
|---|---|
| 设计件物料主数据是否适合由 PLM 作为黄金源？ | 供应商建议及原因 |
| PLM 能否支持 13 位含连字符物料编码？ | 长度、字符集、唯一性校验 |
| REV 独立字段是否支持？ | 是否能参与查询、发布、接口同步 |
| 采购件和设计件如何区分？ | 与 ERP-MM 的主数据边界 |
| 是否支持物料编码、件号、构型状态分离管理？ | 字段模型和样例 |

### 6. 适航追溯与质量文件

| 问题 | 需要供应商回答 |
|---|---|
| PLM/PDM能否保存构型状态和偏离记录？ | 字段、流程和查询方式 |
| NDT规范和质量文件如何受控归档？ | 与 PDM 或质量系统的边界 |
| 是否支持按件号、序列号、版本查询关联文件？ | 是否支持长期归档和审计 |
| 适航追溯数据哪些应在 PLM/PDM，哪些应在 MES/数据中台？ | 供应商建议边界 |

## 六、按部门补充核实的问题

### 1. 面向工程技术部

| 重点问题 | 需要供应商回答 |
|---|---|
| 技术文件如何在 PLM 中受控下发？ | 文档、BOM、模型、工艺对象之间如何关联 |
| 新增工装、工具、材料定额申请是否可纳入流程？ | 是否有标准流程对象，还是需二开 |
| 研发项目立项、设计发布、变更关闭如何留痕？ | 流程节点、审批规则、审计能力 |

### 2. 面向质量管理部

| 重点问题 | 需要供应商回答 |
|---|---|
| 质量文件、检验规范、NDT规范如何与 EBOM/MBD/版本绑定？ | 绑定对象、版本规则、查询方式 |
| 外协供应商质量要求能否与设计件、材料规范关联？ | 是通过文档、属性还是主数据对象实现 |
| 偏离、超差、让步接收等质量记录如何挂在构型档案中？ | 数据模型和流程样例 |

> 项目管理、经营发展、复材车间、物资保障、财务等部门的问题不在本场展开。若供应商进入下一轮比较或进入集成评审阶段，再按主题单独组织沟通。

## 八、洽谈后需要形成的项目组结论

洽谈结束后，项目组建议当天形成一页纸结论：

| 结论项 | 内容 |
|---|---|
| PLM能力判断 | 能满足 / 部分满足 / 关键能力待确认 |
| 对工程技术的匹配判断 | 是否满足设计主数据、EBOM、MBD、ECO、技术文件管理要求 |
| 对质量管理的匹配判断 | 是否满足质量文件受控、检验规范、适航追溯和构型记录要求 |
| 对Q5的影响 | 设计件物料主数据是否倾向 PLM 作为黄金源 |
| 对后续接口设计的影响 | 是否具备进入下一步接口评估的基础能力 |
| 主要风险 | 供应商未明确、需二开、接口受限、字段不匹配等 |
| 需补充资料 | 列出供应商承诺提交的文档和截止时间 |
| 5月9日建议带上会的问题 | 只带已经过工程技术部和质量管理部消化后的关键问题 |

## 九、建议现场坚持的边界

- 不接受“可以做”作为结论，必须要求供应商说明通过标准功能、配置、二开还是接口实现。
- 不现场承诺 PLM 为所有数据的黄金源，只确认其是否具备作为设计件主数据源的能力。
- 不把适航追溯全部压给 PLM，需区分 PLM/PDM、MES、WMS、ERP、数据中台各自的数据归属。
- 不讨论泛泛数字化蓝图，优先锁定 EBOM、MBD、ECO、质量受控、数据开放和构型追溯六件事。
- 不让供应商只讲演示页面，必须拿到字段样例、接口样例和实施边界。
- 不把本场会议开成集成会：采购、合同、外协、库房、车间执行、预算成本等议题留到下一阶段。
