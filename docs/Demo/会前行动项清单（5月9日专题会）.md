## 三、项目组会前沟通方式建议

### 1. 先开小范围预沟通，不开大而全的会

建议项目组按问题分组沟通，而不是一次召集所有部门。每个小组只解决一个主题：

| 主题 | 必须参与部门 | 目标 |
|---|---|---|
| PLM与研发源头数据 | 项目管理部、工程技术部、质量管理部、复材车间 | 明确 PLM 能否支撑 EBOM、MBD、ECO、构型与接口 |
| EBOM→MBOM转换 | 工程技术部、复材车间、CAPP/MES/ERP代表 | 明确谁转、转什么、何时转、版本怎么生效 |
| ECO变更闭环 | 工程技术部、质量管理部、物资保障部、复材车间、OA/ERP/MES代表 | 明确变更对生产订单、在制品、库存、工单的影响 |
| 采购与SCIM定位 | 物资保障部、质量管理部、财务部、项目管理部、ERP代表 | 明确 SCIM 是采购系统、供应商质量门户，还是流程协同入口 |
| 数据中台路线 | 项目管理部、各系统接口负责人 | 明确是否需要统一集成总线/数据中台，以及谁负责建设和运维 |
| 主数据编码校验 | 工程技术部、项目管理部、ERP/MES/PLM候选方 | 确认编码结构在各系统中可存储、可检索、可同步 |

### 2. 每个主题只要求输出“一页纸”

每页纸建议固定结构：

| 项目 | 内容 |
|---|---|
| 当前结论 | 已确认的信息，不写猜测 |
| 待决问题 | 需要5月9日会上拍板的问题 |
| 可选方案 | 2-3个可选项 |
| 推荐倾向 | 牵头部门的建议，如无建议则说明原因 |
| 影响范围 | 会影响哪些系统、部门和接口 |
| 需要供应商补充 | 资料、接口、字段、演示或报价 |
