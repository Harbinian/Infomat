## 第 3 节：四大集成域

### 3.1 研发域（PLM → PDM → CAPP / ERP-PP）

**集成链流程**：

1. **PLM 工程发布（Engineering Release）**
   - 输出：EBOM结构、铺层顺序（Ply Stack-up）、材料规范号、固化工艺规范（Cure Cycle Spec）、NDT检测规范、三维MBD模型、虚拟件标记

2. **PDM 受控BOM管理**
   - 过滤虚拟件 → 版本锁定 → 受控发布
   - 同时推送 CAPP 和 ERP-PP
   - 质量文件归档受控

3a. **CAPP 工艺路线设计**
   - 接收 EBOM + MBD → 展开工序（铺层 → 热压罐固化 → 脱模 → 修边 → NDT → 表面处理 → 检验）
   - 输出：MBOM + 工时定额 + 工装编号

3b. **ERP-PP 生产计划（用友U8）**
   - 接收 MBOM + 工艺路线 → MRP运算 → 生成生产订单 + 采购需求

**MBD 在集成中的关键作用**：

| 传递内容 | 接收方 | 意义 |
|---------|--------|------|
| 含标注的三维模型 | CAPP / 三维工艺 | 工艺设计直接读取模型，无需二维图纸 |
| 材料/公差定义 | CAPP → 计划管控 | 驱动下料管理、零件采购规格 |
| 更改管理 | PDM → EBOM | 设计变更自动触发BOM版本更新 |
| 设计资源 | PDM归档受控 | 确保制造端使用唯一受控版本 |

**四态BOM体系（航空复材场景）**：

| BOM类型 | 主导系统 | 核心字段 | 特殊说明 |
|---------|---------|---------|---------|
| EBOM（工程BOM） | PLM | 铺层顺序、纤维方向、材料规范号、固化工艺规范 | 含虚拟件，不传ERP |
| MBOM（制造BOM） | CAPP/MES | 工序分工、工装编号、工时定额、工艺规范号 | 与工艺路线绑定 |
| PBOM（采购BOM） | ERP-MM | 预浸料规格、批次要求、材料有效期、ASL | 原材料必须来自批准供应商清单 |
| SBOM（构型BOM） | PDM/适航 | 件号、序列号、适用性、构型偏离 | 对应SoC、FAI报告 |

**航空复材 vs 普通制造 BOM核心差异（7维度）**：

| 差异点 | 普通制造 | 航空复材制造 |
|--------|---------|------------|
| BOM最小单元 | 零件 | **铺层（Ply）**，一个蒙皮可能有数十层 |
| 材料属性 | 材料牌号 | **预浸料批次号 + 有效期 + 存储条件** |
| 工艺参数 | 工艺路线 | **固化曲线（温度/压力/时间）+ 热压罐编号**，记录到件 |
| 质量记录 | 检验合格 | **NDT报告（超声C扫/X射线）+ 孔隙率检测**，记录到件 |
| 版本管理 | 版次 | **构型状态 + ECO/EO变更单 + 偏离/超差记录**，适航局可查 |
| 追溯要求 | 批次追溯 | **序列号级追溯**，每个零件独立档案，终身保存 |
| 有效期管理 | 无 | **预浸料冷冻存储时间 + 环境暴露时间 + 上机时限**，超期作废 |

## 第 4 节：主数据规范

### 4.1 为什么主数据是一切的地基

> **真实事故链（C919后机身前段上壁板 CFRP Fuselage Rear Frame Upper Panel）**

```
PLM 叫：  PANEL-CFRP-RFFUP-001-A       （设计态，含铺层顺序）
ERP 叫：  1000045231                    （财务流水号）
MES 叫：  PART-PANEL-RFFUP-001          （车间自命名）
质量系统：后机身上壁板 PANEL-CFRP-RFFUP-001-A（质检员手填）
OA采购：  XX级碳纤维预浸料或CMS-XX-XXX   （采购申请描述）

结果：
→ 预浸料批次与零件无法关联 → 适航审查无法提供材料追溯
→ NDT检测记录找不到对应零件 → 质量档案不完整
→ 固化炉工艺参数记录与零件脱节 → 无法证明工艺符合性
→ 适航局审查时，整批次零件被要求重新验证
```

**在航空制造，主数据混乱不只是效率问题，是适航符合性问题。**

---

### 4.2 编码设计五原则

1. **唯一性**：每一个物料全公司范围内有且仅有一个编码，跨系统共用
2. **稳定性**：编码一经创建，不因物料名称、规格变更而修改；变更须新建物料
3. **可读性**：编码结构须兼顾人工识别与系统解析，不使用纯流水码
4. **扩展性**：分类位预留扩展空间，避免未来分类调整导致编码体系崩溃
5. **系统兼容性**：编码长度与字符集须经各系统确认，确保无截断或乱码风险

---

### 4.3 编码结构（PPT版，13位含连字符）

```
XX  -  XXX  -  00000
│      │        │
大类   小类    流水号
(2位)  (3位)   (5位)

总长度：13位（含2个连字符）

```

### 4.4 航空复材特殊编码规则

| 规则 | 说明 |
|------|------|
| 件号与物料编码分离 | 对外交付件号（主机厂格式）与内部物料编码分离，通过映射表关联。禁止直接用主机厂件号作为内部编码 |
| 预浸料有效期不进编码 | 批次号、生产日期、有效期作为批次属性管理，不体现在物料编码中 |
| 工艺规范号单独字段 | 固化工艺规范（Cure Spec）、NDT规范作为物料属性字段，不进编码 |
| 构型状态码独立 | 适航构型状态（TC/STC适用性）作为独立属性，不进编码 |
| 版次REV独立字段 | 版次不进主编码，作为独立字段管理，支持版本追溯 |

## 第 6 节：数据中台架构（Q7 核心决策）

> 这是本次集成方案中**架构层面最关键的决策**，直接影响所有接口的实现方式和长期维护成本。

### 6.1 两种方案对比

| 维度 | 方案A：点对点集成 | 方案B：数据中台/集成总线 |
|------|----------------|----------------------|
| **架构** | 系统间两两直连 | 统一中间层，所有系统接中台 |
| **接口数量** | N×(N-1)/2，8系统=28条 | N条，8系统=8条 |
| **建设成本** | 低（短期） | 高（需额外建设） |
| **维护成本** | 高（任一系统升级影响多条接口） | 低（只改中台适配器） |
| **数据一致性** | 难保证（各系统各自同步） | 易保证（统一调度） |
| **适航追溯** | 难（数据散落各系统） | 易（中台统一存储追溯链） |
| **适用场景** | 系统少、集成简单 | 系统多、数据复杂、有追溯要求 |
| **推荐度** | ⚠️ 不推荐（8系统规模） | ✅ 推荐 |

### 6.2 数据中台在架构中的正确位置

```
┌──────────────────────────────────────────────────────┐
│                    各业务系统层                        │
│  PLM │ PDM │ CAPP │ ERP │ MES │ WMS │ SCIM │ OA     │
└──────────────────────┬───────────────────────────────┘
                       │ 统一接口（API / 消息队列）
┌──────────────────────▼───────────────────────────────┐
│                数据中台 / 集成总线                      │
│  · 主数据管理（MDM）                                   │
│  · 数据同步调度                                        │
│  · 接口适配器（各系统连接器）                            │
│  · 数据质量监控                                        │
│  · 适航追溯数据湖                                      │
└──────────────────────────────────────────────────────┘
```

> 数据中台是**横向基础设施层**，不属于任何一个业务域，是所有域的共享底座。

## 第 7 节：适航追溯专节（Q8）

### 7.1 适航追溯的核心要求

- **序列号级追溯**：每个零件独立档案，不是批次追溯
- **终身保存**：质量档案须保存至零件退役，通常20年以上
- **全链路可查**：从原材料批次 → 制造工艺 → 检验记录 → 交付构型，全部可追溯

### 7.2 追溯链设计（序列号级）

```
原材料批次（预浸料）
    ↓ 批次号 + 有效期 + 存储记录
铺层工序（MES记录）
    ↓ 铺层顺序 + 操作员 + 时间戳 + 环境温湿度
热压罐固化（MES + IoT）
    ↓ 固化炉编号 + 实际固化曲线（温度/压力/时间）
NDT检测（质量系统）
    ↓ 超声C扫报告 + X射线报告 + 孔隙率结果
修边/表面处理（MES）
    ↓ 工序记录 + 操作员
最终检验（质量系统）
    ↓ 检验报告 + 检验员 + 合格判定
交付构型（PDM/SBOM）
    ↓ 件号 + 序列号 + 构型状态 + 偏离记录
主机厂交付
    ↓ 符合性声明（SoC）+ 首件检验报告（FAI）
```

### 7.3 追溯数据的系统归属

| 追溯节点 | 产生系统 | 存储系统 | 查询入口 |
|---------|---------|---------|---------|
| 原材料批次 | WMS（入库） | ERP-MM + 数据中台 | 数据中台 |
| 铺层/固化工艺 | MES + IoT | MES + 数据中台 | 数据中台 |
| NDT检测报告 | 质量系统 | PDM（受控归档） | PDM |
| 构型状态 | PDM | PDM | PDM |
| 交付文件 | PDM | PDM | PDM |

## 第 8 节：关键接口设计

### 接口卡 #1：PLM → PDM（工程BOM发布）

| 字段 | 内容 |
|------|------|
| 集成方向 | PLM → PDM |
| 集成目的 | 将设计态EBOM受控传递给PDM，作为MBOM转换的数据源 |
| 触发时机 | 工程发布（Engineering Release）时触发 |
| 数据格式 | JSON / XML（待与PLM供应商确认） |
| 核心字段 | 物料编码、件号、版次、铺层顺序、材料规范号、固化工艺规范号、NDT检测规范号、虚拟件标记 |

**字段映射**：

| PLM字段 | PDM字段 | 说明 |
|---------|---------|------|
| item_code | material_code | 物料编码 |
| part_number | part_number | 对外交付件号 |
| revision | rev | 版次（A/B/C） |
| ply_sequence | ply_stackup | 铺层顺序定义 |
| material_spec | mat_spec_no | 材料规范号 |
| cure_spec | cure_spec_no | 固化工艺规范号 |
| ndt_spec | ndt_spec_no | NDT检测规范号 |
| is_virtual | virtual_item_flag | 虚拟件标记（0=实物，1=虚拟） |

**异常处理**：
- 虚拟件不过渡到PDM BOM结构，过渡时需过滤
- PLM发布版本与PDM接收版本严格一一对应，不允许覆盖旧版本
- 接口失败时自动告警，触发人工介入流程

### 9.2 六大风险项

**🔴 高风险 · 问题1：PLM供应商未定——所有接口设计无法锁定**

PLM是研发域数据源头，供应商未定意味着：
- EBOM的数据结构未知
- 与PDM的接口协议未知
- ECO变更单的字段定义未知
- **其他所有系统的接口设计都无法锁定**

> ⚠️ PLM选型必须先于其他系统接口设计冻结，否则后续接口全部返工

---

**🔴 高风险 · 问题2：EBOM → MBOM转换逻辑完全缺失**

```
EBOM（PLM/PDM中）
  ├── 虚拟件（装配辅助节点，ERP不需要）
  ├── 设计替代料（ERP需要展开成采购BOM）
  ├── 原材料（含MBD中的材料牌号、规格）
  └── 外购件（含技术规格，驱动采购）
         ↓ 谁来做转换？转换规则是什么？
MBOM（ERP-PP / MES中）
  ├── 工序分工结构（与工艺路线绑定）
  ├── 定额数量（含损耗率）
  └── 替代料策略（ERP的替代BOM）
```

PDM → ERP-PP 这条线没有转换逻辑定义，实质上是空的。

---

**🔴 高风险 · 问题3：ECO变更流程断链**

现状（文档描述）：`PLM发起ECO → OA审批 → PDM状态更新`

实际需要但缺失的完整流程：
```
PLM 发起 ECO
  ↓
OA 审批（工程/工艺/质量/采购 多部门会签）
  ↓
PDM 发布新版 EBOM
  ↓ ← 文档完全没有
ERP-PP 的 MBOM 如何处理？
  ├── 新版本从哪个生产订单开始生效？
  ├── 在制品按新BOM还是旧BOM完工？
  └── 旧料库存如何处置？（ERP-MM）
  ↓ ← 文档完全没有
MES 的工艺路线如何更新？
  └── 已下发的工单是否需要撤回重发？
```

---

**🟡 中风险 · 问题4：SCIM定位未明确（自研 or 采购？）**

SCIM与ERP的集成深度直接影响采购域接口设计复杂度，需在项目启动阶段明确。

---

**🟡 中风险 · 问题5：中间件方案未确定（点对点 vs 总线）**

8套系统间的集成架构未定义。点对点方案维护成本高，总线方案需要额外建设。需尽早决策（即Q7）。

---

**🟡 中风险 · 问题6：主数据编码规范尚未各系统技术确认**

编码长度、字符集需经用友U8、北京虎蜥MES、PLM各系统供应商技术确认，避免截断或乱码风险。
