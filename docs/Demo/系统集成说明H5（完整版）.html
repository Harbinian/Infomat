PLM 是什么

设计数据源头 · 图纸 / BOM / 变更 · 翎瑞鸿翔已定
PLM 背景铺垫

把 PLM 放回本次集成预审的位置

Windchill PLM 是面向产品全生命周期的研发数据管理平台，来源资料中覆盖产品数据管理、BOM、变更、项目、协作和系统集成等能力。本次预审采用"能力参考 + 一期范围约束"的口径：翎瑞鸿翔已确认一期上线 MBOM(PDM)、ECO(ECN)、工程项目管理；其他能力作为后续详细设计和供应商确认输入，不直接写成最终承诺。

设计件黄金源EBOM / BOM 管理ECO / ECN研发项目管理PLM → PDM 衔接

PDM 产品数据管理

  • CAD 集成：支持设计数据签入/签出、模型与工程图关联、属性自动提取。
  • BOM 自动生成：从设计模型形成 EBOM，减少人工录入，保持设计与结构一致。
  • 图文档管理：统一管理图纸、规范、技术文件、模型和交付物。
  • 版本、基线、权限：记录版本历史，在关键节点形成数据快照，并按角色控制访问。

BOM 管理

  • 来源页能力：支持 EBOM → PBOM → MBOM 的多视图结构管理。
  • 支持 BOM 差异比较、版本管理、有效性范围和批架次/序列号适用性。
  • 预审衔接：后文"研发主链"中的 PLM → PDM → CAPP 数据流，以 EBOM、设计件、版本和构型为关键对象。

变更管理

  • ECR：记录变更需求、原因和影响范围。
  • ECN：正式通知相关部门，触发审批和实施准备。
  • ECO：执行变更并更新受影响的数据对象。
  • 预审衔接：ECO 闭环已并入 PLM 洽谈结论，后续重点是变更对象、状态、审批角色和生效范围落账。

项目管理

  • 项目模板、WBS 任务分解、责任人与交付时间管理。
  • 研发交付物可与 PLM 数据对象关联，便于按项目追踪图纸、BOM、文档和变更。
  • 项目进度、团队任务和人员负荷可视化，支撑工程项目管理一期范围。

协作管理

  • 跨部门在线协作、任务分发、流程审批、待办提醒和协作记录留痕。
  • 支持供应商受控访问的协作模式，但昌兴复材是否启用外部协作边界需另行确认。
  • 预审衔接：OA 与 PLM/PDM 的审批协同，需要明确冻结、生效、退回、会签等状态。

协作与集成

  • 来源页列出 ERP、MES、WMS、CRM、PBI、OA 等系统集成方向。
  • 本次只保留必要衔接：PLM → PDM 的工程 BOM 发布、OA ↔ PLM/PDM 的变更审批协同、后续 PLM/MES/ERP 数据互通。
  • 字段映射、接口频率、异常处理和主写方仍以第 15 节接口卡为准。
预审口径约束

Windchill 的通用产品能力不等于昌兴复材一期交付范围。凡涉及具体接口字段、实施周期、CAD工具适配范围、ERP/MES/WMS双向集成细节，均需在接口卡或供应商技术确认中落账。

现状痛点：为什么 MES 不能只做"上线一个系统"

来源页列出 14 项核心痛点，核心问题不是单点效率低，而是生产、工艺、质量、物料、设备和管理决策缺少实时、可信、可追溯的数据闭环。

生产进度不透明无法实时掌控计划流转状态，决策依赖人工汇报。
资源调度不科学设备利用率、人员负荷缺乏数据支撑，依靠经验调度。
管控模式被动缺乏事前预警，以"救火式"处理为主。
信息失真数据获取依赖人工询问，缺乏客观实时数据源。
非增值工作繁重大量时间耗费在手工记录、单据传递、寻找物料上。
工艺版本控制薄弱难以确保始终使用最新版图纸，存在质量风险。
变更响应滞后设计工艺变更无法实时下发车间，执行脱节。
过程防错缺失依赖个人经验，易发生工序漏做、参数用错。
追溯效率低下质量追溯需翻查大量纸质文件，耗时且准确性低。
质量数据孤立检验数据未与生产数据联动，无法系统化分析。
计划可执行性差插单急单频繁打乱排程，加大管理难度。
在制品管理混乱在制品数量、位置、状态不明，影响交付周期。
决策缺乏数据支撑无法获取准确及时的生产质量数据，难以科学决策。
记录篡改风险全过程依赖纸质单据，存在记录缺失、篡改风险。

MDM 是基石，不是可选项

没有统一主数据，接口越多越乱
这是今天最重要的结论

系统集成不是把系统连起来就结束。没有统一组织、人员、物料、BOM、批次、供应商、资质和术语口径，接口越多，冲突越快暴露。

没有 MDM 的后果

接口只是搬运冲突：系统 A 发出的字段，系统 B 不知道如何解释；系统 C 修改了数据，系统 D 仍使用旧版本。

有 MDM 的效果

接口有共同语言，字段有权威来源，异常有责任人，追溯链可以跨系统连续查询。

今天要确认

组织身份权威源、编码规范推进路径、字段台账责任、Q7 数据中台/集成总线路线。

物料编码设计五原则

唯一性：每一个物料全公司范围内有且仅有一个编码，跨系统共用。

稳定性：编码一经创建，不因物料名称、规格变更而修改；变更须新建物料。

可读性：编码结构须兼顾人工识别与系统解析，不使用纯流水码。

扩展性：分类位预留扩展空间，避免未来分类调整导致编码体系崩溃。

系统兼容性：编码长度与字符集须经各系统确认，确保无截断或乱码风险。
