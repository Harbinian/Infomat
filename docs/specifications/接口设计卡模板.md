# 接口设计卡模板

> 每条集成线一张卡，供实施商在接口设计阶段使用
> 版本：V1.0 | 日期：2026-05-01

---

## 接口设计卡 #1：PLM → PDM（工程BOM发布）

| 字段 | 内容 |
|------|------|
| **集成方向** | PLM（工程系统） → PDM（BOM管理） |
| **集成目的** | 将设计态EBOM（含铺层定义、材料规范、固化工艺规范）受控传递给PDM，作为MBOM转换的数据源 |
| **触发时机** | 工程发布（Engineering Release）时触发 |
| **数据格式** | JSON / XML（待与PLM供应商确认） |
| **数据内容** | 物料编码（PLM侧）、件号（Part Number）、版本版次、铺层顺序（Ply Stack-up）、材料规范号、固化工艺规范号、NDT检测规范号、虚拟件标记 |

**字段映射表**

| PLM字段 | PDM字段 | 说明 |
|---------|---------|------|
| item_code | material_code | 物料编码 |
| part_number | part_number | 对外交付件号 |
| revision | rev | 版次（如A/B/C） |
| ply_sequence | ply_stackup | 铺层顺序定义 |
| material_spec | mat_spec_no | 材料规范号 |
| cure_spec | cure_spec_no | 固化工艺规范号 |
| ndt_spec | ndt_spec_no | NDT检测规范号 |
| is_virtual | virtual_item_flag | 虚拟件标记（0=实物，1=虚拟） |

**异常处理**
- 虚拟件不过渡到PDMBOM结构，过渡时需过滤
- PLM发布版本与PDM接收版本需严格一一对应，不允许覆盖旧版本
- 接口失败时自动告警，触发人工介入流程

**接口示例**
```json
{
  "integration_id": "PLM-PDM-001",
  "trigger": "engineering_release",
  "material_code": "CF-PNL-00001",
  "part_number": "C919-RFFUP-001",
  "revision": "A",
  "ply_stackup": [
    {"ply_no": 1, "material": "T300/197gsm", "orientation": "0°", "area": "A"},
    {"ply_no": 2, "material": "T300/197gsm", "orientation": "45°", "area": "FULL"}
  ],
  "mat_spec_no": "MS-PREPREG-T300-001",
  "cure_spec_no": "PS-CURE-AUTOCLAVE-001",
  "ndt_spec_no": "NDT-SPEC-UT-001",
  "virtual_item_flag": 0
}
```

## 接口设计卡 #2：PDM → CAPP（受控EBOM + MBD传递）

| 字段 | 内容 |
|------|------|
| **集成方向** | PDM → CAPP（工艺设计系统） |
| **集成目的** | 将受控EBOM和MBD模型传递给CAPP，驱动工艺路线设计和工序展开 |
| **触发时机** | PDM受控发布后自动推送，或CAPP按需拉取 |
| **数据格式** | STEP AP242 / JSON（待确认） |
| **数据内容** | EBOM结构、MBD三维模型（含PMI标注）、材料定义、公差定义 |

**字段映射表**

| PDM字段 | CAPP字段 | 说明 |
|---------|---------|------|
| bom_structure | process_bom | EBOM树状结构 |
| mbd_model | 3d_model | 含PMI的三维模型 |
| material_def | material_spec | 材料规格 |
| tolerance_def | pmi | 尺寸公差标注 |

**特殊说明**
- 铺层数据（Ply Stack-up）需作为独立属性字段传递，不嵌入BOM结构
- MBD模型需包含几何拓扑和PMI，驱动三维工艺设计

## 接口设计卡 #3：CAPP → MES（MBOM下发）

| 字段 | 内容 |
|------|------|
| **集成方向** | CAPP → MES（北京虎蜥） |
| **集成目的** | 将制造BOM（含工序分工、工装信息、工艺规范）下发给MES，驱动车间执行 |
| **触发时机** | MBOM审批通过后，MES按需拉取或CAPP推送 |
| **数据格式** | JSON / 数据库视图（待与MES供应商确认） |
| **数据内容** | 物料编码、MBOM工序结构（工序号/名称/工艺规范/工装/定额）、固化工艺规范关联 |

**字段映射表**

| CAPP字段 | MES字段 | 说明 |
|---------|---------|------|
| material_code | work_order.material_code | 物料编码 |
| operation_no | operation.sequence | 工序序号 |
| operation_name | operation.name | 工序名称（如铺层、固化） |
| work_center | operation.work_center | 工作中心 |
| tool_id | operation.tool_code | 工装编号（模具/热压罐） |
| cure_spec_no | operation.cure_spec | 固化工艺规范号（关键字段） |
| material_consumption | operation.bom_qty | 材料消耗定额 |
| work_hours | operation.std_hours | 工时定额 |

**关键约束**
- 固化工艺规范号（Cure Spec No.）必须与EBOM中的固化工艺规范一一对应，MES工序关联后不得修改
- 工装序列号（如热压罐编号）需记录到每件零件，固化曲线参数（温度/压力/时间）必须记录到件

## 接口设计卡 #4：ERP-PP → MES（生产订单 + MBOM下达）

| 字段 | 内容 |
|------|------|
| **集成方向** | ERP-PP（用友U8/生产计划） → MES（北京虎蜥） |
| **集成目的** | 将生产订单、工艺路线、MBOM分工定额下达至MES，驱动车间排产和执行 |
| **触发时机** | ERP生产订单创建并审批通过后推送 |
| **数据格式** | 用友U8标准接口（DB视图/API，待确认） |
| **数据内容** | 生产订单号、物料编码、工艺路线、MBOM分工、定额数量、计划开工/完工日期 |

**字段映射表**

| ERP-PP字段 | MES字段 | 说明 |
|-----------|---------|------|
| production_order | work_order.id | 生产订单号 |
| material_code | work_order.material_code | 物料编码 |
| bom_routing | routing | 工艺路线（分工） |
| bom_quantity | work_order.qty | 数量 |
| plan_start_date | work_order.plan_start | 计划开工日期 |
| plan_end_date | work_order.plan_end | 计划完工日期 |
| workstation | work_center | 工作中心 |

**异常处理**
- ERP侧订单变更时，需同步推送至MES，MES重新计算排产
- 接口延迟超过5分钟告警，人工介入确认

## 接口设计卡 #5：MES → ERP-PP/CO（完工反馈 + 工时回写）

| 字段 | 内容 |
|------|------|
| **集成方向** | MES（北京虎蜥） → ERP-PP（用友U8） & ERP-CO（用友U8） |
| **集成目的** | 完工报告回写ERP，工时数据归集至成本中心 |
| **触发时机** | 工序完工报工时实时推送 |
| **数据格式** | JSON / DB视图（待确认） |
| **数据内容** | 工序完工状态、实际工时、消耗物料批次号（关键追溯字段） |

**字段映射表**

| MES字段 | ERP-PP字段 | ERP-CO字段 | 说明 |
|---------|-----------|-----------|------|
| operation_completion | work_order.completion | — | 工序完工标记 |
| actual_hours | — | labor_cost | 实际工时 |
| material_lot_no | — | — | **消耗物料批次号（适航追溯关键）** |
| work_center | cost_center | cost_center | 成本中心 |
| operator_id | — | — | 操作者工号（追溯用） |

**航空追溯要求**
- 每件零件消耗的预浸料批次号必须记录到MES工序完工数据中
- MES→ERP回写时，物料批次信息不得丢失，否则适航追溯链断裂

## 接口设计卡 #6：ERP-MM → WMS（库存同步）

| 字段 | 内容 |
|------|------|
| **集成方向** | ERP-MM（用友U8/物料管理） ↔ WMS（仓储管理） |
| **集成目的** | 库存数据双向同步，采购入库/领料出库实时联动 |
| **触发时机** | 入库单创建/审核时、出库单过账时实时推送 |
| **数据格式** | 中间表/消息队列（待与WMS供应商确认） |
| **数据内容** | 物料编码、批次号、库存数量、库位、有效期（预浸料专项） |

**字段映射表**

| ERP-MM字段 | WMS字段 | 说明 |
|-----------|---------|------|
| material_code | material_code | 物料编码 |
| lot_no | lot_no | 批次号（预浸料/紧固件必须） |
| quantity | quantity | 库存数量 |
| warehouse | storage_location | 库位 |
| expiry_date | shelf_life_date | 有效期（预浸料专项） |
| frozen_expiry_date | frozen_shelf_life_date | 冷冻存储有效期（预浸料专项） |

**预浸料特殊处理**
- WMS记录冷冻存储有效期，ERP-MM同步记录
- 出库时WMS记录出库时间戳，MES接收后开始计算环境暴露时间

## 接口设计卡 #7：WMS ↔ MES（预浸料批次流转联动）

| 字段 | 内容 |
|------|------|
| **集成方向** | WMS ↔ MES（双向） |
| **集成目的** | 预浸料出库后MES开始计算环境暴露时间，使用数据回写WMS更新剩余量 |
| **触发时机** | WMS出库扫码时 / MES工序完工报工时 |
| **数据格式** | 消息队列（实时推送） |
| **数据内容** | 批次号、出库时间、剩余有效期、使用量、使用零件号 |

**WMS → MES（出库触发）**

| WMS字段 | MES字段 | 说明 |
|---------|---------|------|
| lot_no | prepreg_lot_no | 批次号 |
| out_time | out_time_start | 出库时间戳（环境暴露计时起点） |
| remaining_shelf_life | remaining_valid_days | 剩余有效期 |

**MES → WMS（使用回写）**

| MES字段 | WMS字段 | 说明 |
|---------|---------|------|
| lot_no | lot_no | 批次号 |
| material_consumed | consumed_qty | 实际使用量 |
| part_no | used_for_part | 使用零件号（追溯用） |
| operation_no | used_in_operation | 使用工序 |

**告警机制**
- 有效期<7天时WMS向MES告警
- 环境暴露时间超限（通常30天）时MES告警，禁止继续使用

## 接口设计卡 #8：OA ↔ ERP-MM（采购申请审批）

| 字段 | 内容 |
|------|------|
| **集成方向** | 华天动力OA ↔ ERP-MM（用友U8/物料管理） |
| **集成目的** | 采购申请在OA审批通过后，自动生成ERP采购订单；审批结果回写OA |
| **触发时机** | OA审批流程完成时触发 |
| **数据格式** | 华天动力集成平台API / 中间表 |
| **数据内容** | 采购申请单号、物料编码、数量、供应商、价格、审批结论 |

**字段映射表**

| OA字段 | ERP-MM字段 | 说明 |
|-------|-----------|------|
| purchase_req_no | po_number | 采购申请单号 |
| material_code | material_code | 物料编码 |
| quantity | order_qty | 数量 |
| supplier | supplier_id | 供应商编号 |
| price | unit_price | 单价 |
| approval_result | approval_status | 审批结论（通过/驳回） |

## 接口设计卡 #9：OA ↔ PDM（ECO变更审批）

| 字段 | 内容 |
|------|------|
| **集成方向** | 华天动力OA ↔ PDM（工程数据管理） |
| **集成目的** | ECO变更单线上会签审批，审批结果回写PDM，触发EBOM版本更新 |
| **触发时机** | OA审批流程完成时触发 |
| **数据格式** | 华天动力集成平台API |
| **数据内容** | ECO编号、变更内容、影响物料清单、审批结论、审批人 |

**字段映射表**

| OA字段 | PDM字段 | 说明 |
|-------|---------|------|
| eco_no | eco_number | 工程变更单编号 |
| change_description | change_scope | 变更描述 |
| affected_materials | affected_items | 受影响物料清单 |
| approval_result | approval_status | 审批结论 |
| approver | approved_by | 审批人 |

**关键约束**
- PDM在接收到OA审批完成通知前，不得执行BOM版本切换
- 审批结论为"驳回"时，PDM保持当前版本，OA通知申请人

## 接口设计卡 #10：OA → 全系统（SSO单点登录）

| 字段 | 内容 |
|------|------|
| **集成方向** | 华天动力OA（IdP） → ERP / MES / PLM / WMS |
| **集成目的** | 统一身份认证，会话管理，单点登录全系统 |
| **协议** | **首选：OAuth 2.0 + OIDC**（备选：CAS 3.0） |
| **触发时机** | 用户登录OA后，点击各系统入口时触发跳转 |
| **数据格式** | OAuth 2.0 / OIDC 标准Token |
| **数据内容** | 用户工号、姓名、部门、岗位、角色（航空特殊：特种工艺资质状态） |

**字段映射表**

| OA字段 | 各系统字段 | 说明 |
|-------|-----------|------|
| employee_id | user_id | 统一工号 |
| employee_name | user_name | 姓名 |
| department | department | 部门 |
| position | position | 岗位 |
| role | role | 角色 |
| special_process_qual | qualification_flag | **特种工艺资质（MES派工校验用）** |
