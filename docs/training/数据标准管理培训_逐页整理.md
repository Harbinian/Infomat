| **多系统共用** | 针对在现有 IT 系统中多次使用，以及依据行内 IT 规划或相关经验在未来的 IT 系统中会多次使用的数据和代码 |
| **分析类源数据** | 公司管理分析类系统进行分析必须用到的源数据和代码 |
| **公司发文** | 公司已经发文进行明确要求的数据规范 |

## Slide 14 — 怎么做数据标准——数据标准执行落地方法

- 标题：**怎么做数据标准——数据标准执行落地方法**
- 5 步流程（横向，左→右）：

| 步骤 | 关键内容 |
|---|---|
| 1. **定义数据标准** | 在应用系统标准落地的主题：产品 / 客户 / 协议 / ……<br>在应用系统标准落地的内容：信息项 / 代码 / 引用国标、行标、公司标准 |
| 2. **确定标准落地范围及策略** | 分析对象：应用系统的数据模型、码表与数据标准的信息项、代码进行差异分析<br>分析方式：针对信息项以及代码，将标准与现状进行映射<br>工作方式：标准组与应用项目组分析并多次交流沟通<br>收益预测：对数据标准落地的收益进行分析；对现有系统由数据引起的问题进行分析 |
| 3. **制定落地方案** | 对应用系统落地建议：从信息项、代码等各方面对历史数据及现有系统的数据集及代码等提出落地建议<br>对数据标准的建议：根据实际应用情况，对数据标准组提出修订建议<br>方案制定：业务方案 / 系统建设/改造方案（需求、设计） |
| 4. **标准落地实施** | 系统建设/改造：新建系统调整（模型、界面、功能、接口）；已有系统短期兼容方案；已有系统长期改造方案（模型、界面、功能、接口）；建设/改造同步方案<br>历史数据清洗：辅助数据补录 / 历史数据转换 / 问题数据手工调整 |
| 5. **落地实施跟踪检查** | 各系统建设改造过程中的跟踪检查；对落地的应用系统落地情况进行检查，包括数据库模型、文档、界面等；对与落地应用系统相连的周边系统的改造情况进行跟踪检查，主要包括数据库模型、文档、界面等 |

- 反馈回路：**数据标准调整**（贯穿步骤 2 → 步骤 3）

## Slide 15 — 怎么做数据标准——数据标准落地执行的关键因素与总体策略

- 标题：**怎么做数据标准——数据标准落地执行的关键因素与总体策略**
- 引言：**数据标准落地是一项持续性的工作，其价值毋庸置疑，但同时在落地过程中也会为系统建设带来改造的工作量与复杂度，如何平衡阶段性的投入与产出，保障边际效益最大化是落地执行开展的首要原则，其关键因素包括：**
- 四项关键因素：

| 关键因素 | 要点 |
|---|---|
| **系统改造难度与风险考量** | 尽可能减少已投产运营系统的改造成本与产生额外问题的风险；需考虑外购的成熟软件系统改造的可行性；对于系统实施项目，尽可能在不延长项目实施周期的情况下进行数据标准的落地 |
| **落地的方式** | 对源系统的改造是数据标准落地最直接的方式，有助于控制未来数据录入的质量与准确性；对系统间接口的改造也是保障交互一致性的重要工作；数据平台入仓时将数据按照标准转换，可保障统计分析的准确性 |
| **业务价值实现的优先级** | 通过对集团业务运营和管理的收益分析，排定落地的优先级；对于相关性较强的数据标准内容，建议同时实施落地。 |
| **整体 IT 规划安排** | 按照集团 IT 规划的整体安排，未来的系统建设会有节奏、有计划的进行，数据标准的落地实施也需按照 IT 规划的建设步骤进行 |

- 落地总体策略（右侧栏）：
  - 以规划内即将新建的重要业务应用系统为契机，落实相关数据标准，并推动周边系统的改造
  - 近期而言，即将建设的数据平台将是数据标准落地的重点
  - 围绕上述系统的周边系统改造，也需要同步进行
  - 综合系统改造成本/收益，安排落地实施的优先级，选择最合适的落地方式
  - 对于已建系统，应先比对现有系统与数据标准的差异，制定落地的范围与实施方案
  - 对于在建的业务应用系统，要求按照相关数据标准要求在建设过程中落地，暂时无法落地的部分，应采取临时的方案或排定远期计划
  - 在改造代价不大的前提下，尽可能保证源系统的直接落地
  - 在计划范围内的标准落地，应至少保障系统接口及数据平台的落地
