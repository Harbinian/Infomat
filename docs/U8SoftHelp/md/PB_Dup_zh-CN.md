### 数据复制介绍

数据复制是将一个服务器的数据发送、复制到其他服务器的过程。

通过数据复制功能，可以使服务器在一个本地的账套内查看其他服务器中另一账套的数据，但不支持同时对账套进行操作。

数据复制支持增量复制，即发布方数据发生增量更改（增、删、改），系统自动将其传播到订阅服务器上，保持双方的数据一致。

【菜单路径】

企业门户－控制台－系统服务－数据复制

程序－用友U8－系统服务－数据复制

【名词解释】

-

发布服务器：提供数据以便复制到其它服务器的服务器。

-

分发服务器：作为分发数据库宿主并存储历史数据和/或事务以及元数据的服务器。常将分发服务器和发布服务器设置为同一台服务器，本系统称作发布-分发服务器。

-

订阅服务器：接收复制数据的服务器。

## 系统特点

Source page: `systemcharacteristic.htm`

### 系统特点

-

增强了安全性

-

实现了发布管理与订阅管理的分离，发布方和订阅方各自具有不同的权限。

-

发布方没有任何读写订阅方数据库的权限。订阅方具有读取发布方部分系统信息的权限和写发布库的权限。

-

提高了复制效率

-

允许用户自定义发布内容，减少网络传输数据量，提高复制效率。

-

优化复制过程，在创建订阅的同时初始化订阅库的架构，减少应用初始快照的负荷。

-

允许用户使用FTP方式下载快照，并对初始快照进行压缩。

-

支持Internet应用

支持通过Internet进行数据复制，使用FTP下载初始快照。

-

增加定制发布项目功能

用户可以根据实际需要，选择要发布的功能模块。用户也可以编辑每个功能模块所包含的数据表。

-

提供丰富的运行信息和友好界面

提供详细的发布属性信息、运行提示和代理会话信息。使用异步方式启动代理，界面操作不受影响。

-

自动重新连接功能

系统每两分钟检查一次分发代理是否工作正常，如果发现分发代理运行失败（网络连接错误等），系统自动启动分发代理，进行重新连接。

-

支持发布和订阅的集中管理

-

进行发布管理时，可以集中管理发布-分发服务器上的所有发布；

-

进行订阅管理时，可以集中管理订阅服务器上的所有订阅（限于启动或停止分发代理，以及浏览订阅运行信息等功能）。

### 使用条件

-

在第一次使用U8数据复制之前，请先运行本机的SQLServer企业管理器。

-

数据复制只支持Windows Server 2000、Windows Server 2003,Windows
Server 2008环境下安装SQLServer2000/2005/2008的标准版或企业版的数据库服务器；且发布服务与订阅服务的数据库版本必须一致（包括大补丁版本）。

-

SQLServer安装的磁盘分区必须具有2GB以上的可用空间。

-

发布-分发服务器机器名不能相同，必须唯一。

-

启动快照代理前，发布-分发服务器和订阅服务器端的Sqlserver agent服务必须启动。

-

通过Internet进行数据复制，必须在订阅服务器执行程序管理订阅，不能从远程管理。

-

适用于8.50以上版本数据，用于复制的数据表必须具有主键。

-

发布数据库和订阅数据库的库表架构必须完全一致（主外键关系一致、列的名称、类型、长度、次序一致）。

-

创建发布后，如有更改表结构的操作（例如，增加工资项目等），必须重新创建发布和相关订阅。

-

对账套库进行操作，如果操作增加（或删除）表（例如，项目管理中的增加项目目录操作、自定义表结构操作等），必须重新创建发布，否则增加（或删除）的表的内容无法复制。

-

在订阅尚未删除时，不允许对订阅库进行增加、删除或修改等操作。

-

对于已经创建发布或订阅的账套库，不允许重新引入覆盖

解答：使用订阅管理者前，需要先在发布-分发服务器上注册订阅服务器。请您在发布管理中点击数据复制->配置服务器菜单，注册订阅服务器，并确保在主界面的树状视图中订阅者节点下有您注册的订阅服务器。

-

在订阅管理注册登录时，提示?登录账号没有读取分发库信息的权限?或?登录账号没有读取UFSystem库信息的权限?，如何解决？

-

解答：其它操作（如未删除发布就重新安装U8等）可能造成权限的丢失。可以在发布管理中，点击账号管理->订阅账号管理菜单，然后点击重置权限按钮。

-

为何在订阅年度账时，提示?订阅的业务数据中的系统信息有错误?？

-

解答：在创建订阅的时候，如果没有找到订阅库中的数据版本信息，那么会提示这个信息。版本信息丢失的可能原因是订阅库已经做过订阅，但没有应用初始快照或初始快照应用失败，就删除了订阅（创建订阅时会清空订阅库内的部分数据）。请删除订阅库，重建订阅库。

-

通过局域网下载快照时，分发代理运行失败，提示错误信息?进程未能读取文件，因为发生操作系统错误5?，如何解决？

-

解答：发生这种错误的原因是没有正确配置订阅服务器SQLServer代理的服务启动账号。打开订阅服务器SQLServer企业管理器->管理->SQLServer代理->属性，重新设置服务启动账号。具体设置方法请参见U850数据复制使用说明文档。

-

通过FTP下载快照时，分发代理运行失败，提示错误信息?进程未能连接到 FTP 站点?或?进程未能检索文检?，如何解决？

-

解答：发布-分发服务器的FTP没有正确配置或FTP的用户名和密码有误或快照文件夹路径错误。请依次检查以下相关设置。（1）FTP服务是否运行正常；（2）FTP地址和端口配置正确；（3）FTP用户和密码是否正确；（3）快照文件夹位于FTP根目录下；（4）从FTP根到快照文件夹的路径正确。发现错误后，在发布属性中进行相应的修改，然后删除订阅，删除订阅库，重新创建订阅库，重新订阅年度账。

-

分发代理运行失败，提示?进程未能连接Distributor?，如何解决？

-

解答：这种错误是由于发布-分发服务器的Subscribe账号的密码已经改变，分发代理仍使用原来的密码。可以在订阅管理主界面的右侧的树状视图中选中本地的订阅者，然后再右侧上方的列表视图内选中订阅，单击鼠标右键，选择更改密码即可。

-

分发代理运行失败，提示?进程未能大容量复制到?？

-

解答：请依次进行如下检查：（1）硬盘是否有足够的空间；（2）发布和订阅出错的表的结构是否一致（字段的名称、数据类型、长度和次序是否一致）；（3）发布-分发服务器和订阅服务器的SQLServer版本和补丁是否一致。

-

创建订阅时，提示?发布库和订阅库的表结构不一致无法，创建订阅?，如何解决？

-

解答：本版数据复制要求发布数据库和订阅数据库的库表架构必须完全一致（主外键关系一致、列的名称、类型、长度、次序一致）。如果不一致，可以手工调节订阅库表的结构，或者删除发布后，输出要发布的数据库，然后在订阅方引入作为订阅数据库。

-

打开订阅库的自定义报表时，提示?没有使用当前报表的权限或有互斥的功能在执行?，如何解决？

-

解答：首先确认您的登录账号是否具有相应权限。如果具有所要求的权限，但仍出现相同提示，请打开数据复制管理器，执行?同步系统信息?功能，参见帮助中订阅者的相关操作。

-

设置代理权限工具无法使用，如何解决？

-

解答：设置代理权限工具的使用有一定的限制条件，条件不满足，则无法使用；如果无法使用设置代理权限工具，请依照帮助中的说明进行手工配置。参见设置代理程序权限

### 设置启动账号

如果选择通过局域网下载快照，那么必须确保订阅服务器的SQL Server Agent的启动账号具有发布-分发服务器快照文件夹的读取权限，即启动账号既有启动订阅服务器SQL

在工作组环境下和在域环境下的设置方式不同。可以通过手工方式进行配置，也可以使用自动方式（【账号管理－设置代理程序权限】）进行配置（有一定条件限制）。

手动设置

订阅服务器：菜单SQL目录－企业管理器－控制台根目录－SQL　SERVER组－local-管理－SQL
Server 代理－右键属性－常规－服务启动账户－本地账户－设置以上用户账号

-

订阅服务器：右下角任务栏SQL SERVER服务管理器

-

自动设置：账号管理－设置代理程序权限

【操作流程】

在域中手动设置：

-

在订阅服务器的SQL　Server代理设置服务启动账户，设本地账户，账号为域用户tt，并将tt加入订阅服务器的Administrators
组。

-

在发布－分发服务器上，域用户tt有访问快照文件夹的权限（将tt加入发布-分发服务器的Administrators组）。

-

在订阅服务器启动SQL Server Agent的服务。

在工作组中手动设置：

-

在发布－分发服务器设置用户账号，如tt，密码为***，并将tt加入发布-分发服务器的Administrators
组。

-

在订阅服务器设置用户账号，同上，密码一致，并将tt加入订阅服务器的Administrators
组。

-

在订阅服务器的SQL　Server代理设置服务启动账户，设本地账户，用户同上，密码一致。

-

在订阅服务器启动SQL Server Agent的服务。

使用【账号管理－设置代理程序权限】自动设置。使用条件如下：

-

必须以管理员账号登录Windows系统。

-

必须确保【管理工具-本地安全策略-本地策略-用户权利指派】中的&#8220作为服务登录&#8221指派给了系统管理员组（Administrators），否则SQLServerAgent无法启动。

-

使用自动设置工具只能用于本机操作，不能用于远程管理。

-

订阅服务器如果是域控制器，则不能使用自动设置工具，必须手工配置（并使用域账号进行配置）。

【手动设置应用举例】

设发布-分发服务器为A，订阅服务器为B，快照文件夹为A上的c:\***\ReplData。

-

在域U8Domain环境下，可以将域用户U8Domain\tt设为启动账号，设置U8Domain\tt必须有B上启动SQLServer
Agent的权限，而且有A上快照文件夹的权限c:\***\ReplData，即将U8Domain\tt设置为A和B上Administrators组的成员。

-

在工作组U8Workgroup环境下，在A和B上设置相同的本机账户tt，且具有相同的本机密码，设置A的本机用户tt具有读取c:\***\ReplData的权限，B机用户tt具有启动SQLServerAgent的权限，即将U8Domain\tt设置为A和B上Administrators组的成员。

## 复制代理

Source page: `copydeputize.htm`

### 复制代理

订阅创建成功后，需要启动快照代理和分发代理来执行复制。分发代理在订阅创建之后自动运行，所以我们只需要启动快照代理，可以在发布－分发服务器和订阅服务器上启动、停止、查看代理。

【菜单路径】

主界面左侧树状视图－复制代理－快照代理、分发代理

【操作说明】

-

启动/停止快照代理

-

点击&#8220快照代理&#8221，系统在主界面右侧上方的列表视图显示所有的快照代理，包括发布、发布者、发布年度库。

-

选中某个快照后，单击鼠标右键，用鼠标左键单击选择&#8220启动&#8221，系统启动相应的快照代理；单击选择&#8220停止&#8221，则停止快照代理。

提示：在生成初始快照和应用初始快照期间，不允许停止快照代理或分发代理，避免出现不可恢复错误，否则必须重新创建订阅。

-

查看分发代理

点击&#8220分发代理&#8221，系统在主界面右侧上方的列表视图显示所有的分发代理，包括发布、发布者、发布年度库、订阅者、订阅年度库、订阅类型。

-

启动/停止分发代理

选择要启动的分发代理，单击鼠标右键，用鼠标左键单击选择&#8220启动&#8221，系统启动相应的分发代理；单击选择&#8220停止&#8221，则停止分发代理。

【业务规则】

-

快照：指数据或数据库对象在任一时刻的瞬时状态。在事务复制中，指发布和订阅创建成功后，为第一次复制产生的数据或数据库对象，即第一次复制时发布中现有的数据或数据对象。

-

快照代理：快照代理程序将与所有的复制类型一起使用。快照代理程序准备已发布表和存储过程的架构和初始数据文件、存储快照文件以及记录分发数据库中的同步信息。快照代理程序通常在分发服务器上的
SQL Server 代理程序下运行。

-

日志读取器代理：日志读取器代理程序将与事务复制一起使用。它将标记为复制的事务从发布服务器的事务日志移动到分发数据库中。使用事务复制发布的每一个数据库都有其自己的日志读取器代理程序，该程序运行于分发服务器上并与发布服务器连接。如下图，事务日志－日志读取器代理－分发代理－订阅数据库。

-

分发代理：分发代理程序将与快照复制和事务复制一起使用。它将分发数据库上的快照作业和事务移给订阅服务器。分发代理程序通常运行于分发服务器上（对于强制订阅）或订阅服务器上（对于请求订阅）。

-

快照代理和分发代理运行的时机和条件：

-

快照代理的作用是生成快照文件。当发布和订阅创建成功后，在开始增量复制前，需要生成初始快照和应用初始快照（第一次复制），此时需要运行快照代理生成初始快照文件。如果只创建了发布，而没有相应的订阅，那么快照代理提示没有订阅需要初始化。如果快照生成成功，再启动快照代理，则快照代理提示没有订阅需要初始化。

-

分发代理的作用是应用初始快照或分发增量事务。如果快照还没有生成，分发代理提示初始快照尚不可用，然后分发代理停止。如果应用初始快照成功之后，没有增量事务需要分发，那么分发代理提示没有复制事务，然后分发代理停止。分发代理每2分钟检查一次运行状态，如果分发代理停止，将自动启动分发代理。

-

如图，初始数据：发布数据库－快照代理－快照文件夹－分发代理－订阅数据库。
