## 数据中心版系统管理概述

Source page: `systemsummarize.htm`

### 数据中心版系统管理概述

数据中心版系统管理目前仅支持Linux版SqlServer数据库、华为云RDS和阿里云RDS数据库。

系统管理模块主要能够实现如下功能：

-

对账套的统一管理，包括建立、修改、引入和输出(恢复备份和备份)。

-

对操作员及其功能权限实行统一管理，设立统一的安全机制，包括用户、角色和权限设置。

-

允许设置自动备份计划（RDS除外），系统根据这些设置定期进行自动备份处理，实现账套的自动备份。

-

对账套库的管理，包括建立、引入、输出、备份账套库，重新初始化，清空账套库数据。

-

对系统任务的管理，包括查看当前运行任务、清除指定任务、清退站点等。

### 数据库配置

数据中心版系统管理使用前，需进行如下准备工作：

数据源配置，基础库上传和账套升级引入。

数据源配置：

1.操作路径 应用服务器配置>数据库服务器 进入数据源配置界面如图

[Image: ../系统管理数据中心版-数据源配置.jpg]

2. 点击增加，可增加新的数据库服务器，仅支持SqlServer(Linux)、RDS(Huawei)、RDS(Aliyun)，如图

[Image: ../系统管理数据中心-数据源增加linux.jpg]

[Image: ../系统管理数据中心-数据源增加华为云.jpg]

[Image: ../系统管理数据中心-数据源增加阿里云.jpg]

3. 输入数据来源名称、选择对应的数据库服务器，输入用户名和密码，输入后可使用测试连接功能，测试所设置的数据库服务器是否连通。

4. 选择确定，所设置的数据来源服务器就添加到数据源列表中。用户也可对已设置的数据源进行修改删除操作。

【注意事项】

应用服务器可以管理多个数据库服务器，即可设置多个数据源和数据服务器。

实例ID、AccessKeyID、SecretAccessKey为非必填项。

基础库上传：

上传基础库信息至Linux服务器或RDS数据库，具体操作步骤详见数据中心版系统管理操作手册。

账套升级：

U8+V16.0及之前版本，支持平滑升级至U8+最新版本的账套，如果使用RDS，需要在U8+最新版本的传统系统管理中，将账套升级至最新版本，然后将升级后的账套部署到RDS上，才能在数据中心版系统管理中对该账套进行管理。

U8+V16.0之前版本并支持平滑升级至U8+最新版本的账套，如果使用Linux SQL，需要在U8+最新版本的传统系统管理中，将账套升级至最新版本，然后将升级后的账套部署到Linux系统上，才能在数据中心版系统管理中对该账套进行管理。U8+V16.0及以上版本，则可以先将账套部署到Linux系统上，然后在数据中心版系统管理中，将该账套升级至U8+最新版本。

【注意事项】

系统路径分隔符window下\和Linux下/存在区别，请特别注意。

## 注册

### 注册

用户运行用友U8管理软件系统管理模块，登录注册的主要操作步骤如下：

【操作步骤】

-

选择【开始】--【用友U8】--【数据中心版系统管理】，进入该模块；

-

选择【系统】--【注册】功能菜单，显示登录系统界面；

-

选择服务器，输入操作员名称。如果要以系统管理员Admin或安全管理员身份登录，直接在"操作员"栏中输入Admin或"SAdmin"即可；如果要行使账套主管其他管理员权限，以相应身份登录。

-

登录后显示"系统管理界面"，界面分为左、右上、右下三部分。左侧显示账套及账套库列表；右上部分列示的是各操作员正登录使用的各系统名称、运行状态和注册时间、登录客户端；右下部分列示的是这些系统中正在执行的功能。查看时，用户可在左侧选择账套或账套库，右上部分将相应显示该账套或该库中正在使用的产品情况，用鼠标选中一个子系统，右下部分将自动列示出该子系统中正在执行的功能。这两部分的内容都是动态的，它们将根据系统的执行情况而自动更新变化。

【注意】

-

对于系统管理员(Admin)、安全管理员(SAdmin)、管理员用户和账套主管看到的登录界面是有差异的，系统管理员、安全管理员登录界面只包括：服务器、操作员、密码、语言区域；而管理员用户、账套主管则包括：服务器、操作员、密码、账套、操作日期、语言区域。

-

运行状态：

正常(0)：表示正常；

正常(1)－正常(5)：表示客户端与数据库服务失去连接的时间。客户端与数据库失去连接多长时间被判定为异常在【U8应用服务管理器】--【加密服务】中设置。异常任务可手动清除异常任务，参见清除异常任务，也可以在【U8应用服务管理器】--【加密服务】中设置异常自动清除。

## 设置备份计划

Source page: `setbackupplan.htm`

### 设置备份计划

本功能仅支持Linux版数据库。

暂不支持RDS版数据库，如需备份可使用RDS自带的备份计划功能。

设置备份计划的作用是自动定时对设置好的账套或账套库进行输出(备份)。设置备份计划的优势在于设置定时备份账套/账套库功能，多个账套/账套库同时输出功能，实现无人干预自动输出，在很大程度上减轻了系统管理员的工作量，同时可以更好的对系统进行管理。

【操作步骤】

-

以系统管理员身份Admin或账套主管身份或有权限的管理员用户身份，进入系统管理数据中心版模块。

-

在"系统"菜单下选择"设置备份计划"，弹出"设置备份计划"功能界面。此时界面有11个功能按钮，作用分别如下：

-

〖打印〗按钮：打印功能是对设置的备份计划进行打印输出。

-

〖预览〗按钮：预览功能是对设置的备份计划进行打印效果的预先显示。

-

〖输出〗按钮：输出功能是将设置的备份计划输出为其它格式文件，格式有多种如Excel、mdb、TXT等数据结构，其功能是可以为其它应用提供数据来源。

-

〖增加〗按钮：此项功能是设置备份计划的开始工作，点击"增加"后，系统进入"增加备份计划"界面（其分为表头项和表体项。表头项包括：计划编号、计划名称、备份类型、发生频率、发生天数、开始时间、有效触发、保留份数、备份路径。表体项为账套号、账套名称、年度区间）

-

计划编号：系统可以同时设置多个不同条件组合的计划，系统编号是这些计划的标识号。最大长度可以为12个字符长度。

-

计划名称：可以对备份计划进行标称，最大长度40个字符

-

备份类型：以系统管理员(Admin)身份进入的可以进行选择，分为账套备份、账套库备份和账套库增量备份，对于以"账套主管"或"管理员用户"权限注册进入系统管理备份计划的，只能进行"账套库备份"或"账套库增量备份"。

-

账套备份：按照"发生频率"和"发生天数"备份整个账套的所有账套库，每次产生一份备份文件；比如设置每月进行账套备份，则1月产生一份备份文件，到2月再生成一份备份文件，一共2份。

-

账套库备份：按照"发生频率"和"发生天数"备份指定账套的指定账套库，每次产生一份备份文件；比如设置每天进行账套库备份，则1号产生一份备份文件，到2号再生成一份备份文件，一共2份。

-

账套库增量备份：在一个完整备份周期内，系统先进行账套库的完整备份，然后按照"发生频率"和"发生天数"备份增量内容，每次增量备份产生的备份文件覆盖上一次的备份文件，下一个完整备份时再产生一份新的备份文件。比如设置每周进行完整备份、每天进行增量备份，则第一周第一天产生一份备份文件是整个账套库的信息，第一周第二天备份时直接覆盖第一天的备份文件，内容是完整备份+第二天的增量变化，第三天备份时直接覆盖第二天的备份文件，内容是完整备份+第二、三天的增量变化，依此类推直到一周七天结束都只有一份备份文件；第二周第一天再完整备份产生一份备份文件，此时才有2份。

-

发生频率：系统提供"每天、每周、每月"的选择，即您可以设置备份的周期。账套或账套库备份时表示备份执行周期，账套库增量备份时表示完整备份之后备份增量内容的周期。

-

发生天数：系统根据发生频率，确认执行备份计划的确切天数。

选择"每天"为周期的设置，系统不允许选择发生天数；

选择"每周"围周期的设置，系统允许选择的天数为"1-7"之间的数字(1代表星期日，2代表星期一，3代表星期二，4代表星期三，5代表星期四，6代表星期五，7代表星期六)；

选择"每月"为周期的设置，系统运行选择的天数为"1-31"之间的数字，如果其中某月的时间日期不足设置的天数，系统则按最后一天进行备份。例如：设置为30，但在2月份时不足30天时，系统会在2月的最后一天进行备份

发生频率和发生天数组合确认备份的时间。举例来说：选择每周五进行备份，就有在发生频率中选择"每周"，在"发生天数"选择6即可以。

-

开始时间：是指在知道的发生频率中的发生天数内的什么时间开始进行备份。例如：选择每周六00：00：00时进行备份，就在发生频率中选择"每周"，在"发生天数"选择7，在开始时间选择00：00：00即可以。

-

完整备份频率：进行账套库增量备份时需要设置完整备份的周期，可以选择"每周"或"每月"，但是完整备份频率必须大于增量备份的"发生频率"。

-

有效触发：是指在备份开始到某个时间点内，每隔一定时间进行一次触发检查，直到成功。此处不是检查的周期，而是检查的最终时间点。(如遇网络或数据冲突无法备份时，以备份开始时间为准，在有效触发小时的范围内，系统可反复重新备份，直到备份完成。)

-

保留份数：是指系统可以自动删除多于指定数值的备份文件数量，当数值为0时系统认为永不删除备份。例如：设置为2，则系统始终保留2份备份数据，一旦有新的备份数据产生，则删除时间较早的多余备份文件。

-

备份路径：可以选择备份的目的地，即Linux操作系统上已有路径。

-

〖删除〗按钮：此功能执行可以删除被选定的备份计划

-

〖修改〗按钮：此功能是可以修改备份计划的内容。除"计划编号"不能修改之外，其它都可以修改。特别说明一点，在点击"修改"进入后，系统显示"注销当前计划"按钮，可以注销或启用当前设置好的备份计划。

-

〖刷新〗按钮：此功能是重新初始当前界面。

-

〖日志〗按钮：此功能详细记录每次的备份情况。

-

〖帮助〗按钮：此功能是可以调用当前界面的帮助。

-

〖退出〗按钮：此功能是退出备份计划设置。

注意

-

对于发生天数可以按规定范围进行选择，如果手工输入超过规定数值，则在增加、修改保存时系统提示有效范围。

### 安全策略

如今，信息安全的价值与重要性日益凸现，必须保护对企业发展状大至关重要的信息资产；另一方面，这些资产也暴露在越来越多的威胁当中，毫无疑问，保护信息的私密性、完整性、真实性和可靠性的需求已经成为企业和消费者最优先的需求之一。

一直以来，用友U8为了给用户提供一套安全的、可靠的ERP系统而不懈的努力。并以此保障用户业务的持续运转和企业的持续发展，降低风险防患未然。目前用友U8的应用安全策略和实践包括：用户身份和密码管理；子系统和用户特权管理；数据、功能等权限管理；登录控制；安全日志等。

U8安全管理员登录系统管理，'系统'下的'安全策略'功能提供了与'安全策略'有关的选项，如，制定密码策略等。"上机日志"中会记录对安全策略的各种修改,以方便用户查看。

【操作说明】

-

用户使用初始密码登录时强制修改密码：如果选中此项，则所有新增用户或老用户，只要没有修改初始密码，登录时都会强制其修改才能登录。

-

新增用户初始密码：提供给系统管理员操作的易用性改进，在此处系统管理员可以设置一个企业级的用户初始密码，即新增用户时的默认密码，但可修改。

-

设置用户密码最小长度：控制用户设置密码必须达到一定的长度，默认为零，即不控制长度。

-

设置密码最长使用期：即用户密码从设置开始计算，最长的使用天数，达到使用期限，用户必须修改密码才能正常登录。只能输入数字，单位为天，默认为0，即不控制密码最长使用天数。

-

设置密码最小使用期：即用户密码从设置开始计算，最短的使用天数。即用户每次设置的密码都必须使用一定天数之后才可以修改密码。只能输入数字，单位为天，默认为0，即不控制密码最小使用天数。建议此控制与"强制密码历史记忆密码个数"结合使用。

-

强制密码历史记忆密码个数：U8保存用户曾经使用过的密码，系统管理员在此处录入的个数，意味着用户修改密码时，不能重复修改为在这数字内的前几个使用过的密码。建议此控制与"设置密码最小使用期"结合使用。

例如：强制密码记忆密码个数设为'3'个，新增用户初始密码设为'123456'，某新增用户'USER'的初始密码即为'123456'，如果'USER'改过四次密码，分别为'abc'、'123'、'789456'、'8888'，当USER再一次修改密码时，如果修改成了'123'，系统不予以通过，因为在强制密码记忆密码个数设置了'3'，即系统将会将前三个历史密码默认为是不可以再次使用的。但是如果USER将密码改成'abc'，系统予以通过，因为'abc'并不在前三个历史密码中。

-

设置登录密码最多输入次数：用户在同一次登录期间最多允许输入错误口令的次数，超过此次数则注销该用户，需要管理员再次启用。只能输入数字，为数字型可用的最大位数，默认为0表示不限制次数。

如：设置登录时口令的最多输入次数为3，则连续输入3次错误口令后，该用户自动变为"注销"状态不能再登录，需要管理员手工"启用"才能继续使用。

### 新账套建立

在使用系统之前，首先要新建本单位的账套。用户在系统管理界面单击【账套】菜单选择【建立】，则进入建立单位新账套的功能。

系统提供建立全新空白账套和参照已有账套建账两种方式，满足新用户全新使用和老用户扩展使用的要求。

【操作步骤】

建账方式分为：新建空白账套 和 参照已有账套

A、如果您是U8新用户，或者老用户需要建立一个与已有账套没有关联的账套，可以选择'新建空白账套'方式建账。

第一步：输入账套信息 用于记录新建账套的基本信息，界面中的各栏目说明如下：

-

已存账套：系统将现有的账套以下拉框的形式在此栏目中表示出来，用户只能查看，而不能输入或修改。其作用是在建立新账套时可以明晰已经存在的账套，避免在新建账套时重复建立。

-

账套号：用来输入新建账套的编号，用户必须输入，可输入3个字符(只能是001-999之间的数字，而且不能是已存账套中的账套号)。

-

账套名称：用来输入新建账套的名称，作用是标识新账套的信息，用户必须输入。可以输入40个字符。

-

账套语言：用来选择账套数据支持的语种，也可以在以后通过语言扩展对所选语种进行扩充。

-

账套路径：用来输入新建账套所要被保存在Linux或RDS服务器上的路径，用户必须输入，可以参照输入，必须注意不同服务器路径格式区别。

-

启用会计期：用来输入新建账套将被启用的时间，具体到"月"，用户必须输入。

会计期间设置：因为企业的实际核算期间可能和正常的自然日期不一致，所以系统提供此功能进行设置。
用户在输入"启用会计期"后，用鼠标点击〖会计期间设置〗按钮，弹出会计期间设置界面。系统根据前面"启用会计期"的设置，自动将启用月份以前的日期标识为不可修改的部分；而将启用月份以后的日期（仅限于各月的截止日期，至于各月的初始日期则随上月截止日期的变动而变动）标识为可以修改的部分。用户可以任意设置。

例如本企业由于需要，每月25日结账，那么可以在"会计日历-建账"界面双击可修改日期部分（白色部分），在显示的会计日历上输入每月结账日期，下月的开始日期为上月截止日期+1((26日)，年末12月份以12月31日为截止日期。设置完成后，企业每月25日为结账日，25日以后的业务记入下个月。每月的结账日期可以不同，但其开始日期为上一个截至日期的下一天。输入完成后，点击〖下一步〗按钮，进行第二步设置；点击〖取消〗按钮，取消此次建账操作。

-

是否集团账套：勾选表示要建立集团账套，可以启用集团财务等集团性质的子产品。

-

适用UU：只有"适用UU"的账套才能在UU中列出，并可显示该账套下勾选"适用UU"的部门、以及勾选"UU用户"且在这些部门下有关联人员的操作员。

-

启用智能输入：勾选后才可启用客户端的智能输入功能，在输入部分字符时自动提示相关的档案。

第二步：输入单位信息 用于记录本单位的基本信息，单位名称为必输项。

输入完成后，点击〖下一步〗按钮，进行第三步设置。

第三步：核算类型设置 用于记录本单位的基本核算信息，界面各栏目说明如下：

-

本币名称 用来输入新建账套所用的本位币的名称。系统默认的是"人民币"，此项为必有项。

账套主管 用来确认新建账套的账套主管，用户只能从下拉框中选择输入。对于账套主管的设置和定义请参考操作员和划分权限。

企业类型 用户必须从下拉框中选择输入与自己企业类型相同或最相近的类型。系统提供工业、商业和医药流通三种选择。

-

账套信息-启用会计期间：如果不勾选'结转期初'，与新建空白账套一样，可以自由设置启用会计期间；如果勾选'结转期初'，只能在'建账方式'页所选来源账套的会计年度的下一年一月开始。

### 新账套库建立

对于企业来讲其是持续经营的，因此企业的日常工作是一个连续性的工作，U8支持在一个账套库中保存连续多年数据，理论上一个账套可以在一个账套库中一直使用下去。但是由于某些原因，比如需要调整重要基础档案、调整组织机构、调整部分业务等，或者一个账套库中数据过多影响业务处理性能，需要使用新的账套库并重置一些数据，这样就需要新建账套库。

账套库的建立是在已有账套库的基础上，通过新账套库建立，自动将老账套库的基本档案信息结转到新的账套库中，对于以前业务产品余额等信息需要在账套库初始化操作完成后，由老账套库自动转入新库的下年数据中。

【操作步骤】

-

用户首先要以账套主管的身份登录，选定需要进行建立新库的账套和上年的时间，进入系统管理界面。例如：需要建立999演示账套的2013新账套库，此时就要登录999账套的包含2012年数据的那个账套库。

-

然后，用户在系统管理界面单击【账套库】--【建立】菜单，进入建立账套库的功能。

-

系统弹出建立账套库的界面，显示当前账套、将要建立的新账套库的起始年度、本账套库内业务产品所在会计期间清单和建立新库主要步骤及其进度。这些项目都是系统默认显示内容，不可修改，便于用户确认建库的信息。如果需要调整，请点击〖放弃〗按钮操作重新注册登录选择。您如果确认可以建立新账套库，点击〖确定〗按钮；如果放弃账套库的建立可点击〖放弃〗按钮。

对于账套和账套库的区别，请见"账套和账套库的区别"

提示

-

只有具有账套主管权限的用户才能进行有关账套库的操作。

-

将要建立的新账套库的起始年度，默认是'当前账套库所有业务产品中最大月结月所在年度'+1。

-

只有账套中的最新账套库(所含年度最大)才能建立一个更新的账套库。

## 账套和账套库的区别

Source page: `differencebetweenaccountsetandannualaccount.htm`

### 账套和账套库的区别

在用友U8软件，其账套和账套库是有一定的区别的，具体体现在以下方面：

-

账套是账套库的上一级，账套是由一个或多个账套库组成，一个账套库含有一年或多年使用数据。一个账套对应一个经营实体或核算单位，账套中的某个账套库对应这个经营实体的某年度区间内的业务数据。例如：某单位建立账套"001正式账套"后在2009年使用，然后在2010年的期初建2010账套库后使用，则"001正式账套"具有两个账套库即"001正式账套2009年"和"001正式账套2010年"；如果希望连续使用也可以不建新库，直接录入2010年数据，则"001正式账套"具有一个账套库即"001正式账套2009~2010年"。

-

对于拥有多个核算单位的客户，可以拥有多个账套(最多可以拥有999个账套)。

对于账套和账套库的两层结构的方式好处是：

-

便于企业的管理，如进行账套的上报，跨年度区间的数据管理结构调整等等；

-

方便数据备份输出和引入；

-

减少数据的负担，提高应用效率。

单位信息：所有信息

注意

## 账套引入

Source page: `accountsetimport.htm`

### 账套引入

本功能仅支持Linux版数据库，暂不支持RDS版数据库。

引入账套功能是指将系统外某账套数据引入本系统中。用户可使用系统管理中提供的备份功能（设置备份计划）或输出功能，将U8账套做备份，当需要恢复账套时，可使用引入功能将备份的账套恢复到U8系统中。当账套数据遭到破坏时，将最近复制的账套数据引入到本账套中，尽量保持业务数据完好；同时该功能也有利于集团公司的操作，子公司的账套数据可以定期被引入母公司系统中，以便进行有关账套数据的分析和合并工作。

【操作步骤】

-

系统管理员在系统管理界面单击【账套】的下级菜单【引入】，则进入引入账套的功能。

-

输入要引入的账套数据备份文件和引入路径，系统自动显示该备份文件对应账套的基本信息(如账套号、账套名称)，点击〖确认〗按钮开始引入。

-

通过〖选择备份文件〗可以逐个选择多个备份文件进行引入，也可以〖删除〗某行不引入对应账套。

-

如想放弃，则点击〖取消〗按钮。

【注意事项】

-

引入以前的账套或自动备份的的账套，应先使用文件解压缩功能，将所需账套解完压缩后再引入。

-

注意Linux版数据库路径格式。

### 库存管理

-

-

序列号规则、序列号构成维护：将源账套库中的序列号规则和序列号构成维护全部结转到新账套库中，用户可修改。

-

序列号状态：将源账套库中所有在库状态的序列号全部结转到新账套度中。

2、结转规则：

-

重新初始化时如果用户选择要结转库存结存，则应保证上年度12月已结账。

-

期初余额结转规则：

-

新账套度中库存1月份已结账，则不能结转期初余额，如果1月份未结转则可重复结转期初数据，如果新年度账中已有期初数据则系统会先将期初数据清空后再结转。

-

新帐套库中库存期初中出库跟踪入库的存货已出库，不允许再结转库存期初。

-

如果新账套库中序列号流水中有数据，则不能结转序列号的数据（包括序列号规则、序列号构成维护、序列号状态），如果序列号流水中没有数据则可重复结转序列号，如果新账套库中已有相应的序列号档案，则系统先将数据清空后再结转。

【注意事项】

-

期初余额结转后，期初数据是未审核状态，用户可调整期初数据后再审核期初数据。

-

固定资产的期初数据不结转。

### 清空账套库数据

本功能仅支持Linux版数据库,暂不支持RDS版数据库。

有时，用户会发现某账套库中错误太多，或不希望将上一账套库的余额或其他信息全部转到下一年度，这时候，便可使用清空账套库数据的功能。"清空"并不是指将账套库的数据全部清空，而还是要保留一些信息的，主要有：基础信息、系统预置的科目报表等等。保留这些信息主要是为了方便用户使用清空后的账套库重新做账。

【操作步骤】

-

-

在系统管理界面单击【账套库】菜单，再将鼠标移动到【清空账套库数据】上，单击鼠标。

[Image: ../image75.gif]

-

账套主管用户可在界面中的会计年度栏目确认要清空的账套库的年度区间(仅供确认，不可修改)，同时做好清空前的备份、选择输出路径，点击〖确定〗按钮表示确认。这时为保险起见，系统还将弹出一窗口，要求用户进行再度确认；如果想放弃，则直接点击〖放弃〗按钮。确认后系统弹出窗口，开始执行清空账套库数据操作。

-

账套库数据清空后，系统弹出确认窗口。点击"确认"完成清空账套库数据操作。

注意：

-

清空账套库数据时一定要备份数据，然后再进行操作。

-

清空账套库只是清空数据并不清除基础设置、档案的内容。

## 数据卸出

Source page: `数据卸出.htm`

[Image: ../image27.jpg]

### 数据卸出

一个账套库中包含过多年份数据体积过于庞大而影响业务处理性能时，可以通过数据卸出功能把一些历史年度的历史数据卸出，减小本账套库的体积，提高运行效率。

数据卸出时，只能以会计年为单位进行处理，从本账套库的最小年度开始，到指定年度结束，卸出这个年度区间中所有业务产品的不常用数据。

数据卸出后，系统将自动生成一个账套库保留这些卸出的数据，相对当前使用的账套库来说，这个包含卸出数据的账套库可以称之为'历史账套库'。

用户以账套主管的身份注册进入系统管理，选择【账套库】菜单中的【数据卸出】，则进入数据卸出的功能。

【操作步骤】

1、系统简要介绍数据卸出的功能，明确后按提示点击〖下一步〗按钮。

2、系统列示出本账套库中启用产品的使用情况，包括启用日期和该产品当前所处的会计期间(这些都是用于确认不可修改的)，在此基础上可以选择需要卸出的年度。同时，卸出前最好做好备份，手动输入输出路径。

[Image: ../数据卸出2.JPG]

3、根据启用产品的情况进行数据检查，系统将分别检查上本账套库的数据是否满足各项卸出要求，并列出详细检查结果。如果有产品不满足卸出要求，则不允许继续卸出。

4、如果检查全部通过，点击〖下一步〗，系统显示可清除的相关数据供用户选择，选择卸出这些数据，可以减少当前账套库的数据量。并提供了转移历史账套库功能，用于缓解当前磁盘存储压力。使用提供的卸出后立即收缩当前账套库的功能，可以减小当前账套库的大小。如图

5、根据需要选择后，点击〖下一步〗，系统显示卸出的主要步骤的列表，如创建新账套库、各业务产品卸出准备、各业务产品清除数据前准备等等。点击〖卸出〗按钮开始逐项执行，并有进度条显示各项执行进度。如图

【注意事项】

-

只有账套中的最新账套库(所含年度最大)才能进行数据卸出。

-

所有需要月结的产品都12月结账，才能进行数据卸出。

-

可以卸出的年度，最小是本账套库的最小年度，最大是本账套库已启产品中所处会计期间最小值所在年份-1，即：当前期间不可卸出。

-

在一次卸出操作中，必须同时卸出指定年度范围内所有已启用产品的数据，不可分次卸出。

-

卸载前请一定做好数据备份，以免数据卸出后无法恢复。

### 合同管理

卸载规则

-

单据卸载需判断是否属于卸载的日期范围。

-

单据卸载时，要将单据操作日志和审批流相关信息一并卸载。

-

单据卸载时，都以整单为单位进行数据的卸载，即如果一张单据上有一条记录不满足卸载条件，则整张单据不允许卸载。

-

上游单据不卸载时下游单据也不能卸载，因其他相关接口产品要求合同执行单或合同结算单不能卸载时，由相关产品描述并处理。

-

合同下游单据为应收应付系统单据时，对应单据是否保留由应收应付处理（如合同生成的付款申请单/付款单）

-

单据的卸载条件都是或者的关系，只要不满足一个条件，则单据不允许卸载。

-

合同：

-

合同的生效日期在卸载范围内。

-

合同的卸载，不考虑上游请购单的状态

-

未结案的合同，不允许卸载，其下游业务单据控制不允许卸载。

-

已结案的合同，如果为非阶段性合同，其创建时间在卸载周期内的，允许卸载；如果为阶段性合同，分期执行合同，合同卸载时检查执行收款是否完成

-

已结案的合同，标的为项目或标的为存货，有项目核算的，合同卸载时，检查合同中项目是否已完工结算，如果没有，则不允许卸载。

-

合同为其他合同的主合同，在子合同未卸载前，不允许卸载主合同，主子合同需要一同卸载。

-

合同卸载时，要将合同变更单一起绑定卸载。

-

合同执行单：

-

合同执行单生效日期在卸载范围内。

-

合同未卸载，执行单不允许卸载。

-

未关闭的执行单，不允许卸载；已关闭执行单，其上游合同已结案卸载的，其单据时间在卸载周期内的，允许卸载。

-

合同结算单：

-

合同结算单生效日期在卸载范围内。

-

上游合同已结案卸载，上游合同执行单已卸载的，结算单已审核且核销完成的，其单据日期在卸载周期内的，允许卸载。

-

如果合同启用，应收应付未启用，则合同结算单在满足其他卸载条件后，生效后就可以卸载。

### 库存管理

【数据卸出规则】

1、总规则：

-

上游单据不可卸载时，下游单据也不卸载。下游单据不满足卸载条件时，上游单据满足卸载条件时，仍可卸载。

例如：采购订单不满足卸载条件时，其对应的下游到货单、入库单、发票等都不可卸载。相反如果入库单因未记账不能卸载时，其对应的上游单据到货单和采购订单仍可卸载。

-

采购/委外/进口订单、销售/出口订单均以关闭日期进行判断是否可卸载，即订单已关闭且在卸载日期之前关闭才可卸载。

-

采购/委外/进口到货单、销售/出口发货单以单据是否关闭或是否执行完成来判断，即到货单或发货单已关闭或虽未关闭但已执行完成时也可卸载。

-

存货核算在各业务系统中需要记账的单据如果未记账，则不可卸载。

-

卸载单据时，单据相关的审批流、货位记录、序列号记录同步卸载。

单据日期在卸载日期之前的期初数据（期初结存、期初不合格品、期初合格品序列号和期初不合格品序列号）和所有出入库单（包括采购入库单、销售出库单、产成品入库单、材料出库单、其他入库单和其他出库单）必须全部审核后才能进行数据卸载操作。

-

库存卸载的选项：库存计算库龄时是否包括红字出库单：选项为是或否。默认为是，卸载数据时系统将此选项计算库龄。

### 出口管理

【卸载规则】

总体规则：

-

单据日期大于卸载日期的不可卸载。

-

未整单关闭的不允许卸载。

-

对应的报价单没卸载则订单不卸载。

-

订单对应的出口合同不卸出，订单不可卸出。

-

出口订单未关闭不卸载。

-

关闭日期大于卸载日期或单据日期大于卸载日期的订单不卸载。

-

出口订单对应的任一未关闭销货单未执行完毕不可卸载。

-

（任一未关闭销货单未执行完毕的判断逻辑如下：

-

所有未关闭销货单的销货数量之和>累计出库量之和 或 销货数量之和>累计开票量之和）

-

出口订单对应的任一未关闭退货单未执行完毕不可卸载。

-

（任一未关闭退货单未执行完毕的判断逻辑如下：

-

所有未关闭退货单的 退货数量之和>累计退库量之和 或 退货数量之和>累计退票量之和）

-

单据日期大于卸载日期不可卸载

-

对应的出口订单不允许卸载的销货单不可卸载。

-

销货单未关闭且销货单未执行完成的销货单不可卸载

-

（未执行完成判断依据：销货数量之和>累计出库量之和 或 销货数量之和>累计开票量之和）

四、退货单

-

单据日期大于等于卸载日期不可卸载

-

对应的任何一个订单不允许卸载的退货单不可卸载

-

对应的销货单不允许卸载的退货单不可卸载

-

对于无来源的退货单(未参照订单或销货但生成的退货单),未关闭且业务未执行完毕的退货单不可卸载:

-

执行完毕判断逻辑:退货数量>累计退库量 或
退货数量>累计退票量

五、出口发票

-

未复核或单据日期大于等于卸载日期的出口发票不可卸载。

-

对应的任意订单不允许卸载的出口发票不可卸载。

-

对应的销货单不允许卸载的出口发票不可卸载。

-

是否退税申报为真时已报退税数量等于0的出口发票不可卸载。

-

对应退税单不可卸载的出口发票不可卸载。

六、退货发票

-

未复核或单据日期大于等于卸载日期的退货发票不可卸载。

-

对应的订单不允许卸载的退货发票不可卸载。

-

对应的退货单不允许卸载的退货发票不可卸载。

七、结汇单

-

未关闭或单据日期大于等于卸载日期的结汇单不可卸载。

-

对应的任何一个订单不允许卸载的结汇单不可卸载

-

对应的销货单不允许卸载的结汇单不可卸载。

-

押汇金额+结汇金额<信用证金额的结汇单不可卸载。

八、费用申请单

-

未经审核且单据日期大于等于卸载日期的费用申请单不可卸载。

-

对应的订单不允许卸载的费用申请单不可卸载。

九、退税单

-

未申报或单据日期大于等于卸载日期的退税单不可卸载。

-

对应的出口订单不允许卸载的退税单不可卸载。

-

对应的出口发票不允许卸载的退税单不可卸载。

十、自定义单证

-

有订单关联的单证：

-

随该订单一起卸载。

-

无订单关联的单证：

-

单据日期大于等于卸载日期的自定义单证不可卸载。。

十一、进程计划

-

随对应的出口订单卸载而卸载。

十二、客户存货对照表、客户存货价格档案不卸载

十三、港口、国家、贸易术语、贸易方式、海关编码、海关备案方式、手册料耗、单耗档案、单证定义：不卸载

-

## 工序委外

Source page: `工序委外.htm`

### 工序委外

【卸载规则】

总体规则：

-

所有单据按单据日期判断是否符合卸出条件。

-

所有单据都以整单判断，只要有一行记录不满足卸出条件，整单不可卸出。

-

上游单据不卸出，关联的下游单据不可卸出。

-

单据卸出时，对应的审批流信息一并卸出。

各单据卸载规则：

一、委外加工单

来源于生产订单：

-

对应的生产订单不可卸载，委外加工单不可卸载。

-

单据日期在卸载日期之后的不可卸载。

直接增加的：

-

委外加工单有未关闭的行记录不可卸载。

-

单据日期在卸载日期之后的不可卸载。

二、委外发料单

来源于生产订单：

-

对应委外加工单不可卸载，委外发料单不可卸载。

-

单据日期在卸载日期之后的不可卸载。

直接增加的：

-

对应委外加工单有未关闭的行记录，委外发料单不可卸载。

-

单据日期在卸载日期之后的不可卸载。

三、委外收料单

来源于生产订单：

-

单据表体有未挂帐记录，委外收料单不可卸载。

-

单据日期在卸载日期之后不可卸载。

-

单据行记录对应委外加工单不可卸载，委外收料单不可卸载。

-

收料单对应的明细帐收料单未开发票；收料单已开发票但未生成凭证，委外收料单不可卸载。

直接增加的：

-

单据表体有未挂帐记录，委外收料单不可卸载。

-

单据日期在卸载日期之后不可卸载。

-

单据行记录对应委外加工单未关闭，委外收料单不可卸载。

-

收料单对应的明细帐收料单未开发票；收料单已开发票，但收料单未生成凭证，委外收料单不可卸载。

四、不良品报告单

-

对应的生产订单标记为不可卸载，不良品报告单不可卸载。

-

单据表体行中有未挂帐记录不可卸载。

-

单据日期在卸载日期之后不可卸载。

-

不良品报告单对应明细帐不良品报告单未开发票；不良品报告单已开发票但未生成凭证，不良品报告单均不可卸载。

五、委外挂帐单

-

行记录对应的来源单据（收料单、不良品报告单）标记为不可卸载，委外挂帐单不可卸载。

-

单据行记录开票数量为0，委外挂帐单不可卸载。

-

单据日期在卸载日期之后不可卸载。

-

挂帐单对应明细帐未生成发票不可卸载。

六、加工费发票

-

应收启用，加工费发票未完成收款核销的不可卸载。

-

发票对应的明细帐记帐金额不为0且未生成凭证，加工费发票不可卸载。

-

单据日期在卸载日期之后不可卸载。

七、加工费明细帐

-

明细帐对应的收料单、不良品报告单、加工费发票、挂帐单不可卸载，则明细帐记录不可卸载。

### 角色

U8产品根据企业加强内部控制中权限管理的要求，支持按角色分工管理的理念，加大控制的广度、深度和灵活性。角色是指在企业管理中拥有某一类职能的组织，这个角色组织可以是实际的部门，可以是由拥有同一类职能的人构成的虚拟组织。例如：实际工作中最常见的会计和出纳两个角色(他们可以是一个部门的人员，也可以不是一个部门但工作职能是一样的角色统称)。我们在设置角色后，可以定义角色的权限，如果用户归属此角色其相应具有角色的权限。此功能的好处是方便控制操作员权限，可以依据职能统一进行权限的划分。本功能可以进行账套中角色的增加、删除、修改等维护工作。

【操作步骤】

-

在"系统管理"主界面，选择【权限】菜单中的【角色】，点击进入角色管理功能界面。

-

在角色管理界面，点击〖增加〗按钮，可增加角色。

-

点击〖增加〗按钮，显示"增加角色"界面；

-

输入角色编码，可以录入12位字符；

-

输入角色名称，可以是40位字符(角色编码和名称都不允许重复录入，而且此两项是必输项)；

-

在备注中可以加入对此角色的注释，可以录入119位字符。

-

在界面下部可以选择归属该角色的用户，从左侧的"备选用户列表"选中添加到右侧的"已选用户列表"即可。

-

点击〖增加〗按钮，保存新增设置。

-

可以使用〖定位〗功能，在角色列表中查找，选中要修改的角色，点击〖修改〗按钮，进入角色编辑界面，对当前所选角色记录进行编辑，除角色编号不能进行修改之外，其它的信息均可以修改。

-

删除当前的角色，点击〖删除〗按钮，则将选中的角色删除，在删除前系统会让您进行确认。如果该角色有所属用户，是不允许删除的。必须先进行"修改"，将所属用户置于非选中状态，然后才能进行角色的删除。

-

点击〖导入〗按钮，可以导入U8预制的一些角色，可以使用这些角色快速建立不同职责的操作员。

-

点击〖导入〗按钮，显示账套年度区间的选择界面，随后导入的角色及其包含的权限将导入到所选账套库中；

-

显示导入界面，在左侧显示的是提供了哪些预制角色，右侧显示当前系统中已经存在的角色；

-

左侧选择您需要导入的角色，点击〖导入〗按钮，就会根据"追加"还是"覆盖"的选项将所选角色导入当前系统。

提示：

1、追加选项：如果预制文件与当前系统中有相同的角色（角色编码相同），则不对当前系统中该角色进行操作，只插入当前系统中没有的角色；

2、覆盖选项：如果预制文件和当前系统中有相同的角色（角色编码相同），则先删除当前系统中该角色，然后把预制文件中的该角色插入到当前系统中；

3、选中界面左边的分类，将显示当前系统中已有的该分类下的所有角色，并把预制文件中和当前系统中相同的角色用蓝色表示出来。

-

点击〖刷新〗按钮，重新从数据库中提取当前用户记录及相应的信息。

-

对于界面的选项"是否打印所属用户"是指在打印角色的同时将所属的该角色的客户同时打印出来。

提示：

-

用户和角色设置不分先后顺序，用户可以根据自己的需要先后设置。但对于自动传递权限来说，应该首先设定角色，然后分配权限，最后进行用户的设置。这样在设置用户的时候，如果选择其归属那一个角色，则其自动具有该角色的权限。

-

一个角色可以拥有多个用户，一个用户也可以分属于多个不同的角色。

-

若角色已经在用户设置中被选择过，系统则会将这些用户名称自动显示在角色设置中的所属用户名称的列表中。

-

系统管理员或有权限的管理员用户可以进行本功能的设置。

### 划分权限

随着经济的发展，用户对管理要求不断变化、提高，越来越多的信息都表明权限管理必须向更细、更深的方向发展。用友U8提供集中权限管理，除了提供用户对各模块操作的权限之外，还相应的提供了金额的权限管理和对于数据的字段级和记录级的控制，不同的组合方式将为企业的控制提供有效的方法。用友U8可以实现三个层次的权限管理。

## 权限转授

Source page: `transferp.htm`

[Image: 权限转授%20转授成员.JPG]

[Image: 权限转授%20转授.JPG]

### 权限转授

此功能实现了除系统管理员外，也允许其他用户进行功能权限的授权。目的是减少系统管理员的压力和责任；完善功能权限的管理；提高功能权限授权的灵活性。

【操作说明】

-

在"系统管理"主界面，选择【权限】菜单中的【用户】，点击进入用户管理功能界面。

-

【用户管理】页面上选择用户，点击〖转授〗，设置该用户能够把权限转授给哪些人。如图

-

在"系统管理"主界面，选择【权限】菜单中的【权限】，给相应用户分配"权限转授"的功能权限。

-

拥有转授权限的用户登录门户后，可以在【功能权限转授】中设置权限转授，选择要转授给的用户，点击〖修改〗，弹出权限分配页面，设置要给用户转授的权限。如图

-

用户如果想收回转授的权限，则在权限分配页面把已经转授的权限取消即可，被授权的用户则只拥有它原来本身的权限。

【备注】

-

系统管理员和有【用户】、【权限】菜单操作权限的管理员用户都可以进行转授的设置。

-

权限分配页面中为灰色的部分为目标用户已经拥有的权限，不能对目标用户的该权限进行更改。

-

管理员删除用户能够授权的人时，已经授予的权限依然存在，需要管理员手动调整。

例如：系统管理员设置A可以对B进行转授，A对B进行了权限授权，系统管理员又设置了A不可以对B进行权限转授，此时B还拥有A对它转授的权限，需要系统管理员手动调整。

### 导入导出

要导入用户/角色、权限都必须存在，如果Excel文件格式不符或数据与导入的系统不匹配则不允许导入。

-

追加导入：在指定账套、年度区间(账套库)中指定用户/角色已有权限基础上，增加Excel中的权限内容，用户／角色原来拥有的权限继续拥有，导入后用户/角色拥有权限为原有权限和excel中权限之和。如图

-

覆盖导入：不考虑原有权限，导入后指定账套、年度区间(账套库)中的用户/角色的权限与Excel中一致。

【导出操作说明】

-

仅导出所拥有的权限：按所选操作员分别导出各自拥有的权限信息；如图

-

导出所有权限：导出系统中所有权限信息；

-

可以选择多个用户和角色进行导出，不同用户和不同角色分为不同页签，如果用户被设置角色，则同时导出用户所属角色情况。

【注意】

　如果文件过大(页签行数超过6万行记录或页签数量过大)，不允许继续导出。

如果导出环境使用office2007，则使用office2000的环境无法对其导入。office2000不向上兼容office2007，使用office2000进行导出，使用office2007可以进行导入。

### 上机日志

为了保证系统的安全运行，系统随时对各个产品或模块的每个操作员的上下机时间、操作的具体功能等情况都进行登记，形成上机日志，以便使所有的操作都有所记录、有迹可寻。

日志过滤如图

日志列表如图

【操作步骤】

-

用户以管理员身份注册进入系统管理。

-

单击【视图】下级菜单中【上机日志】即可执行。

【操作说明】

-

使用过滤功能

为了方便用户查看上机日志，系统还提供过滤功能来过滤上机日志的内容。

点击工具栏上的功能按钮〖过滤〗，输出"日志过滤"条件框，用户在界面中根据自己的需要输入过滤条件。

点击〖确认〗按钮，系统将自动按照用户设定过滤条件来对上机日志的内容进行过滤，并将过滤后的内容显示出来。

如果想放弃查询上机日志，则点击〖放弃〗按钮。

-

上机日志排序

为了方便用户查看上机日志，系统还提供了排序的功能，具体方法是：用户选择要进行排序的列，然后点击〖排序〗按钮即可。

-

实时刷新日志

上机日志是动态的，它随着系统的使用情况而不断发生变化，因此要想看到最新的上机日志，就要实时地将上机日志的内容予以刷新，刷新的办法是：用鼠标在菜单条中点击〖刷新〗按钮。

【注意事项】

-

本功能中可以查看所有上机日志，如果需要管理日志，执行备份删除、恢复日志的操作，应以安全管理员'SAdmin'的身份登录后在【系统】下级菜单中【数据清除】、【数据还原】中处理。

### 如何使用帮助

用友U8支持全程在线帮助，能够帮助您及时、快捷地获得所需要的帮助信息。

如何获取帮助

-

您可以在窗口界面点击〖帮助〗按钮，即可弹出帮助页面。

-

按F1快捷键获取帮助。

如何使用帮助

您点击左侧主题，右侧则显示相应的主题内容。在帮助中常用的格式有：隐藏内容、链接主题、链接页签、图形链接。

-

隐藏内容

为了保持帮助窗口的整洁性和条理性，我们对于部分内容或图表采取隐藏显示的形式，隐藏内容显示为绿色字体，点击绿色文字可打开隐藏的内容，再次单击，恢复隐藏。

-

链接主题

对于与当前主题内容有关的主题，帮助文件采取链接主题的形式。链接主题显示为蓝色字体，并加下划线，用户单击链接主题，则帮助跳到所链接的主题，文件左侧的目录也跳到相应的文件。

用户如返回原来的主题，可按〖后退〗；若跳了若干个主题，则按若干次〖后退〗。

用户点击过的链接主题，显示为红色字体。

-

帮助文件中的链接页签

帮助主题的内容较多时，可以将链接关联到相应主题的特定位置，再按〖后退〗则返回原来的主题。

链接页签与链接主题的区别是：前者链接到主题的页签位置，可以是同一个主题；后者链接到相应的主题。

帮助文件中的相关主题按钮

对于与当前主题内容有关的若干个主题，帮助文件采取相关主题按钮的形式。

用户点击按钮，则弹出相关主题菜单，用户可选择要查看的主题，帮助跳到所链接的主题，文件左侧的目录也跳到相应的文件。

-

帮助文件中图形的链接

对于帮助文件中的图形，当鼠标移动到有链接的功能框或按钮上，鼠标会改变为小手形状，用户可直接点击，链接到相关主题。

### 导入加密证书

通过此功能，可以在加密服务器中导入软/硬加密许可文件。用于软/硬加密异机代办注册产品授权时导入许可文件使用。

【功能路径】

进入系统管理，导航栏上"系统"-"加密证书管理"-"导入加密证书"

【操作过程】

软加密：

-

找一台能上网的电脑登录用友产品注册网站http://register.yonyou.com/，点击"软加密产品注册"，输入产品注册卡背面的用户ID和密码；

-

进入软加密产品注册页面后点击"异机代办注册产品授权"；如图

[Image: ../image34.jpg]

-

填写注册单位的详细信息后，在文件名处点击"浏览"按钮上传导出的软加密证书配置信息，即SoftCertParamData.zip文件，最后点击提交注册；如图：（注：1、双机热备版软加密只支持异机代办注册产品授权，且会有两个文件名窗口，位于上方的文件名窗口用于上传主机的SoftCertParamData.zip文件，位于下方的文件名窗口用于上传备机的SoftCertParamData.zip文件；2、若第一次申请软加密使用的是异机代办注册的方式，请以后再次申请时也采用异机代办方式注册。）

[Image: ../image35.jpg]

-

提交注册后网页会给出注册用户的服务识别码和服务密码，点击"下载文件"下载软加密授权文件保存到本地；如图：

[Image: ../image36.jpg]

-

将软加密授权文件拷贝到加密服务器中，在加密服务器里登录系统管理，点击"系统"-"加密证书管理"-"导入加密证书"；

-

选择软加密证书的存放路径，点击打开；

-

若导入成功，则系统会给出提示信息"文件导入成功"。（注：双机热备版软加密的用户请将软加密授权文件分别导入到主机和备机中）

硬加密：

-

找一台能上网的电脑插入硬加密锁，登录用友产品注册网站http://register.yonyou.com/，点击"加密锁产品注册"；

-

进入加密锁产品注册页面后点击"U8+异机代办产品注册"；如图

-

在文件名处点击"浏览"按钮上传导出的加密证书配置信息，最后点击提交注册，提交注册后网页会给出注册用户的服务识别码和服务密码，点击"下载文件"下载加密授权文件保存到本地。（跟软加密异机代办类似）

-

将加密授权文件拷贝到加密服务器中，在加密服务器里登录系统管理，点击"系统"-"加密证书管理"-"导入加密证书"；

-

选择加密证书的存放路径，点击打开；

-

导入成功后，系统会给出提示信息"文件导入成功"。

【注意事项】

-

软加密不支持虚拟机充当加密服务器，若用户使用的是软加密请使用实体机；虚拟机可连接实体机的软加密地址来使用U8产品。

-

U8V11.0及以后版本不支持通卡。

-

若加密服务器能连通互联网，可直接在用友产品注册网站进行本机注册产品授权，无须进行"导出加密证书配置信息"和"导入加密证书"操作。

-

加密注册时会绑定所申请加密服务器的硬件信息，同一个加密注册账号只能申请一台机器，已经申请过软加密的账号再次申请其他机器时网站会给出提示：已安装超过规定次数(不同硬件)。

-

导入加密证书须在加密服务器本机登录系统管理或实施工具进行操作。

-

生成的加密证书只能在加密服务器上使用，若导入到其他机器中则读不出加密信息。

-

软加密导入后"产品登录情况"中左树会显示当前版本产品卡，右侧若有日期则表示的是软加密的使用期限，若没有日期则表示这是标准版软加密没有使用期限限制。

-

登录用友产品注册网站时必须使用IE浏览器，支持IE10以下的版本。登录后请运行用友产品注册网站提供的IE配置工具，对IE进行相关设置。用360浏览器或迅雷下载软证书存在风险，建议用户使用IE进行下载。

-

若进行导入加密证书时在路径中看不到加密授权文件，请将文件类型选择为All files即可。

## Online Revoke

Source page: `online_revoke.htm`

### 在线注销软加密证书

通过此功能，可以在加密服务器中注销软加密证书。用于用户更换软加密服务器前注销原有软加密证书使用（临时授权软加密、借用授权软加密、顾问版软加密、云加密都不支持在线注销）。

【功能路径】

进入系统管理，导航栏上"系统"-"加密证书管理"-"在线注销软加密证书"

【操作过程】

-

点击在线注销软加密证书；

-

弹出提示信息：若证书被注销，必须更换硬件设施，否则此机器不能再作为加密服务器，请确认是否还需要注销此证书；

-

点击是，完成软证书的注销操作。

-

软加密注销后从产品登录情况中可以看见软证书已被注销的提示，产品自动进入演示期的判断。

-

本机注销后可以再选择1台机器重新注册软加密，限制为同一个客户一年内只能做两台机器的重新发放。若用户1年内需要更换两台以上的加密服务器则需要走人工审核，即电话访问或现场派单。

【注意事项】

-

在线注销软加密证书支持异机代办，在登录系统管理时请输入应用服务器的地址即可。

-

软加密注销操作前请谨慎考虑，若证书被注销，必须重新注册申请软加密，否则被注销的软证书将永久失效。

## 升级问题解决方案

Source page: `upgradesolution.htm`

### 升级问题解决方案

-

如果升级失败，请先打开升级日志：U8安装目录\Admin\下文件名为
"UFDATA_"+账套号+"_"+年度.txt，查看详细的错误信息；

-

如果升级提示错误为"错误信息:-2147217900"表示SQL
Server 此时无法获取 LOCK 资源。请在活动用户数较少时重新运行您的语句，或者请求系统管理员检查 SQL Server 锁和内存配置。解决办法：

-

打开SQL Server查询分析器，在Master中运行以下语句：

sp_configure
'locks','2147483647'

reconfigure with
override

-

重启动Server。

-

在升级之前，建议先在查询分析器中执行
DBCC CHECKDB(年度库名称) 语句，检查年度库数据库是否有一致性错误，如果发现错误，请按照SQL Server的提示进行修复，修复后再进行升级。
