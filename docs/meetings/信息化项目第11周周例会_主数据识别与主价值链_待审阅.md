## 第一页：九个部门均已提交，但主数据识别尚未完成

本轮5个部门完成补充或首次提交。至此，9个部门均已完成部门级主数据清单提交，但多数成果仍更像一般数据清单，尚未分清主次。

- **提交进度**：9个部门均已提交部门级主数据清单。
- **当前差距**：清单已经列出数据，但尚未说明哪些数据需要作为核心对象持续治理，哪些属于一般数据项。
- **评价边界**：复材车间本轮暂不评价主数据生成行为，但仍参与主链现场使用核对。
- **阶段判断**：提交范围已经覆盖9个部门，下一步重点不是继续增加清单数量，而是结合流程和数据关系完成主次识别。

**本页结论：清单提交已经覆盖9个部门，但不能将“已提交”表述为“已完成主数据识别”。员工信息表行动项不在本页混写。**

## 第二页：交付质量开始分层，部分部门已形成业务深度

各部门本轮交付质量已经出现明显差异，物资保障部达到交付门槛，财务部和质量管理部的更新体现出更深的业务内容。

- **物资保障部**：交付物达到交付门槛。经研判，交付物质量已达到流程绑定的标准。
- **财务部、质量管理部**：均已进行重大更新，业务深度的体现非常明显。
- **经营发展部、运维安环部**：首次提交即达到质量管理部初次提交的水平，已经具备继续深化的基础。

**本页结论：本轮已出现达到交付门槛和明显深化的成果，后续评价应继续看业务深度及流程绑定情况。**

## 第三页：部门行动项通报——员工信息表尚未发布

员工信息表是行政人事部上一周形成的部门级行动项，当前状态为“未发布、未关闭”。该行动项不属于九部门主数据清单问题，不与本轮清单提交评价合并。

- **责任部门**：行政人事部。
- **当前状态**：未发布、未关闭。
- **关键缺口**：权威的员工岗位，以及员工所属部门、办公室或班组信息。
- **3000影响**：缺少权威岗位和组织归属将严重阻碍3000平台上线准备，员工身份、岗位和组织关系无法可靠核对。
- **责任边界**：行政人事部确认业务事实并发布可核对的信息表；PMO只确认行动项状态和关闭证据。
- **关闭条件**：员工信息表正式发布，岗位与组织归属信息齐全且可以核对，PMO再依据结果和证据确认关闭。
- **未核实事项**：当前没有已核实的截止日期、有效调整记录或具体执行人。本稿不作“逾期”判断，也不补造日期、调整记录或执行人。

**本页结论：员工信息表按独立部门行动项跟踪；该事项不是主数据清单问题，业务事实由行政人事部确认，PMO只负责状态和关闭证据。**

## 第四页：经过两个月学习，现在进入成果检验期

前期工作重点是学习流程、业务行为、数据对象、字段和来源证据的梳理方法。现在进入成果检验期，后续不再以“掌握了多少概念”判断成果，而是以真实业务能否讲清、跨部门能否接住、来源证据能否复核判断成果是否可用。

- **真实业务**：选择真实订单、项目、零件、生产任务、设备或岗位，从开始事件追到结束结果。
- **跨部门接续**：写清交付物、接收部门、接收动作和接收条件，使下游能够说明“怎样才算接住”。
- **对象与记录**：区分稳定数据对象、对象字段、表单字段和具体业务记录，不因名称相似、业务重要或存在编号就直接合并或认定为主数据。
- **异常与责任**：写清异常情况下谁执行什么动作、处理什么对象、产生什么结果。
- **来源证据**：每项关键结论能够回到制度、表单、台账或真实业务记录位置。
- **待确认事项**：不能可靠判断的内容保持待确认，并写明确认主体。

**本页结论：没有真实样本、跨部门承接或来源证据，不能把学习成果写成已经完成，更不能写成业务已经验收。**

## 第五页：行动项一——从一项真实工作中找出主链

“研发主链与计划执行流程治理”在本企业的实际口径下，应从客户数模输入后起算，围绕项目研制、制造准备和计划执行展开。公司不承担产品设计，不能把产品设计列为本企业主链环节。部门经常不是“没有流程”，而是很多判断和交接已经做成习惯，没有被说出来。下周不要求各部门重新罗列全部流程，而是选择一个真实订单、项目、数模对应零件或生产任务，从头到尾回答以下问题。

1. **什么事情发生后，本部门开始工作？**
2. **本部门需要先拿到谁提供的什么材料、数据或状态？**
3. **本部门实际执行哪些动作，作出哪些专业判断？**
4. **本部门完成后产生什么结果，哪些数据或状态发生变化？**
5. **哪个部门接着使用该结果，达到什么条件才算接住？**
6. **计划变化、材料不齐、设备异常、质量不合格或人员不具备资格时，本部门如何处理？**

建议先使用以下连续路径检查主链是否完整：

> 客户需求与合同 → 客户数模接收及启动输入确认 → 项目启动与计划 → 制造工艺策划 → 材料、工装、设备和人员准备 → 生产执行 → 检验与问题处置 → 产品交付、结算与复盘

其中，“客户数模接收及启动输入确认”应单独作为主链候选流程：至少说清接收对象、版本和状态，项目启动所需条件，以及后续数模变化如何传递。该流程的主责部门和会签部门仍需由业务人员确认。

满足以下任一条件的流程，应优先进入主链候选：

- 该流程中断后，项目研制、开工、生产、检验或交付无法继续。
- 该流程的输出会被下一部门直接用于作出判断或执行工作。
- 该流程决定客户数模能否进入项目、计划基线能否建立、物料或工装是否齐套、设备和人员是否可用、质量能否放行，或者成本与交付结果是否可控。

**本页结论：各部门先沿一项真实任务追问“从哪里来、做了什么、交给谁”，把已经存在但尚未说清的经验转成可核对流程。**

## 第六页：行动项一——六个部门先串起数模驱动的研制和生产主路径

以下流程来自当前部门流程输入基线，作为下周讨论的主链候选入口。流程是否真实适用、先后关系和跨部门交付物，仍由相关部门确认。

| 部门 | 建议优先放入主链的流程候选 | 本部门第一抓手 |
|---|---|---|
| 经营发展部 | 市场开发初步接触与方案确认；报价、商务谈判与定价管理；项目合同评审执行管理；销售订单评审和执行管理 | 选择一个真实订单，说明客户需求如何转成合同和销售订单，并与客户数模共同形成项目启动输入 |
| 项目管理部 | 项目启动策划；研制项目策划；年度一层计划、月度二层计划和三层作业计划管理；开工评审管理；项目进度监控 | 选择一个真实项目，把启动令、工作分解、里程碑、生产计划和偏差处理串成一条线 |
| 工程技术部 | 制造工艺策划；工艺网络计划管理；制造工艺设计统筹；工艺过程管控；零件制造工艺文件管控 | 选择一个客户数模对应的真实零件，从项目启动后开始，说明制造工艺策划、工艺路线和制造大纲如何形成并交给现场使用 |
| 物资保障部 | 物料接收、检验、运转、储存与台账管理；冷库材料出入库管理；工装接收、建账、存放与保管；工具申请与采购管理 | 选择一种关键材料和一套关键工装，说明齐套判断、发放、退回和状态反馈如何支撑开工 |
| 复材车间 | 罐前计划编制；排罐执行与跟踪调整；关键件横向跟踪；工序问题闭环与考核 | 选择一个批次或关键件，说明计划如何到达班组、现场如何反馈进度和异常；本抓手不改变“本轮暂不评价主数据生成行为”的结论 |
| 质量管理部 | 检验方案策划管理；首件检验管理；产品检验管理；不合格品审理与处置；交付文件准备管理 | 选择一次首件或产品检验，说明技术要求如何转成检验结果、不合格处置和交付放行证据 |

**本页结论：经营、项目、工程、物资、车间和质量应先把“订单与数模—项目—工艺—计划—资源—执行—放行”连接起来。**

## 第七页：行动项一——三个保障部门把成本、设备和人员条件接入主链

保障流程不需要全部进入主链。只有直接影响项目能否启动、计划能否执行或产品能否交付的部分，才作为主链中的必要条件。

| 部门 | 建议接入主链的流程候选 | 本部门第一抓手 |
|---|---|---|
| 财务部 | 产品全成本测算；生产成本事中控制；月度产品成本核算与成本结转；月度资金计划编制与执行管理 | 选择一个真实项目，说明报价成本基线、实际材料与工时、成本偏差、结算结果如何前后对应 |
| 运维安环部 | 设备计划与资产策划；维护保养与维修保障；设备异常与变动管理；风险识别与分级管控 | 选择一台关键设备，说明设备可用状态、保养维修、故障停机和安全风险如何影响生产计划 |
| 行政人事部 | 员工招聘录用管理；岗前培训与取证管理；技能矩阵与评价管理；培训需求分析与年度培训计划制定 | 选择一个关键岗位，说明人员需求、到岗、培训、取证、技能状态如何决定任务能否分配和执行 |

各部门下周提交的不是“更多流程名称”，而是一份可以接起来的最小成果：

- 明确一个流程的开始事件和结束结果。
- 写清关键业务行为、执行角色和异常处理。
- 列出流程中被创建、修改、使用、传递或保管的数据对象。
- 写清跨部门交付物、接收部门和接收条件。
- 附上能够直接核对的制度、表单、台账或真实业务记录位置。

业务部门负责说明并确认真实做法，主数据管理（Master Data Management，MDM）工作组负责组织结构核验，信息化项目管理工作室（PMO）负责登记和跟踪行动项；三类责任不得相互替代。

**本页结论：九个部门都要进入同一条主链，但每个部门只从一个最熟悉、最能影响下游的流程开始。**

## 第八页：行动项二——MDM工作组先锁定初版范围，再统一编码规则

主数据编码规范初版的起草与发布工作移交至MDM工作组。工程技术部不再承担起草任务，已形成的内容作为评审输入继续使用。

当前已有航空存货四段式编码评审稿，但该稿状态为`PARTIAL`（部分完成），只覆盖航空存货候选规则，尚未完成真实物料样本、系统兼容和业务批准。MDM工作组不得直接把该稿扩大表述为全公司、全对象均已适用的主数据编码规范。

建议初版至少回答六个问题：

1. **适用范围**：本版管理哪些主数据对象，明确不管理哪些订单、批次、记录和动态状态。
2. **对象身份**：什么情况下新建编码，什么情况下沿用原编码，什么情况下只更新属性或关系。
3. **编码结构**：各段表达什么，长度、字符、分隔符、容量和校验方式如何确定。
4. **生命周期**：谁申请、谁核对业务事实、谁分配、谁批准生效，变更、停用、作废和恢复如何留痕。
5. **新旧映射**：历史编码、外部标准号、客户编号、供应商编号和系统内部主键如何分别保留和关联。
6. **验证要求**：使用真实对象试编，检查重复、歧义、换码风险、历史兼容和下游使用结果。

建议将初版交付物定义为：

- 一份通用编码治理规则，说明所有主数据编码共同遵守的边界和生命周期。
- 一份本期试点对象字典，明确本次真正进入试编的对象和分类。
- 一份真实样本试编表，保留成功案例、反例和待确认事项。
- 一份版本与生效说明，明确“评审稿、初版发布、正式生效”分别处于什么状态。

**本页结论：MDM工作组承接的不是替换文件署名，而是统一对象边界、编码规则、责任和验证方法。**

## 第九页：行动项二——每个部门用真实样本帮助规范落地

每个部门建议向MDM工作组提供一个“三类样本包”：一个日常稳定使用的对象、一个历史上容易重复或混淆的对象、一个看起来重要但实际属于订单、批次、表单或业务记录的反例。

| 部门 | 建议提供的对象或使用样本 | 需要防止的混淆 |
|---|---|---|
| 工程技术部 | 客户数模引用、零部件、材料、工装和制造技术文件的真实样本 | 客户数模文件及版本、项目、修订号、物料清单（Bill of Materials，BOM）位置和当前用途，应与稳定对象主编码分开管理 |
| 经营发展部 | 客户、供应商、合同对象和销售业务中的对象引用 | 合同、报价单、销售订单和回款记录不应仅因重要就认定为主数据 |
| 项目管理部 | 项目、工作分解、里程碑和计划对象的真实样本 | 计划版本、任务执行记录、进度偏差和风险事件应与稳定对象分开 |
| 物资保障部 | 物料、工装、工具、量具、仓库或库位引用样本 | 库存数量、批次、领用记录、质量状态和存放位置变化不得直接造成换码 |
| 复材车间 | 班组、作业区域、工位和生产资源在现场被引用的样本 | 车间主要负责验证编码是否能被现场识别和使用，不因本轮无主数据生成行为而退出主链核对 |
| 质量管理部 | 检验项目、检验方法、质量分类和测量设备引用样本 | 检验结果、不合格单、放行记录和质量状态属于过程记录或状态，不能直接当作主数据编码对象 |
| 财务部 | 固定资产、无形资产、资金账户及成本核算中使用的对象引用 | 凭证、报销单、付款记录、月度成本和余额属于业务记录，不进入对象主编码 |
| 运维安环部 | 设备设施、作业区域、风险点、作业许可类型和能源计量器具 | 维修工单、隐患记录、事故记录、实时设备状态和监测结果应与稳定对象分开 |
| 行政人事部 | 组织、岗位、员工、资格证和技能项 | 考勤、请假、培训签到、绩效结果等业务记录不能代替组织和人员主数据；员工样本依赖另行发布的权威员工信息表，该依赖不将行动项并入主数据清单问题 |

MDM工作组汇总样本后，应逐项形成“纳入编码、作为关系管理、作为业务记录管理、保持待定”四类处理结论。业务部门确认本部门事实，MDM工作组组织结构核验，有权主体批准适用范围和生效版本。

**本页结论：编码规范是否可用，不看规则写了多少，而看九个部门的真实对象、反例和历史编码能否得到一致处理。**

## 审阅时重点确认

1. 第三页是否准确表达“员工信息表是独立部门行动项，不是主数据清单问题”。
2. 第三页的关闭条件是否足以支持PMO后续确认关闭，同时不替行政人事部确认业务事实。
3. “物资保障部达到流程绑定标准”是否继续保留为本次会议的正式评价用语。
4. 复材车间“本轮暂不评价”的边界是否需要进一步说明。
5. 第六页、第七页列出的流程是否作为本次会议指定的主链候选，还是由各部门会后自行选择。
6. 主数据编码规范初版是否采用“通用治理规则＋航空存货试点字典”的范围，避免把现有存货评审稿扩大为全对象正式规范。
7. “每部门一个三类样本包”是否作为下周统一交付要求。
8. 当前工程技术部流程输入基线仍包含“产品设计和开发管理”等口径，与本轮确认的“客户提供数模后启动”不一致；是否另立任务修订该流程基线。
9. 会议日期确认后，再确定最终文件名和PPT页脚日期。
