| 项 | 内容 |

## 二、供应商能力判断

### 2.1 MBOM（PDM）

| 评估项 | 结论 |
|---|---|
| 整体判断 | 部分满足，存在明确风险点 |
| 已验证能力 | 系统与客户保持一致，流程已在客户现场验证 |
| 风险点 | **BOM 头**：EBOM→MBOM 结构映射、BOM 头字段对齐两个问题均存在，具体方式待实施阶段细化 |
| 风险来源 | EBOM 项目结构与 MBOM 工序结构无法直接对应；BOM 头字段（项目号、配置、构型状态、REV）在下游系统中的字段名不一致 |

### 2.2 ECO（ECN）

| 评估项 | 结论 |
|---|---|
| 整体判断 | 满足，目前未发现风险 |
| 已验证能力 | 流程闭环、版本生效机制已在客户现场验证 |
| 待确认项 | OA 审批对接细节，留实施阶段验证 |

### 2.3 工程项目管理

| 评估项 | 结论 |
|---|---|
| 整体判断 | 满足，目前未发现风险 |
| 范围说明 | 仅限工程变更驱动的项目任务，不涉及生产调度 |
| 待确认项 | 与复材车间生产调度的联动边界，留后续规划阶段确认 |

### 2.4 接口开放能力

| 项 | 内容 |
|---|---|
| 接口方式 | REST API、WebService、文件交换（XML/Excel）、数据库视图直连，多种方式组合，供应商按场景推荐 |
| 事件触发 | 支持工程发布、ECO 发布等事件触发 |
| 接口开发 | 由供应商方主导实施 |

## 三、一期边界确认

### 3.1 上线范围

- MBOM（PDM）：设计EBOM接收、结构映射、版本管理
- ECO（ECN）：变更发起、审批、发布、版本生效闭环
- 工程项目管理：工程变更驱动的任务分解与进度跟踪

### 3.2 暂不涉及（影响长期规划，不影响一期）

| 模块 | 说明 |
|---|---|
| CAPP | 不在一期，EBOM→MBOM 转换暂由人工或临时方案承接 |
| MBD | 长期需求，一期不覆盖 |
| 质量文件受控 | 长期需求，一期不覆盖 |
| 适航追溯 | 长期需求，一期不覆盖 |

> 注：暂不涉及不代表否决，是一期交付边界的主动收缩。

## 六、主要风险与待跟进项

| BOM 头 EBOM→MBOM 结构映射不透明 | 中 | 实施阶段与供应商细化映射规则；一期内由人工或临时方案承接 |
