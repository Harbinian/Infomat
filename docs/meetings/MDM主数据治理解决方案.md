# MDM主数据治理解决方案

> 编制日期：2026-05-06  
> 适用范围：5月9日集成方案预审会、组织架构专题、主数据专题、接口设计前置准备  
> 定位：本项目主数据治理解决方案，不作为外部项目迁移说明。

---

## 一、方案目标

本项目的主数据治理目标不是先建设一个“大而全”的 MDM 平台，而是先解决系统集成前最容易造成返工和扯皮的基础问题：

1. 组织、人员、岗位、角色、资质、授权由谁统一维护。
2. 各部门业务能力、业务流程和应用系统之间的映射关系如何收集。
3. 每条业务流程涉及哪些数据对象、字段、单据、编码和状态。
4. 同名不同义、同义不同名、缩写混用等术语问题如何统一。
5. 每个主数据字段的黄金源、维护部门、审批部门和消费系统如何确定。

主数据底座应服务于集成方案，而不是脱离流程单独建设。

---

## 二、总体建设路径

建议采用“组织先行、流程牵引、术语统一、字段落账、主数据沉淀”的路线：

```text
组织与身份主数据先行
  ↓
各部门提交业务能力-业务流程-应用系统映射
  ↓
项目组汇总流程涉及的数据对象、字段、单据、编码、状态
  ↓
开展术语治理，处理同名不同义、同义不同名和跨部门歧义
  ↓
形成字段台账，明确黄金源、维护部门、审批部门、消费系统
  ↓
沉淀主数据底座，并作为后续 MDM 平台和接口设计依据
```

## 三、分层方案

### 3.1 第一层：组织与身份MDM

5月9日前优先确认第一层，因为它是所有审批、权限、派工、质量放行和适航授权的入口。

| 主数据对象 | 建议权威源 | 说明 |
|---|---|---|
| 部门 | OA/MDM | 部门编码、部门名称、上级部门、负责人、状态 |
| 人员 | OA/MDM | 工号、姓名、部门、岗位、在职状态、联系方式 |
| 岗位 | OA/MDM | 岗位编码、岗位名称、所属部门、岗位职责 |
| 角色 | OA/MDM + 各系统映射 | 审批角色、系统角色、业务角色要区分 |
| 资质 | OA或质量系统主导，MDM沉淀 | 特种工艺、NDT、检验员、适航授权等 |
| 授权 | OA流程 + 质量确认 | 谁能审批、谁能检验、谁能放行、谁能派工 |
| SSO/认证 | OA/MDM | 统一身份入口，各业务系统消费身份结果 |

### 3.2 第二层：业务主数据MDM

第二层不建议在 5月9日直接定死，应由各部门流程映射和字段台账逐步沉淀。

| 主数据对象 | 初步建议权威源 | 会前状态 |
|---|---|---|
| 设计件物料 | **PLM（翎瑞鸿翔）** | ✅ Q5已解决：一期设计件黄金源为PLM |
| 原材料/采购件 | ERP-MM | 待编码和字段确认 |
| EBOM | PLM/PDM | 待翎瑞鸿翔字段样例确认 |
| MBOM | 一期由人工或临时方案 | ⚠️ Q6条件性决策：CAPP后续规划 |
| 供应商 | ERP-MM，供应链管理系统消费 | 待SCIM定位确认 |
| 批次 | WMS/MES/ERP分工 | 待预浸料有效期方案确认 |
| 工装/设备 | MES或设备管理模块 | 待复材车间与运维安环确认 |
| 质量规范 | 质量管理部 + PLM受控归档 | 待质量文件受控方案确认 |
| 术语词典 | 信息化项目组统筹，各部门确认 | 会前建立V0.1 |

## 四、组织主数据字段建议

组织主数据不能只用中文名称维护，必须有稳定编码和历史有效期。

| 字段 | 说明 |
|---|---|
| department_id | 全局唯一ID，不随名称变化 |
| department_code | 稳定部门编码，例如 `ENG`、`QA`、`PMO`、`MAT`、`SHOP` |
| department_name | 中文显示名称 |
| parent_department_id | 上级部门，用于表达总经理、经营副总、生产副总、部门层级 |
| department_type | 技术、质量、生产、供应链、财务、行政等 |
| manager_user_id | 部门负责人 |
| data_owner_user_id | 部门数据责任人 |
| process_owner_user_id | 部门业务流程确认人 |
| effective_from | 生效日期 |
| effective_to | 失效日期 |
| source_system | OA、MDM、人工导入等 |
| status | 待确认、启用、停用 |

## 五、字段台账方案

各部门提交流程映射后，信息化项目组应汇总形成字段台账。字段台账是接口设计和主数据底座之间的桥，不做字段台账就直接做接口，后续很容易返工。

| 字段 | 说明 |
|---|---|
| 数据对象 | 例如物料、EBOM、MBOM、供应商、批次、人员、工装 |
| 中文字段名 | 业务部门使用的中文名 |
| 英文字段名 | 后续接口建议字段名 |
| 字段类型 | 文本、编码、日期、数值、枚举、附件、JSON等 |
| 黄金源系统 | PLM、ERP、MES、OA、WMS、SCIM、PDM、CAPP等 |
| 维护部门 | 谁负责维护字段内容 |
| 审批部门 | 谁批准字段生效 |
| 消费系统 | 哪些系统只读引用 |
| 同步方式 | 实时、批量、人工导入、事件触发 |
| 说明 | 口径、限制、示例、待确认事项 |

字段台账示例：

| 数据对象 | 中文字段名 | 英文字段名 | 字段类型 | 黄金源系统 | 维护部门 | 消费系统 |
|---|---|---|---|---|---|---|
| 组织 | 部门编码 | department_code | 文本 | OA/MDM | 行政人事部 | ERP/MES/PLM/WMS |
| 物料 | 物料编码 | material_code | 文本 | PLM或ERP-MM | 工程技术部/物资保障部 | ERP/MES/WMS/PDM |
| BOM | 版次 | revision | 枚举 | PLM/PDM | 工程技术部 | ERP/MES/CAPP |
| 批次 | 预浸料批次号 | prepreg_lot_no | 文本 | WMS | 物资保障部 | MES/质量系统 |
| 资质 | 特种工艺资质状态 | qualification_status | 枚举 | OA或质量系统 | 质量管理部 | MES/OA |

## 六、术语治理方案

主数据治理必须先统一术语。建议建立术语词典和术语冲突台账，状态分为：待确认、评审中、已解决、已驳回。

### 6.1 优先治理术语

| 术语 | 冲突风险 | 建议处理 |
|---|---|---|
| 冻结 | 需求冻结、BOM冻结、技术状态冻结、资料冻结含义不同 | 分场景定义，不混用 |
| 件号 | 主机厂件号、设计件号、内部物料编码混用 | 件号与内部物料编码分离，通过映射表关联 |
| 版次 | REV、版本、构型、生效批次混用 | REV独立字段，不进入编码 |
| EBOM | 是否包含铺层、MBD、虚拟件、材料规范 | 通过PLM字段样例确认 |
| MBOM | CAPP、ERP、MES都可能声称维护 | 先确认主导系统，再细化字段 |
| 退回 | 被拒绝还是补正 | 统一使用“退回补正”，明确可继续流程 |
| 资料 | 文件、字段样例、接口文档、数据清单混用 | 资料包按清单、版本、来源、责任人管理 |
| 批次 | 供应商批次、WMS批次、MES消耗批次混用 | 建立批次字段映射 |
| 黄金源 | 系统权威、部门权威、字段权威混用 | 按字段定义黄金源 |

### 6.2 术语冲突台账

| 术语 | 部门A理解 | 部门B理解 | 严重程度 | 状态 | 解决人 | 解决结论 |
|---|---|---|---|---|---|---|

严重程度建议分两级：

| 级别 | 说明 |
|---|---|
| warn | 理解差异，不阻塞会议，但需记录并会后统一 |
| error | 影响决策或接口设计，应阻塞表决，先补资料 |

## 七、权限与资质控制原则

对以下高风险动作，建议采用“未明确授权则不默认放行”的原则：

| 高风险动作 | 必须确认的主数据 |
|---|---|
| MES派工 | 人员、岗位、班组、特种工艺资质、资质有效期 |
| 热压罐固化操作 | 操作者资质、设备校准状态、工艺规范版本 |
| NDT检测 | 检测员资质、NDT规范、设备状态 |
| 质量放行 | 检验员授权、质量职责、质量记录完整性 |
| ECO发布 | 审批角色、工程/质量/采购/车间会签状态 |
| 物料编码生效 | 编码规则、审批状态、黄金源系统、重复校验 |
| 适航审批 | 适航授权人员、构型状态、偏离/超差记录 |

## 八、接口设计前置要求

每张接口卡应增加两栏：主数据依赖、术语风险。

| 接口 | 主数据依赖 | 术语风险 |
|---|---|---|
| PLM→PDM | 物料、EBOM、版次、件号、构型 | EBOM、MBD、REV、虚拟件 |
| PDM→CAPP | EBOM、MBD、工艺规范 | 受控发布、工艺规范 |
| CAPP→MES | MBOM、工序、工装、定额 | MBOM、工序、工装 |
| ERP-PP→MES | 生产订单、MBOM、工艺路线 | 工艺路线、订单状态 |
| MES→ERP | 完工、工时、消耗、批次 | 完工、报工、实耗 |
| WMS↔MES | 批次、库存、有效期、出库时间 | 批次、出炉时间、有效期 |
| OA↔PDM/PLM | ECO、审批角色、版本状态 | 冻结、生效、退回 |

## 十、会议建议结论

建议 5月9日预审会形成以下原则性结论：

> 本项目主数据治理采用“组织与身份先行、流程牵引、术语统一、字段落账、主数据沉淀”的路线。OA/MDM 优先作为组织、人员、岗位、角色、资质和认证的权威源；各业务主数据以部门流程映射和字段台账为输入，逐步明确黄金源、维护部门、审批部门和消费系统。对于角色、资质、字段口径或术语含义尚未明确的高风险流程，不作为最终决议，列入会后补资料和预审整改项。
