# 军工智能制造网文档总结：EBOM / PBOM / MBOM 与主数据规范建设建议

> 来源：本会话基于用户上传的《军工智能制造网.pdf》进行总结整理。  
> 说明：原文档为扫描件，部分小字和手写批注不清晰；本文已根据上下文和 PLM / MES / ERP / BOM 建设通用逻辑，对不清晰内容做了合理补全。  
> 重点：EBOM、PBOM、MBOM 建设，以及支撑三类 BOM 贯通的主数据规范。

---

# 一、文档总体总结

这份《军工智能制造网高级研修班》文档，本质上是一套围绕**数字主线 / 数字线程**的复杂产品全生命周期数据管理培训材料。

其核心思想是：

> 以 BOM 为组织核心，把设计、工艺、制造、交付、服务、运维等阶段的数据状态、版本、配置、有效性、批次、实物信息串起来，解决复杂军工产品“结构多、状态多、版本多、协同链条长、上下游系统割裂”的问题。

文档反复强调：

> **BOM 不是简单的物料清单，而是复杂产品数字主线的骨架。**

从设计到制造再到交付运维，产品数据不是一张静态清单，而是会随着设计成熟、工艺分解、制造执行、批次计划、实物交付、服务维护不断变化。

不同阶段需要不同 BOM 视图：

| BOM 类型 | 主要阶段 | 主要用途 |
|---|---|---|
| EBOM | 设计 / 研发阶段 | 表达产品设计结构、设计件、标准件、通用件、借用件、版本和设计状态 |
| PBOM | 工艺准备阶段 | 在 EBOM 基础上按工艺路线、工序、装配关系重组，形成工艺组织结构 |
| MBOM | 生产制造阶段 | 面向 ERP / MES / 计划执行，表达投产、批次、工单、生产数量、制造资源和现场执行关系 |
| 实作 BOM / 实物 BOM | 交付前后 | 记录实际装配、替换、代料、偏离、返修、批次、实物状态 |
| SBOM / DBOM / OBOM | 服务、交付、运维 | 支撑服务保障、交付验收、运行维护、预测维修和数字孪生 |

文档的整体逻辑是：

```text
先建准 EBOM
    ↓
再在 EBOM 基础上派生 PBOM
    ↓
再由 PBOM 和计划 / 批次 / 生产资源生成 MBOM
    ↓
最终形成实物 BOM 与服务 / 运维 BOM
```

# 二、EBOM 建设重点

EBOM 是文档中最基础的一层。它解决的是：

> 设计上产品是什么、由哪些件组成、每个件处于什么版本和状态。

## 2.1 EBOM 的定位

EBOM，即设计 BOM，是由产品设计部门根据客户订单或设计要求建立的产品设计结构。它通常来源于 CAD、PDM / PLM 中的产品结构、图纸、模型、技术文件和设计更改记录。

文档中强调，EBOM 不能只理解为“零件树”，而应包含：

- 产品层级结构；
- 设计件；
- 标准件；
- 通用件；
- 借用件；
- 零部件版本；
- 成熟度状态，如设计中、审批中、冻结、发布；
- 配置规则；
- 替代 / 借用关系；
- 有效性规则；
- 变更记录；
- 与图纸、三维模型、技术文件的关联。

也就是说，EBOM 是后续 PBOM、MBOM、实物 BOM、服务 BOM 的源头。

## 2.2 EBOM 建设的关键难点

### 1. 版本与状态不能混在一起

一个零件可能有 A 版、B 版、C 版，这是版本。

同一个版本又可能处于：

- 设计中；
- 审批中；
- 已发布；
- 冻结；
- 作废。

这是状态。

文档建议通过：

```text
版本 + 状态标识
```

共同控制，避免单靠版本号表达所有含义。

### 2. 产品结构节点变更要有升级规则

比如：

- 增加件；
- 删除件；
- 替换件；
- 改属性；
- 改关联对象；
- 改借用关系。

这些变更是否必须升版，需要按规则判断。

文档中多次提出：

> 什么时候升版、升哪个对象、是否带动下游同步，是 EBOM 建设的核心问题。

### 3. 借用件、通用件、标准件要区别管理

标准件通常来自标准件库。

通用件可在多个产品中复用。

借用件则来自已有产品结构。

三者都可以出现在 EBOM 中，但管理逻辑不同。借用件特别容易带来版本同步和上下游影响问题。

### 4. EBOM 不应随意下发到下游

文档多处强调：

> 产品结构未受控时，不应直接驱动 PBOM / MBOM，否则会导致工艺、计划、采购、生产反复变动。

EBOM 应通过以下机制控制下发：

- 状态；
- 基线；
- 有效性；
- 配置；
- 审批；
- 变更流程。

## 2.3 EBOM 推荐建设方式

建议按以下路线建设 EBOM：

1. 建立统一的产品结构模型；
2. 明确产品、部件、零件、标准件、通用件、借用件等对象类型；
3. 建立版本、修订、迭代机制；
4. 建立状态机：草稿、设计中、审批中、发布、冻结、作废；
5. 建立配置有效性：按时间、批次、架次、订单、型号等生效；
6. 建立变更影响分析：影响 EBOM、PBOM、MBOM、实物 BOM；
7. 建立 EBOM 基线，用于冻结某一阶段设计状态；
8. 建立 EBOM 到 PBOM 的受控转换机制。

一句话总结：

> **EBOM 建设的核心不是画出一棵产品树，而是建立一个可版本、可状态、可配置、可追溯、可下发的设计数据源。**

# 三、PBOM 建设重点

PBOM 位于 EBOM 和 MBOM 之间，解决的是：

> 设计结构如何变成可制造、可装配、可工艺执行的结构。

## 3.1 PBOM 的定位

PBOM 可以理解为工艺 BOM 或工艺过程 BOM。

它以 EBOM 为基础，但并不是简单复制 EBOM，而是按照制造、装配、工艺路线、工序、工位、工装、设备、辅料、半成品、虚拟件等重新组织产品结构。

文档中对 PBOM 的核心表达是：

- EBOM 表达“产品设计上怎么组成”；
- PBOM 表达“产品工艺上怎么制造 / 装配”；
- PBOM 是 MBOM 和 MES 执行的前置基础。

## 3.2 PBOM 与 EBOM 的主要差异

PBOM 相对 EBOM 会增加大量工艺对象，例如：

- 工艺路线；
- 工序；
- 工步；
- 工位；
- 装配件；
- 工艺件；
- 辅料；
- 工装；
- 工艺装备；
- 虚拟件；
- 过程件；
- 半成品；
- 中间交付物；
- 检验点；
- 质量控制点。

PBOM 不只是“多加几个工序”，而是要把产品结构和工艺结构关联起来。

例如：

- 一个 EBOM 中的零件，在 PBOM 中可能被放到不同装配阶段；
- 一个 EBOM 部件，可能被拆解为多个工艺装配单元；
- 一些辅料、工装、工艺件不会出现在 EBOM 中，但必须出现在 PBOM / MBOM 中。

## 3.3 PBOM 建设中的典型问题

### 1. EBOM 变更是否自动影响 PBOM？

不能简单自动同步。

EBOM 变化后，需要判断变化类型：

- 如果是设计结构、关键属性、版本、状态、有效性变化，可能影响 PBOM；
- 如果是备注或不影响制造的属性变化，则可能不需要同步。

### 2. PBOM 是否能自行补充 EBOM 缺失物料？

PBOM 可以补充工艺相关对象，例如：

- 辅料；
- 工装；
- 工艺件；
- 过程件；
- 半成品。

但不应随意补充设计物料。

设计物料缺失应回到 EBOM 源头修正，否则会破坏设计制造一致性。

### 3. PBOM 的状态是否受 EBOM 状态影响？

是的。

EBOM 未发布、未冻结或发生关键变更时，PBOM 不应无约束下发。

PBOM 自身也需要状态控制，例如：

- 编制中；
- 审批中；
- 已发布；
- 已冻结；
- 变更中；
- 作废。

### 4. 零件 PBOM 与装配 PBOM 的区别

零件 PBOM 更关注：

- 单件加工；
- 材料；
- 工序；
- 加工路线。

装配 PBOM 更关注：

- 装配层级；
- 装配顺序；
- 工位；
- 装入件；
- 借用件；
- 总装关系。

### 5. PBOM 与 BOP 的关系

BOP 是工艺过程、工艺路线、工序活动的组织方式。

PBOM 是产品结构在工艺维度上的组织。

二者需要关联：

```text
PBOM 管：装什么、在哪个工艺阶段装
BOP 管：怎么装、按什么路线 / 工序装
```

## 3.4 PBOM 推荐建设方式

建议按以下步骤推进：

1. 从受控 EBOM 派生 PBOM；
2. 区分设计件、工艺件、辅料、工装、虚拟件、过程件；
3. 建立 EBOM 节点与 PBOM 节点的映射关系；
4. 建立工艺路线、工序、工步、工位模型；
5. 建立工艺状态机：编制、审核、发布、冻结、变更；
6. 建立 EBOM 变更对 PBOM 的影响分析；
7. 建立 PBOM 与 BOP 的关联；
8. 建立 PBOM 到 MBOM / MES 的下发规则。

一句话总结：

> **PBOM 是把设计结构转化为可制造结构的关键层，不能简单由 EBOM 复制生成，必须引入工艺路线、装配逻辑、工序资源和制造状态控制。**

# 四、MBOM 建设重点

MBOM 面向 ERP、MES、生产计划和制造执行。它解决的是：

> 生产现场实际按什么结构、什么批次、什么计划、什么工单来制造。

## 4.1 MBOM 的定位

MBOM，即制造 BOM，是在 PBOM 的基础上增加生产制造信息形成的制造执行结构。

文档中指出，MBOM 会承接 PBOM 的产品结构和工艺信息，同时增加：

- 投产信息；
- 生产计划；
- 生产批次；
- 工单；
- 生产数量；
- 工序执行；
- 工装设备；
- 质量反馈；
- 现场状态；
- MES 执行结果；
- ERP 计划需求。

MBOM 是 ERP 和 MES 之间的关键桥梁。

ERP 更关注：

- 计划；
- 物料；
- 成本；
- 采购；
- 库存。

MES 更关注：

- 现场执行；
- 工序；
- 报工；
- 质量；
- 批次；
- 追踪。

## 4.2 MBOM 与 PBOM 的区别

PBOM 偏工艺准备，MBOM 偏制造执行。

| 对比项 | PBOM | MBOM |
|---|---|---|
| 关注重点 | 工艺设计、工艺路线、装配关系 | 生产计划、批次、工单、执行 |
| 主要系统 | PLM / CAPP | ERP / MES |
| 数据对象 | 工艺件、工序、工装、辅料 | 批次、计划、工单、投产数量、现场反馈 |
| 状态控制 | 工艺发布、冻结、变更 | 计划下达、执行中、完工、返工、报废 |
| 作用 | 为制造准备数据 | 驱动生产执行和现场反馈 |

文档中一个重要观点是：

> 很多企业 ERP / MES 的实施忽视了产品多技术状态管理，导致计划和现场执行脱节。

也就是说，MBOM 如果没有继承 EBOM / PBOM 的版本、状态、有效性和配置逻辑，就很容易出现：

```text
图纸是一个状态
工艺是一个状态
现场干的是另一个状态
```

## 4.3 批次 BOM 是 MBOM 的关键补充

生产制造型企业往往不是只按一个固定产品 BOM 生产，而是按订单、批次、架次、型号、客户配置进行差异化制造。

批次 BOM 的作用是：

- 对某一批次产品配置进行冻结；
- 管理批次内适用的产品结构；
- 控制批次与设计状态、工艺状态、制造状态的一致性；
- 支撑 ERP 计划、MES 执行、质量追溯；
- 解决“同型号不同批次配置不同”的问题。

可以这样理解：

> 产品 BOM 是通用结构，批次 BOM 是某一生产批次 / 订单 / 架次下的结构实例。

## 4.4 MBOM 建设中的典型问题

### 1. 一个产品节点能否创建多次投产批次？

可以。

但必须通过以下字段区分：

- 批次；
- 订单；
- 架次；
- 计划号；
- 工单号。

不能简单覆盖原结构。

### 2. 计划批量和计件批量有什么不同？

计划批量偏生产计划和物料需求。

计件批量偏产品实例或制造对象数量。

军工复杂产品往往需要同时支持：

- 批次管理；
- 单件追踪；
- 实物编号；
- 序列号管理。

### 3. 物料出库、备料、对料、实物追踪是否需要 BOM？

需要。

MES 中的执行信息、ERP 中的物料信息、实物装配信息必须通过 MBOM / 实物 BOM 串联，否则无法追溯。

### 4. MES 合批、分批如何处理？

这类场景在现场很常见。

建议原则：

- 计划可以合批；
- 实物、质量、工序履历必须可拆分追踪；
- 分批后必须保留原批次关系和继承关系；
- 合批后必须能追溯来源批次。

### 5. EBOM / PBOM 变化是否影响 MBOM？

会影响，但不能简单自动覆盖。

需要按以下维度判断：

- 状态；
- 版本；
- 有效性；
- 批次；
- 是否已投产；
- 是否已下发工单；
- 是否已有在制品；
- 是否已交付。

如果 MBOM 已下达到生产现场，设计 / 工艺变更必须走变更流程，而不是直接替换。

## 4.5 MBOM 推荐建设方式

建议按以下步骤推进：

1. 以发布后的 PBOM 为基础生成 MBOM；
2. 引入 ERP 计划、订单、批次、架次、工单信息；
3. 建立 MBOM 与 MES 工序执行数据的关联；
4. 建立批次 BOM 和实物 BOM；
5. 建立计划变更、工艺变更、设计变更对 MBOM 的影响分析；
6. 建立备料、出库、对料、装配、检验、报工、完工的数据闭环；
7. 建立 MBOM 与质量追溯、实物交付、售后服务的衔接。

一句话总结：

> **MBOM 是制造执行的核心数据结构，必须同时服务 ERP 的计划管理和 MES 的现场执行，并通过批次 / 实物信息保证可追溯。**

# 五、EBOM、PBOM、MBOM 的贯通关系

文档最有价值的部分，是把三类 BOM 放在一条数字主线上理解。

可以概括为：

```text
设计需求 / CAD / PDM
        ↓
EBOM：设计结构、版本、状态、配置、技术文件
        ↓
PBOM：工艺结构、工艺路线、工序、工装、辅料、装配逻辑
        ↓
MBOM：生产计划、批次、工单、投产、MES 执行、ERP 物料
        ↓
实作 BOM / 实物 BOM：实际装配、替换、偏离、质量、交付状态
        ↓
SBOM / DBOM / OBOM：服务、交付、运行、维护、预测维修
```

关键不是把 EBOM、PBOM、MBOM 做成三张表，而是要建立它们之间的关系：

- EBOM 节点与 PBOM 节点的映射；
- PBOM 节点与工序 / BOP 的映射；
- PBOM / MBOM 与工装、设备、辅料、工位的映射；
- MBOM 与 ERP 计划、MES 工单的映射；
- MBOM 与实物装配记录的映射；
- 设计变更、工艺变更、制造变更的影响链路；
- 版本、状态、有效性、配置、批次的一致性控制。

# 六、对企业落地的启示

## 6.1 不要先从 MES 表单做起，要先把产品数据主线理清

如果 EBOM、PBOM、MBOM 关系不清，MES 只能做成报工系统，难以支撑：

- 工艺状态；
- 物料状态；
- 批次追踪；
- 质量追溯；
- 实物交付；
- 设计制造闭环。

## 6.2 BOM 建设必须和状态管理一起做

没有状态控制的 BOM，只是静态结构。

有状态、版本、有效性、基线和变更控制的 BOM，才是可用于生产的数据主线。

## 6.3 PBOM 是很多企业最容易缺失的一层

企业常见问题是：

- PLM 有 EBOM；
- ERP 有物料 BOM；
- MES 有工单；
- 中间缺少 PBOM / BOP。

结果就是设计、工艺、制造之间靠人工 Excel 转换。

## 6.4 MBOM 不能只服务 ERP，要同时服务 MES

ERP 的 BOM 多偏计划和成本。

MES 的 BOM 必须能支撑：

- 工序；
- 装配；
- 报工；
- 质量；
- 实物追踪；
- 批次关系。

两者不能互相替代。

## 6.5 复杂产品必须支持批次、架次、实物级追踪

军工、航空、复材、装备制造等场景中，同型号不同批次、不同架次、不同技术状态很常见。

必须用以下机制管理：

- 批次 BOM；
- 实物 BOM；
- 配置有效性；
- 技术状态；
- 变更影响分析。

## 6.6 数字主线的最终目标是闭环

不是只把 EBOM 传给 PBOM、PBOM 传给 MBOM。

而是要把以下信息回流到设计和工艺体系：

- 制造现场反馈；
- 质量问题；
- 实物状态；
- 变更执行结果；
- 服务维护反馈；
- 交付使用情况。

# 七、主数据规范建设建议

主数据规范不要只理解成“编码规则”。

它至少要解决四类问题：

1. **对象统一**：同一个零件、材料、工装、工序、设备，在 PLM、ERP、MES 中不能各叫各的；
2. **结构统一**：EBOM、PBOM、MBOM 之间能建立映射关系；
3. **状态统一**：设计状态、工艺状态、制造状态、实物状态不能混乱；
4. **变更可控**：设计变更、工艺变更、制造变更能判断影响范围。

建议把目标写成一句话：

> 建立以产品、零部件、物料、工艺、资源、状态、配置为核心的主数据体系，支撑 EBOM、PBOM、MBOM、批次 BOM、实物 BOM 的贯通管理。

---

# 八、主数据分层

建议不要一上来把所有数据都纳入主数据管理，而是分成三层推进。

## 8.1 第一层：必须先统一的核心主数据

这部分直接决定 EBOM、PBOM、MBOM 能不能跑通。

| 主数据对象 | 作用 |
|---|---|
| 产品主数据 | 定义产品、型号、项目、批次、架次等 |
| 零部件主数据 | 支撑 EBOM 结构 |
| 物料主数据 | 支撑 ERP、采购、库存、MES 领料 |
| BOM 结构主数据 | 支撑 EBOM / PBOM / MBOM 结构关系 |
| 版本与状态主数据 | 支撑设计、工艺、制造状态控制 |
| 配置有效性主数据 | 支撑不同批次、订单、架次差异 |
| 变更主数据 | 支撑 ECR / ECN / 工艺更改 / 制造偏离 |

这一层必须优先建设。

## 8.2 第二层：支撑工艺与制造的扩展主数据

| 主数据对象 | 作用 |
|---|---|
| 工艺路线 | 支撑 PBOM / BOP |
| 工序 / 工步 | 支撑工艺分解和 MES 执行 |
| 工位 | 支撑现场作业组织 |
| 工装 | 支撑装配、加工、检测 |
| 设备 | 支撑生产资源调度 |
| 检验项目 | 支撑质量控制 |
| 辅料 / 耗材 | 支撑 PBOM、MBOM、领料和成本 |

这一层建议在 PBOM 建设阶段同步推进。

## 8.3 第三层：支撑交付、服务、运维的数据

| 主数据对象 | 作用 |
|---|---|
| 实物编号 | 支撑单件追踪 |
| 批次号 | 支撑批次 BOM |
| 序列号 | 支撑实物 BOM |
| 服务件 | 支撑 SBOM |
| 维修项 | 支撑 OBOM / 运维 BOM |
| 交付包 | 支撑 DBOM |
| 技术文件 | 支撑交付、维修、审计 |

这一层可以在 MBOM、实物 BOM 稳定后建设。

# 九、核心对象规范

## 9.1 产品主数据

产品主数据是最高层对象，建议至少包含：

| 字段 | 建议说明 |
|---|---|
| 产品编码 | 全局唯一 |
| 产品名称 | 标准名称 |
| 产品型号 | 支撑型号族管理 |
| 产品类型 | 整机、部件、组件、试验件等 |
| 项目号 | 对应项目或合同 |
| 客户 / 使用方 | 可选 |
| 研制阶段 | 方案、初样、试制、定型、量产等 |
| 技术状态 | 当前适用技术状态 |
| 生命周期状态 | 新建、设计中、冻结、发布、停用、作废 |

注意：

> 产品编码、型号、项目号不要混用。

产品编码用于系统唯一识别，型号用于业务分类，项目号用于项目 / 合同管理。

## 9.2 零部件主数据

零部件主数据是 EBOM 的核心。

建议至少包含：

| 字段 | 建议说明 |
|---|---|
| 零部件编码 | 全局唯一 |
| 零部件名称 | 标准名称 |
| 图号 | 与设计图纸关联 |
| 版本 | A、B、C 或 01、02 |
| 修订号 | 小版本或修订 |
| 零部件类型 | 自制件、外购件、标准件、通用件、借用件 |
| 所属产品 | 所属产品或型号 |
| 设计状态 | 设计中、审核中、已发布、冻结、作废 |
| 单位 | 件、套、米、千克等 |
| 关键件标识 | 关键件、重要件、一般件 |
| 是否可借用 | 是 / 否 |
| 是否可替代 | 是 / 否 |

建议重点控制三件事：

1. **图号不等于物料编码**。图号是设计文件标识，物料编码是业务对象标识。
2. **版本不等于状态**。A 版可能是设计中，也可能是已发布。
3. **借用件必须有来源关系**。不能只复制一个零件出来，否则后续变更不可追溯。

## 9.3 物料主数据

物料主数据主要服务 ERP、库存、采购、MES 领料。

建议与零部件主数据有关联，但不要完全等同。

| 字段 | 建议说明 |
|---|---|
| 物料编码 | ERP / MES 可识别的唯一编码 |
| 物料名称 | 标准名称 |
| 规格型号 | 材料、规格、牌号等 |
| 物料分类 | 原材料、外购件、标准件、辅料、半成品、成品 |
| 单位 | 主计量单位 |
| 辅助单位 | 可选 |
| 采购属性 | 自制、外购、委外 |
| 库存属性 | 是否库存管理 |
| 批次管理 | 是否启用 |
| 序列号管理 | 是否启用 |
| 质检属性 | 免检、抽检、全检 |
| 默认仓库 | 可选 |
| 替代料关系 | 可选 |

这里要特别注意：

> 设计零件、采购物料、库存物料、制造对象不一定是一一对应关系。

例如：

- 一个设计件可能对应多个采购物料；
- 一个物料可能被多个产品借用；
- 一个辅料不一定出现在 EBOM，但需要出现在 PBOM / MBOM；
- 一个工艺件可能不是最终产品结构的一部分，但会参与制造过程。

EBOM、PBOM、MBOM 建设的关键，是 BOM 本身也要规范化。

## 10.1 BOM 头信息

每一张 BOM 都应有头信息：

| 字段 | 说明 |

BOM 行项目至少包含：

| 字段 | 说明 |

| 是否虚拟件 | 是 / 否 |
| 是否替代件 | 是 / 否 |
| 是否借用件 | 是 / 否 |
| 损耗率 | 工艺 / 制造阶段需要 |
| 生效条件 | 时间、批次、订单、架次 |
| 状态 | 草稿、有效、冻结、失效 |

# 十一、版本、状态、有效性三套机制必须分开

这是主数据规范里最容易混乱的地方。

## 11.1 版本

版本回答的是：

> 这个对象修改到了第几版？

例如：

```text
零件001 A版
零件001 B版
零件001 C版
```

## 11.2 状态

状态回答的是：

> 这个版本现在处于什么业务阶段？

例如：

```text
设计中
审核中
已发布
冻结
作废
```

## 11.3 有效性

有效性回答的是：

> 这个版本在什么条件下适用？

例如：

```text
2026年5月后生效
第3批次后生效
某型号适用
某订单适用
某架次适用
```

所以正确表达应该是：

```text
零件001，B版，已发布，适用于P02批次以后
```

而不是简单写成：

```text
零件001-B-发布-P02
```

否则后期很难维护。

---

# 十二、EBOM / PBOM / MBOM 的主数据边界

## 12.1 EBOM 中应该管什么

EBOM 主要管：

- 产品结构；
- 设计零件；
- 标准件；
- 通用件；
- 借用件；
- 图纸；
- 三维模型；
- 技术文件；
- 设计版本；
- 设计状态；
- 设计变更。

EBOM 不建议直接管理：

- 工序；
- 工位；
- 工装；
- 辅料；
- 加工余量；
- 生产批次；
- 工单；
- 库存状态。

这些应该进入 PBOM 或 MBOM。

## 12.2 PBOM 中应该管什么

PBOM 主要管：

- 工艺结构；
- 工艺路线；
- 工序；
- 工步；
- 工位；
- 工装；
- 设备；
- 辅料；
- 过程件；
- 半成品；
- 装配顺序；
- 工艺状态；
- 工艺更改。

PBOM 是 EBOM 到 MBOM 的转换层，不能简单理解为“工艺部门版 EBOM”。

## 12.3 MBOM 中应该管什么

MBOM 主要管：

- 生产计划；
- 生产批次；
- 工单；
- 投产数量；
- 领料关系；
- 备料关系；
- 生产状态；
- MES 执行；
- 质量反馈；
- 完工入库；
- 实物追踪。

MBOM 是生产执行结构，不应随意被 EBOM / PBOM 变化直接覆盖。

# 十三、建议制定的编码规则

编码不要过度复杂，但必须稳定。

建议采用：

```text
分类码 + 流水码 + 版本独立管理
```

## 13.1 产品编码

示例：

```text
PRD-型号族-流水号
PRD-CXFC-0001
```

## 13.2 零部件编码

示例：

```text
PART-分类-流水号
PART-JG-000001
PART-DQ-000002
PART-BZ-000003
```

其中：

- JG：结构件；
- DQ：电气件；
- BZ：标准件；
- CL：材料；
- GY：工艺件。

## 13.3 物料编码

示例：

```text
MAT-分类-流水号
MAT-AL-000001
MAT-FL-000002
MAT-BZ-000003
```

## 13.4 BOM 编码

示例：

```text
EBOM-产品编码-版本
PBOM-产品编码-版本
MBOM-产品编码-批次-版本
```

例如：

```text
EBOM-PRD-CXFC-0001-A
PBOM-PRD-CXFC-0001-A
MBOM-PRD-CXFC-0001-P01-A
```

但注意：

> 编码中不要塞太多业务含义。

型号、批次、状态、版本、有效性最好作为字段管理，不要全部写进编码。

# 十四、主数据治理机制

主数据规范不是写完表格就结束，必须配套治理流程。

## 14.1 数据责任人

建议明确：

| 数据类型 | 责任部门 |
|---|---|
| 产品主数据 | 技术 / 项目管理部门 |
| 零部件主数据 | 设计部门 |
| 物料主数据 | 工艺 / 采购 / 仓储 / ERP 管理部门 |
| EBOM | 设计部门 |
| PBOM | 工艺部门 |
| MBOM | 生产计划 / MES 管理部门 |
| 工装设备 | 工艺 / 设备部门 |
| 质量检验项 | 质量部门 |

## 14.2 数据创建流程

建议所有核心主数据必须走：

```text
申请 → 校验 → 编码 → 审核 → 发布 → 使用
```

不能让每个系统、每个部门自由新增。

## 14.3 数据变更流程

建议建立统一变更流程：

```text
变更申请 → 影响分析 → 审批 → 升版 / 改状态 → 下发 → 执行反馈
```

影响分析必须判断：

- 是否影响 EBOM；
- 是否影响 PBOM；
- 是否影响 MBOM；
- 是否影响已投产批次；
- 是否影响库存；
- 是否影响在制品；
- 是否影响已交付产品。

# 十六、建设路线建议

## 16.1 第一阶段：标准冻结

```text
主数据治理看板
```

# 十七、最关键的落地建议

主数据规范建设时，建议坚持以下原则：

1. **先统一对象，再统一流程。**
2. **先管 EBOM 源头，再管 PBOM 转换，再管 MBOM 执行。**
3. **编码只负责唯一识别，不负责承载全部业务含义。**
4. **版本、状态、有效性必须分开建模。**
5. **PBOM 不要简单复制 EBOM，MBOM 不要简单复制 PBOM。**
6. **设计变更不能直接覆盖生产现场数据。**
7. **批次 BOM 和实物 BOM 必须提前规划，否则后期 MES 很难补救。**
8. **主数据要有责任部门、审批流程和质量检查机制。**

最简优先级可以这样定：

```text
产品主数据
    ↓
零部件 / 物料主数据
    ↓
EBOM结构
    ↓
版本、状态、有效性
    ↓
EBOM-PBOM映射
    ↓
PBOM-BOP
    ↓
MBOM-批次-工单
    ↓
实物BOM-质量追溯
```

---

# 十八、最终结论

这篇文档的核心价值可以概括为一句话：

> **以 EBOM 为设计源头，以 PBOM 完成工艺转化，以 MBOM 驱动制造执行，再通过实物 BOM 和服务 BOM 完成全生命周期闭环，最终形成复杂产品的数字主线。**

主数据规范建设的核心，也可以概括为一句话：

> **用统一的产品、零部件、物料、版本、状态、有效性和配置规则，把 EBOM、PBOM、MBOM 从三套孤立数据，变成一条可追溯、可变更、可执行的数字主线。**
