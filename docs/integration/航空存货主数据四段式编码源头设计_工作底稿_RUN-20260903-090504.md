| 关系 | 允许基数 | 业务语义和限制 |
|---|---|---|
| 工程技术对象—产品定义文件 | `1:N` | 一个对象可由图样、模型和技术条件共同定义；每个文件必须说明其在该对象定义中的角色 |

| 工程修订—有效性范围 | `N:M`，经适用关系展开 | 一个修订可适用多个构型范围，一个范围也可引用多项修订；关系必须记录生效条件，不能只保留版本号 |
| 材料规范或外部标准—工程技术对象 | `N:M`，经定义引用关系展开 | 一个对象可引用多份规范，一份规范可约束多个对象；必须保存完整标准标识和适用修订 |
| 制造商件号—制造商产品定义 | 给定制造商和有效期内 `N:1` | 一个制造商定义可能有订货、包装或区域件号；每个件号在同一有效期内不得指向多个未区分的定义 |
| 受控定义来源—企业物料身份 | `N:M`，经有语义的定义关联展开 | 一个身份可受多份文件共同定义；同一来源也可能适用于多个企业身份。关联必须说明主定义、补充定义或等效依据 |
| ERP 存货控制对象—企业物料身份 | 每个 ERP 对象 `0..1:1`；每个身份 `1:0..N` | 一个 ERP 档案不能同时代表多个未区分的企业身份；一个身份可能尚未建档或因控制需要存在多个 ERP 对象，后者不自动证明存在多个身份 |
| BOM 结构版本—BOM 行 | `1:N` | 每行属于一个明确结构版本；结构版本必须带修订、状态和有效性 |
| BOM 行—父项/子项身份 | 每行各 `1:1`；身份对 BOM 行为 `1:N` | 行表达一次父子发生关系；同一身份可在多份结构或多个位置重复出现，不能把每个发生行当成新身份 |
| BOM 行—定义文件或材料要求 | 每行 `0..N` | 文件引用、材料要求、说明项不必都形成存货身份；必须先判断该行表达的对象类型 |
| 企业物料身份—批准来源 | `N:M`，经批准来源关系展开 | 同一身份可有多个经批准来源，一个来源可供应多个身份；来源变化不能直接改变身份 |
| 企业物料身份—供给/所有权情境 | `N:M`，经场景和有效期关系展开 | 自制、外购、委外、客供、寄售及所有权是情境关系；不同项目或时点可以不同 |
| 身份—替代、等效、代用、偏离 | 身份间 `N:M`，每条关系有方向和范围 | 不同受控定义之间的可互换、单向替代、批准代用或临时偏离必须分开；关系不能抹去各自身份 |
| 批次或序列实例—企业物料身份 | `N:1` | 每个实例指向一个物料身份；一个身份可产生多个批次或单件实例 |
| 处理单元—所含实例或数量 | `N:M`，经内容行展开 | 一单元可含多个批次，一个批次也可分布于多个单元；内容行必须记录数量、单位和时点 |
| 转换事件—输入行/输出行 | 每个事件分别 `1:N` | 分卷、裁切、合并等通过输入行和输出行记录；每行只指向一个已标识输入或输出对象及其数量和单位 |
| 质量或寿命事件—批次/序列/处理单元 | `N:M`，经事件作用对象行展开 | 一次事件可影响多个实例，一个实例可经历多次事件；必须记录事件类型、时间、结果和适用范围 |
| 制造实例—实际用料行 | `1:N` | 某批或某序列化产品通过实际用料行记录装入或消耗事实；每行指向一个物料及可用的批次/序列依据 |
| 上游 BOM 版本—下游 BOM 版本 | `N:M`，经受控派生关系展开 | 多个上游结构可汇入一个下游结构，一个上游结构也可服务多个变体；每条关系必须保存来源版本和适用范围 |

同一受控定义的重复 ERP 档案，与两个不同受控定义之间存在批准互换关系，是两类不同问题。前者需要核查档案重复和控制目的，后者需要保留两个定义及互换依据；本轮不对具体样本作身份合并或拆分决定。

## 8. 大类、小类规则

本节只规定后续验证问题，不给出大类、小类名称或代码。

### 8.1 大类解锁条件

大类必须先声明唯一主分类轴；同一适用时点只能命中一个大类；在 BOM 层级、供给方式、供应商、项目或仓库变化时原则上稳定；每类都要有必要条件、纳入条件、排除条件、真实正例、相邻反例和边界例；无法归类的对象进入待定事项，不设置永久兜底类。任一真实对象同时命中两个大类且不能以稳定业务规则消除时，分类轴不通过。

### 8.2 小类解锁条件

小类必须在所属大类的同一语义基础上细分；每个对象只能沿一条路径判定；每个小类必须形成身份特征签名；BOM 角色不得直接成为小类；制造阶段只有在具有独立受控定义、重复计划边界和稳定身份转换边界时才能继续研究。

每个待验证小类至少需要 3 个真实正例、2 个相邻类别反例和 2 个边界或冲突例；样本总体还要覆盖全部已知多重命中类型、身份特征组合和主要物料族。样本不足时覆盖全部已取得对象并保持阻断，不能降低门槛。独立反证另需未参与规则设计者完成盲样判断。

## 9. 扩展位适用性和退化风险

### 9.1 当前判断

扩展解释段不能是任意属性压缩区，也不能为了保留四段外观而编造含义。当前没有真实 EBOM、身份样本和逐小类证据，无法证明任何扩展差异同时满足稳定身份作用、生命周期稳定、同类单一维度、值域互斥、可重复判断、与小类不重复且不属于项目、来源、供给、BOM 角色、修订、批次、寿命、状态、包装或当前用途。

本任务当前只保留语义占位原则：四段分别承担大类、小类、顺序和扩展解释语义，精确物理参数待定。该原则不证明四个语义均已成立，其中扩展解释语义仍需重新决策和验证。

因此，本轮明确结论为：**四段式业务假设与证据冲突；扩展段存在退化风险；G5=`FAIL`。** 这不是取消扩展段的决定，也不是把扩展段改成中性占位的授权。

### 9.2 后续必须完成的比较

对每个未来经 G4 验证的小类，必须比较三种承载位置：作为小类区分、作为完整身份属性、作为扩展解释段。只有当差异不能由大类/小类充分表达、属于稳定身份签名或经有权主体批准的持久识别维度，并且扩展位置相对其他两种方式有可证实的必要性时，才可以进入待定设计。

中性值只允许表示已证明“不适用”。未知、未调查、尚未填写和缺证据都必须记为“待定”并阻断取号。若绝大多数对象只能使用中性值，或非中性值不能稳定区分身份，扩展段仍不能通过。
