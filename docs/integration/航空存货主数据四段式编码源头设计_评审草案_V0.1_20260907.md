## 1. 编制目的与使用边界

### 1.1 需要解决的问题

本项研究拟明确：企业需要稳定识别哪些物料对象，依据哪些受控定义区分对象，以及分类和编码应表达哪些已经证实的身份差异。编码研究应从工程定义和真实物料样本出发，再核对用友 U8 及上下游的承载约束。

原有研究发现，按定义来源、供给方式、当前用途和物料清单角色混合分类，会使一个对象命中多个类别；将修订、批次、包装或状态写入身份编码，还可能把对象身份与业务发生时的情境混淆。本草案据此组织评审，详细纠错依据保留在[源头设计工作底稿](./航空存货主数据四段式编码源头设计_工作底稿_RUN-20260903-090504.md)第 2、4、6—9 节。

### 1.2 本次评审的结果边界

评审人员可以对本文的对象分离、判定顺序、验证条件、证据缺口和关闭条件提出意见。缺少真实样本或有权主体确认的内容，继续保留“待定”。评审人员提出意见或同意继续研究，不自动构成业务规则批准。

#### 4.1.2 企业身份、分类与编码

本组依据工作底稿第 4、6—9 节及本文第 6 节。对术语的解释不表示分类轴、分类树或四个段义已经通过验证。

| 术语 | 本草案中的含义及用途 | 使用边界与易混淆点 |
|---|---|---|
| 企业物料身份 | 经有权主体确认、可稳定重复引用的企业技术身份，用于判断不同记录是否指向同一个物料对象 | 名称、旧编码、分类、用途、供应商或库存记录相同，均不能单独证明身份相同 |
| ERP 存货控制对象 | ERP 为计划、成本、库存或质量控制建立的档案对象；本文通过 U8 档案核对其与企业物料身份的关系 | 与企业物料身份是否一一对应需要验证；多个 ERP 档案不自动等于多个技术身份 |

| 对象本质 | 描述对象自身是什么的稳定性质；现有研究仅保留其能否成为唯一主分类轴的问题 | 不能用定义来源、当前用途、供给方式或 BOM 角色代替对象本质；当前未据此形成大类 |
| 固有特征与情境特征 | 固有特征描述对象自身长期稳定的技术特点；情境特征描述具体项目、供给、使用、位置、所有权或状态等条件 | 固有特征是否决定身份仍需验证；情境不同不能直接推导身份不同，自制也不能证明自主设计 |
| 主分类轴 | 划分同一层类别时统一采用的判断维度，用于使对象按相同依据归类 | 不将对象本质、定义来源、供给、用途和 BOM 角色混排为同层类别；唯一主分类轴仍待定 |
| 大类与小类 | 大类是按唯一主分类轴划分的类别；小类是在所属大类同一语义基础上的细分 | 同一对象在同一适用时点只能沿一条路径判断；名称、纳入与排除条件、代码均须由真实样本验证后形成 |
| 顺序段 | 原任务四个语义位置之一，研究在经验证的语义范围内如何满足编号容量需求 | 不能把术语解释当成取号规则；唯一范围、顺序范围、容量、段长及分配方式尚未确定 |
| 扩展解释段 | 原任务提出的第四个语义位置，拟表达大类和小类尚未充分表达、且有必要持续放入编码的身份差异 | 当前 G5=`FAIL`；它不是任意属性压缩区，不能用项目、供给、修订、批次、包装或状态填充 |
| 物理码型 | 编码最终采用的字符集、分隔符、各段长度、顺序范围和总长度等具体表达参数 | “段义是什么”与“编码写成什么样”是两个问题；前置阶段门未通过，不给出具体参数、正则或完整示例编码 |
| 中性值与待定 | 中性值只有在证据已证明某维度“不适用”后才可能进入设计研究；待定表示未知、未调查、未填写或缺少证据 | 不适用与不知道不能共用一个值；当前不提供中性占位，不允许以待定内容取号 |
| 退化四段 | 编码外观保留四段，但某段缺少稳定识别作用、重复其他段含义，或主要依靠占位维持形式的风险 | 四段齐全不等于语义成立；需要逐小类真实样本和承载位置比较，不能凭格式检查排除该风险 |

| 所有权关系 | 记录物料在具体业务情境下的所有权归属及适用范围 | 所有权、保管位置和企业物料身份分别理解；更换仓库不能直接证明所有权或技术身份变化 |

| 批准代用 | 依据已批准的代用记录，在明确范围内使用代用材料的关系和使用依据；需要分别保留原材料、代用材料及影响批次或架次 | 代用依据、适用范围和实际使用分别核对，不能将一次代用直接推广为永久互换或身份合并 |
| 偏离关系 | 记录有依据的偏离及其相对于受控定义的差异、适用对象和范围，供后续身份与使用事实核验 | 不能与批准代用、等效或互换自动等同；本文未取得具体偏离案例，不制定允许偏离的技术条件或审批规则 |

#### 4.1.4 实物实例、事件与谱系

本组依据工作底稿第 4、10 节。下列术语说明物料实际存在和变化的记录层次，不形成批次生成、处理单元编号、寿命计算或报废规则。

| 术语 | 本草案中的含义及用途 | 使用边界与易混淆点 |
|---|---|---|
| 批次或序列实例 | 某企业物料身份对应的实际批次或单件实例；一个身份可以被多个批次或单件实例引用 | 物料身份回答“是什么”，实例用于区分实际哪一批或哪一件；批号、序列号不直接进入身份编码 |
| 处理单元 | 卷、包、箱、托盘等用于包装、保管或操作的实物单元，需要说明其中包含哪些实例及其数量 | 一个批次可分布于多个单元，一个单元也可能包含多个批次；处理单元不等于批次或物料身份 |
| 转换事件 | 分卷、分装、裁切、合并、退料等带有时间、数量、单位及输入输出的事实 | 不能只记录两个处理单元互相关联而省略发生过程；事件不自动提供是否换码的答案 |
| 转换事件输入行与输出行 | 分别记录某次转换使用了哪些输入对象、产生了哪些输出对象，以及各自数量和单位 | 输入、输出和损耗需要真实记录支持，不能因数量差额自行推定损耗、余料或报废原因 |
| 状态事件 | 暴露、温度、复验、寿命或质量状态变化等带有类型、时点、结果及作用对象的事实 | 一个当前状态不能代替历次事件；本文未规定暴露时钟、寿命累计、复验或报废判定 |
| 制造实例 | 某批或某序列化产品的实际制造对象，用于关联该对象真正消耗或装入的物料 | 与标准工程结构、标准制造结构分别识别，不能把标准 BOM 当作已制造完成的实物记录 |
| 实际用料关系 | 通过实际用料行记录制造实例真正装入、消耗、代用或偏离的物料，并关联可取得的批次或序列依据 | 计划需要、标准配比和实际消耗分别记录；不能由标准 BOM 静默推定实际用料 |
| 谱系与回溯路径 | 通过物料实例、处理单元、转换事件及实际用料记录，说明材料从哪里来、经过哪些变化、最终用在哪里 | 需要能沿真实记录核对前后关系；编码相似或对象相互连线不能证明谱系完整，当前真实复材案例仍缺失 |

## 5. 真实样本接收与对象判定方法（待评审）

### 5.1 真实 EBOM 的接收条件

工程定义或构型有权主体需要提供一份可与试点范围对应的真实受控 EBOM，并提供文件编号、来源、修订、状态、有效性、基准日期和发放基线依据。结构内容需要保留完整父子层级、行号、子项标识、数量和单位。

空白模板、程序中的 EBOM 术语、U8 全量导出、采购清单或制造清册说明均不能代替该输入。资料不足时，编制人员应记录缺少的内容和原始来源，保持 `P-EBOM-001` 待定。

### 5.2 逐行判定顺序

取得真实受控 EBOM 后，编制人员按以下顺序整理证据；涉及身份、互换或分类的业务判断，由对应有权主体确认。

1. **识别行表达的内容。** 记录该行是对象引用、材料要求、文件引用、参考项、虚拟项、说明项、关系信息，还是暂时无法判断。不能把每一行都当成存货。
2. **定位受控定义。** 记录图样、模型、材料规范、完整标准标识、制造商件号、技术条件及签发主体；分别保留修订和有效性。
3. **分离对象特征与使用情境。** 记录对象本身稳定的技术特征，另外记录项目、当前用途、供给方式、供应商、所有权、位置和状态。
4. **提出身份判断并保留依据。** 编制人员整理是否具有独立、稳定、可重复引用的技术身份及其证据。工程定义、材料技术或其他有权主体确认身份和互换边界；证据不足时仍为待定。
5. **记录关系与重复发生。** 按定义和经确认的身份特征签名归并多条 BOM 发生行的身份引用，并保留每条结构行。此处整理的是研究记录，不执行 ERP 档案合并。
6. **测试分类并核对 U8。** 先用身份样本测试分类轴，再记录与 U8 档案的对应、无对应或多重映射。不能用 U8 名称、旧分类和旧编码反向决定身份。

逐行记录的完整字段组见工作底稿第 5.2 节和证据索引第 5.2 节。非 EBOM 物料仍需可核验的受控定义及身份样本，不能通过虚构 EBOM 行补齐。

### 5.3 身份映射与异常样本

研究记录需要分别保留无对应、一对一、一对多、多对一、多对多和无法判断的真实映射案例。编制人员应将受控定义、修订、有效性、技术特征、供给与用途情境、U8 对应和有权主体判断放在同一案例中核对。

出现名称相同但定义不同、同一技术定义对应多个 ERP 档案，或一个档案无法明确指向一个身份时，编制人员记录冲突和缺少的依据。身份未确认前，不作自动合并、拆分或换码结论。

## 6. 四个段义及规则形成条件（待验证）

### 6.1 段义研究状态

下表只整理原任务中的四个语义位置，不给出物理码型。段义位置的存在不证明其业务必要性已经成立。

| 语义位置 | 拟回答的问题 | 当前状态 |
|---|---|---|
| 大类 | 对象依据哪一个稳定主分类轴归属 | 主分类轴待定，G4=`BLOCKED` |
| 小类 | 同一大类内依据哪些稳定身份特征进一步区分 | 分类路径和身份特征签名待定，G4=`BLOCKED` |
| 顺序 | 经验证的语义范围需要怎样的编号容量 | 顺序范围、容量及物理参数待定，G7=`BLOCKED` |
| 扩展解释 | 是否存在前述分类尚未表达、且值得持续放入编码的身份差异 | 业务语义尚未成立，G5=`FAIL` |

### 6.2 大类与小类的验证条件

分类有权主体需要依据真实身份样本确认唯一主分类轴。编制人员应分别记录对象本质、定义来源、技术身份特征、供给关系、使用关系、BOM 角色及生命周期或制造阶段，不能把不同维度直接并列为同层类别。

大类测试应满足以下条件：同一适用时点，一个对象只能命中一个大类；BOM 层级、供给方式、供应商、项目或仓库变化时，分类原则上保持稳定；每类具备必要条件、纳入条件、排除条件及真实正例、相邻反例和边界例。无法归类的对象进入待定事项，不设永久兜底类。

小类应在所属大类的同一语义基础上细分，每个对象只能沿一条路径判定，每个小类都需要身份特征签名。BOM 角色不直接成为小类。制造阶段只有在具有独立受控定义、重复计划边界和稳定身份转换边界时，才可继续研究其分类意义。

每个待验证小类至少取得 **3 个真实正例、2 个相邻类别反例、2 个边界或冲突例**。总体样本还需覆盖主要物料族、身份特征组合和全部已知多重命中类型。样本不足时使用全部已取得对象，但不降低门槛，也不把样本不足写成通过。

强制冲突测试沿用工作底稿第 7.2 节，包括机电与流体多功能对象、标准定义与制造商定义并存、品牌化材料与当前用途混淆、工艺辅助及包装清洁材料的范围重叠、同一身份在不同 BOM 角色下重复出现、自制转外购，以及暂时无法归类对象。这些是测试主题，不是已取得的真实样本。

原分类树已整体否定，本文不修补旧树、不沿用旧分类代码，也不生成替代树。具体分类名称与代码须在 G4 通过后再形成。

### 6.3 第四段的必要性与退化风险

当前分析判断仍为：**四段式业务假设与证据冲突，扩展段存在退化风险。** 缺少真实 EBOM、逐小类身份样本和承载位置比较，尚不能证明第四段具有稳定、单一、非重复、非装饰性的识别作用。

在 G4 形成经验证小类后，编制人员应对每个小类比较同一差异的三种承载位置：作为小类区分、作为完整身份属性、作为扩展解释段。比较应回答：该差异是否需要持续识别；前两种位置能否充分表达；放入扩展解释段是否具有证据支持的必要性。

扩展维度和值域需同时满足单义性、身份作用、稳定性、互斥性、非重复性和实际区分能力，并能由不同人员按相同依据重复判断。项目、来源、供给、BOM 角色、工程修订、批次、寿命、质量状态、包装和当前用途不能直接充当扩展语义。

中性值只有在后续证据证明“不适用”时才可能进入设计研究。未知、未调查、尚未填写和缺证据均为“待定”，不能分配中性值或取号。若绝大多数对象只能使用中性值，或非中性值不能稳定区分身份，第四段仍不能通过。本草案不提供扩展字典或任何占位值。

`P-EXT-001` 关闭前，用户或企业物料身份有权主体尚需依据证据决定第四段的处理方向；本次选择评审草案不等于批准保留、取消或改写第四段。

### 6.4 物理参数的形成条件

字符集、分隔符、各段长度、顺序范围、总长度、正则和完整示例编码均保持待定。G4、G5、G6 通过后，编制人员才能在 G7 中至少比较两套物理参数假设，并使用相同的规划年限、历史与预测新增量、保留及作废号需求、安全余量和核心消费者约束进行论证。
