## 1. 结论和使用边界

### 1.1 本稿结论

本稿采用以下四段式目标架构：

```text
权威存货业务编码
  = 大类段 ⊕ 小类段 ⊕ 顺序段 ⊕ 扩展解释段
```

其中，`⊕` 表示四段按固定顺序组成完整编码。分隔符、段长和字符集属于物理参数，不由 `⊕` 预先决定。

四段分别承担以下责任：

1. 大类段表达稳定的一级物料族；
2. 小类段表达大类内稳定且互斥的二级物料族；
3. 顺序段提供不可复用的唯一序号，不承载名称、项目、来源或其他隐含含义；
4. 扩展解释段表达同一小类内单一、稳定、能够决定物料身份差异并具有现场辨识价值的特征。

本稿已经形成以下拟定规则：

- 一个经核实的企业物料身份只分配一个权威存货业务编码；一个编码不得代表多个企业物料身份；
- 已发布编码和各段代码值不得回收、复用或改作其他含义；
- 项目、客户、来源、所有权、供应策略、修订、批次、序列、寿命、质量状态、库存状态和 BOM 位置不得进入四段编码；
- 物料身份、工程修订、批准来源、替代关系、批次、包装处理单元和 BOM 行项目分别管理；
- 历史 U8 编码继续保留历史引用，本稿不授权批量改码、合并、拆分、停用或回写；
- U8 是兼容验证对象，不是物料身份、技术分类或互换性规则的源头。

### 1.3 适用范围

本稿拟适用于航空复合材料零部件制造业务中的新建存货主数据，包括：

- 具有受控工程定义的自制零部件、组件和产品；
- 具有受控制造商定义的外购件；
- 标准件；
- 金属原材料、预浸料、干态增强材料、蜂窝及芯材、胶膜、结构胶、密封剂、涂料和其他受控材料；
- 对产品质量或制造过程有直接影响、需要稳定识别的制造消耗物；
- 经业务确认已经形成独立受控定义和互换边界的半成品、定尺坯料或裁切件。

以下对象不因本稿自动成为存货主数据：服务、费用、虚拟说明节点、BOM 位置、批次、炉号、卷号、包装号、序列号、库存状态、质量状态、客户、供应商、人员、部门、设备、工装和固定资产。设备、工装和固定资产应分别进入其主对象治理，不得仅因当前存在 U8 存货档案就继续按物料处理。

## 3. 术语和对象边界

| 术语 | 本稿定义 | 编码关系 |
|---|---|---|
| 企业物料身份 | 企业需要长期、稳定识别，具有受控技术定义和明确互换边界的业务对象 | 每个经核实的企业物料身份只分配一个权威存货业务编码 |
| 权威存货业务编码 | 业务人员和 U8 存货档案用于识别企业物料身份的四段式编码 | 本稿直接设计的对象 |
| 数据库技术主键 | 系统内部自增键、UUID 或其他技术标识 | 不属于本稿，不得替代权威存货业务编码 |
| 工程定义 | 图样、三维模型、材料规范、技术条件及其签发组织共同形成的受控定义 | 是判断身份的源头证据，不直接等同编码 |
| 工程修订 | 对工程定义进行受控变更的版本标识 | 是否换码取决于身份和互换性，不直接进入编码 |
| ERP 存货控制对象 | 为计划、采购、成本、库存或质量控制建立的业务对象 | 当前对象与企业物料身份的映射可能为 1:1、1:N、N:1 或 N:M，需逐项核验 |
| 批次或序列实例 | 某次制造、接收或单件实物的可追溯实例 | 使用批次号、炉号、卷号、包装号或序列号识别，不产生新的物料编码 |
| 批准来源关系 | 物料与制造商、生产地点、供应商、经销商、批准文件和适用范围之间的关系 | 不进入编码；关系变化先判断技术定义和互换性 |
| BOM 行项目 | BOM 中的父子关系、位置、数量、单位、有效性和替代组 | BOM 位置、用量和有效性不属于物料身份 |
| 大类段 | 表达稳定一级物料族的编码段 | 代码值发布后不得复用或改义 |
| 小类段 | 表达大类内稳定、互斥二级物料族的编码段 | 小类含义受大类约束，不得混入其他分类轴 |
| 顺序段 | 提供不可复用序号的编码段 | 只保证唯一性，不表达业务含义 |
| 扩展解释段 | 在同一小类内表达单一、稳定、身份决定型解释特征的编码段 | 不适用时使用受控中性值；不得省略整段 |

| ERP 存货控制对象 | 由计划、成本、库存或质量控制需要界定 | U8 编码、分类、计量和控制属性 | 未经确认的企业身份结论 |

| BOM 行项目 | 由父项、子项、位置和有效性共同界定 | 层级、位置、用量、单位、替代组 | 作为新物料身份的充分条件 |

### 4.2 关系和基数

| 来源对象 | 目标对象 | 允许基数 | 规则 |
|---|---|---|---|
| 工程定义 | 企业物料身份 | 1:1、1:N、N:1 或 N:M | 只有在受控定义和互换边界核实后确定；图号相同不自动合并 |
| 企业物料身份 | 新建权威存货业务编码 | 1:1 | 新建治理目标；不得以项目、来源或批次制造同物多码 |
| 企业物料身份 | 历史 U8 存货档案 | 1:1、1:N、N:1 或 N:M | 当前映射需人工核实；历史行不因本稿自动合并或拆分 |
| 企业物料身份 | 批准来源关系 | 1:N | 多制造商、地点、供应商和批准范围使用关系表达 |
| 企业物料身份 | 批次或序列实例 | 1:N | 每个实例继承企业物料身份，不改变主编码 |
| 企业物料身份 | BOM 行项目 | N:M | 同一物料可以出现在多个父项和位置；位置变化不换码 |
| 包装处理单元 | 子处理单元 | 1:N 或 N:M | 分卷、分装、裁切和合并必须保留来源谱系 |
| 原物料身份 | 替代物料身份 | N:M | 完全互换、单向替代、批准代用、临时偏离和用完为止分别记录 |

### 4.3 独立企业物料身份成立条件

同时满足以下条件时，业务权责主体才可以进一步确认独立企业物料身份：

1. 对象具有可定位、受控且可复核的工程定义、材料规范、标准或产品定义；
2. 对象的稳定属性组能够与其他对象区分；
3. 业务需要对该对象独立执行计划、成本、质量或技术互换控制；
4. 对象可以在其适用范围内重复识别，而不是一次订单、一次批次或一个包装实例；
5. 设计或材料技术权责主体能够说明其互换边界；
6. 现有对象检索没有发现可以直接沿用的同一企业物料身份，或者疑似重复已经取得人工核实结论。

“可以独立采购、库存或发料”只能作为线索，不能单独证明独立企业物料身份成立。

## 6. 四段式编码的规范性语义

### 6.1 大类段

大类段应表达对象长期稳定的一级技术物料族。大类划分必须满足完备、互斥、稳定、可重复判定和可扩容要求。

大类段不得表达采购、自制或委外策略，不得表达客供或自有所有权，不得表达客户、项目、机型、架次、订单、当前用途、供应商、制造地点、部门、仓库、质量状态或库存状态。

### 6.2 小类段

小类段应在所属大类内表达稳定且互斥的二级技术物料族。每个小类必须明确：

- 纳入条件和排除条件；
- 上位大类；
- 身份决定属性组；
- 允许的扩展解释维度；
- 正例、反例和 Evidence-ID；
- 状态和适用范围。

同一小类不得同时使用“材料本质”和“项目/来源/用途”等不同分类轴。

### 6.3 顺序段

顺序段只用于保证完整编码唯一，不表达物料名称、重要程度、项目顺序、时间、部门、来源或状态。已发布、停用、作废、替代或误发的顺序号不得重新分配给其他物料。

顺序号可以出现间断。号码间断不表示缺失数据，也不得为了连续性回收旧号。

### 6.4 扩展解释段

扩展解释段必须保留在完整编码中。非中性扩展值必须同时满足：

1. 特征在对象建立时已经确定；
2. 特征在物料全生命周期内稳定；
3. 特征在相同大类和小类内互斥；
4. 特征具有现场识读或防错价值；
5. 特征变化确实形成不同企业物料身份；
6. 该特征不适合继续拆成新的小类；
7. 同一小类内只表达一个解释维度。

如果某一小类没有符合上述条件的特征，该小类应使用受控中性值。中性值表示“本小类没有附加编码解释”，不表示字段缺失，也不允许省略扩展解释段。

### 6.5 禁止进入四段编码的内容

以下内容均不得进入任何编码段：

- 图样、技术文件或物料修订；
- MOD、构型状态、有效性、审核或批准状态；
- 批号、炉号、卷号、包装号、序列号、制造日期、失效日期；
- 制造商、供应商、经销商、生产地点或批准来源；
- 客户、项目、机型、架次、订单或当前用途；
- 仓库、库位、所有权、质量状态或库存状态；
- 采购、自制、委外等当前供给策略；
- 单价、税率、ABC 分类、提前期、安全库存或 MRP 策略；
- 主辅计量单位、当前包装数量或当前库存数量；
- BOM 位置、层号、铺层顺序、用量或损耗。

## 7. 物理码型 `TEST_DRAFT`

本章用于组织样本测试，不是拟定规则。G4—G7 未通过前，任何系统、人员或部门不得依据本章分配正式编码。

### 7.1 试评格式

```text
CC-SS-NNNNNNNN-EE
```

| 段 | `TEST_DRAFT` 参数 | 说明 | 待验证事项 |
|---|---|---|---|
| 大类段 `CC` | 2 位大写英文字母 | 表达一级物料族 | 活动大类数、人工混淆和扩容需求 |
| 小类段 `SS` | 2 位大写字母或数字 | 表达大类内二级物料族 | 每个大类的小类数量和代码冲突 |
| 顺序段 `NNNNNNNN` | 8 位十进制数字，保留前导零；`00000000` 保留 | 建议采用企业统一流水，仅提供唯一序号 | 规划年限、峰值新增量和全部消费者的前导零行为 |
| 扩展解释段 `EE` | 2 位大写字母或数字；`00` 作为中性值候选 | 同一小类内的单一解释维度 | 逐小类身份作用、现场识读价值和活动值数量 |
| 分隔符 | 半角连字符 `-` | 固定分隔四段 | U8、接口、Excel、标签和扫码兼容性 |

试评格式总长为 17 个字符，包含 3 个分隔符。8 位十进制顺序段在排除 `00000000` 后有 99,999,999 个候选号码。该容量只是理论值；在规划年限、历史新增量、预测峰值、保留号、作废号和安全余量核实前，不得据此批准段长。

试评格式的校验表达式为：

```text
^[A-Z]{2}-[A-Z0-9]{2}-[0-9]{8}-[A-Z0-9]{2}$
```

本稿暂不设置校验位。是否需要校验位，必须根据人工抄录、标签扫描、离线表格和接口差错样本另行论证；校验位不得占用或冒充扩展解释段。

### 7.2 说明性示例

```text
RM-PP-00001234-00
```

该示例只说明 2—2—8—2 的段位和分隔方式。`RM`、`PP`、`00001234`、`00` 均不是已批准代码、真实物料或可分配号码。

### 7.3 物理参数批准条件

只有同时取得以下证据，才可以把本章从 `TEST_DRAFT` 转为“拟定规则”：

1. 试点 EBOM、修订、有效性和物料映射已经拆解；
2. 大类、小类和扩展解释段通过真实样本的完备性、互斥性和重复判定测试；
3. 编码规划年限、历史新增量、预测新增量和安全余量已经确认；
4. U8 `cInvCode` 的排序规则、大小写、尾随空格、前导零、唯一性和导入导出行为已经核实；
5. BOM、采购、库存、生产、成本、质量和历史单据的核心引用约束已经核实；
6. PLM、工艺、MES、接口、报表、Excel、标签和扫码设备已经验证 17 字符及候选字符集；
7. 业务权责主体已批准分类代码值、扩展值和不可复用规则。

## 9. 新编码、沿用编码和关系变化判定

### 9.1 总体规则

物料发生变化时，业务权责主体应先判断变化属于哪个对象层：

1. 企业物料身份变化；
2. 工程修订变化；
3. 分类或描述变化；
4. 批准来源、供给、所有权或项目关系变化；
5. 批次、序列、包装或动态状态变化；
6. BOM 结构、位置、用量或有效性变化。

只有第 1 类变化才可以直接触发新物料编码判断。其余变化应在对应的修订、关系、实例、状态或 BOM 对象中处理。

### 9.2 判定矩阵

| 变化事项 | 新编码 | 新修订 | 关系或实例处理 | 判定条件与限制 |
|---|---|---|---|---|
| 形状、配合、功能或双向互换性发生实质变化 | 是 | 视工程规则 | 建立替代或不兼容关系 | 由设计权责主体依据受控工程文件确认 |
| 工程修订变化但完整互换且身份不变 | 否 | 是 | 保留修订和有效性 | 修订号本身不得自动触发换码 |
| 图号变化 | 待定 | 待定 | 保留外部标识映射 | 先确认签发组织、技术定义和互换性；图号变化不等于身份变化 |
| 材料规范、牌号、状态、形态或关键尺寸发生不可互换变化 | 是 | 视材料规则 | 建立替代关系 | 由材料技术权责主体确认 |
| 制造商件号对应的受控产品定义发生变化 | 待定 | 待定 | 保留旧新制造商标识 | 不能只按字符串变化判断 |
| 供应商或授权经销商变化 | 否 | 否 | 更新批准来源或供应关系 | 交付物技术定义和适用范围保持不变时不换码 |
| 制造商或实际生产地点变化 | 待定 | 否 | 更新批准来源关系 | 先确认技术差异、批准范围和完全互换性 |
| 采购、自制、委外或客供场景变化 | 否 | 否 | 更新供给关系和所有权事实 | 当前供给策略不属于物料身份 |
| 客户、项目、机型、架次、订单或 BOM 位置变化 | 否 | 否 | 更新适用关系或 BOM 行 | 不得制造同物多码 |
| 批次、炉号、卷号、板号、包装号或序列号变化 | 否 | 否 | 新建或更新实例和谱系 | 实例变化不改变企业物料身份 |
| 制造日期、失效日期、累计暴露、剩余寿命或质量状态变化 | 否 | 否 | 更新实例事件或状态 | 动态属性不得进入编码 |
| 采购包装或库存包装数量变化 | 否 | 否 | 更新包装和计量关系 | 只有形成新的受控技术定义和互换边界时才重新判断身份 |
| 完全互换或替换替代 | 否，双方沿用各自既有码 | 否 | 建立双向替代关系 | 具体术语含义仍按适用制度和案例确认 |
| 不可互换且被替代件停止使用 | 双方各有独立编码 | 视工程规则 | 建立单向承接关系并保留旧码 | 不回收被替代编码 |
| 批准代用、临时偏离或用完为止 | 否 | 否 | 记录批准依据、适用批架次和期限 | 临时适用范围不进入编码 |
| 分类名称调整或分类体系重组 | 否 | 否 | 更新当前分类属性并保留编码签发时语义 | 不批量重写历史编码 |
| 名称或规格描述纠错 | 否 | 否 | 受控更正并保留记录 | 纠错不改变技术身份时不换码 |
| 已发布编码的分类段录入错误 | 不得静默修改；处理方式待批准 | 否 | 保留错误码、状态和替代映射 | 不得用同物新码掩盖错误；需专门纠错规则 |
| 停用、恢复、报废或合并 | 否 | 否 | 更新生命周期或合并关系 | 编码不得回收或重新分配 |

### 9.3 互换性确认边界

形状（form）、配合（fit）和功能（function）只是互换性判断维度，不足以单独覆盖航空复合材料。确认主体还应检查材料性能、工艺窗口、资格鉴定、验收要求、适航影响、客户批准和构型适用范围。

Codex、主数据编制人员、U8 字段、名称规格相似、旧新对照表或供应商声明均不得单独认定互换。

## 11. 批准来源、外部标识和替代关系

### 11.1 必须分开的对象

本稿分别使用以下概念：设计或标准签发组织、制造商、实际生产地点、供应商、授权经销商、批准机构、批准文件、制造商件号、客户件号和标准号。名称相近不表示这些主体或标识可以合并。

批准来源关系至少应说明：适用物料、制造商、制造商件号、生产地点、供应商或经销商、批准文件、状态、适用客户或项目、生效失效范围和限制。本稿只规定业务信息边界，不设计字段、数据库表、接口或审批页面。

### 11.2 源规则

- 制造商、供应商或批准地点变化不得自动产生新物料编码；
- 同一标准件或材料存在多个批准制造商、地点或经销商时，应优先保留稳定物料身份，并通过批准来源关系控制资格；
- 如果不同来源产品存在技术差异、批准范围不同、不得混放或不能在全部预定用途上互换，技术权责主体应重新判断是否为不同企业物料身份；
- 客户件号、设计方件号、制造商件号和标准号作为外部标识分别保存，不得直接代替企业权威存货业务编码。

## 12. BOM 和构型边界

本稿不预设企业已经建立标准化的工程物料清单（Engineering Bill of Materials，EBOM）、工艺物料清单（Process Bill of Materials，PBOM）和制造物料清单（Manufacturing Bill of Materials，MBOM）三层架构。`PBOM` 的企业含义和实际对象仍需业务确认。

### 12.1 拟定规则

- EBOM 行应先判断其表达的是设计对象、材料要求、结构关系还是说明内容，不得把所有行自动转换为存货档案；
- BOM 位置号、安装位置、层号、铺层顺序、用量、架次适用性和 occurrence 不属于物料身份；
- 同一物料出现在不同父项、位置或项目时，不得仅因此建立新编码；
- BOM 头版本、物料修订、行项目修订、位置有效性和产品构型有效性应分别管理；
- 上游结构变化只形成变更影响关系，不得自动覆盖已经发布的下游基线；
- 生产订单组件、实际发料和实装谱系应分别说明其属于计划快照、订单基线、实际消耗还是实物构型，不得默认命名为新的“批次 BOM”；
- BOM 变化不得自动触发父项或子项换码。业务权责主体应先判断变化位于物料身份、物料修订、结构关系、用量、位置、替代还是有效性层。

### 12.2 当前阻断

当前未取得真实 EBOM、受控修订、有效性、父子行、材料规范和 U8 映射样本。设计件分支无法完成从 EBOM 到企业物料身份的回测，相关分类和换码规则保持待定。

## 13. U8 兼容和历史编码原则

### 13.1 已取得的兼容结论

依据 E-U8-001，`Inventory.cInvCode` 为 `nvarchar(60)`，当前主表字段长度能够容纳第 7 章 17 字符试评格式。这只是主字段长度层面的静态判断，不表示其他消费者已经兼容。

当前 `cInvCode` 在快照时点保持唯一，说明新编码仍应维持完整编码唯一性。历史编码包含多种字符和长度，因此新规则不得反向要求历史编码全部改成四段格式。

### 13.2 尚未取得的兼容证据

以下事项未核实前，不得宣布 U8 或上下游系统可以直接承载试评格式：

- `cInvCode` 的实际排序规则、大小写敏感性、尾随空格比较和全半角行为；
- 前导零和半角连字符在 U8 客户端、Excel、导入导出、接口和报表中的保持情况；
- U8 BOM、采购、库存、生产、成本、质量和历史单据的真实引用字段与长度；
- PLM、工艺、MES、标签、扫码设备和二次开发的字段、格式和校验限制；
- 新旧编码并存、历史查询、别名检索和外部报表的业务处理原则；
- 编码规划年限、峰值新增量和顺序号容量。

### 13.3 历史编码源规则

| 编号 | 拟定规则 | 状态 |
|---|---|---|
| MCR-201 | 历史 U8 `cInvCode` 保留原值和历史引用，不因新规范批量改写。 | 拟定规则 |

## 14. 编码稳定性和异常处理

### 14.1 稳定性契约

1. 已发布完整编码永久不复用；
2. 大类、小类和扩展解释代码值一经发布，不得改作其他含义；
3. 分类名称变化不自动换码；
4. 分类体系重组不自动批量改写历史编码；
5. 物料技术本质变化时，依据身份和互换性判断是否新建编码；
6. 停用、报废、作废、合并和被替代的号码不回收；
7. 历史别名和映射必须保留来源、状态、依据和适用范围；
8. 编码本体不承担全部业务属性，业务人员不得根据编码推断项目、来源、批次或质量状态。

### 14.2 异常处理原则

| 异常 | 处理原则 | 禁止动作 |
|---|---|---|
| 疑似重复 | 暂停新码判断，比较受控定义、身份属性、生命周期、责任和使用场景 | 仅凭名称、规格、旧分类或模型评分自动合并 |
| 已发布编码录入错误 | 保留原记录和历史引用，建立受控纠错事项；具体作废或替代规则待批准 | 静默改码、删除记录、回收号码 |
| 分类证据不足 | 使用“待定”，补充正例、反例和权责主体确认 | 使用“其他”永久兜底或编造分类 |
| 扩展维度不足 | 使用该小类的受控中性值候选并保留待定 | 省略扩展解释段或塞入动态属性 |
| U8 或下游不兼容 | 记录兼容差距，暂停该物理格式定稿 | 为迎合旧字段扭曲物料身份和分类语义 |
| 互换性存在争议 | 分别保留各方口径、证据和适用范围，交由有权主体决定 | Codex、MDM 编制人或系统字段代替决定 |

## 17. 样本回测和独立反证要求

### 17.1 核心样本

规则评审至少应覆盖：

- 同一技术材料分别用于试验和批产；
- 同一物料分别用于客供、自采或委外场景；
- 同一物料存在不同所有权和项目资格；
- 设计变化影响互换性与不影响互换性的正反例；
- EBOM 行、材料规范和企业库存物料的一对多、多对一情形；
- 预浸料原卷、分切卷、余卷、退料、暴露和复验；
- 蜂窝整板、定尺板、裁切余料和方向继承；
- 胶黏剂套装、可独立管理组分、混合批和适用期；
- 标准件多制造商、多地点和多经销商；
- 外购制造商件号、自制件、半成品和组件；
- 制造消耗物和对产品质量有直接影响的辅料；
- 历史编码继续被 BOM、单据、成本和质量记录引用；
- 完全互换、单向替代、批准代用、临时偏离和用完为止；
- 分类纠错、名称纠错、停用和恢复。

### 17.2 反证条件

独立评审应主动寻找以下问题：一码多物、同物多码、大类或小类重叠、动态属性入码、同一小类扩展段多义、来源或项目导致换码、物料与包装或批次混淆、U8 现状反向扭曲源规则，以及缺少证据却出现精确参数。

两个独立评审者应使用未参与字典设计的盲样，分别给出物料身份、大类、小类、扩展值和是否换码结论。结果不一致时，相关规则不得通过评审。
