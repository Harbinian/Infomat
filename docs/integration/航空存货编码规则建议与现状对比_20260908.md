# 航空存货编码规则建议与现状对比

## 一、背景介绍

工程、采购、仓储和质量业务需要用物料编码准确识别物料，并在图样、采购记录、库存记录和用料记录之间建立对应关系。编码应当稳定，规格应当清楚，使用人员应能找到物料的定义依据及适用要求。

U8 存货档案中还可能包含服务、费用、工具、资产相关档案和生产任务。建议先区分档案代表什么业务对象，再确定适用的编码和属性规则。物料编码识别物料，技术属性描述差异，业务关系记录项目、供货、使用及任务关联。

## 二、现状描述

本节依据 [2026 年 8 月 31 日存货档案导出](../../outputs/ca_inventory_export_20260831/Ca_Inventory_明细导出.xlsx) 的 `Ca_Inventory` 工作表，包含 **6,532 条档案、21 个字段**。编码未发现空值或重复值；这不能证明没有同一种物料建立多个档案。本节反映该导出时点的档案，不能代表实时数据库或其他业务表的维护情况。

**排除范围以现有分类字段 `cInvCCode` 为准：01 类 1,899 条、02 类 222 条不纳入问题案例。** 其余 03、04、05、98、99 五个大类共 **4,411 条**，覆盖 **32 个末级分类**。存货编码本身以 01 或 02 开头，不代表属于被排除的大类。

下文列出 **80 组案例、164 条不同档案**，32 个末级分类均有实际记录。案例用于展示问题及核对方法，并非随机抽样，不能用案例数量推算全库错误率。

## 三、建议的编码规则

**对经确认属于物料的对象，建议采用“大类—小类—顺序号”作为主编码，规格差异单独保存为结构化属性。** 服务、费用、独立工具实物、资产和生产任务先按各自对象定义管理；它们与物料有关联时记录引用关系，不直接统一换成物料号。工具型号或可独立采购的备件是否纳入物料范围，应按实际管理边界确认。

编码结构以 `01-01-000223` 为例。这里的 01 是建议分类中的演示代码，与现有 U8 的 01 类没有对应含义，也不表示纳入本次排除范围的档案。

| 编码部分 | 建议用途 | 示例解释 |
|---|---|---|
| 第一段：大类 | 表示物料发号时所属的大类 | `01` 示例为“紧固连接件” |
| 第二段：小类 | 表示该大类下进一步划分的物料种类 | `01` 示例为“双头螺栓” |
| 第三段：顺序号 | 区分同类下的不同物料身份 | `000223` 为示例顺序号，不表达长度、供应商或使用位置 |

上述示例采用 2 位大类、2 位小类、6 位顺序号，连同分隔符共 12 个字符。类别代码、各段位数和系统兼容性属于建议内容；正式设置应根据取号范围、预计新增量、保留号码及实际系统字段容量确定。示例编号未分配给真实档案。

| 规则 | 建议做法 |
|---|---|
| 先判断对象，再确定编码体系 | 区分物料定义、具体实物、服务、费用和任务。同一工具型号可以对应多件工具实物；一次返工任务应引用处理对象，不能用任务号替代物料身份。 |
| 一个经确认的物料身份对应一个主编码 | 以适用图样、标准、材料、尺寸、技术要求及适用范围判定。名称相同、规格文字相同或编码相似只能提供核对线索，不能单独作为合并依据。 |
| 分类使用一致的依据 | 在同一层级明确纳入和排除条件，使每种物料具有明确的分类路径。项目、研制或批产阶段、自制或外购、客供、费用归属和当前用途分别记录。 |
| 规格按类别分别维护 | 紧固件保存适用标准、螺纹、长度、材料、强度和表面处理等；材料保存材料体系、规格和供货形态；工具关联图样、适用对象和组成。只维护适用属性，缺失信息依据资料补充，不从编码猜值。 |
| 原文与规范属性共同保留 | 保留原始规格全文；另将尺寸、型号等拆为可比较的属性。空值与占位符分别识别；空格、标点和单位别名可用于规范检索，但规范后的文字不能直接触发合并。 |
| 主单位、包装与换算分别说明 | 统一 m、m² 等单位写法；个与支、EA 与台是否等价要按对象核对。盒、卷、套保存内装数量或组成；长度与面积换算需要幅宽，质量与体积换算需要适用条件，不能预设为 1∶1。 |
| 编码不重复拼接规格 | 经确认属于不同物料的尺寸或材料差异，用不同顺序号区分，并在属性中完整表达；不因每个尺寸变化都增加小类，也不将尺寸再次拼接到主编码末尾。 |
| 业务关系单独管理 | 供货、项目、使用位置、工序、任务及组成关系分别关联。批号和实物卷号描述具体批次或实物；是否新增物料号取决于技术定义，而非仅因发生了新的业务活动。 |
| 编码稳定且不重复使用 | 编码发出后不因分类调整自动换号，当前分类单独维护，前两段保留发号时的分类含义。停用号不再分配；技术定义变化时由有权主体判断是否形成新物料。 |
| 保留与 U8 原档案的对应 | 以“来源系统、账套、原存货编码”定位原档案，记录对应的对象类型和主标识。确认同物后仍需核对档案控制目的及单据引用，不能直接合并、覆盖或改写 U8 原码。 |
| 全程按文本保存编码 | 保存、引用、导入导出和接口传递时保留前导零、斜杠、连字符等完整字符。以实际单据、报表和接口读回结果验证兼容性。 |

对需业务确认的关系，建议提供明确选项：**同物关系选“定义相同／定义不同／证据不足”；对象范围选“物料／工具或资产实物／服务或费用／生产任务／证据不足”；单位关系选“单位别名／有固定包装或组成关系／换算依赖条件／不可换算／证据不足”。** 这些是建议的确认选项，不代表已经作出判断。
