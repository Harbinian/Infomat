# 航空存货主数据分类与编码规则——源头设计

> 文档状态：V0.1 评审稿；已形成单一推荐方案，尚未获得业务批准，不能作为现行制度或系统实施指令  
> 编制日期：2026-09-01  
> 主责对象：企业物料身份、物料编码、物料修订、技术分类、外部标识、供给与所有权关系、批次/序列追溯及 BOM 引用  
> 实施边界：本稿不修改用友 U8、数据库、历史编码、存货分类或 BOM，不启动迁移，不创建编码服务  
> 配套文件：[U8 现状证据与兼容差距](../reports/2026-09-01-用友U8存货档案现状证据与兼容差距_V0.1.md)、[规则证据追溯矩阵](../reports/2026-09-01-编码规则证据追溯矩阵_V0.1.md)、[待定事项与决策记录](../plans/2026-09-01-u8-inventory-masterdata-bom-governance/存货编码待定事项与决策记录_V0.1.md)

## 1. 结论

新建企业物料身份采用一个固定对象前缀加全局非语义流水号：

```text
MAT-0000000001
```

固定格式为：

```regex
^MAT-[0-9]{10}$
```

该编码只回答“这是哪个企业物料身份”，不回答它属于哪个项目、用于研发还是批产、由谁采购、由谁所有、来自哪个供应商、存放在哪个仓库、处于哪个版本、属于哪一层 BOM 或对应哪个批次。上述信息分别进入属性、关系、修订、业务单据、批次或序列号对象。

本稿不采用原计划中的 `<域>-<对象>-<8位流水>`，也不沿用 `PM-PRT`、`RND`、`TEST`、`TRIAL`、`PILOT`、`SERIES` 等未经业务批准的固定字典。`MAT` 在本稿中只是物料编码命名空间的固定字面量，不是项目、部门、品类或生命周期代码。

现有 U8 `cInvCode` 不批量改写。历史编码通过别名关系映射到企业物料身份；证据不足的重复候选保留为待核，不按名称或规格自动合并。

## 2. 适用范围和证据边界

### 2.1 纳入范围

- 形成采购、生产、库存、发料、交付、质量追溯或 BOM 引用的原材料、标准件、外购件、自制件、组件和产品；
- 需要独立技术定义、互换性判断或修订控制的物料对象；
- 与物料相关的外部件号、图号、规范、牌号、来源资格、用途、项目、供给责任、库存所有权、替代、批次、序列号和质量文件关系；
- EBOM、PBOM、MBOM 对物料身份及物料修订的受控引用。

### 2.2 不直接纳入物料编码的对象

以下对象不得仅因当前被 U8 存货档案收录，就自动认定为企业物料：

- 服务、费用和不形成可识别实物的结算项目；
- 工装、量具、设备和固定资产本体；
- 供应商、客户、人员、组织、项目、订单、仓库、库位和业务单据；
- 批次、炉批、序列号、合格证、检验记录和质量事件；
- 仅用于 BOM 分组或工艺组织、不采购、不制造、不入库且没有独立技术身份的虚拟节点。

工装、量具、设备和固定资产应分别判断其主对象。维护这些对象所使用的备件、耗材或可库存标准件可以进入物料主数据，但对象本体不因“在 U8 中建过存货档案”就改用 `MAT` 编码。

### 2.3 证据优先级

本稿按以下顺序使用证据：

1. 当前任务要求、仓库边界和数据治理规则；
2. U8 只读数据库结构、统计快照和冻结导出；
3. 公司现有制度、表单和受控业务资料；
4. 适用合同、客户要求和民航规章；
5. Boeing、Airbus 等公开文件中的通用控制原则；
6. 历史方案、行业经验和本稿分析建议。

用户提供的“源头设计提示词”用于界定研究问题和交付结构，不作为业务事实或外部规范证据。历史《主数据编码规范》、既有 U8 分类和以前的候选编码结构也不自动获得现行效力。

## 3. 设计原则

### 3.1 编码稳定，语义外置

物料编码必须在名称、分类、项目、来源、所有权、供应商、仓库、用途、生命周期和修订变化时保持稳定。只有物料身份发生变化时才分配新编码。

### 3.2 一个编码对应一个企业物料身份

“一物一码”不是“一行一码”或“一名称一码”。同名同规格只能形成重复候选；是否为同一身份必须由技术定义、互换性、来源约束和现有引用共同判断。

### 3.3 身份、修订、实物分层

- 物料身份：稳定对象，使用 `MAT-##########`；
- 物料修订：同一身份下的受控技术状态；
- 实物身份：批次、炉批或序列号；
- 库存身份：实物、所有权、项目、库位和质量状态的组合事实。

这四层不能通过一个 U8 存货编码或一个自由文本字段替代。

### 3.4 权威定义与派生数据分开

[Boeing D6-51991 Rev P](https://www.boeingsuppliers.com/content/dam/boeing/boeingsuppliers/boeing-suppliers/becoming/quality/D6-51991_Rev_P.pdf)要求生产和检验使用当前且已授权的数据，制造计划、派生数据和 BOM 能够追溯到权威数据及其修订，并各自接受变更和修订控制。该文件支持“权威定义—受控派生—独立修订—可追溯”的原则，但没有规定我方物料编码格式，也没有直接定义我方 EBOM、PBOM、MBOM 数据模型。

### 3.5 客户和监管要求按适用性落地

[Airbus 2024 年 12 月采购条款](https://www.airbus.com/sites/g/files/jlcbta136/files/2024-12/RPO-NA-USA-BoOTC-US-NewYork-law-Dec2024-published-as-PurchaseOrderTerms-Conditions-GP-Airbus-Commercial-USLaw.pdf)要求相关产品能够追溯到原材料和适用文件，合格证按适用情况记录件号、批号或序列化标识。[CCAR-21-R5](https://www.caac.gov.cn/PHONE/XXGK_17/XXGK/MHGZ/202403/t20240313_223201.html)对特定 PMA 件、CTSO 件和关键件规定了标牌、件号或序列号要求。这些要求决定追溯字段和实物标识，不决定我方企业物料编码必须包含件号、批号或序列号。

## 4. 对象和身份判定

### 4.1 先判断主对象

申请人提出新建需求时，审核人员先判断对象属于哪一类：

| 判断问题 | 是 | 否 |
|---|---|---|
| 是否形成可采购、制造、库存、发料、交付或 BOM 引用的实物？ | 继续判断物料身份 | 转服务、费用、文档或其他对象审核 |
| 是否有独立技术定义或独立互换性边界？ | 可建立物料身份 | 作为属性、关系或 BOM 虚拟节点处理 |
| 是否为工装、量具、设备或固定资产本体？ | 转对应主对象；必要时建立物料别名关系 | 继续物料审核 |
| 是否只是某批、某件、某项目或某次供货的差异？ | 建批次、序列、项目或供给关系，不新建物料身份 | 继续技术身份判断 |

### 4.2 建立新物料编码的条件

出现下列任一情况并经技术责任人员确认时，建立新物料身份：

- 变化导致形状、配合、功能或互换性边界改变；
- 设计件具有新的独立设计定义，且不能作为原物料的受控修订继续使用；
- 材料牌号、材料规范、状态、产品形式、关键尺寸或适用条件变化后不能与原物料互换；
- 客户或法规明确要求将对象作为独立件号管理；
- 原记录把两个不同技术对象错误合并，需要受控拆分；
- 原对象被完全替代且新旧对象不可互换，需要保留替代链。

### 4.3 沿用编码并形成新修订或关系的条件

以下变化原则上不新建物料编码：

- 不改变身份和互换性的技术修订；
- 名称、描述、单位或录入错误更正；
- 技术分类、项目、用途、仓库、库位或生命周期状态变化；
- 合格供应商增加或减少，但不改变控制制造商件号、设计批准、质量等级或互换性；
- 公司自采、客户供应、内部制造或委外等供给责任变化；
- 实际来源、库存所有权、批次、炉批、序列号、制造日期或失效日期变化；
- 物料进入不同 EBOM、PBOM、MBOM 或不同产品构型。

供应来源变化一旦同时改变控制制造商件号、设计批准、质量等级或互换性，应重新执行身份判定。是否影响互换性必须由业务证据确认。本稿不授权系统根据字段变化自动新建或沿用编码。

### 4.4 分对象身份判定要素

| 对象类型 | 身份判定要素 | 通常不作为身份要素 |
|---|---|---|
| 设计件/自制件 | 控制图号或设计定义、形状、配合、功能、互换性 | 项目、用途、制造批次、工单 |
| 原材料 | 材料类别、牌号/等级、状态、适用规范、产品形式、关键尺寸与公差 | 供应商、采购订单、仓库、炉批 |
| 标准件 | 标准号、品种、规格、材料/等级、表面状态、互换性 | 经销商、采购批次、项目 |
| 外购件 | 制造商件号、技术规格、版本适用性、批准来源约束 | 当前供应商报价、采购员、仓库 |
| 组件/产品 | 独立设计定义、构型边界、互换性和交付身份 | 生产订单、制造批次、交付日期 |
| 消耗品 | 产品技术规格、等级、包装/计量边界及不可互换特性 | 生产日期、失效日期、到货批次 |

上述表格是评审起点，不是自动匹配算法。每类对象还需要用公司真实样例形成身份判定卡。

## 5. 推荐编码结构

### 5.1 固定结构

| 组成 | 固定规则 | 说明 |
|---|---|---|
| 对象前缀 | `MAT` | 全部企业物料身份共用；不区分材料、零件、项目或部门 |
| 分隔符 | 一个半角连字符 `-` | 仅用于人工识读，不承载业务语义 |
| 流水号 | 10 位十进制数字 | 企业级单一序列，不按分类、部门、项目或来源分段 |
| 总长度 | 14 个字符 | `MAT` 3 位、连字符 1 位、流水 10 位 |
| 字符集 | 大写英文字母、数字、半角连字符 | 新码只允许固定格式，不反推历史码整改 |
| 校验位 | 不设置 | 通过格式、唯一约束、精确查询和条码/二维码校验 |

示例：

```text
MAT-0000000001
MAT-0000000002
MAT-0000000003
```

示例只表示三个不同物料身份，不能从数值大小判断品类、时间、项目、重要程度或上下级关系。

### 5.2 为什么不编码大类和小类

当前 U8 分类同时混入物料形态、项目、研发阶段、用途、来源和资产属性。若把现有分类写进新编码，后续分类纠正或业务场景变化将引发改码。技术分类应作为独立、可修订、可多层映射的字典关系，不是永久身份的一部分。

### 5.3 为什么使用全局序列

全局序列有以下约束：

- 一次分配后永久占用；
- 不因撤回、停用、作废或替代而回收；
- 不按对象子类、部门、项目、来源或年度重置；
- 流水间断属于正常审计事实；
- 序号只保证唯一，不保证连续，不表示创建先后之外的业务含义。

10 位序列理论上有 100 亿个数字组合。若按本稿建议从 `0000000001` 起并保留 `0000000000`，可分配 9,999,999,999 个号码。该位数是源头设计的保守容量，不代表已有数量预测已经获得批准。实施前仍需确认全部下游字段和标签能容纳 14 个字符。

### 5.4 为什么不增加扩展位

扩展位容易变成项目、修订、供应商、材料状态或用途的临时容器。若某个业务值能够变化、重复、多选或随场景生效，就必须建字段或关系，不能追加到编码末尾。本稿不预留自由扩展段。

### 5.5 为什么不设置校验位

当前证据没有证明编码必须在脱离系统、脱离标签扫描的环境中大量手工转录。校验位会增加规则复杂度，却不能替代唯一性检查和对象审核。因此 V0.1 不设置校验位；实施时采用精确查询、数据库唯一约束和条码/二维码。若真实作业验证显示离线手工转录是主要风险，再单独评估校验位，不能直接改变已发布编码。

### 5.6 备选结构比较

| 方案 | 结论 | 原因 |
|---|---|---|
| 纯 10 位数字 | 不采用 | Excel 等工具可能丢失前导零；跨对象命名空间不易识别 |
| `MAT-10位流水` | 推荐 | 只有稳定对象前缀和非语义流水；结构简单、容量充足 |
| `<域>-<对象>-<8位流水>` | 不采用 | 域、对象字典和边界未经确认；分域序列增加治理和迁移复杂度 |
| `大类-小类-流水` | 不采用 | 分类变化会引发改码；当前 U8 分类维度混杂 |
| 图号/规范号直接编码 | 不采用 | 外部编号字符、长度和修订规则不统一；易把外部标识误作企业身份 |
| 哈希、UUID 直接作为业务编码 | 不采用 | 不适合人工识读和现场沟通；可作为系统内部技术主键 |

## 6. 编码、外部标识和技术修订

### 6.1 必须分开的标识

| 标识 | 用途 | 是否进入 `MAT` 编码 |
|---|---|---|
| 企业物料编码 | 跨业务识别企业物料身份 | 是，编码本体 |
| 系统内部主键 | 数据库关系和接口幂等 | 否 |
| U8 历史存货编码 | 识别既有 U8 记录和历史单据 | 否，作为别名 |
| 客户件号/图号 | 标识客户或权威工程定义 | 否，作为外部标识关系 |
| 制造商件号 | 标识制造商产品定义 | 否，作为外部标识关系 |
| 标准号/材料规范 | 表达适用标准和技术要求 | 否，作为属性或规范关系 |
| 物料修订 | 表达同一身份下的技术状态 | 否，独立修订对象 |
| 批号/炉批/序列号 | 标识实物批次或单件 | 否，独立追溯对象 |

### 6.2 外部标识关系最小字段

每条外部标识关系至少记录：企业物料身份、标识类型、标识值、发布主体、适用项目或产品、修订/版本、有效期、状态、证据文件和批准记录。相同外部编号在不同发布主体下不得自动视为同一对象。

### 6.3 物料修订最小字段

每个物料修订至少记录：物料身份、修订标识、权威技术依据、状态、生效条件、失效条件、变更原因、互换性结论、影响分析、编制/复核/批准信息以及被替代修订。已发布修订不得原地覆盖。

## 7. 属性归位规则

| 业务信息 | 正确归位 | 禁止做法 |
|---|---|---|
| 技术分类 | 多层分类关系及分类版本 | 写入永久编码 |
| 项目/产品/架次 | 适用关系或业务单据 | 写入编码或名称前缀 |
| 研发、试验、试制、批产 | 用途适用关系；代码字典待业务批准 | 固定成编码段或直接沿用历史候选代码 |
| 公司自采、客户供应、内部制造、委外 | 带场景和有效期的供给责任关系 | 用一个主档开关替代全部场景 |
| 实际供应商/来源 | 采购、收货、制造或调入事实 | 写入物料编码 |
| 库存所有权 | 批次/序列或库存身份关系 | 用仓库名、分类名或自由文本代替 |
| 批次、炉批、序列号 | 实物追溯对象 | 与物料编码拼接成新物料 |
| 生命周期 | 独立状态字段和状态历史 | 写入编码 |
| EBOM/PBOM/MBOM 层级 | BOM 对象类型 | 写入物料编码 |
| 名称、规格、单位 | 物料修订或受控属性 | 用名称相同直接判重合并 |

## 8. 分类模型

### 8.1 分类只表达内在技术属性

企业技术分类建议从对象本质出发，第一层候选为：材料、标准件、设计件、外购成品件、组件、产品、消耗品。该列表尚未经过真实样例评审，不能据此批量改现有 U8 分类。

项目、研发阶段、用途、供给方式、所有权、仓库和资产归属不得成为企业技术分类节点。一个物料可以具有多个用途、项目或供给关系，但在一个分类版本中应只有一个明确的主技术分类；需要交叉检索的特征使用标签或属性，不再复制分类树。

### 8.2 分类版本和映射

分类字典至少包含分类版本、分类代码、分类名称、定义、纳入条件、排除条件、父级、状态、生效期和批准记录。现有 U8 分类与企业技术分类建立映射，映射保留来源节点、目标节点、适用范围、例外和证据，不直接改写历史节点。

### 8.3 U8 现有服务、工装和设备的处理

- 服务类记录：作为历史 U8 兼容对象，评估后转服务主数据或费用项目；在结论形成前不删除、不改码；
- 工装、量具、设备和固定资产本体：转对应对象治理；若历史单据依赖 U8 存货编码，保留别名和引用；
- 工装的组成材料、标准件、备件和耗材：满足物料定义时可使用 `MAT` 编码；
- 仅名称包含“工装”“设备”不能自动完成对象迁移。

公司《工装工具管理》和工装数据集资料对工装图号、系列号、版次、客户编号要求另有控制，说明工装本体具有独立于物料主数据的身份和修订规则。物料编码不得覆盖或替代这些受控编号。

## 9. 用途、供给、所有权和追溯

### 9.1 用途适用性

用途是多值、带场景和生效期的关系。用途字典及代码尚待业务批准，本稿不固定 `RND`、`TEST`、`TRIAL`、`PILOT`、`SERIES`。同一物料可同时适用于多个项目或阶段，不因用途增加而改码。

### 9.2 计划供给责任

公司自采、客户供应、内部制造、委外等属于计划关系。关系至少包含物料、组织、项目/订单/产品场景、供给方式、生效期、状态、证据和批准记录。一个物料可在不同场景采用不同供给方式。

### 9.3 实际来源和库存所有权

- 实际来源记录这批或这件实物由哪个主体、哪张订单、哪次制造或哪次调入产生；
- 库存所有权记录实物归哪个主体所有；
- 仓库和库位记录物理位置；
- 质量状态记录待检、合格、隔离、不合格等状态。

四者必须分开。U8 `cInvDefine9` 中的“客供”文本只能作为复核线索，不能自动生成客户供应或客户所有权事实。

### 9.4 批次和序列追溯

批次或序列追溯至少关联：物料及修订、订单/收货或制造来源、实际来源主体、所有权、批号/炉批/序列号、制造和失效日期、质量文件、实际使用的 BOM 基线、实耗/实装以及交付对象。

[Airbus 独立采购订单通用质量要求](https://www.airbus.com/sites/g/files/jlcbta136/files/2023-10/Airbus%20general%20quality%20requirements%20for%20standalone%20Purchase%20Order.pdf)把件号、产品名称、批号或序列号、合格证和签署信息分开记录，也说明这些标识属于追溯和交付证据，而不是一个企业物料码的组成段。

追溯级别必须由技术、质量、物资及合同适用性共同确认。当前 U8 `bSerial=1` 为 0、`bInvKeyPart` 全部为 1 的统计不能替代业务判定。

## 10. 替代、代用和互换性

公司《材料代用管理程序》分别记录原用和代用材料的物料编码、类别、牌号和状态、规范/技术条件、规格、代料原因及批/架次。该结构证明物料身份、技术属性、替代关系和适用范围需要分别保存。

每条受控替代关系至少包含：原物料、替代物料、关系类型、互换性结论、适用项目/BOM/批架次、数量范围、生效和失效条件、客户批准依据、原因、申请/审核/批准人员及执行结果。

源文件使用“完全替代”和“替换替代”两个术语，并给出不同互换性条件。本稿保留原术语，不自行改写其业务含义；正式入模前由责任部门确认术语是否继续使用及其状态转换规则。

## 11. EBOM、PBOM 和 MBOM 引用

### 11.1 共同边界

BOM 头、BOM 修订、BOM 行、物料身份、物料修订、派生映射和发布基线是不同对象。BOM 修订、行号、层级、数量、工艺路线和有效性不得写入物料编码。

### 11.2 推荐关系

```text
已批准的物料身份及修订
  → EBOM 发布基线引用
  → PBOM 工作修订从指定 EBOM 基线受控派生
  → PBOM 发布后形成基线及行级映射
  → MBOM 工作修订从指定 PBOM 基线受控派生
  → 生产订单绑定明确的 MBOM 发布基线
  → 批次/序列形成实耗、实装和 As-built 事实
```

当前仓库只发现内部材料代用程序明确提到按代料状态修改 MBOM 或材料定额；未取得当前 EBOM、PBOM、MBOM 的真实对象、字段、版本、状态和责任链证据。因此，上述模型是源头治理建议，不是当前系统现状陈述。

### 11.3 派生控制

- 上游变化只生成影响项，不静默覆盖已发布下游基线；
- PBOM/MBOM 新增而上游不存在的对象应标记来源和原因；
- 每条派生关系保留来源 BOM、来源修订、来源行、目标 BOM、目标修订、目标行、映射类型和批准记录；
- 生产和检验只能使用当前有效且已批准的基线；
- 已替代和作废基线保留查询，不再用于新业务。

## 12. U8 兼容和历史过渡

### 12.1 当前兼容结论

U8 `Inventory.cInvCode` 当前结构为 `nvarchar(60)`，本稿 14 字符新码在该字段长度内。当前证据未完成 PLM、MES、标签打印、扫码设备和全部接口字段核验，因此“U8 字段可容纳”不等于“端到端兼容已验收”。

### 12.2 旧码冻结和别名映射

每条历史别名至少保存：企业物料身份、源系统、源编码、源记录主键、别名类型、状态、有效期、映射依据、确认人和批准记录。

过渡规则：

1. 不批量改写历史 U8 `cInvCode`；
2. 不删除历史分类、单据或 BOM 引用；
3. 新对象在正式生效日之后使用 `MAT` 编码；
4. 旧对象只有经过身份核验和引用影响分析后才建立映射；
5. 一对多或多对一映射必须进入人工处理，不用默认值掩盖；
6. 历史自由文本和分类仅作为线索，不自动转成权威属性或关系。

### 12.3 重复候选处理

名称重复、名称加规格重复和辅助代码重复都只形成候选。处理时应同时核对技术定义、外部件号、规格、单位、分类、供应来源、库存、单据、BOM、质量文件和历史使用范围，再决定保留、合并、拆分或建立等价关系。所有决定保留前后编码及引用，不物理删除证据。

## 13. 编码申请、审核和发布

### 13.1 候选责任边界

以下分工是评审建议，不代表现行职责已经确认：

| 工作 | 责任候选 | 控制要求 |
|---|---|---|
| 提出需求和业务场景 | 需求部门 | 提供用途、项目、数量、时间和来源证据 |
| 判断技术身份和互换性 | 工程技术责任人员 | 明确新物料、新修订或关系变更 |
| 确认追溯和质量要求 | 质量管理责任人员 | 明确批次、序列、文件和阻断要求 |
| 确认供给和库存事实 | 采购/物资责任人员 | 提供来源、所有权、订单和库存证据 |
| 查重、编码分配和关系完整性审查 | 统一主数据治理责任 | 分配全局流水；不得替业务作技术判断 |
| 系统承接 | U8 及其他系统管理员 | 只实施已批准结果，不自行编造分类或属性 |

### 13.2 发布前最小材料

- 对象类型和技术身份判定；
- 标准名称、必要规格和计量单位；
- 控制图号、制造商件号、标准号或材料规范等依据；
- 互换性结论；
- 查重候选及排除理由；
- 技术分类候选；
- 用途、项目、供给、追溯等关系需求；
- 编制、复核、批准记录。

### 13.3 流水控制

编码分配必须由一个受控入口完成，具体载体待实施设计。分配请求需要稳定的申请标识，重复提交返回同一结果；并发分配不得产生同号；已正式分配的号码不得回收。人工台账、数据库序列或服务实现均必须满足这些业务规则。

## 14. 代表性场景

| 场景 | 处理结果 |
|---|---|
| 同一技术材料分别用于试验和批产 | 一个 `MAT` 编码，多条用途适用关系 |
| 同一技术材料在 A 项目自采、B 项目客供 | 一个 `MAT` 编码，两条供给责任关系；每批记录实际来源和所有权 |
| 同一材料不同炉批和失效日期 | 一个 `MAT` 编码，多个批次对象 |
| 设计变化不影响互换性 | 沿用 `MAT` 编码，形成新物料修订 |
| 设计变化导致不可互换 | 新 `MAT` 编码，建立替代或不兼容关系 |
| 客户指定另一个件号但技术对象相同 | 沿用 `MAT` 编码，新增客户外部标识关系 |
| 工装本体曾在 U8 建存货 | 保留 U8 历史码；转工装主对象评审，不直接分配 `MAT` 新码 |
| 同名同规格两条 U8 记录 | 进入重复候选；未核对引用前不合并 |
| EBOM 中的分组节点无独立实物身份 | 使用 BOM 节点身份，不建立 `MAT` 编码 |

## 15. 生效门槛和停止点

### 15.1 本稿已经形成

- 一套单一推荐编码结构：`MAT-10位全局流水`；
- 物料身份、新修订、外部标识、批次/序列和关系的分层规则；
- 分类、供给、所有权、替代和 BOM 信息的属性归位；
- U8 旧码冻结和别名映射原则；
- 实施前的责任、证据和验证门槛。

### 15.2 尚未完成

- 业务部门对对象边界、身份判定和责任分工的批准；
- 真实 EBOM、PBOM、MBOM 对象和样例验证；
- 下游系统、接口、标签、扫码和报表的 14 字符兼容测试；
- 新码正式起始号、生效日、并发分配和回退方案；
- 现有 6,565 条 U8 记录的逐条身份核验、映射和迁移；
- 业务验收、系统实现和生产启用。

### 15.3 禁止提前执行

在上述事项批准前，不得：

- 批量生成或写入 `MAT` 编码；
- 修改 U8 存货编码、分类、批次/序列开关或自定义字段；
- 按名称、规格、辅助代码或分类自动合并；
- 从“客供”等文本推断实际来源或所有权；
- 把本评审稿写成 Boeing、Airbus、民航局或公司现行制度的原文要求；
- 将静态检查或样例评审表述为系统上线或业务验收。
