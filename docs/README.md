# docs 资料目录说明

> 状态：导航说明  
> 生效日期：2026-06-10  
> 依据：`REPOSITORY_BOUNDARY.md`、`DIRECTORY_OWNERSHIP.md`、`MAINLINE_MAP.md`

**2026-09-11用户明确：所有`docs/`文件都不再是真源，不得以其为当前治理基础。** 本目录保留历史资料、转换/导出副本、实现说明、测试和交接记录；下方旧入口描述中的“真源”“必须与这里一致”等定位均按历史时点解释，不能决定当前业务、职责、任命或审批链。

当前方向是：外部原始材料和业务说明→3001编制→用户下载未审核JSON并手动上传3000→3000治理、核对、审核及正式版本→生成程序文件。3001保持独立无状态，退回后由用户在3001修订并手动回传3000原案例。这里记录用户决定的文字是交接副本，决定的依据仍是用户和业务主体的明确确认。

人员信息回到用户指定的行政人事部发布Excel，花名册Markdown也只是副本。软件继续读取某些`docs/`契约或旧快照只说明兼容现状，不恢复文档真源身份；不得因此自动从旧资料生成当前治理结论或执行数据库同步。

## 1. 当前入口

| 资料类型 | 当前入口 | 说明 |
|---|---|---|
| 部门到域映射 | `docs/organization/组织架构和部门职责.md` | 历史副本；当前部门和域依据指定外部材料及有权确认。 |
| 工作角色与岗位映射 | `docs/organization/工作角色目录与岗位映射.md` | 历史目录副本；当前角色、任命及流程责任须有权确认，候选不得自动成为正式事实。 |
| 流程输入基线 | `docs/norms/{部门}部门-能力-流程-系统映射关系.md` | 旧映射消费链；当前治理使用指定外部材料、业务确认及人工上传3000的单流程JSON。 |
| 跨部门完整性报告 | `docs/norms/流程治理/跨部门完整性检查报告.md` | 历史风险检查输入；不反推当前跨部门关系。 |
| 流程展示快照 | `docs/company-sankey-data.json` | 由 `scripts/parse-sankey-data.mjs` 生成，供 PMO 驾驶舱和后续平台承接使用，不手工维护。 |
| 工作角色只读快照 | `docs/work-role-data.json` | 由 `scripts/build-work-role-data.mjs` 从历史副本生成，不含人员名单，不手工维护。 |
| 文档结构化输出 schema | `docs/contracts/document-structured-output.schema.json` | 证据映射技能及旧parser的v2草稿兼容模型；3000旧文档编制/导入已退役。 |
| 术语表 | `docs/glossary.md` | 术语查询脚本读取这里，新术语仍应回写到本文件。 |
| 上下文管理 | `docs/architecture/context-management.md` | 说明项目资料上下文分层、读取顺序和历史材料使用规则。 |

## 2. 子目录分工

| 路径 | 职责 | 修改规则 |
|---|---|---|
| `docs/norms/` | 制度/表单源文件材料、流程输入基线和部门桑基图资产 | 仅获准维护旧消费链时显式选择parser输入、输出及页面，命令见目录README。 |
| `docs/organization/` | 组织、人员、角色和岗位的历史及转换副本 | 修改前读取本目录 `AGENTS.md`；依据指定材料及确认维护副本；不自动从旧资料同步治理或数据库。 |
| `docs/reports/` | 审计、测试、稳定化和阶段总结报告 | 新增仓库审查或整改报告放这里，不散放根目录。 |
| `docs/architecture/` | 长期架构和上下文说明 | 解释结构、模块关系和执行规则，不替代 ADR。 |
| `docs/adr/` | 长期架构决策记录 | 记录 `Proposed`、`Accepted` 等明确状态的长期决策，不把普通执行计划伪装成已接受决策。 |
| `docs/contracts/` | 当前主线结构规则 | 修改前读取本目录 `AGENTS.md`；用于校验主线关系和结构化输出，不替代流程输入基线。 |
| `docs/integration/` | 集成、主数据和系统协同方案 | 可沉淀方案，不作为流程输入基线。 |
| `docs/plans/` | 计划类资料 | 作为方案或计划沉淀，不替代 PMO 计划真源。 |
| `docs/samples/` | 最小样例 | 只保留能复现格式或契约的精选样例。 |
| `docs/superpowers/` | 历史设计、计划和协作记录 | 仅用于追溯，和当前规则冲突时以根目录边界文件为准。 |
| `docs/archives/` | 历史归档 | 已含组织更新前逐字节副本；后续迁移仍先核对引用、授权和恢复方式。 |
| `docs/外部参考/` | 外部参考资料 | 作为参考材料保留，使用前需确认与当前真源关系。 |
| `docs/U8SoftHelp/` | U8 帮助文件集合 | 体积较大，迁出或 LFS 化前需先写迁移提案。 |
| `docs/training/` | 培训材料 | 作为资料留存，不作为流程或 MDM 真源。 |
| `docs/Demo/` | 演示材料 | 作为演示留存，不作为主线入口。 |
| `docs/screenshots/` | 精选截图资料 | 新截图默认不放这里，除非已确认为长期样例。 |
| `docs/meetings/` | 会议资料 | 保留会议记录或整理材料，不写入当前执行规则。 |
| `docs/HardwareResearch/` | 硬件相关调研资料 | 作为专项资料留存，不参与流程治理主线。 |

## 4. 修改自检

修改 `docs/` 前先确认：

1. 目标是否为历史副本、技术规则或明确授权的兼容消费资产，是否存在指定材料及确认依据。
2. 是否确有维护旧展示链的授权，以及parser显式输入、输出和写入范围。
3. 是否会影响 `pmo/procedure-management/dashboard.html` 或 MDM 流程治理快照。
4. 如果改了代码、脚本、接口、命令或测试口径，是否已同步更新对应文档。
5. 派生文件是否属于 ADR-0004 拟纳管清单并通过固定检查；截图、运行日志或一次性中间文件是否误放入 `docs/`。

无法判断时，先写入 `docs/reports/` 做审计或迁移提案，不直接移动文件。
