本项目不宜写成“采购一批服务器”，而应定义为：

> 建设统一的企业私有云与数字化基础设施底座，覆盖管理系统虚拟化、核心数据库集群、集中备份容灾、Ansys Fluent 热流场仿真、AI 算力、VDI/图形虚拟化等多类资源池。

推荐拆分为：

1. **超融合/虚拟化底座**：承载 PLM、MES、ERP、OA、测试环境、普通业务虚拟机。
2. **数据库集群与高性能存储**：核心业务数据库、Oracle RAC/Data Guard、全闪存储、日志/归档/备份分区。
3. **Ansys Fluent / AI GPU 算力服务器**：支撑复合材料成型工装热分布、湍流、瞬态传热、多工况扫描，以及本地 70B 级大模型推理。
4. **VDI 与图形虚拟化平台**：普通职员云桌面、CATIA/Fibersim、Ansys 前后处理。
5. **统一备份与容灾平台**：数据库一致性备份、虚拟机备份、文件库备份、不可变备份、恢复演练。
6. **网络与机房配套**：10/25/100GbE、交换机、光模块、UPS、PDU、机柜功耗、散热和承重。

# 服务器基础设施总体规划与招标范围

## 一、建设目标

本项目目标不是单纯采购服务器硬件，而是建设统一的企业私有云与数字化基础设施底座，支撑：

- PLM/PDM
- MES
- ERP
- OA
- 普通职员虚拟化桌面
- CATIA/Fibersim 等三维设计与前后处理
- Ansys Fluent 热流场仿真
- 本地 AI 大模型推理
- 统一数据库集群
- 统一备份与容灾

## 二、总体原则

### 1. 资源池分离

不同负载不应混跑在同一资源池中。

| 负载类型 | 建议资源池 |
|---|---|
| PLM/MES/ERP/OA 管理系统 | 超融合/虚拟化资源池 |
| 数据库 | Oracle 数据库集群与高性能全闪存储 |
| 普通职员办公桌面 | VDI/桌面云资源池 |
| CATIA/Fibersim/Ansys 前后处理 | vGPU 图形虚拟化资源池 |
| Ansys Fluent 热流场仿真 | GPU Fluent 计算节点 + CPU 兜底节点 |
| 本地 70B 大模型 | AI GPU 服务器或独立 AI 算力资源池 |
| 备份与容灾 | 独立备份一体机/备份存储/容灾资源池 |

### 2. 不把超融合当万能底座

浪潮三节点 IR5280M7 超融合方案适合承载管理系统虚拟机，但不建议承载：

- Ansys Fluent 生产仿真
- 70B 大模型推理
- CATIA/Fibersim 图形虚拟化
- 大规模 VDI
- 高强度数据库全部负载

### 3. 数据库、备份、容灾集中管理

各业务系统服务商不得各自建设孤立数据库、孤立备份、孤立监控和孤立容灾。核心系统原则上统一纳入 Oracle 数据库集群、统一备份平台、统一监控平台和统一容灾体系。

## 三、建议招标包件

| 包件 | 名称 | 主要内容 |
|---:|---|---|
| 包一 | 超融合/虚拟化底座 | IR5280M7 类超融合服务器、虚拟化软件、分布式存储、网络虚拟化 |
| 包二 | 数据库集群与高性能存储 | Oracle RAC/Data Guard、数据库服务器、全闪存储、日志/归档/备份分区 |
| 包三 | Ansys Fluent / AI GPU 算力服务器 | NF5468A7/G7 类 GPU 服务器、H100/A100/L40S 等 GPU、NVMe、本地模型盘 |
| 包四 | VDI 与图形虚拟化 | 普通职员 VDI、Ansys/CATIA 前后处理、NVIDIA vGPU 授权 |
| 包五 | 备份与容灾 | DP3000G7 或同级备份一体机、不可变备份、数据库一致性备份、恢复演练 |
| 包六 | 网络与机房配套 | 10/25/100GbE 交换机、光模块、UPS、PDU、机柜改造、散热、承重 |

## 四、需要避免的采购风险

### 风险 1：把 AI GPU 服务器当 Ansys Fluent 生产服务器

AI GPU 服务器从硬件上可以运行 GPU 计算，但 Fluent GPU Solver 受 Ansys 版本、CUDA、驱动、物理模型支持范围、License 等限制。必须由 Ansys 技术人员基于代表模型确认。

### 风险 2：把 Ansys Fluent 放进 PLM/MES/OA 超融合池

Fluent 计算会占用大量 CPU/GPU、内存和本地 I/O，容易影响业务系统稳定性，不应与 PLM/MES/OA 共用同一生产超融合池。

### 风险 3：只看裸容量，不看有效容量和性能

分布式存储两副本会明显折损容量。数据库还必须看 IOPS、延迟、日志盘、归档盘、备份窗口和恢复能力。

### 风险 4：忽略 License

Ansys、Oracle、NVIDIA vGPU、虚拟化平台、桌面云等授权都会影响最终能否真正发挥硬件性能。不能只验收服务器型号。

### 风险 5：忽略功耗和机柜

GPU 服务器可能单台功耗就超过普通机柜承载能力。现有 42U、8 位 10A、2500W 机柜不一定能承载 NF5468A7/G7 这类 4U GPU 服务器。

## 五、推荐总体架构

```text
普通业务系统：
PLM / MES / ERP / OA
    ↓
超融合/虚拟化资源池
    ↓
Oracle 数据库集群 + 全闪存储 + 统一备份

研发/仿真/AI：
CATIA/Fibersim/Ansys 前后处理
    ↓
vGPU 图形虚拟化资源池

Ansys Fluent 热流场仿真
    ↓
GPU Fluent 计算节点 + CPU 兜底节点

本地 AI 大模型
    ↓
AI GPU 服务器 / 独立 AI 算力池
```

# 关键术语通俗解释

## 一、总体类

| 术语 | 通俗解释 |
|---|---|
| 私有云 | 企业自己建设、自己管理的内部云平台，不把核心系统和数据放到外部公有云。 |
| 数字化底座 | 支撑 PLM、MES、ERP、OA、AI、VDI 等系统运行的基础设施，包括服务器、存储、网络、数据库、虚拟化、备份等。 |
| 虚拟化 | 把一台物理服务器切成多台虚拟服务器或虚拟桌面使用。 |
| 超融合 | 把计算、存储、网络虚拟化整合到一组服务器里，统一管理。 |
| 高可用 HA | 一台设备故障时，业务可以切换到其他设备继续运行，减少停机。 |
| 资源池 | 把 CPU、内存、存储、GPU 等集中起来统一分配。 |

## 二、服务器与计算

| 术语 | 通俗解释 |
|---|---|
| CPU | 服务器的大脑，负责通用计算。 |
| 核心数 | CPU 里可以同时干活的计算单元数量。核心多，适合多任务并行。 |
| 主频 | CPU 单个核心的速度。部分软件更依赖高主频。 |
| 内存 | 程序运行时使用的高速临时空间。内存不足会导致系统很慢。 |
| DDR5 | 较新的服务器内存规格。 |
| NVMe SSD | 高速固态硬盘，适合数据库、仿真临时文件、AI 模型盘。 |
| RAID | 多块硬盘组合，提高性能或可靠性。 |

## 三、GPU 与图形

| 术语 | 通俗解释 |
|---|---|
| GPU | 图形处理器，也就是显卡芯片，适合图形渲染、AI 和部分科学计算。 |
| 显存 VRAM | GPU 自带的高速内存。跑 AI 和 CFD GPU 求解时，显存是否足够非常关键。 |
| vGPU | 虚拟 GPU，把一张物理显卡切分给多个虚拟桌面或虚拟机使用。 |
| NVIDIA vGPU 授权 | 使用显卡虚拟化能力通常需要购买的软件授权。 |
| 图形虚拟化 | 工程师通过瘦终端远程使用机房里的高性能图形桌面。 |

## 四、Ansys / Fluent

| 术语 | 通俗解释 |
|---|---|
| Ansys | 工程仿真软件体系，包含结构、流体、电磁、显式动力学等多个模块。 |
| Fluent | Ansys 的流体仿真软件，常用于 CFD、热流、气动、传热等分析。 |
| CFD | 计算流体力学，用计算机模拟空气、液体等流动和换热。 |
| 湍流模型 | 用来模拟复杂流动的数学模型，如 k-epsilon、k-omega SST、LES 等。 |
| 热分布 | 分析工装或产品各位置温度是否均匀。 |
| 瞬态传热 | 模拟升温、保温、降温随时间变化的过程。 |
| 共轭传热 CHT | 同时计算流体流动和固体导热。 |
| Fluent GPU Solver | Fluent 的 GPU 求解器，可以用 GPU 加速部分流体/传热计算，但不是所有功能都支持。 |
| Cell 数 | CFD 网格数量，类似模型被切成多少小格子。Cell 数越多，计算越重。 |

## 五、AI 大模型

| 术语 | 通俗解释 |
|---|---|
| AI 大模型 | 参数规模很大的人工智能模型，可用于问答、总结、写作、代码、知识库等。 |
| 70B | 约 700 亿参数的大模型。B 是 billion，表示十亿。 |
| 推理 | 使用训练好的模型回答问题或生成内容。 |
| 训练 | 用大量数据从头或大规模更新模型能力。成本很高。 |
| 量化 | 把模型压缩成低精度，减少显存占用。 |
| INT4/INT8/FP16 | AI 推理常用的低精度计算格式。 |
| KV Cache | 大模型处理长上下文和多用户并发时占用的显存缓存。 |

## 六、VDI 与桌面云

| 术语 | 通俗解释 |
|---|---|
| VDI | 虚拟桌面。员工桌面运行在服务器上，终端只负责显示和输入。 |
| 瘦终端 | 功能较简单的小终端，依赖服务器提供桌面环境。 |
| 云桌面 | 通过服务器集中提供的办公桌面。 |
| 登录风暴 | 很多人早上同时登录云桌面，造成服务器和存储瞬间压力。 |
| 镜像 | 标准桌面模板，包含操作系统和基础软件。 |

## 七、数据库、备份、容灾

| 术语 | 通俗解释 |
|---|---|
| Oracle RAC | Oracle 数据库集群，多台数据库服务器共同支撑一个数据库，提高可用性和性能。 |
| Oracle Data Guard | Oracle 灾备机制，把生产库数据同步到备库，故障时可切换。 |
| RPO | 能接受丢失多少时间的数据。例如 RPO 15 分钟表示最多丢 15 分钟数据。 |
| RTO | 系统故障后多久恢复。例如 RTO 2 小时表示 2 小时内恢复服务。 |
| 快照 | 某个时间点的数据状态记录，方便快速回退。 |
| 备份 | 把数据复制到独立位置，防止误删、勒索、硬件故障。 |
| 不可变备份 | 备份在保留期内不能被篡改或删除，防勒索。 |

## 八、网络与机房

| 术语 | 通俗解释 |
|---|---|
| 10GbE / 25GbE / 100GbE | 10G、25G、100G 网络，数字越大带宽越高。 |
| 光纤网络 | 使用光纤连接服务器和交换机，速度快、稳定性好。 |
| UPS | 不间断电源，停电时为服务器临时供电。 |
| PDU | 机柜电源分配单元。 |
| 42U 机柜 | 常见服务器机柜高度规格。 |
| 机柜功率 | 一个机柜能承载的最大用电能力，不是有空位就能放高功耗服务器。 |

# 浪潮超融合测算解读

## 一、一句话结论

浪潮提供的“中航 PLM 等应用超融合”测算，本质上是一套 **PLM/MES/ERP/OA 等管理系统的三节点超融合底座方案**。

它适合承载普通业务虚拟机和部分核心系统，但不覆盖：

- Ansys Fluent 热流场仿真
- AI 大模型服务器
- CATIA/Fibersim 图形虚拟化
- 大规模普通职员 VDI
- 完整 Oracle RAC/Data Guard 数据库集群
- 详细功耗、机柜、UPS 评估
- 详细价格

## 二、当前测算核心配置

| 项目 | 参数 |
|---|---|
| 服务器型号 | 浪潮 IR5280M7 |
| 数量 | 3 台 |
| 单台 CPU | Intel Xeon 6459C 3.0GHz 32C ×2 |
| 三台裸 CPU | 192C |
| 可用物理核心 | 182C |
| 可分配 vCPU | 364 vCPU |
| 单台内存 | 64GB DDR5 ×8，即 512GB |
| 三台裸内存 | 1536GB |
| 可用内存 | 1459GB |
| 全闪裸容量 | 46.08TB |
| 全闪两副本可用 | 20.7TB |
| 混闪裸容量 | 96TB |
| 混闪两副本可用 | 36TB |
| 软件 | InCloud Sphere V8、dSAN V8、SmartFlow V8、文件存储、iCenter |
| 交换机 | S6820-16T20X8Y-E ×2 |
| 备份 | DP3000G7 备份一体机 ×1 |

## 三、可以承载什么

| 系统/场景 | 是否适合 | 说明 |
|---|---|---|
| OA | 适合 | 轻量业务，适合虚拟化 |
| ERP 应用服务器 | 适合 | 数据库需单独评估 |
| PLM 应用服务器 | 适合 | 文件库和数据库需独立规划 |
| MES 应用服务器 | 适合 | 数据库写入压力需评估 |
| 测试/培训环境 | 适合 | 可放在虚拟化资源池 |
| 中间件、缓存、检索 | 适合 | 需分配独立资源 |
| 数据库 | 可承载但需谨慎 | 核心数据库建议 Oracle 集群和专用全闪资源 |

## 四、不建议承载什么

| 场景 | 原因 |
|---|---|
| Ansys Fluent 生产仿真 | 需要 GPU/大内存/本地 NVMe，不应和业务系统抢资源 |
| 70B 本地大模型 | 需要大显存 GPU |
| CATIA/Fibersim 图形虚拟化 | 需要专业 GPU 和 vGPU 授权 |
| 大规模 VDI | 登录风暴、IOPS、用户体验需专项测算 |
| 高强度数据库全集中混跑 | 容易出现 IOPS、延迟、资源争抢风险 |

## 五、关键风险

### 1. 三节点是起步配置，不一定是最终高可靠配置

三节点两副本一般可容忍一个节点故障，但要追问：

- 单节点故障后，剩余两节点是否还能承载全部生产业务？
- 是否按 N+1 设计？
- 数据重建需要多久？
- 重建期间性能下降多少？
- 是否建议四节点更稳？

### 2. 有效容量要看清

全闪裸容量 46.08TB，两副本可用 20.7TB。实际还要考虑：

- 快照空间
- 告警水位
- 元数据
- 数据增长
- 数据库日志和归档
- 备份是否占用生产池

### 3. 数据库性能不能只看容量

PLM/MES/ERP/OA 数据库应明确：

- IOPS
- 平均延迟
- 峰值延迟
- 日志盘位置
- 归档盘位置
- 备份窗口
- 数据库一致性快照
- Oracle RAC/Data Guard 适配

### 4. 软件授权口径要明确

需要确认：

- InCloud Sphere 授权是按节点还是按 CPU？
- 三台双路服务器是否需要 6 个 CPU 授权？
- dSAN、SmartFlow、文件存储、iCenter 的授权数量和有效期？
- 三年后续保费用？
- 过保后是否还能继续使用和升级？

## 六、应要求浪潮补充的内容

1. 明确本方案仅覆盖 PLM/MES/ERP/OA 超融合底座，不包含 Ansys Fluent、AI、vGPU 和大规模 VDI。
2. 补全硬件明细：CPU、内存、硬盘、RAID/HBA、网卡、电源、功耗。
3. 按 PLM/MES/ERP/OA 输出资源落位表。
4. 明确数据库部署建议和 IOPS/延迟指标。
5. 明确三节点两副本故障边界。
6. 明确软件授权数量和续保费用。
7. 明确备份一体机容量、RPO/RTO、数据库一致性备份。
8. 补充网络拓扑：管理网、业务网、存储网、备份网、迁移网。
9. 补充详细报价。
10. 另行提供 Ansys Fluent、AI、VDI、图形虚拟化专项方案。

# Ansys Fluent 热流场仿真服务器测算与推荐配置

## 一、场景定义

当前仿真方向已明确为：

> 以 Ansys Fluent 为主，用于复合材料成型工装的热分布、温度均匀性、湍流流场、瞬态传热、多工况参数扫描。

典型仿真内容包括：

- 工装内部/外部流场分析
- 工装升温、保温过程中的瞬态热分布
- 湍流模型下的对流换热
- 工装抽壳/薄壁等效建模后的热传导与流场耦合
- 不同流量、温度、边界条件和工装材料参数的多工况扫描

## 二、核心判断

这不是传统结构仿真服务器，而是 **CFD + 热分析服务器**。

因此，服务器测算重点应从 CPU 结构计算转向：

- Fluent GPU Solver 适配
- GPU 显存
- Cell 数
- 瞬态步数
- 湍流模型
- 能量方程
- 共轭传热
- 薄壁/抽壳支持边界
- 本地 NVMe 临时盘
- Ansys License 消耗

## 三、需要先确认的仿真边界

| 问题 | 需要确认 |
|---|---|
| 稳态还是瞬态 | 稳态较轻，瞬态计算量和结果文件大得多 |
| 是否算固体导热 | 只算流场、共轭传热 CHT、还是薄壁等效 |
| 湍流模型 | k-epsilon、k-omega SST、LES/DES |
| 网格规模 | 50 万、300 万、800 万、2000 万 Cells 级别 |
| 目标周转时间 | 2 小时、8 小时、24 小时或夜间批量完成 |
| 是否使用 GPU Solver | 需要确认物理模型支持范围 |
| 是否有 UDF、辐射、Shell Conduction | 可能影响 GPU Solver 适配 |

## 四、代表模型建议

| 模型 | 用途 | 规模建议 | 目标时间 |
|---|---|---:|---|
| 小型局部模型 | 验证抽壳、边界条件、湍流模型 | 50万～200万 Cells | 1～2 小时 |
| 中型工装模型 | 工程主力热分布分析 | 300万～800万 Cells | 4～8 小时 |
| 大型瞬态模型 | 升温曲线、热滞后、温度均匀性 | 800万～2000万 Cells | 12～24 小时 |
| 多工况扫描 | 流量、温度、边界条件、材料参数比较 | 中型模型 ×10～30 工况 | 夜间或 1～2 天 |

## 五、推荐架构

建议采用：

> 1 台 Fluent GPU 主力计算节点 + 1 台 CPU 兜底节点 + 前后处理图形资源

### 1. Fluent GPU 主力计算节点

| 项目 | 推荐配置 |
|---|---|
| 服务器形态 | 4U GPU 服务器，例如浪潮 NF5468A7/G7 同级别 |
| CPU | 双路 Xeon / EPYC，核心数适中，主频不低 |
| 内存 | 1TB DDR5 起 |
| GPU | 4 × 80GB 数据中心 GPU 优先 |
| 最低显存 | 总显存不低于 192GB |
| 推荐显存 | 320GB，即 4 × 80GB |
| 本地 NVMe | 4 × 3.84TB 企业级 NVMe 起 |
| 系统盘 | 2 × 960GB 或 1.92TB SSD，RAID1 |
| 网络 | 25GbE 起步，预留 100GbE |
| 用途 | Fluent GPU Solver、热流场、湍流、瞬态传热、多工况扫描 |

### 2. CPU 兜底计算节点

| 项目 | 推荐配置 |
|---|---|
| 服务器形态 | 2U 双路服务器 |
| CPU | 双路高主频 Xeon / EPYC |
| 物理核心 | 48～64 核左右 |
| 内存 | 1TB DDR5 |
| 本地 NVMe | 4 × 3.84TB 企业级 NVMe |
| 网络 | 25GbE |
| 用途 | GPU Solver 不支持场景、传统 CPU Fluent、网格、结果后处理、模型检查 |

### 3. 前后处理图形资源

| 项目 | 推荐 |
|---|---|
| 并发人数 | 5～10 名仿真工程师起步 |
| 每人显存 | 4GB～8GB 起，大结果后处理建议 8GB～12GB |
| 平台 | vGPU 图形虚拟化 |
| 软件 | Workbench、Fluent Meshing、CFD-Post、SpaceClaim、Discovery |

## 六、GPU 选择建议

| 档位 | 判断 |
|---|---|
| 4 × H100 80GB / H800 80GB | 性能强、预算高，适合长期主力 |
| 4 × A100 80GB / A800 80GB | 成熟稳妥，适合 CFD/HPC |
| 4 × L40S 48GB | 成本较低，适合中型模型，但显存余量不足 |
| 2 × 80GB | 可做验证起步，不建议作为最终生产主力 |
| 8 × 80GB | Benchmark 证明 4 卡不足后再考虑 |

建议招标口径：

> 本项目优先采用 4 张 80GB 级数据中心 GPU。如供应商建议采用 48GB GPU，必须基于我司代表模型证明显存容量、计算时间和多工况并发满足要求。

## 七、Benchmark 测试要求

每个代表模型需分别测试：

- CPU only
- 1 GPU
- 2 GPU
- 4 GPU

记录：

1. 总运行时间
2. 单步迭代时间
3. 峰值内存
4. 峰值显存
5. GPU 利用率
6. CPU 利用率
7. 临时文件峰值
8. 结果文件大小
9. Ansys License 消耗
10. 计算结果一致性
11. 是否存在 GPU Solver 不支持项

## 八、验收目标建议

| 模型 | 验收目标 |
|---|---|
| 中型工装热分布模型 | 4～8 小时内完成 |
| 大型瞬态升温模型 | 12～24 小时内完成 |
| 多工况参数扫描 | 支持夜间批量运行 |
| GPU Solver 适配 | 明确支持和不支持边界 |
| 结果一致性 | GPU 与 CPU 结果在工程可接受范围内一致 |
| 稳定性 | 不出现内存、显存、临时盘瓶颈 |

## 九、最终建议

若预算允许：

> 1 台 4 卡 80GB GPU Fluent 服务器 + 1 台 1TB 内存 CPU 兜底节点。

若预算受限：

> 先采购 1 台 4 卡 GPU 服务器，GPU 优先 80GB；预算不足再退到 48GB，但必须做代表模型 Benchmark。

注意：当前截图中 GPU 数量需进一步确认。按 Ansys Fluent 和 70B 本地模型建议，目标应优先确认 **4 × 80GB GPU**。

## 二、A7 与 G7 如何判断

如果供应商所谓 A7/G7 实际是在比较 AMD 平台和 Intel 平台，则建议：

| 场景 | 推荐 |
|---|---|
| Ansys Fluent GPU Solver 为主 | 优先 NF5468A7 / AMD 平台 |
| 70B AI 推理兼顾 Fluent | A7 更有扩展余量 |
| 传统 Intel 生态、Ansys 代理商有成熟案例 | 可考虑 Intel G7/M7 |
| 只买 4 张 GPU，不准备扩展 | 两者都可，关键看价格、兼容性和 Benchmark |
| 供应商无法提供 Ansys Benchmark | 不应仅凭型号拍板 |

## 三、为什么倾向 A7

你们当前重点是：

- Ansys Fluent
- 复合材料成型工装热分布
- 湍流模型
- 瞬态传热
- 多工况扫描
- 可能兼顾 70B 本地模型

这种场景的优先级是：

```text
GPU 显存 > GPU 数量 > Fluent GPU Solver 适配 > 本地 NVMe > 内存 > CPU
```

A7 的 AMD EPYC 平台通常具备较强核心数、PCIe 通道和 GPU 扩展能力，更适合 GPU 密集型工作负载。

## 四、Fluent GPU Solver：服务器销售未必懂

服务器厂商通常懂：

- 服务器型号
- CPU / 内存 / GPU / 硬盘
- 供电散热
- GPU 数量
- 显存容量
- CUDA / 驱动概念

但未必真正懂：

- Fluent GPU Solver 支持哪些物理模型
- 湍流 + 传热 + 抽壳/薄壁模型能否跑 GPU Solver
- Ansys HPC 授权如何消耗
- GPU Solver 和 CPU Solver 结果如何验收
- Shell Conduction、辐射、UDF、CHT 的限制
- 48GB 与 80GB 显存到底够不够

因此，最终配置必须由：

```text
浪潮服务器售前 + Ansys 原厂/代理商技术人员 + 甲方内部仿真工程师
```

共同确认。

## 五、必须让浪潮确认的事项

1. GPU 数量到底是几张。
2. 是否支持扩展到 8 张 GPU。
3. H100 80GB PCIe 是否满足 Fluent GPU Solver 支持矩阵。
4. Ansys Fluent 版本、CUDA、驱动、操作系统是否匹配。
5. 湍流模型、能量方程、共轭传热、薄壁/抽壳、辐射、UDF 是否支持 GPU Solver。
6. 不支持 GPU Solver 的模型如何 CPU 兜底。
7. 4 × 80GB GPU 可支撑多大 Cell 数。
8. Ansys HPC / GPU 相关授权如何消耗。
9. 整机最大功耗、典型功耗、PDU、UPS、制冷要求。
10. 现有 42U、8 位 10A、2500W 机柜是否能承载。

## 六、推荐招标口径

```text
优先选择 NF5468A7 / AMD 平台作为 Ansys Fluent GPU 计算节点。
如供应商推荐 Intel 平台 NF5468G7/M7，必须说明在我司 Fluent 热分布、湍流、瞬态传热代表模型下，其性能、显存、License、CUDA/Driver 适配和 Benchmark 结果不低于 AMD 平台。

服务器配置应不低于：
1. 4U GPU 服务器；
2. 双路高性能 CPU；
3. 内存不低于 1TB DDR5；
4. GPU 优先配置 4 × 80GB 数据中心 GPU；
5. 本地 NVMe 不低于 4 × 3.84TB；
6. 网络不低于 25GbE，并预留 100GbE；
7. 支持后续 GPU 扩展；
8. 提供 Ansys Fluent GPU Solver 适配性确认和代表模型 Benchmark。
```

## 七、最终判断

主攻 Ansys Fluent 热流场，优先选 NF5468A7；但不能只听服务器销售承诺。

最终必须以：

- Ansys 技术适配确认
- 代表模型 Benchmark
- GPU Solver 支持边界
- License 消耗
- 功耗机柜评估

作为采购依据。

# 统一 Oracle 数据库集群、性能调优与容灾备份要求

## 一、总体要求

为保障 PLM、MES、ERP、OA 及后续数字化系统稳定运行、统一运维和数据安全，本项目要求各业务系统数据库架构统一纳入甲方私有云数字化底座管理体系。

原则如下：

1. 核心业务系统数据库原则上统一采用 Oracle 数据库集群架构。
2. 数据库高可用、性能调优、备份恢复、容灾切换应集中化设计、集中化管理。
3. 不允许各业务系统服务商自行建设孤立数据库、孤立备份、孤立监控和孤立容灾体系。
4. 所有数据库资源应纳入统一虚拟化/私有云资源池、统一存储资源池、统一备份平台和统一监控平台。
5. 各服务商应配合甲方完成数据库架构审查、性能基线测试、备份恢复演练和容灾切换验证。

## 二、Oracle 数据库集群统一要求

PLM、MES、ERP、OA 等核心系统原则上统一采用 Oracle 数据库，数据库部署应采用高可用集群架构。

| 系统 | 数据库要求 | 高可用要求 |
|---|---|---|
| PLM/PDM | Oracle 数据库集群 | 支持节点级故障切换 |
| MES | Oracle 数据库集群 | 支持高并发写入与高可用 |
| ERP | 原则上纳入 Oracle；如原厂不支持，应提交偏离说明 | 不低于现有可用性 |
| OA | 原则上纳入 Oracle；如原厂不支持，应提交偏离说明 | 支持主备或集群高可用 |
| 后续新增系统 | 优先采用 Oracle | 纳入统一数据库管理体系 |

如某业务系统因产品原厂限制无法采用 Oracle，服务商必须提交：

1. 原厂数据库兼容性说明。
2. 不能采用 Oracle 的技术原因。
3. 替代数据库高可用方案。
4. 替代数据库备份恢复方案。
5. 与统一监控、统一备份、统一容灾平台的对接方案。
6. 偏离项对性能、稳定性、运维和后续扩展的影响说明。

未经甲方书面确认，不得擅自采用非 Oracle 数据库架构。

## 三、数据库集群架构要求

### 3.1 生产数据库集群

| 项目 | 技术要求 |
|---|---|
| 数据库类型 | Oracle Database |
| 集群方式 | Oracle RAC 或同等级数据库集群高可用架构 |
| 节点数量 | 生产库不少于 2 个数据库节点 |
| 存储 | 优先使用全闪存高性能存储区域 |
| 网络 | 业务网、集群心跳网、存储网、备份网逻辑隔离 |
| 高可用 | 单节点故障时业务可继续运行 |
| 性能 | 支持 PLM/MES/ERP/OA 并发访问及高频读写 |
| 运维 | 纳入统一数据库监控、告警、备份和性能管理平台 |

### 3.2 灾备数据库

| 项目 | 技术要求 |
|---|---|
| 灾备方式 | Oracle Data Guard 或同等级数据库级灾备机制 |
| 灾备模式 | 支持物理备库、日志同步、主备切换 |
| 数据同步 | 支持归档日志或实时日志传输 |
| 切换能力 | 支持计划内切换和故障切换 |
| 演练要求 | 验收前完成至少 1 次灾备切换演练 |
| 恢复目标 | 服务商应明确 RPO 和 RTO |

## 四、数据库资源配置建议

| 项目 | 推荐配置 |
|---|---|
| 数据库节点数量 | 不少于 2 节点 |
| 单节点 CPU | 不低于 32 核，关键数据库建议 48 核以上 |
| 单节点内存 | 不低于 256GB，PLM/MES 数据库建议 512GB 起 |
| 数据盘 | 全闪 NVMe/SSD 高性能存储 |
| 日志盘 | 独立高性能 SSD/NVMe 区域 |
| 归档盘 | 独立归档日志存储区 |
| 备份盘 | 独立备份存储，不得与生产数据混用 |
| 网络 | 业务网、存储网、集群心跳网、备份网分离 |
| 高可用 | 支持数据库集群节点故障切换 |

## 五、重点系统数据库建议

| 系统 | 数据库资源建议 |
|---|---|
| PLM/PDM | 独立数据库实例或独立数据库资源池；内存不低于 512GB；数据盘使用全闪高 IOPS 区域；文件库与数据库分离 |
| MES | 独立数据库实例；优先保障写入性能、事务性能和日志盘性能 |
| ERP | 根据原厂支持情况确认 Oracle 适配；如无法采用 Oracle，应提供等效高可用和统一备份方案 |
| OA | 可采用共享 Oracle 集群中的独立实例或独立 PDB；附件与正文数据库分层存储 |
| 报表/BI | 不得直接压垮生产库，建议建设只读库、报表库或数据集市 |

## 六、集中式性能调优要求

各服务商必须配合甲方完成数据库性能调优，不得仅以“硬件资源不足”为由规避软件、SQL、索引、连接池、事务设计等优化责任。

服务商应提供：

1. 数据库安装部署参数。
2. 数据库实例参数建议。
3. 表空间规划。
4. 索引规划。
5. 慢 SQL 分析与优化。
6. 连接池配置建议。
7. 并发用户数与连接数测算。
8. 批处理任务调度策略。
9. 日志、归档、临时表空间规划。
10. 性能基线测试报告。

## 七、性能监控指标

| 类型 | 指标 |
|---|---|
| CPU | 使用率、等待队列、峰值负载 |
| 内存 | SGA/PGA 使用率、缓存命中率 |
| 存储 | IOPS、吞吐、平均延迟、峰值延迟 |
| SQL | 慢 SQL、执行计划、全表扫描、锁等待 |
| 会话 | 活跃连接数、阻塞会话、长事务 |
| 日志 | redo 日志切换频率、归档日志堆积 |
| 表空间 | 使用率、增长趋势、告警阈值 |
| 备份 | 备份成功率、备份耗时、恢复验证结果 |

## 八、统一备份平台要求

所有核心业务系统数据库、应用服务器、文件库、配置文件和虚拟机应纳入统一备份平台管理。

不允许各服务商仅在本系统内部自行配置简单脚本备份，不允许备份数据只保存在生产服务器本地。

统一备份平台应支持：

1. Oracle 数据库一致性备份。
2. 虚拟机整机备份。
3. 文件级备份。
4. 应用配置备份。
5. 定时自动备份。
6. 备份任务集中监控。
7. 备份失败告警。
8. 恢复任务审计。
9. 备份数据加密。
10. 不可变备份或防勒索保护。

## 九、容灾目标建议

| 系统 | RPO 建议 | RTO 建议 |
|---|---:|---:|
| MES | ≤15 分钟 | ≤2 小时 |
| PLM/PDM | ≤30 分钟 | ≤4 小时 |
| ERP | ≤30 分钟 | ≤4 小时 |
| OA | ≤1 小时 | ≤4 小时 |
| 文件库 | ≤4 小时 | ≤8 小时 |
| 测试/培训环境 | 可不纳入核心容灾 | 按需恢复 |

## 十、验收要求

| 验收项 | 要求 |
|---|---|
| Oracle 集群部署 | 节点正常、集群状态正常、故障切换正常 |
| 数据库性能 | 达到性能基线要求，无明显慢 SQL 和异常等待 |
| 备份任务 | 自动备份正常，失败可告警 |

| 运维文档 | 文档完整、参数清晰、账号权限明确 |
| 偏离项 | 偏离项已说明并经甲方确认 |

# 供应商响应问题清单与 Benchmark 要求

## 一、总体要求

本项目不接受仅基于硬件规格的笼统响应。所有服务商应按资源池、业务系统、数据库、备份、容灾、License、功耗和验收指标逐项响应。

## 二、发给浪潮/服务器厂商的问题

### 1. 超融合平台

1. 当前三节点 IR5280M7 方案是否仅覆盖 PLM/MES/ERP/OA 管理系统底座？
2. 是否不包含 Ansys Fluent、AI 大模型、vGPU 图形虚拟化、大规模 VDI？
3. 请补全 CPU、内存、硬盘、RAID/HBA、网卡、电源、功耗、维保明细。
4. 请按 PLM/MES/ERP/OA 输出资源落位表。
5. 三节点两副本可容忍何种故障？
6. 单节点故障后是否仍能保障全部核心业务运行？
7. 数据重建时间和重建期间性能影响是多少？
8. 软件授权按节点、CPU 还是容量授权？
9. 三年后续保费用和过保影响是什么？

### 2. GPU 服务器

1. NF5468A7 配置中 H100 80GB 的数量是多少？
2. 是否支持后续扩展至 8 张 GPU？
3. CPU、GPU、NVMe 的 PCIe 拓扑是什么？
4. 本地 NVMe 是否可作为 Fluent 临时盘和结果缓存？
5. 现有双万兆网卡是否满足需求，是否建议升级 25GbE/100GbE？

7. 现有 42U、8 位 10A、2500W 机柜是否可承载？
