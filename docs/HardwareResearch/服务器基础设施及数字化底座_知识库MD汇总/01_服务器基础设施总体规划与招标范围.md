# 服务器基础设施总体规划与招标范围

## 一、建设目标

本项目目标不是单纯采购服务器硬件，而是建设统一的企业私有云与数字化基础设施底座，支撑：

- PLM/PDM
- MES
- ERP
- OA
- 普通职员虚拟化桌面
- CATIA/Fibersim 等三维设计与前后处理
- Ansys Fluent 热流场仿真
- 本地 AI 大模型推理
- 统一数据库集群
- 统一备份与容灾

## 二、总体原则

### 1. 资源池分离

不同负载不应混跑在同一资源池中。

| 负载类型 | 建议资源池 |
|---|---|
| PLM/MES/ERP/OA 管理系统 | 超融合/虚拟化资源池 |
| 数据库 | Oracle 数据库集群与高性能全闪存储 |
| 普通职员办公桌面 | VDI/桌面云资源池 |
| CATIA/Fibersim/Ansys 前后处理 | vGPU 图形虚拟化资源池 |
| Ansys Fluent 热流场仿真 | GPU Fluent 计算节点 + CPU 兜底节点 |
| 本地 70B 大模型 | AI GPU 服务器或独立 AI 算力资源池 |
| 备份与容灾 | 独立备份一体机/备份存储/容灾资源池 |

### 2. 不把超融合当万能底座

浪潮三节点 IR5280M7 超融合方案适合承载管理系统虚拟机，但不建议承载：

- Ansys Fluent 生产仿真
- 70B 大模型推理
- CATIA/Fibersim 图形虚拟化
- 大规模 VDI
- 高强度数据库全部负载

### 3. 数据库、备份、容灾集中管理

各业务系统服务商不得各自建设孤立数据库、孤立备份、孤立监控和孤立容灾。核心系统原则上统一纳入 Oracle 数据库集群、统一备份平台、统一监控平台和统一容灾体系。

## 三、建议招标包件

| 包件 | 名称 | 主要内容 |
|---:|---|---|
| 包一 | 超融合/虚拟化底座 | IR5280M7 类超融合服务器、虚拟化软件、分布式存储、网络虚拟化 |
| 包二 | 数据库集群与高性能存储 | Oracle RAC/Data Guard、数据库服务器、全闪存储、日志/归档/备份分区 |
| 包三 | Ansys Fluent / AI GPU 算力服务器 | NF5468A7/G7 类 GPU 服务器、H100/A100/L40S 等 GPU、NVMe、本地模型盘 |
| 包四 | VDI 与图形虚拟化 | 普通职员 VDI、Ansys/CATIA 前后处理、NVIDIA vGPU 授权 |
| 包五 | 备份与容灾 | DP3000G7 或同级备份一体机、不可变备份、数据库一致性备份、恢复演练 |
| 包六 | 网络与机房配套 | 10/25/100GbE 交换机、光模块、UPS、PDU、机柜改造、散热、承重 |

## 四、需要避免的采购风险

### 风险 1：把 AI GPU 服务器当 Ansys Fluent 生产服务器

AI GPU 服务器从硬件上可以运行 GPU 计算，但 Fluent GPU Solver 受 Ansys 版本、CUDA、驱动、物理模型支持范围、License 等限制。必须由 Ansys 技术人员基于代表模型确认。

### 风险 2：把 Ansys Fluent 放进 PLM/MES/OA 超融合池

Fluent 计算会占用大量 CPU/GPU、内存和本地 I/O，容易影响业务系统稳定性，不应与 PLM/MES/OA 共用同一生产超融合池。

### 风险 3：只看裸容量，不看有效容量和性能

分布式存储两副本会明显折损容量。数据库还必须看 IOPS、延迟、日志盘、归档盘、备份窗口和恢复能力。

### 风险 4：忽略 License

Ansys、Oracle、NVIDIA vGPU、虚拟化平台、桌面云等授权都会影响最终能否真正发挥硬件性能。不能只验收服务器型号。

### 风险 5：忽略功耗和机柜

GPU 服务器可能单台功耗就超过普通机柜承载能力。现有 42U、8 位 10A、2500W 机柜不一定能承载 NF5468A7/G7 这类 4U GPU 服务器。

## 五、推荐总体架构

```text
普通业务系统：
PLM / MES / ERP / OA
    ↓
超融合/虚拟化资源池
    ↓
Oracle 数据库集群 + 全闪存储 + 统一备份

研发/仿真/AI：
CATIA/Fibersim/Ansys 前后处理
    ↓
vGPU 图形虚拟化资源池

Ansys Fluent 热流场仿真
    ↓
GPU Fluent 计算节点 + CPU 兜底节点

本地 AI 大模型
    ↓
AI GPU 服务器 / 独立 AI 算力池
```
