# 统一 Oracle 数据库集群、性能调优与容灾备份要求

## 一、总体要求

为保障 PLM、MES、ERP、OA 及后续数字化系统稳定运行、统一运维和数据安全，本项目要求各业务系统数据库架构统一纳入甲方私有云数字化底座管理体系。

原则如下：

1. 核心业务系统数据库原则上统一采用 Oracle 数据库集群架构。
2. 数据库高可用、性能调优、备份恢复、容灾切换应集中化设计、集中化管理。
3. 不允许各业务系统服务商自行建设孤立数据库、孤立备份、孤立监控和孤立容灾体系。
4. 所有数据库资源应纳入统一虚拟化/私有云资源池、统一存储资源池、统一备份平台和统一监控平台。
5. 各服务商应配合甲方完成数据库架构审查、性能基线测试、备份恢复演练和容灾切换验证。

## 二、Oracle 数据库集群统一要求

PLM、MES、ERP、OA 等核心系统原则上统一采用 Oracle 数据库，数据库部署应采用高可用集群架构。

| 系统 | 数据库要求 | 高可用要求 |
|---|---|---|
| PLM/PDM | Oracle 数据库集群 | 支持节点级故障切换 |
| MES | Oracle 数据库集群 | 支持高并发写入与高可用 |
| ERP | 原则上纳入 Oracle；如原厂不支持，应提交偏离说明 | 不低于现有可用性 |
| OA | 原则上纳入 Oracle；如原厂不支持，应提交偏离说明 | 支持主备或集群高可用 |
| 后续新增系统 | 优先采用 Oracle | 纳入统一数据库管理体系 |

如某业务系统因产品原厂限制无法采用 Oracle，服务商必须提交：

1. 原厂数据库兼容性说明。
2. 不能采用 Oracle 的技术原因。
3. 替代数据库高可用方案。
4. 替代数据库备份恢复方案。
5. 与统一监控、统一备份、统一容灾平台的对接方案。
6. 偏离项对性能、稳定性、运维和后续扩展的影响说明。

未经甲方书面确认，不得擅自采用非 Oracle 数据库架构。

## 三、数据库集群架构要求

### 3.1 生产数据库集群

| 项目 | 技术要求 |
|---|---|
| 数据库类型 | Oracle Database |
| 集群方式 | Oracle RAC 或同等级数据库集群高可用架构 |
| 节点数量 | 生产库不少于 2 个数据库节点 |
| 存储 | 优先使用全闪存高性能存储区域 |
| 网络 | 业务网、集群心跳网、存储网、备份网逻辑隔离 |
| 高可用 | 单节点故障时业务可继续运行 |
| 性能 | 支持 PLM/MES/ERP/OA 并发访问及高频读写 |
| 运维 | 纳入统一数据库监控、告警、备份和性能管理平台 |

### 3.2 灾备数据库

| 项目 | 技术要求 |
|---|---|
| 灾备方式 | Oracle Data Guard 或同等级数据库级灾备机制 |
| 灾备模式 | 支持物理备库、日志同步、主备切换 |
| 数据同步 | 支持归档日志或实时日志传输 |
| 切换能力 | 支持计划内切换和故障切换 |
| 演练要求 | 验收前完成至少 1 次灾备切换演练 |
| 恢复目标 | 服务商应明确 RPO 和 RTO |

## 四、数据库资源配置建议

| 项目 | 推荐配置 |
|---|---|
| 数据库节点数量 | 不少于 2 节点 |
| 单节点 CPU | 不低于 32 核，关键数据库建议 48 核以上 |
| 单节点内存 | 不低于 256GB，PLM/MES 数据库建议 512GB 起 |
| 数据盘 | 全闪 NVMe/SSD 高性能存储 |
| 日志盘 | 独立高性能 SSD/NVMe 区域 |
| 归档盘 | 独立归档日志存储区 |
| 备份盘 | 独立备份存储，不得与生产数据混用 |
| 网络 | 业务网、存储网、集群心跳网、备份网分离 |
| 高可用 | 支持数据库集群节点故障切换 |

## 五、重点系统数据库建议

| 系统 | 数据库资源建议 |
|---|---|
| PLM/PDM | 独立数据库实例或独立数据库资源池；内存不低于 512GB；数据盘使用全闪高 IOPS 区域；文件库与数据库分离 |
| MES | 独立数据库实例；优先保障写入性能、事务性能和日志盘性能 |
| ERP | 根据原厂支持情况确认 Oracle 适配；如无法采用 Oracle，应提供等效高可用和统一备份方案 |
| OA | 可采用共享 Oracle 集群中的独立实例或独立 PDB；附件与正文数据库分层存储 |
| 报表/BI | 不得直接压垮生产库，建议建设只读库、报表库或数据集市 |

## 六、集中式性能调优要求

各服务商必须配合甲方完成数据库性能调优，不得仅以“硬件资源不足”为由规避软件、SQL、索引、连接池、事务设计等优化责任。

服务商应提供：

1. 数据库安装部署参数。
2. 数据库实例参数建议。
3. 表空间规划。
4. 索引规划。
5. 慢 SQL 分析与优化。
6. 连接池配置建议。
7. 并发用户数与连接数测算。
8. 批处理任务调度策略。
9. 日志、归档、临时表空间规划。
10. 性能基线测试报告。

## 七、性能监控指标

| 类型 | 指标 |
|---|---|
| CPU | 使用率、等待队列、峰值负载 |
| 内存 | SGA/PGA 使用率、缓存命中率 |
| 存储 | IOPS、吞吐、平均延迟、峰值延迟 |
| SQL | 慢 SQL、执行计划、全表扫描、锁等待 |
| 会话 | 活跃连接数、阻塞会话、长事务 |
| 日志 | redo 日志切换频率、归档日志堆积 |
| 表空间 | 使用率、增长趋势、告警阈值 |
| 备份 | 备份成功率、备份耗时、恢复验证结果 |

## 八、统一备份平台要求

所有核心业务系统数据库、应用服务器、文件库、配置文件和虚拟机应纳入统一备份平台管理。

不允许各服务商仅在本系统内部自行配置简单脚本备份，不允许备份数据只保存在生产服务器本地。

统一备份平台应支持：

1. Oracle 数据库一致性备份。
2. 虚拟机整机备份。
3. 文件级备份。
4. 应用配置备份。
5. 定时自动备份。
6. 备份任务集中监控。
7. 备份失败告警。
8. 恢复任务审计。
9. 备份数据加密。
10. 不可变备份或防勒索保护。

## 九、容灾目标建议

| 系统 | RPO 建议 | RTO 建议 |
|---|---:|---:|
| MES | ≤15 分钟 | ≤2 小时 |
| PLM/PDM | ≤30 分钟 | ≤4 小时 |
| ERP | ≤30 分钟 | ≤4 小时 |
| OA | ≤1 小时 | ≤4 小时 |
| 文件库 | ≤4 小时 | ≤8 小时 |
| 测试/培训环境 | 可不纳入核心容灾 | 按需恢复 |

## 十、验收要求

| 验收项 | 要求 |
|---|---|
| Oracle 集群部署 | 节点正常、集群状态正常、故障切换正常 |
| 数据库性能 | 达到性能基线要求，无明显慢 SQL 和异常等待 |
| 备份任务 | 自动备份正常，失败可告警 |
| 恢复测试 | 能够从备份中成功恢复 |
| 容灾切换 | 能够完成主备切换和回切 |
| 监控告警 | 数据库、主机、存储、备份均纳入统一监控 |
| 运维文档 | 文档完整、参数清晰、账号权限明确 |
| 偏离项 | 偏离项已说明并经甲方确认 |
