# 浪潮超融合测算解读

## 一、一句话结论

浪潮提供的“中航 PLM 等应用超融合”测算，本质上是一套 **PLM/MES/ERP/OA 等管理系统的三节点超融合底座方案**。

它适合承载普通业务虚拟机和部分核心系统，但不覆盖：

- Ansys Fluent 热流场仿真
- AI 大模型服务器
- CATIA/Fibersim 图形虚拟化
- 大规模普通职员 VDI
- 完整 Oracle RAC/Data Guard 数据库集群
- 详细功耗、机柜、UPS 评估
- 详细价格

## 三、可以承载什么

| 系统/场景 | 是否适合 | 说明 |
|---|---|---|
| OA | 适合 | 轻量业务，适合虚拟化 |
| ERP 应用服务器 | 适合 | 数据库需单独评估 |
| PLM 应用服务器 | 适合 | 文件库和数据库需独立规划 |
| MES 应用服务器 | 适合 | 数据库写入压力需评估 |
| 测试/培训环境 | 适合 | 可放在虚拟化资源池 |
| 中间件、缓存、检索 | 适合 | 需分配独立资源 |
| 数据库 | 可承载但需谨慎 | 核心数据库建议 Oracle 集群和专用全闪资源 |

## 四、不建议承载什么

| 场景 | 原因 |
|---|---|
| Ansys Fluent 生产仿真 | 需要 GPU/大内存/本地 NVMe，不应和业务系统抢资源 |
| 70B 本地大模型 | 需要大显存 GPU |
| CATIA/Fibersim 图形虚拟化 | 需要专业 GPU 和 vGPU 授权 |
| 大规模 VDI | 登录风暴、IOPS、用户体验需专项测算 |
| 高强度数据库全集中混跑 | 容易出现 IOPS、延迟、资源争抢风险 |

## 五、关键风险

### 1. 三节点是起步配置，不一定是最终高可靠配置

三节点两副本一般可容忍一个节点故障，但要追问：

- 单节点故障后，剩余两节点是否还能承载全部生产业务？
- 是否按 N+1 设计？
- 数据重建需要多久？
- 重建期间性能下降多少？
- 是否建议四节点更稳？

### 2. 有效容量要看清

全闪裸容量 46.08TB，两副本可用 20.7TB。实际还要考虑：

- 快照空间
- 告警水位
- 元数据
- 数据增长
- 数据库日志和归档
- 备份是否占用生产池

### 3. 数据库性能不能只看容量

PLM/MES/ERP/OA 数据库应明确：

- IOPS
- 平均延迟
- 峰值延迟
- 日志盘位置
- 归档盘位置
- 备份窗口
- 数据库一致性快照
- Oracle RAC/Data Guard 适配

### 4. 软件授权口径要明确

需要确认：

- InCloud Sphere 授权是按节点还是按 CPU？
- 三台双路服务器是否需要 6 个 CPU 授权？
- dSAN、SmartFlow、文件存储、iCenter 的授权数量和有效期？
- 三年后续保费用？
- 过保后是否还能继续使用和升级？

## 六、应要求浪潮补充的内容

1. 明确本方案仅覆盖 PLM/MES/ERP/OA 超融合底座，不包含 Ansys Fluent、AI、vGPU 和大规模 VDI。
2. 补全硬件明细：CPU、内存、硬盘、RAID/HBA、网卡、电源、功耗。
3. 按 PLM/MES/ERP/OA 输出资源落位表。
4. 明确数据库部署建议和 IOPS/延迟指标。
5. 明确三节点两副本故障边界。
6. 明确软件授权数量和续保费用。
7. 明确备份一体机容量、RPO/RTO、数据库一致性备份。
8. 补充网络拓扑：管理网、业务网、存储网、备份网、迁移网。
9. 补充详细报价。
10. 另行提供 Ansys Fluent、AI、VDI、图形虚拟化专项方案。
