# 部门能力流程系统映射使用说明

## 1. 使用对象

本文用于说明各部门如何查看和反馈本部门的能力、流程、系统映射成果。

每个部门只需要关注本部门对应的三个文件：

| 文件 | 用途 |
|---|---|
| `{部门名}部门-能力-流程-系统映射关系.md` | 核对本部门的能力域、业务能力、业务流程、制度依据、应用系统，以及业务行为（A1）明细 |
| `{部门名}能力层与MDM建设要求.md` | 查看本部门涉及的主数据对象、数据治理要求和后续建设建议 |
| `{部门名}部门能力流程系统桑基图.html` | 用图形方式查看部门、能力、流程、行为和系统之间的关系，便于部门集中审核 |


## 2. 三个文件怎么看

### 2.1 映射关系 Markdown

文件名：`{部门名}部门-能力-流程-系统映射关系.md`

这个文件是部门审核的主文件。

重点查看：

1. 能力域（L1）是否覆盖本部门主要职责。
2. 业务能力（L2）名称是否符合部门日常用语和制度原文。
3. 业务流程（L3）是否完整、是否有遗漏或重复。
4. 制度依据是否准确，文件号、版次、条款号是否正确。
5. 应用系统（S1）建议是否合理。
6. 业务行为（A1）是否拆得过粗或过细。
7. 业务行为（A1）的执行角色、触发情景、前置条件是否符合实际。
8. 需要部门确认的提醒项是否已有明确结论。

如果发现问题，建议直接按行反馈：

| 位置 | 问题 | 建议修改 |
|---|---|---|
| 例如：业务流程（L3）第 12 行 | 流程名称与部门实际叫法不一致 | 改为“……” |
| 例如：业务行为（A1）编号 0103-A04 | 执行角色不是具体岗位 | 改为“绩效管理专员” |

### 2.2 能力层与 MDM 建设要求

文件名：`{部门名}能力层与MDM建设要求.md`

这个文件用于查看本部门后续信息化和数据治理建设建议。

重点查看：

1. 本部门涉及哪些主数据对象。
2. 哪些数据需要统一编码、统一分类、统一状态。
3. 哪些数据需要明确维护责任部门。
4. 哪些数据会被 OA、MES、PLM、ERP 等系统共同引用。
5. 哪些建设建议需要部门确认优先级。

部门反馈时，重点说明：

| 问题 | 部门需确认内容 |
|---|---|
| 主数据对象是否准确 | 是否有多列、漏列、名称不准确 |
| 数据责任是否准确 | 哪些数据由本部门维护，哪些只是引用 |
| 优先级是否合理 | 哪些对象应优先治理，哪些可以后置 |

### 2.3 桑基图 HTML

文件名：`{部门名}部门能力流程系统桑基图.html`

这个文件用于快速看整体关系和向部门汇报。

本目录下的桑基图页面必须引用同目录 `echarts.min.js`，不要引用上一级 `../echarts.min.js`。

建议查看顺序：

1. 先看“全域总览”，确认本部门能力域（L1）和应用系统（S1）的总体关系。
2. 再切换到具体能力域（L1），查看业务能力（L2）、业务流程（L3）、业务行为（A1）和应用系统（S1）的明细。
3. 查看下方明细表，逐条核对制度依据、执行角色、触发情景、前置条件、审批类型和核验提醒。
4. 对带有“请部门确认”的内容逐项反馈。

图中业务行为（A1）节点应显示“行为名称 + 执行角色”。编号只用于追溯，不作为前端主要显示内容。

## 3. 部门需要完成的待办

每个部门审核时，建议按以下顺序完成。

### 待办一：确认能力和流程范围

部门需确认：

- 能力域（L1）是否覆盖本部门职责。
- 业务能力（L2）名称是否准确。
- 业务流程（L3）是否完整。
- 是否存在遗漏流程。
- 是否存在不属于本部门主责的流程。

### 待办二：确认制度依据

部门需确认：

- 文件号是否正确。
- 版次是否为当前有效版本。
- 条款号是否准确。
- 是否有制度已废止或已升版。
- 是否有实际在做但制度未覆盖的工作。

### 待办三：确认业务行为（A1）

部门需确认：

- 每条业务行为（A1）是否符合实际工作步骤。
- 执行角色是否为具体岗位或人员角色。
- 如果当前只写了部门、办公室、小组、委员会等组织名称，需补充具体责任岗位。
- 触发情景是否准确。
- 前置条件是否准确。
- 审批类型是否准确。

### 待办四：确认验收标准

只需要重点确认以下两类环节：

- 某个业务流程（L3）的最后一个业务行为（A1）。
- 跨部门交接前的最后一个业务行为（A1）。

普通中间步骤不需要强行补验收标准。

跟踪、提醒、催办、进度展示类任务，优先作为系统待办、到期预警、状态看板或闭环记录来处理。

### 待办五：确认应用系统建议

部门需确认：

- 业务流程（L3）和业务行为（A1）建议承载的应用系统（S1）是否合理。
- 已经在现有系统中办理的流程，应注明实际系统。
- 尚未系统化的流程，应确认是否需要纳入后续建设。
- 不适合 OA、MES、PLM、ERP 承载的事项，应说明原因。

### 待办六：确认主数据建设建议

部门需确认：

- 主数据对象是否完整。
- 数据名称是否符合部门习惯。
- 数据维护责任是否准确。
- 哪些数据需要统一编码。
- 哪些数据需要跨系统共享。
- 哪些数据应优先治理。

## 4. 反馈方式建议

部门反馈建议采用表格形式，便于后续逐项修订。

| 文件 | 位置 | 问题类型 | 部门意见 | 是否需要修改 |
|---|---|---|---|---|
| 映射关系 Markdown | 业务流程（L3）第 X 行 | 流程遗漏 | 建议增加“……”流程 | 是 |
| 映射关系 Markdown | 业务行为（A1）编号 XXX | 执行角色不准确 | 应改为“……” | 是 |
| 桑基图 HTML | 某能力域明细 | 系统建议不准确 | 实际使用 OA，不是 ERP | 是 |
| 能力层与MDM建设要求 | 主数据对象表 | 主数据缺项 | 建议增加“……” | 是 |

## 5. 最终确认清单

部门完成审核前，请确认以下事项：

- 三个标准文件都已查看。
- 能力域（L1）和业务能力（L2）名称已确认。
- 业务流程（L3）没有明显遗漏。
- 制度依据已确认到文件号、版次和条款号。
- 业务行为（A1）执行角色已尽量明确到岗位。
- 带“请部门确认”的内容已反馈。
- 应用系统（S1）建议已确认或提出修改意见。
- 主数据对象和数据责任已确认或提出修改意见。
