# 流程映射表字段说明

> 状态：流程输入基线字段口径
> 范围：`docs/norms/{部门}部门-能力-流程-系统映射关系.md` 中的 DCM 主表、L3 稳定编号索引和 BBM/A1 主记录表。
> 验证入口：从仓库根目录运行 `node scripts/verify-norms-source-mapping.mjs`。

本说明用于统一流程治理映射表字段含义，支撑 PMO 驾驶舱、MDM 流程治理问题卡和后续人工复核。字段填写只反映制度、表单、流程图、台账或部门确认后的事实；证据不足时保留待确认口径，不把分析推断写成已确认结论。

## 1. DCM 主表字段

DCM 主表描述稳定流程骨架：部门（D1）到能力域（L1）、业务能力（L2）、业务流程（L3）和应用系统（S1）的对应关系。

| 字段 | 是否必填 | 填写口径 | 核验方式 | 进入“在哪发现” |
|---|---|---|---|---|
| 序号 | 可选 | 仅用于阅读排序，不作为稳定主键。 | 可为空；不得替代 L3 稳定编号。 | 不进入。 |
| 部门（D1） | 必填 | 使用组织真源中的标准部门名称。 | 与 `docs/organization/组织架构和部门职责.md` 及合同部门清单一致。 | 不单独展示，可用于过滤。 |
| 能力域（L1） | 必填 | 部门能力的一层分类，表达管理领域。 | 同部门内名称稳定；不写成具体动作。 | 不单独展示。 |
| 业务能力（L2） | 必填 | 能力域下的可管理能力，不写成系统功能。 | 与 L3 所属能力一致。 | 不单独展示。 |
| 业务流程（L3） | 必填 | 面向业务人员可理解的流程名称，是 A1 行为挂接的上级流程。 | A1 编号或 A1 行中的 L3 必须能回到本表。 | 进入“业务流程”。 |
| 制度依据（文件号/条款） | 必填 | 写源文件编号、制度或表单名称、条款/章节/表格/全文等位置；没有编号时写 `待分配编号《文件名》§位置`。 | 先匹配 `docs/norms/*业务资料` 源文件，再核验条款、表格或摘录是否可定位。 | 拆解为“源文件编号”“制度或表单名称”“大概位置”。 |
| 应用系统（S1） | 可为空 | 只允许 `OA`、`MES`、`PLM`、`ERP` 或留空；多个系统用顿号、中文逗号或英文逗号分隔。 | 与 DCM/BBM 合同枚举一致；`MDM` 不作为 S1。 | 不进入“在哪发现”。 |
| 系统设计依据 | 必填 | 说明为什么该 L3 建议落位到某个 S1，使用业务场景语言，不写系统评价。 | 不得把制度条款误放到系统字段；不得出现源文件编号被解析为系统。 | 不进入。 |

## 2. L3 稳定编号索引字段

L3 稳定编号索引用于让 A1 编号和前端跳转稳定挂接，不改变 DCM 主表的业务含义。

| 字段 | 是否必填 | 填写口径 | 核验方式 | 进入“在哪发现” |
|---|---|---|---|---|
| 稳定编号 / 业务流程（L3）编号 / 流程编号 | 必填 | 每个 L3 一个稳定编号，如 `XM-L3-32`。 | A1 编号前缀应能匹配该编号。 | 不直接展示。 |
| 业务流程（L3） | 必填 | 与 DCM 主表中的 L3 名称一致或可明确对应。 | 与 DCM 主表互相校验。 | 进入“业务流程”。 |
| 业务能力（L2） | 必填 | 与 DCM 主表的 L2 一致。 | 与 DCM 主表互相校验。 | 不单独展示。 |
| 能力域（L1） | 必填 | 与 DCM 主表的 L1 一致。 | 与 DCM 主表互相校验。 | 不单独展示。 |

## 3. BBM/A1 主记录字段

BBM/A1 主记录表描述业务流程下的具体业务行为。A1 只挂接到已确认的 L3，不反向改写 DCM。

| 字段 | 是否必填 | 填写口径 | 核验方式 | 进入“在哪发现” |
|---|---|---|---|---|
| 业务行为（A1）编号 | 必填 | 稳定编号，通常由 L3 编号加 `-Axx` 组成。 | 同部门内不得重复；前缀应能回到 L3 稳定编号。 | 可作为内部追溯，不替代业务行为。 |
| 业务行为（A1） | 必填 | 写一个明确业务动作，避免只写名词或编号。 | 不得与编号相同；跨部门输入/输出应有证据支撑。 | 进入“业务行为”。 |
| 执行角色 | 必填 | 写实际执行岗位、角色或组织。集体角色可保留，但需提醒确认具体岗位。 | 与执行角色依据、核验提醒相互印证。 | 不进入“在哪发现”。 |
| 执行角色依据 | 可选 | 写支持执行角色判断的条款、摘录或待补说明。 | 优先回到本行制度依据中的源文件核验章节或摘录。 | 可辅助“大概位置”，但不单独作为源文件。 |
| 触发情景 | 必填 | 写业务何时启动，不与前置条件混写。 | 与触发情景依据相互印证。 | 不进入。 |
| 触发情景依据 | 可选 | 写触发情景的条款、摘录或待补说明。 | 优先回到本行制度依据中的源文件核验。 | 可辅助“大概位置”。 |
| 前置条件 | 必填 | 写执行前必须满足的状态、资料或审批结果。 | 与前置条件依据相互印证。 | 不进入。 |
| 前置条件依据 | 可选 | 写前置条件的条款、摘录或待补说明。 | 优先回到本行制度依据中的源文件核验。 | 可辅助“大概位置”。 |
| 数据输入 | 可选 | 写受控输入物、表单、台账、计划或数据。 | 有跨部门来源时必须有证据证明传递关系。 | 不进入。 |
| 数据输出 | 可选 | 写受控输出物、表单、台账、通知或结果。 | 有跨部门目标时必须有证据证明交付关系。 | 不进入。 |
| 输入来源部门 | 可选 | 只有制度、表单、流程图或台账证明输入来自某部门时填写。 | 不能把职责、参与、审批、归档自动写成输入来源。 | 不进入。 |
| 输出目标部门 | 可选 | 只有证据证明输出物发送、提交、反馈、交接到某部门时填写。 | 不能把职责、参与、审批、归档自动写成输出目标。 | 不进入。 |
| 审批类型 | 必填 | 仅使用 `无审批`、`单人审批`、`多级审批`、`会签`。 | 审批类结论必须有原文、流程图、表单签批栏或审批链证据。 | 不进入。 |
| 应用系统（S1） | 可为空 | 只允许 `OA`、`MES`、`PLM`、`ERP` 或留空。 | 与 DCM/BBM 合同枚举一致。 | 不进入。 |
| 应用模块（S2） | 可选 | 写 S1 下的业务模块或功能域；没有明确模块时留空或待确认。 | 不得替代 S1；不得写成制度依据。 | 不进入。 |
| 制度依据 | 必填 | 写源文件编号、制度或表单名称、条款/表格/全文；可带短摘录。 | 先匹配源文件，再核验章节、表格或摘录。 | 拆解为“源文件编号”“制度或表单名称”“大概位置”。 |
| 证据类型 | 必填 | 使用 `原文明确-正文`、`原文明确-流程图`、`原文明确-表单`、`上下文推断`、`分析拆分`。 | 不在枚举中视为需处理；扩展说明放备注或核验提醒。 | 不进入。 |
| 验收标准 | 必填 | 写该 A1 完成后如何判断已经做到。 | 不能只写“完成”或空泛结果。 | 不进入。 |
| 验收标准依据 | 可选 | 写验收标准来源条款、表单栏位或待补说明。 | 优先回到本行制度依据中的源文件核验。 | 可辅助“大概位置”。 |
| 核验提醒 | 必填 | 写需要业务部门确认的问题，使用业务人员能照着处理的句子。 | 不预设结论；不把“源证据不足”和“制度原文没写清”混写。 | 可作为问题说明，不作为“在哪发现”主字段。 |
| 部门确认意见 | 必填 | 人工确认前通常为 `待确认`；确认后写处理结论。 | 不由脚本自动改写。 | 不进入。 |
| 是否调整 | 必填 | 人工确认前通常为 `待确认` 或留待确认口径；确认后写是否调整。 | 不由脚本自动改写。 | 不进入。 |
| 调整建议 | 可选 | 写建议调整方向，不直接修改源制度或映射基线。 | 有明确确认后再进入正式修改流程。 | 不进入。 |
| 备注 | 可选 | 放旧模板遗留值、边界说明、补充解释。 | 不替代必填字段。 | 不进入。 |

## 4. “在哪发现”展示字段

MDM 流程治理问题卡中的“在哪发现”应从映射表证据字段和源文件清单拆解，不展示 Markdown 文件名、中间 JSON、抽取脚本产物或 `_extracted` 目录。

| 展示项 | 生成来源 | 显示口径 |
|---|---|---|
| 源文件编号 | DCM `制度依据（文件号/条款）` 或 A1 `制度依据` 中的文件号；也可从匹配源文件名识别。 | 如 `GLTX-XM-06-A`、`GLC260701-A`、`FM2607-14`；没有编号时显示 `待分配编号`。 |
| 制度或表单名称 | 证据字段中的 `《文件名》`，或匹配源文件名去掉编号、版本和扩展名后的名称。 | 显示制度、程序、管理标准、表单或台账名称。 |
| 大概位置 | 证据字段中的 `§条款`、`表格`、`附件`、`全文`、页码或可定位摘录。 | 能定位原文时写条款、页码、表格或摘录；只能定位到流程输入基线时，必须明说尚未定位到制度或表单原文段落。 |
| 业务流程 | DCM `业务流程（L3）`，或 A1 通过编号/字段挂接到的 L3。 | 显示业务流程名称，不显示内部解析路径。 |
| 业务行为 | A1 `业务行为（A1）`。 | 显示业务动作文本；DCM 层问题没有 A1 时可为空。 |

## 5. 核验结果口径

`verify-norms-source-mapping.mjs` 输出四类结果：

| 结果 | 含义 | 处理方式 |
|---|---|---|
| OK | 源文件匹配成功，条款、表格或摘录至少一项可定位。 | 可作为已验证证据使用。 |
| INFO | 字段为空但非必填，或源文件已匹配但没有可自动核验锚点。 | 通常作为提示保留。 |
| WARN | 源文件存在但格式暂不能抽正文，或含待补/待确认口径，或部分锚点未定位。 | 需要 OCR、人工打开原件或补齐证据。 |
| BLOCK | 必填证据为空、源文件缺失、源文件已匹配但条款/摘录均无法定位、表头缺失或 A1 编号重复。 | 必须处理或登记为历史遗留后再交付。 |

机器明细写入 `artifacts/norms-source-mapping-verify/<run-id>/`，人工报告写入 `docs/reports/<日期>-norms-source-mapping-verification.md`。
