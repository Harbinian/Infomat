## 一、这份文件是什么

这是一份 Infomat 3001 单流程治理编制工具的结构化编制文件，结构版本 `process-governance-v7`，只描述一个业务流程：经营发展部归口的「数字化技术研究与应用管理」。
3001 只接受这类 JSON 文件导入，不接受自由文本。编制人在 3001 页面通过「文件 → 继续已有流程」导入后，可以在页面内存中修改，再下载为新的 JSON。
文件中的内容全部是业务事实的待核对记录，不是已发布制度，也不构成流程输入基线。

## 二、文件顶层结构

文件是一个 JSON 对象，包含九个顶层键，全部为必填：

1. `schema_version`：固定为 `process-governance-v7`。
2. `export_meta`：编制包的标识、导出时间、发起部门和编制人。
3. `process`：一条流程的基本信息。
4. `behaviors`：业务行为和判断节点的数组，共 25 条。
5. `flow_relations`：行为之间的先后、条件、回路关系，共 33 条。
6. `data_objects`：流程产生的数据对象，共 10 个。
7. `forms`：关联表单和记录，共 9 张。
8. `terms`：流程涉及的术语，共 7 条。
9. `migration`：来源版本、来源流程和参考材料等迁移信息。

## 四、流程关系（33 条）

关系类型有四种取值：`sequence`（顺序）、`condition`（条件分支）、`loop`（回路）、`parallel`（并行）。本文件只使用了前三种。
每条形如「从某行为到某行为，条件为……」。条件为空表示顺序流转。

1. `relation_01`　顺序：提出部门填报数字技术应用需求申报表 → 数字工程室核对需求申报表
2. `relation_02`　顺序：数字工程室核对需求申报表 → 数字工程室判断申报表是否需要退回补正
3. `relation_03`　回路：数字工程室判断申报表是否需要退回补正 → 提出部门填报数字技术应用需求申报表，条件“填写要素缺失或者业务场景不具体，退回补正”
4. `relation_04`　条件：数字工程室判断申报表是否需要退回补正 → 数字工程室汇总需求并编制年度计划表，条件“核验通过”
5. `relation_05`　顺序：数字工程室汇总需求并编制年度计划表 → 分管领导签署年度计划表审批意见
6. `relation_06`　顺序：分管领导签署年度计划表审批意见 → 分管领导判断年度计划表是否通过审批
7. `relation_07`　回路：分管领导判断年度计划表是否通过审批 → 数字工程室汇总需求并编制年度计划表，条件“分管领导退回修改”
8. `relation_08`　条件：分管领导判断年度计划表是否通过审批 → 数字工程室判断事项是否需要立项研究，条件“同意执行”
9. `relation_09`　条件：数字工程室判断事项是否需要立项研究 → 数字工程室编制项目实施方案，条件“实施方式为立项研究的事项”
10. `relation_10`　条件：数字工程室判断事项是否需要立项研究 → 数字工程室下达年度计划并登记接收，条件“纳入年度计划直接实施或者暂不实施的事项”
11. `relation_11`　顺序：数字工程室下达年度计划并登记接收 → 实施部门反馈年度计划事项完成情况
12. `relation_12`　顺序：实施部门反馈年度计划事项完成情况 → 数字工程室移交项目资料归档，条件“年度计划执行情况随项目资料归档”
13. `relation_13`　顺序：数字工程室编制项目实施方案 → 评审组评审项目实施方案并签署评审意见
14. `relation_14`　顺序：评审组评审项目实施方案并签署评审意见 → 评审组判断方案评审是否通过
15. `relation_15`　回路：评审组判断方案评审是否通过 → 数字工程室编制项目实施方案，条件“评审结论为退回修改”
16. `relation_16`　条件：评审组判断方案评审是否通过 → 分管领导签署项目立项审批意见，条件“评审通过”
17. `relation_17`　条件：评审组判断方案评审是否通过 → 数字工程室移交项目资料归档，条件“不予立项，终止并归档”
18. `relation_18`　顺序：分管领导签署项目立项审批意见 → 数字工程室判断项目是否需要外部合作
19. `relation_19`　条件：数字工程室判断项目是否需要外部合作 → 数字工程室签署外部合作协议，条件“需要外部合作”
20. `relation_20`　条件：数字工程室判断项目是否需要外部合作 → 数字工程室按方案实施并填写项目过程记录表，条件“自主实施”
21. `relation_21`　顺序：数字工程室签署外部合作协议 → 数字工程室按方案实施并填写项目过程记录表
22. `relation_22`　顺序：数字工程室按方案实施并填写项目过程记录表 → 数字工程室判断里程碑节点是否达到方案要求
23. `relation_23`　回路：数字工程室判断里程碑节点是否达到方案要求 → 数字工程室按方案实施并填写项目过程记录表，条件“节点未达到方案要求，补救后继续实施”
24. `relation_24`　条件：数字工程室判断里程碑节点是否达到方案要求 → 数字工程室核对技术指标并填写验证记录，条件“全部里程碑节点达到方案要求”
25. `relation_25`　顺序：数字工程室核对技术指标并填写验证记录 → 使用部门填写试点应用记录
26. `relation_26`　顺序：使用部门填写试点应用记录 → 评审组判断验证与试点是否通过
27. `relation_27`　回路：评审组判断验证与试点是否通过 → 数字工程室核对技术指标并填写验证记录，条件“整改后复验”
28. `relation_28`　条件：评审组判断验证与试点是否通过 → 评审组编制成果评价报告，条件“验证与试点通过”
29. `relation_29`　条件：评审组判断验证与试点是否通过 → 数字工程室移交项目资料归档，条件“终止并归档”
30. `relation_30`　顺序：评审组编制成果评价报告 → 数字工程室编制应用推广方案
31. `relation_31`　顺序：数字工程室编制应用推广方案 → 数字工程室填写应用效果评价表
32. `relation_32`　顺序：数字工程室填写应用效果评价表 → 数字工程室修订制度或者编制作业指南
33. `relation_33`　顺序：数字工程室修订制度或者编制作业指南 → 数字工程室移交项目资料归档

其中指向判断节点的回路有两条：方案评审未通过时退回重新编制实施方案；验证与试点未达到要求时退回重新验证。另有两条指向流程收口行为（资料归档），分别承接「不予立项终止」和「验证终止」两个结论。
