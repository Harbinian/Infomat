# AGENTS.md — 组织与工作角色资料

根目录 `AGENTS.md`、`CODEX.md` 和仓库边界文件继续有效。本文件规定 `docs/organization/` 的本地维护边界。

## 目录责任

- 2026-09-11用户已撤销所有`docs/`文件的真源身份。本目录全部文件只作历史、转换/导出和交接副本，不作为当前组织、人员、角色或流程治理的依据。
- 人员事实回到用户指定的行政人事部发布Excel核对；`花名册.md`仅保留转换结果及来源摘要。
- 业务职责和具体任命由业务主体或有权主体明确确认，不由旧组织说明或项目映射反推。
- `docs/work-role-data.json`保留为旧消费链的派生资产，不能以其内容决定当前角色或授权。

## 修改规则

1. 修改前先确认目标是授权的交接记录、来源副本还是历史兼容说明；不将本目录文件重新认定为真源。
2. 不根据姓名、岗位、职务、原文角色称谓或人员所在部门推断正式工作角色、最终负责人或权限。
3. 不为治理任务自动从本目录生成部门、角色、任命或数据库记录；旧消费链的兼容修改须明确输入、输出及授权，不手工改派生JSON掩盖来源问题。
4. 文件包含人员信息时，只处理当前任务必需的最小范围，不把人员明细复制到报告、日志、样例或第三方服务。
5. 3001编制、人工下载/上传、3000治理并形成正式版本，再生成程序文件；不把本目录更新写成已完成平台发布或人员导入。
6. 人员按公司领导层（总经理、副总经理）、部门、办公室或班组的三级管理口径记录。来源未提供的第三级组织及人员归属保留为空；虚拟办公室或班组由项目负责人后续按流程设置，不根据岗位、姓名或相近名称自动补建、合并或授权。

## 固定验证

只有明确授权修改旧岗位/角色消费链的兼容行为时，才按影响选择以下入口；本次撤销真源身份不自动运行这些基于旧资料的生成命令：

```powershell
npm run build:work-role-data
npm run test:work-role-contract
npm run test:dept-domain-mapping
```

生成失败时保留已有快照，先修复真源或明确待确认项，不以默认值或人工改 JSON 绕过检查。
