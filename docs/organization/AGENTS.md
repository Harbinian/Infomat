# AGENTS.md — 组织与工作角色资料

根目录 `AGENTS.md`、`CODEX.md` 和仓库边界文件继续有效。本文件规定 `docs/organization/` 的本地维护边界。

## 目录责任

- `组织架构和部门职责.md` 是部门到域映射的当前真源。
- `工作角色目录与岗位映射.md` 是正式工作角色、生命周期、岗位映射和原文别名的受控入口。
- `信息化项目人员角色映射.md` 只记录已经进入项目运行链条的人员映射。
- `花名册.md` 是岗位核验和历史追溯参考，不自动成为 3000 员工主数据。
- `docs/work-role-data.json` 是受控派生消费文件，不是本目录的人工维护入口。

## 修改规则

1. 修改前先确认目标是组织事实、工作角色、项目人员映射还是参考资料，不从页面、脚本常量或运行数据库反推本目录真源。
2. 不根据姓名、岗位、职务、原文角色称谓或人员所在部门推断正式工作角色、最终负责人或权限。
3. 修改部门、域、工作角色、岗位映射或别名后，先改对应 Markdown 真源，再运行生成和一致性检查；不得手工改 `docs/work-role-data.json` 掩盖真源问题。
4. 文件包含人员信息时，只处理当前任务必需的最小范围，不把人员明细复制到报告、日志、样例或第三方服务。
5. 3000 正式切换后的真源变化按 `README.md` 的切换边界执行，不把切换前资料写成已发布员工主数据。

## 固定验证

涉及工作角色、岗位映射、别名或花名册岗位时，从仓库根目录运行：

```powershell
npm run build:work-role-data
npm run test:work-role-contract
npm run test:dept-domain-mapping
```

生成失败时保留已有快照，先修复真源或明确待确认项，不以默认值或人工改 JSON 绕过检查。
