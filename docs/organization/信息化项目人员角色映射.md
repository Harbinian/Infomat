# 信息化项目人员角色映射

> 状态：组织人员真源映射层  
> 生效日期：2026-07-06  
> 最近修订：2026-09-11
> 维护位置：`docs/organization/`  
> 用途：把花名册人员与信息化项目组、项目执行架构和 PMO 运行材料中的项目角色对齐，供 3002 等运行台账只读选择。

## 1. 定位

本文件是 `花名册.md` 与信息化项目材料之间的映射层。

- `花名册.md` 是依据行政人事部最新发布文件转换的当前仓库人员真源。
- `组织架构和部门职责.md` 仍是组织架构、部门职责、信息化工作组和项目执行架构来源。
- `pmo/信息化项目_协同工作规则.md` 和 `pmo/信息化项目_部门主备对接人名单.md` 是部门主备岗及相关 PMO 运行权限的补充来源，不替代花名册和组织真源。
- 其他 PMO 材料只作为项目运行分工补充来源，不替代花名册和组织真源。
- 本文件只收已经进入信息化项目运行链条的人，不复制全量花名册。
- 3002 周会行动项服务只能只读使用本映射或其派生快照，不能在运行台账里新增、修改、禁用人员。
- 周会或会后整理发现人员信息不一致时，应形成 `人员信息待校正` 跟踪事项，而不是在 3002 选择器里直接改人。

2026-09-11 按最新花名册以工号核对，并核对姓名一致，只同步花名册部门、职务及匹配状态。人员属性变化的映射标为待确认，项目组织、项目角色、任命状态及依据原样保留，后续由任命责任方核对任职关系。新版未收录者保留映射行和历史工号，标为 `花名册待补`；这不表示离职、撤销任命或停用账号。原先未匹配的人员不只凭姓名自动认领。详见[本轮更新说明](花名册更新说明_2026-09-11.md)。本轮未发布 3002 运行快照。

## 2. 字段口径

| 字段 | 口径 |
|---|---|
| 工号 | 来自 `花名册.md`；花名册未匹配时写 `待花名册确认` |
| 历史工号 | 新版花名册未收录时保留更新前工号，仅供追溯，不作为当前有效员工匹配或授权凭证 |
| 姓名 | 来自项目材料原文，不根据岗位或角色猜测 |
| 花名册部门 | 来自 `花名册.md`；花名册未匹配时写 `待花名册确认` |
| 花名册职务 | 来自 `花名册.md`；花名册未匹配时写 `待花名册确认` |
| 项目组织 | 信息化工作组、项目决策组、信息化项目管理工作室、专项工作组或 PMO 运行补充分工 |
| 项目角色 | 项目材料中写明的角色、岗位或运行职责 |
| 任命状态 | `红头任命`、`项目执行分工`、`暂定`、`待确认`、`已撤销` |
| 来源材料 | 支撑该行映射的材料 |
| 来源位置 | 材料中的章节、表格或条款位置 |
| 来源可信度 | `高：红头文件`、`高：组织真源明确列示`、`中：PMO运行材料`、`待确认：需补花名册或正式任命` |
| 人员匹配状态 | `已匹配花名册` 或 `花名册待补` |
| 是否待确认 | 人员、任命或来源是否还需后续确认 |
