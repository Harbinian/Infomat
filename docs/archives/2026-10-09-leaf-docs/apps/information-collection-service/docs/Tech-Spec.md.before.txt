# 信息表收集服务技术设计

## 1. 总体结构

一个 Node.js 进程创建两个 Express 应用。4000 只注册管理路由和后台静态资源；4001 只注册填报路由和填报静态资源。两个应用共享 MySQL 连接池、领域服务、结构校验和文件存储模块，不开放跨域访问。

4000 和 4001 使用不同 Cookie 名称。服务把随机会话令牌的 SHA-256 保存到 MySQL，并在每次请求时重新核对人员状态、账号状态和 `auth_version`。

## 2. 数据流

```text
person / user_accounts / departments（只读身份真源）
  ↓ 登录与请求复核
4000 管理接口 ── collection_* ── 4001 填报接口
                       │
                       └── COLLECTION_FILE_ROOT（附件正文）
```

4000 发布任务时，服务在一个事务中锁定表单、校验设计稿、复用或生成不可变版本、展开人员范围并创建任务和目标快照。事务任一步骤失败时，服务回滚本次发布。

4000 的表单预览只渲染当前页面设计稿，不创建任务、答卷或附件。归档操作把表单状态改为 `archived` 并写入审计记录，不物理删除表单、历史版本、任务或答卷；服务拒绝继续修改或发布已归档表单。

删除操作只接受没有表单版本和收集任务的设计稿。服务在同一事务内锁定表单、复核部门权限、检查历史引用、删除表单并写入审计记录；如果表单已经发布过，服务返回 `409 FORM_HAS_HISTORY`，用户只能归档该表单。

4001 保存答卷时，服务按不可变表单版本校验答案。提交时，服务锁定当前答卷、写入提交快照，再更新当前状态和修订号。

表单分区的 `kind` 为 `main` 或 `detail`。旧结构没有 `kind` 时按 `main` 读取。主表答案继续使用稳定 `fieldKey` 保存在答案根对象；明细答案保存在 `__detailRows[sectionKey][]`，每行包含稳定 `rowKey` 和按 `fieldKey` 保存的 `values`。人员和部门答案在主表及每条明细行中都由服务端重新读取身份真源并保存名称快照。

每张明细表分别配置 `minRows` 和 `maxRows`，其中 `0 <= minRows <= maxRows <= 100`。服务端在草稿保存时校验结构、行标识、字段类型和未知字段，在正式提交时追加校验最少行数及每行必填字段。附件字段当前只允许放在主表中。

4001 的明细表使用二维网格录入。浏览器从剪贴板读取 `text/plain`，按制表符和换行解析 Excel 复制的矩形区域，也保留带引号单元格内的换行。页面以当前单元格为左上角，将文本转换为表单版本中对应字段的稳定答案值；人员姓名存在重名时，页面拒绝按姓名匹配并提示填报人粘贴工号。页面在修改答案前完成整块数据预检查，任一单元格越界、类型转换失败或违反字段校验规则时均不写入任何单元格。检查通过后，页面自动补足明细行、保留一次撤销快照，并沿用现有 `expectedRevision` 自动保存机制。系统不读取或上传本地 Excel 文件。

4001 收到 `REVISION_CONFLICT` 后停止自动保存并读取同一任务的服务器最新答卷，但继续在页面内存中保留本页答案。页面要求填报人选择服务器版本或本页版本。填报人选择服务器版本时，页面用服务器答案和修订号替换本页状态；填报人选择本页版本时，页面仅在服务器任务仍开放且答卷仍为草稿的条件下，使用服务器最新修订号重新提交本页完整答案。服务器答卷已经提交或任务已经关闭时，页面禁止用本页内容覆盖。冲突未处理前，页面阻止任务切换；任务切换前，页面先等待当前自动保存结束，避免一个任务的保存结果写入另一个任务的页面状态。

## 3. 并发与幂等

- 表单设计稿和答卷保存使用修订号；更新语句同时检查 `expectedRevision`。
- 发布请求携带 `clientRequestId`。同一人员重复发送相同标识时，服务返回已创建任务，不重复发放。
- 同一任务和人员由数据库唯一约束保证只有一份当前答卷。
- 定时检查每分钟把到时任务转为开放，把到期任务转为关闭；请求处理仍按服务器当前时间再次判断，避免定时检查延迟造成越界写入。

## 4. 附件安全

服务只接受 PDF、PNG、JPEG、DOCX、XLSX、TXT 和 CSV。服务校验扩展名、浏览器上报类型和文件头，使用随机存储名，并把正文保存在静态目录之外。生产环境没有病毒扫描程序时，服务禁用附件上传。

下载接口在每次请求时重新校验本人答卷或表单归属部门。响应使用下载方式返回文件，不允许浏览器把附件作为站内脚本执行。

## 5. 限制

- 单表最多 20 个分区、200 个字段；单选择字段最多 100 个选项。
- 单附件默认不超过 20 MB；单附件字段最多 5 个文件；单任务附件默认不超过 2 GB。
- 统计由服务读取单任务答卷后计算，适用范围为单任务 500 人以内。
- 主表字段统计按答卷份数计数；明细字段统计按实际明细行中的已填写项计数。
- Excel 的“答卷明细”工作表保存主表字段；每张明细表生成独立工作表，并带出工号、姓名、部门、答卷状态和明细行号。
