# 信息表收集服务需求说明

## 1. 建设目标

部门设计者通过 4000 设计可重复使用的信息表，并向内部人员发布一次性收集任务。填报人通过 4001 保存草稿并提交本人答卷。信息收集管理员和归属部门设计者查看完成情况、答卷和导出文件。

完成标准：系统能够证明谁发布了哪个表单版本、任务分配给谁、谁在何时提交了哪一版答卷，以及谁查看或导出了结果。

## 2. 用户与职责

| 用户 | 主要动作 | 数据范围 |
|---|---|---|
| 信息收集管理员 | 授权设计者，管理所有表单、任务、答卷和导出 | 全部信息收集数据 |
| 部门设计者 | 设计本部门表单，向任意部门或人员发布任务，查看本部门任务结果 | 本部门创建的数据 |
| 填报人 | 查看本人任务，保存、提交和截止前修改本人答卷 | 本人被分配的任务和答卷 |
| 系统 | 校验身份、权限、任务时间、表单结构、答卷和并发版本，保存审计记录 | 按当前请求处理 |

## 3. 业务流程

1. 信息收集管理员显式授予人员后台角色和部门范围。
2. 部门设计者创建表单，配置分区、字段、选项和校验条件。
3. 部门设计者选择开始时间、截止时间、部门和人员。系统预检查账号状态。
4. 部门设计者发布任务。系统固化表单版本和可填报人员快照。
5. 填报人在任务开放期间保存草稿并提交。系统保留每次正式提交快照。
6. 部门设计者查看完成情况和字段统计，并下载 Excel 或附件包。
7. 任务到期、被关闭或取消后，系统锁定填报入口并保留历史数据。

## 4. 范围

首期支持短文本、长文本、整数、小数、日期、日期时间、单选、多选、是/否、人员、部门和附件。一个表单可以包含多个主表分区和多个独立明细表。4001 在桌面端按“字段为列、记录为行”的网格展示明细表；填报人可以逐格录入，也可以从本地 Excel 复制连续单元格后直接粘贴，不需要上传或导入 Excel 文件。填报人还可以新增、复制、删除和排序明细行。每张明细表最多 100 行，设计者可以配置最少和最多行数。附件字段当前只能放在主表中。

首期不支持匿名填报、审核退回、消息通知和条件跳转。系统允许永久删除从未发布且没有版本和任务记录的设计稿；已有发布历史的表单、任务、答卷和附件不得物理删除。

首期只用于普通内部信息，不收集身份证号、银行卡、健康信息等敏感个人信息。

## 5. 验收条件

- 非目标人员无法读取任务；填报人无法读取他人答卷。
- 部门设计者无法管理其他部门创建的表单，但可以向其他部门发布任务。
- 发布后的表单版本、人员范围和历次提交不可被后续设计稿修改。
- 并发保存使用 `expectedRevision`；版本不一致时返回 `409 REVISION_CONFLICT`。
- 4001 收到 `409 REVISION_CONFLICT` 后保留本页内容并读取服务器最新修订。填报人明确选择采用服务器内容，或者在服务器答卷仍为开放草稿时选择保留本页内容并重新保存。冲突未处理前，页面不得重新打开或切换任务，不得自动覆盖任一版本。
- 4001 桌面端使用紧凑表格工作台：左侧窄栏展示任务，右侧答卷铺满剩余空间；任务状态、保存修订和提交操作集中在顶部或底部工具栏。明细表保持紧凑行高、固定表头、固定序号列和表内横向滚动。
- 500 人范围展开、统计和 Excel 导出结果一致。
- 服务重启后，会话、任务、草稿和答卷仍从 MySQL 恢复。
- 旧表单未声明分区类型时，系统按主表分区处理；旧任务和旧答卷继续使用原有字段结构。
- Excel 导出保留每名填报人的主表一行，并为每张明细表生成独立工作表和明细行。
- 填报人从 Excel 粘贴矩形区域时，页面以当前单元格为左上角填入数据并自动补足明细行。页面先检查整块数据的行列范围、字段类型和字段校验规则；任一单元格不符合要求时，本次粘贴全部不生效，并显示 Excel 相对行列及目标字段。检查通过后，页面允许撤销最近一次粘贴并自动保存服务器草稿。
