## 二、逐域问题诊断

### 🔴 研发域（PLM → PDM → CAPP → ERP）

**文档写的：**
> PLM → PDM → CAPP / ERP-PP，传递 EBOM、三维模型、更改单

**实际执行时会卡在哪里：**

#### 问题1：PLM"暂定供应商"是最大的地雷
整个研发域的数据源头是 PLM，但供应商未定。这意味着：
- EBOM 的数据结构未知
- 与 PDM 的接口协议未知
- ECO 变更单的字段定义未知
- **其他所有系统的接口设计都无法锁定**

> ⚠️ **建议：PLM 选型必须先于其他系统接口设计冻结，否则后续接口全部返工**

#### 问题2：EBOM → MBOM 的转换逻辑完全缺失

文档里 PDM 同时向 CAPP 和 ERP-PP 传数据，但没有说清楚：

```
EBOM（PLM/PDM中）
  ├── 虚拟件（装配辅助节点，ERP不需要）
  ├── 设计替代料（ERP需要展开成采购BOM）
  ├── 原材料（含MBD中的材料牌号、规格）
  └── 外购件（含技术规格，驱动采购）
         ↓ 谁来做转换？转换规则是什么？
MBOM（ERP-PP / MES中）
  ├── 工序分工结构（与工艺路线绑定）
  ├── 定额数量（含损耗率）
  └── 替代料策略（ERP的替代BOM）
```

**这个转换逻辑没有定义，PDM→ERP-PP 这条线就是空的。**

#### 问题3：ECO 变更流程是断的

文档 7.5 节写了 OA 负责 ECO 审批，但流程是：

```
现状描述（文档）：
PLM 发起 ECO → OA 审批 → PDM 状态更新

实际需要但缺失的：
PLM 发起 ECO
  ↓
OA 审批（工程/工艺/质量/采购 多部门会签）
  ↓
PDM 发布新版 EBOM
  ↓ ← 这一步文档完全没有
ERP-PP 的 MBOM 如何处理？
  ├── 新版本从哪个生产订单开始生效？
  ├── 在制品按新BOM还是旧BOM完工？
  └── 旧料库存如何处置？（ERP-MM）
  ↓ ← 这一步也没有
MES 的工艺路线如何更新？
  └── 已下发的工单是否需要撤回重发？
```

### 🟡 OA 域（华天动力横向集成）

#### 问题9：OA 是"审批触发器"还是"数据中台"？边界模糊

文档里 OA 做了很多事：
- 费用报销 → 自动生成财务凭证（ERP-FI）
- 采购申请审批 → ERP-MM 生成采购订单
- ECO 审批 → PDM 状态更新

**这意味着 OA 需要直接写 ERP 和 PDM 的业务数据，这是高风险集成。**

需要明确：

```
方案A（推荐）：OA 只传审批结果（审批通过/拒绝 + 审批人 + 时间戳）
              ERP/PDM 收到结果后，自己执行业务动作
              → OA 是"信号源"，业务系统是"执行者"

方案B（高风险）：OA 直接调用 ERP API 创建凭证/订单
              → OA 与 ERP 深度耦合，ERP 升级时 OA 接口全部失效
```

#### 问题10：单点登录（SSO）的技术方案未定义

文档写"OA 提供单点登录统一入口"，但：
- 协议是什么？SAML 2.0 / OAuth 2.0 / CAS？
- 用友 U8 的 SSO 支持能力如何？（U8 老版本对 SSO 支持有限）
- 北京虎蜥 MES 支持哪种 SSO 协议？
- 账号同步：HR 系统新增员工 → OA → 其他系统账号自动创建，这个流程有吗？

## 三、执行化改造路线图

### 第一步：补充主数据规范（最优先，阻塞其他一切）

```
需要产出的文档：
□ 物料编码规范（编码规则 + 分类体系 + 各系统映射）
□ 组织架构统一方案（以哪个系统为主，其他系统如何同步）
□ 主数据黄金源定义表（每类数据 → 唯一负责系统）
```

### 第二步：锁定 PLM 供应商

在 PLM 供应商确定前，以下工作无法推进：
- EBOM 数据结构定义
- PDM 接口设计
- ECO 变更流程详细设计

### 第三步：逐条接口设计（每条集成线需要一张接口卡）

每条集成线需要定义：

| 字段 | 示例（ERP-PP → MES） |
|------|---------------------|
| 接口名称 | 生产订单下发 |
| 触发时机 | ERP 生产订单状态变为"已下达" |
| 传输协议 | REST API / MQ |
| 同步方式 | 异步消息队列（RabbitMQ） |
| 数据格式 | JSON，字段清单见附录 |
| 幂等设计 | 以生产订单号为幂等键 |
| 失败处理 | 重试3次，超时告警，人工干预队列 |
| 反向确认 | MES 接收成功后回写 ERP 接口状态 |

### 第四步：定义集成中间件方案

当前文档完全没提中间件，需要决策：

```
选项A：点对点（短期快，长期是灾难）
  适合：系统少、接口少、预算紧

选项B：用友 U8 集成平台（如有）
  适合：以 ERP 为核心的集成场景

选项C：独立 ESB / 消息中间件
  适合：系统多、接口复杂、长期维护
  推荐：Apache Kafka（高频IoT数据） + REST API（业务数据）
```

### 第五步：制定上线顺序

建议顺序（基于依赖关系）：

```
Phase 1：主数据平台 + 组织架构统一
Phase 2：ERP（用友U8）基础模块上线
Phase 3：OA（华天动力）+ SSO 打通
Phase 4：PLM + PDM（供应商确定后）
Phase 5：CAPP + MBOM 转换
Phase 6：MES（北京虎蜥）+ ERP 集成
Phase 7：WMS + SCIM
Phase 8：IoT + 智慧能源
Phase 9：全链路联调 + 数据底座汇聚
```
