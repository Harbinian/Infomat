## 二、格式与命名观察

### VSD（108 个）
- **集成研发风格**：父目录形如 `12.1.5概念定义阶段设计-王健1009`，含 `流程编号 + 流程名 + 责任人 + 月日`
- **集成制造风格**：文件名形如 `信息流图--集成制造业务域-14.7.1工装工具策划.vsd`，含 `流程编号 + 流程名`（无责任人）
- **市场营销风格**：形如 `信息流图-项目管理业务域-市场推广与开发-11.1.1 市场推广与开发策划.vsd`
- **多版本现象（已去重）**：`12.1.5 概念定义阶段设计` 原本有 3 个 VSD（10/09 信息流图、10/09 流程图、10/21 信息流图），按"按类型分组，保留组内最新"规则：保留 10/21 信息流图 + 10/09 流程图，删除 10/09 信息流图。脚本 `dedupe-vsd.cjs`
- **命名不一致**：例 `12.1.7详细设计阶段信息流图`（文件夹）vs `详细定义阶段设计实现信息流图20250821.vsd`（文件名）——同一流程两种叫法
- **子目录过深**：集成研发子目录有 3 层（业务域/版本/责任人+流程名），而集成制造只有 2 层

### XLSX（8 个）
- **两种格式**：
  - 15 列 A 格式（集成研发、市场营销）
  - 30 列 B 格式（集成制造各子表，含子流程、SAP 模块、权威数据源双栏等）
- **数据从第 6 行起**（1-3 行是说明，4 行表头，5 行注释）
- **数据质量参差**：
  - 部分行的"操作"列含 `[object Object]`（公式/超链接）
  - "对比业务表名称"列也有 `[object Object]`，需手工核
  - 部分行的"表责任部门"列填了表号（`FM1305-31`）而非部门名（数据录入不规范）
  - 433 行"核查结果"为空（未审）、724 行已 OK

## 五、发现的数据质量问题

1. **VSD 命名不一致**：
   - 同流程不同叫法：`12.1.7详细设计阶段信息流图`（文件夹）vs `详细定义阶段设计实现信息流图`（文件名）
   - 同流程多版本：`12.1.5 概念定义阶段设计` 有 3 个 VSD（10/09、10/10、10/21）
2. **XLSX 录入不规范**：
   - `[object Object]` 残留（公式/超链接未渲染）
   - "表责任部门"列混入表号（`FM1305-31` 等）
   - 433 行核查结果为空
3. **集成研发/集成制造流程编号体系**：
   - 集成研发 12.1.x / 12.2.x
   - 集成制造 14.1-14.9
   - 市场营销 11.1.x
   - 业务域号是"经营"过程分配的离散编号（11/12/14），未严格连续
