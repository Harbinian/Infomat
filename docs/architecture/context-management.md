# Infomat Codex 上下文管理说明

> 状态：当前技术维护说明
> 范围：指令入口、按需文档、项目字节预算及历史材料使用方式；不提供业务治理依据。

## 1. 目标

当前指令提供稳定边界，详细说明按任务读取。每类规则保持明确的承载位置，避免重复正文、历史流水账和应用细节占满入口。普通只读和局部修改按根任务路由选择所需内容。

业务要求依据当前用户决定、指定原始材料和业务确认；实现、兼容及运行事实依据相应技术证据。历史资料和代码均不能单独确定业务要求。

## 3. 指令发现与项目预算

官方文档说明：Codex 先读取用户级指令，再沿项目根到当前工作目录查找；每层按 `AGENTS.override.md`、`AGENTS.md` 和配置中的候补文件名选择至多一个文件。更深目录的指令在合并后出现。非空指令受 `project_doc_max_bytes` 限制，默认上限为 32 KiB。详见 [AGENTS.md 官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md) 和 [配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。

本仓库检查器采用以下项目预算，实际值由 [check-codex-context.mjs](../../scripts/check-codex-context.mjs) 的 `LIMITS` 维护：

| 检查对象 | 上限 |
|---|---:|
| 根 AGENTS.md | 6,144 UTF-8 字节 |
| 3001 局部 AGENTS.md | 8,192 UTF-8 字节 |
| 任一已登记“根 → 当前目录”项目指令链 | 16,384 UTF-8 字节 |

这些数值是仓库静态检查门槛，不等于全部运行上下文的大小。检查器不计算用户级指令、宿主注入内容或聊天历史，也不证明客户端实际加载了哪些文件。保留现有预算，先整理重复和职责混合，不通过调高上限掩盖问题。

## 4. 路由与注册

- 根 AGENTS.md 的 `codex-context-routing:authoritative` 标记和“任务路由”维护任务类型到文档的对应关系；其他位置链接该入口，不另建固定全量读取顺序。
- DIRECTORY_OWNERSHIP.md 的 `codex-context-registry` 块是局部 AGENTS.md 的唯一清单；新增或删除入口只维护该清单及受影响引用。
- 局部入口指向主责目录的当前说明；历史章节和副本不作为当前执行入口。
- 目标实例版本、健康、开关、数据库和 Git 状态在具体任务中实时核对；配置和当前说明不替代运行证据。

## 5. 维护与验证

文档维护的方法由 [CODEX.md](../../CODEX.md) 维护：确定当前正文，更新受影响内容，核对状态、范围和引用，保留有效要求及必要历史。合并重复内容时核对主体、条件及例外；相似度只提供线索，不能自动决定删除。

修改指令入口、路由、注册或预算后运行：

```powershell
npm run test:codex-context
```

该入口执行夹具测试和仓库只读检查。夹具写系统临时目录；不修改仓库文件、不连接数据库、不启动服务。以下问题阻断：

- 根入口、3001 局部入口或已登记项目链超过预算；
- 局部入口未登记，或登记路径不存在；
- 根入口出现检查器所列的应用详细章节或固定实现标识；
- 权威路由或注册标记重复或缺失。

完全重复及模糊相似内容只提供提示，按实际语义处理。文件和字节检查通过不代表业务验收、实际提示加载或模型行为评测通过。

只有任务涉及实际加载、优先级或截断疑点时，才核对客户端诊断。诊断可能含私有上下文，仅输出必要的脱敏信息。模型比较、技能回归和应用检查按任务需要选择，不作为普通文档整理的固定门槛。

历史与当前入口或实时证据冲突时，分别核对业务确认和技术事实。长期记忆更新仍需明确授权，不能为了缩短上下文删除责任、迁移、异常或验收边界。
