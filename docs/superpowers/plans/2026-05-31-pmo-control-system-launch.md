# PMO 管控体系 V1 启用 — 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 WBS 评审定稿 → Project 导入验证 → 基线设置固化，使 PMO 数字化底座项目计划管控体系具备基础可用状态。

**Architecture:** 三个 Phase 严格串行。Phase 1 产出管理版和执行版 CSV，Phase 2 将管理版导入 Project 并验证，Phase 3 设置基线并固化规范文档。每 Phase 结尾有验收关卡，前一 Phase 验收通过才进入下一 Phase。

**Tech Stack:** Office Project 2016+, CSV (UTF-8 BOM), Markdown

**参考文档:** `docs/superpowers/specs/2026-05-31-pmo-control-system-launch-design.md`（操作手册）
**数据源:** `pmo/信息化项目_资源池简化版_UTF8_BOM.csv`

### Task 1.2：逐主线评审执行

**说明：** 此任务为会议操作，需评审主持人、各主线负责人、数据合规审核员三方参与。按 8 条规则逐行检查。

- [ ] **Step 1：第一场评审会（主线 1-4，约 70 分钟）**

参会人：评审主持人 + 主线 1-4 负责人 + 数据合规审核员

议程（按顺序过）：

2. **主线 2：招采合同与供应商管理**（WBS 2.x，CSV 行 25-73）— 重点检查 R1（资源池）、R2（供应商字段），这条主线供应商条目多。
3. **主线 3：数据标准与主数据治理**（WBS 3.x，CSV 行 74-110）— 重点检查 R4（前置任务，这条主线依赖链长）。

- [ ] **Step 2：第二场评审会（主线 5-7，约 60 分钟）**

参会人：评审主持人 + 主线 5-7 负责人 + 数据合规审核员

议程：
1. **主线 5：基础设施与 AI 底座**（WBS 5.x，CSV 行 135-170）— 这条主线子任务多（36 条），重点检查 R3（协作资源不进资源池）、R8（字段口径）。

3. **主线 10：AI 应用深化、驾驶舱与总体验收**（WBS 10.x，CSV 行 301-314）— 重点检查 R6（覆盖关键里程碑）。

### Task 1.3：执行修改与复核

- [ ] **Step 1：分发修改任务**

将评审记录中"需修改"和"待确认"的条目按负责人分发。修改直接在 CSV 的 `评审意见` 列中追加进度：
- 修改完成行：末尾追加 `[已修改 YYYY-MM-DD]`
- 待确认行：末尾追加 `[待确认: 由XXX确认 YYYY-MM-DD]`

- [ ] **Step 2：负责人执行修改**

各主线负责人在 CSV 中修改不合规行。修改时注意：

- 改 `前置任务` 时，确认新的 CSV 行号正确

- 修改是否完整解决了规则问题
- 修改是否引入了新问题
- 通过的行改为 `[已确认 YYYY-MM-DD]`
- 不通过的行改回 `[需重新修改: 原因]`

### Task 1.4：管理版与执行版拆分

- [ ] **Step 1：复制源文件**

```bash
cp "pmo/信息化项目_资源池简化版_UTF8_BOM.csv" "pmo/信息化项目_资源池简化版_V2_执行版.csv"
cp "pmo/信息化项目_资源池简化版_UTF8_BOM.csv" "pmo/信息化项目_资源池简化版_V2_管理版.csv"
```

- [ ] **Step 2：整理执行版**

在 `信息化项目_资源池简化版_V2_执行版.csv` 中：
1. 对所有保留在管理版的行（WBS 一级/二级摘要、里程碑、每条主线 3-5 个关键三级任务），在 `备注` 列标记 `[M]`（Management）
2. 对所有仅在执行版的三级任务，在 `备注` 列标记 `[E]`（Execution）
3. 清理 `评审意见` 列（评审过程记录在 `WBS评审记录_V1.md` 中，CSV 中可清空该列内容，仅保留 `[已确认 YYYY-MM-DD]` 标记的行）

- [ ] **Step 3：整理管理版**

在 `信息化项目_资源池简化版_V2_管理版.csv` 中：
1. 保留所有 WBS 一级和二级摘要任务（即 WBS 编号形如 `N` 和 `N.M` 的行）
2. 保留所有里程碑行（`任务类型` = 里程碑）
3. 每条主线保留 3-5 个关键三级任务（`任务类型` = 高风险 + 长工期 + 关键路径依赖）
4. 删除其余三级任务行
5. 计数：总行数应在 80-120 之间。不到 80 则补回关键任务，超过 120 则再精简三级任务
6. 清理 `评审意见` 列

- [ ] **Step 4：行数校验**

```bash
# 统计管理版行数（减去表头 1 行）
wc -l "pmo/信息化项目_资源池简化版_V2_管理版.csv"
```

确认输出在 82-121 之间（含表头）。不在范围内则回到 Step 3 调整。

- [ ] **Step 5：一致性校验**

检查管理版和执行版之间无矛盾：
- 管理版中的每一行在执行版中都存在
- 两个文件共同行的字段值一致（任务名称、工期、日期、资源）
- 两个文件的表头结构完全一致

- [ ] **Step 6：Commit**

```bash
git add "pmo/信息化项目_资源池简化版_V2_管理版.csv" "pmo/信息化项目_资源池简化版_V2_执行版.csv"
git commit -m "feat: split WBS into management (80-120 lines) and execution (~300 lines) editions"
```

**实际操作**：跳过在 CSV 中插入注释行。改为在 `WBS评审记录_V1.md` 顶部追加版本信息块：

### Task 2.2：层级结构与前置任务修复

- [ ] **Step 1：检查摘要任务层级**

1. 在 Project 中切换到 `任务 → 甘特图` 视图
2. 展开所有摘要任务（WBS 1-10 一级任务）
3. 逐条检查：每个一级摘要任务下的子任务是否都正确缩进
4. 未正确缩进的：选中该行，点工具栏 `→`（降级）或 `←`（升级）按钮调整

- [ ] **Step 2：建立 WBS 二级摘要层级**

CSV 导入后，二级 WBS（如 2.1, 2.2）可能不会被自动识别为摘要任务。需要手动处理：

1. 对于每个 WBS 二级编号组（如 2.1.1 到 2.1.8），将 2.1.x 行降级为 2.1 的子任务
2. 对 2.1、2.2 等二级任务，将它们降级为 WBS 1-10 一级任务下的子摘要
3. 对三级任务（如 4.1, 4.2），将它们降级为对应二级下的子任务

正确层级应为：
```
1 项目启动与总体蓝图（一级摘要）
  1.1 项目启动会准备（二级任务）
  1.2 项目启动会召开（二级里程碑）
  1.3 项目治理机制建立（二级任务）
  ...
```

- [ ] **Step 3：修复前置任务**

CSV 中 `前置任务` 用 CSV 行号（如 `11,12`），导入后 Project 重新分配了行 ID，前置任务可能断链。

1. 在甘特图视图中，定位到 `前置任务` 列
2. 逐行检查：值为 `#N/A` 或空白但 CSV 源中该行有前置依赖的 → 断链
3. 对断链的任务：根据 CSV 中的前置任务行号，找到对应任务名称，在 Project 中手动重新设置前置
   - 双击任务 → `前置任务` 选项卡 → 从下拉列表中选择正确的任务
4. 优先修复摘要任务和里程碑的前置依赖（它们影响最大）
5. 修复完成后，检查甘特图中任务条之间的连线是否完整
