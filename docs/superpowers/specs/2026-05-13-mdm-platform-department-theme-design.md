# MDMplatform 部门主题色设计

**日期**: 2026-05-13  
**选择方向**: B. 部门色主导  
**范围**: 优化 MDMplatform 前端配色，让每个部门拥有稳定主题色，重点体现在统计看板 dashboard。

## 背景

MDMplatform 目前已完成红黑品牌化配色：顶部导航、主按钮、焦点态和图表主色均使用 logo 驱动的红黑体系。新的诉求是让各部门在平台中拥有可识别的主题色，尤其在 dashboard 中能快速看出部门分布、责任归属和跨部门关系。

现有前端是单文件应用 `mdm-platform/public/index.html`，dashboard 的核心入口是 `renderDashboard()`，当前“各部门流程数”柱状图使用单一品牌红，不能区分部门。

## 设计目标

1. 每个部门拥有稳定、可复用的主题色。
2. dashboard 中部门维度的图表、指标和标识优先使用部门色。
3. 保留现有红黑品牌顶栏和主操作风格，不把整个平台改成无品牌的彩色界面。
4. 明确颜色语义边界：部门色表达“谁”，状态色表达“事情处于什么状态”。
5. 第一版尽量不改数据库，降低实现和迁移风险。

## 非目标

1. 不在第一版做后台可配置主题色。
2. 不改登录页、后端权限、审批流程或数据模型。
3. 不把所有按钮、标签、状态都替换成部门色。
4. 不引入新的 UI 框架或构建工具。

## 颜色语义边界

部门色用于表达部门身份，包括：

- dashboard 中的部门柱状图、部门占比环图、部门图例。
- 部门名称旁的色点或小徽标。
- 指标卡或表格行的彩色顶边、左边框、浅色背景。
- 冲突详情中的部门 A/B 对比区头部或边框。

状态色继续表达业务状态，包括：

- 成功、警告、错误、待办、冲突严重度。
- 审批状态标签。
- 主操作按钮、危险按钮、输入校验。

品牌色继续表达平台身份和主要动作，包括：

- 顶部导航、激活 tab、主按钮、焦点态。
- 信息化项目组或数据管理部门本身的主题色。

## Dashboard 设计

### 顶部指标卡

dashboard 顶部 4 个指标卡保持紧凑布局，但增加部门色主导的视觉层：

- 指标卡使用彩色顶边或左边框，避免大面积纯色背景。
- 数字可按指标关联的主部门或最高占比部门着色。
- 待办、冲突等状态型指标仍以状态色优先。

### 各部门流程数

当前柱状图从单一红色改为每个部门一色：

- 按流程数量从高到低排序。
- x 轴显示部门简称，tooltip 显示部门全称、流程数和占比。
- 柱色来自 `departmentThemeMap`。
- 无匹配部门时使用“未归属”灰色 `#9ca3af`。

### 部门占比

将 dashboard 右侧图表改为更贴合 B 方案的部门占比视图，或在审批状态分布下方增加部门占比摘要：

- 环图颜色与部门柱状图保持一致。
- 图例显示部门名、色点、数量。
- 审批状态分布如保留，继续使用品牌红黑与灰阶，不混用部门色。

### 部门图例

dashboard 增加部门色图例：

- 常驻显示当前出现过的部门。
- 图例颜色与柱状图、环图一致。
- 部门过多时换行，不横向撑破页面。

## 其他页面轻量延展

第一版重点在 dashboard，但可以做少量一致性延展：

- “我的报送”列表中，部门列显示色点 + 部门名。
- “待办收到”中，来源部门和接收部门显示对应色点。
- “冲突管理”列表中，部门 A/B 使用不同色点。
- 详情页“部门 A / 部门 B”对比卡片使用部门色边框。

这些延展不改变表格结构和业务逻辑，只增加视觉标识。

## 技术设计

### 前端工具函数

在 `mdm-platform/public/index.html` 增加以下前端概念：

- `departmentThemes`: code/name 到颜色的静态映射。
- `fallbackDepartmentColors`: 未知部门备用色数组。
- `getDepartmentTheme(department)`: 根据 code、name 或字符串返回颜色。
- `departmentDot(name, code)`: 返回色点 + 部门名的 HTML。
- `departmentTint(color)`: 生成浅色背景或直接使用固定浅色 token。

### 数据来源

优先使用已有数据：

- `state.departments` 来获得部门 code/name。
- `state.mappings[].owner_dept_name` 用于当前 dashboard 统计。
- 如果 mapping 接口未来返回 `owner_dept_code`，主题匹配优先使用 code。

第一版不要求修改 API；如果没有 code，就按中文名匹配。

### ECharts

`renderDashboard()` 中构建部门统计时，将数据结构从 `{ name: count }` 升级为数组：

- `name`
- `code`，如可获得
- `count`
- `color`

柱状图 `series.data` 使用对象形式 `{ value, itemStyle: { color } }`。环图 `data` 使用 `{ name, value, itemStyle: { color } }`。这样颜色随部门绑定，而不是依赖 ECharts 全局 color 顺序。

### 响应式

现有 900px 断点继续沿用。移动端要求：

- 图例允许换行。
- dashboard 两列图表降为单列。
- 部门简称优先显示，tooltip 显示全称。

## 测试与验收

### 自动验证

- 运行 `npm run test:frontend`。
- 运行 `npm run smoke`。

### 手动验证

1. 登录 `ADMIN001 / admin123` 后打开统计看板。
2. 检查“各部门流程数”每个部门使用不同颜色。
3. 检查部门占比和柱状图颜色一致。
4. 检查品牌红黑顶栏、tab、主按钮仍然保留。
5. 检查状态标签仍使用状态色，不被部门色覆盖。
6. 检查 375px 移动宽度下图例、标签、图表不重叠。

### 成功标准

- dashboard 第一眼能识别部门分布。
- 部门色在不同图表、列表、详情中保持一致。
- 状态色和部门色没有混淆。
- 不需要数据库迁移即可上线第一版。

## 后续增强

如果第一版效果稳定，可以在后续版本增加：

- `departments.theme_color` 数据库字段。
- 组织管理页中的主题色选择器。
- Excel 导出或汇报图中的部门色复用。
- 为部门色做对比度检查，避免用户配置过浅颜色。
