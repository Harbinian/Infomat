## 一、背景与决策上下文

**Q7 决策问题：是否建设数据中台/集成总线？**

| 选项 | 说明 |
|------|------|
| 选项A | 点对点集成，由各实施商自行负责接口 |
| 选项B | 建设统一集成总线（ESB/消息中间件） |
| 选项C | 建设完整数据中台（含MDM主数据管理） |

**本设计针对选项C（完整数据中台），结合昌兴复材航空复材制造场景下的适航追溯需求。**

---

## 二、建设策略

### 2.1 三阶段渐进方案

| 策略 | 说明 |
|------|------|
| **技术并行** | 集成总线与MDM平台在技术上可并行建设，互不依赖 |
| **业务分期** | 总线比MDM早启动3个月，等MDM数据Ready时总线已可分发 |
| **风险可控** | 每阶段有明确产出，验证后再投入下一阶段 |

### 2.2 团队能力假设

| 维度 | 假设 |
|------|------|
| IT团队规模 | 2-3人，具备基础Java/Python开发能力 |
| AI辅助 | 使用AI辅助编程（Copilot或国产工具），提升开发效率 |
| 外部支持 | 关键节点（架构设计、新技术培训）依赖外部顾问 |

## 四、Phase 1 集成总线技术路径

### 4.1 技术选型

| 组件 | 推荐方案 | 原因 |
|------|---------|------|
| **消息中间件** | Apache Kafka | 高吞吐、持久化、消费者组、消费追踪（适合追溯链） |
| **注册中心/配置** | Nacos | 轻量、无缝兼容Dubbo生态，运维简单 |
| **API网关** | Spring Cloud Gateway | 可用AI辅助开发，国产定制方便 |
| **消息监控** | Kafka Eagle / Kafka-ui | 开源免费，界面友好 |

### 4.2 Phase 1 接入顺序

| 时间 | 接入系统 | 说明 |
|------|---------|------|
| Month 1-2 | ERP（用友U8） | 最熟悉，先跑通 |
| Month 3-4 | MES（北京虎蜥） | 制造数据核心 |
| Month 5-6 | OA（华天动力） | 审批流对接 |
| Month 5-6 | PLM（候选方） | 根据选型结果 |
| Month 5-6 | PDM / CAPP / WMS / SCIM | 根据实施进度 |

### 4.3 接口数量变化

| 方案 | 接口数 | 维护复杂度 |
|------|--------|-----------|
| 方案A（点对点） | 28条 | N×(N-1)，任一系统升级影响多条 |
| **方案B（总线）** | **8条** | **N×1=8条**，只改中台适配器 |

## 五、Phase 2 MDM平台技术路径

### 5.1 技术选型

| 组件 | 推荐方案 | 原因 |
|------|---------|------|
| **MDM平台** | Apache Atlas 或 DataSphere | 开源免费，支持元数据血缘、标签分类 |
| **数据血缘** | Apache Atlas | 适航追溯核心依赖，能追踪数据从哪来到哪去 |
| **数据质量** | Great Expectations（Python）| 可AI辅助编写质量规则 |

### 5.2 MDM四大核心主数据

| 主数据 | 黄金源 | 创建入口 | 审批流 |
|--------|--------|---------|--------|
| 物料 | PLM/ERP-MM | ERP-MM | 工程技术部 |
| 组织/人员 | OA | OA | 行政人事 |
| 供应商 | SCIM/ERP-MM | ERP-MM | 物资保障部 |
| 物料分类 | PLM | PLM | 工程技术部 |

## 六、Phase 3 追溯数据湖技术路径

### 6.1 技术选型

| 组件 | 推荐方案 | 原因 |
|------|---------|------|
| **存储** | ClickHouse + MinIO | 列存高效查询，冷热分离，国产化支持 |
| **追溯链** | Apache Atlas（扩展）| 跨系统血缘追踪，复用Phase 2资产 |
| **文件归档** | PDM + 对象存储 | NDT报告PDF/图像存MinIO，指纹存档 |
| **展示** | 自研追溯看板 | 业务关系网络图同款前端，扩展追溯视图 |

### 6.2 追溯数据写入时序

```
零件序列号 S/N 登记（MES）
    ↓
预浸料批次（ERP-MM）→ MES消费 Kafka 批次事件
    ↓
固化参数曲线（IoT → MES → Kafka）
    ↓
NDT报告（质量系统 → PDM归档 → MinIO）
    ↓
检验记录（质量系统 → ClickHouse）
    ↓
符合性声明（PDM → OA审批 → 归档）
```

## 八、风险与对策

| 风险 | 概率 | 影响 | 对策 |
|------|------|------|------|
| Kafka/开源产品运维复杂度高 | 中 | 高 | Phase 1先上云托管Kafka（阿里云/腾讯云），稳定后再迁移自建 |
| PLM供应商未定影响接口设计 | 高 | 高 | 先做已知系统（ERP/MES/OA），PLM接口预埋，供应商选定后对接 |
| MDM数据梳理各部门协调困难 | 中 | 中 | 项目管理部牵头，总经理背书，纳入部门KPI |
| 适航追溯法规变化 | 低 | 高 | 追溯设计基于行业标准，模块化，可快速适配新要求 |
| AI辅助代码质量不可控 | 中 | 中 | 建立Code Review机制，关键业务逻辑人工复核 |

## 十、Q7决策建议措辞

> **建议采用完整数据中台方案（方案B/C），分三阶段实施：**
>
> - **第一阶段（Year 1）**：集成总线建设，8系统接入
> - **第二阶段（Year 2）**：MDM主数据平台，数据同源治理
> - **第三阶段（Year 3）**：追溯数据湖，适航序列号级追溯
>
> **总预算约99万**（纯外部实施服务及培训，软硬件及内部人员不计）
>
> **资金来源**：分期年度IT预算
