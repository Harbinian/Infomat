# PMO 管控体系 V1 启用 — 设计说明

## 背景

PMO 项目计划管控体系建设方案已通过评审。当前需在 1-2 周内完成 WBS 评审 → Project 导入 → 基线设置三个步骤，使管控体系具备基础可用状态。H5 甘特图看板已在并行开发中。

## 目标

完成 PMO 数字化底座项目计划管控体系从 WBS 定稿到基线固化的端到端启用。

## 三阶段设计

### Phase 1：WBS 评审与定稿（3-4 天）

**输入**：`pmo/信息化项目_资源池简化版_UTF8_BOM.csv`（V1，约 320 行，10 条主线）

**评审方**：信息化项目管理工作室

**评审维度**（依据 PMO 建设方案第 8 节核心规则）：

| 评审项 | 标准 |
|---|---|
| 行数控制 | 管理版 80-120 行，当前约 320 行需拆分为管理版+执行版 |
| 资源池 | 只保留工作组级资源（信息化项目组、MDM工作组等），供应商不入池 |
| 前置任务 | 只保留关键路径依赖，去除冗余链接 |
| 里程碑 | 0 工期、阶段门、关键节点完整 |
| 风险等级 | 高/中/低判定标准一致 |
| 供应商字段 | 独立自定义字段，不进 Resource Names |

**执行步骤**：逐主线 review → 标记修改项 → 产出 V2 → 记录版本变更

**输出物**：
- `信息化项目_资源池简化版_V2.csv`（定稿）
- 评审记录（参与人、各主线结论）

---

### Phase 2：Project 导入与验证（2-3 天）

**输入**：Phase 1 定稿 CSV V2

**执行步骤**：
1. CSV 列 → Project 字段映射确认
2. 导入 Office Project
3. 四类验证：层级/日期链/里程碑/资源池
4. 发现问题 → 修正 CSV → 重新导入（迭代至通过）

**验收标准**：
- 摘要任务/子任务层级正确
- 前置任务引用无空链
- 里程碑任务（0 工期）正确标记
- Resource Names 只有工作组级资源，无供应商/人名
- 供应商信息在独立自定义字段

**输出物**：
- 可用的 `.mpp` Project 文件
- 导入问题记录（如有）

---

### Phase 3：基线设置与固化（1-2 天）

**输入**：Phase 2 验证通过的 Project 文件

**执行步骤**：
1. Project 中设置基线，固化时间/工期/资源
2. 固化视图（筛选器、分组按方案建议配置）
3. 版本记录（版本号、基线日期、基准说明）
4. 回写 CSV（从 Project 导出含基线时间列的 CSV）
5. 编写 `Project导入规范.md`（初版）

**输出物**：
- 已设基线的 `.mpp` 文件
- `信息化项目_基线版_V1.csv`
- `pmo/Project导入规范.md`（初版）

---

## 依赖关系

```
Phase 1 → Phase 2 → Phase 3（严格串行）
```

H5 看板开发与 Phase 1-3 并行，Phase 3 完成后看板可切换为基线版数据源。

## 不在本次范围内

- 风险/问题/变更台账模板制定
- 月报模板设计与月度汇报机制
