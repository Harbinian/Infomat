# PMO 管控体系 V1 启用 — 操作手册

## 0. 概述

### 0.1 本手册用途

本文档是 PMO 数字化底座项目计划管控体系的**启动操作手册**。阅读对象是信息化项目管理工作室成员。读完本文档，你可以按步骤独立完成：WBS 评审定稿 → Project 导入验证 → 基线设置固化。

### 0.2 前置条件

开始操作前需确认：

- [ ] PMO 项目计划管控体系建设方案已通过评审（已达成）
- [ ] 拥有 Office Project（2016 或更高版本，或 Project Online）可用
- [ ] 拥有 `pmo/信息化项目_资源池简化版_UTF8_BOM.csv` 的读写权限
- [ ] WBS 评审会议已预约，参与人已通知

### 0.3 三阶段概览

```
Phase 1 (3-4天)          Phase 2 (2-3天)          Phase 3 (1-2天)
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│ WBS 评审与定稿    │ ──→ │ Project 导入与验证│ ──→ │ 基线设置与固化   │
│                  │     │                  │     │                  │
│ 输入: CSV V1     │     │ 输入: CSV V2     │     │ 输入: .mpp 文件  │
│ 输出: CSV V2     │     │ 输出: .mpp 文件  │     │ 输出: 基线版CSV  │
│       + 评审记录  │     │       + 问题记录  │     │       + 导入规范  │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

**总工期 1-2 周**，三个阶段严格串行，前一阶段验收通过才能进入下一阶段。

H5 甘特图看板开发与 Phase 1-3 并行推进，Phase 3 完成后看板可切换为基线版数据源。

## 1. Phase 1 — WBS 评审与定稿（3-4 天）

### 1.1 本阶段目标

对当前 `信息化项目_资源池简化版_UTF8_BOM.csv`（约 320 行、10 条主线）进行结构化评审，按 PMO 管控体系规则修正后输出定稿版 CSV（V2）。

### 1.2 参与人

| 角色 | 职责 | 建议人选 |
|---|---|---|
| 评审主持人 | 逐主线引导评审、记录决议、催办修改 | PMO 负责人或计划管理员 |
| 主线负责人 | 对各自主线任务内容负责、回答评审质疑 | 各工作组代表 |
| 数据合规审核 | 按 8 条规则逐行核验 CSV 合规性 | 计划管理员或指定专人 |

### 1.3 评审规则速查（来自 PMO 建设方案第 7、8 节）

评审时逐行对照以下 8 条规则。任何不合规行必须标记并修正：

| 规则编号 | 规则 | 合规标准 | 不合规示例 |
|---|---|---|---|
| R1 | 资源池只保留工作组级 | `资源名称` 和 `主责资源` 列只能包含：信息化项目组、信息化项目管理工作室、MDM工作组、PLM工作组、MES工作组、ERP·OA工作组、数据质量工作组、基础设施工作组、技术架构组、变更控制组、网络工程组 | 出现人名、部门名、供应商名（如"用友U8""PLM供应商""张三"） |
| R2 | 供应商进独立字段 | `供应商` 列独立存在，不进 `资源名称` | 供应商在 `资源名称` 中以分号合并 |
| R3 | 协作资源不进资源池 | `协作资源` 列独立存在，不进 `资源名称` | 协作组在 `资源名称` 中拼合 |
| R4 | 前置任务只保留关键路径 | 每条前置依赖必须是该任务的真实硬依赖，主线上任务不逐条链接 | 同一工作组内部任务逐条链接、形成过长依赖链 |
| R5 | 里程碑为 0 工期 | `任务类型` = 里程碑 时，`工期` 必须为 0 工作日 | 里程碑有 1+ 天工期 |
| R6 | 里程碑覆盖阶段门 | 每条主线至少有一个里程碑（阶段门或关键交付节点） | 某条主线无任何里程碑 |
| R7 | 风险等级判定一致 | 高风险：核心路径、资源紧张、依赖未定；中风险：有缓冲但不确定；低风险：常规任务 | 同类任务风险等级不一致 |
| R8 | 字段口径统一 | 每列的值域统一（如"任务类型"只使用约定的枚举值） | 同概念用不同写法 |

### 1.4 操作步骤

#### 步骤 1：准备评审材料（30 分钟）

在 CSV 中新增一列 `评审意见`（放在最后一列右侧），用于记录每条任务的评审决议。另建一份 `评审记录.md`，模板如下：

```markdown
# WBS 评审记录

- 评审日期：YYYY-MM-DD
- 参与人：xxx、xxx
- 主审文件：信息化项目_资源池简化版_UTF8_BOM.csv（V1，N 行）

## 逐主线评审结论

| 序号 | 主线名称 | 行数 | 需修改 | 待确认 | 结论 | 负责人 |
|------|---------|------|--------|--------|------|--------|
| 1 | | | | | | |
| ... | | | | | | |

## 全局性问题

## 下次行动
```

#### 步骤 2：逐主线评审（建议分 2-3 场，每场 3-4 条主线）

按以下顺序逐一评审。10 条主线的 CSV 行号范围如下：

| 序号 | 主线 | WBS 编号 | CSV 行号范围 | 建议用时 |
|------|------|---------|-------------|---------|
| 1 | 项目启动与总体蓝图 | 1.x | 12-24 | 15 分钟 |
| 2 | 招采合同与供应商管理 | 2.x | 25-73 | 20 分钟 |
| 3 | 数据标准与主数据治理 | 3.x | 74-110 | 20 分钟 |
| 4 | MDM 自研平台一期 | 4.x | 111-134 | 15 分钟 |
| 5 | 基础设施与 AI 底座 | 5.x | 135-170 | 25 分钟 |
| 6 | PLM 基础深化 | 6.x | 171-191 | 20 分钟 |
| 7 | ERP/OA 补强 | 7.x | 192-207 | 15 分钟 |
| 8 | MES 建设与 QMS | 8.x | 208-280 | 30 分钟 |
| 9 | 全系统集成联调与现场推广 | 9.x | 281-300 | 15 分钟 |
| 10 | AI 应用深化、驾驶舱与总体验收 | 10.x | 301-314 | 15 分钟 |

每条主线的评审动作：

1. **主持人朗读主线摘要行的"备注"列**，确认该主线的范围边界和关键约束
2. **主线负责人逐条确认**：任务名称准确、工期合理、前置依赖正确、交付物明确
3. **数据合规审核员同时按 8 条规则逐行检查**，不合规的当场在 `评审意见` 列标记，如：`[R1] 资源名称含供应商，需剥离`
4. **逐条决议**：通过 / 需修改（指定修改内容）/ 待确认（指定由谁确认）
5. **填写评审记录表**：更新该主线的结论行

#### 步骤 3：执行修改（评审后 1-2 天）

根据 `评审意见` 列的标记，由各主线负责人分头修改：

- 修改直接在 CSV 中进行，不要新开文件
- 修改完成后在 `评审意见` 列追加 `[已修改 YYYY-MM-DD]`
- 计划管理员逐条复核，确认后改为 `[已确认 YYYY-MM-DD]`

#### 步骤 4：管理版与执行版拆分

评审和修改完成后，执行拆分：

**管理版（80-120 行）**：
- 保留所有 WBS 一级和二级摘要任务（如 1、1.1、1.2 级别的行）
- 保留所有里程碑行
- 保留每主线 3-5 个关键三级任务（高风险、长工期、关键路径上的任务）
- 其余三级任务移到执行版

**执行版（保留完整约 300 行）**：
- 保留管理版全部内容
- 保留所有被移除的三级任务
- 在备注列标注 "[E]" 表示执行版行

**操作方式**：
1. 复制定稿 CSV → 管理版（筛选后删除，保留 80-120 行）
2. 复制定稿 CSV → 执行版（保留全部，标注 [M] 管理版行）

#### 步骤 5：版本记录与封版

在 CSV 文件头部（第 1 行上方）插入版本信息行（最终导出时移除或保留在备注列）：

```csv
# 版本: V2 | 定稿日期: YYYY-MM-DD | 评审方: 信息化项目管理工作室 | 变更说明: 按8条规则逐行评审修正，拆分管理版/执行版
```

输出文件：
- `pmo/信息化项目_资源池简化版_V2_管理版.csv`（80-120 行）
- `pmo/信息化项目_资源池简化版_V2_执行版.csv`（约 300 行，含全部任务）
- `pmo/WBS评审记录_V1.md`（评审过程记录）

#### 步骤 6：Phase 1 验收

验收人（信息化项目管理工作室负责人）逐项确认：

- [ ] 8 条规则逐行复核通过，无遗漏
- [ ] 10 条主线均有里程碑覆盖
- [ ] 管理版行数在 80-120 范围内
- [ ] 执行版保留全部任务，与管理版无矛盾
- [ ] 评审记录完整，含参与人、日期、每条主线的结论
- [ ] 版本信息已记录

全部确认 → 进入 Phase 2。

## 2. Phase 2 — Project 导入与验证（2-3 天）

### 2.1 本阶段目标

将 Phase 1 产出的管理版 CSV 导入 Office Project，生成可用 `.mpp` 文件，并验证数据完整性。

### 2.2 CSV → Project 字段映射表

导入时按以下映射关系配置：

| CSV 列名 | Project 字段 | 说明 |
|---|---|---|
| `WBS` | 任务名称（不导入 WBS 列本身） | WBS 编号用于验证层级，导入后由 Project 自动生成 WBS |
| `任务名称` | 任务名称 | 直接对应 |
| `任务类型` | 标志域 / 自定义字段 | 映射到 Project 自定义字段 `Text1` |
| `工期` | 工期 | 直接对应（注意单位：工作日 vs 天） |
| `开始时间` | 开始时间 | 直接对应 |
| `完成时间` | 完成时间 | 直接对应 |
| `前置任务` | 前置任务 | 格式 "ID,ID,ID"，CSV 中用逗号分隔多个前置 |
| `主责资源` | 资源名称 | 只导入 `主责资源` 列，不导入原 `资源名称`（含组合资源） |
| `责任部门` | 自定义字段 `Text2` | — |
| `供应商` | 自定义字段 `Text3` | 关键：独立字段，不进 Resource Names |
| `审核人/审批组` | 自定义字段 `Text4` | — |
| `风险等级` | 自定义字段 `Text5` | 值域：高 / 中 / 低 |
| `里程碑` | 标志域 / 自定义字段 `Text6` | 值域：是 / 否 |
| `交付物` | 自定义字段 `Text7` | — |
| `备注` | 备注 | — |

**关键提醒**：
- `协作资源` 和 `供应商资源` 列**不导入** Project（已简化为独立字段）
- 原 `资源名称` 列**不导入**（含组合资源，直接改用 `主责资源`）
- `ID` 列**不导入**（Project 自动生成行 ID，前置任务依赖需在导入后重新关联）

### 2.3 导入操作步骤

#### 步骤 1：新建 Project 文件

1. 打开 Office Project
2. 新建空白项目
3. 设置项目信息：`项目 → 项目信息 → 开始日期` 设为 `2026-06-01`
4. 保存为 `数字化底座项目管理版_V1.mpp`

#### 步骤 2：导入 CSV

1. `文件 → 打开 → 浏览`，文件类型选 `CSV 文件`
2. 选择 `信息化项目_资源池简化版_V2_管理版.csv`
3. 在导入向导中：
   - 第一步：选 `新建映射`
   - 第二步：勾选 `将数据导入新项目`
   - 第三步：按 2.2 字段映射表逐一映射列
   - 第四步：将 `任务名称` 设为 `合并/分隔符` 的键字段
4. 点击完成，等待导入

#### 步骤 3：验证层级结构

导入后立即检查：

1. **摘要任务/子任务层级**：检查每条 WBS 一级任务（1-10）是否自动成为摘要任务，子任务是否正确缩进
2. 如有遗漏的层级关系：手动用 `→` 降级按钮调整
3. 导入后 Project 会自动分配行 ID，此前置任务中的 CSV 行号引用可能失效 — **需人工校对前置任务**（见步骤 4）

#### 步骤 4：修复前置任务

CSV 中 `前置任务` 列用 CSV 行号（如 `11,12`），导入后 Project 行 ID 重新编号，前置任务可能断链。

修复方法：
1. 在 Project 中打开 `任务 → 甘特图` 视图
2. 逐条检查每个任务的前置任务列
3. 断链的（显示为 `#N/A` 或空白但 CSV 中有值），手动重新关联
4. 优先修复摘要任务和里程碑的前置依赖

#### 步骤 5：验证清单

逐项检查，一项不合格即需修正后重新导入：

| 序号 | 验证项 | 检查方法 | 通过标准 |
|------|--------|---------|---------|
| V1 | 任务层级 | 抽查 WBS 1-10 及其子任务 | 每级缩进正确，摘要任务正确折叠 |
| V2 | 日期链 | 从最早开始任务到最晚完成任务，逐行检查无空白日期 | 所有任务有开始和完成日期（摘要任务除外） |
| V3 | 前置任务引用 | 点击每个任务，查看前置任务列 | 无 `#N/A`，无循环引用 |
| V4 | 里程碑标记 | 筛选 `里程碑 = 是` 的任务 | 均为 0 工期，甘特图中显示为菱形 |
| V5 | 资源池干净 | `资源 → 资源工作表` | 只出现工作组级资源名，无人名/供应商名/部门名 |
| V6 | 供应商字段 | 抽查含供应商的任务 | 供应商在自定义字段 Text3 中，不在资源工作表中 |
| V7 | 任务类型一致 | 筛选 `任务类型` 自定义字段 | 值域统一，无拼写错误 |
| V8 | 风险等级一致 | 筛选 `风险等级` 自定义字段 | 值域为 高/中/低 |
| V9 | 工期单位统一 | 抽查非里程碑任务 | 单位统一为工作日 |
| V10 | 甘特图可读 | 缩放至月视图浏览全图 | 任务条正确连接，无悬空任务 |

#### 步骤 6：问题修正迭代

验证发现的任何问题：
1. 记录问题到 `pmo/Project导入问题记录.md`（问题描述 + CSV 源头行号 + 修正方案）
2. 修正 CSV 源文件
3. 重新导入（覆盖或新建 Project 文件）
4. 重新验证

迭代直到 V1-V10 全部通过。

#### 步骤 7：Phase 2 验收

验收人逐项确认：

- [ ] V1-V10 验证项全部通过
- [ ] `.mpp` 文件可正常打开，甘特图正确渲染
- [ ] 导入问题记录完整（即使无问题也记录"无问题"）
- [ ] 导入问题记录中的每个问题都有 CSV 源头修正记录

全部确认 → 进入 Phase 3。

### 2.4 常见导入问题及处理

| 问题现象 | 可能原因 | 处理方法 |
|---|---|---|
| 日期导入后偏移 1 天 | CSV 日期格式与 Project 日期格式不一致 | 确认 CSV 和 Project 使用相同日期格式（建议 YYYY-MM-DD） |
| 前置任务全部断链 | 导入时 ID 列被映射到某字段导致行号重新编号 | 不要导入 ID 列；导入后手工关联前置任务 |
| 摘要任务没有工期 | 正常行为 — Project 自动计算摘要任务工期 | 不需处理，检查摘要任务是否正确缩进 |
| 资源名称中出现供应商 | 导入时使用了原 `资源名称` 列而非 `主责资源` 列 | 重新导入，资源映射选 `主责资源` |
| 里程碑显示为普通任务 | CSV 中"里程碑"列值不是 Project 识别的格式 | 确保 CSV 中"里程碑"列值为"是"/"否"；导入后手动设置里程碑标记 |
| 中文乱码 | CSV 编码不是 UTF-8 | 用记事本另存为 UTF-8（带 BOM） |

## 3. Phase 3 — 基线设置与固化（1-2 天）

### 3.1 本阶段目标

在 Project 中设置项目基线，固化当前版本的计划数据，输出基线版 CSV 和导入规范文档。

### 3.2 基线设置操作

#### 步骤 1：基线设置前最终确认

在设置基线前做最后一次全量复核：

- [ ] 所有任务有开始/完成日期
- [ ] 所有里程碑为 0 工期
- [ ] 前置任务依赖链完整（无 `#N/A`）
- [ ] 资源分配正确（每人/组不超负荷）
- [ ] 甘特图中无悬空无依赖的孤立任务

#### 步骤 2：在 Project 中设置基线

1. `项目 → 设置基线 → 设置基线`
2. 选择 `设置基线`（不选"设置中期计划"）
3. 范围选 `整个项目`
4. 点击确定

Project 会在每条任务上记录基线开始时间、基线完成时间、基线工期、基线资源。

#### 步骤 3：固化视图配置

按以下配置保存常用视图，方便后续查阅：

**视图 1：PMO 管理视图**
- 显示字段：WBS、任务名称、工期、开始时间、完成时间、前置任务、资源名称、风险等级、里程碑
- 筛选器：不筛选（全量）
- 分组依据：WBS 一级（1-10）
- 甘特图时间刻度：中层=月，底层=周

**视图 2：里程碑视图**
- 显示字段：WBS、任务名称、开始时间、完成时间、风险等级
- 筛选器：里程碑 = 是
- 分组依据：风险等级

**视图 3：高风险视图**
- 显示字段：WBS、任务名称、工期、开始时间、完成时间、资源名称、供应商
- 筛选器：风险等级 = 高
- 分组依据：资源名称

**视图 4：供应商进度视图**
- 显示字段：WBS、任务名称、工期、开始时间、完成时间、供应商
- 筛选器：供应商 不为空
- 分组依据：供应商

保存方法：`视图 → 分组依据 → 另存为新视图`。

#### 步骤 4：版本记录

在 Project 文件的 `文件 → 信息 → 高级属性 → 摘要` 中填写：

| 属性 | 填写内容 |
|------|---------|
| 标题 | 数字化底座项目管理版 V1 |
| 主题 | 信息化项目计划管控基线 |
| 作者 | 信息化项目管理工作室 |
| 备注 | 基线日期: YYYY-MM-DD，基线条目: N 条任务，10 条主线，M 个里程碑 |

#### 步骤 5：从 Project 导出基线版 CSV
