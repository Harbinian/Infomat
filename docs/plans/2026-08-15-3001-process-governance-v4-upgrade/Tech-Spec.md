# 3001流程结构规则v4技术规格

## 结构真源

`docs/contracts/process-governance-v4.schema.json`是3001当前导出结构真源。`data_objects[].behavior_links[]`是数据与业务行为关系的唯一写入位置；v4行为对象不再保存`input_data_refs`和`output_data_refs`，数据对象也不再保存`produced_by_behavior_ref`和`consumed_by_behavior_refs`。

版本历史由`docs/contracts/process-governance-version-history.json`维护，服务端只读提供给前端。版本说明不依赖当前草稿，不修改未导出状态。

## 主要对象

| 对象 | 作用 | 关键字段 |
| --- | --- | --- |
| 数据行为关系 | 表达当前流程对数据的操作 | `behavior_ref`、`operation` |
| 数据来源线索 | 表达外部或跨流程来源及可用时间 | 来源部门、流程、行为、数据名称、`availability_mode` |
| 表单行为关系 | 表达业务行为如何处理表单 | `behavior_ref`、`operations[]`、`notes` |
| 字段关系 | 表达字段归属和取值依赖 | `business_data_ref`、`value_origin_mode`、`source_links[]` |

## 迁移算法

1. 先建立业务行为和数据对象的稳定标识映射。
2. 对每项旧数据，合并数据对象侧产生引用与行为侧输出引用。只有一个候选行为时转换为“创建”；存在多个候选行为时全部转换为“待确认”。
3. 合并数据对象侧使用引用与行为侧输入引用，去重后转换为“使用”。只在一侧存在的引用也保留。
4. 旧表单的`behavior_ref`转换为一条表单行为关系，操作列表留空，表示待确认。
5. 旧字段保留稳定标识、名称、类型、必填状态、填写说明、区域和顺序；业务数据归属为空，取值方式为“待确认”，来源列表为空。
6. v4再次规范化时只清理非法值和重复列表项，不重复生成关系。导入源文件始终只读。

## 校验边界

服务端使用JSON Schema检查对象形状、必填字段和枚举，并检查所有当前文件内引用。跨流程来源名称不是本地技术引用，不要求存在于当前文件。多个创建关系、来源线索不完整、取值时序和业务内容缺项进入业务提示，不作为结构错误。

## 页面实现

- “输出物与数据”继续作为数据关系唯一编辑入口；业务行为页面使用派生摘要。
- 表单顶部编辑表单行为关系；字段表的字段名称单元格提供“数据关系”入口，关系编辑区统一维护业务数据归属、取值方式和多个取值来源。
- 关系总览按数据展开，显示信息类型、来源、创建、更新、使用、表单字段和待确认事项，并提供定位按钮。
- 删除操作先扫描本地引用。存在引用时不修改草稿，页面显示引用位置。
- 当前结构评分保持100分和原权重，更新数据与表单项的内部判断；评分规则标记为v4，不与旧分数直接比较。

## 运行与兼容

3001继续使用现有`/api/schema`、`/api/template`和`/api/validate`外层接口；默认版本改为v4，并继续按版本校验v1至v3。新增`GET /api/version-history`只读接口。3000不在本次变更范围内，页面和导出提示不声明MDM兼容性。
