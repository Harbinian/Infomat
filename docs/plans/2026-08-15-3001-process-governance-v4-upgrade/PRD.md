# 3001流程结构规则v4升级需求

## 结论

本次把“输出物与数据”“表单与记录”以及流程步骤中的业务行为连成可核对的关系链。3001继续是无状态编制工具，不增加数据库、账号、自动保存或3000运行依赖。所有新关系都由用户确认后写入；系统只提示，不按名称或页面顺序自动推断业务事实。

## 业务目标

业务人员应能回答四个问题：哪个行为创建、更新或使用某项数据；哪个行为如何处理一张表单；表单字段属于哪项业务数据；字段值直接来自当前流程，还是依赖本流程或其他流程产生的数据。

## 范围

- 将可结构化的信息输出登记为数据对象；实物、服务结果和动作完成结果继续写在完成标准中，需要追溯时登记其记录或数据。
- 数据对象增加信息类型、行为关系和来源线索。
- 信息类型下拉中的每个枚举项显示业务例子；例子只用于帮助选择，不改变枚举值，也不写入导出JSON。
- 表单增加多行为、多操作关系；操作包括创建、填写、修改、复核、批准、确认、查阅、归档和作废。
- 表单字段增加业务数据归属、取值方式和多个取值来源。
- 业务行为页面只读展示相关数据和表单，并提供跳转入口。
- 增加只读的关系总览和独立“版本说明”标签。
- v1、v2、v3文件在当前页面内存中升级；源文件不修改，导出统一为v4。
- MDM-AI助手读取、编辑、预审和下载v4，不推断新关系。

## 非目标

- 不判断主数据、权威源、黄金源、数据责任或质量规则。
- 不绑定其他流程文件或3000对象；跨流程来源只记录线索。
- 不建立字段到业务行为的直接关系。
- 不增加运行态技术血缘、生命周期、持久化、自动保存或3000功能。
- 不把业务缺项变成导出阻断条件。

## 关键规则

1. 数据与行为关系只使用“创建、更新、使用、待确认”。同一数据可以有多个更新和使用关系；多个创建关系作为业务提示，不由系统替用户裁决。
2. 数据来源可以记录多条线索。每条线索记录来源部门、流程名称、行为名称、数据名称和当前流程中的可用时间；部门使用组织目录，流程和行为名称手工填写。
3. 字段最多归属一个业务数据对象，可以依赖多个来源数据；来源作用分别为提供字段值、参与计算和作为校验依据。
4. 新字段的取值方式默认为“待确认”。选择“依赖数据”但未登记来源时给出业务提示。
5. 被其他内容引用的数据、行为、表单或字段不得直接删除。页面先列明影响，用户解除或替换引用后才能删除；不级联删除。
6. 名称相同的数据对象允许保留，页面提示核对并在选择器中显示创建或来源上下文，不自动合并。

## 验收标准

- v4文件通过结构校验和文件内引用校验，导出后重新导入不丢失内容。
- v1、v2、v3文件可导入并转换；重复转换结果稳定；转换失败时保留当前页面内容和源文件。
- 本地创建、更新、使用、外部来源、多行为表单、字段归属和多来源关系均可编辑并在关系总览核对。
- 表单字段表只保留字段录入所需的八列；业务数据归属、取值方式和多个取值来源从同一个“数据关系”入口编辑，填写说明不再被三列关系控件挤占。
- 文字编制页不显示流程图预览条件提示条或重复查看入口；跨职能流程图标签继续显示当前状态。
- 版本说明在没有当前草稿时仍可查阅，并显示v1至v4历史；导入旧文件后显示本次迁移摘要。
- 业务缺项仅提示；结构错误、重复技术标识、断开的本地引用、非法枚举和往返丢失阻断导出。
- 1920×1080及以上完成视觉回归；更小窗口不显示低分辨率专门提示，保留滚动，不阻断导入、编辑和导出，也不丢失内容。
