# 流程治理到导入导出主线稳定性检查

> 编制日期：2026-06-07  
> 适用范围：流程地图与数据地图梳理阶段、MDM 一期恢复验证、字段台账与主数据治理衔接检查。  
> 定位：本文件定义一条可执行的稳定性检查口径，不改变当前流程数据真源。

## 1. 主线范围

本仓库当前主线按以下顺序验收：

```text
流程治理
  ↓
字段台账
  ↓
主数据对象
  ↓
权限
  ↓
导入导出
```

检查目标不是提前恢复 MDM 平台开发，而是保证后续每次修改页面、脚本或数据时，都能证明这条链路没有断。

## 2. 数据边界

| 环节 | 当前真源/载体 | 稳定性判断 |
|---|---|---|
| 流程治理 | `docs/norms/{部门}部门-能力-流程-系统映射关系.md`、`docs/company-sankey-data.json`、`process_governance_*` 快照表 | 能从流程治理快照读取 L3、A1、跨部门交互和组织口径，且不破坏 PMO 静态驾驶舱链路 |
| 字段台账 | `field_entries` | 字段可引用流程治理 L3/A1，报送人与数据 owner 的可写列边界清楚 |
| 主数据对象 | `org_unit`、`position`、`person`、`product_family`、`product`、`attribute_def`、`attribute_value` | 组织、人员、产品和属性元数据可独立创建、发布或写入，不依赖共享数据库 |
| 权限 | `roles`、`permissions`、`role_permissions`、`user_roles`、项目角色访问测试 | 角色可控制映射查看、冲突处理、升级终裁和关键维护动作 |
| 导入导出 | `import.js`、`export.js` | 字段台账可导入，字段台账、黄金源矩阵、术语冲突台账可导出 |

注意：字段台账中的 `data_object` 是主数据对象候选，不等同于已经完成主数据建模。只有在黄金源、维护部门、审批部门、消费系统和权限边界确认后，才进入正式主数据对象沉淀。

## 3. 一键检查命令

在平台目录执行：

```bash
cd apps/mdm-platform
npm run test:mainline
```

该命令串联以下检查：

| 顺序 | 覆盖环节 | 检查内容 |
|---|---|---|
| 1 | 流程治理 | 隔离数据库路径、组织同步、流程治理 schema、快照导入、API、前端挂钩、字段台账 A1 关联 |
| 2 | 字段台账/导入 | 字段台账 Excel 导入、报送人列级边界、跨部门不可导入保护 |
| 3 | 导出 | 字段台账、黄金源矩阵、术语冲突台账导出结构 |
| 4 | 权限 | 项目角色访问、冲突升级和终裁边界 |
| 5 | 主数据对象 | 组织、人员、产品族、产品发布、属性定义、属性值、质量汇总的隔离冒烟检查 |

## 4. 通过标准

一次检查只有在以下条件全部满足时才算通过：

- 所有子检查退出码为 0。
- 检查过程使用隔离 SQLite 数据库，不清空或覆盖 `apps/mdm-platform/data/platform.db`。
- 流程治理快照可与字段台账建立 L3/A1 引用。
- 字段台账导入后，报送人不能越权写入 owner 列。
- 导出的 Excel 至少包含字段台账、黄金源矩阵、术语冲突台账。
- 项目角色权限能区分一般冲突处理和升级冲突终裁。
- 主数据对象检查能完成创建、激活/发布、属性写入和质量汇总。

## 5. 不通过处理

若 `npm run test:mainline` 不通过，先按失败环节定位：

| 失败位置 | 优先检查 |
|---|---|
| 流程治理 | `scripts/import-process-governance.js`、`server/routes/processGovernance.js`、`server/db.js` 的快照表结构 |
| 字段台账 | `server/routes/fieldEntries.js`、`server/routes/import.js` |
| 主数据对象 | `server/routes/orgUnit.js`、`server/routes/person.js`、`server/routes/productFamily.js`、`server/routes/product.js`、`server/routes/attribute.js` |
| 权限 | `server/auth.js`、`server/routes/roles.js`、`server/routes/conflicts.js` |
| 导入导出 | `server/routes/import.js`、`server/routes/export.js` |

不要用共享数据库反复试错。所有复现都应先使用 `MDM_DB_PATH` 指向临时数据库，确认问题后再判断是否需要迁移共享数据。

## 6. 后续加严项

当前稳定性检查覆盖主线最小闭环。后续恢复 MDM 平台开发后，可逐步增加：

- RBAC 批量导入模板和导入结果检查。
- 字段身份确认与主数据对象候选之间的矩阵检查。
- 从 `docs/company-sankey-data.json` 到 PMO 驾驶舱内嵌 `#sankey-data` 的一致性检查。
- 主数据对象候选的黄金源、维护部门、审批部门和消费系统完整率检查。
