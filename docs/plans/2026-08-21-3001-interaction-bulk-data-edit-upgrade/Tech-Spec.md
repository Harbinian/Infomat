# 3001 交互缺陷收口与批量数据编辑技术方案

## 1. 技术边界

本次变更只发生在 `apps/structured-output-service/public/` 的浏览器前端和对应自动化测试中。页面仍使用现有 `/api/template`、`/api/validate`、`/api/migrate` 和静态资源；不新增业务接口。

`process-governance-v7` 结构不变：

- 数据对象仍以 `data_objects[]` 为唯一真源。
- 对象字段仍以 `data_objects[].fields[]` 为当前流程内复用真源。
- 数据行为关系仍以 `data_objects[].behavior_links[]` 为唯一有效关系。
- 表单字段继续通过 `data_field_ref` 引用对象字段。

因此，本次升级没有旧数据结构迁移。历史 v1 至 v6 JSON 仍先按现有迁移逻辑进入 v7 页面内存，再使用批量编辑功能。

## 2. 页面状态

页面内存增加两组临时状态：

1. `checkedGovernanceSteps`：记录当前草稿已主动检查的步骤。任何影响草稿内容的修改都会清除对应检查状态。该状态不写入 JSON。
2. `bulkDataEditorState`：记录当前表格类型、粘贴文本、预览结果和预览时的草稿指纹。刷新或重新导入后清空。

第 1 至第 5 步只有在当前步骤已主动检查时才渲染本轮自检面板。第 6、7 步继续按角色显示业务核对项和交接检查事项。技术结构错误不受该开关影响。

## 3. 批量处理链路

```text
Excel/WPS 单元格区域
  → 用户主动粘贴
  → TSV 解析与列头映射
  → 行级字段、枚举和技术标识检查
  → 对象/行为引用解析
  → 在草稿副本上计算新增、修改、删除和不变项
  → 运行前端技术完整性检查
  → 展示差异预览
  → 用户一次应用
  → 作为一个历史操作写入页面内存
  → 调用现有校验并刷新页面
```

解析和候选变更在独立纯函数模块中完成，便于 Node.js 自动化覆盖。批量预览不修改当前草稿。

## 4. 解析规则

- 输入格式为制表符分隔文本，支持 Windows 和 Unix 换行。
- 支持 Excel/WPS 复制产生的双引号包裹、单元格内换行和双引号转义。
- 第一行必须是受支持的中文列头；列顺序可以调整，额外空列忽略。
- 空白行忽略；单元格首尾空白按字段规则清理，说明和定义中的内部换行保留。
- “处理方式”支持空白、`新增或更新`、`删除`。
- “信息类型”和“数据操作”必须转换为 v7 既有枚举；不接受未声明的新枚举。
- 新记录的技术标识由现有页面标识生成器提供，不在纯函数中猜测。

## 5. 引用规则

1. 技术标识优先，存在且有效时按技术标识定位。
2. 技术标识为空时，可以用名称定位数据对象或业务行为，但名称必须在当前草稿中唯一。
3. 技术标识和名称同时提供时，两者必须指向同一记录。
4. 重名、找不到记录或标识与名称冲突时，行级报错，整批不应用。
5. 新增对象字段和数据关系必须先解析其所属数据对象；新增数据关系还必须解析业务行为。

## 6. 变更与删除

- 表格未列出的记录不变。
- 既有标识对应记录执行更新；空标识执行新增。
- 删除对象字段前，检查所有表单字段的 `data_field_ref`；仍被引用时阻止删除。
- 删除数据对象继续使用现有引用影响检查，不允许级联删除。
- 删除数据行为关系只删除对应 `link_ref`，不删除数据对象或业务行为。
- 同一批次内先校验全部定位和冲突，再在副本中按安全顺序应用；失败不产生部分结果。

## 7. 撤销与并发保护

- 批量应用通过现有 `GraphEditorState.execute()` 提交完整候选文档，因此只产生一条撤销记录。
- 预览保存草稿指纹。预览后如果用户通过其他入口修改草稿，应用按钮失效，用户必须重新预览。
- 页面刷新、导入其他文件、迁移或切换候选会清空批量编辑临时状态。

## 8. 安全与隐私

- 页面不调用剪贴板读取权限，不监听后台剪贴板内容。
- 用户点击复制按钮时，只在用户手势内写入当前表格文本；写入不可用时在页面提供可手工复制的文本。
- 粘贴内容、预览和错误只保留在当前浏览器页面内存，不写日志、数据库、浏览器存储或服务端业务文件。
