# 3001 交互缺陷收口与批量数据编辑需求

## 1. 结论

本次升级解决两组直接影响流程编制效率的问题：一是编制阶段提前显示大量待补充项，造成阶段错位和角色责任混淆；二是数据对象、对象字段和数据行为关系只能逐项录入，用户需要在多个页面之间反复切换。

升级后，编制人先完成当前步骤，再主动执行本轮自检；业务核对项集中在第 6 步，交接检查事项集中在第 7 步。用户可以保留单项编辑，也可以从 Excel 或 WPS 表格复制数据，经过解析、引用核对、变更预览和整体校验后一次应用。

## 2. 用户与操作顺序

| 角色 | 操作顺序 | 系统反馈 |
|---|---|---|
| 流程编制人 | 编制当前步骤 → 按需执行本轮自检 → 修正当前步骤 | 不在进入步骤时自动展开整份流程的待补充项 |
| 业务核对人 | 第 6 步查看业务核对项 → 回到制度或表单源文件核对 → 记录结论 | 只显示需要业务判断的事项，不混入技术结构错误 |
| MDM 工作组接收人 | 第 7 步检查结构阻断、交接说明和下载条件 | 结构错误阻止下载；业务待定如实保留，不由系统虚构结论 |
| 数据编制人 | 选择单项编辑或 Excel/WPS 批量编辑 → 粘贴 → 预览 → 一次应用 | 未通过预览和校验时不修改当前数据 |

## 3. 问题分类

1. **提示阶段错位**：编制阶段显示应在核对或交接阶段处理的事项。
2. **角色责任混淆**：编制人、业务核对人和 MDM 工作组的任务显示在同一问题面板中。
3. **问题类型混杂**：技术结构错误、业务核对项、交接检查事项和填写建议使用同一“待补充项”名称。
4. **信息层级失衡**：问题面板默认展开并位于编辑器之前，遮挡当前主要任务。
5. **导航与上下文切换过多**：数据对象、字段和关系分散在卡片、子页面和弹窗中。
6. **批量编辑能力缺失**：同一业务流程的大量相同字段需要逐条重复录入。
7. **引用与变更安全风险**：同名对象可能错误匹配，批量失败可能留下半成品，删除可能破坏表单字段引用。

## 4. 功能范围

### 4.1 提示分层

- 第 1 至第 5 步默认不显示整份流程的待补充项数量和展开面板。
- 用户点击“检查本轮”后，只在当前步骤显示本轮自检项。
- 第 6 步使用“业务核对项”，第 7 步使用“交接检查事项”。
- 技术结构错误保持即时可见，并继续作为下载阻断条件。
- 用户修改当前步骤后，本轮自检结果失效，需要重新检查。

### 4.2 批量编辑

- 支持三类表格：数据对象、对象字段、数据行为关系。
- 支持复制列头、复制当前数据、粘贴 Excel/WPS 单元格区域、预览和一次应用。
- 既有记录使用稳定技术标识更新；新记录的技术标识可留空，由系统生成。
- 表格未出现的既有记录保持不变，不以“遗漏行”表示删除。
- 删除必须在“处理方式”列明确填写“删除”，并在预览中单独列出。
- 对象或行为仅按名称匹配时，名称必须唯一；存在重名时停止应用并提示用户补充技术标识。
- 一批数据全部通过前端结构检查后才能应用；任一行失败时，当前数据保持不变。
- 一批数据作为一个可撤销操作。

## 5. 表格列

| 表格 | 必填或识别列 |
|---|---|
| 数据对象 | 处理方式、数据对象标识、数据对象名称、信息类型、说明 |
| 对象字段 | 处理方式、字段标识、数据对象标识、数据对象名称、字段名称、字段类型、字段定义 |
| 数据行为关系 | 处理方式、关系标识、数据对象标识、数据对象名称、业务行为标识、业务行为名称、数据操作 |

“处理方式”留空时按“新增或更新”处理；只有明确填写“删除”才触发删除预览。

## 6. 非目标

- 不开发 Office Add-in、Excel 插件安装包或宏。
- 不直接读取用户剪贴板；只处理用户主动粘贴到页面的文本。
- 不支持上传 `.xlsx` 文件。
- 不改变 v7 JSON 字段、枚举和导入导出格式。
- 不新增服务器业务接口、数据库、草稿保存或浏览器持久化。
- 不让用户为每一个业务行为手工定义一份独立的数据字典；对象字段仍由数据对象统一定义，表单字段继续引用对象字段。

## 7. 验收标准

1. 进入第 1 至第 5 步时，页面不自动显示整份流程的“待补充项”面板。
2. 用户可以主动执行本轮自检；修改数据后，自检状态自动失效。
3. 第 6、7 步的事项名称和角色责任清楚，不再统一称为“待补充项”。
4. 三类表格均能从 Excel/WPS 复制粘贴，并能复制当前数据回表格继续编辑。
5. 粘贴内容必须先显示新增、修改、删除、不变、警告和错误摘要，不能直接写入当前流程。
6. 引用不明确、技术标识重复、枚举无效或删除仍被引用的记录时，整批不应用。
7. 成功应用一批数据后，执行一次撤销即可恢复应用前状态。
8. v1 至 v6 导入 v7、v7 导出后重新导入、重复迁移和失败恢复继续通过。
9. 1920×1080、1536×864、1280×720 三档视口无页面横向溢出，主要操作可见，控制台无新增错误。
