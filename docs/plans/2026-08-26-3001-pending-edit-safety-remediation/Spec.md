# 3001 未应用修改与误导性交互整改规格

> 日期：2026-08-26  
> 适用对象：3001编制人、前端维护人员和测试人员  
> 状态：已锁定需求；实施与验证状态以同目录`Verification-Record.md`为准

## 1. 问题和目标

3001同时存在三种内容状态：页面编辑器中的未应用修改、已经写入当前JSON但尚未下载的修改、最近一次成功导入或下载形成的文件基线。页面必须分别识别和显示这三种状态。任何页面上可见的输入都不得在切换、重绘、下载或离页时被静默丢弃、静默应用，或被遗漏在下载文件之外。

## 2. 状态定义

| 状态 | 含义 | 用户可以如何恢复 |
|---|---|---|
| 未应用修改 | 用户已经在显式应用编辑器中输入，但尚未点击“应用修改”；内容只属于当前页面编辑会话，尚未进入当前JSON | 继续编辑，或在统一保护框中选择应用或放弃 |
| 未下载修改 | 内容已经进入当前JSON，但当前JSON与最近一次成功导入或成功下载的基线不同 | 下载JSON文件 |
| 当前内容已下载 | 当前JSON与最近一次成功下载文件的实际内容一致，且页面没有未应用修改 | 使用最近下载的JSON恢复 |
| 当前内容与导入文件一致 | 原生v7导入后，当前JSON与用户选择的导入文件一致，且页面没有未应用修改 | 可使用原导入文件恢复；该状态不表示本次会话已下载 |
| 尚未下载 | 当前流程为新建内容，本次会话还没有成功下载文件 | 首次下载JSON文件 |

页面不得在仍有未应用修改时显示“当前内容已下载”。“未应用修改”也不得替代“未下载修改”；用户点击应用后，状态应从前者转为后者。文件基线的呈现还必须区分导入文件、新建内容和本次会话的成功下载，不得用“当前内容已下载”概括前两种情况。

## 3. 显式应用编辑器

以下编辑入口统一接入候选级页面内编辑会话保护，同一时间只允许一个对用户可见的未应用编辑上下文：

1. 业务行为属性；
2. 流程关系属性；
3. 数据对象属性；
4. 数据行为操作及本次更新字段；
5. 新流程关系向导；
6. 新数据行为关系选择；
7. 网页表格工作副本；
8. 尚未确认的更新字段选择弹窗。

编辑会话必须绑定当前候选、编辑器种类和对象稳定标识。输入要么已经进入当前JSON，要么登记在该编辑会话中。页面不得只把输入保留在DOM、匿名变量或未绑定候选的临时集合中。

`EditSessionManager`管理节点属性（普通业务行为和控制节点）、流程关系属性、数据对象信息、数据操作和关系向导。网页表格工作副本和更新字段弹窗可以保留各自的技术状态，但必须通过适配器接入同一待处理编辑查询和切换保护入口。统一管理不要求所有工作副本存入同一技术对象。

普通`data-bind`字段继续按现有规则即时写入当前JSON。用户手册必须明确：显式应用编辑器需要点击“应用修改”，即时写入字段则在输入后直接形成未下载修改。

## 4. 统一切换保护

任何会隐藏、替换、重建或清空当前编辑上下文的操作，都必须先调用同一个切换保护入口。保护范围包括步骤、视图、对象、图节点、图关系、候选、业务式/表格式编辑、数据流/生命周期、撤销/重做、问题定位、新建、导入、清空和下载。

存在有效未应用修改时，页面显示三项选择：

- **应用修改并继续**：页面先校验并把修改写入当前JSON；成功后执行原操作。
- **放弃修改并继续**：页面明确清除当前编辑会话；随后执行原操作。
- **继续编辑**：页面取消原操作，并恢复原候选、控件值、滚动位置、图形焦点和键盘焦点。

向导尚缺必填内容时，页面保留三项结构，但禁用“应用修改并继续”，并说明缺少的内容。应用校验失败、同字段冲突或目标对象已经不存在时，页面保留全部输入，取消原操作，并显示用户可以处理的原因。

顶部候选下拉框和侧栏候选按钮必须使用同一候选切换函数。用户选择“继续编辑”时，顶部下拉框必须恢复原候选值。

## 5. 字段补丁和冲突

属性面板只能提交自己拥有的字段补丁，不能用打开面板时取得的完整旧对象覆盖当前对象。

| 编辑器 | 允许提交的字段 |
|---|---|
| 业务行为属性 | 节点类型、节点名称、执行主体确定方式、固定部门和岗位、动态部门来源数据、岗位或责任人确定规则 |
| 流程关系属性 | 关系类型、起点、终点 |
| 数据对象属性 | 数据名称、说明、信息类型 |

应用时，页面使用候选标识和对象稳定标识重新取得当前最新对象，只合并用户实际修改的允许字段。其他步骤已经写入的动作说明、完成标准、会签、关系条件、对象字段、数据关系、来源关系和生命周期必须保留。

如果同一字段在编辑会话打开后已经由其他入口修改，页面阻止应用并列出冲突字段。如果对象已经不存在，页面不得把补丁应用到其他对象。一次成功应用只形成一次撤销记录和一次未下载状态变化。

网页表格继续保留整文档`SOURCE_CHANGED`检查，避免旧工作副本覆盖当前JSON。

表单引用对象字段时，页面可以同步业务数据归属、对象字段数据类型，并只在表单显示名称为空时带入对象字段名称。页面不得根据“第几个表单引用该字段”推断本流程权威录入点、沿用已有值或字段取值方式；`value_usage_mode`和`value_origin_mode`没有人工确认时继续保持待确认。

## 6. 数据对象属性和生命周期

数据对象属性卡只有两种状态：已经建立当前候选、当前数据对象的编辑会话，可以输入和应用；或明确只读，输入控件和应用按钮均不可用。页面不得显示“可以输入，但点击应用没有结果”的状态。

生命周期视图中的入口名称固定为“返回数据流编辑对象信息”。该入口只返回同一数据对象的数据流属性区，不提交属性，也不重新克隆旧对象。数据流属性卡不重复显示该入口。

主数据认定提示只依据已经应用到当前JSON的内容。属性存在未应用修改时，页面同时显示：

> 当前提示依据为已应用内容；应用修改后重新判断。

页面删除“列入交接待定事项”入口及其临时集合，不新增替代JSON字段、步骤7清单或人工标记。

数据流/生命周期切换、选择数据对象、展开说明和普通重绘必须是纯读取操作。缺少生命周期结构时，页面只使用临时默认值显示，不写回当前JSON。只有“重新分析当前对象”和“重新分析全部对象”可以改变生命周期内容；分析无变化时，不新增撤销记录或未下载状态。分析有变化时，一次分析形成一次撤销记录。分析失败时，当前JSON保持不变。

## 7. 下载、替换和离页顺序

下载、新建、导入、清空和离页按以下顺序处理：

1. 页面先处理未应用修改；
2. 页面再处理已经进入当前JSON、但尚未下载的修改；
3. 页面最后执行下载、新建、导入、清空或离开。

下载发现未应用修改时不得直接生成文件。选择应用后，下载文件必须包含刚应用的内容；选择放弃后，下载文件不得包含该输入；选择继续编辑时，不得启动下载。下载成功后，页面只能把实际进入文件的JSON设为新的下载基线。

新建、导入和清空即使已经应用页面输入，仍须继续执行现有未下载修改保护。成功安装新数据后，页面原子清理全部编辑会话、向导、弹窗工作副本和旧候选临时状态。导入失败或用户取消导入时，当前JSON、编辑会话、候选、选择、撤销记录和焦点保持不变。

浏览器关闭或刷新时，`beforeunload`同时检查未应用修改和未下载修改。该提示是最后防线，不替代页面内三项保护。

## 8. 删除保护

步骤5中删除数据对象、对象字段、数据行为关系、数据来源关系、表单、表单区域、表单字段、表单行为关系和字段取值来源，以及列表中删除业务行为、流程关系和术语时，页面统一执行：

1. 先检查引用；
2. 有引用时阻止删除，并列出需要先处理的引用；
3. 无阻断引用时显示对象名称和影响；
4. 用户确认后，通过一次文档事务修改当前JSON；
5. 一次删除形成一次撤销记录；
6. 撤销恢复完整嵌套记录和稳定标识；
7. 页面更新未下载状态并显示与本次删除对应的反馈。

用户取消删除后，当前内容、选择、滚动位置和焦点保持不变。页面不得静默级联删除。

生命周期路径对流程关系的引用、生命周期事件对触发行为的引用也属于删除阻断项。页面不得先删除行为或关系，再把断裂引用留到下载校验时才发现。

## 9. 撤销和重做的来源变化保护

图命令和文档事务仍以完整文档快照形成撤销记录。执行撤销前，页面必须核对当前JSON是否仍等于该记录提交后的内容；执行重做前，页面必须核对当前JSON是否仍等于该记录撤销后的内容。如果用户随后通过即时写入字段修改了当前JSON，页面阻止本次撤销或重做并保留全部内容，不得用历史快照覆盖后续修改。该保护只阻止存在来源变化的历史操作，不把普通即时字段改造成显式应用编辑器。

## 10. 外部边界

本整改不改变`process-governance-v7` JSON结构、Schema、导入导出格式或服务端API，不需要历史JSON迁移。3001继续只在当前页面内存中处理单流程，不新增数据库、服务端草稿、自动保存、`localStorage`、`sessionStorage`、IndexedDB、Cookie、3000通信或AI调用。用户下载的JSON仍是唯一持久化结果。

## 11. 完成条件

只有同目录`Test-Plan.md`中的自动测试、下载重导入、失败恢复、三档真实浏览器、中文输入法、焦点恢复、页面溢出、浏览器存储和网络边界均取得实际证据后，本整改才可以标为技术验证完成。软件技术验证不等于真实流程业务验收。
