## 1. 通用完成规则

任务输入、当前工作区和有效授权先于任务卡的历史值。完成须有实际产出和对应证据；完成准备卡只表示材料已准备，不替代其后的运行或人工验收卡。条件卡不适用须有确认来源，不得自行将待定改为不适用。前置卡标为完成仍须满足有关门槛和条件；任务 ID 依赖不替代实际业务依赖。

`A27/A29` 是启用准备，实际运行及办公室办理分别在 `A30/A31`；`A28` 固定继承门槛的位置，剩余获准预演在 `A32`。A23 在正式发布前，还须满足 A28 中被确认属于“正式发布前”的所有实际门槛。A30/A31 使用正式版本时还依赖 A23；使用预览或独立固定材料时不得伪造正式版本 ID。

每卡共同输出到原批次 `evidence/p25/` 下不存在的新执行目录，并登记到共享台账。输出须有北京时间、任务键、真实会话标识、输入摘要、实际变更、检查证据、授权来源、限制和下一步。Secret、会话正文、真实完整材料、SQL 及未脱敏日志不进入公开报告。

## 2. 任务卡

### P25-A00：验证新会话调度、台账和互斥入口

- **归属及前置**：调度前置；无前置产品任务；门槛 调度或技术基线。
- **适用与动作边界**：正式激活前手工完成；不执行产品任务。动作类别 `local_plan`，含义见 11 计划授权表；类别本身不授予权限。
- **输入**：本计划、任务卡、queue.json、原暂停自动任务元数据及实际工具能力。

执行步骤：

1. 用最小本地入口实现或验证原子认领、占用检查、报告提交和状态更新；只使用 Node 标准库或现有运行时，不引入调度框架。
2. 用临时复制的台账验证双重认领、无可执行任务、失效占用、报告缺失、输入摘要变化、中途退出及结果未知；不对正式业务发请求。
3. 核对原任务更新是否支持改为独立项目任务；不能转换时保留原 heartbeat 暂停，登记替换关系后创建唯一新任务。
4. 手工用通用提示词演练一次，只完成任务选择和交接；记录模型、推理、权限及项目环境实际值，默认设置无法核实则不填造。

- **交付物**：scheduler-preflight.md、调度入口及副作用说明、临时台账演练结果；queue.json 中登记验证证据。
- **完成证据**：只能有一个工作区写入者；缺证据不能标完成；旧任务保持暂停；工作目录为本地累计工作区；手工演练通过。
- **停止条件**：互斥或异常恢复失败、工具要求未核实参数、项目环境不是指定本地目录。
- **恢复方式**：修复调度入口并复验失败用例后，才申请激活；本轮计划稿不表示已完成 A00。

### P25-A03：只读定位准确 3000 的退出原因

- **归属及前置**：T1；P25-A01；门槛 G1。
- **适用与动作边界**：必须；诊断可独立于首批业务确认。动作类别 `local_read`，含义见 11 计划授权表；类别本身不授予权限。
- **输入**：准确 03 副本、非敏感控制状态、运行管理代码和相关退出日志。

执行步骤：

1. 核对端口、准确进程入口、创建时间与父进程归属；PID 不存在或复用时不据旧 PID 操作。
2. 先检查日志内容风险，仅提取脱敏退出时间、退出码、信号或堆栈位置；不读私有配置、DPAPI、SQL 或会话正文，不输出完整进程命令行。
3. 将状态文件、应用退出、守护退出、会话结束及运行管理源码按时间对应；日志未记录原因时说明只能提出哪些假设。
4. 不运行 runtime-service.cjs check 或 ready；这些入口涉及凭据或数据库。health 仅在确认无数据库及写副作用时作一次只读请求。

- **交付物**：runtime-diagnosis.md、runtime-observations.json，记录北京时间及证据来源。
- **完成证据**：给出证实的原因或可验证的具体缺口；端口失败与退出原因分开；不启动第二副本掩盖问题。
- **停止条件**：需要数据库、私有内容或服务重现才可继续时，仅将依赖步骤列为待条件。
- **恢复方式**：取得对应授权后进入 A06—A09；若需要隔离复现，进入 A04。
