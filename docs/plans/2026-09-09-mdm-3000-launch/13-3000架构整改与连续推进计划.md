## 2. 连续推进与会话切换

### B01：保护规则集合并收敛确定性计算输入

目标：外部消费者不能通过修改导出集合改变高风险判定、工作包完成规则或输入种类。

1. 盘点 HIGH_RISK_ACTIONS、COMPLETE_DETAIL_STATUSES 及固定引用种类的所有消费者；保留具体业务值和原规则版本。
2. 内部集合私有化，提供判定函数或受保护查询接口；旧 .has／迭代等受支持读取保留兼容适配，不使用 Object.freeze(Set) 冒充只读。
3. 只对本次计算边界收敛时间、随机标识或校验结果等输入；保留页面编辑、CSRF、会话代次和事务状态，不以纯度指标清除必要状态。
4. 将输入修改和外部集合污染加入行为验证；同输入反复计算、V8/V7 样本及原摘要保持。

产出：规则保护补丁、消费者对照、确定性行为验证和合同不变说明。

完成条件：外部污染不能改变高风险或完成判定；输入不修改，输出和旧兼容读取正确；纯规则和工作包相关检查通过。

停止条件：需要改变业务风险值、工作包完成条件、规则版本或历史摘要时，停止该语义变化。

接续：如实报告局部保护范围；不据此宣布全仓纯函数化。

### B02：统一身份表示和事务内授权核验合同

目标：人员、独立管理员、账号标识和部门范围在消费者之间保持相同含义，同时保留每次受保护写入的最新资格复核。

1. 定义最小内部主体表示，区分人员与 system-admin，不对类型化身份 Number 转换；BIGINT、accountId、personId、authVersion 和空人员语义保持。
2. 分离纯身份解析、当前资格读取及事务内锁后复核；复用现有 identityMysqlRepository、auth 和 access，而非再建权限体系。
3. 逐个迁移定义、正式流转及办公室等消费者，保持各自锁顺序、撤权／改密／部门变化检查和服务端数据范围。
4. 统一权限及身份失败的内部适配，外部 API／错误码不变；admin 只读，不能通过统一接口得到业务写入旁路。

产出：内部主体合同、逐消费者补丁和身份兼容对照；无 DDL 或真实授权变更。

完成条件：人员、独立 admin、admin 叠加角色、无权、跨部门、撤权、锁等待后失效均按原合同；已知类型化身份回归通过。

停止条件：拟取消事务内复核、缓存写权限、扩角色或改变真实身份结构时停止。

接续：未覆盖消费者列清，不在一次新会话顺手扩大全部身份链。

### B03：收敛前端会话、错误、回执和入口声明

目标：新旧页消费同一明确协议，页面声明及导航参数集中维护，业务输入和身份门槛保持。

1. 固定登录、CSRF、密码状态、会话失效、错误分类、请求 ID／原快照及未知结果处理合同；共享协议适配不能增加自动重试写入。
2. 用一个公开安全的页面元数据清单驱动 React 页面识别与 Express 注册；不放后端实现、凭据或权限判断。
3. 把已迁移模块的旧目标转换集中处理，保留案例／修订／任务／版本及 finding 等参数；未迁移入口保留明确适配。
4. 改密是否迁入 React 以相同后端合同完成一个独立子任务；不能只删除旧跳转而造成无法改密或绕过 gate。
5. 验证刷新／后退、角色切换、401/403/409/503、会话代次和迟到响应，以及未提交输入；仅 Edge100%、1699×828 桌面。

产出：前端协议与入口清单、必要适配补丁及实际浏览器证据；没有删除全部旧页的要求。

完成条件：新旧协议行为一致，完整目标参数保留，默认工作台正确；会话与输入保护、CSRF及回执相关检查通过。

停止条件：身份门槛放宽、未提交输入静默丢失、路由未知或旧兼容参数被删除。

接续：若一次会话需要多个补丁，按已冻结子范围串行新建会话，不等待整点。

### B04：提取正式流转用例与仓储，保持事务原子性

目标：HTTP 路由只负责请求／响应适配，正式办理操作和 MySQL 实现可以经明确接口独立验证。

1. 先选一个有现有保护证据的正式用例，固定前后外部行为与事务步骤；候选是提交审核或审核决定，执行前按当前代码确定。
2. 应用操作负责办理前置、修订／摘要、部门卡口及操作顺序；仓储负责明确 SQL 和锁；事务范围由一个明确入口持有，不能拆成多次提交。
3. 保持提升来源、正式正文、审核及发布的原生 V8/V7 语义、事件、ID和错误码；旧路由导出和测试工厂提供适配。
4. 通过接口验证后再逐个迁移其余确实属于相同正式流转模块的操作；保留退役旧版本拒绝入口，不重新开放旧写入。

产出：正式办理模块、仓储和路由适配；前后用例对照、事务／锁顺序说明和回归证据。

完成条件：正常路径及 admin／无权／过期／撤权／来源变化拒绝、事务与审计失败回滚、并发和旧 V7/V8 历史均保持。

停止条件：只有大段搬文件却无法独立验证用例，或事务／锁／审计保护被拆开。

接续：大范围正式流转迁移拆为具体子任务；每个通过后立即接续下一个。

### B05：集中组装消费者并明确依赖和缓存生命周期

目标：定义、固定映射和分析消费者在一个明确组装入口连接，不让下层反复获取上层内部闭包。

1. 画清现有 transaction／actor／scope／version／request／来源解析等实际依赖；选择一个消费者先从层层组装移到明确组合入口。
2. 保留小且能验证的内部接口，将 pool、env、now、UUID 和校验器按实际需要注入；不得把几十个内部函数包装成同样复杂的大容器。
3. 模块加载不读取实际配置、连接库或启动 worker；生产默认组装仍保持兼容入口，测试可独立构造并释放实例。
4. 明确单例、失败 promise、连接池和结构缓存的所有者与释放；保留现有 32 项指纹缓存保护及事务作用域，不清除必要状态。

产出：组合入口、消费者依赖图、实例／缓存生命周期说明和无副作用加载验证。

完成条件：构造两个独立实例互不污染，注入不同环境／时钟可验证；无正式连接或环境泄漏，队列／worker／权限行为保持。

停止条件：增加无收益的转发层、隐式全局 IO 或调用方仍需知道原闭包内部细节。

接续：按消费者逐项迁移并验证；3001 缓存单独保留为未授权应用的后续问题。

### B06：明确问题、办公室任务及编制答复的协作接口

目标：跨模块协作使用明确内部接口和事件解析合同，保留一个事务内的必要关系及独立问题关闭。

1. 固定目前创建任务、办公室分派、分析绑定、事件和编制记录的写入顺序与共同锁顺序。
2. 以业务动作封装协作，显式传入同一事务连接，不由模块再发起嵌套事务或跨连接提交。
3. 集中定义历史 note.record_id 等事件字段的读取适配及允许语义；保留原 JSON、ID、查询权限和非 JSON 历史，不批量改写事件。
