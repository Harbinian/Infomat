# PRD：3001双模式网页表格编辑器与字段复用减负

## 一、业务目标

流程编制人在步骤5既要能逐项理解和维护对象、字段、表单及关系，也要能在记录较多时直接按表格集中编辑。本次升级使用同一份v7 JSON支撑两种操作方式，并减少以下重复劳动和误操作：

- 编制人只在“数据对象与行为关系”中定义一次数据对象和对象字段。表单、主表、明细表通过稳定引用使用对象字段，不再重复填写同一字段名称、所属对象和类型。
- 业务式编辑只保留一个数据对象和对象字段的正式写入口。其他位置只显示引用摘要和“修改对象定义”入口。
- 表格式编辑任一时刻只显示一张可编辑表格和一个名称明确的新增按钮，避免相邻编辑区的“新增行”造成焦点混淆。
- 页面不把第一个业务行为、第一个数据对象、“非必填”“权威录入”“沿用已有值”等未经确认内容写成业务事实。
- 用户修改草稿后，步骤检查结果继续显示并标记为已过期。用户可以重新检查并继续定位下一项。

上述交互状态只存在当前页面内存中，不写入JSON、浏览器存储或服务端，也不与3000通信。

## 二、角色与操作顺序

| 角色 | 操作 | 完成条件 |
|---|---|---|
| 编制人 | 先建立数据对象和对象字段，再批量选择对象字段、目标区域和必填属性；需要时继续维护数据行为关系和字段取值来源 | 当前JSON通过引用、技术完整性和v7完整校验 |
| 业务核对人 | 依据制度、表单、台账和实际做法核对字段含义、来源和使用方式 | 业务事实已确认，不能确认的内容保持待定 |
| MDM工作组 | 检查结构、文件名、摘要和待定事项 | 接收未审核v7文件和JSON之外的核对记录 |

## 三、功能范围

1. 业务式编辑把“数据对象与行为关系”作为数据对象和对象字段的唯一正式写入口。表单、主表、明细表和表单字段只显示所引用对象及字段的只读摘要，并按`data_ref`和`field_ref`提供“修改对象定义”入口。
2. 业务式表单字段使用统一的“引用对象字段”选择器。选择器按“数据对象／对象字段”分组，同时显示对象名称、字段名称和字段类型；同名字段按稳定技术标识区分，不按名称合并。只有进入“对象字段待补，仅登记业务数据归属”兼容模式后，用户才能单独选择数据对象。
3. “引用对象字段”支持批量操作。编制人按以下顺序完成一批引用：
   1. 选择一个或多个对象字段；
   2. 选择当前表单中的主表、明细表、归属待确认区域，或明确新建明细表／归属待确认区域；
   3. 为每个字段明确选择“必填”或“非必填”，也可以先统一设置后再逐项调整；
   4. 执行“引用所选N个字段”。
4. 批量弹窗显示每个对象字段的引用次数和已有位置。已经使用过的字段默认不勾选，但用户明确勾选后可以再次引用。同一批次不允许重复选择同一个`field_ref`。选择“新建明细表”时必须填写名称；名称尚未确定时，用户应选择“新建归属待确认区域”。“添加空白字段”继续保留，但同样要求用户先选择目标区域和必填属性。
5. 表格编辑包含两个工作区和九类表：
   - 数据工作区：数据对象、对象字段、数据行为关系、跨流程数据来源。
   - 表单工作区：表单、表单行为关系、主表与明细表、表单字段、字段取值来源。
6. 表格式编辑任一时刻只渲染当前页签的一张主表格。页面显示当前父级路径、当前范围行数、未应用修改标记、错误数量和缺少上级选择状态。子表没有有效父级时，页面显示明确空状态并禁用新增，不自动选择第一条父级记录。
7. 九类表的新增按钮分别使用“新增数据对象”“新增对象字段”“新增数据行为关系”“新增数据来源”“新增表单”“新增表单行为关系”“新增主表或明细表”“新增表单字段”和“新增字段来源”。页面任一时刻只显示当前表格对应的一个新增按钮。
8. 表格支持单元格编辑、区域复制粘贴、键盘导航、增删与复制行、显式调整顺序、下拉选择、查找筛选、问题定位和表格内部横向滚动。新增记录时，页面清空会隐藏新行的本表筛选条件，并把焦点移到新行第一个未确认或必填单元格。
9. 每个可编辑单元格常驻显示原生输入控件。用户单击并松开鼠标后可以持续输入或切换中文输入法；普通输入不得导致当前单元格重建或丢失焦点。中文输入法组合输入尚未结束时，页面不得切换表格、重绘或抢走焦点。
10. 表格修改只存在于同一个完整文档工作副本。用户切换表格时，其他表中的修改、筛选、排序、选中行和滚动位置继续保留。用户执行“应用本次修改”后，页面检查九类表的完整候选并一次写入当前JSON；失败时当前JSON和撤销栈均不改变。
11. 页面按候选隔离业务式和表格式的选择上下文，并只使用稳定引用记录当前工作区、当前表格、父级对象、选中行和焦点列。删除或失效的引用回到最近仍有效的父级或明确空状态，不自动选择另一条记录。刷新、新建、清空和重新导入后按规则重置。
12. 步骤1至5共用现有问题来源形成连续整改队列。队列显示当前问题序号、总数、问题说明、发现位置、修改入口、上一项、下一项、暂时跳过和“重新检查并定位下一项”。草稿修改后，旧结果继续显示并标记为已过期；问题只有在重新检查后消失才算解决。“暂时跳过”只改变当前页面的浏览顺序。
13. 表格有未应用修改时，切换模式或其他会隐藏编辑上下文的操作必须选择“应用修改并继续”“放弃修改并继续”或“继续编辑”。未应用的新行不能直接交给业务式编辑展示。
14. 表格应用和批量字段引用执行异步结构检查时，页面锁定重复提交及会隐藏当前输入的操作。检查返回后，页面重新核对当前候选、JSON、编辑会话和修订状态；状态已经变化时，系统保留最新输入并拒绝旧结果。结构检查20秒未返回时，页面明确提示超时、解除锁定并保留输入供重试。
15. 弹窗或治理抽屉打开后，`Tab`和`Shift+Tab`只在视觉最上层的当前对话框内移动。关闭、取消、放弃或继续编辑后，焦点和滚动位置返回发起操作的控件；键盘焦点不得进入背景编辑区或底层弹窗。

## 四、业务规则

- 筛选、显示排序和粘贴内容缺行不表示删除。删除只能由明确的删除动作触发。
- 被其他有效记录引用的对象或字段不得删除，页面应说明原因并定位引用。
- 同名数据对象或业务行为不得按名称自动合并。需要区分时，选择器显示稳定技术标识。
- 新建数据行为关系和表单行为关系时，页面不预选业务行为。新建字段来源时，页面不预选来源类型、来源对象或来源作用。选择“本流程数据”后，编制人仍须明确选择数据对象。
- 字段来源选择“本流程数据”时，编制人必须选择数据对象和来源作用，页面清空外部系统名称和来源数据名称。选择“外部系统”时，编制人必须填写外部系统名称、来源数据名称和来源作用，页面清空本流程数据对象引用。任一条件必填项未完成时，页面保留来源草稿并阻止应用，当前JSON和撤销栈不改变。
- 表格式新增表单时，`form_design_state`使用`unspecified`；新增主表或明细区域时，`area_type`先保持空值。表单字段的“必填”在工作副本中使用“请选择／必填／非必填”，用户明确选择后才写入布尔型`required`。
- 表单字段引用对象字段后，页面只确定性带入`data_field_ref`、`business_data_ref`和`item_type`；只有表单显示名称为空时，页面才带入对象字段名称。用户已经填写的表单显示名称、填写说明、必填属性、来源关系、值使用方式和取值方式不得被覆盖；对象字段改名也不得批量改写既有表单显示名称。
- 页面不得根据对象字段的引用次数推断`value_usage_mode`或`value_origin_mode`。新建字段没有人工确认时，两项继续保持`pending_confirmation`；旧v7文件中的既有值原样保留。
- 3001不判断主数据、权威来源或业务事实。相关内容仍由有权主体确认。

## 五、非目标

- 不开发Office插件，不上传`.xlsx`文件。
- 不提供公式、合并单元格、格式设计或多工作表。
- 不改变v7 JSON字段、枚举、生命周期或迁移规则。
- 不把“必填”改为可持久化的三态字段。空值只存在于表格工作副本，应用前必须解决。
- 不根据对象字段改名批量更新表单显示名称，不按同名字符串自动合并对象或字段。
- 不增加行为参与者批量复用、关系矩阵录入、下载前问题总览重构或生命周期批量编辑。
- 不提前实施3000的持久化、权限、审计或v7迁移。
- 不在本次工作中重启、替换或发布正式端口3001。

## 六、验收标准

1. 两种模式往返编辑同一JSON，内容和稳定引用不丢失。
2. 业务式编辑只在数据对象正式入口提供对象名称、信息类型、对象字段名称、类型和定义的可编辑控件；表单区域只显示引用摘要和准确跳转入口。
3. 一次选择三个对象字段和一个目标区域后，页面一次新增三个表单字段；字段名称、所属对象和类型由引用确定，每个字段的必填属性均来自用户明确选择。
4. 目标区域、任一对象字段或文档指纹在确认前失效时，整批不写入，不遗留空区域或部分字段，并保留弹窗中的选择供用户修正。
5. 批量应用成功只形成一条撤销记录；一次撤销删除整批，一次重做恢复整批。
6. 新建关系、来源、区域和字段时没有首项、“明细清单”或“非必填”等未经确认的业务默认值。
7. 任一时刻只显示一张可编辑表格和一个对象名称明确的新增按钮；九类表的新增、修改、复制、排序、显式删除和区域粘贴可用。
8. 隐藏表存在错误时，页签显示错误数量；用户点击问题后，页面切换到正确工作区、表格、父级、行和单元格。
9. 未应用修改切换模式的三个分支均符合页面提示；应用后按稳定引用定位新实体，放弃后清理临时引用并返回有效父级。
10. 业务式、表格式和不同候选之间不串选；页面内存上下文不进入JSON、下载文件或任何浏览器持久化空间。
11. 用户修改后，步骤检查快照继续显示并标记为已过期；重新检查后，已解决问题消失，仍存在问题和新问题按稳定顺序显示。
12. v1至v6导入v7、v7重新导入、重复迁移和失败恢复保持原有结果；生命周期和迁移归档不因表格编辑改变。
13. 30个数据对象、200个对象字段、120条数据关系和10张表单的样本，主要表格操作不出现超过1秒的可感知冻结。
14. 1920×1080、1536×864和1280×720三档视口无新增控制台错误，表格只在自身容器内横向滚动。
15. 完整鼠标单击后，当前单元格可以连续输入；切换输入法的按键不被页面拦截；组合输入结束后的选词回车不移动焦点，随后明确按下的普通回车进入下一行同列。
16. 异步结构检查期间，重复应用、放弃、候选切换、步骤切换和统一三分支处理被锁定；检查期间工作副本、批量选择或当前JSON发生变化时，旧结果不写入。20秒超时后，当前JSON和撤销栈不变，输入仍在，操作锁解除，用户可以再次应用。
17. 单层和多层弹窗中的正向、反向`Tab`均不进入背景页面；顶层控件全部禁用时，焦点留在对话框容器。关闭弹窗后，焦点回到发起按钮或本次新增后的正式编辑控件。
18. 字段来源的两种来源类型均执行条件必填和互斥清理；外部系统名称、来源数据名称、来源作用或本流程数据对象缺失时，应用失败且当前JSON、撤销栈不变。
