# PRD：3001双模式网页表格编辑器

## 一、业务目标

流程编制人在步骤5既要能逐项理解和维护对象、字段、表单及关系，也要能在记录较多时直接按表格集中编辑。本次升级删除反直觉的TSV文本框，用同一份v7 JSON支撑两种操作方式，减少重复录入和模式切换造成的数据分叉。

## 二、角色与操作顺序

| 角色 | 操作 | 完成条件 |
|---|---|---|
| 编制人 | 先建立数据对象和对象字段，再维护数据行为关系、表单区域、表单字段和取值来源 | 当前JSON通过引用、技术完整性和v7完整校验 |
| 业务核对人 | 依据制度、表单、台账和实际做法核对字段含义、来源和使用方式 | 业务事实已确认，不能确认的内容保持待定 |
| MDM工作组 | 检查结构、文件名、摘要和待定事项 | 接收未审核v7文件和JSON之外的核对记录 |

## 三、功能范围

1. 业务式编辑沿用选择器和详情卡。数据对象和对象字段都可以逐项选择、编辑和删除；录入表单字段时，用户优先选择已有对象字段和主表或明细表位置，再执行“引用并添加”。页面同步对象字段的数据类型，并只在新字段的表单显示名称为空时带入对象字段名称；没有可复用对象字段时，用户可以明确选择“添加空白字段（待补引用）”。
2. 表格编辑包含两个工作区和九类表：
   - 数据工作区：数据对象、对象字段、数据行为关系、跨流程数据来源。
   - 表单工作区：表单、表单行为关系、主表与明细表、表单字段、字段取值来源。
3. 用户选择上级记录后，下方只显示对应的字段或关系。新增记录由页面生成稳定技术标识。
4. 九类表的新增按钮必须使用当前业务对象名称，不使用通用“新增行”。每个编辑区具有完整卡片边界，新增、查找和选中行操作均保留在本区内。
5. 支持单元格编辑、区域复制粘贴、键盘导航、增删与复制行、显式调整顺序、下拉选择、查找筛选、问题定位和表格内部横向滚动。新增记录时，页面清空本表查找条件，并把焦点移到新行第一个空白可编辑控件。
6. 每个可编辑单元格常驻显示原生输入控件。用户单击并松开鼠标后可以持续输入或切换中文输入法；普通输入不得导致当前单元格重建或丢失焦点。
7. 表格修改只存在于工作副本。用户执行“应用本次修改”后，页面完成全部检查并一次写入当前JSON；失败时不写入。
8. 表格有未应用修改时，切换模式必须选择应用并切换、放弃并切换或继续编辑。

## 四、业务规则

- 筛选、显示排序和粘贴内容缺行不表示删除。删除只能由明确的删除动作触发。
- 被其他有效记录引用的对象或字段不得删除，页面应说明原因并定位引用。
- 同名数据对象或业务行为不得按名称自动合并。需要区分时，选择器显示稳定技术标识。
- 表单字段引用对象字段后，字段类型从对象字段同步；只有表单显示名称为空时，页面才带入对象字段名称。用户已经填写的表单显示名称及已经确认的值使用方式、取值方式不得被覆盖；对象字段改名也不得批量改写既有表单显示名称。
- 3001不判断主数据、权威来源或业务事实。相关内容仍由有权主体确认。

## 五、非目标

- 不开发Office插件，不上传`.xlsx`文件。
- 不提供公式、合并单元格、格式设计或多工作表。
- 不改变v7 JSON字段、枚举、生命周期或迁移规则。
- 不提前实施3000的持久化、权限、审计或v7迁移。

## 六、验收标准

1. 两种模式往返编辑同一JSON，内容和稳定引用不丢失。
2. 九类表的新增、修改、复制、排序、显式删除和区域粘贴可用。
3. 任一引用、枚举、标识或完整结构错误导致整批不写入；成功应用形成一次整体撤销。
4. 未应用修改切换模式的三个分支均符合页面提示。
5. v1至v6导入v7、v7重新导入、重复迁移和失败恢复保持原有结果；生命周期和迁移归档不因表格编辑改变。
6. 30个数据对象、200个对象字段、120条数据关系和10张表单的样本，主要表格操作不出现超过1秒的可感知冻结。
7. 1920×1080、1536×864和1280×720三档视口无新增控制台错误，表格只在自身容器内横向滚动。
8. 完整鼠标单击后，当前单元格可以连续输入；切换输入法的按键不被页面拦截；组合输入结束后的选词回车不移动焦点，随后明确按下的普通回车进入下一行同列。
9. 业务式编辑选择对象字段和添加位置后，只新增一个表单字段；名称和类型自动带入，用户自定义的表单显示名称保持不变。
10. 九个新增按钮名称均能明确表示所属对象；相邻编辑区不重叠，点击新增后焦点位于本区新行。存在查找条件时，页面先清空本表查找，再显示并聚焦新行。
