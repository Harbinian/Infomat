# 测试计划：3001双模式网页表格编辑器

## 一、自动化

| 范围 | 检查内容 |
|---|---|
| 表格内核 | 工作副本不修改源JSON、显式删除、恢复、复制、顺序、来源指纹冲突、接受与放弃 |
| 九类表 | 新增、修改、复制、显式删除、区域替换和完整候选文档生成 |
| 引用与枚举 | 重复标识、无效枚举、跨对象或跨表单移动、字段归属、来源引用、多个创建行为、重复关系 |
| 重名 | 数据对象和业务行为重名只提示并按技术标识保持引用，不自动合并 |
| 原子应用 | 任一错误不写入；成功应用只形成一条撤销记录，一次撤销恢复全部内容 |
| 顺序 | 筛选和显示排序不修改JSON顺序；显式调整后往返顺序稳定 |
| 内容保持 | 生命周期、迁移归档和九类表之外的v7内容保持不变 |
| 前端约定 | 双模式入口、两个工作区、九类表、中文输入法组合状态、回车后连续定位、三个切换分支、本地静态资源和无浏览器持久化 |

## 二、迁移回归

执行现有3001完整测试，覆盖v1至v6导入v7、v7导出后重新导入、重复迁移和失败恢复。迁移失败不得改变当前候选、撤销记录或用户源文件。

## 三、性能

使用30个数据对象、200个对象字段、120条数据行为关系和10张表单的样本，测量适配层读取、工作副本修改和完整候选生成。单次主要操作门槛为1秒以内；真实浏览器同时观察编辑、筛选、选择上级和工作区切换。

## 四、真实浏览器

分别在1920×1080、1536×864和1280×720内容可视区检查：

1. 新会话首次进入步骤5默认业务式编辑。
2. 业务式编辑对象字段后，进入表格编辑能看到同一内容。
3. 表格修改在应用前不出现在业务式编辑；应用后立即同步。
4. 未应用修改切换模式的应用、放弃和继续编辑三个分支。
5. 单元格编辑、中文输入法组合输入、普通回车后连续定位、键盘、区域粘贴、下拉框、筛选、显式排序、删除保护和问题定位。
6. 长文本、表格内部横向滚动、页面无意外横向溢出和控制台零新增错误。

## 五、发布门槛

依次执行`npm.cmd test`、`npm.cmd audit --json`、`git diff --check`、独立候选端口根页和`/api/health`检查、三档真实浏览器验证。全部通过且工作树干净后，只替换端口3001服务，再检查正式根页和`/api/health`。软件发布只表示技术版本可供使用中验证，不代表真实流程业务验收通过。
