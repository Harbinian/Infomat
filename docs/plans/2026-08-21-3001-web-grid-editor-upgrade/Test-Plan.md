# 测试计划：3001双模式网页表格编辑器

## 一、自动化

| 范围 | 检查内容 |
|---|---|
| 表格内核 | 工作副本不修改源JSON、显式删除、恢复、复制、顺序、来源指纹冲突、接受与放弃 |
| 九类表 | 新增、修改、复制、显式删除、区域替换和完整候选文档生成 |
| 对象字段复用 | 新表单字段引用对象字段后补齐空白名称并同步类型；自定义表单显示名称不覆盖；既有空名称记录不静默改写；补齐只发生在表格工作副本 |
| 引用与枚举 | 重复标识、无效枚举、跨对象或跨表单移动、字段归属、来源引用、多个创建行为、重复关系 |
| 重名 | 数据对象和业务行为重名只提示并按技术标识保持引用，不自动合并 |
| 原子应用 | 任一错误不写入；成功应用只形成一条撤销记录，一次撤销恢复全部内容 |
| 顺序 | 筛选和显示排序不修改JSON顺序；显式调整后往返顺序稳定 |
| 内容保持 | 生命周期、迁移归档和九类表之外的v7内容保持不变 |
| 前端约定 | 双模式入口、两个工作区、九类表、九个对象化新增名称、独立卡片和标题关联、新增后焦点、查找状态新增、常驻原生输入控件、中文输入法组合状态、回车后连续定位、三个切换分支、本地静态资源和无浏览器持久化 |

## 二、迁移回归

执行现有3001完整测试，覆盖v1至v6导入v7、v7导出后重新导入、重复迁移和失败恢复。迁移失败不得改变当前候选、撤销记录或用户源文件。

## 三、性能

使用30个数据对象、200个对象字段、120条数据行为关系和10张表单的样本，测量适配层读取、工作副本修改和完整候选生成。单次主要操作门槛为1秒以内；真实浏览器同时观察编辑、筛选、选择上级和工作区切换。

## 四、真实浏览器

分别在1920×1080、1536×864和1280×720内容可视区检查：

1. 新会话首次进入步骤5默认业务式编辑。
2. 业务式编辑对象字段后，进入表格编辑能看到同一内容。
3. 业务式编辑选择已有对象字段和添加位置后，只新增一个表单字段并带入空白名称和类型；修改表单显示名称后，对象字段改名不得覆盖该名称。
4. 表格修改在应用前不出现在业务式编辑；应用后立即同步。
5. 未应用修改切换模式的应用、放弃和继续编辑三个分支。
6. 九个新增按钮名称与所在编辑区一致；相邻卡片不重叠；新增按钮完整位于所属卡片；点击后只有目标表按既有规则新增，焦点进入本区新行。
7. 本表存在不匹配新空行的查找词时，点击新增会清空本表查找，显示新行，并优先聚焦第一个空白可编辑控件。
8. 单元格编辑、中文输入法组合输入、普通回车后连续定位、键盘、区域粘贴、下拉框、筛选、显式排序、删除保护和问题定位。
9. 长文本、表格内部横向滚动、页面无意外横向溢出、浏览器存储为空和控制台零新增错误。

真实浏览器自动化必须使用一次完整的鼠标单击后再输入，不能用持续按住鼠标模拟编辑。自动化可以验证`compositionstart`、`compositionend`、`isComposing`和`keyCode 229`事件顺序，但不能调出操作系统中文输入法候选窗；正式验收时必须如实区分事件级回归和人工输入法实测。

## 五、发布门槛

依次执行`npm.cmd test`、`npm.cmd audit --json`、`git diff --check`、独立候选端口根页和`/api/health`检查、三档真实浏览器验证。全部通过且工作树干净后，只替换端口3001服务，再检查正式根页和`/api/health`。软件发布只表示技术版本可供使用中验证，不代表真实流程业务验收通过。

## 六、统一切换保护补充

网页表格继续保留独立工作副本和`SOURCE_CHANGED`整文档防覆盖检查，但模式切换不再使用一套只服务于表格的规则。测试必须证明网页表格与业务行为属性、流程关系属性、数据对象属性、数据行为操作和关系向导共用同一切换保护。

- 表格存在未应用修改时，切换步骤、对象、候选、视图，或执行撤销、重做、新建、导入、清空和下载，均显示应用、放弃和继续编辑三项结果。
- 选择应用时，表格通过引用、技术完整性、完整v7校验和来源指纹检查后才写入当前JSON；失败时保留工作副本并取消目标操作。
- 选择放弃时，只清除表格工作副本，当前JSON保持不变；选择继续编辑时，页面恢复原候选、滚动位置和当前单元格焦点。
- 顶部候选下拉框和侧栏候选按钮执行相同结果；取消顶部切换后，下拉框恢复原候选。
- 表格内容应用后属于未下载修改，不得显示“当前内容已下载”。下载成功后，只把实际进入文件的JSON设置为新基线。
- 真实浏览器分别覆盖中文输入法组合输入、`compositionend`后紧随的回车、三项保护后的焦点恢复和三档视口模态框无遮挡。
