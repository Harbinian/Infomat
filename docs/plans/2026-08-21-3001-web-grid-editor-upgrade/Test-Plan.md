# 测试计划：3001重复劳动与编辑焦点减负

## 一、自动化

| 范围 | 检查内容 |
|---|---|
| 编辑会话 | 打开、修改、应用、放弃、重置、候选隔离、来源冲突时零部分写入，以及统一弹窗的“应用修改并继续／放弃修改并继续／继续编辑”三个分支 |
| 表格内核 | 工作副本不修改源JSON、显式删除、恢复、复制、顺序、来源指纹冲突、接受与放弃；九张表共用一个完整文档工作副本 |
| 九类表 | 新增、修改、复制、显式删除、区域替换、完整候选文档生成、单面板切换、各表独立筛选和选中状态，以及隐藏表错误定位 |
| 对象字段复用 | 只派生`data_field_ref`、`business_data_ref`、`item_type`和空白`item_name`；不覆盖自定义显示名称，不推断权威录入、沿用已有值或取值方式；第一、第二和第N次引用结果一致 |
| 批量规划 | 三个字段一次添加、一个新明细表、稳定顺序、独立`item_ref`、每项明确的布尔型`required`、同批重复字段拒绝、目标或字段失效时零写入，以及一次撤销和一次重做 |
| 选择上下文 | 父子稳定引用归一化、父级删除后清理、双模式同步、候选隔离、各表视图状态恢复，以及上下文不进入JSON或浏览器存储 |
| 问题队列 | 规则编码与稳定引用组成唯一身份、同文案不同对象分别保留、修改后快照过期、重新检查移除已解决项、跳过不等于解决，以及隐藏表问题定位 |
| 表格适配器 | 新增关系的`behavior_ref`为空；新增来源的`source_type`、`source_data_ref`和`source_role`为空；表单状态为`unspecified`；区域类型为空；`required`未选择时应用失败，明确选择后成功；两类字段来源执行条件必填和互斥清理 |
| 引用与枚举 | 重复标识、无效枚举、跨对象或跨表单移动、字段归属、来源引用、多个创建行为、重复关系；`data_field_ref`跨对象分组选择，所属对象和类型的只读约束不能被输入、粘贴、批量输入或复制行绕过 |
| 重名 | 数据对象和业务行为重名只提示并按技术标识保持引用，不自动合并 |
| 原子应用 | 任一错误不写入；成功应用只形成一条撤销记录，一次撤销恢复全部内容 |
| 异步应用安全 | 表格应用期间锁定重复提交、放弃和切换；批量字段应用期间锁定全部选择、快捷设置、确认和取消；校验返回后重新比较候选、JSON指纹、会话对象／令牌、会话修订和补丁指纹，旧结果零写入 |
| 校验超时 | 使用可控挂起的`POST /api/validate`验证20秒后请求中止、当前JSON与撤销栈不变、工作副本或批量选择保留、操作锁解除、可以重试，迟到结果不能写入 |
| 模态焦点 | 单层及多层弹窗的正向／反向`Tab`只在最上层循环；顶层控件全部禁用时焦点落在对话框容器；关闭、取消、放弃、继续编辑和确认后按稳定引用恢复焦点 |
| 顺序 | 筛选和显示排序不修改JSON顺序；显式调整后往返顺序稳定 |
| 内容保持 | 生命周期、迁移归档和九类表之外的v7内容保持不变 |
| 服务装配 | 字段复用、选择上下文、问题队列和编辑会话脚本装载顺序正确；旧弹窗标识不存在；新测试进入`npm test`主测试链 |
| 前端约定 | 双模式入口、两个工作区、九类表、单面板、九个对象化新增名称、父级路径、页签行数与错误数、新增后焦点、查找状态新增、常驻原生输入控件、中文输入法组合状态、回车后连续定位、本地静态资源和无浏览器持久化 |

重点输入组合包括：

- 两个数据对象存在同名字段，选择结果不得串到另一对象。
- 已填写表单显示名称后切换对象字段，页面不得覆盖显示名称。
- 已经在当前或其他表单使用的字段默认不勾选，但用户明确选择后可以再次引用。
- 选择`process_data`后，页面不得自动选择第一个数据对象。
- `process_data`缺少数据对象或来源作用时应用失败；`external_system`缺少外部系统名称、来源数据名称或来源作用时应用失败。两种来源类型切换后，不适用字段被清理，失败前后当前JSON和撤销栈不变。
- 新增行前存在会隐藏新行的筛选条件时，页面清除该条件并定位新行。
- 表格切换后，工作副本、筛选、排序、选中行和滚动位置不得丢失。

## 二、迁移回归

执行现有3001完整测试，覆盖上一受支持版本导入当前版本、当前版本导出后重新导入、重复迁移和迁移失败后恢复当前草稿。迁移失败不得改变当前候选、撤销记录或用户源文件。

另增加以下兼容样本：

- 只有`business_data_ref`、没有`data_field_ref`的旧v7表单字段；
- 已确认`value_usage_mode`和`value_origin_mode`的旧v7表单字段；
- `data_field_ref`失效或对象归属错配的旧v7表单字段；
- 批量新增后导出并重新导入；
- 表格应用失败后放弃工作副本，并恢复到应用前状态。

## 三、性能

使用30个数据对象、200个对象字段、120条数据行为关系和10张表单的样本，测量适配层读取、工作副本修改和完整候选生成。单次主要操作门槛为1秒以内；真实浏览器同时观察编辑、筛选、选择上级和工作区切换。

## 四、真实浏览器

分别在1920×1080、1536×864和1280×720内容可视区检查：

1. 候选端口根页完整渲染，页面脚本和静态资源加载成功，控制台不存在旧弹窗变量造成的`ReferenceError`。
2. 新会话首次进入步骤5默认业务式编辑。页面不自动选择第一个数据对象、表单或业务行为。
3. 编制人在数据对象正式入口建立三个对象字段后，表单区域只显示引用摘要和“修改对象定义”，不显示第二套对象名称、信息类型、字段名称、类型和定义输入控件。
4. 批量弹窗一次选择三个字段和一个目标区域。页面要求逐项明确必填属性，不预选主表、明细表或“非必填”。一次应用新增三项，一次撤销全部移除，一次重做全部恢复。
5. 任一对象字段或目标区域失效时，整批失败且当前JSON深比较不变；快速双击确认不得生成重复批次。失败后，弹窗保留已选字段、目标区域和必填设置。
6. 第一次、第二次和后续引用均不自动改变`value_usage_mode`或`value_origin_mode`。已有表单显示名称、填写说明、必填属性和来源关系不得被覆盖。
7. 表格式编辑任一时刻只显示当前页签的一张主表格和一个新增按钮。九个新增按钮名称与当前表格一致，父级路径持续可见，下一页签的新增操作不得靠近当前输入焦点。
8. 子表缺少有效父级时，页面显示空状态并禁用新增。父级在工作副本中标记删除后，页面不得继续新增子项。
9. 本表存在会隐藏新空行的查找条件时，点击新增会清除该条件，显示新行，并聚焦第一个未确认或必填单元格。
10. 隐藏表存在错误时，页签显示错误数量；点击错误后，页面切换到正确工作区、表格、父级、行和单元格。
11. 表格修改在应用前不出现在业务式编辑；应用后立即同步。切换表格不会应用或丢弃其他表中的工作副本修改、筛选、排序、选中行和滚动位置。
12. 未应用修改切换模式的应用、放弃和继续编辑三个分支符合提示。应用成功后定位新实体；放弃后清理临时引用并回到有效父级。
13. 业务式、表格式和不同候选之间不串选。刷新、新建、清空和重新导入后，页面按规则重置选择上下文。
14. 执行“检查本轮”后修改草稿，旧问题继续显示并标记为已过期；“重新检查并定位下一项”移除已解决问题并定位下一项；“暂时跳过”不改变JSON，也不把问题标为解决。
15. 表格存在未应用修改时，问题队列明确提示“表格修改尚未应用”；表格工作副本错误继续显示在页签和单元格。
16. 单元格编辑、中文输入法组合输入、普通回车后连续定位、键盘、区域粘贴、下拉框、筛选、显式排序、删除保护和问题定位均可用。
17. 三档视口均无页面级横向溢出。表格只在自身容器内滚动，父级路径和当前新增操作持续可见。
18. `localStorage`、`sessionStorage`、IndexedDB和Cookie不保存业务内容；网络记录中不存在对3000的请求；控制台warning和error均为0。
19. 延迟结构校验期间，重复应用、放弃、候选切换、步骤切换和统一三分支处理均被阻止；工作副本或批量选择在等待期间失效时，旧结果不写入，当前JSON和撤销栈深比较不变。
20. 实际挂起校验请求达到20秒后被中止；页面保留工作副本或批量字段选择，解除全部操作锁并显示可执行提示。恢复正常校验后，用户不重新录入即可再次应用；超时请求的迟到结果不能写入。
21. 单层弹窗连续执行正向和反向`Tab`；批量字段弹窗上再打开统一保护弹窗时，焦点只停在顶层。顶层按钮全部禁用时，焦点停在对话框容器；关闭、继续编辑、放弃和确认后回到原按钮或本次新增后的正式字段。
22. 字段来源分别验证本流程数据和外部系统：每个条件必填项缺失时零写入，来源类型切换时不适用字段被清理，明确填写后可以应用。

真实浏览器自动化必须使用一次完整的鼠标单击后再输入，不能用持续按住鼠标模拟编辑。自动化可以验证`compositionstart`、`compositionend`、`isComposing`和`keyCode 229`事件顺序，但不能调出操作系统中文输入法候选窗；正式验收时必须如实区分“事件级自动化已验证”和“Windows候选窗人工验收”，未执行人工操作时明确记录为待验收。

## 五、本轮验证门槛

依次执行`npm.cmd test`、`npm.cmd audit --json`、`git diff --check`、独立候选端口根页和`/api/health`检查，以及三档真实浏览器验证。候选端口的`/api/health`必须返回`ok`、`schema_version=process-governance-v7`和`release_status=released`。静态测试必须标明是纯逻辑测试还是源码装配断言；异步超时、模态焦点和操作锁至少取得一次真实浏览器运行时证据。验证记录只能在取得实际结果后追加，不得预写“已通过”。

本轮验证不停止、重启或替换正式端口3001。正式3001的发布和重启需要后续明确授权，并另行执行正式根页、健康检查和回退核对。技术验证通过不代表真实流程业务验收通过。

## 六、统一切换保护补充

网页表格继续保留独立工作副本和`SOURCE_CHANGED`整文档防覆盖检查，但模式切换不再使用一套只服务于表格的规则。测试必须证明网页表格与业务行为属性、流程关系属性、数据对象属性、数据行为操作和关系向导共用同一切换保护。

- 表格存在未应用修改时，切换步骤、对象、候选、视图，或执行撤销、重做、新建、导入、清空和下载，均显示应用、放弃和继续编辑三项结果。
- 选择应用时，表格通过引用、技术完整性、完整v7校验和来源指纹检查后才写入当前JSON；失败时保留工作副本并取消目标操作。
- 选择放弃时，只清除表格工作副本，当前JSON保持不变；选择继续编辑时，页面恢复原候选、滚动位置和当前单元格焦点。
- 顶部候选下拉框和侧栏候选按钮执行相同结果；取消顶部切换后，下拉框恢复原候选。
- 表格内容应用后属于未下载修改，不得显示“当前内容已下载”。下载成功后，只把实际进入文件的JSON设置为新基线。
- 真实浏览器分别覆盖中文输入法组合输入、`compositionend`后紧随的回车、三项保护后的焦点恢复和三档视口模态框无遮挡。
- 多层弹窗验收不能只检查视觉无遮挡，还必须证明正向和反向`Tab`不能进入底层弹窗或背景编辑区；顶层控件禁用期间仍须保留对话框焦点。
- 校验期间不得只依赖按钮禁用；测试还要在等待期间改变工作副本修订或使批量会话失效，确认旧异步结果被拒绝且最新输入仍在。
