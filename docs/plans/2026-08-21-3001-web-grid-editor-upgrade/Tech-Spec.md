# 技术方案：3001双模式网页表格编辑器

## 一、事实来源与状态边界

当前候选的`process-governance-v7` JSON是步骤5唯一业务数据。业务式编辑直接修改当前JSON；表格编辑从当前JSON生成工作副本。工作副本不写入浏览器存储，刷新、放弃、导入其他文件、切换候选或服务重启后清除。

```text
当前v7 JSON
  ├─ 业务式编辑：直接修改并刷新页面
  └─ ProcessV7GridAdapter.read
       → WebGridCore工作副本
       → NativeWebGrid与常驻原生输入控件
       → 引用检查与技术完整性检查
       → POST /api/validate
       → 一次替换当前v7 JSON
       → 一条整体撤销记录
```

## 二、模块边界

### 1. WebGridCore

`public/web-grid-core.js`只管理表格定义、工作副本、稳定行标识、显式删除、顺序、差异、来源版本检查、应用和放弃。它不认识v7字段，不调用业务接口。

通过JSDoc固定三个复用接口：

- `GridTableDefinition`：表格标识、列、编辑器、引用选择器和父级过滤规则。
- `GridIssue`：表格、行、列、严重程度、错误码、用户提示和JSON定位路径。
- `GridCommitDriver`：取得当前文档及版本指纹、校验完整候选文档、提交完整候选文档。

### 2. ProcessV7GridAdapter

`public/process-v7-grid-adapter.js`负责v7 JSON与九类表之间的双向映射、稳定技术标识、枚举、父子引用、跨上级移动保护、显式删除保护、字段类型同步、候选文档和差异摘要。

适配层保留不属于表格范围的字段，包括生命周期、迁移归档、流程基本信息、业务行为、流程关系和术语。它不推断主数据、权威来源或业务事实。

### 3. 页面提交驱动

3001提交驱动取得当前JSON及指纹，调用现有技术引用检查和`/api/validate`，再通过现有撤销管理器一次替换完整候选文档。表格打开后如果当前JSON指纹变化，应用返回来源冲突，要求重新生成工作副本。

未来3000可以实现独立提交驱动，携带`expected_revision`保存MySQL草稿，并继续执行权限、并发和审计检查。本次不实现该驱动，也不让3000依赖3001服务。

### 4. NativeWebGrid

`public/native-web-grid.js`只处理输入法组合事件、剪贴板二维数据、粘贴值转换、区域边界和复制文本。页面直接渲染常驻的原生`input`、`textarea`和`select`，并通过事件委托更新`WebGridCore`工作副本。普通输入不调用整页`render()`，选择上级记录只刷新下级表格。

## 三、原生表格边界与Tabulator退役决定

- 2026-08-24确认原Tabulator实现不适合3001。Tabulator的临时单元格编辑器与3001按上级记录刷新下级表格的机制冲突；鼠标按下后建立的编辑器会在行选择触发重绘时被销毁，表现为用户只有持续按住鼠标才能输入。临时编辑器的建立和销毁也无法稳定承接Windows中文输入法事件顺序。
- 3001已删除`tabulator-tables`依赖、JS/CSS静态路由、旧编辑器封装和对应许可文件，不保留备用入口。
- 单击输入控件同时确定当前行和当前区域起点；普通输入只修改工作副本。按住Shift再单击可以扩展区域，粘贴多行多列时一次更新工作副本。
- 输入法切换按键不拦截。组合输入期间和组合结束后紧随的选词回车保持当前单元格；随后明确按下的普通回车进入下一行同列，没有下一行时保持当前焦点。
- 技术标识默认隐藏或只读；发生重名时，引用选择器显示技术标识用于区分。
- 显示排序不修改`_order`；只有上移、下移等显式顺序动作修改业务数组顺序。

交互依据包括飞书官方帮助中“选择单元格”与“双击进入编辑状态”的区分，以及本仓库`apps/information-collection-service/public/respondent/app.js`中4001明细表常驻原生输入控件的实现。飞书参考：[设置单元格局部内容样式](https://www.feishu.cn/hc/zh-CN/articles/947298221311-%E4%B8%BA%E5%8D%95%E5%85%83%E6%A0%BC%E5%86%85%E7%9A%84%E5%B1%80%E9%83%A8%E5%86%85%E5%AE%B9%E8%AE%BE%E7%BD%AE%E6%A0%B7%E5%BC%8F/)、[插入或删除行列和单元格](https://www.feishu.cn/hc/zh-CN/articles/360049067459-%E5%9C%A8%E8%A1%A8%E6%A0%BC%E4%B8%AD%E6%8F%92%E5%85%A5%E6%88%96%E5%88%A0%E9%99%A4%E8%A1%8C-%E5%88%97%E5%92%8C%E5%8D%95%E5%85%83%E6%A0%BC)。3001没有照搬双击模式，而是采用常驻输入控件，因为其业务表格更接近表单填报，不是通用电子表格。

## 四、校验与失败恢复

应用顺序固定为：

1. 检查来源指纹是否仍与表格打开时一致。
2. 检查必填值、枚举、技术标识、父子关系、字段归属、关系冲突和删除引用。
3. 生成完整v7候选文档并执行现有技术完整性检查。
4. 调用`POST /api/validate`执行完整结构校验。
5. 全部通过后一次替换当前JSON并写入一条撤销记录。

任一步失败时，当前JSON、撤销栈和源文件保持不变；表格工作副本和问题定位继续保留。用户可以修正后再次应用，或明确放弃。

## 五、旧数据影响

本次不改变v7结构，不新增迁移步骤。v1至v6和历史结构化文件仍按既有迁移模块在页面内存中转换为v7，再由适配层读取。表格应用不得重写生命周期、迁移归档或不在九类表范围内的内容。
