## 6. 实施阻断清单

以下任一事项未关闭时，不得批量生成新码、修改 U8 或宣布上线：

- [ ] `P0-01` 编码结构获得具名批准；
- [ ] `P0-02`、`P0-03` 技术判断和编码控制责任获得批准；
- [ ] 物料、服务、工装、量具、设备、资产和虚拟节点的对象边界通过样例评审；
- [ ] 14 字符编码通过 U8 全部接口、PLM/PDM/CPM、工艺、MES、标签和扫码验证；
- [ ] 采购、收货、库存、批次、序列、生产、实耗、实装、质量和 BOM 表族完成只读盘点；
- [ ] 旧码映射形成一对一、一对多、多对一和无法判断的处理规则；
- [ ] 迁移完成备份、dry-run、幂等、失败回退、数量、关键字段和引用核对设计；
- [ ] 至少完成上一受支持版本导入、当前格式回导、重复执行、失败恢复四类验证；
- [ ] 业务用户完成代表性样例验收；
- [ ] 发布记录明确“已实现、已准备、已开启、已验收”的实际状态。

## 7. 评审建议议程

评审会议按以下顺序逐项收口，避免把多个分支混在一次讨论中：

1. 先批准或否决“编码只标识稳定物料身份”；
2. 再批准或否决 `MAT-10位全局流水`；
3. 再确认物料与服务、工装、量具、设备、资产的对象边界；
4. 再用真实样例确认新物料和新修订的分界；
5. 再确认用途、供给、所有权、批次/序列和替代的关系模型；
6. 最后确认职责、系统承接、旧码映射和分阶段实施。

每个议题只接受三类结果：批准、否决并给出替代方案、补证后再议。不得用“原则同意”替代具体边界、责任和生效条件。
