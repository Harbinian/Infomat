# 技术方案：3001 v7数据生命周期

## 1. 数据结构

`data_objects[].fields[]`是当前单流程内对象字段的唯一结构位置。每个对象字段固定包含`field_ref`、`field_name`、`field_type`和`definition`。`forms[].areas[].items[]`通过`data_field_ref`引用对象字段，并使用`value_usage_mode`记录权威录入、引用已有值、计算生成、外部来源或待确认。表单项继续单独保存主表或明细表位置、必填、填写说明和顺序。

`data_field_ref`必须引用`business_data_ref`所指数据对象下的字段，表单项字段类型必须与对象字段一致。对象字段名称或类型变化时，页面同步更新引用项的显示值；被表单引用的对象字段禁止删除。对象字段技术引用只在当前文件内有效，不参与跨流程身份认定。

`data_objects[].lifecycle`是对象级生命周期唯一结构位置，包含：

- `applicability`：适用、不适用或待确认；
- `entry_state`：对象进入本流程时的三个状态维度；
- `routes[]`：引用既有流程关系的路径、路径事件和出口状态；
- `analysis`：分析器版本、来源指纹和最近一次分析结果摘要。

`routes[].flow_relation_refs[]`只能引用`flow_relations[].relation_ref`。事件不能脱离数据对象和路径存在。路径标识是技术引用，不表示跨流程身份。

事件核对状态固定为`auto_generated`、`pending_confirmation`、`confirmed`、`needs_recheck`、`not_applicable`或`rejected`。`confirmed`、`not_applicable`和`rejected`受保护；重新分析不得静默覆盖。来源变化时，原确认值保留并转为`needs_recheck`。

## 2. 状态和动作

业务效力、保管状态和可识别性分别记录。事件结果显式填写三个维度，未变化的维度沿用路径前态。销毁和不可逆匿名化是高风险动作；`target_scope=all_records`也属于高风险。高风险事件只能处于待确认、已确认、需要重新核对、已否决或不适用状态，不能自动确认。

结构校验负责枚举、必填和引用完整性。前端确定性校验负责动作前后状态是否合理，例如只有停用状态才能重新启用。业务材料没有提供完整前态时保留待确认，不能补写默认事实。

## 3. 确定性分析器

`lifecycle-analyzer.js`不调用网络、AI、3000或服务端会话。输入仅为当前文档和数据对象引用，输出包含：

- 规范化来源指纹；
- 生命周期事件候选；
- 主数据认定提示及判断依据；
- 需要重新核对的既有事件引用。

规则优先级为用户受保护事实、明确结构关系、业务行为说明、弱关键词。明确且唯一的可逆动作可以生成`auto_generated`事实；高风险、冲突、多义或复杂条件只能生成`pending_confirmation`建议。合并键由对象、路径、动作和来源组成，保证重复分析幂等。

## 4. 页面状态

“数据流”和“生命周期”共用对象选择。视图切换只改变呈现，不复制对象事实。对象属性面板显示主数据认定提示，提供查看依据、补充对象事实和列入交接待定事项入口，不提供“确认是主数据”。

分析器先把同一对象、业务行为和生命周期动作的多字段线索合并为一个事件。待确认、需要重新核对和高风险事件默认展开核对区；用户集中处理触发方式、条件组合、作用范围、载体范围、责任、例外处理和动作完成状态，不需要返回每个业务行为重复定义数据。

对象字段编辑器位于数据对象下，表单编辑器只允许从所属对象的字段中选择。首次引用对象字段时默认`authoritative_input`，后续引用默认`reuse_existing`；用户可以改为计算生成、外部来源或待确认。页面对同一对象字段存在多个权威录入位置、仅有引用但没有建立位置，以及同名不同类型字段给出非阻断提示。3001不得根据表单顺序擅自更换用户已确认的权威录入位置。

页面内存是唯一草稿状态。导入采用候选副本：迁移、v7结构校验和引用校验全部通过后才替换当前草稿。失败时保留当前草稿、选中对象、撤销记录和下载基线。

## 5. 失败与回退

- 分析失败：保留原生命周期内容，显示对象级错误，不清空用户确认。
- 导入失败：不替换当前页面状态，不修改源文件。
- 服务回退：保留用户已下载的v7文件，待v7恢复后重导；不生成v6降级文件。
- 3000未兼容：页面和下载说明明确标注“v7文件暂不能直接导入3000”。
