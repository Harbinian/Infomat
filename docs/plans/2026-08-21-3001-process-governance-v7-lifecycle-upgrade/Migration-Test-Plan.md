# 迁移测试计划：3001 v7

## 1. 自动化样本

- v1至v6各迁移到v7，核对结构版本、稳定引用、业务内容、对象字段、表单引用、值使用方式和待确认生命周期容器。
- 同一对象内同名同类型表单字段归为同一对象字段，首个直接采集位置为权威录入，后续依赖位置引用已有值。
- 同名不同类型字段分别生成对象字段；跨对象同名字段不归并。
- 早期不含对象字段的v7候选补齐字段引用，同时保留既有生命周期和人工决定。
- 构造断裂对象字段引用、跨对象引用和字段类型不一致，核对v7校验拒绝。
- 旧v7数据行为关系缺少`updated_field_refs`时，迁移在副本中补为空数组，源对象保持不变；用户已选择的更新字段在重复迁移和重导入后保持不变。
- 更新字段引用其他数据对象或不存在字段时校验拒绝；非更新操作清空更新字段；空更新字段保持为可定位的业务提示。
- v7下载后重新导入，核对已确认、待确认、需要重新核对、不适用和已否决内容。
- 同一输入重复迁移和重复分析，核对不重复创建事件或路径。
- 对源对象做深度快照，核对迁移和失败路径均未修改源对象。
- 构造非法枚举、断裂路径引用和高风险自动确认，核对v7校验拒绝。
- v1、v2和v3分别覆盖仅行为侧数据引用、仅数据对象侧数据引用、双方一致、多个输出和双方生产冲突；核对可确定引用不丢，冲突保持待确认。
- 早期v7仅缺四类后增字段时迁移通过；叠加非法枚举、额外字段、断裂引用或重复技术标识时整批拒绝，并保持当前页面状态。
- 新建和复用数据关系第一次迁移即包含`updated_field_refs`；字段归并改写更新字段引用；第一次与第二次迁移、下载重导入结果一致。
- 网页表格、图编辑和服务端分别拒绝把数据或表单关系改指开始、结束、判断、并行拆分或并行汇聚节点；失败不写回当前JSON。
- HTTP覆盖未知版本、畸形JSON、无`Content-Length`的超限正文、超深对象、超长文字、异常Unicode、错误DOCX、路径越界和重复错误去重；所有响应为稳定JSON且不含内部详情。

## 2. 流程图形态

- 分支：同一对象的不同出口路径保留不同事件和出口状态。
- 并行：路径引用既有并行关系，不合并成单一路径结论。
- 循环：允许路径引用循环关系，分析合并键保证不无限递归、不重复生成；非回路关系形成闭环时，每条提示显示起点和终点，点击后定位对应终点节点。
- 大流程：使用代表性对象和行为数量检查分析耗时、页面响应和事件列表可读性。

## 3. 失败恢复

- 导入前建立含未下载修改、当前对象选择和撤销记录的草稿。
- 导入非法文件，确认上述状态保持不变。
- 修复文件后重新导入，确认只在全部校验通过后替换草稿。
- 服务回退到v6时，不生成降级文件；恢复v7后重新导入原v7文件。

## 4. 浏览器验收

在1280×720、1536×864和1920×1080三档视口检查：七步导航、对象字段编辑、更新字段多选弹窗及回填、两张表单引用同一对象字段、权威录入与引用已有值自动选择、数据视图切换、对象属性面板、闭环提示定位终点节点、主数据提示、生命周期事件核对、下载提示、页面级横向溢出、长文本和控制台错误。正式结论记录实际浏览器和服务提交，不以本文档代替测试结果。

## 5. 生命周期纯读取与对象属性保护补充

本节是当前测试计划的补充要求，不改写既有迁移结论或历史验证证据。

- 数据流/生命周期切换、选择当前数据对象、展开生命周期详情、展开主数据提示依据和普通页面重绘前后，分别比较JSON指纹、未下载状态和撤销记录数量；三项必须保持不变。
- 对象缺少生命周期结构时，渲染只能使用只读临时默认值，不得补写当前JSON。
- “重新分析当前对象”和“重新分析全部对象”结果有变化时，一次操作只形成一次撤销记录；结果无变化时不增加撤销记录或未下载状态。分析失败时，当前JSON保持不变。
- 修改对象名称、说明或信息类型但不应用，然后切换生命周期。页面必须先提供应用、放弃和继续编辑三项保护。继续编辑后保留输入；应用后只合并这三个允许字段；放弃后恢复已应用值。
- 生命周期视图中的“返回数据流编辑对象信息”必须返回同一对象，不得重新克隆旧对象。数据对象属性卡不得出现控件可编辑但没有有效编辑会话的状态。
- 主数据认定提示存在未应用对象属性时，必须说明当前提示仍依据已应用内容。“列入交接待定事项”不得出现，也不得产生候选间共享的临时状态。
