# 迁移映射：v1至v7到process-governance-v7

## 1. 通用规则

- 原有流程、行为、流程关系、数据对象、表单、术语和迁移归档按v6既有规则保留。
- `schema_version`统一升级为`process-governance-v7`。
- 每个数据对象新增`lifecycle`。旧文件没有生命周期事实时，`applicability`和入口状态全部为待确认，`routes`为空。
- 每个数据对象新增`fields[]`。同一对象内，字段名称去除首尾空白并统一比较形式后完全相同且类型相同的旧表单字段归为一个对象字段；不同对象之间不得归并。
- 每个表单项新增`data_field_ref`和`value_usage_mode`。既有`business_data_ref`确定字段所属对象；无法确定归属时保留空引用和待确认，不跨对象猜测。
- 同名不同类型字段分别生成对象字段并保留原类型，页面提示业务人员核对，不自动合并。
- 既有取值来源表示当前表单直接采集时使用`authoritative_input`；同一对象字段已有直接采集位置时，后续依赖该值的表单使用`reuse_existing`。无法可靠判断时使用`pending_confirmation`。
- 迁移不得用文件导入时间、当前时间、名称猜测或默认值补写“有效”“归档”“已完成”“不适用”。
- 已包含对象字段的v7文件再次迁移时执行确定性规范化，保留对象字段引用、值使用方式、事件、核对状态、否决原因、来源和分析器版本。早期不含对象字段的v7候选按上述规则补齐，不修改源文件。

## 2. 版本映射

| 来源版本 | 保留内容 | v7补充内容 |
|---|---|---|
| v1至v3 | 按既有规则规范化行为、关系、数据对象和表单 | 增加对象字段、表单引用、值使用方式和待确认生命周期容器 |
| v4至v6 | 保留规范化后的`behavior_links`、`source_relations`和表单位置 | 增加对象字段、表单引用、值使用方式和待确认生命周期容器 |
| v7早期候选 | 保留既有生命周期、事件和人工决定 | 补齐对象字段、表单引用和值使用方式 |
| 当前v7 | 保留稳定引用和全部业务内容 | 仅执行确定性规范化，不重复创建字段或事件 |
| `document-structured-output-v2` | 先拆分为单流程，再按既有规则迁移 | 每个迁移对象增加对象字段、表单引用、值使用方式和待确认生命周期容器 |

## 3. 禁止自动确认

下列内容不能从旧文件直接推定：入口是否有效、保管位置、匿名化适用性、期限届满、作废和失效的区别、销毁范围、责任岗位、全部记录处置、异常补偿和跨流程对象身份。

迁移完成后，确定性分析器可以根据当前v7文档生成可解释建议；迁移本身不承担业务推断，避免同一旧文件因规则升级产生不可追溯的事实变化。

## 4. 失败处理

迁移在源对象的深复制副本上执行。任一候选文档未通过v7结构或引用检查时，整个导入失败；页面保留原草稿，用户源文件不变。重复迁移相同输入必须得到语义相同的结果。
