# 3001单流程真实用户试验包

> 状态：材料已准备，等待业务授权；真实用户试验尚未开始  
> 编制日期：2026-08-26  
> 适用对象：项目负责人、流程编制人、独立业务核对人、MDM工作组观察人  
> 适用版本：`process-governance-v7`

## 1. 当前结论

本目录只准备第二阶段所需的执行说明、六类合成拓扑和记录模板。项目负责人尚未在本目录登记脱敏流程、独立参与角色、来源材料范围和3001隔离运行授权，因此任何人员不得根据本目录宣称真实用户试验已经开始或完成。

技术检查通过只说明文件结构、引用和页面行为符合本试验包列出的技术规则，不表示流程事实、部门责任、业务做法或主数据结论已经通过业务核对。

## 2. 启动门槛

项目负责人必须在试验记录中逐项登记以下内容。任一项为空时，项目负责人不得批准执行；其他参与人只能维护试验材料，不得开始真实流程编制。

| 门槛 | 必须登记的内容 | 确认主体 |
|---|---|---|
| 脱敏流程授权 | 流程代号、归口部门、脱敏范围、允许试验的书面依据 | 有权部门、项目负责人 |
| 编制人与核对人分离 | 编制人代号、独立业务核对人代号；两者不得为同一人 | 项目负责人 |
| MDM工作组观察人 | 观察人代号及“只记录结构和工具问题”的职责 | MDM工作组 |
| 来源材料范围 | 允许读取的制度、规程、表单或台账名称和版本 | 有权部门 |
| 运行授权 | 允许使用的3001提交、摘要、端口或隔离地址、时间窗口、恢复方式，以及证据获准存放位置、访问主体、保留期和到期处置方式 | 3001发布或运行负责人 |

## 3. 目录内容

- `Trial-Runbook.md`：规定参与角色、执行顺序、浏览器和输入法矩阵、停止条件及恢复动作。
- `Synthetic-Topology-Cases.md`：规定六类不含真实业务内容的图形样本、关系语义和检查结果。
- `Trial-Record-Template.md`：记录授权、版本、文件摘要、技术结果、业务核对结果和未完成事项。

## 4. 结果边界

- 真实流程只用于检验业务可理解性、来源定位和实际工作量。试验以`docs/norms/`中已确认流程映射的L3界定范围；基线内已有的已确认A1、证据和`confirmed`工作角色绑定仍按现行真源读取。
- 试验中的具体业务事实必须由业务核对人回到允许范围内的制度、规程、表单或台账核对。
- 试验输出仍是未审核v7文件，不进入3000，不回写`docs/norms/`，不形成正式流程或正式数据地图。
- 试验材料不得发送给外部模型、第三方服务或未授权插件。
- 试验最多执行两轮。第二轮只复核第一轮发现的问题，不增加流程范围。

## 5. 完成判定

只有`Trial-Record-Template.md`中的启动门槛、技术验收和人工验收全部有证据且结果为通过时，项目负责人才能记录第二阶段完成。任何停止条件被触发时，项目负责人下令停止；流程编制人保留源材料和最近一次阶段下载文件；MDM工作组观察人把结果记录为“已停止，待处理”。任何人员都不得手工修改JSON掩盖问题。
