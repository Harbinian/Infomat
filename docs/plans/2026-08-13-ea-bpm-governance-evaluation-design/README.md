> 状态：3001四方面前端已实现；3000治理评价与数据治理工作包等待开发门槛
> 确认日期：2026-08-13
> 主责资产：`apps/mdm-platform/`
> 关联资产：`apps/structured-output-service/`、`pmo/`
> 适用对象：MDM 工作组、PMO、流程归口部门、开发人员和测试人员

## 1. 设计结论

本设计采用“一个总方案、两个实施工作包”：

1. 流程设计评价与 3001 推广工作包：处理流程发布前的业务流程管理（BPM）设计评价、3001 四轮编制、问题整改、三类真实流程试点和部门推广。
2. 数据流与生命周期治理工作包：处理流程生效后的企业架构（EA）关系、待治理数据对象、关键字段、生命周期规则和数据地图发布，继续执行[现有延后开发计划](../2026-08-09-mdm-data-flow-lifecycle-governance-development-plan.md)。

两个工作包共用评价规则、问题卡、证据、权限、审计和版本基础能力。正式评价以不可变的 L3 `process_version_id` 为根对象；业务能力地图由已确认的流程关系汇总形成，不开展脱离流程的能力自评。

## 3. 共同边界

- 第一阶段只评价业务架构和设计态数据架构。应用系统只记录当前支撑关系，不评价系统优劣，不建设目标应用架构、运行态技术血缘或技术架构评价。
- 供应商系统评价属于采购、选型或验收专项，不属于本设计范围。
- 3001 继续保持无状态，不增加账号、数据库、服务端草稿、自动保存、浏览器持久化、正式证据或 3000 运行依赖。
- 3001 继续输出 `process-governance-v3`。本设计原则上不新增字段、不升级结构版本，也不把学习评分写入 JSON。
- 3000 保存流程事实、评价批次、确认记录、问题卡和发布结果。评价内容不得反向覆盖 `docs/norms/` 或原始 3001 文件。
- 现行流程事实、治理结论和拟调整流程方案分别管理。拟调整方案只有经过评审、批准并生成新流程版本后才生效。
- 第一阶段不建设运行绩效评价，不采集预计工时、成本、处理量、及时率、自动化率或流程成熟度。

## 4. 执行门槛

本设计包完成不代表可以开始编码。开发前必须继续满足[数据治理工作规则](../../architecture/data-governance-operating-rules.md)和现有延后计划规定的门槛：

1. 3001 JSON 批量导入范围和摘要已经冻结；
2. 每个文件都有可追溯的处理结果；
3. 导入前后数量、结构版本、稳定引用、修订号和内容摘要核对通过；
4. 相同输入幂等复跑不产生重复记录；
5. 第一轮完整测试和真实导入核对通过，阻断缺陷为零；
6. MDM 工作组完成门槛审核，`mdm_lead` 记录开发启动结论。

2026年8月13日，用户明确要求为次日部门现场评审启用3001四方面前端检查，因此页面内无状态评审准备已经实施。上述门槛继续约束3000正式评价、数据库、接口、批量导入、数据流和生命周期治理开发；本次3001前端实施不解除这些门槛。
