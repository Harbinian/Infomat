> Created: 2026-07-06

## Current Stage

The repository is in the "process map and data map consolidation" stage. The default analysis object is the business process, not a specific application system.

MDM platform development is currently paused unless the user explicitly asks for MDM platform work. Process input baselines, PMO views, and business source materials must not be written into platform source code by accident.

## Technical Shape

- Package manager: npm, inferred from `package-lock.json`.
- Root runtime: Node.js CommonJS scripts.
- Main dependency at root: `mysql2`.
- Main runnable apps:
  - `apps/mdm-platform/`: MDM platform, Express backend and static frontend.
  - `apps/structured-output-service/`: stateless single-process governance compiler, default port `3001`.
  - `apps/structure-assistant/`: centrally deployed browser assistant for the five-account DeepSeek structure pilot, default HTTPS ports `3003` and `3004`.
  - `apps/weekly-action-service/`: PMO weekly action service, default port `3002`.
  - `apps/information-collection-service/`: internal information collection service; admin port `4000`, respondent port `4001`.
- Main document and source directories:
  - `docs/`: information assets, contracts, source materials, reports, architecture notes.
  - `docs/norms/`: process input baselines and source materials.
  - `docs/organization/`: organization and people source documents.
  - `pmo/`: PMO workbench, dashboard, Gantt app, and controlled deliverables.
  - `scripts/`: repository-level parsing, generation, and verification scripts.

## Current Runtime Baseline

> Verified against repository entry documents and implementation on 2026-08-31. This section defines the current version and runtime boundaries; dated notes below are retained only for durable behavior or historical traceability and cannot override this baseline.

- 3001 is a stateless seven-step `process-governance-v7` compiler. It imports v1 through v7 and supported historical multi-candidate files in page memory; JSON download is the only persistence. Version 7 is released for in-use verification, which is not business acceptance. Step 5 provides guided editing and a nine-table web grid over the same in-memory JSON; the grid uses a working copy and applies a validated batch as one undoable change. The web grid uses persistent native `input`, `textarea`, and `select` controls rather than Tabulator or another temporary cell-editor component. Update data-operation links use optional `updated_field_refs[]` to select one or more fields from the current data object through one shared popup; older v7 links missing the property normalize to an empty business-review prompt without changing the source file. Process-skeleton non-loop cycle prompts identify source and target and focus the target behavior node when clicked.
- 3001 ordinary lifecycle review first asks whether the current process changes the data object, then asks whether the data remains usable and how it is kept. Identifiability questions appear only when an anonymous or de-identification action applies. Trigger, scope, responsibility, and exception handling are visible only after the user temporarily enables advanced structural review; this page-memory switch resets on refresh, is not stored, and does not change JSON. Ordinary scoring uses `structure-learning-score-v5` and excludes advanced fields. Behavior names receive a non-blocking prompt unless they state the subject, action, and object. Cross-rank decision branches use outer routes, and multiple loop returns to one node share its bottom-center entry while retaining separate tracks.
- 3000's existing process-design path uses `process-governance-v3`, accepts v1 through v3 as compatible inputs, and normalizes storage and export to v3. A separate native V7 technical path implements preview, cross-department review, promotion, submit, review, publish, and immutable `process_version_id` readback without projecting V7 into V3. Both preview and formal writes are closed by default and require one exact approved `process_ref`, permissions, department scope, content digests, and blocker checks. Code and database preparation do not mean the runtime is enabled or the business has accepted a pilot.
- MDM-AI Assistant remains a five-account `process-governance-v5` client. It explicitly requests the versioned v5 health, schema, and template endpoints from 3001 and does not depend on 3001's default v7 response.
- The formal MDM runtime uses MySQL. `apps/mdm-platform/data/` and SQLite implementations are historical compatibility or isolated-test assets, not the current formal runtime database.
- The root process-governance sync uses the existing MySQL importer. SQLite initialization, organization sync, snapshot import, and snapshot checks remain available only under explicit `legacy-sqlite:` command names for migration or isolated tests.
- The information collection service uses one Express process for ports 4000 and 4001. Only never-published form drafts with no versions or tasks may be permanently deleted; forms with history can only be archived.
