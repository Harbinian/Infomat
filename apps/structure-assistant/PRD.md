# MDM-AI助手需求说明

## 1. 背景与目标

3001流程结构化辅助工具已经规定单流程JSON的对象、字段和引用关系。部分试点人员能够说明业务材料，但难以把信息稳定放入既定结构。公司需要验证AI能否通过对话辅助用户形成结构化预输入，同时避免AI结果未经确认直接上交。

本期页面名称暂定为“MDM-AI助手”。用户从端口3003登录后，默认进入端口3004上的受限DeepSeek Harness（DSH）治理工作区。本期设置5个固定账号，其中4名业务试点人员仅使用浏览器完成“新建治理工作区、绑定本人API Key、对话梳理、可选材料补充、结构化内容预览、未审核JSON下载、独立结构预审、逐条确认、手工导入3001”的完整路径。该试点不属于3001，也不是局域网用户访问3001的前置入口。

## 2. 用户与职责

| 用户 | 职责 |
|---|---|
| 张广懿 | 配置服务器和账户；发布唯一试点版本；处理结构基准和故障；查看不含其他账号余额、指纹和完整Key的非内容类状态 |
| 丁硕 | 完成1个统一基准案例 |
| 工程技术部研发试点人员 | 完成1个统一基准案例和1个研发真实案例 |
| 工程技术部批产试点人员 | 完成1个统一基准案例和1个批产真实案例 |
| 行政人事部试点人员 | 完成1个统一基准案例和1个部门真实案例 |

张广懿没有业务案例数量指标。正式发布后，5名用户仍须分别用合成材料完成一次Key绑定、一次填报和一次独立预审，以验证各账号模型调用链路；该操作会产生实际费用，执行前必须显式确认。

## 3. 功能范围

- 五账号登录和按登录会话隔离的本人API Key绑定；
- 每个登录会话一个隔离DSH实例，同一Cookie多标签共享；
- 一个治理工作区对应一个治理案例，并通过`revision`阻止旧标签页覆盖新状态；
- 管理员在DSH默认入口和`/classic`应急入口之间受控切换；
- 密码掩码输入、不可逆指纹展示、绑定、更换、清除和失效后重新配置；
- 以对话为主的流程梳理入口；
- 每轮只问一个主问题，并沿当前业务行为持续追问角色、表单或记录、全部数据项、数据来源和数据去向；
- 对话过程中发现信息缺口、前后矛盾、字段归位不清和对象混写；
- 授权、脱敏确认后的`.docx/.txt/.md`可选文字补充；
- Pro模型关闭思考模式后连续追问、受限Patch和即时3001校验；
- 实时结构化内容预览、结构清单和字段处置状态；
- 从“补充材料”导入部分完成的`process-governance-v5`文件，并将其作为当前草稿继续编辑；v1至v4文件先在3001中导入并重新导出，助手不得自行猜测或补造流程关系、表单设计状态和数据表单关系；
- Pro模型独立结构预审；
- 硬性结构错误强制修复；
- 字段归位和对象拆分建议的两种人工处置；
- 预审过程中同步显示同一份3001格式内容、JSON原文和只读跨职能流程图；
- JSON和独立问题处理记录下载；
- 本人余额、管理员五账号Key会话状态和非内容用量汇总；
- 维护状态、版本变化阻断、DSH运行状态和认证网关；
- Windows内网主机集中发布。

本期不建设知识库、向量检索、OCR、PDF或图片处理、移动端、长期工作区、3000自动提交、流程内容审核和业务审批。业务用户不能使用DSH原生编码Agent、目录选择、命令、文件编辑、技能、子Agent、网页检索、模型选择、权限选择、插件管理、会话日志下载或Models设置。

## 4. 业务规则

1. `process-governance-v5`是每次对话和预审的硬限制。
2. 模型可以追问`form_design_state`、字段归属和字段取值来源。取值来源为外部系统时，模型只能按用户确认结果记录系统名称和来源数据名称，不得创建本流程行为或数据行为关系；不得根据字段名称、数据类型、表单编号或明细数量推断现状表单、拟设计表单或合理的明细表数量。
3. AI不得新增结构规则以外的字段，不得判断流程内容是否正确。
4. 用户无需先上传材料；补充材料只在对话无法说明清楚时使用。
5. 导入部分完成的JSON后，该文件替换当前草稿，旧对话和旧文字材料清空；后续对话继续编辑该JSON，不能把它当普通文字材料重复发送。
6. AI每轮只提出一个主问题，并沿当前分支追问到用户已经明确、明确暂不清楚或明确不适用，再进入下一分支。
7. 每项业务行为都要问清实际执行部门和岗位、实际工作、表单或记录及全部数据项、数据来源和数据去向，以及触发、条件、时限、完成标准和后续流转。
8. AI发现的问题只用于继续追问和结构归位，不得扩展为流程内容审核。
9. 用户明确下载是业务内容唯一持久化动作。
10. 模型返回内容必须经过受限Patch和3001校验后才能进入页面草稿。
11. 独立结构预审不得接收填报对话历史。
12. 硬性结构错误不能忽略；结构建议允许保持原值，但必须记录理由。
13. 独立结构预审从导入、问题处置到下载始终使用`process-governance-v5`，不得产生另一种“预审格式”。预审意见和处置记录与JSON分开保存；`migration`中的旧跨部门记录只读。
14. 预审页面必须同步显示结构化内容和3001现有只读跨职能流程图；流程图只解释JSON中的既有对象和关系，不得补画关系或修改JSON。
15. 助手不得自动写入3001或3000。
16. 模型调用前后必须核对当前Git提交和Schema摘要。
17. 版本变化时，页面必须保留内存草稿并阻止后续模型调用，直到用户下载并刷新。
18. 正式启动必须拒绝未提交的服务器工作区。
19. 试点启动脚本不得停止、启动、重绑或代管3001；局域网用户无需经过试点或端口3004即可使用3001。
20. 用户登录后必须输入本人API Key并由服务端通过余额接口验证；未绑定时，填报和独立结构预审返回`428 API_KEY_REQUIRED`，导入、编辑、结构校验和下载仍可使用。
21. API Key只保存在当前登录令牌`nonce`对应的服务端进程内存中。同一账号的不同登录会话相互隔离；退出、会话到期、模型认证失败或服务重启后清除。
22. 页面不保存或回显完整Key。输入框使用密码掩码；绑定后只显示服务端生成的SHA-256前12位指纹、绑定时间和会话到期时间。
23. 余额不足或低于20元不阻止绑定，但必须提示用户；系统不得自动充值。
24. 管理员只能查看各账号是否存在有效Key会话、有效会话数和非内容用量，不得查询其他账号余额、指纹或完整Key。
25. 一份流程JSON在同一时间只有一名编制人。工程技术部研发、工程技术部批产和行政人事部分别编制不同真实流程，不并行修改同一文件。
26. DSH固定使用`@deepseek-ai/dsh@0.1.0-rc.6`和Node.js 24；不得使用`latest`动态升级，也不得直接修改DSH上游构建产物。
27. DSH子进程只监听`127.0.0.1`随机端口，并通过端口3004的Cookie认证、Host和Origin校验后访问。浏览器不得取得内部端口、运行令牌、临时路径或登录`nonce`。
28. 每个登录会话只能启动一个DSH实例。默认最多同时运行10个实例，启动超时60秒，停止宽限5秒；达到上限时不得驱逐其他有效实例。
29. 材料、对话、草稿、预审问题和核对记录只保存在当前DSH子进程内存中。刷新可以恢复；退出、会话到期、管理员终止、子进程故障或服务重启后清除。
30. 多标签页修改同一案例时使用递增`revision`。旧版本提交返回`409 STATE_CONFLICT`，保留尚未提交的本页输入并要求用户重新加载最新状态。
31. 管理员切换全局入口时必须填写原因。入口切换只改变新进入页面的前端，不终止有效Key、不复制业务内容，并记录管理员和时间。

## 5. 验收

- 4个统一基准案例和3个真实案例均完成生成、独立预审、手工导入、编辑、导出和重新导入。
- 5个固定账号唯一；同一账号不同登录会话的API Key也相互隔离。
- Key绑定、更换、清除、刷新保留、退出清除、到期清除、重启清除和模型认证失败清除均符合规则；完整Key不进入响应、日志、Cookie或浏览器持久化空间。
- 用户电脑不安装、复制或更新仓库、Schema和配置。
- 张广懿在服务器发布一次后，用户刷新即可取得新版本。
- 版本不一致、维护状态、无Key、Key认证失败和3001不可用均在模型调用前阻断；余额不足或低于20元允许保留Key，但明确提示且不自动充值。
- 3001保持独立局域网直连；启动或停止本试点不影响3001的监听地址和现有用户。
- 用户不上传材料也能开始对话；页面始终同时显示对话区和结构化输出预览。
- 用户可以从“补充材料”导入部分完成JSON；助手清楚提示该文件已经成为当前草稿，并能继续对话编辑。
- 每轮只显示一个主问题；每个案例均逐项记录业务行为的角色、表单或记录、数据项、数据来源和数据去向，未知和不适用项有明确状态。
- 独立结构预审导入、处理和下载的文件均为当前`process-governance-v5`格式；右侧内容预览、JSON原文和流程图随问题处置同步更新，问题记录不进入JSON。
- 预审流程图与3001对同一份JSON的只读图形含义一致；图形加载失败时，问题处理和文件下载仍可继续。
- 材料、对话、草稿和模型答复不进入服务器业务日志、数据库或浏览器持久化空间。
- 未登录、Host或Origin不匹配、跨登录会话访问均不能取得端口3004上的DSH静态资源或接口响应；DSH内部端口、令牌、路径和登录`nonce`不出现在响应或日志中。
- DSH临时目录、凭据文件、SQLite、JSONL和`settings.yaml`不存在API Key或业务内容；原生编码和Models能力不可用。
- 同Cookie多标签共享实例；旧`revision`提交被阻止并保留本页输入。退出、到期、实例终止、子进程故障和服务重启均清除DSH业务内容。
- 管理员可以填写原因切换`dsh`和`classic`入口；业务用户不能调用管理接口，入口切换不复制内容或清除有效Key。
- 原四账号试点总充值不超过800元；第五账号费用另行批准。全部账号均不启用自动充值。
- 验收只评价结构化结果和安全边界，不评价流程内容。
