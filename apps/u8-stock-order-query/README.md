## 当前行为

页面使用中文字段名称，可按单据类型、单据号、生产编号、生产订单、销售订单、物料编码、质量编号、U8 零件编号、解析状态、生产编号差异及单据日期查询。文本按字面包含匹配；多个条件按 AND 组合；日期包含起止两天。生产编号查询覆盖原编号、实际归属编号、销售生产编号；生产订单查询覆盖原订单号和归属订单号。物料筛选针对出入库物料编码。质量编号筛选针对销售源头，零件编号筛选针对 U8 保存的生产明细原编号，不查询计算值。

默认每页 20 条，可选 50 或 100 条，按首次捕获时间倒序。默认表格显示质量编号与 U8 零件编号。点击明细或按回车可查看全部 24 个映射字段、16 项当前关联信息及逐项注释，优先展示编号源头、复制值及核对结果。列名旁的注释按钮、集中字段说明及使用说明均可在页面打开。结果和条件不写浏览器持久化存储，刷新后恢复默认查询。

顶部质量告警覆盖全部已捕获明细，不受当前筛选及分页影响。两个有效质量编号不一致时显示红色告警及明细数；“查看告警”展示最新最多 100 条双方值与单据，可进入完整明细。“质量编号核查”可分别筛选不一致、一致、编号缺失、引用待核查。告警计数按出入库明细统计，同一生产零件可能出现在多条单据明细中，不等于不同零件数量。

页面可见时每 60 秒自动核查，执行查询或点击“刷新告警”也会核查。失败时显示“告警暂不可用”，不把上次结果或零条差异当成本次成功结果。自动告警不会应用尚未提交的筛选输入，也不改变当前分页。现阶段是网页当前值告警，没有外部消息推送、关闭确认、持久化告警记录或编号修改功能。

`CapturedAtUtc8` 为首次捕获时间、`RefreshedAtUtc8` 为最近同步时间，均直接保存北京时间（UTC+8），类型为 `datetime2(3)`。API 返回没有 Z 后缀的北京时间字符串，浏览器直接显示，不再次加 8 小时。数量、大整数 ID 使用字符串传输，保留数据库精度。

一行对应一条出入库明细。入库记录来源归属；材料出库记录实际领用归属。`resolved` 在页面显示为“已解析”，不表示审核通过、BOM 完整或实物追溯完成。编号差异为 NULL 时显示“无法比较”。原生产编号为空时，明确的领用引用仍可确认归属。

物料名称和生产母件从关联表当前值读取，没有固化在映射表。入库生产母件按保留的原引用读取，出库按已捕获的生产明细 ID 读取；引用本身需要核验，名称和编码不用于猜测组件层级。上游订单单独变化不会刷新映射。删除单据会删除当前映射，本表没有完整审计历史，也没有具体来源入库到领用出库的分配桥表。

## 编号源头与核查

用户确认销售订单子表 `SO_SODetails` 是生产编号、质量编号的源头。查询按映射表已捕获的 `SalesDetailID → SO_SODetails.iSOsID` 读取，不按相同编号猜订单。生产明细的 `OrderDId` 为销售明细引用，`Define25`、`Define29` 是生产环节的对应值。

| 页面名称 | 读取方式 | 使用边界 |
|---|---|---|
| 质量编号 | `SO_SODetails.cDefine29` | 当前销售源头值 |
| 生产明细质量编号 | `mom_orderdetail.Define29` | 当前生产复制值，与源头独立显示 |
| 质量编号核对 | 比较上述两个值 | 一致、不一致、编号缺失、引用待核查 |
| 销售源头生产编号 | `SO_SODetails.cDefine25` | 当前值；映射表销售生产编号是最近同步值 |
| U8 零件编号 | `mom_orderdetail.Define28` | 原编号，不由计算值补填 |
| 按规则计算的零件编号 | `mom_order.MoCode + CONVERT(nvarchar(20),mom_orderdetail.SortSeq)` | 无分隔符、无补零，仅供核对 |
| 生产明细行号 | `mom_orderdetail.SortSeq` | 当前样本中零件编号使用的拼接行号 |
| 生产用料行号 | `mom_moallocate.SortSeq` | 领用清单的行号，与生产明细行号分开 |
| BOM 子件行号 | `bom_opcomponent.SortSeq` | 按用料 `OpComponentId` 且 BOM/部件引用一致读取，不按物料猜测 |

入库显示产出零件编号；材料出库显示实际领用订单的生产母件编号及其销售源头。母件编号不能证明领用子件的来源订单。销售源头物料可能为上层组件，不要求它与生产母件或领用材料编码相同。例：`CLCK2610140020` 领用蜂窝 `201813`，母件为 `5542C10011G71`，销售明细物料是上层组件 `5542C10000G23-401`。

编号读取前核查当前生产订单与已捕获订单是否相符、入库物料或材料出库用料引用是否相符，并核对销售订单与生产销售明细引用。引用不符时保留映射明细，编号显示未提供并提示引用待核查，不互相补填。质量、零件编号核对独立于原映射的归属解析状态，编号问题不会修改原 `ResolutionStatus`。

默认表格用橙色副文字提示销售质量编号与生产值不一致、原编号缺项或引用待核查，点击明细可看双方原值。例如销售源头为 `50G`、生产复制值为 `50J` 时，页面保留双方并显示不一致；该例只说明显示行为，当前差异以实时核查为准。订单归属已解析不能掩盖编号差异。差异原因及应如何更正需要业务核实，本服务不修改编号。

以上编号、行号与核查结果在查询时读取或计算，未新增映射表列、未改触发器、未回填历史。重新查询可取得当前上游值，但不形成这些编号的修改历史。`/api/schema` 的 `fields` 保持 24 个映射字段，`relatedFields` 为 16 项当前关联信息；后者带 `storage: current`。

## 质量编号唯一性独立页

入口为 `/quality-uniqueness`，首页“质量编号唯一性”链接可进入，独立页可返回出入库查询。该页按用户确认核查当前账套 `SO_SODetails` 的全部现存销售明细，包括以往和已关闭订单；不受出入库映射捕获范围限制，不回填或修改任何单据。

产品图号取 `cInvCode`，质量编号取 `cDefine29`。按“产品图号＋质量编号”分组，组内存在两个及以上不同 `cDefine25`（销售生产编号）时判为重复。同一销售生产编号出现于多条销售明细仍计一个；生产拆单、多次出入库不会增加计数。本查询不关联生产或出入库明细来计算重复。

分组先将字段前后普通空格去除，空字符串视为缺失，其他判等遵循数据库排序规则。图号或质量编号缺失时待核查；有效图号、质量编号已对应多个不同有效生产编号时，缺失的其他生产编号不掩盖已证实的重复；尚不能证实重复而生产编号缺失时待核查。除此之外显示“未发现重复”，不表示业务审核或实物追溯已完成。

默认只显示重复组合，可按图号、质量编号及核查结果筛选。文本按字面包含匹配，多条件按 AND 组合；统计卡片随当前筛选变化。分组判定始终在完整源头范围内完成，再应用筛选及分页。每页 20、50 或 100 个组合；点击或按回车查看源头明细，明细每页 50 条，保留图号、质量编号、销售生产编号原值及销售订单、明细 ID、销售行号、数量。

“字段与使用说明”解释来源、去重单位及结果边界；明细字段标签带注释。核查为手动触发，页面没有自动轮询、编号修改、消息推送、异常关闭或历史告警持久化。分页及每页数量变化不会应用未提交的图号、质量编号输入；查询失败时清空本次结果，计数显示未取得，保留输入。输入不写浏览器持久化存储，刷新恢复默认条件。

独立 API 为 `GET /api/quality-uniqueness`，仅接受 `drawing`、`qualityNumber`、`status`、`page`、`pageSize`；结果选项为 `duplicate`（默认）、`unique`、`pending`、`all`。`GET /api/quality-uniqueness/details` 要求提供 `drawing` 和 `qualityNumber` 两个精确组合键，允许用空值查询缺失组，另接受分页参数。源头明细 ID、数量及组合中的源头明细数按字符串传输，保留精度。两种运行方式复用 `sql/quality-*.sql`，不允许客户端传 SQL。

本页“重复”与原页面的“销售质量编号和生产复制值不一致”是两种独立核查。独立页通过销售源头判定编号重复；原页面按已捕获出入库关联核对两处质量编号当前值。不能用其中一个结果替代另一个。

## Docker 部署

Docker 使用固定摘要的 Linux Node 24 镜像及锁定的 `mssql` 依赖，固定以 `va2` 查询同一账套。Windows 直接运行保留 PowerShell SQL 桥；两个入口复用 `sql/joins.sql`、`sql/columns.sql`、`sql/health.sql` 的只读 SQL，质量编号核对规则只有一份。采用支持 Linux 的纯 JavaScript 驱动是因为原 Windows .NET SQL 桥无法在此容器直接运行，驱动能力见 [node-mssql 文档](https://github.com/tediousjs/node-mssql)。

部署命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File apps/u8-stock-order-query/scripts/deploy-docker.ps1
```

脚本只操作本服务。它先核查 Docker 与容器归属，生成私有凭据文件及源码摘要，构建带摘要标签的镜像，然后在 **127.0.0.1:3099** 启动候选容器验证数据库、北京时间和告警接口。候选通过后才停止已核对归属的 Windows 3088 进程，或更新本服务既有容器，再切换到 **0.0.0.0:3088**。Compose 用 `U8_BIND_IP` 控制主机绑定地址，正式部署脚本固定为 `0.0.0.0`，候选固定为 `127.0.0.1`。不按端口批量停止进程，不重启 Docker Desktop 或其他容器。Docker 引擎不可用时在切换前停止部署；切换失败时同时恢复本服务原镜像及原绑定地址，或恢复 Windows 入口。

密码从既有 Windows 用户环境内部读取，写入被 Git 忽略且 ACL 限制为当前用户与 SYSTEM 的 `artifacts/u8-stock-order-docker-runtime-3088/private/sqlserver-password`。Compose 将其作为只读 secret 文件挂载；镜像、构建上下文、容器环境及浏览器不包含密码。服务配置只保存 secret 文件路径，不输出内容。修改该密码文件后需重启本服务，以重新建立连接。

容器名 `infomat-u8-stock-order-query-3088`，Compose 项目名 `infomat-u8-stock-order-query`，使用非 root 用户、只读根文件系统、移除 Linux capabilities，并设置健康检查与 `unless-stopped`。容器内部监听 `0.0.0.0:3088`，主机也发布到 `0.0.0.0:3088`，覆盖所有 IPv4 网卡。Docker Desktop／引擎自身未运行时服务无法启动；此策略不改变 Docker Desktop 的登录启动设置。

当前 Docker 入口已开启，3088 由 `infomat-u8-stock-order-query-3088` 提供；Windows 直接运行入口保留为备用方式，不能同时占用 3088。2026-10-15 独立页发布镜像为 `infomat-u8-stock-order-query:quality-uniqueness-20261015-b1eabe6b3d49`。容器健康、唯一性源头对账、正式 API 和 Edge 桌面页面已验证；此前已验证本服务容器重启恢复。这些技术检查不构成业务验收，其他电脑到本机的网络访问尚未实测。部署记录及镜像 ID 保存于 `artifacts/u8-stock-order-docker-runtime-3088/deployment.json`，后续实际运行状态须同时检查容器健康及 HTTP 契约。

## 访问与数据边界

- Windows 备用入口默认监听 `127.0.0.1`；正式 Docker 主机端口监听 `0.0.0.0:3088`，可通过各 IPv4 网卡访问。
- API 仅允许 GET。只接受固定筛选参数，不接受客户端 SQL，所有文本和分页参数均参数化。
- SQL 桥仅有固定 SELECT 查询；没有数据修改接口。此“只读”描述服务行为，不是对 `va2` 全部数据库权限的声明。
- Host 接受服务端口上的 IP 地址或 `localhost`，拒绝其他域名和含糊地址。浏览器 Origin 必须与请求当前地址一致，拒绝跨来源、跨站请求；页面禁止嵌入，静态文件按白名单提供，脚本、配置和凭据不公开。
- 单次最多返回 100 行；并发数据库查询最多 3 个；SQL 查询超时 12 秒，Windows 子进程超时 20 秒。Docker 使用最多 3 个连接的 SQL 连接池。
- 查询失败时清空本次结果并提示重试，保留输入条件；不会把上次成功数据显示为本次成功结果。

## 时间变更维护

2026-10-14 时间变更在同一事务内将既有两列增加 8 小时，改名为 `CapturedAtUtc8`、`RefreshedAtUtc8`，并修改 `ext_SyncStockOrderAttribution` 的后续写入表达式为 `DATEADD(HOUR,8,SYSUTCDATETIME())`。主键、业务归属字段和四个原触发器保持原逻辑。

原首次安装包和历史查询 JSON 保留 UTC v1 记录用于追溯，不能直接当作当前列名使用。恢复脚本同时将现有值减 8 小时、恢复旧列名和过程，带版本哈希校验；事务内恢复演练通过后已回滚演练，当前账套继续保持北京时间。恢复实际执行需要临时管理员入口；日常查询不使用该入口。恢复后网页的北京时间契约不再满足，应先停止本服务，再按恢复后的字段重新适配。
