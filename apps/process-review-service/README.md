# 独立流程评审服务

本应用落实2026-11-05用户确认的跨部门评审方案。当前仅供本机隔离运行与验证，入口默认为 `http://127.0.0.1:3090`。评审意见不等于已确认事实，评审覆盖、问题处理、正式发布分别记录。

## 运行与边界

2026-11-12已切换工作空间样式，镜像为`infomat-process-review:workspace-20261112130123`；页面、健康及两块网卡地址已验证。

界面源码沿用 Infomat 工作空间的深绿导航、浅灰绿背景和统一控件。样式由 `public/styles.css` 与 `public/review-layout.css` 维护；走查画布、业务状态及未提交输入保护保留各自的实现。Docker运行内容以已部署镜像为准，源码样式修改不会自动切换正在运行的服务。

- 使用 Node.js 22.13及以上版本（本机验证环境为25.2.1），内置 SQLite 仅承载本地隔离演练。正式部署、正式数据库和真实员工身份接入尚未开启。
- 默认监听127.0.0.1。Docker局域网演练须明确指定宿主机的局域网IPv4。应用不连接MDM平台、3001、MySQL或外部API，禁止使用3000/3001端口。
- 页面中的人员均为明确标记的合成演练身份。身份切换用于测试权限，不构成真实登录或人员任命。MDM平台仍为员工唯一维护源，本应用不另建员工主数据。
- 本地材料和记录保存在仓库根 `artifacts/process-review-service/local/`。该目录被忽略，不随源码分发。退出或重启服务保留记录，勿删除该目录。
- 浏览器图形依赖来自本应用的 `node_modules`，无CDN。新依赖Cytoscape、Dagre及其适配器用于带分支、回路的流程布局和节点/交接选择。
- 只支持桌面 Edge 100%、1699×828 CSS像素，不做窄屏适配。

从本目录运行：

```powershell
npm.cmd ci --ignore-scripts --no-audit --no-fund
npm.cmd start
```

后台本机启动及健康、页面检查：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-local.ps1
```

`REVIEW_PORT`可指定其他独立端口，`REVIEW_DATA_DIR`可指定隔离数据目录。不要指向正式数据或来源材料目录。前台启动用Ctrl+C停止；后台停止前核对 `artifacts/process-review-service/server.pid` 所记进程确实是本应用，不按端口批量停止进程。

### Docker 局域网演练

`compose.yaml` 在容器内监听 `0.0.0.0:3090`，并发布至宿主机全部IPv4接口。`REVIEW_LAN_IP`是HTTP地址允许清单，可用逗号列出当前各网卡的局域网IPv4；本机为`192.168.19.199,192.168.10.184`，地址变化后须同步配置并重建本服务。浏览器用 `http://<宿主机局域网IPv4>:3090/` 访问，页面显示“局域网隔离演练”。能够访问服务的人员均可选择演练身份并读取演练材料。

启动前须准备专用 Docker 命名卷 `infomat-process-review-data`。从已有本机工作副本切换时，先使用 SQLite 备份将完整数据库复制到该卷，并核对材料、修订和审计记录。之后从本目录运行以下命令，将地址替换为宿主机实际用于参会的局域网IPv4。

```powershell
$env:REVIEW_LAN_IP = '192.168.19.199,192.168.10.184'
docker compose up -d --no-build
docker compose ps
```

从宿主机局域网地址检查首页及 `/api/health`，健康响应应显示 `network: lan`、`mode: local-isolated` 和 `formalIntegration: false`。局域网参会终端的访问情况以该终端打开页面的结果为准。停用时使用 `docker compose stop review`，保留命名卷。Docker运行期间的新记录写入命名卷。切回本机进程前须备份并核对卷内数据，再决定恢复哪个工作副本。

## 材料导入

页面可选择多个单流程JSON导入。目录导入先预检，明确加 `--apply` 才写本地隔离库：

```powershell
node scripts/import-directory.mjs --source '<用户指定的材料目录>' --dry-run
node scripts/import-directory.mjs --source '<用户指定的材料目录>' --apply
```

脚本只读来源目录，仅递归JSON，不跟随符号链接；导入前后核对来源文件指纹。导入报告和逐文件清单保存在隔离数据目录。支持 `process-governance-v8`；不支持或缺少基本结构时整批拒绝，保留原文件，不能当作已完成业务正确性校验。

原始JSON、未知字段、原流程标识和来源分别保留。同路径同内容重复导入不新增材料；同名、同标识、不同路径或不同内容不会互相覆盖。图形引用异常以材料警告保留，不静默修正原文。目录归属仅表示提交来源，不证明业务主责。

候选主题规则更新后，可用 `node scripts/refresh-group-suggestions.mjs` 查看变化数量，加 `--apply` 才更新尚未确认且未冻结的候选分组并记录前后值。该操作不改原文、不选有效版本、不修改已确认材料。

本次选材范围包含后续修订和旧版。提交部门代表逐项确认有效材料和主题；本地确认只用于演练，不代表实际部门批准。后续版本需要明确关联前版及变化说明，不继承旧版评审结果。

## 评审组织与页面

全部门固定代表参加，按议题增补实际经办与交接人员。PMO整理材料、组织批次和跟踪，流程主责与上下游部门确认各自业务事实。会议频率、时长、日期和具体真实人选尚未确定。

12个主题为计划骨架，不等于12场会议：项目计划与生产协同；技术文件、工艺程序与变更；物料需求、采购与供应商履约；到货验收、库存与物料追溯；工装业务与使用管理；产品检验与质量改进；设备计量、安全与运行保障；商务合同、销售、成本与回款；组织人员与上岗资质；行政协同、档案与物流；经营目标、考核与持续改进；法律合规、证照与海关。

| 页面 | 用途 |
|---|---|
| 评审总览 | 按材料核对、批次准备、会上走查和问题跟进入口办理；主题卡直接打开对应材料，逐部门核对覆盖 |
| 材料与版本 | 导入、筛选、查看原文、确认候选版本、明确关联后续版本 |
| 批次计划 | 选择准确材料、参与人、主讲/主持与记录人员、需要反馈的部门；冻结后固定材料和名单 |
| 流程走查 | 部门泳道与直角连线、部门和步骤定位、交接详情、节点和表单联动、个人意见；个人浏览、投屏跟随及两份材料对照 |
| 我的意见 | 跨流程查找当前身份保存的草稿和已提交意见，定位来源步骤或连线，查看已关联的问题 |
| 问题台账 | 查看待整理的已提交意见，由记录员据此形成问题；问题分派、回复证据、分层复核、退回和重开 |
| 系统性问题观察 | 将多个流程或问题关联，记录现象、时间变化、变量、假设、反馈、时延、证据、反例和待补信息 |

批次计划分开显示已选入的批次材料和主题候选。已选材的批次可点“进入走查”，材料下拉框仅列本批次的快照。待选材的批次可点“浏览主题候选”直接查看该主题的候选流程图。此时处于独立浏览，意见与修订关联所选材料，批次清单仍须由 PMO 在“选入材料”中明确保存。

选材时核对材料名称、来源、主题和确认状态。已选材的计划若还有冻结前待办，批次卡片会列出具体材料、来源部门或缺少的参会安排。条件齐全后可打开冻结确认窗口，每次打开均须确认当前清单。独立浏览已入批次的材料时，可点“进入所属批次”，在原材料上继续走查或提交部门反馈。

走查首先显示部门泳道总览，流程按从左到右的布局展示，分支和回退仍按原关系连接。每个步骤仅进入一个泳道；材料明确的办理部门按步骤中首次出现的顺序排列，归属不明确的步骤集中放在末尾的“待核对”泳道。该泳道表示需要核对归属，不是新增部门。左侧部门名称在缩放和拖动画布时保持可读，与可见泳道对齐；“查看部门”可聚焦该部门，右侧步骤列表按部门分组，并显示原材料中的办理角色。选择“全部部门泳道”恢复总览。

使用“定位步骤”或点击节点查看职责、输入输出和实际关联的上下游；右侧交接按钮可跳转到关联步骤。编号来自材料列表位置，不表示系统另行确定业务先后。选中节点突出相邻关系，“全图”查看整体结构，“清晰阅读”恢复当前步骤的可读字号。流程较大时，总览用于查看部门分工，具体步骤和交接通过定位后阅读。画布可拖动，节点位置固定，避免拖动后破坏直角路线。超长分支条件在图中缩略，点击连线可查看完整原文。

每张流程图都有“定位入口”。当前连线能识别出唯一没有入线、且可到达所有步骤的节点时，图中和步骤下拉框会标记“入口”，点击按钮即可放大并居中查看。存在多个候选入口时，可从候选列表选择；回路、连线不完整等情况无法确定入口时，可从步骤清单定位。空图保留按钮，新增步骤后即可使用。入口标记供走查导航使用，业务启动条件仍以材料为准。

图形使用本地Dagre安排流程层次，再将节点放入部门泳道；同一部门的并行节点分行避让，最后计算避开节点的水平、垂直线段。路由在不同端口分配、回退通道和布线顺序之间比较交叉与重叠，选择较清晰的几何方案；回退、自循环及重复分支均保留原关系。显示布局不写回材料，不改变流程事实。连线交叉或经过其他部门泳道不新增交接，只有原关系中的起止节点表示流程连接。路由与端点实现参考 [Cytoscape分段连线与端点文档](https://js.cytoscape.org/#style/segments-edges)。

绿色加粗连线表示当前走查内容中可明确识别的跨部门交接。金色虚线表示交接部门待核对。节点下方显示部门提示。只有两端均为固定部门分配、角色明确匹配本轮部门名称且没有条件性或会签主体歧义时，才提示跨部门或同部门流转。动态分配、简称、泛称、待确认规则及不唯一的节点引用保留待核对。部门提示供走查使用，仍需相关部门核对。

走查页默认以大画布展示流程，右侧保留步骤、关系和意见。点图上方的“新增步骤”可建立办理、判断、并行开始或并行汇合节点，保存后定位到新增步骤。点“新增连线”可选起点、终点、关系类型和流转条件。如果已选中步骤，系统将它预填为起点。

选中节点后点“编辑步骤”，可修改名称、类型、办理角色、部门分配方式及规则、办理说明、输入、输出、完成标准、触发条件、前置条件和时限。步骤名称使用单行输入；历史名称中已有的换行会保留。选中连线后点“编辑连线”，可修改端点、类型和条件。无法识别的历史类型和端点标注“原值保留，待核对”，可从有效选项中明确更正，编辑其他内容时保留原值。

移除步骤或连线前，窗口先列出需处理的关联内容。相连连线、数据或表单引用、生命周期路径引用以及主持投屏定位均须先处理。可移除时，确认窗口显示步骤名称或连线的起点、终点与条件，填写原因后确认。保存新增或编辑后，键盘焦点回到对应编辑入口；移除后回到相应新增入口。历史意见与修订记录继续保留。新增连线及编辑端点、类型或条件时，均会核对重复连线。

固定部门分配的步骤先选择“执行部门”，再从该部门的“执行岗位”中选择办理角色。新增步骤使用同一组联动选项。切换部门后须核对岗位；尚未匹配目录的原有角色会原样显示并标注待核对。只修改其他字段时保留该原值。选择全公司适用或依据业务数据确定时，部门和岗位选择停用，原角色保留，具体安排填写在部门分配规则中。

部门与岗位选项来自本应用 `config/organization-catalog.json`，是 3001 同名配置的独立副本。目录源文件及补充依据保留在 `source` 中，当前副本 SHA-256 为 `e2977d3320b8e6d3100099f9d51d1dda10ab950c8b9fbaed4f23ab70e86c3076`。它供编制选择，实际办理职责仍须由业务人员确认。本应用独立读取该副本；更新目录时须核对 3001 的相应配置、替换副本并验证原值保留和联动选项。

填写修订原因后保存，走查页立即显示新内容，其他参会者的走查页通过定期同步显示新内容。正在输入意见或打开编辑窗口时，页面会等本次输入结束再更新图面。同一字段已由他人修改时，编辑窗口保留本人的输入并提示最新内容，核对后可再次保存。

在步骤或连线详情的“修订记录”中可查看历次修改前后内容、操作人、时间和原因。画布下方的“共享走查修订”也可查阅已移除元素的记录。修订绑定材料快照及稳定的元素位置，并随评审包的审计记录导出。走查图按修订后的内容展示，导入原件仍可在“材料与版本”中查看。修订记录与批次冻结、评审覆盖、问题处理和正式审核分别保存。

“交接清单”可逐项定位跨部门及待核对关系。点击清单或图中连线后，可查看两端办理角色、交出内容、接收要求、流转条件和完成标准；“记录本交接意见”进入个人意见编辑区，投屏时对应入口先退出投屏。新意见关联所选原始关系，已有输入不会因选择另一条交接而改换来源。提交后仍由记录员确认需要核实或处理，再整理为问题，不直接产生已确认结论。“突出跨部门交接”减淡同部门连线，关系本身不会被删除。

“数据与表单”扩大右栏的表格阅读区。数据对象按字段名称、类型和定义列出，表单按区域展示字段、类型、必填状态和填写说明。点右栏顶部的“数据对象”或“表单”可跳到对应分组。选择步骤后，右栏优先显示材料中与该步骤关联的数据对象和表单，其余条目可展开查看。常规走查的意见区位于表格下方。会议投屏也可使用表格。

“会议投屏”扩大图面并收起导航、个人意见编辑区和讨论记录，保留材料状态和交接详情；退出按钮或Esc恢复常规视图和原输入。投屏视图只改变本机显示，不自动发布主持位置。现有主持位置同步支持具体步骤和整份流程；选中交接关系或聚焦部门泳道时该按钮停用，可先选择具体步骤或返回全图，再发布给主动跟随的参会者。

未保存输入在当前页面会话中保留。意见输入按演练身份、材料快照和批次分别保存。从“我的意见”打开其他走查范围的意见时，原范围的输入继续保留。目标范围如已有未保存输入，会先打开该输入，避免覆盖。身份下拉框选择“请选择演练身份”可退出当前身份，重新选择原身份后可继续填写该页面会话中的未提交输入。离页时提示确认，失败和并发冲突均保留输入。业务正文不写入 `localStorage`。通过“保存草稿”保存的意见存入本地服务，已提交意见的更正保留历史。切换步骤、上下游跳转、返回全图和从总览重新进入，均保留已开始填写的意见来源。

点击“记录本交接意见”时即固定所选连线。保存期间可继续输入，服务先保存本次提交的内容，后续输入保留在编辑器中。同一条意见在其他窗口更新时，页面显示最新保存内容，核对后可继续编辑和提交。并排对照以两侧当前选择为准，切换材料时各自显示载入状态。

勾选“跟随主持投屏”时定位到主持人最近发布的位置。后续仅在主持人发布新位置时跳转，期间可手动查看其他步骤。打开弹窗或在意见框输入时，跳转延后，草稿仍关联原材料和步骤。

## 状态与复核

走查页右侧“走查状态”显示当前材料的覆盖状态及待完成事项。独立浏览时，先由 PMO 选入材料并冻结批次。指定部门代表在冻结批次中对该材料提交反馈。必需反馈齐全后，主持人或本批次记录员点“记录走查覆盖”，填写结论，选择“已完成走查”并保存。右侧随即显示完成标记。已登记的问题可继续跟进。

条件未满足时，覆盖窗口会说明缺少的环节，并暂停选择“已完成走查”。若他人更新了同一材料的走查结论，窗口保留本次输入并显示最新记录供核对。问题台账中可用 Tab 定位问题标题，再按 Enter 查看该问题。保存分派、答复或复核等处理结果后，焦点回到当前问题标题。走查结论等表单字段可通过可见标签定位，Esc 可关闭编辑窗口并保留本次页面会话中的输入。

意见保存或提交后可到“我的意见”查找。其他参会者提交的意见会在下一次页面同步时出现在对应的走查讨论区。更新讨论时会保留正在填写的意见及焦点。已提交且尚未被问题引用的意见会进入问题台账的“待整理意见”。记录员选择“据此形成问题”并保存后，原意见显示已关联问题，可从“我的意见”直接打开该问题。处理当前问题后，如果新状态与所选筛选条件冲突，台账会切换到“全部状态”，保留搜索词及当前问题详情。

“我的意见”“问题台账”和“材料与版本”的搜索结果随输入更新，输入法组词完成后再应用该段文字。搜索时焦点留在输入框，清空搜索词会恢复其他筛选条件下的结果。

登记问题或调整复核安排时，表单会随选择显示尚缺哪几个受影响部门的代表。各受影响部门至少选择一名部门代表，其他身份可作为补充复核人。若代表尚未选齐，表单会提示缺项并保留输入。

批次材料及人员未明确时保持计划状态。冻结要求材料已明确确认、主讲和记录人属于参会名单、所需反馈部门有对应参会代表。部门反馈绑定冻结材料。完成走查且关键部门反馈齐全，可记录已评审，即使仍有未关闭问题；缺少核对的部分保留待补评。

初次启动预建12个空计划模板，未替用户选择有效材料或指定业务人员。已评审材料收到新的部门反馈后转为待补评，避免旧的覆盖结论掩盖新增意见。

记录员确认意见需要核实或处理后登记问题，不以达成事实共识为前提。跟进人和期限可保持待落实，但不得猜测填入；提交回复需提供依据。

- 部门内问题由该部门指定人员复核。
- 跨部门问题需覆盖相关交接部门的指定复核人员共同复核。
- 职责或制度变更问题还需指定有权主体的确认依据。
- 本人回复不自动关闭问题，指定复核全部满足后关闭；退回、重新回复及重开保留原记录。
- 改版不自动关闭或重开旧问题，记录受影响问题，指定人员核对后办理。

变更处理人或复核人员后，当前复核结果失效；重新答复、复核退回及重开均需按当前处理内容取得新的复核和制度决定依据，旧记录保留历史。

正式员工任命、制度生效、正式发布均不由本地演练记录产生。导出评审包仅提供人工交接，不调用其他系统写入接口。

系统动力学观察仅积累分析材料，不由流程先后关系推断因果，不生成预测或自动治理结论。方法参考：[Vensim建模过程](https://vensim.com/documentation/21360.html)、[因果回路说明](https://vensim.com/documentation/usr04.html)。
