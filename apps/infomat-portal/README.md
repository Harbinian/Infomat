# Infomat 工作门户

独立的桌面应用入口，收录流程编制、评审、数据查询、项目看板及开发工具。应用目录由本目录的`services.json`维护，不从容器数量或端口扫描自动生成。

当前镜像`infomat-portal:all-ip-20261112`已发布到全部IPv4接口的8080。可通过[192.168.10.184:8080](http://192.168.10.184:8080/)、[192.168.19.199:8080](http://192.168.19.199:8080/)或本机[127.0.0.1:8080](http://127.0.0.1:8080/)进入。10个应用均沿用访问门户的主机地址；3000和代码地图已不再限制为本机链接。

## 使用

- 左侧选择全部应用、收藏或用途分类；可按名称、用途、关键词和端口搜索，按`/`聚焦搜索框。
- “进入应用”在新标签页打开原系统，各应用保留各自的账号、权限和业务数据。
- 收藏只在当前浏览器的localStorage保存应用标识；存储失败时显示提示，不保存业务内容、凭据或访问历史。
- “刷新状态”读取服务器对固定网页的检查结果，最多缓存30秒，并合并并发请求。网络入口统计只统计当前目录。
- 页面的“网页可访问”不证明数据库、业务功能、其他终端网络或业务验收已经通过。

仅支持桌面Microsoft Edge、100%缩放、1699×828 CSS像素，不做窄屏适配。

## 启动与停止

从本目录启动已准备的镜像：

```powershell
docker compose up -d --no-build --pull never
docker compose ps
Invoke-RestMethod 'http://127.0.0.1:8080/api/health'
```

更新源码或目录后须另选新镜像标签，构建、验证并重建门户。当前样式和监听恢复方式见[工作空间维护说明](../../artifacts/workspace-style-20261112/README.md)。停止仅此门户：

```powershell
docker compose stop portal
```

Docker容器沿用普通用户、只读根文件系统及现有安全设置；不挂载宿主机目录、Docker socket、数据库或数据卷。通过host.docker.internal传输固定网页请求，HTTP Host保持对应的宿主回环入口。镜像不推送远程仓库，未修改防火墙。

Node.js 22及以上版本也可运行`npm.cmd start`，该独立开发入口默认仅监听127.0.0.1:8080。PORTAL_PORT、PORTAL_BIND_HOST、PORTAL_PROBE_HOST控制本进程监听和固定网页探测主机；不要与当前Docker端口冲突。

## 检查与维护

```powershell
npm.cmd test
node --check server.mjs
node --check public/app.js
```

7项自动化使用合成响应和独立随机回环端口，核对错误页面、重定向、超时、缓存、只读路由和目录边界，不连接业务库。实际两块网卡的页面、应用链接和浏览器证据见工作空间维护说明。新增应用须明确名称、用途、分类、端口、路径、访问范围及网页标记，先取得真实页面证据。

目录仅收录用户入口；数据库、内部API、候选和临时验证容器不纳入。只接受GET和HEAD：`/api/health`检查门户，`/api/services`返回公开目录，`/api/status`返回固定网页检查结果。静态资源由显式白名单提供，不暴露仓库或服务源码，不接受任意URL探测。

网页探测要求成功HTML及预期内容标记，只跟随同一来源最多3次重定向，最多读取64KiB。检查不调用业务API、数据库、同步、迁移、通知或Docker接口。流程评审保留隔离演练，部门职能保留参考建议，代码地图保留静态快照边界。
