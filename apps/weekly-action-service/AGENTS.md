# AGENTS.md

本目录是 PMO 每周例会行动项管理服务，默认端口 `3002`。

## 修改边界

- 可以修改：`server.js`、`public/index.html`、`scripts/`、`package.json`、本目录 README、`docs/` 下的服务设计说明。
- 不要修改：PMO Markdown 真源、`pmo/tasks.json`、`pmo/gantt-react/public/tasks.json`、MDM 平台代码，除非用户明确要求进入对应资产。
- 本服务的运行数据是 PMO 运行台账，默认写入 `artifacts/weekly-actions/`，不提交。
- 不使用浏览器本地保存作为行动项台账；刷新、换浏览器或多人访问时应读取同一套 3002 服务端台账。
- 当前不接 MySQL；在用户确认 PMO 管理模式稳定前，不提前重数据库化。
- 不接 SQLite，不新增 `.db` 运行文件。

## v2 设计边界

- v2 设计基线见 `docs/weekly-action-service-v2-design.md`；当前代码仍是 v1 简化台账，实施前先核对该设计基线。
- 人员快照由仓库脚本从 `docs/organization/信息化项目人员角色映射.md` 生成，3002 只读消费，不直接解析组织 Markdown 真源。
- 3002 可以保存责任人快照和 `snapshotId`，但不能反向修改花名册、组织架构、人员角色映射、PMO Markdown 真源或 MDM 数据库。
- v2 写操作必须走业务动作接口，并写入全局审计事件流；不要用通用 `PUT` 绕过状态、权限、证据和留痕规则。
- 删除语义为误录作废，不允许物理删除事项和证据附件。
- 会议草稿、周会复盘包和责任穿透导出只能作为 3002 运行材料，不自动生成正式会议纪要或 PMO DLV。

## 业务口径

- 周会周期按周四至下周三计算。
- v1 事项类型固定为：周会行动项、风险事项、问题事项、变更事项、责任池事项。
- v2 事项按六类跟踪去向管理：行动项台账、责任池、材料缺口清单、制度或表单待补说明、后续访谈清单、MDM 现有入口。
- v2 责任必须拆分主业务责任人、协作人、PMO 跟踪人、PMO 核验人和升级接收人，并锁定姓名、部门、岗位、项目组织和本事项角色。
- v2 关闭必须基于结构化证据清单和 PMO 核验，业务责任人不能自行关闭。
- 3002 是 PMO 周会执行辅助工具，不替代会议纪要、受控交付物或 PMO 计划真源。

## 运行与验证

```powershell
npm start
npm test
```

默认访问 `http://127.0.0.1:3002`。测试使用隔离端口和临时台账目录，不依赖正在运行的 3002 服务。
