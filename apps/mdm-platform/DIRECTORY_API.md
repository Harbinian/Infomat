# 组织与员工目录维护及读取接口

## 适用范围与状态

按2026-10-19用户确认，3000员工信息作为全域唯一维护源，行政人事部维护组织架构和员工资料，保存后直接生效，不增加审批环节。其他系统逐个接入，只读引用3000的有效记录。本文描述本次工作树的实现合同；角色迁移、实际人员授权、服务部署和接入方启用须分别核对，不因代码存在而认定已开启。

目录覆盖现有部门、办公室、员工及办公室成员关系。员工字段为工号、姓名、所属部门、在职状态、手机和邮箱；不扩展薪酬、证件等资料。部门最终负责人等现有职责字段只读保留，不从岗位、名称或本次目录维护推定任命。角色授权由管理员明确办理，不按人员所属部门名称自动授权。

## 维护权限与页面

固定角色`hr_directory_manager`（行政人事信息维护员）拥有`identity:read`、`directory:read`、`directory:maintain`，维护范围为全公司目录。角色不授予账号办理、角色授权、流程审核或治理发布权。管理员包括叠加人事角色的管理员保持目录只读，仍负责已有人员开户、启停、密码及系统角色授权。

在`/app/organization`新增或修改部门、办公室，在`/app/roster`新增或修改员工。填写变更原因，点击“核对本次变更”，检查前后差异后“保存并生效”。核对不是审批。支持Excel/CSV目录导入，沿用原模板、字段映射和版本保存，但也必须具备人事维护权限并填写原因；一般主数据发布继续使用原治理发布权限。

未保存输入保留在页面内存中。修改任一字段会清除旧核对结果。并发冲突时保留输入，点击“读取最新目录并保留输入”后重新核对；保存响应不明时锁定原输入，使用同一请求标识核实结果。刷新或离页遵循现有未提交输入保护。

每次保存将目录更新、发布版本及审计在同一事务提交。审计保存修改前后值、操作人标识、原因、时间及目录对象标识；新目录变更另在审计元数据中固化保存前的操作人姓名`actor_name`，直接维护与表格导入均适用，后续改名不改写已记录姓名。该可选字段不改变发布正文或内容摘要；旧审计缺失姓名时保持缺失。行政人事维护角色可在发布记录详情及主动下载的完整记录文件中查阅追溯信息。页面按业务名称和中文字段展示，不输出内部编号、机器字段或原始结构；历史引用缺少当时名称时明确提示未记录，不以当前名称补写。其他已授权读取角色仅查看目录发布元数据摘要，完整目录历史及下载会返回明确403；一般主数据历史读取权限保持。旧版本没有原因审计时保持缺失，不补造历史。

## 目录导入核对的兼容

组织与花名册导入的新核对返回`sourceHashVersion: directory-publication-source-v2`，临时`baseHash`按精确十进制标识计算，区分超出JavaScript安全整数范围的相邻记录。发布请求须携带核对返回的版本。该变化只用于导入保存前的并发核验，不改写已发布的`payload_json`、`content_hash`、版本链、审计、额外列或下载结构；单条维护继续使用原精确`snapshot_hash`合同，主数据导入合同保持。

服务端先按当前权限、原操作人、原内容及原原因核实已成功请求，旧请求缺少新核对版本仍可取得原回执。尚未提交的旧、缺失或未知核对版本返回409及`PUBLICATION_SOURCE_CHECK_EXPIRED`，不自动换用新版本或写入。页面保留原文件、列对应关系、工作表、发布名称和原因，只撤下过期核对结果；用户重新核对并明确确认后才能保存。版本码和摘要不作为界面文字输出。

## 员工与账号兼容

沿用`person.person_id`、部门ID及办公室ID。普通修改不能改变工号或组织编码，不删除历史记录；新建重复工号/编码明确拒绝。姓名不用于定位修改对象。旧花名册额外列和发布快照继续保留。

管理员对现有员工使用`POST /api/org/accounts/:personId/assign-account`。旧`POST /api/org/accounts`仅兼容为已有员工开户；没有员工记录返回409及`PERSON_DIRECTORY_RECORD_REQUIRED`，资料不一致返回`PERSON_IDENTITY_MISMATCH`。旧`PATCH /api/org/accounts/:personId`提交一致资料时返回原记录且不写入；实际改姓名、工号或部门返回`PERSON_DIRECTORY_MAINTENANCE_REQUIRED`，角色变更须改用授权接口。

现有账号、角色、办公室负责人及成员约束继续生效。涉及有效账号人员离职、带有效部门角色的人员调部、仍有使用关系的组织停用等情形，先完成明确的关联调整，再重新核对。系统不自动撤销授权、变更负责人或停用账号。有人身关联的管理员员工可由人事更正姓名、手机和邮箱；涉及其部门、在职状态或办公室归属时，先明确调整管理员身份及相关责任，不能通过人事目录变更破坏管理员访问。

## 3000页面接口

以下接口使用现有登录会话，写操作沿用CSRF校验。原`GET /api/org/roster`同步将手机、邮箱限制为行政人事维护身份可读，非维护身份仍可读取员工基础目录。`GET /api/directory/v1`要求`directory:read`或`identity:read`；返回基础目录和`canMaintain`。仅具备人事维护资格的人员可使用`?include_contacts=true`读取手机、邮箱。写操作在事务内再次检查当前账号、人员、角色和认证版本。

| 接口 | 用途 |
|---|---|
| `POST /api/directory/preview` | 只核对单条变更，返回差异、问题、请求摘要；不写目录 |
| `POST /api/directory/changes` | 以核对过的请求保存，原子更新目录和追溯记录 |

请求字段：`entity`为`department`、`office`或`person`；`operation`为`create`或`update`；修改必须提交稳定`id`；`values`为该对象允许的字段；`reason`为非空原因；`expected_snapshot_hash`为读取时的目录摘要。保存另带核对返回的`request_hash`及UUID格式`request_id`。服务端校验字段白名单，不接收客户端账号或权限声明。

| 对象 | `values`字段 |
|---|---|
| 员工 | `employee_no`、`person_name`、`current_department_id`、`employment_status`、`mobile`、`email`、`office_ids` |
| 部门 | `code`、`name`、`parent_id`、`department_type`、`status` |
| 办公室 | `code`、`name`、`department_id`、`manager_person_id`、`status` |

同一保存请求原样重试返回原回执；同一请求标识绑定不同内容或不同操作人时拒绝。目录变化返回409，验证问题返回422，失去权限返回403；依赖不可用不返回数据库细节。成功回执包含发布标识、对象标识、操作类型、保存后快照摘要和`idempotent`。

## 系统间只读接口 v1

`GET /api/integration/v1/directory`为3000以外系统提供同一目录投影，只有GET可用。这里“外部系统”表示3000之外的接入方，不表示开放互联网。接口不使用人的登录会话，不提供系统间写入。

响应包含`schema_version: organization-person-directory-v1`、`source: 3000`、`snapshot_hash`、`departments`、`persons`、`offices`。所有ID均为十进制字符串，接入方不得转成可能丢失精度的浮点数。工号和组织编码也是字符串。

| 集合 | 字段 |
|---|---|
| `departments` | `id`、`code`、`name`、`parent_id`、`department_type`、`status`、`final_responsible_person_id`、`data_owner_person_id` |
| `persons` | `person_id`、`employee_no`、`person_name`、`current_department_id`、`employment_status`、`status`、`office_ids` |
| `offices` | `id`、`code`、`name`、`department_id`、`manager_person_id`、`status` |

响应为事务内读取的完整快照，包含停用、离职和归档记录供消费方核对状态，不以缺席推断删除。`snapshot_hash`用于判断快照是否变化，不是审批版本或时间顺序。接口不返回手机、邮箱、密码、账号或角色授权；响应禁止缓存，不将返回数据记录到访问日志。日志只记录接入方标识、路径、状态及请求编号等技术信息。

## 启用、迁移与恢复

角色模型为`rbac-raci-v5-2026-10-19`，共9个固定角色、22项权限、12项RACI活动。已有v3目标先完成治理职责迁移到v4，再执行人事角色迁移到v5；不可仅替换代码而跳过模型迁移。人事迁移保留原角色ID和人员授权，不自动授予任何人新角色；检查及恢复命令见[scripts/README.md](scripts/README.md#组织与员工目录专项)。正式目标执行前须明确目标、备份和恢复条件。

系统间接口默认关闭。只有同时配置`DIRECTORY_INTEGRATION_ENABLED=1`和受保护的`DIRECTORY_API_CLIENTS_JSON`才接受服务凭证。后者为数组，每项包含非敏感接入方标识`client_id`、256位随机凭证的SHA-256十六进制摘要`token_sha256`、布尔`enabled`及带时区的到期时间`expires_at`；最多100项，标识和摘要不得重复。明文随机凭证由接入方以`Authorization: Bearer <credential>`传递，不写入源码、页面、日志或本文。摘要配置也应作为私有部署配置管理，不提交仓库。

停用接口返回503；配置不完整返回503；缺失、错误、停用或到期凭证返回401。配置只赋予这一个基础目录读取入口，不授予3000其他接口权限。后续接入时明确系统、用途、传输保护和凭证交付方式，再配置和验收；本次不建立真实接入方凭证，不修改其他系统。

人事角色迁移提供只读检查、dry-run、apply及compensate。补偿仅限新角色从未产生任何历史人员授权的情况，保留新增权限、备份表及兼容的分组约束，不删除人员或历史版本。新角色已使用时不得强制回退，应保留备份并按实际数据制定恢复方案。提交结果不明先inspect核对，不盲目重试补偿。
