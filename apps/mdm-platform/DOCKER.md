## 运行与恢复

日常只操作准确的`infomat-mdm-3000`。启动后核对`/api/health`、`/api/ready`、来源摘要及实际功能开关；身份模型常量不能单独证明数据库状态。Windows的`service:*`入口不管理此Docker容器。

出现故障先保留当前数据和故障容器。确认只是应用版本问题、当前数据可信时，从仓库根使用本轮精确回退入口：

```powershell
node artifacts/3000-n01-n07-release-20261027/release.cjs rollback
```

该入口核对容器身份，停止新应用并恢复保留的同v5的R06—R10容器和原自动重启策略，不恢复旧dump、不回退数据库。部署后的新增记录继续保留。

数据库内容、结构或授权出现异常，或者数据可信性尚未确认时，使用兼容只读恢复入口：

```powershell
node artifacts/3000-n01-n07-release-20261027/release.cjs recover-readonly
```

该入口使用既有v5只读备用容器，阻止业务写入、设置治理只读标记并暂停后台待办草案生成器，保留查阅及登录/登出会话操作。只读恢复不修复数据，重新开放办理前须定位原因、核对后续记录和准确版本。以上入口均不操作3001；未知容器身份会拒绝继续。

不要重放此前批次的deploy、activate、迁移、授权或旧recover脚本，它们不适用于当前容器身份。本批deploy及prepare也已完成，不得重放。原v4及更早容器只用于追溯，不能直接启动替代当前v5服务。已有页面不强制刷新；用户先保存未提交输入，再手动刷新读取新界面。
