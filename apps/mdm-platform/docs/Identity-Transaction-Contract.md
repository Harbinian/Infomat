# 身份表示与事务内资格合同

本文说明当前源码的身份表示和资格读取边界，依据是本目录当前规则及对应身份、预览、发布、工作包和办公室仓储。实现检查不表示正式包已更新或业务已验收。

## 身份表示

普通人员会话由精确的账号、人员及密码代次绑定；独立系统管理员保持系统维护主体，人员为空，不生成虚拟员工或部门。安全整数保留数值类型，超安全范围的身份使用精确十进制字符串；已舍入的Number不能猜测恢复。身份表示只描述主体，不授予权限。

定义仓储的独立系统管理员读取使用现有系统身份校验，并在原事务连接上锁定系统账号复核状态、密码代次和强制改密要求，再读取现有权限。设计交接等读取仍须具备全局治理读取权限；空人员标识不单独判定为未登录，也不转换成人员主体。管理员治理写入继续返回403。

身份SQL采用精确字符投影及十进制绑定。相邻大整数不得因prepared参数解释或驱动插入元数据舍入而误关联。新标识通过原事务连接的字符型LAST_INSERT_ID读取；普通返回字段、历史JSON和可空关系保留。具体查询及错误合同按`server/sessionSubject.js`、`server/identityMysqlRepository.js`及对应路由核对。

## 写入资格

写入在原业务锁之后、首次业务写入之前，用同一事务连接复核账号状态、人员、当前会话、有效角色、权限和部门。路由预检、页面允许动作及历史任命不作为现场授权。管理员及叠加管理员仍遵守治理只读；编制专属资格、办公室负责人和成员办理范围分别复核。

普通账号维护由`server/accountMaintenanceAuthority.js`消费原权限门槛；独立管理员由原维护绑定和系统账号锁后状态及密码代次核验。读取展示、候选资格及角色汇总不产生维护或业务写权限。权限关联和祖先遍历保留原顺序、deny及字段限制；读取异常不得改写为空资格。

## 工作包事务与诊断

工作包创建任务与物化为两段事务。内部排队必须取得调用方原事务连接；池调用被`PROCESS_DATA_GOVERNANCE_TRANSACTION_REQUIRED`拒绝。物化按任务、来源版本、账号、人员、角色锁定，资格通过后再核对固定来源。

已通过现场资格的物化失败时，业务事务回滚；原池连接记录失败诊断、原错误和重试时间，不自动重放任务。身份拒绝不写诊断或改变任务状态；诊断失败仍返回原业务错误。失败诊断的进一步隔离设计仍待完成，不能把当前归属写成已确认的新业务规则。

## 摘要与已知限制

发布目录的原字段快照与精确身份视图分开。精确别名不进入原`baseHash`，历史正文、全文快照、审核摘要和既有业务摘要不重算。旧摘要在相邻大BIGINT被原驱动读为同值时可能不能识别来源变化；临时发布源摘要的新版本及旧待提交预览兼容仍需确定，不能宣称已全部闭环。

其他身份投影、页面中的Number转换、队列池合同及失败诊断隔离须按具体消费者继续核对。局部合同或真实隔离MySQL检查通过不表示上述剩余问题已解决。

## 登录返回与历史读取授权（R08、R01）

`POST /api/org/login` 的返回体在 MySQL 身份读模型下经 `identityInteger` 归一：安全整数范围内保持 number，超出范围保持精确十进制字符串，字段缺失或无法精确表示时为 null。当账号、人员或授权版本任一无法精确表示时，登录以 503 `IDENTITY_UNAVAILABLE` 拒绝并且不写会话，不截断、不取默认值、不新建身份；凭据在此之前已经核验，因此该拒绝不增加账号存在性通道。旧会话在身份或授权变化时按原合同显式失效。

`/api/versions/entity/:type/:id`、`/api/versions/mapping/:id`、`/api/versions/field/:id` 三个历史入口共用同一条范围授权：实体类型经`server/versionAuditScope.js`的白名单分派，未列出的类型不返回任何历史；`mapping`/`field_entry`按其承载对象（`data_map_contexts`/`data_map_fields`）所属部门判定，对象已删除且无法给出可核验归属时拒绝而不是默认开放；全公司治理材料仍要求 `governance:read-global`；保留的待办删除记录继续按原逐行部门过滤。拒绝与"不存在"返回相同状态码与相同响应体，调用方无法据响应区分二者，也不返回任何历史值。历史行不被删除或改写以关闭缺口。
