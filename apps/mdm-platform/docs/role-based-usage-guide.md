# 3000 角色化使用手册

## 1. 先确认自己的身份

登录后，工作台顶部显示：

- 当前人员；
- 当前部门；
- 全部有效MDM工作角色；
- 当前优先事项数量；
- 治理模型版本。

一人可以有多个MDM工作角色。系统合并展示为“我的工作台”，但每个事项和按钮仍按角色、部门、任务关系和对象状态分别校验。

如果页面提示账号已失效、权限已变化或必须修改密码，请重新登录或先完成改密。前端显示按钮不代表最终授权，服务端会在提交时再次检查。

流程治理只有一个顶部入口，内部包括“流程编制、跨部门承接待办、承接冲突待办、V7预览核对”。正式流程编制继续使用v3；3001继续独立、无状态运行。用户可以把3001导出的V7文件上传到预览核对工作区，由3000保存案例、修订、部门核对结果和处理进度。预览记录本身没有发布含义，也不会把核对结果写回V7文件；核对完成后，MDM工作组组长还要明确选择正式主档、提升当前修订，并等待正式审核通过后发布。

## 2. MDM系统管理员

角色编码：`admin`

### 目标

保证账号入口、授权记录和访问审计可用。

### 第一步

进入“账号与授权”，查看待启用、锁定或停用账号。

### 可以做

- 查看人员、账号、部门和固定角色。
- 手工创建待启用账号。
- 授予或撤销MDM工作角色。
- 启用、恢复、停用账号。
- 重置临时密码。
- 查看账号和授权审计记录。
- 在“角色可见标签”中只读查看固定标签和权限依据。
- 只读查看治理材料。

### 不能做

- 起草、修改或提交部门材料。
- 审核部门材料或记录部门业务决定。
- 处理业务冲突。
- 发布流程地图、数据地图或术语版本。

### 开户步骤

1. 取得已确认的登录名、工号、姓名和部门。
2. 选择固定MDM工作角色。
3. 填写授权依据、生效日期和可选失效日期。
4. 核对所选多个角色的“可见标签并集”。该预览不能编辑，也不替代服务端权限。
5. 创建待启用账号。
6. 核对账号和角色后执行启用。
7. 只通过受控渠道交付本次响应中的一次性临时密码。

### 常见错误

- 不得根据旧角色、岗位名称或历史名单自动授权。
- 部门角色只能授权到人员所属部门。
- 变更部门时必须同时填写原因和新部门角色安排。
- 停用和撤销必须填写原因。
- 不得停用或撤销最后一个有效管理员。

### 完成标准

账号状态、人员部门、有效角色、授权依据、有效期和访问审计一致。

## 3. MDM工作组组长

角色编码：`mdm_lead`

### 目标

在业务责任已经明确的前提下，使治理版本具备发布条件。

### 第一步

进入“我的工作台”，按待办跳转到“流程治理→跨部门承接待办”“流程治理→承接冲突待办”或“流程治理→V7预览核对”。

### 可以做

- 查看全公司治理材料。
- 分派治理事项。
- 分派承接责任部门和承接冲突处理人。
- 为归口部门待定的V7预览案例分派有效部门，并查看各部门核对进度。
- 在V7预览核对完成后，明确选择新建流程主档或已有流程主档，把当前修订提升为正式草稿。
- 检查结构、证据和责任链。
- 提请升级治理争议。
- 在发布卡口全部通过后发布治理版本。
- 在正式V7审核任务与当前修订号、内容摘要一致且审核通过后，发布原生V7版本并取得`process_version_id`。

### 不能做

- 代替部门负责人确认业务事实。
- 直接改写部门业务材料。
- 以全局角色跳过部门决定。
- 管理账号或角色。

### 发布步骤

1. 核对对象和版本。
2. 核对每个必需部门的最新决定。
3. 核对部门最终负责人是否完整。
4. 核对阻断问题已经关闭。
5. 核对结构和版本检查通过。
6. 执行发布并保留版本记录。

### 完成标准

发布版本具备完整责任证据、结构检查结果、版本检查结果和发布记录。

## 4. 部门主对接人

角色编码：`department_contact`

### 目标

将本部门确认的流程、数据和术语事实整理为可审核材料。

### 第一步

进入“流程治理→流程编制”，选择已有草稿或新建流程。收到V7核对修改意见时，在3001修改并下载新文件，再进入“流程治理→V7预览核对”上传到原案例。

### 可以做

- 查看本部门治理材料。
- 起草、修改和整改本部门材料。
- 使用左侧条目列表选择、上移或下移业务行为、流程关系、数据对象和跨部门承接；移动操作保留技术标识和引用。
- 查看结构化学习评分和跨职能流程图。评分用于提示结构缺项，不代表业务事实已经审核。
- 按当前承接步骤补充本部门实际承接流程、业务行为和完成标准。
- 提交本部门材料。
- 在归口部门已经明确时，上传本部门V7文件建立预览案例；收到修改意见后上传3001新修订。
- V7被受控提升后，提交本部门正式草稿审核；不能在3000直接修改V7正文。

### 不能做

- 查看其他部门材料。
- 审核本部门材料。
- 把个人判断写成部门负责人决定。
- 发布全局治理版本。

### 典型处理

根据制度、表单和业务人员说明补齐材料。无法确认的内容明确标记缺口，不用默认值补齐，然后提交部门MDM审核员。

### 完成标准

材料已经提交，缺失信息、证据和暂不能确认事项均有明确记录。

## 5. 部门MDM审核员

角色编码：`department_mdm_reviewer`

### 目标

审核本部门材料，并使部门最终责任可以追溯。

### 第一步

进入“我的工作台”查看本部门审核事项，并跳转到“流程治理→跨部门承接待办”或“流程治理→V7预览核对”。

### 可以做

- 查看本部门治理材料。
- 审核或退回本部门材料。
- 记录部门负责人已经在线下作出的决定。
- 核对跨部门事项中本部门的确认记录。
- 在承接冲突中接受或不接受协调方案，并记录依据。
- 对V7核对项记录本部门的“已确认、需要修改、待补证据、存在分歧”和依据。
- 对已经提交的正式V7草稿记录审核结论；审核任务显示的修订号或内容摘要过期时停止处理，并要求重新提交当前修订。

### 不能做

- 审核其他部门材料。
- 代替部门负责人作决定。
- 修改部门主对接人提交的业务事实。
- 发布全局治理版本。

### 记录决定步骤

1. 确认部门负责人已经在线下作出决定。
2. 选择治理领域、对象和版本。
3. 选择`approved`、`returned`或`rejected`。
4. 填写决定依据、决定时间和可选证据引用。
5. 提交后核对系统记录的部门最终负责人。

若系统返回`RESPONSIBILITY_CHAIN_INCOMPLETE`，先由组织资料负责人补齐部门最终负责人。审核员不得自行猜测。

### 完成标准

审核结果、部门最终负责人、决定依据、决定时间和记录人均可追溯。

## 6. 数据冲突处理人

角色编码：`data_conflict_handler`

### 目标

处理本人被明确分派的数据或术语冲突。

### 第一步

进入“流程治理→承接冲突待办”，只查看分派给本人的事项。

### 可以做

- 查看被分派冲突及完成处理所需的上下文。
- 记录双方立场、协调证据和协调方案。
- 处理普通冲突。
- 任一部门不接受协调方案后，填写依据并提请项目决策。

### 不能做

- 查看或处理未分派事项。
- 代替受影响部门确认业务事实。
- 决定重大升级争议。
- 发布治理版本。

### 完成标准

冲突已有协调记录、各部门决定，或有完整证据的升级记录。

## 7. 数据质量审计人

角色编码：`data_quality_auditor`

### 目标

识别数据完整性、准确性和一致性问题，并跟踪整改证据。

### 第一步

进入“数据质量”，查看全局数据治理信息和待复核整改。

### 可以做

- 全局读取数据治理信息。
- 记录审计发现。
- 提出整改要求。
- 复核整改证据。

### 不能做

- 修改部门源数据或部门材料。
- 代替部门作出业务决定。
- 发布数据地图或其他治理版本。

### 完成标准

审计结论有依据，整改事项有责任部门、处理状态和复核记录。

## 8. 项目决策组

角色编码：`decision_group`

### 目标

处理常规协调无法解决且已经升级的重大跨部门争议。

### 第一步

进入“流程治理→承接冲突待办”，查看已经升级且证据完整的争议。

### 可以做

- 查看已升级事项及必要上下文。
- 只能选择继续承接、认定无需承接或退回修订，并记录决定依据。

### 不能做

- 查看普通未升级冲突。
- 日常编辑或部门审核。
- 发布治理版本。
- 管理账号和角色。

### 完成标准

升级事项已有决定、依据、影响范围和后续责任记录。

## 9. 多角色与临时代办

- 多角色用户按每个动作所需权限分别校验，不会因为拥有一个全局读取角色而获得其他写权限。
- 顶部功能标签按全部有效角色取并集；“角色可见标签”页面可查看每个标签的访问方式和权限依据。
- 标签可见性由固定模型生成，不提供按角色或按账号自定义。
- 部门角色始终绑定人员所属部门。
- 跨部门临时代办通过独立委托关系处理，不修改永久角色范围。
- 委托只覆盖明确对象、时间和动作，不能变成全部门或全局访问。

## 10. 常见提示

| 提示 | 处理方式 |
|---|---|
| `ROLE_ASSIGNMENT_EVIDENCE_REQUIRED` | 补充角色、授权依据或生效日期 |
| `ROLE_SCOPE_DEPARTMENT_MISMATCH` | 将部门角色范围改为人员所属部门 |
| `RESPONSIBILITY_CHAIN_INCOMPLETE` | 补齐部门最终负责人或必需部门决定 |
| `LAST_ACTIVE_ADMIN` | 先确认并启用另一名管理员 |
| `CORE_GOVERNANCE_MODEL_READ_ONLY` | 固定模型只能查看，不能在页面修改 |
| `LEGACY_IDENTITY_API_RETIRED` | 改用“账号与授权”页面或`/api/org/accounts` |
| `DRAFT_REVISION_CONFLICT` | 草稿已被其他人员修改；重新载入后合并内容，再使用最新修订保存 |
| 会话已失效 | 重新登录；账号、部门或角色可能已变化 |
