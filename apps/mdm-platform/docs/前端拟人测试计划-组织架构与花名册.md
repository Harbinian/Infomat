# 前端拟人测试计划：组织架构与花名册

> 本计划用于 MDM 平台（3000）`/app/organization`（组织架构）与 `/app/roster`（花名册）两个页面的拟人（人工）验收。用例预期由当前后端实现推导，来源见文末追踪表；`docs/` 不作为业务真源，若与 3000 实际实现或用户确认口径不一致，以实测与确认口径为准。
>
> 拟人指：由测试人员用真实浏览器、真实中文输入法，按业务用户视角逐步操作，观察页面反馈与落库结果，不依赖自动化脚本。桌面与窄屏适配不在范围内（仅 Edge 100%、1699×828 CSS 像素）。

## 1. 目的与范围

第一轮覆盖“先配置组织架构、再配置花名册”的主链路及其服务端硬约束：

- 组织架构与花名册的查阅、导入准备、核对、正式发布、版本与下载；
- 组织与花名册之间的依赖顺序（部门 → 花名册 → 办公室及负责人 → 再次导入花名册补充办公室归属）；
- 由后端校验推导的边界与错误分支；
- 身份与权限差异、输入保护、并发与幂等。

账号与授权办理、访问审计、角色详细管理等页面在本计划后续轮次补充，本文只覆盖其作为前置条件的部分。

## 2. 执行前提

### 2.1 环境与入口

- 目标为隔离或获授权的 3000 实例，前端入口 `/app/`；未登录跳转登录页，登录成功后默认进入 `/app/workbench`，独立管理员默认落到 `/app/accounts`。
- 仅验证 Edge 100%、1699×828 CSS 像素；确认页面无横向滚动，缩放为 1。
- 准备好手工导入用的合成文件：组织架构 `.xlsx`/UTF-8 `.csv`、花名册 `.csv`，列名与模板一致。
- 记录基线：开始前导出或记录当前组织层级、花名册行数、已发布版本号，便于对比。

### 2.2 账号与权限矩阵

按固定治理模型（`rbac-raci-v3-2026-07-31`）核对，实际账号须已存在；**不得临时越权授权，也不得用管理员代办发布**。

| 身份 | 组织架构页面（层级查阅） | 花名册页面 | 手工导入准备 | 正式发布 |
|---|---|---|---|---|
| `admin`（MDM系统管理员） | 可见 | 可见 | 可准备、可核对 | 不可（管理员被排除发布） |
| `mdm_lead`（MDM工作组组长） | 可见 | 不可（需 `identity:read`） | 可准备、可核对 | 可发布 |
| `department_contact`（部门主对接人） | 层级可见，导入/发布区无权 | 不可 | 不可 | 不可 |

页面按钮的可见性与可点性依据服务端 `canPrepare`/`canPublish` 返回，而不是页面本地判断；页面不授予权限。

### 2.3 基础数据与首导顺序

组织架构与花名册是两条相互依赖的目录，必须按固定顺序首次导入，否则后一步会因前置对象不存在或不启用而报错：

1. 导入并发布 **部门**（组织层级=部门）；
2. 导入并发布 **花名册**（人员 + 明确部门归属）；
3. 导入并发布 **办公室及负责人**（组织层级=办公室）；
4. 再次导入 **花名册**，用“办公室编码”列补充人员与办公室的归属关系。

### 2.4 通用拟人约定

以下约定在全部用例中反复核对：

- **输入保护**：导入草稿未提交时离开页面、切换页面或刷新，应弹出确认；放弃须显式确认，未确认则保留输入。
- **提交二次确认**：发布前弹确认框；取消则不写入。
- **失败保留输入**：导入失败、`403/409/503` 或断网后，当前文件、列对应与核对结果不被静默清空。
- **刷新与重读**：页面提供“刷新组织架构/花名册”“刷新发布记录”，刷新后仍按 URL 查询参数还原筛选。
- **不静默应用**：任何可见输入在切换、重绘、下载、替换或离页时不得静默丢失或静默生效。

## 3. 组织架构配置

组织架构没有前端直接增删改部门的入口；仓库中 `POST/PUT/DELETE /api/org/departments` 一律返回 405（组织真源只读）。**配置只能通过“手工导入组织架构 → 核对 → 发布”完成**，据此设计用例。

### 3.1 页面查阅（OB-01~04）

| 用例 | 前置 | 操作 | 预期 |
|---|---|---|---|
| OB-01 | 已发布部门与办公室 | 打开 `/app/organization` | 显示“当前组织层级”树，节点形如“名称 · 编码 · 部门/办公室”；同时显示表头为“编码/名称/类型/上级 / 归口部门/办公室负责人/状态”的清单 |
| OB-02 | 同上 | 组织类型筛选选“部门/办公室” | 仅保留对应类型；办公室“办公室负责人”列显示负责人或“尚未指定”，部门显示“不适用” |
| OB-03 | 存在循环或过深层级 | 打开页面 | 树正常渲染其余节点，并对循环/层级过深记录给出“请在导入核对时处理”的提示，原始记录仍在下方列表可见 |
| OB-04 | 无匹配记录 | 搜索不存在的编码/名称 | 清单为空且不报错；刷新后保持搜索条件 |

### 3.2 首次导入部门（OB-10）

- **前置**：当前部门目录为空或仅有历史数据；准备 `部门编码,部门名称,上级部门编码` 列的文件。
- **步骤**：
  1. 点击“手工导入组织架构”，填写发布名称；
  2. 选择 `.xlsx` 或 UTF-8 `.csv`，点击“读取文件”；
  3. 在“确认列对应关系”核对“组织编码”“组织名称”等必填映射（系统给出建议映射），必要时手工调整；
  4. 点击“核对导入内容”，查看“新增/更新/无变化”统计与逐行变更；
  5. 勾选“我已核对文件、列对应关系和变更结果，确认发布此版本”，点击“发布此目录版本”。
- **预期**：发布后刷新，组织层级出现新部门；发布记录新增一条 `v1`。

### 3.3 首次导入办公室及负责人（OB-11）

- **前置**：部门已发布且启用；花名册已发布，负责人为**在职且有效**人员。
- **步骤**：同 OB-10，文件列含 `组织编码,组织名称,组织层级(办公室),归口部门编码,办公室负责人工号`。
- **预期**：办公室出现在树中并归入对应部门；清单“办公室负责人”列显示负责人工号对应人员；“上级/归口部门”显示归口部门名称。

### 3.4 校验与错误分支（OB-20~32）

构造下列文件，逐条核对页面错误提示（提示文案以实测为准，判断依据以服务端为准）。存在错误时“发布”按钮不可用，且不出现确认勾选框。

| 用例 | 构造 | 预期 |
|---|---|---|
| OB-20 | 组织编码或组织名称留空 | 预览报错“第 N 行的……”；不可发布 |
| OB-21 | 组织层级填“部门”“办公室”以外的值 | 报“组织层级只能是部门或办公室” |
| OB-22 | 办公室行缺“归口部门编码” | 报“办公室缺少归口部门编码” |
| OB-23 | 办公室编码含 `; ； 、 换行` | 报“办公室编码不能包含成员关系分隔符” |
| OB-24 | 上级部门编码指向不存在的部门（且不在本文件内） | 报“上级部门编码不存在” |
| OB-25 | 上级关系形成环（A→B→A） | 报“……上级关系形成循环” |
| OB-26 | 文件内组织编码重复（忽略首尾空格与大小写） | 报唯一标识重复（前端映射为“唯一标识重复……”），不可发布 |
| OB-27 | 组织编码已被办公室占用，却按“部门”导入 | 报“该组织编码已被办公室使用，不能转换为部门” |
| OB-28 | 办公室编码与已有部门编码相同 | 报“该组织编码已被部门使用，请为办公室使用独立编码” |
| OB-29 | 办公室行填了“上级部门编码” | 报“办公室请使用归口部门编码，上级部门编码应留空” |
| OB-30 | 办公室负责人工号在花名册不存在，或该人非在职 | 报“办公室负责人必须是花名册中当前有效的在职人员” |
| OB-31 | 将仍有在职人员或启用办公室的部门置为停用/归档 | 报“部门仍有在职人员/办公室，请先调整后再停用或归档” |
| OB-32 | 将仍有有效成员或未办结任务的办公室置为停用/归档 | 报对应阻断信息；办公室调归口部门时若仍有未办结任务，同样阻断 |
| OB-33 | 导入 `status` 列填“有效/启用/停用/归档”以外值 | 报“部门状态无效” |

### 3.5 发布、版本、模板与下载（OB-40~43）

| 用例 | 操作 | 预期 |
|---|---|---|
| OB-40 | 点击“下载组织架构空白模板” | 下载到含标准列名的 `.xlsx` 模板 |
| OB-41 | 打开“组织架构导入与发布记录”，查看版本 | 显示发布名称、版本号、行数、源文件、发布时间；可“查看版本” |
| OB-42 | 在版本详情点“下载此版本 Excel”与“下载完整记录 JSON” | 下载成功；JSON 保留原始列与值，含原始扩展列 |
| OB-43 | 再次导入含变更的新文件并发布 | 版本号递增（v2）；未在文件中出现的组织继续保留，不被删除 |

### 3.6 权限差异（OB-50~52）

| 用例 | 身份 | 预期 |
|---|---|---|
| OB-50 | `admin` | 可见“手工导入组织架构”，可读取文件并核对；发布按钮不可用，并提示“当前身份无正式发布权限，可以保留并核对本次输入” |
| OB-51 | `mdm_lead` | 可准备并可正式发布；组织层级与发布记录均可读 |
| OB-52 | `department_contact` | 层级树可见；导入/发布区显示无权，`/api/publications*` 返回 403 |

## 4. 花名册

花名册记录人员目录，与账号开通分别办理；**发布花名册不会创建登录账号**（账号在“账号与授权办理”单独管理）。花名册中明确的办公室归属只显示已导入关系。

### 4.1 页面查阅（RS-01~03）

| 用例 | 前置 | 操作 | 预期 |
|---|---|---|---|
| RS-01 | 已有人员 | 打开 `/app/roster` | 顶部显示“在职 X 人 · 部门待明确 Y 人 · 当前显示 Z / W 人” |
| RS-02 | 存在离职/停职人员 | 在职状态筛选 | 仅保留对应状态；未提供手机/邮箱显示“未提供”，未关联部门显示“未关联部门” |
| RS-03 | 人员归属多个办公室 | 查看“办公室”列 | 以“名称（编码）”形式列出，多个以“、”分隔 |

### 4.2 首次导入（RS-10）

- **前置**：部门已发布且启用；文件列为 `工号,姓名,部门编码`（或部门名称）。
- **步骤**：同 OB-10 的准备流程，选择发布名称为花名册的导入。
- **预期**：预览显示新增计数；发布后花名册新增该人员，部门正确关联；发布记录新增 `v1`。

### 4.3 补充办公室归属（RS-11）

- **前置**：办公室已发布，人员已存在。
- **步骤**：导入含 `工号,姓名,部门编码,办公室编码` 的文件（办公室编码可用 `; ； 、 换行` 分隔多个）。
- **预期**：人员记录不变（`person_id` 稳定），仅归属更新；页面“办公室”列显示新归属。未映射办公室列时保留既有归属；映射列的空值表示移除归属。

### 4.4 校验与错误分支（RS-20~29）

| 用例 | 构造 | 预期 |
|---|---|---|
| RS-20 | 工号或姓名留空 | 报对应必填为空；不可发布 |
| RS-21 | 既未映射部门编码也未映射部门名称 | 报“请选择部门编码或部门名称对应的文件列” |
| RS-22 | 部门编码不存在、未启用，或部门名称不唯一 | 报“部门不存在、未启用或名称不唯一……” |
| RS-23 | 同一行部门编码与部门名称不一致 | 报“部门编码与部门名称不一致” |
| RS-24 | 工号重复（忽略首尾空格与大小写） | 报唯一标识重复；不可发布 |
| RS-25 | 在职状态填“在职/离职/停职/停用”以外值 | 报“在职状态无效” |
| RS-26 | 办公室编码不存在、未启用或尚未明确归口部门 | 报对应错误 |
| RS-27 | 同一人员办公室编码重复 | 报“同一人员的办公室编码重复” |
| RS-28 | 调整部门的人员仍有部门范围有效角色 | 报“请先撤销原部门授权，再调整部门” |
| RS-29 | 将离职/停职人员但其账号仍有效；或将系统管理员按业务花名册修改 | 分别报“请先停用账号”“系统管理员身份不通过业务花名册修改” |
| RS-30 | 将仍是启用办公室负责人的人员改为离职/停职；或移除仍有未办结办公室任务的人员归属 | 报对应阻断信息 |

### 4.5 发布与版本（RS-40~41）

| 用例 | 操作 | 预期 |
|---|---|---|
| RS-40 | 下载花名册空白模板、查看发布记录、查看版本详情与下载 | 行为同 OB-40~42；JSON 保留原始扩展列 |
| RS-41 | 二次导入更新人员信息并发布 | 版本号递增；人员 `person_id` 不变；不新建登录账号 |

### 4.6 与账号的关系（RS-50）

- 发布花名册后，到“账号与授权办理”核对：**该人员存在但没有账号记录**（`account_status` 为空/无账号）。
- 花名册页面对“已发布人员但无账号”不做账号状态断言，避免把目录记录误显示为已开通账号。

### 4.7 权限差异（RS-51~52）

| 用例 | 身份 | 预期 |
|---|---|---|
| RS-51 | `admin` | 可查阅花名册、可准备、不可发布 |
| RS-52 | `mdm_lead`、`department_contact` | 打开花名册显示“花名册暂不可用”，`/api/org/roster` 返回 403（花名册读取需 `identity:read`） |

## 5. 跨模块一致性与并发

| 用例 | 场景 | 预期 |
|---|---|---|
| XC-01 | 导入草稿未提交时切换页面 | 弹确认；取消则留在原页并保留文件与列对应 |
| XC-02 | 导入草稿未提交时刷新/后退 | 弹确认；未确认不丢失输入 |
| XC-03 | 先“核对导入内容”，另一端修改了同一目录或产生新版本后再发布 | 发布返回 409，页面丢弃旧核对结果并提示重新核对；输入文件保留 |
| XC-04 | 发布请求响应丢失（网络中断）后再次点击发布 | 同一请求标识幂等：不产生重复版本，最终只落一条发布记录 |
| XC-05 | 预览通过但未勾选确认即点发布 | 发布按钮不可用，不能绕过确认 |
| XC-06 | 预览含错误 | 不出现确认勾选框，发布按钮始终不可用 |
| XC-07 | 提交任一发布时双击按钮 | 只提交一次，不产生重复版本 |
| XC-08 | `admin` 多角色后仍尝试发布 | 仍被服务端拒绝（管理员不因叠加业务角色获得发布权） |
