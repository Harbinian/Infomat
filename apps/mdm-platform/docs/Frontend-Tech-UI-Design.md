# 3000 第一期桌面表现层与交互规格

本规格描述当前源码中的桌面实现，不提供业务规则。用户指定的 开发提示词（仅本机保留） 确定本期范围；原 Spec 的独立原型、取消第二期、R3F/Drei 和完全不变 CSP 等冲突项未采用。第二期完整多端仍保留，本期没有新增窄屏断点或执行窄屏测试。候选实现、隔离技术验证、实际开启和业务验收分别记录。

## 设计令牌表

唯一令牌入口为 `frontend/src/presentation/tech-ui.css`。公共组件和全部当前 React 页面消费同一主题，不另建原型应用。

| 语义 | 令牌与实际值 | 使用条件 |
|---|---|---|
| 页面基底 | `--bg-base: #08111F` | 外壳和背景 |
| 业务面板 | `--surface: #111C30` | 表格、审核、录入实色面板 |
| 次级面板／输入 | `#172640`／`#0B1628` | 历史、来源、字段及只读明细 |
| 正文／次级文字 | `#E6EDF8`／`#9AAAC2` | 正文14px，页面标题26px |
| 主强调／装饰 | `#22D3EE`／`#A78BFA` | 主要按钮深色字；装饰不表达治理结论 |
| 焦点 | `--focus: #67E8F9` | 3px可见轮廓，保留原生光标 |
| 控件边界 | `--border: #5B7895` | 必要输入和按钮边界相对实际实色控件背景至少3:1 |
| 错误／成功 | `#FFB4B4`／`#8FE0BA` | 原状态名称、说明和权限不变 |

| 外壳 | 顶栏64px／侧栏232px | Edge100%、1699×828 CSS像素，主区与侧栏分别滚动 |
| 玻璃 | 顶栏8px模糊 | 基础档、减少效果和高对比模式回退实色 |

输入、表格与审核按钮不倾斜。登录、工作台和看板局部有抽象线框与粒子；真实流程及数据关系继续由 ECharts/Cytoscape 承担。暗色图形配置仅在3000消费层叠加。PNG生成前临时恢复共享渲染器原打印样式，随后恢复屏幕样式；原正文、来源、版本和下载结构保持。

## 动画与交互规格表

| 效果标识 | 触发及停止 | 减少效果／失败回退 | 清理 |
|---|---|---|---|
| `entrance` | 当前页面标题进入，200ms、6px；原导航先完成 | 暂停、系统或用户减少效果时取消位移；模块失败保留标题 | 停止Motion实例并撤销局部样式，不改变页面key |
| `ripple` | 有效按钮指针或键盘点击，160ms；禁用不播放 | 减少/暂停时移除；反馈不调用业务提交 | 清除定时器与效果登记 |
| `pointer` | 登录展示区、工作台展示卡及看板指标卡；最大3° | 输入、表格、审核按钮关闭；基础档回退实色平面 | 与采样共用调度，移除3个监听、样式与回调 |
| `lottie-loading` | 真正loading状态持续220ms后加载，循环 | 文案始终先显示；Worker/WASM/资产失败回静态SVG | 取消迟到实例调用、移除事件、销毁播放器；库缓存一个共享空闲Worker，不持续绘制 |
| `lottie-success/error` | 原组件已有结果状态出现后播放一次，1秒 | 无预演结果，错误说明及重试保持；减少效果立即显示静态符号 | 同加载播放器；小型动画JSON共用只读缓存，避免短请求结束后库产生中止加载日志 |
| `scene` | 登录、工作台/看板可见区域；页面首轮呈现后空闲加载 | 不支持OffscreenCanvas、Worker失败或WebGL上下文丢失时静态SVG/渐变；不切主线程重场景 | 一个场景一个Worker/canvas；断开Resize/Intersection观察器，停止调度，释放几何/材质/WebGL并终止自有Worker |

`PresentationProvider` 只管理本次页面会话的显示设置：自动、增强、减少效果、暂停、质量及诊断。系统减少动态效果优先，设置不写浏览器存储。自动从标准档开始，用户增强从高档开始；标准粒子最多96、像素比最多1，高档最多300、像素比最多1.5，基础档关闭连续场景和跟随。两个连续可见2秒窗口低于55fps或估计丢帧比例超过5%时降一级；本会话不自动升档，用户可重新检测。帧率为rAF调度估计，刷新周期通过预热样本估计，不硬编码60Hz。

诊断默认关闭，仅记录固定效果标识、窗口、回调耗时、支持的性能事件、降档原因与资源计数，不记录身份、密码、URL参数或业务材料，也不发送遥测。Event Timing原始事件没有冒充整页INP；不支持的API与尚未取得的INP使用null和原因。

## 功能覆盖与验证矩阵

当前入口清单以 `shared/browserProtocol.pages` 为准。`scripts/collect-tech-ui-evidence.js` 从该清单和实际组件、子组件、操作节点生成 `source-coverage.json` 与 `coverage-matrix.md`；新增入口未补组件映射时检查失败。源码状态登记与实际运行证据分开。构建、全部入口截图、正常办理与异常状态、输入保护、图形几何、下载、权限及资源检查的对应证据见 性能与验证报告（仅本机保留）。

本期全入口检查采用受限合成身份，业务专项采用自有临时MySQL和合成材料；两类证据互相补充，不将错误页截图表述为所有办理动作已通过。人工IME、辅助技术、指定办公硬件与业务验收仍按报告的实测状态说明。WCAG2.2 AA及动画可关闭是实现与审阅目标，自动化和令牌对比度不能单独证明整站符合。

## 同源资源和维护

前端精确锁定Motion14.0.0、Three0.186.0、dotlottie-react0.20.0及dotlottie-web0.81.0；React/Vite原版本保持。各依赖MIT许可证及公开导出通过本地npm元数据核对。Lottie使用包根软件Worker入口，并通过公开 `setWorkerUrl`、`setWasmUrl` 配置Vite输出资产；[官方Worker说明](https://docs.lottiefiles.com/en/runtimes/distributions/react/v0.x/api-reference)区分异步实例和共享Worker。Three通过模块Worker和OffscreenCanvas绘制抽象场景；不引入R3F、Drei或第二套播放器。

`assetsInlineLimit: 0` 禁用资产内联；Worker、WASM、动画JSON均在同一候选的 `/app/assets/`。CSP源码仅增加 `worker-src 'self'` 与 `script-src 'self' 'wasm-unsafe-eval'`；不允许blob Worker、外域、内联脚本、JS eval或脚本哈希回退，其他原策略保持。候选Express提供WASM的正确MIME，实际服务策略仍以正式发布后的响应为准。

候选开发写新的仓库artifacts目录，不使用默认 `build:frontend` 覆盖运行中的 `frontend/dist`。后续授权发布以当前不可变Docker镜像为基线，仅更新已验证构建和CSP并保留恢复容器；本次运行对象见[Docker说明](../DOCKER.md)。隔离测试入口、依赖和清理见 [脚本说明](../scripts/README.md)。
