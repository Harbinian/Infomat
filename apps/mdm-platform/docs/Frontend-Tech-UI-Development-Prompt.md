## 5. 技术路线与内部职责

当前核对基线：React/react-dom 19.2.6、Vite 8.0.14、React 插件 6.0.2、Node `^20.19.0 || >=22.12.0`。执行时重新读取本地清单，不为 UI 升级顺手更新现有栈。

2026-10-14 核对过的新增依赖基线如下，安装时使用精确版本并维护前端自己的锁文件。重新核对包导出、浏览器支持与许可证；发现实质兼容问题先说明，不自动改用另一套架构。

| 依赖 | 版本 | 用途 |
|---|---|---|
| `motion` | `14.0.0` | `LazyMotion` 与按需加载的 React 微交互和入场动画 |
| `three` | `0.186.0` | Worker 内 WebGL 粒子与抽象低复杂度 3D 模型 |
| `@lottiefiles/dotlottie-react` | `0.20.0` | `DotLottieWorkerReact`；其声明的核心依赖为 dotlottie-web 0.81.0 |
| `@lottiefiles/dotlottie-web` | `0.81.0` | 显式依赖用于导入自托管 Worker/WASM 资源，与 React 包装层保持配套 |

默认不引入 R3F、Drei、GSAP、lottie-web 或实验性 WebGPU，不并存两套 Lottie 播放器。需要额外依赖时说明具体收益和实际开销，并遵守当前授权与项目规则。

新增能力保持小而明确：

- `PresentationProvider` 管理会话内展示模式 `auto/enhanced/reduced`、质量 `high/standard/basic`、暂停与可见性。系统减少动态效果优先，不能被 enhanced 模式覆盖。
- 展示组件只读取业务状态和现有回调；不拥有业务草稿、身份、提交资格或服务器结果。效果注册以固定效果标识关联采样与清理，不引入泛用动画引擎。
- 自研指针效果与采样共用调度器；Motion 和播放器使用其自身调度。逐帧更新使用 ref、MotionValue 或局部样式，不逐帧更新页面 React 状态。
- Lottie 从包根入口使用软件渲染的 Worker 版本。GPU/WebGL/WebGPU 版本当前没有 Worker 播放能力，不混用或宣称 Worker 播放为 GPU 加速。
- Three.js 模型与粒子共享一个可见场景的 Worker/canvas；主线程仅发送尺寸、最新指针、可见性和质量等少量数据。无需加载真实业务拓扑、外部纹理或人物素材。

### 同源资源与 CSP

Worker、WASM、Lottie 资源输出到同一候选构建的 `/app/assets/`，不得默认从 CDN 取文件或使用 blob Worker。使用库公开导出和 Vite 资产导入，明确设置 `setWorkerUrl`、`setWasmUrl`；对这些资源禁用内联，验证所有路由下 URL 正确、文件内容正确和 WASM MIME 正确。

当前库公开了 `@lottiefiles/dotlottie-web/dotlottie.worker.js` 与 `@lottiefiles/dotlottie-web/dotlottie-player.wasm`；可通过 Vite URL 导入交给播放器，不需要自行编写 Lottie 渲染引擎。

在源码和隔离服务中最小调整 `server/cspPolicy.js`：`worker-src 'self'`、`script-src 'self' 'wasm-unsafe-eval'`。保留其他当前有效策略，不开放外域、内联脚本、JavaScript `eval`、`new Function` 或宽泛脚本许可。CSP 测试按精确指令项检查，不能因 `wasm-unsafe-eval` 含有相似字符而删掉对 `unsafe-eval` 的保护。实际运行服务的 CSP 更新随正式发布另行执行。

### 动效失效与清理

库的 Worker 实例方法是异步调用，处理迟到结果及取消，避免旧播放请求在暂停或卸载后重新启动。处理 Worker/WASM/动画加载失败、渲染失败、WebGL 上下文丢失与不支持 OffscreenCanvas 等情况，回退静态 SVG/渐变和真实状态文字；不改用主线程重场景来掩盖失败。

退出页面、减少动态效果或对象销毁时，停止播放和调度、断开观察器、移除监听、释放本组件拥有的几何/材质/纹理/WebGL 资源。共享播放器 Worker 按引用计数或库机制管理，不因某组件卸载破坏其他实例。

## 6. 动画与交互规格

| 场景 | 默认实现与约束 |
|---|---|
| 页面进入 | 180–220ms 透明度与不超过 8px 位移；原离页确认通过后执行，不等待退出动画再导航 |
| 区域入场 | 160–240ms；展示卡片少量错峰，总错峰不超过 300ms；表格行和图节点不逐项播放 |
| 普通微交互 | 100–160ms，保留原点击面积和焦点；动画结束不触发提交或权限刷新 |
| 加载 | 初始保留原可访问加载说明；Lottie 按真实 pending 状态播放，支持暂停，停止与完成都不生成业务结果 |
| 成功与失败 | 接收既有请求结果后播放一次短反馈；不预演成功、不循环警示闪烁，错误文字与重试动作完整保留 |
| 鼠标跟随 | 仅登录展示区、展示卡片和允许的看板区域；保留原生光标，装饰层不收点击，表单区关闭 |
| 点击涟漪 | 指针位置或键盘居中反馈；禁用按钮不产生可操作暗示，装饰不进入阅读顺序 |
| 悬停倾斜 | CSS 展示卡片不超过 4°，离开复位；表格、输入区和审核按钮保持平面 |
| 阻尼 | 仅装饰模型旋转与展示面板边缘反馈；业务列表原生滚动、现有图形平移/缩放保持原行为 |
| 连续粒子与 3D | 登录展示区、工作台/看板局部可见区域运行；隐藏暂停，离开释放，基础模式静态回退 |
| 手势 | 第二期图形平移缩放、展示内容切换；全部提供按钮/键盘替代，审批发布删除仍用原明确动作 |

保持原路由、浏览器前进后退、定位参数、身份 key、草稿生命周期和标题焦点处理。不对业务页面直接使用可能延迟卸载或使多页同时存活的 AnimatePresence 包装；优先稳定外壳上的入场与装饰过渡。增加包装时核对固定浮层、定位包含块、焦点和叠层。

## 7. 性能监测、预算与降级

监测从最小动效接入阶段开始，诊断面板默认关闭。记录构建、浏览器、可见性、效果标识、模式、帧间隔、回调耗时、降档原因及支持的长任务/Long Animation Frame 指标；不收集业务内容、人员、密码、案例参数或上传材料，不新增上报服务或第三方遥测。

`requestAnimationFrame` 频率是调度估计，不能当作实际 GPU 呈现帧率。结合前台浏览器性能轨迹判断卡顿和归因；隐藏、预热、无连续动效的区间单独标记。每个效果应有启停和采样登记，连续效果按窗口观测，一次性效果按发生区间观测。API 不支持时如实记录，不能填零代表通过。

| 指标 | 验收目标 |
|---|---|
| 测试环境 | 指定普通办公电脑、优化构建、前台 Edge、100% 缩放、1699×828 CSS 像素；记录实际版本与刷新率 |
| 常用场景 | 预热后 30 秒，平均估计帧率 ≥58fps、帧间隔 P95 ≤18ms；结合轨迹核对真实卡顿 |
| 新增动效开销 | 不引入超过 50ms 的长任务；主线程自研动效回调 P95 ≤2ms，整页业务脚本和布局绘制分别记录 |
| 交互响应 | 有代表性的交互 INP ≤200ms，按规范或可靠测量工具聚合；单次事件延迟不能冒充整页 INP |
| 首屏增量 | 相对于原候选构建新增首屏 JavaScript ≤50KB gzip；Motion、Lottie、WASM、Three.js 均按需控制，重资源不进入首屏关键路径 |
| 资源稳定性 | 连续切换页面 20 次后，无活动 Worker、观察器、监听器或 WebGL 资源持续累积 |

标准档粒子上限 96、像素比上限 1；增强档粒子上限 300、像素比上限 1.5；基础档关闭连续粒子、3D 和跟随，仅保留清晰的短反馈或静态表现。自动模式从标准档开始，触控端按实际能力保守启用。

对可见连续动效，连续两个 2 秒窗口估计帧率 <55fps 或丢帧估计比例 >5%时降一级。丢帧估计以实际刷新周期 T 为基准，统计间隔 >1.5T 的采样比例；排除隐藏或暂停区间。本会话不自动升档，用户可主动重新检测；不因高刷设备将帧率硬编码为 60 或降低动画速度来假装流畅。

仅优先动画 transform/opacity。filter、模糊、阴影与混合效果单独做绘制检查；读写分离，will-change 临时启用并回收。content-visibility 先用于独立只读区块并配置尺寸占位，不等同于虚拟化；不默认应用到编辑表格、错误定位或焦点关键区域。

性能比较使用相同合成数据、操作步骤及构建方式，记录普通场景与压力场景的规模；压力数据不代表业务容量。没有指定办公硬件时继续完成实现与可获得的验证，标记该硬件性能未验证；CPU 节流、模拟终端或高配机器结果不能冒充实机验收。

## 8. 无障碍与第二期多端

目标为 WCAG 2.2 AA，另实现 2.3.3 AAA 的交互动画可关闭要求。不要仅凭扫描器无错误宣布整站符合。

保留跳过导航、标题焦点、Tab 顺序、状态播报、错误关联、密码管理器与键盘办理。登录前后均提供可访问的减少动态效果/暂停入口，遵从系统偏好；减少模式停止连续装饰和位置变化，业务反馈文字立即、完整呈现。

普通操作目标至少 24×24 CSS 像素，主要触控操作按 44×44 设计；色彩不是唯一表达。拖拽和复杂手势提供单次点击及键盘替代，装饰画布 aria-hidden、不占焦点、不遮挡真实控件。

第二期使用 ≥1280px、768–1279px、≤767px 三档布局。各端保留完整字段和原有业务动作：密集表格可局部滚动或摘要加完整详情；图形独立查阅；抽屉与分区仅调整呈现，不新增审批步骤、录入前置条件或删去办理入口。复用同一表单状态，断点变化不复制可编辑控件或重新挂载导致输入丢失。

桌面和平板覆盖 Edge/Chrome，手机覆盖 Android Chrome 与 iOS Safari；增加 320 CSS 像素重排、文字放大、横竖屏、软键盘遮挡、触控与焦点验证。模拟浏览器用于技术检查，真实设备、辅助技术和人工中文 IME 未检查时单独标注限制。

## 9. 执行顺序与验证入口

按以下顺序连续推进必要的安全可逆工作，修复相关失败后复验，不在每个阶段追加无必要的设计审批。明确限定一期的任务在该期交付后结束。

1. **基线与覆盖**：检查最新工作树、页面协议、组件、业务异常和测试；形成覆盖矩阵及四项设计附件，记录原构建与性能对照方法。
2. **桌面视觉**：建立令牌与公共组件，再覆盖全部页面和子功能；检查真实 Edge 布局、表格密度、图形文字、遮挡、对比度和焦点。
3. **最小 Worker 动效**：完成一个加载与一个结果动效，验证同源 Worker/WASM、CSP、异步取消、减少模式及静态回退；随后扩展普通动效和局部粒子/3D。
4. **桌面完整验证**：执行受影响的前端合同、CSP、浏览器流程、图形与性能检查，修复任务导致的失败，形成桌面候选交付与限制清单。
5. **第二期完整多端**：在已稳定桌面实现上重排，逐项对照完整功能矩阵，执行多端、触控、重排与无障碍检查；保留一期桌面表现与行为。
6. **交付与发布准备**：同步受影响的当前说明、构建/验证命令和回退方式，交付候选构建及证据；正式服务更新按另行授权执行。

已存在的相关入口包括 `npm.cmd --prefix frontend test`、`test:frontend`、`test:frontend-shell`、`test:frontend-shell-browser`、`test:process-preview-browser`、`test:process-formal-browser`、`test:native-diagrams-browser`、`test:dashboard-browser`，以及直接执行的 `scripts/test-csp-policy-contract.js`、`scripts/test-csp-browser.js`。以执行时 package.json 和脚本说明为准，不虚构 `test:navigation-*` 等命令。

上述入口可能默认读取 frontend/dist；在运行前核对副作用和候选目录支持。必要时只扩展相关测试入口，使其接收独立候选构建目录，保持默认行为兼容；复用 `frontendRouter(dist)` 参数及已有隔离夹具，不扩大静态发布白名单或读取正式配置。壳测试原先只允许 JS/CSS 资产，新增 WASM/动画资源时使用精确类型与清单校验，保留禁止源码、材料、Secret、旧 UI 和任意 SPA 回退的断言。

构建使用 Vite 已支持的 outDir 覆盖参数写入新候选目录；不要直接运行会覆盖运行中 frontend/dist 的默认 `build:frontend`。按影响面选择浏览器测试，优先补齐本次特有的效果关闭、Worker 失败、资源释放、焦点和多端输入保护检查，不无条件执行全仓测试。

必须覆盖：

- 未提交输入后导航、取消离页、前进后退、刷新身份、退出与同身份重登；取消时输入完整保留，跨身份不暴露或重绑定。
- 401、403、409、超时、结果不明及快速切换；迟到响应不覆盖新选择，重复点击不增加提交，动画完成不生成业务动作。

- 键盘、减少动态效果、暂停、低性能降档、Worker/WASM 不可用、上下文丢失；关闭所有装饰后业务仍可完整办理。
- 真实图形几何、箭头、标签、溢出、控制台、外域请求、同源资源与浏览器存储；不用源码断言替代真实呈现。
