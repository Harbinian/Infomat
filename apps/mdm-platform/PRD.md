# 3000 RBAC 与 RACI 重构产品需求

## 1. 文档状态

- 产品：Infomat 3000
- 版本：`rbac-raci-v2-2026-07-30`
- 状态：已实现，待按迁移手册执行正式数据迁移
- 适用范围：人员身份、账号生命周期、MDM工作角色、权限、责任记录、访问审计和既有治理接口授权

## 2. 业务目标

3000改为内部治理平台，不再向全员开放。普通账号只能由MDM系统管理员手工创建、授权和启用。

本次重构解决四个问题：

1. 账号来源不受控，历史接口和脚本可以绕过管理员开户。
2. 旧角色同时混用系统权限、项目职责和业务责任，管理员可以绕过业务责任链。
3. 部门决定缺少可追溯记录，系统无法证明谁最终负责。
4. 身份数据存在`person`、`user_accounts`、`person_roles`与旧`users/user_roles`并行读取的问题。

## 3. 范围

本期包括：

- 固定七个MDM工作角色和十九项权限。
- 管理员手工开户、启用、恢复、停用、密码重置、部门变更、角色授予和撤销。
- 账号与授权操作审计。
- 部门决定记录和发布责任核验。
- 流程、数据、术语、冲突、字段和工作台接口的统一权限判断。
- 旧身份数据盘点、备份、迁移、回滚和补偿。
- 只读“角色与责任”页面。

本期不包括：

- 重做流程地图、数据地图和术语治理业务数据模型。
- 自定义角色、自定义权限包或页面编辑RACI。
- 根据姓名、岗位、职务或历史常量推测部门负责人。
- 修改`docs/norms/`、PMO页面或组织真源。
- 把正式流程工作角色`WR-*`、岗位或人员身份当作MDM工作角色。

## 4. 用户与职责

| 角色 | 主要工作 | 禁止事项 |
|---|---|---|
| MDM系统管理员 | 管理账号、MDM工作角色和访问审计；全局只读 | 修改、审核、确认或发布业务内容 |
| MDM工作组组长 | 分派事项、检查结构和责任证据、发布治理版本 | 代替部门确认业务事实 |
| 部门主对接人 | 起草、修改、提交和整改本部门材料 | 部门审核和全局发布 |
| 部门MDM审核员 | 审核本部门材料，记录部门负责人线下决定 | 代替部门负责人作决定 |
| 数据冲突处理人 | 处理本人被分派的冲突并提请升级 | 查看或处理未分派事项 |
| 数据质量审计人 | 全局读取数据治理信息，记录审计发现和整改要求 | 修改部门源数据或发布版本 |
| 项目决策组 | 决定已经升级的重大跨部门争议 | 日常编辑、部门审核、发布和账号管理 |

## 5. 核心业务规则

### 5.1 身份与账号

- 唯一运行时身份链路为`person -> user_accounts -> person_roles`。
- 未登录用户只能看到登录页。
- 不提供自助注册、批量开户或RBAC导入入口。
- 新账号初始状态为`pending_activation`，不能登录。
- 管理员启用账号时生成一次性临时密码；密码只在该次响应中显示。
- 首次登录只能修改密码或退出。
- 账号状态为`active`且人员状态有效时，系统才继续计算角色和权限。
- 账号、部门或角色变化时递增`auth_version`，旧会话从下一次请求起失效。

### 5.2 角色授权

- 角色清单、权限包和RACI由版本化固定模型维护，页面只读。
- 每项角色授权必须填写授权依据和生效日期；失效日期可为空，但授权仍必须保留有效期语义。
- `department_contact`和`department_mdm_reviewer`只能授权到人员所属部门。
- 人员变更部门时必须填写原因并同时提交新部门角色安排；旧部门角色自动撤销。
- 撤销角色必须填写原因。
- 撤销最后一个有效角色时，管理员必须同时停用账号。
- 不得停用最后一个有效管理员，也不得撤销其管理员角色。

### 5.3 最终授权

业务写操作必须同时满足：

1. 人员和账号有效。
2. 会话`authVersion`与当前账号一致。
3. 角色处于固定模型的有效状态。
4. 角色授权处于有效期内并有授权依据。
5. 用户拥有所需权限。
6. 数据在该用户的部门、被分派事项或已升级事项范围内。
7. 当前对象状态允许该动作。
8. 当前用户与任务、部门或争议存在要求的责任关系。
9. 需要部门决定或发布时，责任证据完整。

RBAC只决定用户最多可以做什么；RACI和对象状态决定当前事项是否轮到该用户处理。

### 5.4 部门决定与发布

- 部门最终负责人以`departments.final_responsible_person_id`为准，可以没有3000账号。
- 部门MDM审核员只能记录本人所属部门的决定。
- 记录内容包括治理领域、对象、版本、部门、系统确认的最终负责人、记录人、决定、依据、可选证据引用和决定时间。
- 决定值固定为`approved`、`returned`、`rejected`。
- 新记录只追加；替代旧决定时保留被替代记录。
- 跨部门事项按部门分别记录决定。
- 责任人缺失或必需部门决定不完整时返回`RESPONSIBILITY_CHAIN_INCOMPLETE`。
- 发布前必须同时满足：所需部门决定完整、阻断问题关闭、结构检查通过、版本检查通过。

## 6. 主要使用流程

### 6.1 创建并交付账号

1. 管理员取得已确认的人员、工号、部门、MDM工作角色、授权依据和生效日期。
2. 管理员创建待启用账号。
3. 系统在同一事务中创建或复用人员、创建账号、写入角色授权和审计事件。
4. 管理员核对账号和角色后执行启用。
5. 系统返回一次性临时密码。
6. 用户首次登录后修改密码。

### 6.2 记录部门决定

1. 部门负责人在线下作出决定。
2. 部门MDM审核员打开对应治理对象。
3. 系统核对审核员部门、对象部门和部门最终负责人。
4. 审核员记录决定、依据、时间和可选证据。
5. 系统追加责任记录，不覆盖历史。

### 6.3 发布治理版本

1. MDM工作组组长发起发布。
2. 系统核对发布权限、对象状态、各必需部门最新决定、阻断问题、结构检查和版本检查。
3. 任一条件不满足时，系统返回具体原因并禁止发布。
4. 全部条件满足后，系统记录版本和发布人。

## 7. 异常与错误

| 错误码 | 含义 |
|---|---|
| `LEGACY_IDENTITY_API_RETIRED` | 旧身份写接口已经停用 |
| `CORE_GOVERNANCE_MODEL_READ_ONLY` | 固定角色、权限或RACI不允许页面修改 |
| `ROLE_ASSIGNMENT_EVIDENCE_REQUIRED` | 缺少角色授权依据、生效日期或初始角色 |
| `ROLE_SCOPE_DEPARTMENT_MISMATCH` | 部门角色范围与人员所属部门不一致 |
| `DEPARTMENT_ROLE_REPLACEMENT_REQUIRED` | 部门变更未提交新部门角色安排 |
| `LAST_ACTIVE_ADMIN` | 操作会导致系统没有有效管理员 |
| `RESPONSIBILITY_CHAIN_INCOMPLETE` | 部门最终负责人或必需部门决定不完整 |
| `ACCOUNT_REQUIRES_ACTIVATION` | 待启用账号不能直接恢复 |
| `ACCOUNT_DISABLE_REASON_REQUIRED` | 停用账号未填写原因 |

## 8. 验收标准

- 七个固定角色只能获得固定权限，`*:*`和旧管理员业务权限不生效。
- 管理员可以完成身份管理，但业务写接口返回403。
- 部门角色不能跨部门使用。
- 冲突处理人不能查看或处理未分派事项。
- 项目决策组只能处理已升级事项。
- 待启用、停用、锁定账号不能登录。
- 部门变更、角色撤销或账号停用后，旧会话立即失效。
- 部门审核员只能记录本部门决定。
- 部门负责人缺失时，决定记录和发布被阻断。
- 发布必须通过责任、阻断问题、结构和版本四类检查。
- 旧身份数据迁移具备盘点、备份、幂等、回滚或补偿和迁移后核对。
- 主线测试、身份测试、流程治理测试、数据与术语测试、服务烟测和浏览器验收通过。
