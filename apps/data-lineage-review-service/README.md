# 字段血缘与主键评审

2026-11-12运行前端已包含Infomat工作空间样式。本次保留另一项已完成工作部署的最新前端镜像，没有用较早候选覆盖它；API容器及数据卷保留。9992在全部接口发布，`192.168.19.199`与`192.168.10.184`的矩阵页面均已取得HTTP及实际渲染证据。

会议评审提供两个页面。首页解释 CRUD 和 RACI，[收集工作台](http://127.0.0.1:9992/matrix)默认打开全部字段的选择弹窗，不预选字段或评审清单。选定字段后，通过「职责矩阵」「血缘与取值」页签编辑记录，旁边显示父级参考、已有证据和待确认事项。9997 的精确字段链接直接打开指定字段，不自动切换清单。

顶栏「从全部字段选择」打开系统、表名、字段三级联动弹窗。在所选系统内搜索表名，在所选表内搜索字段。搜索保留当前选择，切换上一级后清空下一级搜索；点击「打开字段」才切换编辑对象，取消或关闭弹窗保留当前填写。「同名字段候选」和「收集概览」从顶栏打开独立弹窗。桌面布局以 Edge 100%、1699×828 CSS 像素验证。

左侧「评审清单」默认收起，可通过顶栏展开或收起；收起时编辑区使用释放的空间。展开后可选「制造大纲升版（样例）」等已启用清单。选择或取消清单只改变任务范围、进度和清单导出，不切换当前字段；点击清单中的字段才进入该项。任务列表与编辑区分别滚动，选中清单内的字段另显示「下一项」。清单显示、隐藏和选择均不保存、清空或更改已有评审；字段标识、历史修订及原清单归属保持。

字段标题旁的「同名对照」将当前可选底册内字段原名完全相同的各张表一起列出，覆盖全部系统，可按系统或表名筛选，也可搜索后切换其他同名分组。每项左侧显示父级参考，右侧直接编辑 CRUD/RACI；已有证据和待确认事项在本项内展开。参考使用已收集的血缘样例和同名候选线索，缺少线索时明确提示待核对，不因字段同名认定血缘或沿用其他表的职责。原名不同而业务标签相同的字段不自动合组。勤哲 ES 表及含 ExcelServer 的字段仍按现有底册可见范围处理。

对照页每项独立保存并显示状态，也可用「保存本组修改」或 Ctrl+S 保存本组所有修改，包括被系统或表名筛选暂时隐藏的项。每项仍对应原字段标识和修订版本，整组保存会分别提交；部分失败时报告已保存数和待处理数，保留失败项填写。单字段与对照页共用本页草稿，切换分组和返回单字段保留修改，底部同时提示本组和其他字段的未保存数；跨窗口冲突逐项核对、合并后重新保存。整组保存期间暂时锁定编辑和分组切换。候选详情也提供「同名对照」入口。

「血缘记录」可在对照项内展开填写，完成确认仍按该字段已纳入收集的血缘分支核对缺口。仅作为候选显示的父级线索不会自动扩大收集批次或新增必填项。矩阵规则继续为每个 CRUD 动作 A 最多一个岗位、R/C/I 可多选、待定留空；确认完成逐字段勾选。

字段枚举覆盖当前底册、同名候选、父级参考及 9997 已引用的 219 个表/视图，按 2026-11-12 的只读 SQL Server 结构查询补齐到 6206 个可见字段：勤哲 161 个对象、2955 个字段；用友 U8 27 张表、2511 个字段；KFU8QZ 31 个对象、740 个字段。这是本轮引用对象的完整可见列目录，不表示三套数据库的全部对象已纳入。勤哲 7 个 ES 系统对象不纳入；已核查对象内 987 个名称含 `ExcelServer` 的列不进入下拉和搜索，匹配不区分大小写。各字段独立可选，组合键成员可分别评审。自增、计算列和疑似系统生成字段排在后面；实际赋值方式由现场核对。表编号、序列号可直接选择。

各系统在选择器、编辑标题、同名对照和候选详情中使用中文名称，技术名保留为搜索关键字、接口身份和导出定位。用友使用本表字段字典、单据主明细定义与字段分区联合定位，KFU 使用本表字段字典和数据库注释；KFU 三个视图的 285 个字段通过 SQL Server 结果集来源元数据核实其用友来源，作为只读父级参考显示，不自动新增必填项或收集批次。订单归属扩展采用既有技术字段说明。用户确认的存货编码公司含义优先保留为「存货编码（PDM产品图号或物料编码）」。仅同名、仅同模块或无法唯一定位到本表的解释只作为待核实线索，不计为已核实名称。缺少定义时显示「业务含义待核实」及列序号，主键、数据版本标记可按数据库属性说明。

字段标题及对照项的「名称依据」显示名称来源、字典上下文和待核实状态；技术定位另行展开。「收集概览」中的「结构覆盖与名称缺口」显示本轮补列数及 1424 项含义缺口，可下载逐字段待核实 CSV。结构已核查、名称已有依据与业务含义获确认是不同状态；原有 CRUD/RACI 和制造大纲批次仍由现场评审确认。

中文显示映射与字段结构清单分开加载，调整中文名称不会改变字段标识、已有清单摘要、评审矩阵或修订版本。同名对照仍按技术字段原名精确归组，中文别名不同的项分别显示其名称；中文名称相同不自动合组。

9997 的字段详情可以通过 `/matrix?field=<字段标识>` 打开矩阵。页面只按当前评审清单中的精确字段标识选择系统、表名和字段。链接未命中时提示手工选择。评审结果仍通过本服务保存。

## Docker 运行

在此目录运行以下命令。Docker 将宿主机所有地址的 9992 端口转发到前端容器。入口为 [本机评审页面](http://127.0.0.1:9992/)，局域网设备以宿主机的 IP 地址访问同一端口。

```powershell
docker compose up -d --build --wait
docker compose ps
Invoke-RestMethod 'http://127.0.0.1:9992/api/health'
```

前端容器 `review` 从 `web.mjs` 提供 `public/` 下的页面，将浏览器的同源 `/api/` 请求转发给后端。后端容器 `api` 从 `server.mjs` 提供字段、进度和保存接口，在 Docker 内部网络监听。后端独占评审数据卷和目录挂载。前端与后端分别使用 `Dockerfile.web` 和 `Dockerfile` 构建。

前端改动可运行 `docker compose build review`，再执行 `docker compose up -d --no-deps --wait review`。后端改动对应 `docker compose build api` 和 `docker compose up -d --no-deps --wait api`。两侧同时变更时运行上述整套启动命令。浏览器使用的接口仍位于 9992。

后端从仓库根目录下的 `artifacts/data-lineage-review-service/` 只读挂载评审证据清单 `review-catalog.json`、字段结构清单 `field-catalog-20261110.json` 和岗位枚举 `position-catalog.json`。健康接口返回结构清单摘要、可选字段数及岗位组合数。原工作簿供线下核对证据。结构清单由 `prepare-field-catalog.mjs` 从本地只读查询成果生成。脚本校验源文件摘要、数据库名、原评审字段和表的覆盖，再生成可挂载的字段清单。

`field-addendum-20261110.json` 补充了同名候选中 8 个经 2026-11-10 只读结构查询核实的目标字段。仅补目标列所在位置及数据库属性，相关表的其余列按现有底册范围提供。运行 `node prepare-candidate-fields.mjs <评审证据清单> <原字段清单> <候选清单 JSON> <查询结果目录> <输出 JSON>` 生成补充清单，脚本核对候选身份、查询及结果摘要。后端以独立摘要加载，旧字段沿用原记录归属。

`field-extension-u8-20261112.json` 追加销售订单明细的其余 136 列；已收录的销售订单号仍沿用原补充清单摘要。原底册和原补充清单不改写。API 通过 `REVIEW_FIELD_EXTENSION_PATH` 读取该扩展，以独立摘要登记和保存新字段的评审。多个快照中的重复字段会阻止启动，避免覆盖旧记录归属。

当前使用 `full-audit-20261112/catalog-v3/` 内三个只读快照：`field-audit-extension.json` 追加 1524 个字段，`field-presentation.json` 提供全部 6206 个字段的中文显示与逐字段依据，`catalog-audit.json` 记录 219 个对象的结构覆盖、排除项及源查询身份。分别通过 `REVIEW_FIELD_AUDIT_EXTENSION_PATH`、`REVIEW_FIELD_PRESENTATION_PATH`、`REVIEW_CATALOG_AUDIT_PATH` 加载。原三个结构快照、字段标识及修订归属均保留；旧版用友显示映射作为历史快照保留。

`/api/catalog-audit` 提供覆盖与名称缺口，`/api/catalog-audit/pending-names.csv` 下载含义待核实清单，`/api/fields/<字段标识>/name-reference` 提供逐字段名称依据。健康接口增加 `fieldAuditExtensionDigest`、`catalogAuditDigest`、`auditedObjects` 和分系统 `namingCounts`；导出包含新增结构快照、显示映射和核查快照。覆盖数、身份、已收字段属性或中文映射不一致时阻止启动。

本轮生成入口为 `node prepare-comprehensive-review.mjs <评审清单> <原字段清单> <原补充清单> <销售明细扩展清单> <已审计查询成果目录> <订单归属扩展字段说明> <新输出目录>`。生成器验证查询及结果摘要、完整列数、旧字段属性和引用覆盖，只读取本地成果并创建新文件，不连接业务库、不覆盖输入。底册扩大不自动启用新批次；中文名称调整不修改已有矩阵或完成状态。

旧入口 `prepare-u8-review-data.mjs` 用于追溯销售订单明细扩展和上一版中文映射，不用于覆盖本轮完整核查结果。更换映射前核对字典来源、用户确认口径及逐字段缺口。

同名血缘候选使用同目录的 `same-name-lineage-candidates-20261110.json` 只读挂载。执行 `node prepare-candidate-catalog.mjs <候选清单 Markdown> <输出 JSON>` 可生成该文件。脚本按表格逐条拆出同名关系，保留原稿摘要和证据状态。后端按当前底册和首批范围计算目标分类，通过 `/api/lineage-candidates` 只读提供。

后续批次由 `artifacts/data-lineage-review-service/collection-batches.json` 登记。文件格式为 `field-review-batches-v1`，`batches` 数组每项包含 `id`、`name`、`sourceSha256`、`targetIds`。维护者确认新范围后，把导出配置中的新条目追加到现有数组，保留已有批次，再执行 `docker compose up -d --no-deps --force-recreate --wait api`。API 健康后，现场刷新页面即可切换批次。启动会拒绝候选版本不符、底册中缺失或已纳入其他批次的目标。批次配置只读挂载，核验草案和导出配置均在发布前完成。

岗位枚举取 2026-10-20 的 3000 组织与岗位快照及用户确认的更正和补充。选项保留部门、办公室和班组的已知归属及岗位原名，未确认的层级留空。该清单只包含岗位组合，采用本地快照刷新方式。

## 保存与恢复

- 点矩阵单元格，在岗位列表内按部门或名称筛选。每项动作的 A 最多选择一个岗位，R、C、I 可以多选。待定或不适用可留空。应用选择后点「保存记录」，或在编辑区按 Ctrl+S。可访问评审端口的设备可以读取和保存评审记录，应用不校验员工身份。
- 展开「评审清单」并选择「制造大纲升版（样例）」后，可按表名、字段名、业务标签或收集状态筛选这份清单。保存清单内字段后可继续「下一项」。18 条血缘样例按不同目标字段去重，共 31 项，保留原批次标识和已有记录。上游字段作为参考，当同一字段也是样例中的目标时，在该目标下计一次。「收集概览」显示所选清单缺口和全部底册的分系统统计；未选择清单时明确提示。`/api/progress` 的原批次与全量统计合同保持。
- 打开「同名字段候选」，左侧按目标或父级搜索，右侧查看已有依据和待确认事项。编辑区的「查看同名参考」可定位到当前目标。未纳入批次的目标可拟选到下一批草案，待补底册的目标在草案中单独标识。拟选保存在本页会话中，可导出 JSON 备查。正式应收按已启用批次统计。
- 「导入草案」和「核验草案」通过 `/api/lineage-candidates/validate` 按当前候选、底册和批次核对，分别列出可收集、待补底册、已在批次。确认后可把导入结果中可拟选的字段并入本页草案。当本次核验的目标全部可收集时，可填写批次名称并导出供维护者启用的配置。
- 评审清单选择器列出已启用的批次，未选择时不显示任务列表。各清单独立统计已确认、已收待确认、未收和待完成；打开字段不自动切换清单。后续批次的同名线索按原依据和待确认事项显示，按目标字段收集矩阵和分支处理记录。
- 「已收待确认」可细分为「待补血缘」和「记录齐、待确认」。缺口按各目标最新一次保存计算，草稿另在本页标识。点击左下角「导出本批清单」，可下载当前批次 CSV。每个目标占一行，包含父级参考、证据、缺口、已保存的血缘记录、CRUD/RACI 和修订版本。接口为 `/api/collection-batches/<批次编号>/report.csv`。
- 「血缘与取值」按分支记录写入或取值时点，以及上游变更后的处理；右侧父级参考同步显示原有线索，已有证据与待确认事项分开呈现。血缘未填齐时，底部显示缺口并可跳转到首个空项；完成确认前须填写每条血缘的写入或取值时点及上游变更后的处理。确无适用内容的，可在对应记录中写明理由。待定项可留空并先保存。
- 统计使用字段最新一次保存。核对岗位矩阵和血缘记录后，勾选「确认本字段收集完成」并保存，才计入本批已确认。已保存但尚未确认或血缘记录不齐的目标计入已收待确认。改变岗位或血缘记录，或合并其他窗口的修改后，需要重新确认。全部字段底册仍按各字段矩阵的确认状态统计。
- 旧修订中的多个 A 原样保留。该矩阵再次保存前，须为对应动作选定一个 A 或明确留空。
- 保存时记录所选岗位及其名称快照。旧版自由文本标记为历史填写，可以保留，或由评审人明确更换或清空。
- 编辑区分别显示已保存状态和未保存修改。通过任务清单或底册切换字段时，本页草稿按字段保留，任务列表标记未保存项。「下一项」在当前有未保存修改时暂不可用，保存后可继续。页签切换保留填写；离页时存在草稿会提示确认。多窗口同时修改时，核对冲突提示后可将本次修改合并到最新矩阵；读取最新记录失败时可重试核对，核对后仍无新版本时按提示刷新页面重新核对。在未显式修改完成确认的情况下，把内容改回与已保存一致时会恢复为未修改状态，不产生额外修订。显式取消完成确认后仍会作为待保存修改保留。
- 字段清单读取失败时，编辑区显示「重新读取字段清单」入口；统计读取失败时可在「收集概览」中重试。
- Docker 命名卷 `infomat-data-lineage-review-data` 保存本地 SQLite 文件、清单快照和历次记录。各字段沿用所属清单摘要，补充字段使用补充清单摘要。替换清单前先导出当前结果。历史快照及其修订按摘要保存在数据卷中。
- `/api/export` 可下载当前清单、原逐条评审记录 `history` 和各当前清单对应的字段矩阵修订 `matrixHistory`。新填的血缘记录随矩阵修订一并导出。正常停用使用 `docker compose stop review api`，保留命名卷。

本服务承载独立评审记录，评审结果保存在该服务的数据卷中。记录在会上作进一步确认和使用。
