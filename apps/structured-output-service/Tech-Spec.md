# 3001 单流程编制技术规格

## 1. 文件结构和兼容策略

新增 `docs/contracts/process-governance-v1.schema.json`。当前格式以单个 `process` 为根对象，不使用 `processes[]`，从结构上保证一份JSON只对应一个流程。

`document-structured-output-v2` 保持只读兼容：

1. 制度文件解析器继续产生v2内存结果，避免重写成熟解析逻辑。
2. 前端按 `process_ref` 拆分多流程结果，只把当前候选送入编辑工作台。
3. 导出时把当前单流程编辑结果转换为 `process-governance-v1`。
4. 当前单流程格式可重新导入，并适配回编辑工作台。
5. 3000重构前不支持当前单流程格式。

## 2. 无状态实现

- Multer继续使用 `memoryStorage()`。
- 服务端不提供会话接口，也不新增会话表、缓存、文件目录或草稿接口。
- 页面状态只保存在JavaScript运行内存中。
- 不调用任何浏览器持久化API。
- `/api/data` 和 `/api/export` 继续返回404。
- 结构化JSON导入在浏览器内存中处理。服务端保留的历史解析接口仍使用内存上传，请求完成后不保留用户内容。

## 3. 页面状态

页面维护：

- 当前单流程编辑结果。
- 本次导入拆出的候选流程列表。
- 当前候选索引。
- 当前未保存标记。
- 当前打开的“文字编制／流程图预览”标签。
- 当前打开的文字分区和流程步骤子分区；流程步骤只包含业务行为、流程关系、输出物与数据、跨部门承接。
- 当前选中的业务行为、表单或记录、主表或明细表结构。
- 从`/api/enums`读取的花名册岗位目录及当前加载状态。
- 本次页面运行内已经打开过预览的流程标识。

候选列表只存在当前页面运行态。切换候选时保留本次运行内的编辑结果，刷新后全部清空。

文字编制使用“基本信息、目的与范围、术语定义、流程步骤、表单与记录、导出检查”六个互斥分区。表单名称和业务行为名称在输入时只更新对应侧栏标签，不因控件失焦重绘整个工作区，避免连续输入时把下一个字段替换为失效节点。

## 4. 只读流程图预览

- 前端锁定使用`cytoscape@3.34.0`。服务端通过`GET /vendor/cytoscape.min.js`提供本地浏览器脚本，不使用CDN，也不暴露整个`node_modules`目录。
- `public/process-diagram.js`把当前`process-governance-v1`内存对象转换为图形元素。转换函数不得修改输入对象。
- `behaviors[]`生成本流程节点；只有关系类型、起点和终点均明确且引用有效的`flow_relations[]`才生成本流程箭头。
- `cross_department_handoffs[]`和导入文件中已有的`internal_process_calls[]`生成边界外占位节点。存在有效恢复位置时，预览额外绘制返回箭头。
- 缺少绘制条件的关系、承接或调用进入预览问题清单，不写回原对象，也不自动补关系。
- 自动布局按主流程从左到右排列。回路和返回箭头不参与主线分层，布局完成后再恢复显示，避免回路改变主流程阅读顺序。
- Cytoscape节点设置为不可抓取。图形只允许平移、缩放、适应画布和重置视图。业务行为、关系和跨部门承接可以定位到对应文字卡片；内部流程调用只显示MDM平台维护提示，不跳转到文字编辑区。
- 标签选择、图形实例和节点坐标只保存在页面内存中；Schema、导入导出JSON和`/api/validate`不增加图形字段。
- Cytoscape或图形模块加载失败时，前端只关闭预览画布并显示错误说明，不清空文字数据，不阻止现有导出流程。

## 5. 旧版拆分

拆分时：

- 只保留当前 `process_ref` 对应的步骤、行为详情、分支和工作角色关系。
- 表单通过 `step_ref` 归入对应流程。`form_tables.table_kind=main`映射为`area_type="基本信息"`，`detail`映射为`area_type="明细清单"`；`form_table_fields`只进入其`table_ref`指向的结构，不合并不同明细表。
- 跨部门关系按源步骤归入当前流程。
- 术语和文档级参考材料复制到每个候选并在内存中隐式保留，不形成制度关联，也不显示为当前页面编辑入口。
- 当前或历史文件中已有的`internal_process_calls[]`在候选规范化、切换和导出过程中保持不变，不生成3001编辑入口。
- 无法归属的旧字段不静默删除；转换器将其保留为参考材料或待治理数据候选。

## 6. 当前单流程格式映射

| 编辑工作台 | `process-governance-v1` |
|---|---|
| 当前流程 | `process` |
| 隐式保留的历史编制参考材料 | `reference_materials[]` |
| 步骤及行为详情 | `behaviors[]` |
| 执行部门和花名册岗位兼容值 | `behaviors[].current_actor_role` |
| 顺序、判断、循环、并行 | `flow_relations[]` |
| 隐式保留的已有正式工作角色 | `behaviors[].work_role` |
| 输出及消费关系 | `data_objects[]` |
| 跨部门发送、输入数据、返回数据和恢复位置 | `cross_department_handoffs[]` |
| 隐式保留并仅供流程图预览的同部门调用 | `internal_process_calls[]` |
| 表单或记录、主表／明细表、填写项 | `forms[].areas[].items[]` |

## 7. 跨部门承接和部门内调用预览

- 业务行为卡片通过`send_behavior_ref`查找已关联的`cross_department_handoffs[]`，并直接绑定承接部门和处理事项字段。业务行为区和跨部门承接区编辑的是同一个内存对象。
- 用户从业务行为卡片新增承接时，前端生成`handoff_ref`，把当前业务行为写入`send_behavior_ref`，并按现有规则预填发出部门。其余字段保持空值，不推测承接部门、目标流程或目标行为。
- “完善承接信息”把页面切换到跨部门承接子分区，并按`handoff_ref`定位和高亮同一条记录。
- 一项业务行为可以被多条`cross_department_handoffs[]`引用。删除该行为时，前端先显示关联数量；用户确认后再级联删除这些承接记录。
- 页面不渲染`internal_process_calls[]`编辑器，也不提供新增和删除动作。规范化导入和导出继续保留该数组；新建模板保持空数组。
- 预览中的内部流程调用被点击时，前端保留流程图并显示“部门内调用请在MDM平台正式功能中维护”，不得切换到不可编辑区域。

## 8. 岗位和表单实现

- `/api/enums`读取仓库`docs/organization/花名册.md`，返回`rosterRolesByDepartment`。该接口不调用3000、数据库、认证或会话。
- 执行部门选项由组织部门常量和`rosterRolesByDepartment`的部门键去重生成，排除作为特殊兼容值的`全公司`后，向用户列出全部实际部门；`全公司通用`仍作为单独选项。
- 前端比较所选执行部门和`process.owning_department`：相同则显示“本部门执行”，不同则显示“跨部门执行”。该判断只用于页面说明，不新增JSON字段或浏览器持久化状态。
- 执行岗位选项始终从`rosterRolesByDepartment[selectedDepartment]`读取。前端不得根据岗位名称猜测部门，也不得因为岗位名称包含“车间”等字样而改写花名册归属。
- 执行岗位选择器不设默认值。具体岗位保存为部门名与岗位名拼接的`current_actor_role`字符串；“全公司通用”保存为`全公司`。
- 规范化导入不清空未收录岗位。花名册加载失败时，岗位选择器不可修改现有值，但不影响其他编制和导出。
- 新增业务行为的`work_role`为`null`。合法历史`work_role`经行为引用规范化后隐式保留，页面不提供新增、修改或删除入口。
- 新建表单同时创建一个空`area_type="基本信息"`主表框架，不创建名称、编号、标题或填写项。
- 明细表按`area_type="明细清单"`逐张创建和删除。删除明细表时，其`items[]`随结构删除；主表不提供直接删除入口。
- 导入缺少主表、多个主表或`area_type=""`的结构时，不做自动归类。页面只显示编制提示，Schema和技术引用有效时仍允许导出。

## 9. 校验分层

3001导出前执行：

- 新建流程通过`/api/template?version=process-governance-v1`读取服务端空白模板，避免前后端分别维护结构。
- 新建和导出前调用`/api/schema`确认服务端默认结构版本为`process-governance-v1`；版本不一致时停止后续请求并保留当前页面内容。接口返回HTML或其他非JSON内容时，前端转换为可操作的服务异常提示，不直接暴露JSON解析错误。
- JSON Schema校验。
- 技术标识格式校验。
- 单文件内行为、数据对象、表单引用检查。
- 一份文件一个流程检查。

以下内容仅提示，不阻止草稿导出：

- PMO审核必填内容缺失。
- 流程入口、出口和可达性。
- 判断分支覆盖。
- 回路退出条件。
- 并行分支及汇合完整性。
- 跨流程和跨部门目标是否存在。
- 执行岗位是否为空或仍为当前花名册未收录的历史值。
- 表单是否缺少主表、包含多个主表或存在未分类结构。

3000后续重构负责跨对象和最终可执行性校验，不承担业务事实审核。

JSON Schema结构错误和单文件技术引用错误分别提示。结构错误提示维护人员检查导出格式；只有技术标识重复或本文件引用断开时，页面才提示“技术引用已断开或重复”。

## 10. 页面参考材料暂停和DeepSeek移除

- 删除页面“导入参考材料”、拖放区、参考材料编辑区和缺失提示，只保留JSON结构化文件导入。
- `/api/template`生成`reference_materials: []`。`normalizeV1()`保留导入JSON中已有的合法参考材料，再导出时不清空。
- 后端确定性解析和`/api/upload`仅保留用于历史迁移和回归测试，不再作为业务用户页面入口。
- 删除页面模型说明、建议状态和建议请求。
- 删除 `/api/suggestions`。
- 删除DeepSeek及CC Switch配置读取、健康状态和网络调用。
- 页面顶部不展示DeepSeek停用说明，也不展示3001无状态、3000通信或线下审核边界的通用声明；这些边界只保留在产品和运行文档中。
- 历史上传解析只使用确定性解析器。
- 健康检查只返回服务状态、端口、运行时间、Git提交、结构版本和结构摘要。

## 11. 安全和隐私

- 原文件不嵌入JSON。
- 历史参考材料只保留结构化JSON中已有的文件名、编号或版本、SHA-256摘要和可读文本；页面不新增这些内容。
- 服务端不记录文件名、原文、编制人或业务内容。
- 导出由浏览器完成。
- 服务默认监听`0.0.0.0:3001`，公司局域网用户通过服务器局域网地址直接访问；`STRUCTURED_OUTPUT_HOST`只用于维护人员显式收窄监听范围。
- 3001运行时不依赖DeepSeek、`apps/structure-assistant`或认证网关。独立试点脚本不得停止、重绑或启动3001。
- 部署主机通过公司局域网边界和防火墙限制访问来源，不将3001映射到公网。
- 空白模板接口提供Git提交、结构版本和结构摘要，不提供用户内容。

## 12. 后续3000重构边界

本轮不修改3000。后续至少需要：

- 导入 `process-governance-v1`。
- 单流程幂等导入和重复流程拒绝。
- 流程状态机、部门确认、跨部门承接、冲突升级和最终批准。
- 每行为唯一工作角色正式分配。
- 人员级职责分离和审计。
- 移除 `admin` 的 `*:*` 通配权限。
- 流程与制度关联待办及制度一致性核对。
- 流程拓扑、会签、并行和跨流程完整性校验。
