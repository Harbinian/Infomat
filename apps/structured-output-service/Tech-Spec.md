## 当前v7技术补充（2026-08-27）

### 导入与严格校验边界

`scripts/process-governance/v7-validator.js`为历史控制节点关系返回稳定规则码：

- `DATA_RELATION_ACTION_BEHAVIOR_REQUIRED`
- `FORM_RELATION_ACTION_BEHAVIOR_REQUIRED`

`public/import-compatibility.js`只判断迁移候选能否进入页面整改。候选校验通过，或全部错误都属于上述两个规则码时，该候选可以进入待安装批次；任一候选出现其他错误时，整个批次不得安装。`public/index.html`只有在所有候选完成分类后才替换当前候选列表。

页面导入已标明v7但仍保留历史控制节点关系的文件时，也使用同一受限分类。页面保留原`behavior_ref`，把候选标记为未下载，并通过原有技术检查显示阻断。关系选择器只把原控制节点作为“历史关系待处理”的当前值显示，新值仍只能选择`node_type=action`。

`POST /api/validate`、图命令、网页表格应用和下载均不调用`import-compatibility.js`。下载继续执行完整v7校验；上述任一规则码仍会使`valid=false`并阻止生成文件、更新下载基线或清除未下载状态。

### 接口错误响应

所有非2xx的`/api/*`响应至少包含：

```json
{
  "error": "用户能够照着处理的说明",
  "code": "STABLE_CODE"
}
```

缺少文件、空文件、空粘贴内容和缺少校验对象分别返回`FILE_REQUIRED`、`FILE_CONTENT_EMPTY`、`PASTED_CONTENT_EMPTY`和`VALIDATION_DATA_REQUIRED`；`data`缺少`schema_version`时返回`SCHEMA_VERSION_REQUIRED`。未知版本在`/api/validate`、`/api/schema`、`/api/template`和`/api/health`统一返回`UNSUPPORTED_SCHEMA_VERSION`。非法JSON返回`INVALID_JSON`，不支持的上传类型返回`UNSUPPORTED_FILE_TYPE`。`/api/session`、`/api/data`和`/api/export`返回`STATELESS_ENDPOINT_DISABLED`，未知API返回`API_NOT_FOUND`。响应不得包含请求正文、绝对路径、堆栈、模块名或底层异常。

JSON单段文字上限按UTF-8实际字节计算。10MB正文、64层嵌套、100000个对象或字段节点和无效Unicode限制保持既有值。

`inspectDocxArchive`同时读取ZIP中央目录和本地文件头，检查条目数2000、单条解压量20MB、总解压量50MB、压缩比100:1和路径层级20的闭区间边界，并拒绝路径越界、ZIP64、无效UTF-8文件名、中央目录与本地文件头名称或大小不一致，以及压缩数据越过中央目录。`createDocxParserPool`把工作线程创建、表格提取、并发上限和超时作为可注入边界；生产固定使用工作线程、并发2和超时5秒。并发已满时返回429，超时后终止工作线程、归还名额并返回422。

### 自动测试夹具

`scripts/process-version-fixtures.js`分别构造v1至v6合法输入。每份夹具先通过对应版本JSON Schema和本地引用校验，再验证迁移到v7、重复迁移、源对象不变以及v7下载后重新导入。公共v3培训样例固定验证迁移后6条数据关系和1条表单关系进入整改，但严格校验仍失败；另一个脱敏技术夹具验证人工改到业务行为后可以严格校验并重新导入。

### 编辑会话、状态聚合和切换保护

前端使用候选级`EditSessionManager`管理节点属性（普通业务行为和控制节点）、流程关系属性、数据对象信息、数据操作和关系向导。会话至少绑定候选标识、编辑器种类、对象稳定标识、允许字段基线、字段补丁、修改状态、可应用状态和焦点恢复信息。网页表格工作副本和更新字段弹窗保留各自的状态对象，通过适配器接入统一的`getPendingEdit()`和`requestTransition()`。同一时间只允许一个对用户可见的未应用编辑上下文。图形选择只表示当前选择，不再保存完整旧对象或同时承担关系向导状态。

状态聚合分别计算当前候选是否存在未应用修改，以及当前JSON是否偏离最近一次导入或下载基线。步骤、视图、对象、候选、图选择、撤销、重做、问题定位、新建、导入、清空和下载均调用统一切换保护。保护框提供应用、放弃和继续编辑三项结果；应用失败时不执行目标操作，不清除输入。

属性应用以字段补丁为单位。前端在应用时重新从当前最新JSON取得对象，比较用户实际修改字段的基线值和当前值；没有同字段冲突时只合并允许字段，其他字段保持当前值。同字段已经变化或对象已经不存在时，前端阻止应用并保留编辑会话。网页表格继续通过来源指纹和`SOURCE_CHANGED`执行整文档防覆盖检查。

网页表格异步应用在校验前捕获候选标识、当前JSON指纹、表格会话对象、会话修订号和来源键；批量字段应用捕获候选标识、批量会话令牌、会话指纹、批量补丁指纹和当前JSON指纹。异步校验期间，页面锁定重复应用、放弃、候选／步骤／视图切换和统一三分支处理。校验返回后，页面再次比较上述状态；任一项变化时，旧结果只返回冲突，不提交、不清理最新工作副本或批量选择，也不增加撤销记录。

前端调用`POST /api/validate`的等待上限为20秒。超时后`AbortController`中止本次等待，页面在`finally`中解除操作锁；当前JSON、撤销栈、表格工作副本或批量字段选择保持不变。用户修正或直接重试时重新生成候选并执行完整校验；超时请求的迟到结果不得写入。

表单引用对象字段时，只同步对象归属、对象字段类型，并只为空白的表单显示名称带入对象字段名称。引用顺序不能证明权威录入点或沿用关系，因此页面不得据此改写`value_usage_mode`或`value_origin_mode`；没有人工确认时，两项继续保持待确认。

`public/form-field-reuse.js`提供浏览器与Node共用的纯逻辑：按稳定`field_ref`建立对象字段索引、生成只包含确定性派生字段的补丁，并在文档克隆上规划整批引用。批量输入绑定候选标识、打开草稿时的文档指纹、`formRef`、去重后的`fieldRefs[]`、逐字段布尔型`required`和目标区域。规划器重新解析稳定引用，只创建一个新区域并为每个字段生成独立`item_ref`；完整候选通过引用和v7结构检查、来源指纹再次一致后，前端才通过整文档命令一次提交。失败时返回可定位错误，不返回部分写入后的文档。

新增数据行为关系、表单行为关系和字段取值来源使用未应用编辑会话，`behavior_ref`、`source_type`、`source_data_ref`和`source_role`初始为空。表格适配器新增表单使用`form_design_state=unspecified`，新增区域的`area_type`为空，新增表单字段的`required`为`null`。这些空值只允许存在页面草稿或表格工作副本中；适配器应用前必须阻断未确认值，正式v7 JSON中的`required`仍为布尔值。对象字段选择器跨全部数据对象工作；选择有效`data_field_ref`后，`business_data_ref`和`item_type`在直接输入、粘贴和复制链路中均按派生只读处理。

字段来源适配器按`source_type`执行条件必填和互斥清理。`process_data`要求`source_data_ref`和`source_role`，并清空`source_system_name`、`source_data_name`；`external_system`要求`source_system_name`、`source_data_name`和`source_role`，并把`source_data_ref`置为`null`。任一必填项缺失时，适配器返回可定位错误，不生成可提交候选。

`public/authoring-selection-context.js`按候选保存业务式／表格式编辑方式、数据／表单工作区、当前表格、`dataRef`、`dataFieldRef`、`formRef`、`areaRef`、`formItemRef`，以及九张表各自的筛选、排序、稳定选中行、焦点列和滚动位置。上下文只存在页面内存。切换候选前先读取当前可见表格的实际滚动位置；恢复时按最新文档重新解析稳定引用。删除父对象、应用或放弃工作副本后，前端清除失效子级和失效行，但保留仍有效的表视图状态。新建、清空和重新导入执行全量上下文重置。

表格式编辑继续使用同一个九表工作副本，但`renderWebGridEditor()`只渲染当前页签对应的一张`web-grid-panel`。数据工作区含四张表，表单工作区含五张表；页签汇总当前范围行数、未应用状态、错误数和父级状态。每张表只显示一个对象明确的新增按钮。切表前检查中文输入法组合状态，切表后恢复滚动、稳定选中行和真实DOM焦点。完整v7校验错误通过JSON路径重新解析到稳定实体、表格、行和列；无法映射到九张表时，错误按钮切换到业务式正式入口，不能生成无动作按钮。

`public/governance-review-queue.js`管理候选级页面内存问题快照、过期状态、跳过顺序和重新计算差异。问题身份固定为规则编码、稳定引用和无数组序号路径；一条检查结果包含多个`focusPaths`时，先拆成多个单目标问题，再分别解析稳定引用。步骤1至5只复用现有技术结构检查和业务提示，不增加第二套校验规则。文档修改只把旧快照标记为过期，不在每次输入时重算；重新检查后，已消失、仍保留和新增问题由稳定身份对比。表格工作副本错误不并入基于已应用JSON的全局队列。

页面对全部可见模态框和治理抽屉按计算后的`z-index`及DOM顺序确定顶层`role="dialog"`。全局键盘处理在执行其他快捷键前拦截`Tab`：正向和反向焦点只在顶层对话框可见且未禁用的控件之间循环；顶层没有可聚焦控件时，页面阻止默认行为并聚焦对话框容器。关闭、取消、放弃或继续编辑后，页面使用候选及实体稳定引用重新查询发起控件，再恢复焦点和滚动位置，不保留指向已重绘DOM的旧元素引用。

下载、新建、导入、清空和离页先处理未应用修改，再处理未下载修改。成功安装新数据后，前端原子清理编辑会话、图选择、关系向导、更新字段弹窗和网页表格工作副本；失败或取消导入时，不改变当前JSON和页面状态。下载成功后，前端只以实际序列化并进入下载文件的JSON更新基线。

生命周期渲染使用只读临时默认值，不向缺少`lifecycle`的业务对象赋值。视图切换、对象选择和渲染不得改变JSON指纹、未下载状态或撤销记录。显式重新分析在副本中完成；结果有变化时作为一次文档事务提交，结果无变化或分析失败时不提交。

步骤5删除以及列表中的业务行为、流程关系和术语删除统一通过文档事务入口执行。事务先检查引用；存在引用时返回可定位阻断。生命周期路径引用的流程关系和生命周期事件引用的触发行为也必须阻断删除。没有阻断引用时，用户确认后一次提交修改，并在当前候选中形成一次撤销记录。事务不执行静默级联删除。

本项只新增前端页面内控制，不改变`process-governance-v7`结构规则、服务端API、导入导出格式或持久化边界。完整规格和测试记录见`../../docs/plans/2026-08-26-3001-pending-edit-safety-remediation/`。

### 四项任务候选显示层与职责边界

`structuredOutputUiConfig()`只接受`STRUCTURED_OUTPUT_COMPACT_TASK_UI_ENABLED=1`作为候选四项任务界面的启用条件；其他值均关闭。`GET /api/ui-config`返回无业务内容的只读界面配置，并设置`Cache-Control: no-store`。该接口不建立账号、权限、服务端草稿或3000通信。

`COMPACT_TASK_WORKFLOW`只映射显示层：`start + boundary`、`skeleton + action`、`data`、`cross-department + handoff`分别显示为“文件与边界”“流程、执行人、动作与异常”“数据与表单”“检查与保存”。内部`GovernanceWorkflow.STEPS`、问题身份、阶段下载、v7结构和候选内存状态保持七步，不执行数据迁移。候选界面收到内部`action`定位时，把用户带到流程图和当前节点或关系的右侧浮层。新建关系确认页始终渲染`condition`编辑框；`relationConditionEditorCopy()`根据`relation_type`和端点节点类型显示判断条件、退回条件、并行启动条件或并行汇合要求。已有关系通过流程线或清单打开同一关系编辑会话，不显示转到“动作与异常”的入口。导航按钮不显示内部步号和责任长文；问题队列在候选模式下显示任务名称。帮助页根据配置选择七步说明或四项任务说明。

业务部门只提供单流程事实：边界、实际办理、执行主体、异常、表单字段、数据操作、当前编号和来源、跨部门交接及来源证据。主数据认定、跨流程对象匹配、关键字段、正式生命周期规则和跨流程冲突不在3001形成正式结论；3000发布不可变`process_version_id`后，由MDM工作组通过默认关闭的数据治理工作包处理。候选显示层不具备身份能力，不能替代3000服务端职责和权限校验。

### 当前v7验证与证据边界

本轮先在独立候选端口执行`npm.cmd test`、`npm.cmd audit --json`和`git diff --check`，再检查根页、静态资源和`/api/health`。健康结果必须同时证明`status=ok`、`schema_version=process-governance-v7`和`release_status=released`。真实浏览器覆盖批量原子提交、异步旧结果零写入、20秒超时恢复、统一三分支、顶层模态焦点、三档视口、存储边界、3000网络边界和控制台。源码字符串或装配断言只能作为静态证据，不能替代运行时行为检查。

自动化对`compositionstart`、`compositionend`、`isComposing`、`keyCode 229`和紧随回车的检查属于事件级证据。Windows中文输入法候选窗必须由人工实际打开、选词并继续录入；未执行时，验证记录明确标为待人工验收。正式3001的启动、重启和替换属于另行授权的发布动作，候选验证不代表发布完成。

## 1. 总体设计

3001继续使用Node.js服务端和单页前端。服务端只提供静态资源、受控枚举、模板、结构规则、版本历史、健康检查、确定性历史解析和纯校验。业务草稿、图状态、撤销记录、下载基线和最近下载摘要只存在浏览器当前页面内存中。

```text
用户操作
  ↓
页面内存中的单一v7草稿
  ├─ 七步内部状态与默认导航
  ├─ 默认关闭的四项任务候选显示层
  ├─ 流程关系图或互斥列表
  ├─ 数据关系图
  └─ 唯一字段编辑入口
  ↓ 每次合法图命令后
POST /api/validate
  ↓
结构阻断和业务提示
  ↓
用户主动下载v7 JSON
```

3001不调用3000，不使用MDM-AI助手，不新增数据库、会话接口、自动保存、浏览器持久化或运行时依赖。

## 2.1 页面治理状态

七个步骤固定为`start`、`boundary`、`skeleton`、`action`、`data`、`cross-department`和`handoff`。步骤只组织已有v6字段和前端视图，不新增JSON字段，不改变公共API。

- 当前步骤和图/列表偏好保存在候选的页面内存状态中，切换候选时恢复，刷新后清除。
- 步骤1至3映射到`round-1`，步骤4映射到`round-2`，步骤5映射到`round-3`，步骤6映射到`round-4`，步骤7映射到`final`。
- 步骤3拥有骨架字段；步骤4拥有动作和条件字段；步骤6、7只读汇总并通过目标映射跳回唯一编辑入口。
- 顶部单行操作区和治理流程帮助弹窗都由当前候选派生，不写入JSON。操作区只保留当前流程及必要状态、“保存当前草稿”“检查本轮”和文件、帮助入口；步骤正文不重复渲染“第几步、这一步做什么”的大块说明。
- 四项任务候选模式下，任务状态从所包含的内部步骤派生；“流程、执行人、动作与异常”同时汇总`skeleton`和`action`状态。节点办理规则和关系条件都通过流程骨架的右侧浮层编辑；关系条件仍写入既有`flow_relations[].condition`，不新增字段或迁移。进入“检查与保存”后，用户可以在跨部门事实核对和最终检查之间切换，未应用修改保护继续使用原切换门禁。
- `governanceIssues()`汇总当前页面业务提示；步骤状态和当前步骤的待补充项共同使用该列表。用户点击待补充项时，页面复用既有字段定位逻辑返回唯一编辑位置，不创建第二份可写字段。
- 第一步“JSON基本信息”显示源文件名、来源版本、源文件SHA-256和候选数量，不显示迁移结果。历史版本迁移仍在当前页面内存中执行，迁移规则、失败恢复和版本说明不变。

## 2.2 操作帮助与术语

操作帮助使用`public/index.html`中的静态受控内容渲染，不读取或改写当前候选，不新增JSON字段或持久化状态。帮助页固定分为使用前必读、当前编制任务、常用操作与异常处理、本工具术语四部分；默认显示七步，候选开关开启时显示四项任务。

术语定义从`../../docs/glossary.md`、`../../docs/contracts/process-governance-v6.schema.json`和本目录规则取得。前端只解释业务用户理解页面所需的定义、用途和边界；机器字段、枚举和技术标识保持原名。服务接口测试固定检查帮助入口、四部分结构和关键术语，防止后续页面改动再次缩减为零散提示。

## 3. v6结构

结构真源是`../../docs/contracts/process-governance-v6.schema.json`。根对象固定包含：

- `schema_version`
- `export_meta`
- `process`
- `behaviors[]`
- `flow_relations[]`
- `data_objects[]`
- `forms[]`
- `terms[]`
- `migration`

`behaviors[].node_type`允许空历史值、`action`、`decision`、`parallel_split`和`parallel_join`。普通行为可以编辑执行主体、动作、时限、完成标准和会签；控制节点不承担执行主体，已有普通行为字段只读保留，类型切换不得删除。

结构检查把普通`action`节点发出的`condition`关系，或同一普通节点同时存在继续和退回结果，识别为“隐藏判断”。页面提示用户保留`action`办理节点，并在其后增加独立`decision`节点，把判断名称写成可回答的问题。校对、复核、审核、核查、审批、批准等办理节点即使只保留一条退回线，也按隐藏判断提示。判断节点不参加业务行为评分。该检查属于业务提示，不改变JSON，也不阻止未审核草稿下载。

`declaredRouteDetails()`只检查节点说明中已经明确写出的直达关系。它从“进入、转入、转到、提交至、提交给、退回”等常用表达中识别目标业务动作，再核对当前节点是否有关系直达对应`action`。缺线时在第3步“流程骨架”提示说明和流程图不一致，并定位声明路线的源判断节点；它不从数据库字段名、相邻节点或行业惯例推断未写出的业务规则。

跨泳道的外侧分支和退回线在节点排位完成后重新计算轨道净空。轨道必须绕开起点、终点及中间业务行为，再按独立轨道放置条件标签；标签与节点仍有碰撞时继续触发未发布告警。多条关系进入同一目标时，按“独立分支—公共连接点—公共入线”显示：语义关系仍逐条保留，只有最后一段入线共享。退回关系从目标下方进入，其他前向关系从目标左侧进入。

数据关系和表单处理关系的新建选择器只列出`node_type=action`。命令层拒绝把数据操作绑定到`decision`、`parallel_split`或`parallel_join`。历史文件中已经存在的控制节点关系继续作为当前值显示并原样往返，直到用户把关系改到实际办理行为；导入和迁移不静默删除旧内容。

`trigger`只允许没有非回路入边的流程入口节点编辑。`input_description`和`output_description`只读保留。

`migration`固定包含首次来源字段和以下归档数组：

- `legacy_cross_department_records[]`
- `reference_materials[]`
- `internal_process_calls[]`
- `work_roles[]`
- `unresolved_actor_roles[]`
- `unresolved_join_modes[]`

新建v6文件使用`source_schema_version=process-governance-v6`、`source_process_ref=null`和`source_process_count=1`。v6重新导入直接深拷贝，不覆盖首次来源。

## 4. 迁移算法

迁移入口接收一个v1至v6对象或`document-structured-output-v2`多候选对象，按以下事务式顺序执行：

1. 深拷贝来源。
2. 回调`validateSource`按来源版本执行纯校验。
3. 按候选稳定顺序生成v6副本；引用和自动生成标识采用确定性规则。
4. 回调`validateTarget`逐个校验v6副本。
5. 全部成功后返回结果，由页面一次替换候选列表。

迁移不记录当前时间。相同输入产生相同输出；v6输入再次迁移只返回语义相同的深拷贝。

关键规则：

- 删除固定值`governance_status=candidate`。
- 字段来源缺少`source_type`时补`process_data`；现行值只允许`process_data`或`external_system`。
- 空`join_mode`和明确指向`parallel_join`的`all`不进入活动结构；无法确定的`all`归档到`unresolved_join_modes[]`并保留关系。
- 已知部门前缀从`current_actor_role`拆为部门和岗位；岗位未被花名册收录也保留。
- 无法识别的固定执行主体归档到`unresolved_actor_roles[]`，活动部门和岗位留空。
- `work_role`归档并保留迁移时的原行为名称，后续行为改名不改历史名称。
- 参考材料和内部流程调用原样归档，不参与当前绘图、流程计算或评分。
- 归档引用必须有效，且阻止删除被引用对象。
- 旧跨部门记录的诊断只识别历史固定触发句式，并要求句中行为名称与当前唯一行为名称完全一致；其他文字只按原值展示，不据此推断衔接位置。
- 旧触发位置与当前流程关系位置不一致时，页面列出两个具体位置和对应处理选项；诊断不修改草稿、迁移归档或源文件。

来源校验、目标校验、用户取消或任何候选失败时，页面不替换草稿、图状态、选择、撤销记录和导入基线。

## 5. 纯校验接口

`POST /api/validate`读取输入中的`schema_version`并选择对应结构规则。校验过程不得迁移、改变版本、补业务字段或归一化内容。响应`data`是输入语义不变的深拷贝。

v6在JSON Schema之外检查：

- 全文件技术标识唯一性。
- 行为、关系、数据、表单、字段和迁移归档引用完整性。
- 流程自环和语义重复关系。
- 数据操作中待确认与已确认操作冲突。
- 受归档引用对象的删除保护。

业务缺项、节点类型语义、分支条件、并行完整性和非回路闭环不属于服务端结构改写范围，只形成可定位提示。

## 6. 图命令和状态

图命令接收当前草稿，先深拷贝，再执行以下检查：

- 新技术标识与全文件标识不冲突。
- 关系端点存在，起点和终点不同。
- 关系判重符合类型规则。
- 数据操作状态不冲突。
- 删除对象没有活动引用和迁移归档引用。
- 同名归并满足名称、信息类型、创建行为和待确认状态规则。

命令成功返回新草稿，页面一次替换并提交`/api/validate`。命令失败不返回部分结果。

`graph-editor-state.js`按候选标识维护最多20个历史快照。撤销和重做只处理图命令及受控文档事务；文字输入仍使用浏览器原生`Ctrl+Z`。执行撤销前，当前完整文档必须与该历史记录的提交后指纹一致；执行重做前，当前完整文档必须与该历史记录的撤销后指纹一致。后续即时字段已经改变当前JSON时，页面返回`UNDO_SOURCE_CHANGED`或`REDO_SOURCE_CHANGED`并保留当前内容和历史记录，不使用完整旧快照覆盖后续修改。重新导入、清空和刷新清除历史；下载更新基线但保留历史。

内容指纹采用稳定键序列化，并忽略`export_meta.exported_at`。当前指纹与最近一次成功导入或下载基线不同即为未下载。

下载先克隆当前草稿并写入`export_meta.exported_at`，再执行服务端纯校验和浏览器迁移回读检查。四轮阶段下载跳过业务提示确认，最终下载保留确认；任何技术结构错误都阻止下载。下载文件名包含阶段。SHA-256输入是最终JSON文本经`TextEncoder`生成的实际UTF-8字节，优先调用`crypto.subtle.digest`，失败时调用同模块的纯JavaScript SHA-256。摘要计算失败只影响交接摘要，不影响已通过技术检查的文件下载。

## 7. 流程布局

流程布局只接收`behaviors[]`和`flow_relations[]`：

1. 用强连通分量收纳显式回路和异常非回路环。
2. 在分量图上执行稳定拓扑分层。
3. 普通行为按部门泳道和数组顺序稳定排列。
4. 控制节点进入顶部“流程控制”带。
5. 按最小列距分配节点，并使用正交折线路由；可见线段只允许0°、45°或90°，当前自动路由只生成0°和90°。
6. 检查节点—节点、标签—节点和标签—标签碰撞。
7. 根据碰撞类型增加垂直间距、泳道高度、关系轨道槽、列距或上下轨预留，最多重新计算六轮。

六轮后仍有碰撞时返回可定位的碰撞标识。布局告警不修改JSON、不阻止单个用户下载，但代表性发布样本存在碰撞时发布门槛失败。

`process-diagram.js`保持`autoungrabify`，不允许自由拖动。主流程图通过`editable`选项启用选择事件；选中节点或关系后保存当前缩放和平移，再打开全屏蒙版属性弹窗。重新挂载时通过`selectedFocus`恢复选择，通过图状态管理器恢复缩放和平移。主流程图默认使用三倍尺度：池标题48像素、泳道和外部节点42像素、普通与控制节点45像素、关系标签39像素、徽标36像素；节点和徽标等比放大，泳道内节点间距保持24像素，其他间距只增加到消除节点、标签或轨道碰撞为止。首次挂载使用`zoom=1`并把流程开头定位到左上可视区；“查看全图”执行全图适配。“查看图例示例”中的只读流程图图例始终传入`editable=false`且不显示数据或表单徽标。节点组合图例默认折叠，只在用户展开后挂载画布；折叠、离开流程关系页或重新渲染时销毁画布实例。

普通行为徽标从当前草稿只读聚合：数据徽标汇总创建、更新和使用数量，表单徽标显示关联表单数量，超过99显示`99+`。徽标不进入rank、泳道、路由或JSON。

## 8. 数据关系图

数据关系图不复用流程rank、部门泳道或流程边路由。当前数据对象位于中心；直接关联行为按操作类型和`behaviors[]`稳定顺序排列。

步骤5字段编辑和数据关系图从同一份`data_objects[]`读取数据，但两种界面需要不同的选择结果。字段编辑使用包含当前数据对象、数组位置和稳定引用的选择结果；数据关系图直接使用当前数据对象。两个选择函数使用不同名称，避免浏览器函数覆盖后导致字段编辑无法解析当前数据对象。

同一数据对象和行为的操作合并为一条可见边：

- 创建：行为指向数据。
- 更新：双向。
- 使用：数据指向行为。
- 待确认：问号且无方向。

可见边只用于显示，JSON保留独立`behavior_links[]`和未变化记录的`link_ref`。

同名数据归并先计算字段归属、字段来源、动态责任部门、行为关系和来源线索影响。活动引用改写到保留对象，迁移归档不改写。冲突或归档引用存在时返回失败；通过后把整个归并作为一条图命令写入历史。

## 9. 页面恢复和降级

普通字段修改优先只更新相应图元素。必须重新布局时，页面先保存当前模式、选择、缩放和视口，布局后恢复。

图模块加载或运行异常时：

- 图区域显示停用提示。
- 不清空或修改草稿。
- 列表和字段编辑、导入、`/api/validate`和下载继续工作。

页面以浏览器内容可视区1920×900为硬门槛。`syncViewportRequirement()`和CSS媒体查询共同判断宽度或高度不足；不足时全屏阻断层显示当前尺寸，为应用根节点增加`inert`并阻止编辑。达到要求时，`body`和`.page`固定为一个内容可视区且`overflow:hidden`，主工作区、侧边栏、表格和弹窗分别管理内部滚动。1536和1280宽度不再提供压缩布局；1920宽屏可以保留浏览器栏和系统任务栏。

## 10. 测试与性能

`npm.cmd test`依次运行治理流程、评分、服务接口、认知负担、四项任务候选界面和图编辑等测试。治理流程测试覆盖七步顺序、阶段映射、问题定位、步骤状态和SHA-256标准向量；四项任务测试覆盖默认关闭、严格开关值、四组映射、动作问题返回流程骨架、候选帮助文案和七步内部状态保留。固定构造器覆盖v1至v5、历史多候选、非法枚举、断裂引用、无法解析角色、未解决`join_mode`、历史工作角色、多创建行为、归并冲突、迁移幂等、失败恢复、v6往返和`/api/validate`纯校验。前端固定检查还验证唯一编辑入口所依赖的数据对象选择函数不会被图选择函数覆盖，并检查“JSON基本信息”不显示迁移结果、待补充项入口、操作帮助四部分和关键工具术语。

代表性布局样本包含约40个节点、80条关系、长名称、长标签、多分支、跨泳道和多回路，要求三类碰撞清单为空且相同输入坐标一致。

性能样本包含40个节点、80条流程关系、30个数据对象、120条操作记录、至少60条合并可见边、10张表单和200个字段。预热一次，连续三次取中位数，门槛如下：

| 操作 | 门槛 |
| --- | ---: |
| 图首次显示和模式切换 | 2秒 |
| 选择和聚焦可见反馈 | 300毫秒 |
| 新增、删除、撤销、重做 | 1秒 |
| 200字段归并 | 2秒 |
| 下载并重新导入 | 3秒 |
| 单次界面冻结 | 不超过1秒 |

真实浏览器覆盖1920×900和1920×1080可编辑状态，以及1919×1080、1920×899、1536×864和1280×720阻断状态。1920×900检查页面级纵向与横向滚动均为零、流程骨架默认不全屏、用户主动全屏后的尺寸、右侧约二分之一宽度的编辑浮层、动作与异常字段应用、判断/退回/并行关系在新建确认页填写并可从流程线再次编辑、未应用修改三选保护、100%清晰检查和查看全图；不足尺寸检查阻断层显示且应用根节点具有`inert`。全部场景同时检查控制台warning/error均为0、无3000请求和本地静态资源断网可用。图模块使用Cytoscape默认滚轮灵敏度，避免非必要覆盖产生控制台告警。

真实浏览器性能回归入口为 `npm.cmd run test:browser-performance -- --BaseUrl <候选3001地址>`。该入口不启动、停止或重启服务。脚本从候选实例取得当前V7空白模板，在页面内存生成固定大样本并先调用严格校验接口；计时使用页面的 `performance.now()`，每项预热一次后测量三次。流程图和数据图完成条件以 Cytoscape 实际节点或模型状态为准，并等待两个绘制帧；界面冻结同时使用 Long Task 和相邻 `requestAnimationFrame` 间隔检查。归并计时排除人工阅读确认框的时间，下载重导入计时包含浏览器下载、临时内容读取、文件输入和重新安装候选的完整链路。

多候选原子拒绝回归入口为 `npm.cmd run test:browser-import-atomic`。该脚本使用随机回环端口和系统临时目录，测试结束后关闭独立服务与浏览器并清理临时目录。浏览器状态验收拆成图编辑与网页表格两个自然场景；每个场景都在源校验和全部目标候选校验结束后触发真实文件输入，并对失败前后快照做严格比较。文件输入按页面安全规则清空，但测试保留同一个不可变 `File` 对象引用，重新核对名称、大小、修改时间和SHA-256，不能把输入控件清空误写成源文件被修改。

## 11. 发布与回滚

发布记录保存v5和v6提交号、结构摘要、自动测试、三档视口浏览器截图、认知负担走查、碰撞结果、性能记录和健康检查结果。发布前还必须由一名真实编制人和一名真实核对人各完成一次代表性流程走查；自动化测试不得替代该人工门槛。

图编辑模块故障时，先使用内置降级保留v6列表和字段编辑。v6结构或迁移存在严重缺陷时，回退到记录的v5提交。回退不得自动降级、改写或删除用户已经下载的v6文件；用户保留文件，等待v6修复后重新导入。
