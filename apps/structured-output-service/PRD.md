# 3001 process-governance-v6 图编辑升级 PRD

## 1. 业务目标

3001升级为无状态、以图为主的单流程编制工具。业务人员可以在流程关系图和数据关系图中直接维护结构，再用文字编制补充详细内容。图、属性面板和文字编制共同读写一份页面内存草稿，避免同一事实出现多套编辑来源。

当前交付只形成未审核的`process-governance-v6` JSON。业务部门负责核对流程事实，3001的结构检查和流程评审不构成正式审核、批准或发布。

## 2. 用户与使用场景

主要用户是流程编制人员和现场核对人员。

- 编制人员从空白模板开始，或导入v1至v6、历史多候选结构化JSON。
- 编制人员先建立流程和数据关系，再补充表单、字段、动作、时限和完成标准。
- 核对人员在流程评审页面查看当前流程和固定对照图例，记录业务问题。
- 编制人员处理结构阻断后下载v6 JSON。下载是唯一保存动作。

## 3. 固定范围

本期包括：

- `process-governance-v6`结构规则和版本历史。
- v1至v5、v6及历史多候选文件的确定性无损迁移。
- 可编辑流程关系图、聚焦式数据关系图和单一属性面板。
- 每候选20次图操作的撤销、重做。
- 无级联删除保护和同名数据受控归并。
- 确定性布局、三类碰撞避让和布局告警。
- 五层提示、流程评审对照图例和结构化学习评分v3。
- 桌面浏览器内容可视区适配、自动化测试、浏览器走查、性能和回滚证据。

本期不包括：

- 账号、数据库、服务端草稿、自动保存和浏览器持久化。
- 自由拖动摆位、图坐标持久化、拖线插件和新增运行时依赖。
- 3000代码、接口或数据库变更；v6不能直接导入3000，也不自动降级。
- MDM-AI助手变更或测试；该应用继续使用v5。
- 手机布局、业务用户独立验收会议或用户行为采集。

## 4. 默认操作路径

1. 新建或导入。
2. 编辑流程关系。
3. 编辑数据关系。
4. 在文字编制中补充详细字段和表单。
5. 进入流程评审。
6. 处理结构阻断并导出。

页面不得同时展开完整流程关系图和完整数据关系图。当前图模式最多显示六个一级操作；页面同时只保留一个活动选择和一个属性面板。

## 5. 关键业务规则

### 5.1 流程关系

- 普通行为按部门进入泳道，控制节点进入“流程控制”显示带。
- 关系建立最多经过选择类型、选择起点、选择终点和确认四个动作。
- 每条关系只有一个起点和一个终点；一对多和多对一由多条独立关系表达。
- 判断分支和并行开始都能表达一对多，但语义不同：判断分支只执行符合条件的路线，并行开始同时启动多条路线。
- 普通汇合只表示多条路线可到达同一行为；并行汇合表示等待全部路线完成。
- 自环、缺失端点和完全重复关系不得写入草稿。其他业务完整性问题只提示。

### 5.2 数据关系

- 每次只围绕一个数据对象显示直接关联行为。
- 同一数据对象和行为的多个操作在图上合并显示，JSON仍保留独立记录。
- 待确认操作不能与已确认操作并存。
- 历史多个创建行为不自动纠正，只提示业务人员确认。

### 5.3 同名数据归并

- 只有去除首尾空白后名称完全相同时才显示入口，不自动归并。
- 用户选择当前数据对象作为保留对象并查看影响预览。
- 信息类型、创建行为或待确认状态冲突时阻止归并。
- 普通字段值差异由用户明确选择。
- 活动引用改写到保留对象；迁移归档不得改写。归档引用待删除对象时阻止归并。
- 归并通过副本校验后一次替换，并可作为一条图命令撤销。

### 5.4 删除、撤销与未导出保护

- 删除不级联。系统列出流程关系、数据关系、表单、动态执行主体、字段来源和迁移归档引用。
- 被引用对象禁止删除，并提供跳转入口。
- 每个候选流程独立保留最近20次图操作；两个图模式共享当前候选的记录。
- 内容指纹与最近一次成功导入或导出基线不同时，页面显示未导出状态并在离开前提示。
- 旧版迁移为v6后标记为未导出。导出成功后更新基线，但不清空草稿和撤销记录。

## 6. 提示和评审

页面按以下层次显示信息：

1. 本次操作反馈。
2. 当前对象待补内容。
3. 默认折叠的迁移摘要。
4. 集中显示的导出阻断。
5. 不写入JSON的流程评审意见。

结构规则错误、非法枚举、重复技术标识、断裂引用和往返丢失阻止导出；业务缺项只提示。

流程评审固定使用`process-review-readiness-v6`。原有九类图例之外，增加“一对多怎么表达”和“多对一怎么表达”两个只读对照图例。图例必须显示“仅用于理解关系，不属于当前流程，不代表评审通过”。

结构化学习评分固定使用`structure-learning-score-v3`，页面标签为“结构化学习评分 v3（process-governance-v6）”。评分只反映当前结构化内容，不代表业务正确或正式评审通过。

## 7. 桌面可视区

- 目标电脑物理屏幕分辨率不低于1920×1080。
- 浏览器内容可视区不低于1600像素时使用完整桌面布局。
- 1280至1599像素时缩窄侧栏和属性面板，宽表格只在自身容器滚动。
- 低于1280像素时显示窗口过窄提示并保留必要滚动，不切换手机布局，也不阻止文字编辑和合法导出。
- 桌面触摸屏继续支持Pointer Events。

## 8. 验收标准

- 默认模板、结构规则、健康检查和版本历史一致返回v6。
- v1至v5及历史多候选可以确定性迁移；失败、取消和重复迁移不损坏现有状态。
- v6导出后重新导入无业务内容和引用丢失。
- 流程图和数据图可以完成新增、建立关系、删除保护、归并、撤销和重做。
- 代表性流程的节点—节点、标签—节点和标签—标签碰撞清单为空。
- 图模块故障时，文字编制、导入、校验和导出仍可使用。
- 1920×1080、1536×864和1280×720内容可视区中的主要操作可见或能通过局部滚动到达，没有意外页面级横向滚动和控制台错误。
- 性能样本达到计划规定的2秒、300毫秒、1秒、2秒和3秒门槛。
- 页面不请求3000接口；静态资源断网可用。
- 自动化测试、浏览器走查、认知负担、性能、文档、审计整改和回滚证据全部一致后，才可以宣布v6完成。
