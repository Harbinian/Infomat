# 3001 单流程编制功能需求

## 1. 业务目标

3001 为业务人员提供无状态的流程编制页面。用户可以直接新建流程，也可以导入现行或历史结构化 JSON 继续整理。用户主动导出的 JSON 是唯一保存方式。

流程是本功能的管理抓手：一份 JSON 只对应一个流程；流程向下管理业务行为、判断节点、现行执行岗位、已有工作角色、输入输出和跨部门关系，向上为未来生成并关联正式制度提供依据。

## 2. 使用角色

- 编制人：在3001中整理流程并导出未审核 JSON。
- Codex：在线下对 JSON 做预审，输出独立问题清单，不在 JSON 中写入审核意见。
- PMO：在线下完成业务审核；未审核结果不得进入3000。
- 业务部门 `business_contact`：在后续3000重构完成后，上传PMO批准的JSON。

编制人通过公司局域网直接访问3001。3001不登录、不识别账号，也不产生审核任务。

## 3. 本期范围

### 3.1 新建和导入

- 页面提供“新建流程”入口，打开空白单流程编辑页。
- 新建时不自动填写流程名称、制度编号、业务行为或判断节点。
- 页面只提供结构化 JSON 导入，不再提供制度、表单、操作说明或其他参考材料上传入口。
- 历史 `document-structured-output-v2` 文件包含多个流程时，3001拆成多个候选，用户逐一编辑并分别导出。
- 一个 `process-governance-v1` JSON只能包含一个流程。

### 3.2 分区式文字编制

- 顶部保留“新建流程、导入结构化文件、导出当前流程、清空当前页面”。
- “文字编制”内部设置“基本信息、目的与范围、术语定义、流程步骤、表单与记录、导出检查”六个分区，一次只显示一个工作区。
- “流程步骤”内部设置“业务行为、流程关系、输出物与数据、跨部门承接”四个子分区，不提供“部门内调用”填写入口。
- 新建流程默认进入“基本信息”。候选切换、未导出内容保护和导出失败保留当前页面继续沿用。

### 3.3 只读跨职能流程图预览

- 主工作区设置“文字编制”和“跨职能流程图预览”两个互斥标签。新建空白流程默认打开文字编制；导入包含已命名业务行为的文件后，自动打开预览。
- 文字编制页持续说明预览条件：填写至少一个业务行为名称后可以查看节点；只有填写明确的流程关系后才显示箭头。系统不得按行为录入顺序或名称推测关系。
- 预览采用BPMN 2.0.2最小图形子集，不生成BPMN XML，也不向业务用户展示完整BPMN术语。画布上方常驻七类业务图例和阅读提示，并提供画布外的三步示例。
- 每个执行部门形成一条横向泳道。归口部门在已参与执行时排在最上方，其他参与部门按组织目录顺序排列；执行岗位显示在节点第二行。无法识别部门的历史执行值进入“执行部门待明确”泳道，原值不得改写。
- 业务行为使用圆角矩形，判断使用带“×”菱形，并行拆分和并行汇合使用带“＋”菱形，节点类型为空时使用虚线矩形。会签只显示“会签×N”标记，完整会签部门继续在文字编制中查看。
- 本流程关系使用实线实心箭头。判断条件写在对应箭头上，回路使用带“回路”文字的实线回返箭头；回路和返回关系不参与主线前后层级计算。
- 节点名称、岗位和关系条件必须完整显示，不得截断。预览可以按中文字符增加显示用换行，并按实际行数调整节点高度；判断和并行菱形必须同时扩大宽度和高度，使名称和岗位留在图形内部。
- 相邻层级为两个节点的半宽、最长220图形单位的关系标签和48图形单位安全间距预留空间，中心间距不得小于440图形单位。单一相邻顺序关系继续使用直角连线；多个判断分支和跨层关系使用上方独立轨道；显式“流程内部回路”使用下方独立轨道。同一目标的多条回路按稳定关系顺序外扩，线路、标签和点击区域不得重合。
- 对非回路关系构建的有向图如果形成闭环，参与闭环的判断分支、顺序或并行关系进入可定位的“关系类型请核对”清单。页面说明“该关系与其他非回路关系形成闭环；如果这是退回前序行为，请选择‘流程内部回路’。”该提示不阻止导出，不自动改关系类型，也不改变图中关系语义。
- 跨部门承接显示在泳道区域外，使用虚线空心箭头连接。承接卡只显示承接部门、目标流程或行为和承接事项；缺失内容显示“待明确”，不得补造业务事实。
- 导入JSON中已有的内部流程调用在调用部门泳道内显示为粗边框节点。3001不提供新增或编辑入口；用户点击该节点时，页面说明由MDM平台正式功能维护。
- 主图不显示数据对象、表单、完整会签部门、流程阶段或推测的开始和结束事件。用户点击本流程节点、关系或承接卡时，页面返回文字编制并定位对应卡片。
- 关系类型、起点、终点或跨部门发送行为缺失或引用无效时，流程图不得绘制错误箭头，并显示可定位的未绘制提示。
- 用户可以平移、缩放、适应画布、重置视图和展开查看，但不能拖动节点、增删图形或连接箭头。完整画布拟合比例不低于0.60时默认显示全图；低于0.60时默认聚焦泳道表头和前两层节点，并显示“当前已聚焦流程开头，点击‘适应画布’查看完整流程”。“适应画布”始终显示全部内容，“重置视图”恢复自适应默认视野。桌面端画布高度不超过约520像素，移动端约420像素。
- 图例示例状态、展开状态和计算坐标只存在当前页面运行内存，不写入JSON。图形加载失败时，页面必须保留文字内容、导入和导出能力。

### 3.4 无状态边界

- 服务默认监听`0.0.0.0:3001`，公司局域网用户通过服务器局域网地址直接访问。
- 不写数据库。
- 不使用 `localStorage`、`sessionStorage`、IndexedDB、Cookie或服务端草稿恢复。
- 导入的结构化文件只在当前浏览器内存中处理，处理完成后不写服务端文件。
- 刷新或关闭页面后内容清空。
- 新建、导入另一文件或清空当前页面前，向用户提供“取消、先导出、放弃当前内容”。
- 3001不得通过API、数据库、队列、回调、共享会话或状态轮询与3000通信。
- 3001不得调用DeepSeek，也不得把结构化填报助手或认证网关作为启动、访问或导出的前置条件。

### 3.5 流程内容

PMO批准前，流程至少应补齐：

- 发起部门、编制人、流程名称、归口部门。
- 流程目的和适用范围。
- 至少一个业务行为。
- 每个业务行为写明当前执行岗位或“全公司通用”、触发条件或前置条件、完成标准和输出结果。

能力域和业务能力属于可选归类结果，缺失时保持“未归类”，不阻止3001导出或PMO审核。

制度名称、制度编号和制度关联不是新流程审核或导入的前置条件。正式制度在流程生效后另行生成和关联。

### 3.6 流程、执行岗位和工作角色

- 新增步骤时，步骤类型默认留空，由用户主动选择业务行为、判断节点、并行分支或并行汇合。
- 判断节点至少两条分支，条件应互斥并覆盖全部结果；3001只提示，不阻止草稿导出。
- 允许有明确退出条件的流程内部回路；跨部门承接链禁止形成回路。
- 3001允许记录并行分支和汇合，但不验证完整性。
- 业务行为使用“执行部门和执行岗位”选择器。岗位目录由`/api/enums`从仓库花名册只读提供，不调用3000。
- 执行部门可以选择组织目录中的任一部门。所选执行部门与流程归口部门相同时，页面说明为本部门执行；二者不同时，页面说明为跨部门执行。页面不新增执行范围字段，仍通过`current_actor_role`中的部门名称判断。
- 执行岗位只显示所选执行部门在花名册中的岗位，不得混入其他部门岗位。花名册中存在名称与部门看似不一致但确实归入该部门的岗位时，3001仍按花名册原值显示，不擅自调整部门或岗位名称。
- 新增行为不默认选择部门或岗位。具体岗位以“部门名称 + 岗位名称”保存到`current_actor_role`；“全公司通用”保存为`全公司`。
- 导入值未被当前花名册收录时，3001保留原值并醒目标注；花名册岗位加载失败时，也不得清除已有值。
- 工作角色与岗位严格区分。岗位容纳工作角色，一个工作角色可以由多个岗位容纳；3001不得根据岗位生成或推测正式工作角色。
- 普通编制页面不新增或编辑正式工作角色，新业务行为的`work_role`为`null`。导入文件中已有的合法`work_role`隐式保留并随再次导出带回。
- 已有工作角色仍必须绑定具体业务行为，并保持“XX行为的发起／办理／审核／批准／判断／发送／接收／会签角色”的全称，不得退化为“申请人、审核人、批准人”等孤立名称。

本期不增加“业务流程／行政流程”分类字段，统一按不存在行政流程处理。

### 3.7 跨部门承接、内部调用预览和会签

- “承接”只指跨部门业务行为。同一部门内流程之间称为“内部流程调用”。
- 业务行为卡片提供“为当前行为添加跨部门承接”。用户可以先填写承接部门和处理事项；3001在`cross_department_handoffs[]`中创建同一条承接记录，并把当前业务行为写入`send_behavior_ref`。
- “跨部门承接”子分区引用并编辑同一条承接记录，不复制业务字段。页面显示发起承接的本流程业务行为，并允许用户继续补充输入数据、返回数据、触发条件、完成标准、目标流程、目标行为和主流程恢复位置。
- 一项业务行为可以创建多条跨部门承接。每个承接部门形成独立记录。
- 删除已经关联跨部门承接的业务行为前，3001必须说明将同时删除多少条承接记录，并由用户确认。
- 跨部门承接必须形成“发送行为—数据对象—接收行为”。3001记录业务关系和已有工作角色，但本轮页面不新增正式工作角色。
- 接收行为是后续承接行为的前置条件。
- 一项发送行为可以向多个部门发送同一输出，但每个部门形成独立承接关系。
- 主流程分别指定发给承接部门的输入数据、完成标准、承接完成后返回的数据和恢复执行位置；承接部门不得修改恢复位置。
- 恢复位置只保存在主流程调用关系中，不写入承接流程。
- 部门内调用属于MDM平台正式功能的预览。新建流程保持`internal_process_calls: []`；3001不新增、不编辑也不校验业务完整性。导入文件中已有的`internal_process_calls[]`在当前页面内存中隐式保留，流程图可以预览，再次导出时不得清空或改写。
- 会签表示知悉，不表示审核、批准或承接。3001记录需要确认知悉的部门；全部会签对象确认知悉后，会签行为才完成。
- 会签未完成时流程不得结束，即使批准行为已经完成。

### 3.8 数据和表单

- 用户填写的输出物登记为待治理数据对象，生成隐藏技术标识。
- 3001只记录数据对象名称、产生行为和使用行为，不判断主数据、黄金源、数据责任或质量规则。
- “表单与记录”作为独立编制页面。用户先选择表单或记录，再选择主表或某张明细表结构，最后编辑当前结构下的填写项。
- 用户文案使用“表单或记录名称”“表单或记录编号（如有）”“主表结构／主表标题”“明细表结构／明细表标题”和“填写项”。
- 新建表单只建立一个空主表框架，不自动生成名称、编号、标题或填写项。
- 每张表单正常情况下只有一个主表，可以增加多张明细表；表单与业务行为保持可选关联。
- 不新增JSON字段：`area_type: "基本信息"`表示主表，`area_type: "明细清单"`表示明细表，`areas[].items[]`保存填写项。
- 导入缺少主表、包含多个主表或存在未分类结构时，3001保留全部内容并提示用户确认，不静默改写，也不以此阻止草稿导出。

### 3.9 编制参考材料

- 页面暂停提供编制参考材料入口、拖放区、编辑区和缺失提示。
- 新建流程的`reference_materials`为空数组。
- 导入的旧JSON如果已有参考材料，3001在当前页面内隐式保留，再导出时原样带回；页面不展示、不编辑，也不自动清空。
- 导入的现行或历史JSON如果已有`internal_process_calls[]`，3001只在流程图中预览，并在再次导出时原样带回；页面不提供填写入口。
- 服务端确定性解析能力保留用于历史文件迁移和回归测试，不作为业务用户页面功能。

### 3.10 导出和审核边界

- 3001允许导出不完整草稿。
- 导出文件名统一为 `未审核-发起部门-流程名称-导出时间.json`。
- JSON不包含审核状态、审核意见或批准标记。
- Codex预审材料和PMO审核材料与流程JSON严格分开。
- 3001硬校验只保证JSON可读和单文件引用不损坏。唯一入口、结束条件、循环、会签、并行汇合和跨流程关系只提示或原样导出。
- 新格式在3000重构完成前不得投入3000。

## 4. 明确不做

- 不在3001保存草稿、账号或审核状态。
- 不在3001使用DeepSeek辅助抽取或填报。
- 不在页面提供编制参考材料上传或编辑。
- 不在3001新增或编辑部门内调用；该能力由MDM平台正式功能维护。
- 不在普通编制页面新增或编辑正式工作角色。
- 不要求局域网用户通过结构化填报助手或认证网关访问3001。
- 不在3001生成制度、维护制度审批或关联正式制度。
- 不在3001实施完整流程引擎、跨流程完整性校验或数据治理。
- 不修改3000现有代码、RBAC或数据库。

## 5. 页面顶部信息

页面顶部只显示工具名称、用途说明和操作入口。页面不显示DeepSeek停用说明，也不显示3001无状态、3000通信或线下审核边界的通用声明。上述边界继续作为产品和技术规则执行。

## 6. 验收标准

1. 用户无需先上传文件即可创建空白流程。
2. 页面刷新后无法恢复内容，浏览器存储中不存在草稿。
3. 新建、导入其他文件或清空前出现三选一保护。
4. 新增步骤的类型为空，不默认认定业务行为或判断节点。
5. 3001导出符合 `process-governance-v1`，根对象只有一个 `process`。
6. 旧版多流程JSON可拆分为多个候选，候选逐一导出后内容不串流程。
7. 导出文件名包含“未审核”、发起部门、流程名称和导出时间。
8. 页面顶部不显示DeepSeek停用说明或系统边界通用声明；页面及服务端不包含DeepSeek调用入口或健康状态。
9. 新增业务行为的`work_role`为空；导入已有合法工作角色后可无损再次导出。
10. 新建流程默认显示文字编制；导入包含业务行为的文件后默认显示只读流程图。
11. 没有明确流程关系时，流程图只显示孤立节点，不按录入顺序生成箭头。
12. 图中可以识别跨部门承接和历史内部流程调用；点击跨部门承接后定位到对应文字卡片，点击内部流程调用后只提示在MDM平台正式功能中维护。
13. 图形操作不修改流程JSON，导出结果不包含坐标、标签页状态或图形配置。
14. 自动测试和真实页面主路径通过。
15. 页面和服务端结构版本不一致时，页面在新建或导出前明确提示保持当前页面打开并重启3001服务，不得显示JSON解析错误、旧版字段缺失或误报技术引用损坏。
16. 不设置`STRUCTURED_OUTPUT_HOST`时，3001监听`0.0.0.0:3001`；局域网用户可通过服务器局域网地址完成新建、编辑和导出，全程不依赖DeepSeek、结构化填报助手或认证网关。
17. 新建流程没有参考材料入口，导出结果包含空数组；导入含历史参考材料的文件后再次导出，历史内容不丢失。
18. 具体岗位、“全公司通用”、未收录旧岗位、花名册加载失败和空岗位五种情况均不会误填或清空已有数据。
19. 新建表单形成一个空主表，可以分别维护多张明细表和各自填写项；导出后重新导入，主明细归属、业务行为关联和技术引用保持一致。
20. 连续填写表单名称、编号等相邻字段时，不因分区或侧栏标签刷新丢失刚输入的值。
21. 用户可以在业务行为卡片中创建一条或多条跨部门承接，并在“跨部门承接”分区继续编辑同一条记录；删除发送行为前会显示关联承接数量并要求确认。
22. 新建流程不显示部门内调用填写入口；导入含`internal_process_calls[]`的历史JSON后，流程图可以只读预览，再次导出和重新导入时历史调用保持不变。
23. 执行部门下拉可以选择全部组织部门；选择归口部门以外的部门时，岗位下拉只显示该部门的花名册岗位，并明确提示当前属于跨部门执行。现行花名册把岗位归入哪个部门，3001就按该归属显示。
