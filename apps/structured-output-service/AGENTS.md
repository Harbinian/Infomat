# AGENTS.md

本目录是文档结构化输出辅助服务，只服务制度文件到 `document-structured-output-v2` 的本地整理、页面编辑和结构化文件导入导出。

## 修改边界

- 可以修改：`server.js`、`public/index.html`、`scripts/` 下的服务测试、`package.json`。
- 不要修改：`docs/norms/` 流程输入基线、PMO 驾驶舱、MDM 平台运行代码，除非用户明确要求进入对应主责资产。
- 数据合同以 `../../docs/contracts/document-structured-output.schema.json` 为准；不要在本目录另造字段口径。
- 本服务是无状态辅助工具：不得写数据库，不得保存用户上传原文或页面内容，不得使用浏览器存储恢复内容。
- 刷新或关闭页面后内容应清空；导出结构化文件是用户主动保存结果的唯一方式。
- 本服务输出不得自动发布为已确认流程映射，也不得写回 `docs/norms/`。
- 导出的 `document-structured-output-v2` JSON 可以交给 MDM 平台 3000 端口导入；导入落库由 MDM 的 `/api/process-design/import-structured-output` 承接，本服务不得直接写 MDM 数据库或调用 MDM 写接口。
- 允许只读读取 `docs/norms/*映射关系.md` 用于流程映射匹配；不得修改流程输入基线。
- 允许只读读取 `../../docs/organization/花名册.md` 用于执行角色、填写角色的职务选择和核对；业务行为优先展示所在流程归口部门下的职务，表单与记录优先展示当前表单形成部门下的职务，局部部门为空时回退制度归口部门；“公司领导”作为可选执行部门固定提供“董事长 / 总经理 / 副总经理”三个角色，用于领导审批、决策和签发场景；导入内容中的外部门角色只提示核对；不得写回花名册、身份库或 MDM 平台数据。
- DeepSeek 只用于受控抽取和页面非枚举空字段填报建议；建议不得写入导出的结构化文件，不得记录用户原文、建议内容或上传文件名。
- DeepSeek 优先读取本服务显式环境变量；未显式配置时，可读取 CC Switch 写入的 Claude 配置中的 DeepSeek Anthropic 兼容地址、令牌和模型。只读取运行配置，不写回 CC Switch、Claude 配置或用户内容。
- DeepSeek 填报建议在页面填充后后台生成，不得阻塞上传填充；可以分批请求以提升返回格式稳定性，分批不得截断空字段清单，慢响应、失败或总时限用尽时只降级为页面通用建议。

## 运行与验证

```powershell
npm start
npm test
```

默认端口是 `3001`。测试使用 `STRUCTURED_OUTPUT_PORT` 启动隔离端口，不应依赖正在运行的 3001 服务。

## 用户界面口径

- 用户按钮固定为“导入制度文件”“导入结构化文件”“导出结构化文件”。
- 页面面向业务编辑，顶部保留“Deepseek-V4-Pro 1M上下文模型辅助生成”说明；除此之外不显示内部字段名、模型参数、schema、JSON、多个建议值、置信度、待确认问题等技术口径。
- 页面视觉跟随 MDM 的暖宣纸系配色，避免高亮冷白底和刺眼蓝色。
- 页面不得显示“一级分类”“二级分类”“三级流程”“流程名称”“管理主题”“业务事项”“流程范围”“流程动作”等要求用户理解内部抽象或临时造词的标签；流程映射沿用来源表列名，业务行为沿用数据模型名称。
- 流程映射中的“能力域”和“业务能力”来自 `docs/norms/*映射关系.md` 只读匹配结果，只展示来源值和依据，不作为用户手填字段。
- 归口部门使用下拉选择，制度文件和结构化文件都可以通过按钮或拖入导入。
- 必填字段用星号标出，顶部用红绿双色饼图显示必填内容是否已经可以结构化。
- 导入制度文件后必须立即显示持续可见的整理中提示；文件较大时前端应更新等待文案并暂时禁用导入/导出/清空按钮。页面填充完成后先恢复编辑和导出，填报建议较慢时只显示后台补充提示，不再阻止用户继续操作。
- 态度、原则、倡导和泛化要求不得生成业务行为；原文未写清的角色、输入、输出、触发和前置条件留空。
- 流程正文如果已按“行为N / 执行角色 / 触发场景 / 前置条件 / 输入或输入材料 / 输出或输出结果 / 执行标准”成组填写，必须优先按显式字段直接转换，不再把同一流程章节里的邻近正文和字段标签重复拆成业务行为。每个字段保留自己的原文依据；只规范部门与岗位之间的连字符，不自动修正源文中的角色、行为名称或业务内容。
- Word 术语定义优先按表格列识别；术语表多出“序号”列时不得把序号当术语，也不得把“定义”表头当术语。
- 填表类业务行为应收敛为“填写《表单名称》”，不要把时限、“附表1”等附件编号写进行为名称；输入材料保留完整书名号。
- 填表类业务行为的执行标准优先按对应表单的填表说明执行，并提示继续完善具体填写标准。
- 一份制度允许拆成多条流程；页面可以人工新增业务行为、判断节点和判断分支。判断节点仍按业务行为字段填报；判断分支只允许连接同一流程内的步骤，未补流向可以保留为空。
- 流程卡片可按整条流程折叠；折叠资格只看业务行为、执行角色、输入材料、输出结果和执行标准，触发场景和前置条件不影响折叠资格。折叠状态只保存在当前页面运行态，不进入导出文件。
- 执行角色在页面中通过当前流程归口部门和花名册职务选择；流程归口部门为空时回退制度归口部门。下拉不展示其他部门职务，但可选择“全公司”作为全员/全公司适用制度的特殊执行范围。导入内容中的外部门角色、或不在当前部门花名册职务中的角色，只在字段原位置提示核对，不新增问题清单，不拦截导出。
- 跨部门流程不要在同一个执行角色下混选其他部门岗位；应新增或切换到对应承接流程，把该流程归口部门改为目标部门或“公司领导”，再选择该部门下的岗位。
- 非枚举空白字段可以在原位置显示填报建议；DeepSeek 建议优先展示，有逐字匹配依据时可折叠查看参考原文；建议只帮助用户补齐页面，不进入导出的结构化文件。下拉选择、执行角色部门和岗位选择等枚举类字段不显示填报建议。
- DeepSeek 不可用、超时或返回不合规时，页面只保留通用填报建议，不显示技术错误。
- 表单字段在页面中使用表格编辑，不再以字段卡片堆叠；字段表格必须先选中具体表单和具体表，允许新增表并编辑表头名称，只展示和编辑当前表对应字段。表单与记录的填写角色通过当前表单形成部门和花名册职务选择，形成部门为空时回退制度归口部门。Word 主表中嵌套的“名单/明细清单”应识别为明细表，不要把明细表标题当普通字段。
- 主数据对象和跨部门流转保留在结构化文件字段中，当前页面不设置独立编辑区。

## 乱码处理

`.txt` 和 `.md` 上传应优先按 UTF-8 读取，发现替换字符时降级按 GB18030 读取。修复上传或导出问题后，必须跑 `npm test` 覆盖中文文本。
