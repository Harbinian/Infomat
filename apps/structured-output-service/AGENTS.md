# AGENTS.md

本目录是端口 3001 的单流程治理编制工具。本文件只保留目录级硬规则和任务路由；产品行为、技术实现、接口和测试细节按任务读取当前 README、PRD、Tech-Spec 和结构规则。

## 修改边界

- 可以修改本目录的 `server.js`、`public/`、`scripts/`、`package.json` 和说明文档。
- 不修改 `apps/mdm-platform/`、`apps/structure-assistant/`、`docs/norms/`、PMO 驾驶舱或 MDM 数据库，除非用户明确扩大范围并确认主责资产。
- 3001 不依赖 DeepSeek、MDM-AI助手或认证网关，不停止、重绑、读取或代管 3000。3001 不判断 3000 当前是否允许承接文件。
- 本轮只调整文档或协作入口时，不得改变 v7 Schema、接口、状态、枚举、导入导出格式或页面行为。

## 不可违反的产品边界

- 3001 是无状态、单流程、可独立访问的结构化编制工具。一份 JSON 只编制一个流程，输出是未审核成果，不是正式流程、正式数据地图或已确认主数据。
- 工作内容只存在当前页面内存。用户主动下载 JSON 是唯一持久化动作；刷新、关闭页面或服务重启后，系统不负责恢复未下载内容。
- 不新增账号、数据库、服务端草稿、自动保存、缓存目录、业务 Cookie、`localStorage`、`sessionStorage`、IndexedDB 或与 3000 的通信。
- 3001 不保存审核状态、批准标记、MDM 审核意见、图坐标或运行时界面状态。上传文件中的相似字段不能作为审核凭证。
- 新建、导入、校验、编制和下载均不依赖 3000。用户主动下载和手工上传是 3001 与 3000 之间唯一允许的业务内容传递方式。

## 版本和旧数据

- 正式模板、默认结构规则和健康检查使用当前已发布的 `process-governance-v7`。软件发布和技术测试不代表真实流程业务验收已经完成。
- 数据结构、必填字段、状态、枚举、标识、引用、Schema 摘要或导入导出格式变化时，必须发布新的 `process-governance-vN`，并在同一版本工作中处理受支持旧文件；不得继续追加同名当前修订来隐藏结构变化。
- 实施新版本前，盘点现有 JSON 和历史摘要，说明旧字段映射、无法自动迁移内容、兼容截止条件、失败处理和用户恢复方式。
- 旧文件只在用户导入后的当前页面内存中迁移。迁移不得修改源文件；导入失败或取消时，当前 JSON、候选、选择、图状态、撤销记录和可见输入均保持不变。
- 版本变更至少验证：上一受支持版本导入当前版本、当前版本导出后重新导入、重复迁移不重复生成内容、迁移失败后保住当前草稿和源文件。服务回退不得生成降级文件。
- v7 字段、枚举、引用和机器校验以 `../../docs/contracts/process-governance-v7.schema.json` 及当前 Tech-Spec 为准，不在本入口复制逐字段规则。

## 编辑安全

- 页面必须区分“未应用修改”“已经进入当前 JSON 但尚未下载的修改”和“当前内容已下载”。存在可见未应用输入时，不得显示“当前内容已下载”。
- 属性卡、关系向导、更新字段选择和网页表格中的可见输入尚未应用时，任何会隐藏、替换、重建或清空编辑上下文的操作，都必须先让用户选择“应用修改并继续”“放弃修改并继续”或“继续编辑”。页面不得静默丢失、静默应用或遗漏输入。
- 下载、新建、导入、清空和离页按“先处理未应用修改，再处理未下载修改，最后执行目标操作”的顺序处理。应用失败、校验超时、同字段冲突、对象不存在或来源已经变化时，页面保留输入并取消目标操作。
- 属性面板只提交本面板拥有的字段补丁；异步校验返回后必须重新核对候选、修订和来源。旧结果不得写入当前 JSON 或撤销记录。
- 删除数据对象、字段、关系、来源、表单、区域或表单字段前必须检查引用并显示影响。被引用内容不得删除；确认删除形成一次可撤销修改，不得静默级联。
- 数据流/生命周期切换、对象选择、展开说明、筛选、排序和普通重绘只改变呈现，不得生成业务事实、改变 JSON 或增加未下载状态。

## 证据边界

- 自动化中的 `compositionstart`、`compositionend`、`isComposing`、`keyCode 229` 和回车事件只能证明事件级保护。只有人工实际使用 Windows 中文输入法、打开候选窗、选词并继续录入，才能记录为操作系统输入法验收。
- 源码字符串、装配断言和隔离测试不能替代真实浏览器中的焦点、滚动、碰撞、溢出、控制台、存储和网络行为。
- 独立候选端口的测试和健康检查不表示正式 3001 已经启动、替换或发布；自动化和候选验证也不表示业务验收通过。
- 未实际启动服务时，不得报告 3001 正在运行。仅有端口监听时，不得报告应用可用；运行证据至少包括首页、`/api/health` 的 v7 released 状态、结构摘要和本地静态资源。

## 运行与验证入口

从本目录运行：

```powershell
npm.cmd test
npm.cmd audit --json
```

文档或协作入口变化还要从仓库根目录运行 `npm run test:codex-context`，并对本轮文件执行 `git diff --check`。只有应用行为实际变化时，才按 README 和 Tech-Spec 补充候选服务、真实浏览器、性能或人工输入法验证；本次没有启动或人工验证时必须明确标为未验证。
