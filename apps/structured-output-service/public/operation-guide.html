一步步操作说明

跟着一份流程文件，从“看懂现有内容”走到“补充后下载”。已有内容正确就继续，无需重新填写。

回到编制页面操作：打开流程后，顶部会显示“下一步：核对流程范围”。每做完一处就点“下一步”，页面会带你到对应位置；需要细看时点“这一步怎么做”。这里的上一步、下一步只翻阅说明。引导顺序不代表业务核对已经完成。

左侧四项任务分别做什么
  • 编制环节与流转：谁做什么、按什么条件流转。
  • 填写流程说明：名称、目的、范围和材料来源。
  • 整理数据与表单：对象字段、表单及取值来源。
  • 检查问题并下载：定位问题、下载未审核草稿。

先记住：“应用修改”把输入放进当前流程；“保存当前草稿”把文件下载到电脑。需要留存时一定要下载。

这次按什么顺序做

  1. 打开这次要核对的流程
  2. 说清流程从哪开始、到哪结束
  3. 核对一个环节由谁做、做什么
  4. 核对下一步和退回条件
  5. 对照实际表单，逐项看字段
  6. 补齐字段定义，再让表单引用
  7. 说明每个环节怎样使用数据
  8. 检查、下载，下次接着改

可以直接点某一步。这里的阅读顺序不会标记你的流程已经完成。

本说明在独立标签页打开。看完一步，切回原来的3001标签页操作；再回这里继续看。

操作说明 · 共8步

1. 打开这次要核对的流程

这一步只确认：我打开的是哪一条流程。

到哪里：原页面右上角 文件 → 继续已有流程

  1. 手边已有流程JSON文件时，点“文件 → 继续已有流程”，再选择这份文件。空白首页也可以点“继续已有流程”。
  2. 导入成功后，先看顶部“当前流程”的名称。历史文件如果拆出了多条流程，用下拉框明确选择本次要核对的一条。
  3. 需要确认文件来源时，点“文件 → 查看文件信息”，核对原文件名。页面列出“导入规范化差异”时，展开查看原值和当前值，再继续核对。
  4. 确实没有已有文件时，点“文件 → 新建流程”，再按第2步填写流程说明。不要为了练习清空正在核对的文件。

贯穿示例（虚构）

后文以“费用申请”为例：申请人填写费用申请单，核对人核对金额和附件。不完整时退回补充。示例只解释操作，不会自动写入你的文件，也不是本单位的业务规则。

看到什么就继续：顶部显示本次要核对的流程名称。导入已有文件后，主区域进入“编制环节与流转”，显示流程图。

没有导入成功时

按提示检查文件格式、版本或文件大小，不要清空当前内容。格式或引用问题无法判断时，把提示交给MDM工作组或工具维护人员处理；当前页面内容先保留。

2. 说清流程从哪开始、到哪结束

先划清范围，再核对里面的环节，避免把几条流程混在一起。

到哪里：左侧 填写流程说明

  1. 核对流程名称、归口部门、发起部门和编制人，按本次实际情况填写。
  2. 在“目的”和“范围”中说明为什么需要这条流程、从什么事情开始、办理到什么结果为止，必要时注明哪些工作不包含在内。
  3. 已有内容准确时直接保留。不能确认的分类先保持未归类或待确认；可选内容不需要为了填满而猜测。
  4. 回到左侧“编制环节与流转”。流程说明中的普通输入会更新当前页面的流程；如果出现未应用修改提示，先选择应用、放弃或继续编辑。

例如这样描述范围

“从申请人提交费用申请开始，到核对结果反馈给申请人为止；不包含后续付款。”这里只是虚构示例，实际结束位置由业务人员确认。

什么时候继续：同事能够根据名称、目的和范围，判断一件事是否属于这条流程。

3. 核对一个环节由谁做、做什么

先看懂一个环节，再顺着流程逐个核对。

到哪里：编制环节与流转 → 流程图 → 点一个环节 → 人员与动作

  1. 先找流程开始的位置。长流程默认使用清晰视图；“查看全图”用于核对整体路线。需要读具体环节时，在“定位节点”中按名称选择，或点“清晰检查”定位选中节点或流程起点。点“全屏检查流程图”可扩大画布，退出后仍保留阅读目标。
  2. 在右侧“人员与动作”中，核对执行主体、具体做什么、怎样算完成。对照实际做法，不只看环节名称。
  3. 需要改动时点“修改人员与动作”。写明谁处理什么、按什么顺序做、留下什么结果；已有文字正确就不改。
  4. 改好后点“应用修改”，再点“返回摘要”核对结果。点下一个环节，重复这一步。详情太挤时可点“放大详情”，看完点“恢复并排”。

把抽象描述写成能照做的动作

“核对人逐项核对申请金额与附件金额；发现差异时写明差异项目，反馈申请人补充。”完成标准可以说明“核对结果和需补充事项已经记录”。具体岗位与完成标准应以真实做法为准。

什么时候继续：每个实际办理环节都能看出由谁处理、处理什么，以及何时算完成。

只有判断，没有人实际办理的节点

判断、并行开始、并行汇合属于控制节点，只表达路线如何选择或汇合。核对、审核、批准等实际办理仍应放在业务行为中；不要为了填写执行人而给控制节点编造岗位。

4. 核对下一步和退回条件

让读者知道：正常时接着做什么，出现问题时回到哪里。

到哪里：编制环节与流转 → 流程图 → 点连接线；或在该任务中进入 环节清单 → 关系与条件

  1. 顺着箭头核对起点和终点是否正确。点连接线，在右侧查看“关系与条件”；需要调整时点“修改关系与条件”。
  2. 按真实路线选择关系类型。普通先后顺序使用顺序关系；判断后的不同去向各自写明条件；返回已经做过的环节时使用“流程内部回路”。
  3. 点“应用修改”，返回摘要，确认箭头去向和条件正确。缺少连接时点“建立关系”，明确选择起点、终点、类型和条件后完成。
  4. 回到对应环节的“条件与异常”，点“修改条件与异常”，补充真实存在的开始条件、办理时限或会签要求，再点“应用修改”。只有流程入口填写“流程如何开始”。

费用申请如何表达退回

“核对申请”是实际办理环节，其后可设“资料是否齐全”的判断节点：齐全时向后办理，不齐全时返回“补充申请”。每条路线写清自己的条件，不能只写一个笼统的“通过／不通过”而省略去向。

什么时候继续：正常路线、不同条件下的路线和退回后的继续路径都能沿箭头走通。不存在的异常或并行路线不用添加。

涉及并行或跨部门时

确实同时办理、并且要等待全部路线完成时，才使用并行开始和并行汇合。跨部门时核对实际承接人、传递内容和返回位置；其他部门的做法需要由对方确认。复杂组合可回原页面查看流程图图例或帮助中的完整治理流程。

5. 对照实际表单，逐项看字段

拿一张正在使用的表单，核对页面有没有漏掉填写项。

到哪里：整理数据与表单 → 全流程表单 → 点一张表单 → 点一个字段

  1. 选择实际使用的一张表单、台账或记录，核对名称、编号和状态。要改表单基本信息，点“修改表单信息”，改好后“应用修改”。
  2. 对照原表逐项核对显示名称、是否必填和填写说明。点击字段后可用“修改表单字段”调整这些内容；编号、必填性和业务含义都按原表及实际做法确认。
  3. 看“对象字段定义”。已有引用时点进去，核对含义和数据类型，再用“返回上一级”回到原字段。显示“尚未引用对象字段”时，按第6步补充；不要把这条提示当成字段内容已经丢失。
  4. 缺少整张表单或填写项时，从目录点“整理表单与字段”，或在表单详情点“管理关联与字段”。整张现有表单用“录入现有表单”添加，再按实际主表、明细表补充；新增字段如何引用已有定义，见第6步。
沿“元素关系引用”查看关联内容
  1. 在环节、关系、数据对象、对象字段、表单或表单字段的详情摘要中找到“元素关系引用”。“本项引用了什么”列出目标，“哪些元素引用本项”列出引用方；对象和表单的结果也包含其字段。
  2. 点击标为“本流程引用”的目标或引用方，查看对应详情；用“返回上一级”回到原处。需要辨别同名内容时，展开“查看稳定标识与引用位置”，核对标识和文件内路径。仅查看不会改写草稿；存在未应用输入时，仍须先应用、明确放弃或继续编辑。
  3. 显示“目标缺失”“标识重复”“字段归属不一致”或“外部线索，未解析”时，不提供定位按钮。点击后若提示引用位置已经变化，页面保留当前位置，请重新核对当前引用。先保留内容，回原引用入口明确修正；不要按相似名称选择另一项。找到引用目标不表示业务事实或企业映射已经确认。

先把这几个名字连起来

虚构的同一项费用申请信息
页面里的名称在这个例子里是什么
表单费用申请单：业务人员实际填写的一张单据。
表单字段单据上的“金额（元）”这一填写项。
数据对象费用申请信息：这次申请需要记录的一组信息。
对象字段“申请金额”的定义，例如“本次申请支付的金额”。表单上的金额填写项引用这份定义。

表单字段管“这张表上怎么显示、怎么填”；对象字段管“这项信息是什么意思、是什么类型”。这里编制的是流程和字段定义，不是在3001逐笔录入真实报销金额。

什么时候继续：这张表单的主表、明细表和实际填写项都能找到；哪些字段还缺定义或来源也能指出。

6. 补齐字段定义，再让表单引用

把同一项信息的含义说明一次，让实际表单指向这份定义。

先到：整理数据与表单 → 整理数据对象与关联
再回：整理表单与字段 → 选择原表单 → 字段旁的“数据关系”

  1. 先找已有定义。在数据对象目录中找这项信息所属的对象；点对象、点字段可查看定义。含义相同且确认是同一项信息时，复用已有定义；仅名称相同不能据此合并。
  2. 确实缺定义时再补。从“整理数据对象与关联”进入，明确选择已有对象；确实没有对象时点“新增数据”，填写名称和说明。属性修改出现“应用修改”按钮时，先应用。
  3. 在所选对象下方的“对象字段正式定义入口”点“添加对象字段”，填写对象字段名称、数据类型和业务定义。已有定义需要调整时，也在这里核对后修改；这会影响引用它的表单，请先确认影响。
  4. 给已有表单字段补引用。回“整理数据与表单 → 整理表单与字段”，选择原表单，找到原来的字段，点其“数据关系”。在“引用对象字段”中明确选择刚才的定义，不要为同一个已有填写项再新增一行。
  5. 新增填写项时：在表单整理区点“选择并批量引用对象字段”，勾选所需字段，选择目标主表或明细表，逐项明确是否必填，再点“引用所选…个字段”。随后核对表单显示名称和填写说明。

同一项信息，两处不同的名称

数据对象“费用申请信息”下定义“申请金额”；费用申请单上的显示名称仍可以是“金额（元）”。选择引用后，页面能够找到“费用申请信息 / 申请金额”，不需要再抄一份业务定义。

什么时候继续：回到表单字段详情，可以沿“对象字段定义”进入正确的对象和字段。没有依据的定义先向业务人员核实，不因提示而编造。

按钮灰色、列表为空或暂时不能确认

“选择并批量引用对象字段”不可用时，先确认是否已经建立对象字段。列表中找不到字段时，回去确认定义建在哪个对象下。原表确实有填写项但定义暂时无法确认，可用“添加空白字段（待补引用）”保留表单现状，并继续保留待补状态。

7. 说明每个环节怎样使用数据

V8 候选支持判断节点的“使用”关系。例如，“是否具备测量软件验证合格证明”可使用“软件合格证明”作为判断依据，无需新增重复核对步骤。创建、更新和待确认操作应关联实际执行步骤；判断依据不会改变证明内容、状态或流程分支。操作不合法时保留输入，按提示修正；仍可按原规则下载草稿。

把“谁做了什么”与“这一步用了什么、改了什么”连起来。

到哪里：编制环节与流转 → 流程图 → 选环节 → 数据与表单

  1. 先看该环节已关联的数据和表单，以及括号中的操作方式。对照实际做法确认本环节是创建信息、更新信息，还是使用已有信息；已有关系正确时保留。
  2. 缺少数据关系时，点“补充数据与表单关联”，明确选择数据对象，点“建立数据关系”，选择真实办理环节和操作方式后应用。选择“更新”时，还需从该对象已有字段中选择本次更新哪些字段。
  3. 缺少表单处理关系时，到“整理数据与表单 → 整理表单与字段”，选择表单，点“添加表单处理关系”，明确选择办理环节及实际处理方式，再点“应用新增关系”。
  4. 需要说明字段的值从哪里来时，在表单字段旁点“数据关系”，核对“字段值使用方式”“取值方式”和来源。沿用已有值、系统计算、外部取得等选择，必须有真实做法支持；不确定就保持待确认。
  5. 核对生命周期时，到“整理数据与表单 → 整理数据对象与关联”，选择对象后点击“生命周期”。主状态为“待确认”也可以展开“查看或维护已记录的生命周期明细”，直接核对入口的使用、保管和匿名处理状态。无需先把主状态改成“会改变”；没有依据的判断仍保持待确认。
  6. 回到原环节，检查关联摘要是否符合实际。目录里暂未关联的对象也逐项看一遍：确实要用的补关系，是否使用还不清楚的先核实，不要直接删除。

同一张费用申请单，在不同环节作用不同

申请人填写申请单；核对人查看已有金额和附件。只有实际修改了信息时才登记“更新”。“能看到这张表”不能直接推断为“创建这份数据”，重复引用也不能推断为权威来源。

什么时候继续：能从一个环节找到它实际使用的数据和表单，并说明该环节对信息做了什么。确实不涉及数据或表单时保持为空。

如何看取值来源和外部来源线索

表单字段详情的“取值来源”只读展示已有记录；外部系统来源显示系统名称、来源数据和来源作用，尚未绑定企业系统或数据版本。数据对象详情的“外部来源线索”显示已记录的部门、流程、环节和数据名称。这些文字不会自动生成本地引用；没有线索也不表示已确认由本流程创建。需要补充或修正时，回“整理数据与表单”的原整理入口，按实际做法修改；出现未应用修改时按提示明确处理，最后下载留存。

8. 检查、下载，下次接着改

把当前修改真正留在电脑上，并知道哪些事项还需业务确认。

到哪里：检查本轮；左侧 检查问题并下载；顶部 保存当前草稿

  1. 在编制过程中点“检查本轮”，逐条查看提示；能定位的问题点进去修正，修正后重新检查。不能确认的业务事实继续留待核实，页面检查不替代业务确认。
  2. 进入“检查问题并下载”，核对六方面提示。涉及跨部门时，从“返回跨部门事实核对”查看交接，由相关部门确认本方做法；发现问题再返回对应环节、关系或字段修改。这里不会保存正式部门确认记录。
  3. 随时需要暂存本轮工作，点顶部“保存当前草稿”；准备交接当前成果时，点“下载最终待核对文件”。如果出现未应用修改提示，先选择“应用修改并继续”“放弃修改并继续”或“继续编辑”。
  4. 确认浏览器实际下载了JSON文件。结构错误、损坏引用和业务提示都不阻止先保留草稿；下载保留当前原值，不会自动修正问题，交接前仍需逐项处理。
  5. 核对完成后，可通过“文件”的导入入口重新打开刚下载的文件，检查关键内容；以后继续编制也导入这份文件。若下载后又有新修改，先再次下载留存，再替换或关闭页面。

三个状态对应三件事

有未应用修改
输入仍在当前编辑区，尚未进入流程。先应用，或明确放弃。
有未下载修改
内容已进入当前流程，但电脑上的下载文件还没有这些修改。
当前内容已下载
页面已执行下载。再看浏览器下载记录，确认拿到了实际文件。

这轮可以结束的标志：电脑上有本轮下载的文件，关键修改重新导入后仍在，尚未确认的业务事项也清楚。下载文件仍是未审核成果。

常见卡点：输入、批量编辑和下载
  • 要保留输入继续修改，选“继续编辑”；要带着修改去下一处，选“应用修改并继续”；只有确定不要这些输入时才选放弃。
  • 批量表格需要点“应用本次修改”。提示应用失败时保留原输入，处理错误后再应用。
  • 普通逐项输入不一定有单独的应用按钮，应看顶部状态；“有未下载修改”仍需要下载，不代表已保存到电脑。
  • 当前草稿在浏览器内下载，不依赖检查接口。服务暂时不可用时仍可先下载留存，不要用刷新或关闭页面来尝试恢复未下载内容。
标有“预览”的按钮是什么意思

“解析跨流程引用”“企业对象与字段映射”“企业元素目录”“映射变更重检”“跨部门核对”“审核与发布”“数据治理工作包”目前只展示能力位置与说明，按钮禁用。它们不会读取3000企业目录、提交映射、记录确认、发起审核发布或生成治理工作包。

表单字段中的“字段自动带值与控制”、生命周期中的“执行归档与销毁”和流程图工具栏中的“流程图阅读演示”同样为禁用预览。当前页面不会自动填值，不执行真实归档或销毁，也不播放逐步流程动画；流程图仍可静态查看、选择和定位。

3001与3000复用结构及引用检查规则，但本页面不连接3000或共享数据库。需要交接时，由你下载未审核JSON并手工上传3000。3001当前候选输出V8；3000源码具备V8接收路径，但不能由此判断正式服务是否已经开放。3000的已发布版本企业映射来源和数据治理工作包目前仍限定V7，不能把V8草稿当成已具备这些治理能力的正式版本。
