# 3001 单流程治理编制工具

3001是无状态、以图为主的单流程编制工具。当前默认结构版本为`process-governance-v6`，结构规则见`../../docs/contracts/process-governance-v6.schema.json`。

## 当前边界

- 所有业务内容只保存在当前页面内存中；下载JSON是唯一保存方式。
- 刷新、关闭页面或服务重启后不恢复草稿。存在未导出修改时，页面先提示。
- 不增加账号、数据库、自动保存或浏览器持久化。
- 不调用3000。v6文件暂不能直接导入3000，也不会自动降级。
- MDM-AI助手继续使用v5，本次没有修改或测试该应用。
- 页面不提供手机布局。目标电脑物理屏幕分辨率不低于1920×1080，页面适配1280像素及以上的浏览器内容可视区。

## 默认操作路径

1. 新建或导入。
2. 在“流程关系”中编辑普通行为、控制节点和流程关系。
3. 在“数据关系”中围绕一个数据对象编辑直接关系。
4. 在“文字编制”中补充详细字段和表单。
5. 在“流程评审”中执行现场核对。
6. 处理结构阻断并导出。

流程关系图、数据关系图、属性面板和文字编制共同读写一份页面内存草稿。两个完整图不会同时展开；页面同时只保留一个活动选择和一个属性面板。

## v6结构

v6根对象固定包含：

- `schema_version`
- `export_meta`
- `process`
- `behaviors[]`
- `flow_relations[]`
- `data_objects[]`
- `forms[]`
- `terms[]`
- `migration`

普通行为和控制节点统一保存在`behaviors[]`。流程关系保存在`flow_relations[]`；数据对象与行为的创建、更新、使用和待确认关系保存在`data_objects[].behavior_links[]`。图坐标、缩放、视口、选择和评审结果都不写入JSON。

`migration`保存首次来源和只读历史归档。旧交接、参考材料、内部流程调用、工作角色、无法解析的执行主体和无法确定的汇合方式不参与当前评分、流程计算或绘图，但引用仍受保护。

## 兼容迁移

3001可以导入v1至v6以及`document-structured-output-v2`多候选文件。迁移遵循以下顺序：

1. 按来源版本执行纯校验。
2. 在深拷贝上执行确定性迁移。
3. 按v6规则校验全部候选。
4. 全部成功后一次替换当前页面内容。

迁移不修改源文件，不记录动态迁移时间。失败或取消时，当前草稿、图状态、撤销记录和源文件保持不变。v6重新导入时保留首次来源信息；旧版迁移成功后标记为未导出。

## 两种图模式

### 流程关系

- 普通行为按执行部门进入泳道。
- 判断、并行开始和并行汇合进入顶部“流程控制”显示带。
- 建立关系固定为选择类型、选择起点、选择终点、确认四步。
- 一对多和多对一使用多条独立关系。
- 自环、端点不存在和完全重复关系阻止写入；节点类型不匹配、条件缺失、普通行为直接一对多和非回路闭环只提示。
- 普通行为最多显示一个数据徽标和一个表单徽标。徽标只用于跳转，不写入JSON。

### 数据关系

- 当前数据对象位于中心，只显示直接关联行为。
- 行为是只读端点，可以跳转到流程关系模式。
- 同一数据对象和行为的多个操作在图上合并为一条线，JSON仍保留独立记录和未变化的`link_ref`。
- 待确认操作不能与已确认操作并存。历史多个创建行为保留并提示，不自动选择。
- 同名数据只在去除首尾空白后名称完全相同时允许人工归并。归并先预览影响，在副本上校验后一次替换，并可撤销。

## 编辑安全

- 每个候选流程独立保留最近20次图操作。流程关系和数据关系共享当前候选的撤销、重做记录。
- 图命令先在草稿副本上检查标识、引用、端点、冲突和删除依赖，通过后一次替换草稿。
- 删除不级联。被流程关系、数据关系、表单、动态执行主体、字段来源或迁移归档引用的对象不得删除。
- 图坐标由确定性布局计算，不允许自由拖动摆位。
- 图模块故障时，文字编制、导入、校验和导出仍可使用。

## 校验与提示

结构错误、非法枚举、重复技术标识、断裂引用和往返丢失阻止导出。业务缺项只提示。

页面把提示分为五层：本次操作反馈、当前对象待补内容、迁移摘要、导出阻断和流程评审意见。流程评审使用`process-review-readiness-v6`；结构化学习评分使用`structure-learning-score-v3`，页面显示“结构化学习评分 v3（process-governance-v6）”。二者均不代表正式评审通过。

流程评审包含一对多和多对一对照图例，并固定提示：“仅用于理解关系，不属于当前流程，不代表评审通过。”

## 接口

- `GET /api/health`：服务状态、端口、Git提交、当前结构版本和摘要。
- `GET /api/schema?version=...`：v1至v6或历史结构化规则；默认v6。
- `GET /api/template?version=process-governance-v6`：空白v6模板。
- `POST /api/validate`：按输入版本纯校验，不迁移、不补字段、不改变输入语义。
- `GET /api/version-history`：只读版本历史。
- `GET /api/enums`：部门、岗位和字段类型等受控选项。

服务不提供用户内容保存、读取或导出接口。

## 运行与验证

```powershell
cd E:\CA001\Infomat\apps\structured-output-service
npm.cmd install
npm.cmd test
npm.cmd start
```

默认监听`0.0.0.0:3001`。健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:3001/api/health
```

响应中的`status`应为`ok`，`schema_version`应为`process-governance-v6`。

自动测试覆盖v1至v5和历史多候选迁移、v6往返、纯校验、归档保护、关系规则、同名归并、撤销重做、候选隔离、删除保护、40节点布局碰撞和性能基线。页面变化还必须用真实浏览器覆盖1920×1080、1536×864和1280×720内容可视区。
