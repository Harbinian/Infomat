# 文档结构化输出辅助服务

> 状态：本地辅助工具  
> 端口：`3001`  
> 主责资产：`docs/contracts/document-structured-output.schema.json`

本服务用于把 Word、TXT 或 Markdown 制度文件整理到 `document-structured-output-v2` 结构化输出编辑页，供用户直接修改并导出结构化文件。它不替代 MDM 平台、流程输入基线或组织真源，也不反向写入 `docs/norms/`。

## 运行

```powershell
npm install
npm start
```

默认地址为 `http://127.0.0.1:3001`。需要隔离端口时：

```powershell
$env:STRUCTURED_OUTPUT_PORT='3101'
npm start
```

## 数据边界

- 输入：`.docx`、`.txt`、`.md` 制度文件，或页面导入的结构化文件；页面支持按钮选择和拖入文件。
- 输出：当前页面中的结构化内容，以及用户主动下载的 `document-structured-output-v2` JSON 结构化文件。普通 v2 文件可在 MDM 平台 3000 端口导入；第一里程碑期间，顶层或结构块投影含非空 `work_role_bindings` 的文件都会被 3000 以 `422 WORK_ROLE_BINDINGS_UNSUPPORTED` 明确拒绝，避免静默丢字段。
- 存储：服务端不保存用户上传原文或结构化结果；浏览器不做自动恢复；刷新或关闭页面后当前内容清空。
- 真源：结构化字段以 `../../docs/contracts/document-structured-output.schema.json` 为准。
- 原文称谓：业务行为的 `actor_role` 在页面显示为“制度原文中的角色/岗位称谓”，始终保留原文；花名册岗位不会覆盖原文。流程草拟期可在独立的 `source_position_name` 中按“部门 + 岗位”记录当前参与岗位，该记录不等于正式工作角色。
- 工作角色目录：只读 `../../docs/work-role-data.json`。目录由行政人事部受控发布；为空时原文抽取、证据和待确认问题仍正常工作，用户可以先选择花名册岗位和参与方式形成 `proposed` 记录，流程固化后再选择正式工作角色。
- 页面建议：上传先完成页面填充，随后在后台调用 DeepSeek 结合制度全文生成非枚举空字段填报建议；建议只存在当前页面，不进入导出的结构化文件。
- 禁止：不得把本服务输出直接写回 `docs/norms/`；不得自动发布为已确认流程映射。

## 使用口径

- 页面按钮使用“导入制度文件”“导入结构化文件”“导出结构化文件”。
- 页面顶部说明“Deepseek-V4-Pro 1M上下文模型辅助生成”。
- 与 MDM 联调时，3001 只负责本地整理和导出 JSON；3000 导入时读取用户选择的 JSON 文件，不反向调用 3001 服务。
- 除指定的辅助生成说明外，用户界面不展示内部字段名、模型参数、schema、多个建议值、置信度或待确认问题。
- 页面视觉跟随 MDM 的暖宣纸系配色，保持低亮度、低噪音和高密度编辑。
- 目的、适用范围、术语定义优先按标准模板章节原文填充。
- Word 术语定义优先按表格列识别；即使术语表包含“序号”列，也只取“术语/术语名称”和“定义”列，不把序号或“定义”表头当成术语。
- 制度编号、制度名称、版次和归口部门按标准 Word 表头读取；归口部门在页面中允许用户下拉选择。
- 导入制度文件后，页面必须立即显示持续可见的整理中提示；页面填充完成后先恢复编辑，填报建议在后台补充，并提示用户可以先检查和修改页面内容。
- 流程映射只读消费 `docs/norms/*映射关系.md`，按制度编号、标题、上传来源线索或正文表单编号片段匹配底层字段；页面沿用映射表中的“能力域、业务能力、业务流程”等来源列名，不额外创造归类名称。
- “能力域”和“业务能力”是流程映射来源值，只读展示并可查看依据，不作为用户手填字段；未匹配时显示未匹配状态，由用户回到来源文件或映射基线核对。
- 流程正文只按明确可执行内容整理为业务行为；常见“工作程序”“申请流程”“操作流程”“审批流程”“核心流程及要求”等章节会纳入整理，“下列/包括”类触发条件清单不进入业务行为。态度、原则、倡导和泛化要求不进入业务行为。填表动作会去掉时限和“附表1”等附件编号，保留“填写《表单名称》”。图片流程图、Visio 和截图不进入自动整理链路。
- 流程章节中如果已成组填写“行为N、执行角色、触发场景、前置条件、输入/输入材料、输出/输出结果、执行标准”，3001 优先直接读取这些字段，并为每个字段保留对应原文依据。该流程章节的邻近正文和“输出：……”等字段行不再重复生成步骤；源文中的重复行为名、错字或角色内容保持原样，由用户在页面核对。
- 同级流程章节会拆成多条流程；有映射时流程名采用“映射业务流程 - 章节名”，无映射时采用章节名，重复章节名自动追加序号。系统不会自动识别判断节点，判断节点只来自用户人工新增或 v2 结构化文件导入。
- 每条流程可以新增业务行为、判断节点和判断分支。判断节点使用与业务行为相同的字段填报；判断分支保存到 `step_transitions[]`，只允许同一流程内连接，`to_step_ref` 可为空用于保留未补流向。
- 流程步骤采用“左侧步骤清单 + 右侧当前步骤编辑”工作台。大批量导入时只展开当前选择的一项；清单可以查看全部、待补、疑似重复和已完成步骤，并跳到下一项待补内容。疑似重复按同名步骤提示人工核对，不自动删除或合并。
- 当前步骤按“何时触发、开始前有什么、谁来做、具体做什么、办理时限、怎样算完成、最终交付什么”的业务顺序填写；已有 `timing` 办理时限字段在页面可编辑并随结构化文件无损往返。
- 整条流程可以随时折叠。折叠摘要显示步骤数、待补数、疑似重复数、判断节点数、分支数和未补流向数；折叠状态只属于当前页面，不写入导出文件。
- 触发场景、前置条件、输入材料、输出结果、执行标准采用字段级词库和句式识别：收到/发现/发生等事件进入触发场景，经审核/批准/确认后等句式进入前置条件，提交/提供/随附/填写等句式抽取输入材料，形成/出具/反馈/归档/保存等句式抽取输出结果，在 N 个工作日内、必须/不得/按要求、保存材料等句式进入执行标准。原文未写清的角色、输入、输出、触发和前置条件留空。
- 原文明写的评价维度、标准或规则进入业务行为的执行标准；填表动作优先推荐按对应表单的填表说明执行，并提示继续完善具体填写标准。
- 制度原文中的角色/岗位称谓使用普通文本编辑，多角色文本保留完整原文；花名册候选只提示可能相关岗位，不自动拆分或确认。
- 每个 L3 可先记录一个负责人岗位，每个 A1 可添加多个参与岗位并分别选择参与部门和参与方式；流程固化后再把岗位参与关系归并为正式工作角色。岗位与流程角色是多对多关系，不自动一对一改名。自动抽取、岗位选择及同名匹配最多形成 `proposed`；正式确认还需有效 `WR-*`、岗位映射、可定位证据和业务部门确认依据。
- 用户将绑定改为“已确认”时，页面会把已选择且可定位的非 OCR 原文依据标记为 `verified`；因此应先核对依据位置和原文摘录。OCR 或待复核证据不能形成正式绑定。
- 申请人、当前处理人、全体员工等场景身份，客户、供应商、银行等外部参与方，以及未拆清的集体称谓，只保留原文证据和“角色责任待确认”，不建立正式绑定。
- 非枚举空白字段在原位置显示填报建议，提示用户按制度原文补充什么；DeepSeek 建议优先展示，有逐字匹配依据时可折叠查看参考原文；建议只用于页面编辑，不写入导出的结构化文件。工作角色、参与方式和部门等枚举字段不显示填报建议。
- 表单与记录按 3000 结构化输出合同组织，覆盖表单编号、主表名称、形成部门或填写角色、归档位置、保管期限、具体表头和表格字段；填写角色通过当前表单形成部门和花名册职务选择，形成部门为空时回退制度归口部门；Word 中嵌在主表里的“名单/明细清单”会识别为明细表；用户先选择具体表单，再选择具体表，可新增表、编辑表头名称，并在当前表内录入字段。
- 主数据对象和跨部门流转字段保留在导出的结构化文件中，供后续承接；当前页面不提供这两类内容的独立编辑区。
- DeepSeek 用作受控抽取器和非枚举空字段填报建议辅助；抽取值必须带原文依据，且依据不能在解析文本中逐字匹配时丢弃。
- DeepSeek 配置优先读取本服务显式环境变量：`STRUCTURED_OUTPUT_DEEPSEEK_ENABLED=1`、`DEEPSEEK_API_KEY`、`DEEPSEEK_API_URL`、`DEEPSEEK_MODEL`。如果未显式配置，本服务会读取 CC Switch 写入的 Claude 配置：`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL`、`ANTHROPIC_MODEL`，并在地址或模型指向 DeepSeek 时按 Anthropic 兼容接口调用。读取过程不写回配置，也不保存用户内容。
- DeepSeek 辅助建议有单次超时、总时限、建议专用重试、短时熔断、分批请求和降级保护；不可用、慢响应或返回不合规时页面继续显示通用填报建议，不向用户暴露技术状态。分批只用于提升返回格式稳定性，不截断空字段清单。
- 建议生成可通过 `STRUCTURED_OUTPUT_DEEPSEEK_SUGGESTION_TIMEOUT_MS`、`STRUCTURED_OUTPUT_DEEPSEEK_SUGGESTION_TOTAL_MS`、`STRUCTURED_OUTPUT_DEEPSEEK_SUGGESTION_MAX_RETRIES`、`STRUCTURED_OUTPUT_DEEPSEEK_SUGGESTION_BATCH_SIZE` 调整；默认优先保护页面可编辑和响应可控。
- `/api/health` 仅返回 DeepSeek 是否已配置、最近是否可用和失败分类，不暴露密钥、用户原文、建议内容或上传文件名。

## 验证

```powershell
npm test
```

测试会启动隔离端口，校验：

- 服务不写死 3001。
- 上传制度样例能按模板章节填充目的、范围、术语、流程步骤、表单和字段。
- 指定 Word 模板样例能正确读取表头、术语明细表、流程映射、业务行为、填表执行标准、附件主表和嵌套明细表字段。
- 指定 `docs/norms` 真实制度样例覆盖“工作程序”“申请流程”“核心流程及要求”等章节标题，以及触发场景、前置条件、输入材料、输出结果、执行标准五类字段级词库。
- 结构化合同固定为 `document-structured-output-v2`，覆盖 v1 文件拒绝、v2 导入导出、多流程拆分、人工判断节点、判断分支、跨流程流向清理、流程级折叠摘要和 `work_role_bindings` 无损往返。
- 流程步骤工作台覆盖大批量步骤的单项编辑、完成状态筛选、同名重复提示、下一项待补导航、办理时限编辑，以及步骤移动/删除后的字段依据对齐。
- 业务流程闭环覆盖制度上传抽取、多流程拆分、流程级执行角色、公司领导角色、跨部门承接流程、同流程判断分支、表单填写角色和导出后重新导入一致性。
- 显式业务行为块回归覆盖“行为N”优先级、七类字段直接写入、部门-岗位连字符规范、逐字段依据和邻近正文不重复拆步。
- 原文角色必须生成可定位证据和角色责任待确认；花名册精确同名只能产生候选，不能自动确认，外部角色、场景身份、集体称谓和多角色链不得被强行映射。
- 服务端不保存上传原文或结构化结果，健康检查不暴露用户会话数量、密钥、用户原文、建议内容或上传文件名。
- DeepSeek 建议 mock 覆盖成功、依据不匹配、429、慢响应总时限、熔断、分批请求和恢复；CC Switch / Anthropic 兼容接口使用本地假服务覆盖；真实 API 不进入自动测试。
- GBK/GB18030 文本上传不会变成乱码。
- 前端页面使用业务口径，提供 MDM 风格配色、必填星号、红绿饼图、导入等待提示、依据折叠、按流程/表单局部部门隔离的角色选择、DeepSeek 空白字段填报建议、按表单和具体表切换的表头及字段表格编辑、文件拖入、结构化文件导入导出和刷新提醒。
