# 3001 单流程治理编制工具

> 状态：局域网无状态临时工具
> 端口：`3001`
> 导出结构规则：`docs/contracts/process-governance-v3.schema.json`

3001用于编制一条流程。用户可以直接新建，也可以导入现行或历史结构化JSON继续整理。页面中的内容只存在于当前浏览器运行内存；用户主动导出的JSON是唯一保存结果。

页面顶部只显示工具名称、用途和操作入口，不重复展示模型停用、系统通信或线下审核边界的通用声明。相关边界仍按本README和目录`AGENTS.md`执行。

## 运行

```powershell
npm install
npm start
```

服务启动后，局域网用户访问`http://<服务器局域网IP>:3001`。服务器维护人员也可以使用`http://127.0.0.1:3001`检查本机服务。需要隔离监听地址或端口时：

```powershell
$env:STRUCTURED_OUTPUT_HOST='127.0.0.1'
$env:STRUCTURED_OUTPUT_PORT='3101'
npm start
```

服务默认监听`0.0.0.0:3001`，公司局域网用户无需DeepSeek、MDM-AI助手或认证网关即可直接使用。不得把3001映射到公网；部署主机应通过公司网络边界和防火墙限制访问来源。

## 用户操作

1. 点击“新建流程”，或导入`.json`结构化文件。
2. 在“文字编制”中依次切换“基本信息、目的与范围、术语定义、流程步骤、表单与记录、导出检查”，一次只处理一个工作区。业务行为、流程关系、输出物与数据、跨部门承接均在左侧侧栏选择和上移／下移条目，右侧一次只编辑当前条目；移动端的条目侧栏位于编辑区上方并可横向滚动。
3. 填写业务行为或节点名称；需要补充实际操作时，在“具体做什么（补充说明，可选）”中说明。随后选择执行部门和花名册岗位，填写流程关系和输出数据。需要跨部门协同时，在当前业务行为卡片中分别选择“登记本行为开始前需要外部门提供的输入”或“登记本行为完成后需要外部门承接的事项”。每个外部门形成一条承接关系；责任部门暂时未知时选择“待在MDM平台明确责任部门”，不得猜测部门、流程或行为。顺序调整只交换对应数组中的完整对象，不重新生成技术标识，也不改写其他对象对业务行为、数据或承接的引用。普通编制页面不要求新增正式工作角色。
4. 填写至少一个业务行为名称后，切换到“跨职能流程图预览”核对责任部门和流程关系。导入包含业务行为的文件时，页面会自动打开预览。
5. 进入“导出检查”，查看结构完整性、展示分、等级、六项维度得分和可点击整改项；需要时展开“查看评分标准”。评分和提示项下方同时说明业务评审后的MDM平台接收步骤，并预告后续系统动力学评价。
6. 导出当前流程。文件名统一为`未审核-发起部门-流程名称-导出时间.json`。
7. 业务评审完成后，把导出的未审核JSON交给归口部门MDM审核员。
8. 归口部门MDM审核员在MDM平台选择“预览并审核导入3001文件”，核对流程内容并填写审核依据。MDM平台复核文件内容未变化后写入流程草稿，并把跨部门承接关系转换为有责任范围和处理状态的承接待办。

3001不提交审核、不记录审核结果，也不与MDM平台通信。“导出检查”中的两张卡片只说明后续处理路径和规划方向，不提供跳转、上传或状态写入。系统动力学评价尚未上线，不属于当前结构化学习评分。

## 结构化学习评分 v1（试行）

“导出检查”自动计算两个分数：

- 结构完整性：六个结构维度得分之和，满分100分。
- 展示分：结构完整性乘以有效行为链系数，用于本期结构化学习成果展示。

六个维度为：

| 维度 | 分值 | 检查内容 |
|---|---:|---|
| 技术结构 | 15 | JSON解析、当前版本兼容、结构规则及技术引用、导出回读、内容与引用保持 |
| 基础信息 | 10 | 发起部门、编制人、流程名称、归口部门、目的、范围 |
| 业务行为 | 25 | 节点类型、名称、执行岗位、触发或前置、输出结果、完成标准 |
| 行为关系 | 20 | 关系字段、节点覆盖、判断出口、回路条件、并行结构 |
| 数据与承接 | 20 | 数据对象15分，跨部门承接5分 |
| 表单结构 | 10 | 表单名称、唯一主表、区域结构、填写项结构 |

有效行为链长度为0—1、2、3、4、5个及以上时，展示系数分别为0.80、0.85、0.90、0.95和1.00。显式流程内部回路不重复计数，孤立行为不增加最长有效链。展示分达到90、75、60时，等级分别进入A、B、C；低于60为D。当前文件发生技术阻断时，展示分最高为59分。

判断节点可以使用一条无条件顺序关系作为默认继续路径。判断分支和流程内部回路必须填写条件；承接判断结果的后续节点仍可以是普通业务行为。评分不判断条件是否互斥，也不判断流程设计、部门职责或业务事实是否正确。

必填项使用“待填写、待补充、待确认、未知、暂无、无、不适用、N/A”时，按未完成处理；选填项可以留空或使用占位说明。无数据对象时，数据对象子项为0/15；无表单时，表单结构维度为0/10；无跨部门承接时，承接子项按不适用计5/5。不要为提高分数虚构数据、表单、行为或关系。

每条已登记承接关系只检查五项结构信息，每项1分：承接方向、本流程有效锚点、外部门或“待在MDM平台明确责任部门”、传递数据或承接事项、触发条件或完成标准。外部门流程、外部门行为、是否确认承接、返回路径、证明材料以及前置输入实际属于哪条外部流程，都不扣当前编制人的结构分；缺口只形成治理提示。

“具体做什么”、输入说明和办理时限等字段本期不计分。页面会把相关内容标为后续集中评审预告。

评分结果只存在当前页面，不写入导出JSON，也不改变候选流程的未导出状态。校验服务不可用或前后端版本不一致时，页面暂停生成最终分数；服务恢复后点击“重新评分”。这种运行异常不会形成用户扣分。

本评分只反映当前JSON展示出的结构化学习成果，不是正式PMO评审规则，不代表流程设计正确、部门职责正确或业务事实已经确认。

### 顺序、判断分支和流程内部回路怎么选

“流程步骤—流程关系”顶部常驻显示以下说明；没有流程关系或存在多条流程关系时，说明都只显示一次：

- 顺序：当前节点完成后，默认进入下一业务行为。判断节点可以用一条顺序关系表示默认继续路径，不需要填写条件，但必须填写要去的业务行为。
- 判断分支：需要按某个明确判断结果进入后续步骤时使用。需要填写判断条件和要去的步骤。
- 流程内部回路：因为审核不通过、材料有误等原因，退回本流程前面已经存在的步骤重新处理。需要填写退回条件和退回位置。

承接顺序或判断分支的后续节点仍可以是普通业务行为。该节点只有在自身还需要继续判断时，才选择“判断节点”。流程内部回路是一条返回关系，不是一个新节点，也不需要另外创建“回路节点”。

例：部门负责人审核报销单。审核通过 → 使用顺序关系进入财务复核；审核不通过 → 使用流程内部回路退回申请人补充材料。财务复核仍是普通业务行为。

“关系类型”下方同时提示：默认继续下一步选择“顺序”；按明确判断结果进入后续步骤选择“判断分支”；需要退回前面步骤重新处理，选择“流程内部回路”。桌面端三类说明并列显示，移动端上下排列。

## 跨职能流程图预览

- “文字编制”和“跨职能流程图预览”互斥显示，图形不会长期占用文字表单面积。新建空白流程默认打开文字编制；导入包含已命名业务行为的JSON或历史候选后，页面自动打开预览。
- 预览采用BPMN 2.0.2的最小图形子集，但页面继续使用业务语言。画布上方始终显示业务行为、判断、并行、流程关系、跨部门承接、内部流程调用和类型待判断七类图例，并可展开三步读图示例。
- 每个执行部门形成一条横向泳道。归口部门在已参与执行时排在最上方，其他部门按组织目录顺序排列；节点第二行显示执行岗位。无法识别部门的历史执行值进入“执行部门待明确”泳道，原值保持不变。
- 业务行为使用圆角矩形，判断使用带“×”菱形，并行拆分或汇合使用带“＋”菱形，未选择节点类型时使用虚线矩形。会签只在对应节点右上角显示“会签×N”，完整部门清单仍在文字编制中查看。
- 本流程关系使用实线实心箭头，判断条件直接写在箭头上，回路使用带“回路”文字的实线回返箭头。图例旁固定提示：“带条件的前进箭头表示判断分支；标有‘回路’的返回箭头表示退回前序步骤。”只有关系类型、起点和终点都明确且引用有效时才绘制箭头；没有关系的行为保持孤立，3001不会按录入顺序推测先后。
- 节点名称、岗位和关系条件按中文字符自动换行并完整显示，不做省略。节点会按文字行数增高，判断和并行菱形同步扩大；相邻层级会为节点和关系标签保留安全间距。
- 单一相邻顺序关系继续使用直角连线。多个判断分支和跨层关系使用上方独立轨道；“流程内部回路”使用下方独立轨道。同一目标存在多条回路时，各关系的线路、标签和点击区域分别外扩。
- “判断节点”负责表达条件判断，“流程内部回路”负责表达在某个条件下返回本流程前序行为。回路是从当前节点发出的关系，不是必须另建在判断节点之后的节点；例如“不批准时退回、批准后继续或发起跨部门承接”分别构成判断节点的两个出口。
- 如果判断分支、顺序或并行关系与其他非回路关系形成闭环，预览下方显示“关系类型请核对”。该提示不阻止导出，也不会自动改关系类型；如果业务含义确为退回前序行为，编制人应在文字编制中选择“流程内部回路”。
- 跨部门承接显示在泳道区域外，使用虚线空心箭头连接。前置输入按“外部门承接卡片 → 本流程行为”绘制；后续承接按“本流程行为 → 外部门承接卡片”绘制，有返回要求时再连接本流程恢复行为。卡片缺失值统一显示“待明确”。历史内部流程调用在调用部门泳道内显示为粗边框节点，点击后提示由MDM平台正式功能维护。
- 主图不显示数据对象、表单、完整会签部门、流程阶段或推测的开始和结束事件。用户可以平移、缩放、适应画布、重置视图、展开查看或点击图形定位文字卡片，但不能拖动节点、增删图形或连接箭头。完整画布拟合比例不低于0.60时默认显示全图；更大的流程默认聚焦泳道表头和前两层节点，并显示查看全图提示。“适应画布”显示全部内容，“重置视图”恢复自适应默认视野。
- 图例展开状态、预览展开状态和计算坐标只存在当前页面内存，不写入JSON。图形加载失败时，文字内容、导入和导出功能继续可用。

## 新建规则

- 一份JSON只对应一个流程。
- 页面通过`/api/template?version=process-governance-v3`读取服务端空白模板，不在前端维护第二份结构定义。v1、v2只作为兼容导入版本。
- 新建时不自动生成流程名称、制度编号、业务行为或判断节点。
- 新增节点类型默认留空，由编制人选择业务行为、判断节点、并行分支或并行汇合。
- 制度名称、制度编号和正式制度关联不是本阶段的前置条件。
- 能力域和业务能力可以不填，不阻止草稿导出或PMO审核。
- 页面暂不要求用户提供编制参考材料。新建流程仍按结构规则导出`reference_materials: []`。

## 纸质表单字段录入

- “录入现有表单”和“设计新建／优化表单”分别创建现状表单和拟设计表单；空白流程不会自动生成表单。
- 右侧一次展示整张表单的字段。用户逐字段选择主表或具体明细表；选择“新建明细表”时，页面只在当前内存和导出JSON中建立分组，不创建数据库表。
- 主表不填写标题。明细表标题按纸质单据填写；没有标题时页面显示顺序占位，但不把猜测名称写入JSON。
- 字段和明细表支持排序。字段改变归属时保留完整对象和`item_ref`；删除明细表前显示字段数量，取消删除不修改当前内容，空明细表不自动删除。
- 多张明细表本身不是问题。表单状态、字段归属或多张明细表的区分标题未确认时，导出检查逐项提示并定位到对应控件。

## 执行岗位和工作角色

- “业务行为或节点名称”是流程节点的主内容，用于流程图、流程关系和工作角色绑定。“具体做什么”是可选补充说明，只用于解释实际操作，帮助PMO和部门业务人员沟通。
- `behavior_name`保存业务行为或节点名称，`behavior_description`保存“具体做什么”。补充说明不替代名称，不显示在流程图节点上，留空时不阻止草稿导出。
- 执行岗位来自仓库中的`docs/organization/花名册.md`。3001通过本服务的`/api/enums`只读取得岗位，不调用MDM平台接口、数据库或会话。
- 执行部门可以选择组织目录中的任一部门。选择流程归口部门表示本部门执行；选择其他部门表示跨部门执行。
- 执行岗位只显示所选执行部门在花名册中的岗位。3001不根据岗位名称猜测归属；例如花名册把“车间主任助理”归入工程技术部时，工程技术部岗位下拉会原样显示该岗位。
- 新增业务行为不默认选择部门或岗位。选择具体岗位后，`current_actor_role`保存为“部门名称 + 岗位名称”；选择“全公司通用”时保存为`全公司`。
- 导入值未被当前花名册收录时，页面保留原值并标注“当前花名册未收录”。用户主动修改后只能选择有效岗位或“全公司通用”。
- 花名册岗位暂时不可用时，3001不会清除已有执行岗位，其他内容仍可继续编制和导出。

岗位不等同于正式工作角色，3001不会根据岗位生成工作角色。新业务行为的`work_role`为`null`；导入文件中已有的合法`work_role`会在内存中隐式保留并随再次导出带回。

历史正式工作角色仍不能脱离业务行为保存，其全称保留业务行为和职责，例如：

- `费用申请行为的发起角色`
- `费用审核行为的审核角色`
- `费用批准行为的批准角色`

岗位、人员和花名册不由3001维护；3001只是读取花名册岗位供编制人选择。花名册归属存在疑问时，由行政人事部修正花名册真源，3001不得自行改写。

## 跨部门承接和部门内调用预览

- 跨部门关系分为`inbound_prerequisite`前置输入和`outbound_followup`后续承接。两类关系都使用稳定的`handoff_ref`，并以`anchor_behavior_ref`关联本流程中相邻的业务行为。
- 一项业务行为可以创建多条跨部门承接。每个外部门形成独立记录，分别保存方向、来源部门、目标部门、传递数据或承接事项、触发条件、完成标准、可选外部门流程与行为，以及可选返回要求和本流程恢复行为。
- 业务行为卡片中的每条承接都提供“完善承接信息”和“删除这条承接”。删除前会显示当前承接的部门、处理事项和删除范围；取消后数据不变，确认后只删除这条承接，业务行为和其他承接不受影响。
- 删除已经关联跨部门承接的业务行为时，页面必须说明将同时删除的承接数量，并由用户确认后再处理。
- 责任部门暂时未知时必须设置`counterparty_resolution=needs_identification`。外部门流程、行为或责任部门尚未明确只形成治理提示，不阻止导出。
- 部门内调用属于MDM平台正式功能。3001不提供新增或编辑入口；新建流程保持`internal_process_calls: []`。
- 导入JSON中已有的`internal_process_calls[]`只在流程图中预览，并在当前页面内存中隐式保留。再次导出时不得清空或改写。为保护历史数据，被部门内调用引用的业务行为或数据对象不得在3001中删除。
- 会签只表示确认知悉。3001记录需要确认知悉的部门；全部会签完成前，流程不得视为结束。

## 数据和表单

- 输出物按待治理数据对象登记，只记录产生行为和使用行为。
- 3001不判断主数据、黄金源、数据责任、质量规则或共享范围。
- “表单与记录”是独立工作区。用户先选择表单或记录，再选择主表或某张明细表，最后编辑当前结构下的填写项。
- 页面使用“表单或记录名称”“表单或记录编号（如有）”“主表结构／主表标题”“明细表结构／明细表标题”和“填写项”。
- 新建表单只建立一个空主表框架，不自动生成名称、编号、标题或填写项。每张表单正常情况下只有一个主表，可以增加多张明细表。
- 表单与业务行为可以关联，也可以暂不关联。
- “填写项类型”必须从3001提供的标准类型中选择，不允许自由填写。当前类型包括：文本、长文本、数字、日期、日期时间、金额、枚举、布尔、部门、人员、文件编号、签名、图片、附件和二维码。
- 导入旧JSON时，如果填写项类型不在当前字典中，3001保留原值并标注“当前类型字典未收录”；用户主动修改后只能改选标准类型。类型字典暂时不可用时，选择器不可修改，但已有值和其他编制内容不受影响。
- JSON结构不变：`area_type: "基本信息"`表示主表，`area_type: "明细清单"`表示明细表，`areas[].items[]`保存各自填写项。
- 导入缺少主表、包含多个主表或存在未分类结构的旧文件时，页面保留全部内容并提示确认，不自动改写，也不把该提示作为技术性导出阻断。

## 编制参考材料

- 页面不提供“导入参考材料”、拖放区或参考资料编辑区，也不提示用户补充参考材料。
- 新建流程导出空的`reference_materials`数组。
- 导入的旧JSON如果已经包含参考材料，3001在当前页面内隐式保留，再次导出时原样带回；页面不展示、不编辑，也不自动清空。
- 服务端确定性解析能力仅保留用于历史文件迁移和回归测试，不再作为业务用户页面功能。

## 历史文件兼容

确定性文档解析器继续在内存中生成`document-structured-output-v2`结果。页面不会把旧版结构直接导出：

1. 旧文件按`process_ref`拆分。
2. 每条流程成为一个页面候选。
3. 关联步骤、行为详情、已有工作角色、表单、跨部门承接和部门内调用跟随当前流程。
4. 用户逐一检查并分别导出`process-governance-v3`。

旧版主表和不同明细表分别迁移，不合并不同明细表。无法直接归入当前单流程结构的证据和额外角色绑定会保留在“旧版结构化补充信息”参考材料中，避免静默丢失历史成果。

旧版`process-governance-v1`和`document-structured-output-v2`没有独立的“具体做什么”补充说明。导入时，3001保留原业务行为名称，并在当前页面内存中把`behavior_description`补为空字符串；系统不得把业务行为名称复制成补充说明，也不得推测实际操作。

## 无状态和安全边界

- 服务端使用内存上传，不保存原文件和业务内容。
- 页面不使用浏览器持久化保存草稿。
- 刷新或关闭页面后，本次内容无法恢复。
- 新建、导入其他文件或清空前，页面提供“取消、先导出当前流程、放弃当前内容”。
- `/api/data`和`/api/export`不可用。
- 3001不调用MDM平台的API、数据库、队列或任何共享状态。
- 3001不调用DeepSeek，不依赖MDM-AI助手或认证网关；这些服务不可作为3001启动或访问的前置条件。

## 校验边界

3001导出前只硬校验：

- JSON符合`process-governance-v3`；v1、v2可以导入，表单状态在当前页面内存中补为`unspecified`，导出统一升级为v3。
- 一份文件只有一个流程。
- 技术标识不重复。
- 当前文件内的行为、数据、关系和表单引用没有损坏。

“导出检查”把下列内容标为“提示项（不阻止导出）”。系统生成的每条提示只描述一个确定缺陷，不使用“或”把缺条件、缺目标等不同问题合并。用户点击字段问题后，页面返回相应分区，聚焦存在问题的输入控件，并显示红色呼吸高亮；没有具体输入控件的结构性问题仍定位到对应卡片或分区。触发条件和前置条件同时为空时，页面用一条“均为空”的提示说明“至少填写一项”，并同时高亮两个输入框。

- 发起部门、编制人、目的和范围是否补齐。
- 执行部门是否已选择。
- 已选岗位是否仍被当前花名册收录。
- 表单是否缺少主表。
- 表单是否包含多个主表。
- 表结构类型是否已选择。
- 流程入口、出口、可达性和回路触发条件。
- 判断节点是否有至少两个明确出口，以及各出口是否补齐必要信息。出口可以是本流程顺序、判断分支、流程内部回路或跨部门承接；作为默认继续路径的顺序关系可以不填条件，但必须填写目标行为。判断分支和回路必须填写条件及目标，跨部门承接必须填写触发条件和承接部门。显式回路不参与主线入口和出口数量计算。
- 并行分支和汇合是否完整。
- 会签对象是否完整。
- 外部目标流程、接收行为和责任部门是否待在MDM平台继续治理；这些缺口不阻止3001导出。

业务事实由真实责任人审核；MDM平台负责身份、部门决定、最终责任人、状态流转、发布卡口和跨对象可执行性校验。

## 常见故障

页面提示“3001前端与服务端版本不一致”时，用户应保持当前页面打开，不要刷新或关闭。维护人员重启3001服务后，用户在原页面再次执行“新建流程”或“导出当前流程”；重启服务不会清除已经打开页面中的编制内容。旧后端把首页HTML返回给空白模板接口时，页面必须显示版本或服务异常提示，不得直接显示JSON解析错误。

维护人员可以用以下命令确认服务端默认结构版本：

```powershell
(Invoke-RestMethod http://127.0.0.1:3001/api/schema).properties.schema_version.const
```

命令应返回`process-governance-v3`。如果仍返回v1、v2或`document-structured-output-v2`，说明端口3001仍由旧进程提供服务。

`/api/schema`响应头和`/api/template`响应同时提供结构摘要，用于确认当前页面与3001服务端结构一致。该检查只比较3001自身版本，不依赖外部助手。
