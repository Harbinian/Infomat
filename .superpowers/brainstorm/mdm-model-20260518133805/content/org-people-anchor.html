组织/人员域：先确定“主干关系”

这是首期数据模型的骨架选择，会直接影响后续流程、权限与集成复杂度

A

岗位为核心（推荐用于 Transaction Hub）

关系示意
OrgUnit
组织单元（部门/工厂/公司）
Position
岗位（隶属某 OrgUnit）
Person
人员（通过任职 Assignment 关联 Position）

优点

  • 岗位与编制、权限、成本归集更自然
  • 支持一人多岗/代岗/兼职

代价

  • 模型对象更多，建设略复杂
B

部门为核心（最快落地）

关系示意
OrgUnit
组织单元（部门/工厂/公司）
Person
人员（直接挂到 OrgUnit）

优点

  • 对象少，上线快

风险

  • 一人多部门/矩阵组织难处理
  • 后续补岗位常要大改
C

任职关系为核心（最灵活）

关系示意
OrgUnit
组织单元
Person
人员
Assignment
任职/归属关系（可同时关联 OrgUnit 与 Position）

优点

  • 矩阵组织/项目制表达最强

代价

  • 数据治理与查询更复杂
  • 对流程与权限设计要求更高
