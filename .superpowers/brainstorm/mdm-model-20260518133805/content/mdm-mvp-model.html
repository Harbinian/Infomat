首期 MDM 数据模型（MVP）草案

范围：组织/人员（岗位为核心） + 产品主数据（PLM口径，版本=新记录） + 外部系统映射

1）组织 / 人员域（岗位为核心）

核心实体与关系
OrgUnit（组织单元）
关键字段
  • org_unit_id（内部ID）
  • org_unit_code（可读编码，MDM生成）
  • org_unit_name
  • org_type（类型：集团/公司/工厂/部门/班组…）
  • parent_org_unit_id（可配置层级树）
  • manager_person_id（负责人，可空）
  • status / effective_from / effective_to
Position（岗位）
关键字段
  • position_id（内部ID）
  • position_code（可读编码，MDM生成）
  • position_name
  • org_unit_id（归属组织）
  • status / effective_from / effective_to
Person（人员）
关键字段
  • person_id（内部ID）
  • employee_no（工号，MDM生成；后续可对接HR）
  • person_name
  • mobile / email（可选）
  • employment_status（在职/离职等）
  • status / effective_from / effective_to
PersonPositionAssignment（任岗关系）
关系
  • person_id → Person
  • position_id → Position
  • is_primary（是否主岗，约束：同一人最多1个主岗）
  • start_date / end_date

为什么这样建（贴合你们当前约束）

  • 不依赖矩阵组织/项目制，也能表达“人-岗位-部门”主链路
  • 为后续角色/资质/授权预留挂载点（先不强上）

后续扩展方向

  • 当需要班组/项目制时：在 Assignment 上扩展维度或新增 ProjectAssignment

2）产品主数据（PLM口径，版本=新记录）

核心实体与关系
ProductFamily（产品族/型号根）
作用
  • 承载“同一型号/产品”的稳定标识
  • 让多个版本（A/B/C 或 Rev1/Rev2）可归一查询
关键字段
  • product_family_id（内部ID）
  • product_family_code（可读编码，MDM生成）
  • model_name / product_type / status
Product（版本化产品记录）
关键字段
  • product_id（内部ID）
  • product_code（可读编码，可与件号分离）
  • product_family_id（所属型号根）
  • revision（版次/修订号字段；不强制进入编码）
  • lifecycle_state（草稿/受控发布/废止）
  • superseded_by_product_id（新版本指针，可选）
  • effective_from / effective_to
BOMHeader / BOMLine（可选：若MDM暂不管BOM可先不做）
  • BOMHeader：bom_id，owner_product_id（对应某个 Product 版本）
  • BOMLine：parent_bom_id，child_product_id / child_material_id，qty，uom
Classification / Attribute（建议做“可配置属性”）
  • ClassNode：分类树（与物料编码大类/中类/小类可对齐）
  • AttributeDef / AttributeValue：让技术属性不靠加字段发版

为什么需要 ProductFamily

  • 你选择“版本=新记录”，如果没有 Family，版本一多就难以聚合统计与集成

与现有编码规范的关系

  • 物料编码规范草案建议“REV独立字段、不进主编码”
  • 即使你们以“新记录”表示新版本，编码是否变更仍可按规范由流程决定

3）跨系统映射（PLM / ERP / 数仓）

ExternalIdentity（统一外部ID映射表）
  • entity_type（OrgUnit/Position/Person/Product/Material…）
  • entity_id（内部ID）
  • system_code（PLM/ERP/DW）
  • external_key（对方主键/编码）
  • is_primary（该系统主标识）
  • last_sync_at / last_sync_status

请你确认 3 个点（点选 + 回一句话即可）

1

人员工号由 MDM 生成（后续对接HR再做映射）

如果你们已有工号规则也可以替换

2

产品版本用 ProductFamily + Product(版本记录) 表达

满足“版本=新记录”同时保留聚合查询能力

3

属性扩展用 AttributeDef/AttributeValue（不靠加字段发版）

首期可先做在 Product 上
