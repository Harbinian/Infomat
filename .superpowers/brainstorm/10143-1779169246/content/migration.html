迁移策略

将现有的 4 角色 + JSON permissions 平滑迁移到新 RBAC 系统

迁移步骤

Step 1：建表 + 预置数据
运行 init-db 脚本，创建 5 张新表，插入 4 个系统角色和对应权限码。此步骤通过 db.js 的 CREATE TABLE IF NOT EXISTS 自动完成，幂等安全。
Step 2：迁移现有用户
执行迁移脚本，读取每个 users 行的 role 和 permissions 字段：
  • users.role → 在 user_roles 中创建对应记录
  • users.permissions (JSON) → 解析后匹配预置权限码，若找不到对应则创建新的 permission 行
Step 3：替换中间件
全局替换 22 个路由文件中的 requireRole → requirePermission，requireDataPermission → requirePermission。 运行冒烟测试验证所有路由行为一致。
Step 4：废弃旧字段
保留 users.role 列（不删，避免破坏性变更），但标记为废弃。后续新增/编辑用户时不再写入此字段。users.permissions 同理。

迁移脚本

scripts/migrate-to-rbac.js
// 伪代码概要
const users = db.prepare('SELECT * FROM users').all();
const roleMap = { admin:'admin', reviewer:'reviewer', owner:'owner', submitter:'submitter' };

for (const user of users) {
  // 1. 角色映射
  const roleCode = roleMap[user.role] || 'submitter';
  db.prepare('INSERT OR IGNORE INTO user_roles (user_id, role_id) SELECT ?, role_id FROM roles WHERE role_code=?')
    .run(user.id, roleCode);

  // 2. 权限迁移
  if (user.permissions && user.permissions !== '{}') {
    const perms = JSON.parse(user.permissions);
    for (const [category, actions] of Object.entries(perms)) {
      for (const action of actions) {
        const code = `${category}:${action}`;
        // 确保权限定义存在，再关联到角色
        db.prepare('INSERT OR IGNORE INTO permissions (perm_code, resource, action) VALUES (?, ?, ?)')
          .run(code, category, action);
        db.prepare(`INSERT OR IGNORE INTO role_permissions (role_id, perm_id)
          SELECT r.role_id, p.perm_id FROM roles r, permissions p
          WHERE r.role_code=? AND p.perm_code=?`).run(roleCode, code);
      }
    }
  }
}

回滚策略

迁移前自动备份 platform.db → platform.db.backup-YYYYMMDD。
在新系统上运行全部冒烟测试（smoke-master-data.js + smoke-integration.js）确认通过后删除备份。
