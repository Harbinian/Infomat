批量导入格式设计

两个导入模板的列定义、校验规则和处理逻辑

模板一：用户-角色分配

#列名必填说明
A工号是匹配 users.employee_no
B姓名否仅用于校验提示，不写入
C角色编码是多个角色用逗号分隔，如 reviewer,dept_auditor
D操作类型否add（追加）/ replace（替换，默认），默认 replace

模板二：角色-权限定义

#列名必填说明
A角色编码是目标角色，不存在则创建
B角色名称新建时已有角色忽略此列
C父角色编码否继承角色，新建时有效
D权限码是resource:action 或 *:* 通配
E效果否allow（默认）/ deny
F字段限制否JSON 字符串，如 {"exclude":["mobile"]}

导入处理流程

文件上传 → multer 接收 → 判断格式(Excel/CSV) → 逐行校验
                                              │
                                    ┌─────────┴─────────┐
                                    ▼                   ▼
                              校验通过               校验失败
                                    │                   │
                                    ▼                   ▼
                            事务批量写入          记录错误行+原因
                                    │                   │
                                    ▼                   ▼
                            返回成功报告    ←── 合并结果 →  逐行详细错误
                                    │
                                    ▼
                            写入 version_log
                            (记录导入操作)

校验规则

  • 工号校验：必须在 users 表中存在，否则报错
  • 角色编码校验：必须在 roles 表中存在（用户-角色导入），或自动创建（角色-权限导入）
  • 权限码校验：格式必须为 resource:action 或 *:*
  • 字段限制 JSON 校验：如果填写必须是合法 JSON
  • 重复行去重：同一用户+同一角色重复时只保留最后一次
