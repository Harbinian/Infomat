三种 RBAC 架构方案对比

为 MDM 平台选择角色权限系统的数据模型方案

A

轻量 JSON RBAC

新建 roles 表 + user_roles 关联表，权限以 JSON 字段存储在 roles 表中。字段级权限通过 JSON path 表达。

优点

  • 表结构简单（3-4 张新表）
  • 与现有 users.permissions JSON 模式一致
  • 实现快，改动范围小

缺点

  • JSON 权限不可被 SQL 查询
  • 字段级权限表达冗长
  • 权限校验需在应用层逐条判断
B

全关系型 RBAC

权限作为独立表行存在：permissions (resource, action, fields)。所有权限关系通过关联表建模。

优点

  • 权限可 SQL 查询和分析
  • 类型安全，结构清晰
  • 字段级权限天然支持

缺点

  • 新增 6-7 张表
  • 初始数据量大（需预置大量权限行）
  • 查询需要多表 JOIN
C

混合型 RBAC 推荐

核心 CRUD 权限走关系表（可查询），字段级约束和扩展规则用 JSON 补充（灵活）。

优点

  • 常用权限可查询，扩展权限灵活
  • 中等复杂度（5 张新表）
  • 兼顾性能与灵活性

缺点

  • 中间件需要两层判断逻辑
  • 权限定义分散在两处
