# 中文技术文档受控写作

目标是让目标读者看清谁在什么条件下做什么、产生什么结果，同时保留事实和责任。使用自然、完整的中文，不为简短或文风改变业务含义。

## 不可改变的信息

- 已确认事实、责任主体、对象、条件、时序、输入输出、状态、异常和验收规则不得自行补造或改写。
- 制度原文、合同条款、直接引文、数据、编号、路径、字段、枚举和错误码保持原样；只改外围说明。
- 术语和业务口径依次采用受控原文或用户已确认口径、项目术语表及契约、当前文档定义、本技能通用解释。两个名称可能是不同对象时不得擅自合并。
- 用户明确要求修改规则时，可在授权范围内修改对应规则；上述保护不应被解释为禁止用户授权的变更。缺失的业务事实仍保留待确认。

## 按需参考

本入口足以处理一般受控改写。只在当前内容需要时读取参考文档的对应章节：

| 需要解决的问题 | 参考 |
|---|---|
| 责任链、审核与审批用词、事实保护或复杂压缩 | [受控写作规则](references/controlled-writing-rules.md) |
| 起草完整方案、SOP、验收材料、纪要或使用说明 | [文档类型规则](references/document-type-rules.md) 中对应类型 |
| 用户要求问题表、专门输出格式或 Humanizer 联用 | [输出示例](references/output-templates.md) |

已有模板和用户要求优先。局部修改只检查受影响内容，不扩写整篇文档，也不固定建立事实表、主体表或术语表；跨来源或复杂责任关系确有需要时再使用内部清单。

## 表达与核对

写清执行主体，区分人员、部门与系统动作；主体、条件或责任链变化时消除歧义。统一专业术语，按读者需要解释其实际含义。生活化实例只在有助理解时使用，并与正式规则及证据分开。

核对改写是否保留原有事实、数据、责任和条件。对有依据可修正的问题直接修正；无法确定的业务信息明确标记，不为填写模板而补造。交付用户要求的正文或修改说明，不固定附加评分、自检表、空白问题栏或多轮中间稿。

`humanizer-zh` 仅在用户明确点名时联用，只清理套话、重复和夸张表达；联用后核对语义，不允许其改变受控信息。
