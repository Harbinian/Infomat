# 输出格式与调用模板

## 1. 直接改写

用户要求“直接改写”时，只输出修订后的正文，不输出问题分析或评分。

如果原文缺少无法可靠补出的主体、对象或条件，在对应位置使用：

> 【需确认：责任主体】

不要静默猜测。

调用示例：

```text
请使用 technical-chinese-writer 改写以下内容。

文档类型：技术方案
目标读者：业务部门、工艺部门和信息化部门
要求：
1. 补足能够从原文确定的行为主体；
2. 使用条件、主体、动作、对象和结果的正序表达；
3. 统一专业术语；
4. 对首次出现且读者可能不理解的术语作必要解释；
5. 不改变业务含义、参数、责任和时序；
6. 只输出修订稿。

原文：
[粘贴原文]
```

## 2. 审校

用户要求“审校”或“说明问题”时，使用：

```markdown
## 修订稿

[修订后的正文]

## 主要问题

| 位置 | 问题类型 | 原因 | 修改方式 |
|---|---|---|---|

## 需确认事项

- [无法从原文判断的业务、主体或术语问题]
```

没有需确认事项时写“无”，不要编造问题。

## 3. 压缩

压缩目标是减少冗余，不是减少必要信息。保留：

- 责任主体；
- 处理对象；
- 触发条件和时序；
- 处理结果；
- 审核、审批、批准、确认或评审关系；
- 输入、输出和异常处理；
- 标准术语、编号、数据和引文。

禁止通过省略主体、宾语前置、名词化或术语换词压缩。

## 4. 优化为正式文档

根据文档类型补足必要标题、编号、表格和章节。只重组原文已经提供的信息；缺失的业务事实标记“待补充”或“需确认”，不得代填。

## 5. Humanizer 联用

仅在用户明确点名 Humanizer 时使用：

```text
先使用 technical-chinese-writer 修复主体、术语、条件、时序和责任关系，
再使用 Humanizer 删除套话、重复和夸张表达，
最后再次使用 technical-chinese-writer 核对事实和责任。

Humanizer 不得修改专业术语、缩写、编号、数据、责任主体、业务条件、
处理对象、时序、输入输出、审批关系和异常处理。
```

最终只输出用户要求的成品，不输出三轮处理中间稿。

## 6. 普通回复

普通回复只执行轻量检查：

- 结论先行；
- 主体、动作和对象明确；
- 事实和术语一致；
- 不补造信息；
- 删除无信息量的开场和结尾。

不要输出术语表、问题表、评分或自检过程，除非用户明确要求。
