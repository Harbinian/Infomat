# CXSYSYS 到 process-governance-v7 的映射规则

| 数据库证据 | V7目标 | 生成口径 |
|---|---|---|
| 表单配置、主表和明细表 | `data_objects[]`、`forms[]` | 主表和明细表分别形成区域；业务字段形成对象字段和表单字段引用；技术字段排除 |
| 工作流节点 | `behaviors[]` | 动作节点名称必须写清主体、动作和对象；判断节点写清业务问题 |
| 工作流连线和条件 | `flow_relations[]` | 顺序、判断、退回和并行按配置生成；判断分支必须核对语义目标 |
| 角色配置 | 候选证据、待确认问题 | `current_actor_role`保持空，不能把配置角色当正式岗位 |
| 表间公式 | 表单字段`source_links[]` | 只生成字段来源或使用关系；缺少来源对象时保持待确认 |
| 审批姓名和日期字段 | `behavior_links[]` | 证据表明节点实际写入时用`update`并列出`updated_field_refs[]`；只更新对应对象 |
| 列表规范 | 枚举字段、`terms[]`候选 | 普通字段、审计字段、技术字段不生成术语；没有可靠解释时定义可以为空 |
| 业务目的、正式责任、生效归档规则 | 待确认问题 | 数据库不能证明时不补造，不靠角色名称或字段名称代替业务确认 |

## 业务文案排除项

下列内容不得出现在流程目的、适用范围、术语、行为名称和面向业务人员的说明中：

- `ExcelServer`、`WorkItem`、`_wi`、`ES_WorkItem`。
- `CXSYSYS.dbo`、物理表名、数据库列类型、连接和账号信息。
- `Operator`、`ITEM`、`FONO`等技术尾列。

物理名称只保留在证据文件中。表单字段的业务名称即使与数据库列名相同，也必须以页面业务字段身份进入 JSON，不得附带物理路径。

## 数据关系约束

- `create`表示本行为形成该对象记录。
- `update`只用于有实际写入字段证据的行为，并必须列出该对象中的字段引用。
- `use`表示读取、核对或作为判断依据，没有写入字段证据时不得扩大为`update`。
- 同一行为对同一对象只能保留一条关系；同时创建并修改时优先使用`create`。
- 判断节点读取条件字段时对对应对象使用`use`。
